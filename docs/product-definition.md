# 首版产品定义

状态：Spec 001 的产品基线已落地，桌面骨架已通过独立工程验收。用户确定 Electron 桌面形态；下文区分本次交付与后续会议目标流程。

## 产品与用户

Personal Agent Assistant 是面向 macOS 和 Windows 的个人工作助手。核心用户使用自己的电脑参与会议、了解团队与项目进展，需要减少记录整理工作，并积累可追溯的长期工作信息。

当前以会议为首个使用场景，员工周报和长期 Memory 是后续方向。产品不是团队 SaaS，本阶段不加入账号、云同步或多人协作。

## 首版界面与本 Spec 交付

- **会议工作区**：应用主入口，显示空会议状态、录音能力尚未接入的说明；可以进入设置或查看能力状态。
- **能力 / 准备状态**：显示本地核心是否连接，以及录音、转写、总结是否已实现。核心可用不代表模型已就绪。
- **设置**：展示当前本地运行状态，提供核心连接刷新 / 重试入口及必要故障信息；不提供尚未可用的密钥提交或模型下载流程。
- **后续能力**：可以用清晰的“后续支持”展示周报和长期记忆，不设置伪装可用的操作。

默认不注入演示会议，不伪造转写、计数或纪要。“开始会议”未实现时不可触发录音，应禁用并就近说明。所有展示给用户的状态必须来自真实能力或明确的未接入状态。

视觉采用清晰的中文桌面工作区：稳定侧栏、浅色内容区、克制的绿色强调、足够的留白和明确的空状态。窗口可缩放，在最小支持尺寸下主要操作和文字仍可访问。产品主界面不堆叠框架版本、IPC 等开发信息。

## 后续 Meeting MVP 用户流程

```text
开始会议 → 检查录音设备与权限 → 持续录音并展示转写
结束会议 → 停止采集 → 处理剩余音频 → 整理完整转写
         → 生成结构化纪要 → 查看与回顾历史会议
```

上述为后续目标流程，Spec 001 只建立应用入口及模块边界。

异常体验方向：

| 情况 | 目标行为 |
| --- | --- |
| 麦克风或权限不可用 | 明确提示原因，不能显示已开始录音；待录音模块实现 |
| ASR 未安装或模型缺失 | 显示未配置；录音数据的暂存策略由会议 Spec 定义 |
| ASR 失败或积压 | 显示处理状态与保留原始音频，不能阻塞采集；待会议 Spec 实现 |
| LLM 未配置或总结失败 | 完整转写可保留；后续提供重试总结，不伪造纪要 |
| Python 核心不可用 | 本次窗口仍正常出现，显示核心不可用并可重试连接 |

## 生命周期

本次无真实录音。关闭最后一个窗口时应用退出并停止其管理的 Python 进程，macOS 和 Windows 行为一致；不加入托盘常驻。后续录音功能必须另行定义会议中的退出确认、停止与数据收尾。

## 正式用户安装体验

macOS 与 Windows 正式用户应安装应用后直接使用，不需要自行安装 Python、Node.js、创建虚拟环境或手动启动后台服务。所需运行时和内部处理程序随应用分发，由桌面应用管理生命周期。

“本地核心”是当前内部模块名称；正式界面应说明用户可理解的处理状态和恢复操作，不能要求普通用户配置解释器路径。当前 Python 版本及 `.venv` 提示属于开发骨架的诊断信息，用户安装包尚未实现。模型文件的随包分发或应用内下载方式留给后续功能与分发 Spec 确定。

交付约束见 [决策 0005](../.ai/decisions/0005-self-contained-desktop-distribution.md)。

## 本次范围与完成标准

交付可通过开发环境启动的桌面应用、真实的核心连接、明确能力状态和验证命令。不包含真实会议采集、ASR、LLM、周报、长期 Memory、签名安装包或自动更新。

Mac 实机运行结果与 Windows 验证配置分别记录。完整 Spec 标准见 [Spec 001](../specs/spec-001-product-and-technical-foundation/spec.md)，本文件不将未运行平台视作已经支持。
