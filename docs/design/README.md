# UI 设计基准

Web、Electron 与未来手机端沿用本目录的视觉与交互语言。先改造 Web，再分阶段适配其他端；现有翻书登录页保留。业务页面尚未迁移，不能把原型视为已上线功能。

## 可运行参考

[原型源码](prototype/) 保存已选定的黑白灰方案，包含浅／深色、助手会话、工作列表、团队看板、报告和模型服务页面，以及窄屏适配。它是视觉参考，不替代真实路由、权限与业务规格；示例数据和模拟反馈不得带入正式功能。

在仓库根目录使用现有依赖启动（先关闭占用 5186 端口的临时预览）：

```sh
node_modules/.bin/vite --config docs/design/prototype/vite.config.mjs
```

访问 http://127.0.0.1:5186/ 。右上角切换明暗主题；“继续上次的对话”展示消息、来源与确认卡；左下角切换用户视角查看报告。原型不连接业务接口，不填写真实密钥。

设计参考：[BeUI AI Agents](https://beui.dev/components/agents/message-bubble)。以本仓库归档为准，参考站更新不代表项目跟随变化。没有安装 BeUI 依赖。

## 配色

支持浅色、深色与跟随系统，保留正式产品现有主题偏好和默认策略；原型默认浅色仅用于预览。

使用无蓝、紫、绿偏色的中性灰。以表面亮度、文字和留白区分层级，不用大量描边或阴影划分每一块内容。

| 语义             | 浅色                      | 深色                      |
| ---------------- | ------------------------- | ------------------------- |
| 应用外框／侧栏   | `#f5f5f5`                 | `#101010`                 |
| 主内容画布       | `#fcfcfc`                 | `#151515`                 |
| 弹层／独立表面   | `#fcfcfc`                 | `#1c1c1c`                 |
| 柔和内容底色     | `#f5f5f5`                 | `#1c1c1c`                 |
| 悬浮             | `#ebebeb`                 | `#252525`                 |
| 选中背景         | `#e9e9e9`                 | `#242424`                 |
| 主文字           | `#0b0b0b`                 | `#f2f2f2`                 |
| 次文字           | `#454545`                 | `#bcbcbc`                 |
| 辅助文字         | `#636363`                 | `#868686`                 |
| 轻边界           | `#0b0b0b0f`               | `#ffffff0d`               |
| 强边界           | `#0b0b0b1f`               | `#ffffff1a`               |
| 主操作／用户气泡 | `#0b0b0b`，字 `#fcfcfc`   | `#f2f2f2`，字 `#151515`   |
| 成功             | `#16815b`，底 `#00bd6c0d` | `#54bc90`，底 `#00bd6c10` |
| 待确认／阻碍     | `#a26b12`，底 `#f5a5000d` | `#d4ad65`，底 `#f5a50010` |

语义色只用于必要状态，并配图标或文字，不把整片页面染色。原型未覆盖的错误、危险操作和校验状态，正式落地时补齐并检查对比度。不要重新引入蓝紫色选中条、偏色灰阶或带间隙的紫色焦点外圈。

## 排版与组件

- 桌面采用紧凑侧栏、轻量顶部导航和内嵌主画布；面包屑表达路径，单个页面只有一个主标题，主操作与标题同行。
- 内容按任务组织。列表筛选、结果、分页形成一个整体；空状态收在对应内容区域，不靠大段空白撑满页面。详情就近进入或展开。
- 输入区、快捷入口和工作结果采用柔和表面；弹层有轻阴影，普通内容不套多层白卡。主要容器圆角约 14～20px，小控件约 8～12px，状态与短操作可用胶囊形。
- 中文优先系统字体，常规正文以 14～16px 为起点，明确区分标题、正文与辅助信息。原型中的小字仅作参考，落地时检查实际可读性，不照搬缩小截图的字号。
- 控件具备默认、悬浮、选中、键盘焦点、禁用、加载和错误状态。焦点效果贴合控件轮廓；下拉层紧靠触发器，不被父容器截断。

## 工作助手

- 用户消息为反色气泡，助手正文直接呈现在画布上，身份和时间保持轻量。
- 工具执行与来源采用紧凑、可展开的摘要，不把技术过程堆成一排大卡片；结果与正文清楚区分。
- 需要确认的业务操作使用独立确认卡，呈现操作对象、关键内容和主按钮；待确认与完成状态可辨认。
- 输入区采用浅灰／炭灰底色，附件、模式与发送动作形成稳定工具栏；附件分类呈现，输入高度有上限。
- 新消息可短暂进入，生成中的正文保持稳定；不能反复整段入场、抖动或自动打断用户阅读历史。

## 动效与跨端适配

- 动效用于表达选中、展开、按压、到达等状态。通常 150～350ms，明暗切换可稍长；避免无关循环动画，遵循减少动态效果偏好。
- 手机保留同一套灰阶、层级和组件语言，导航改抽屉，复杂横排改纵排；不要等比例缩小桌面。触摸目标、软键盘、安全区和长内容单独适配，重要操作不能仅靠悬浮出现。
- 共享设计规范，不共享应用私有 CSS。Web 保持现有 CSS Modules 与功能目录；Electron 独立维护；未来原生手机端按其技术栈实现语义色与交互。
- 原型的全局 CSS、大型演示页面和内存导航不是生产代码模板。正式实施从各端现有组件边界落地，保留全部业务能力、登录、权限和会话行为。

## 后续改造

Web Spec 以这份规范和原型为视觉验收依据，先建立主题、基础控件与应用框架，再覆盖业务页面。验收查看浅／深色、桌面／窄屏，以及空数据、有数据、加载与错误状态；测试范围按实际影响确定。

本目录保留一个当前基准，修改通过 Git 留历史，不堆积多份版本文档。`artifacts/` 中的临时预览、构建产物和截图不是长期依据。
