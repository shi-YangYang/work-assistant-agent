# 0010 — 本地会议资料的管理与检索

2026-09-12 · ACCEPTED，对应 [Spec 007](../../specs/spec-007-meeting-library/spec.md)。用户在收到完整草案和永久删除建议后授权“开始实施”，本轮据此采用二次确认后永久删除，保留中途失败的恢复／重试机制。

## 背景

当前会议资料保存在 SQLite 和按会议 ID 管理的 WAV 中，历史与转写均分页。下一步需要检索和带走已有资料；无需模型推理即可完成。

## 决策与理由

- 复用现有会议列表、详情及引用定位，采用本地关键词查询，不引入外部检索服务。初版优先对可见文本做参数化子串匹配，转义通配符，保留中文短词能力；数据规模确实形成瓶颈后再考虑专用索引。
- 不直接把 FTS5 trigram 设为必需依赖：其全文匹配对不足三个 Unicode 字符的查询有限制，而本产品需要一两个汉字的搜索。SQLite 自带 LIKE 的默认大小写折叠只覆盖 ASCII，首版英文大小写约定依此限定，其他文字按字面匹配。
- 沿用会议名称字段作为用户管理名称，保留 AI 纪要标题的原始内容；手动改名不重新生成纪要，也不改变 ID 和引用。
- 文本导出由 Electron 主进程通过系统保存对话框完成，核心管理数据快照；显示在界面中的一页数据不能作为完整导出来源。保留既有 IPC 信任和消息大小边界。
- 删除协调任务、文件与数据库生命周期，采用明确确认的永久删除；完整范围与恢复语义见 Spec。功能实施授权不授权测试时删除用户既有数据。

## 取舍与后果

直接文本查询减少索引同步、打包兼容和迁移负担，但大库查询需有界执行、分页和可观测的失败状态，不能让长查询阻塞录音控制。暂不提供语义相似、相关性排序或复杂查询语法。确认删除后不提供应用内恢复入口，因此确认框和执行时的任务保护必须明确有效。

## 依据

- [SQLite 表达式与 LIKE](https://www.sqlite.org/lang_expr.html#like)：参数绑定、字面通配符转义及 ASCII 大小写边界。
- [SQLite FTS5 trigram](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)：短于三个字符的全文查询限制及子串匹配支持。
- [Electron 保存对话框](https://www.electronjs.org/docs/latest/api/dialog#dialogshowsavedialogwindow-options)：主进程的系统保存入口与取消结果。
