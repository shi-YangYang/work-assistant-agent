# Decision — 项目骨架初始化

日期：2026-09-09

## Context

用户已提供 Personal Agent Assistant 的产品背景和通用 `AGENTS.md` 开发规范，随后明确要求：“先完成项目骨架，此时你不需要创建spec”。

初始化前仓库仅有已跟踪的 MIT `LICENSE`，没有业务代码、依赖清单或工程配置，工作区干净。因此本次按 `NEW` 处理。

## Decision

- 将用户提供的通用开发规范原样放入根目录 `AGENTS.md`。
- 建立 `constitution/`、`specs/`、`.ai/` 标准 Agent 结构，以及 `docs/`、`tests/`、`src/` 基础项目目录。
- `src/` 作为本次初始化采用的业务代码位置，内部包和模块结构留待技术方案确定。
- `specs/` 只创建说明和空白模板；本次不创建编号 Spec，不启动功能实施。
- 本次骨架验收以用户当前范围要求、`AGENTS.md` 适用的初始化条款及本决策为依据。
- 记录明确的产品目标、阶段边界与技术约束，区分候选技术和已确定内容。
- 不创建业务代码、依赖清单、运行配置、数据库或部署设施。
- 保留已有 `LICENSE`，不修改现有提交或远端配置。

## Reason

当前任务是建立可持续维护的开发基础。用户本轮明确指令优先于通用流程中初始化时创建首个 Spec 的要求。具体架构尚未确认，骨架不应将候选框架、数据库或模型写成实施决定。

## Alternatives

- 同时创建首个功能 Spec：不符合用户本轮范围要求。
- 立即生成可运行项目脚手架：需要提前选定尚未确认的运行环境、框架和依赖。
- 暂不预留业务目录：不如明确单一 `src/` 位置便于后续接入；内部模块仍可在架构确认后设计。

## Consequences

- 当前仓库只具备目录与文档基础，没有可运行应用或测试套件。
- 后续实际业务实现前仍需完成架构设计、关键决策和具体 Spec。
- 后续业务目录迁移遵守 `AGENTS.md` 的目录变更规则。
- 空目录使用 `.gitkeep` 占位，后续加入实际文件时可移除占位文件并保留目录职责。
- 本次不创建 Spec 是一次任务范围例外，不构成后续开发流程的普遍豁免。
