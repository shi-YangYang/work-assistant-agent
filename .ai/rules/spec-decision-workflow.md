# Spec 工作规则

- 需求讨论、调研、选型和文档由主 Agent 完成，不开子 Agent、不安排独立验收；按 S0 检查后交用户审查。
- 开 Spec 的业务实施：实施 Agent 开发，新的独立 Agent 验收；关键决策未确认前不实施。
- 不开 Spec／直接修改：主 Agent 自行分析、修改和验证，不创建子 Agent。
- 普通文本集中询问当前需要确定的问题，不用问题卡，不重复询问已确认内容；等待时推进不依赖答案的工作。

## 文档精简

- 只记录无法从代码看出的重要取舍，优先更新已有结论；不加日期、Spec 编号、讨论流水账和重复引用。
- 普通修复、样式、测试和提交不额外写决策，也不默认同步多份报告。
- 验收只保留结果、必要证据及未解决问题，如实区分通过、失败、未执行；日志和截图放 `artifacts/`。
- 交接只记录未完成事项和恢复所需信息；不删除唯一有效约束或用户数据。
- 验证遵循 S0～S3，必要检查通过后停止；文档整理不运行业务测试。
