# Git 分支工作规则

更新日期：2026-09-11。

来源：用户要求 Agent 提交并推送 `dev` 后提供网页链接，由用户合并到 `main`，随后自行回同步 `dev`。本规则替代此前 Agent 自动合并与回同步的约定。

## 持续约定

- `dev` 和 `main` 长期保留；默认在 `dev` 开发、提交和推送，不为每个任务另建临时分支，也不直接在 `main` 开发业务改动。
- 开发与验收仍遵循 Spec 流程和 S0～S3 验证规则。用户要求提交并推送时，在必要检查通过后推送 `dev`，提供 `dev → main` 的 HTTP(S) 链接；已有开放 PR 时提供该 PR 地址，否则可提供仓库的 `compare/main...dev?expand=1` 创建页。区分 PR 创建页与已经存在的 PR，不重复创建。
- 用户要求仅本地 commit 时不推送。用户要求不触发 CI 时，不创建／更新会触发检查的 PR，也不手动运行工作流；本地 commit 不触发远端 CI，推送已有 PR 的分支会触发 PR 检查。
- 用户通过链接创建／查看 PR，确认当前提交的必需检查后执行合并。Agent 不自动合并到 `main`，提供链接和已知检查状态后即可交付，不默认等待 CI；未知或仍运行的结果如实说明。
- PR 优先使用普通 merge commit，保留长期分支共同历史。用户合并后留在 `dev`，依次执行 `git pull --no-rebase origin main`、`git push origin dev`，将远端最新 `main` 同步到本地及远端 `dev`；无新增开发提交时通常直接 fast-forward。
- Agent 仅在用户另外要求时执行回同步；若存在新提交或冲突，先读取差异并保留现场，按相关范围处理，不覆盖用户修改。工作区留在 `dev`。
- 不删除长期 `dev`。如另行创建临时分支，只有本任务创建、已完成合并且内容已安全推送的分支才可清理；不删除用户或其他任务的分支。
- 保留用户修改和他人提交，不使用强制推送、reset 或丢弃内容解决分歧。无法安全合并或推送时保留现场并说明具体原因。
- 验证与等待统一遵循 [CI 减负与交付效率](../../AGENTS.md#ci-减负与交付效率)。合并后内容未变的回同步不重复本地测试，远端重复检查可报告仍在运行，不默认阻塞交付；尚未运行或完成的检查不能表述为通过。
- 本规则持续适用，除非用户明确改变要求。
