# Git 分支收尾规则

记录日期：2026-09-10。

来源：用户明确要求“要么不单独开分支，要么开完分支，验收合格之后自动合并到 main 并删除你开的分支”。

## 持续约定

- 默认在 `main` 上完成工作，不为了个人工作习惯单独创建分支。
- 如果为任务创建了分支，验收合格后自动完成：合并到 `main` → 推送 `main` → 删除自己创建的远端及本地分支 → 工作区回到 `main`。
- 上述合并和清理已经获得用户持续授权，不重复询问，不将仅推送功能分支视为完整交付。
- 合并前读取远端最新状态，优先 fast-forward；保留用户修改和他人提交，不使用强制推送、reset 或丢弃内容解决分歧。
- 仅清理本任务由 Agent 创建且已经合并的分支。推送 `main` 成功后再删除分支；如果无法安全合并或推送失败，应明确具体原因并保留分支。
- 复用与最终代码对应的验收和 CI 证据，遵守验证与停止规则；仅文档或不改变内容的 fast-forward 不重复业务测试。
- 该约定适用于后续所有任务，除非用户明确改变要求。
