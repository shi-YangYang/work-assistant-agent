# Personal Agent Assistant

面向 macOS 和 Windows 的个人智能助手，从会议记录与员工周报场景起步，逐步建立对人员、项目、任务、决策和历史信息的长期理解。

当前仓库处于项目骨架阶段，尚无可运行的应用。首个开发目标是 Meeting Agent MVP。

当前开发环境为 macOS，产品目标平台包括 macOS 和 Windows。后续技术选型与架构设计需考虑两个平台的兼容性，具体支持版本和交付安排待定。

## 背景

项目的长期价值是连接会议、周报与历史工作信息，帮助用户理解项目进展、跟踪任务和识别长期风险。当前优先实现会议录音、转写和会后总结的完整流程。

详细目标与约束见 [项目使命](constitution/mission.md)，阶段范围见 [路线图](constitution/roadmap.md)。

## 当前范围

Meeting Agent MVP 的目标流程如下，尚未实现：

```text
开始会议
  → 电脑麦克风持续录音
  → 产生音频分块
  → 本地 ASR 转写
  → 持续显示并保存完整 Transcript
结束会议
  → 停止录音并完成剩余音频转写
  → 整理完整 Transcript
  → 调用 LLM 生成结构化会议纪要
  → 保存会议记录
```

录音必须独立持续运行，不能被 ASR 或 LLM 请求阻塞。第一阶段不实现复杂实时会议理解、说话人识别、复杂 RAG、知识图谱或产品中的多 Agent 工作流。

## 开发与验证

开发遵循 [AGENTS.md](AGENTS.md)：明确需求与关键决策，维护 Spec 和实施计划，由实施 Agent 开发，再由独立验收 Agent 验收。开发协作使用多个 Agent，不代表 MVP 产品需要实现多 Agent 功能。

本次初始化按用户要求不创建具体 Spec，仅提供目录说明和空白模板。测试、类型检查、Lint、格式化和构建命令均尚未配置，后续以 [技术约束](constitution/tech-stack.md) 和实际工程配置为准。

录音、转写、会议数据库、模型缓存和日志等本地运行数据应存放在受忽略的目录中，避免进入版本库。原始数据保留是产品要求，具体存储与清理策略将在后续设计中确定。
