# 项目使命

## 项目背景

Personal Agent Assistant 从面向 macOS 和 Windows 的会议桌面助手起步，长期目标是让 Agent 参与公司真实业务，连接员工工作记录、组织架构、工作画像、项目进度与公司知识。用户最新方向见 [决策 0011](../.ai/decisions/0011-company-agent-direction.md)。

本文根据用户提供的项目背景整理，描述长期方向与已明确约束，不代表各项能力均已实现。

## 目标用户与价值

试点首先服务老板明确提出的两项需求：持续跟进会议中的责任事项、重要信息与安排；让员工通过图片、文字、语音提交日报、周报和日常信息，并让老板通过看板及时了解工作进展。需求来源与尚待明确的行为见 [决策 0011](../.ai/decisions/0011-company-agent-direction.md)。系统应减少人工记录与信息整理成本，并保留原始依据；在既有本地会议产品之外，[Spec 008](../specs/spec-008-meeting-followup/spec.md) 已进入公司 Web 与共享服务的实施验收。

长期应能够结合历史会议、周报和关联记忆，回答项目近期进展、延期原因、人员工作内容、长期未解决的问题以及历史会议决策等问题。

## 当前优先目标

优先在试点公司建立“员工消息 → 工作进展 → 员工确认或纠正 → 日报／周报 → 老板看板”的业务流程，以 harness 支撑持续处理。首期优先 Web＋共享服务端，逐步支持更多客户端；Electron 保留现有会议功能。已确认方向、部署约束与待定边界统一见 [决策 0011](../.ai/decisions/0011-company-agent-direction.md)。

## 会议能力基础（保留）

最初的 Meeting Agent MVP 目标为：

1. 用户点击开始会议，通过电脑麦克风持续录音。
2. 持续产生 Audio Chunk，由本地 ASR 转写。
3. 界面持续显示 Transcript，并保存完整转写。
4. 用户结束会议后，完成剩余音频处理，整理完整 Transcript。
5. 调用 LLM 生成结构化会议纪要及适合人阅读的纪要。
6. 保存会议记录，为后续 Meeting Memory 提供数据基础。

会议纪要至少考虑标题、摘要、话题、决策、行动项、风险和未解决问题。行动项考虑任务内容、负责人、截止时间和状态；具体字段约束在后续设计中确定。

## 后续核心能力

- 会议事项跟进：帮助回顾会议中的责任事项、重要信息和安排，具体跟进与日程行为待 Spec 明确。
- 扩展愿景：组织架构、员工工作画像，以及工作材料逐步进入公司知识库；这些不属于老板原始需求，不默认全部纳入首版。
- 长期 Memory：关联 People、Projects、Meetings、Tasks、Decisions、Weekly Reports 和 Risks。
- 增量会议理解：后续按转写时长、文本量或语义边界触发分析，积累会议事件和状态。
- 更长期考虑主动分析、工具调用和基于历史信息的问答。

## 核心原则

- 先设计再编码，优先验证最小可运行流程，避免第一阶段过度工程化。
- 产品目标平台包括 macOS 和 Windows。当前使用 macOS 开发，技术选型与核心业务设计仍需考虑跨平台兼容性，将必要的平台差异隔离在适配边界内。
- 录音、ASR、转写管理和 LLM 分析低耦合；ASR 或 LLM 延迟不得中断录音。
- 音频采集与 Agent 推理分离，采用独立的生产者与消费者处理思路。
- 音频分块策略可配置、可演进。约 5～15 秒是初始参考，不能把固定时长写死在核心架构中。
- ASR、LLM、Memory 使用清晰接口，不将具体模型或服务商绑定在业务逻辑中。
- 后续业务 Agent 遵循 harness 范式，允许按需使用 LangChain、LangGraph、AutoGen 等框架与运行组件；以用户所在公司试点并逐步演进，具体约束见 [决策 0011](../.ai/decisions/0011-company-agent-direction.md)。
- 原始数据尽量保留，避免只保留 LLM 总结而丢失事实和上下文。
- Transcript 应能表达片段标识、会议标识、起止时间和文本，并预留说话人与置信度字段；第一阶段允许后两者为空。
- 数据设计考虑未来的 Speaker、People、Project、Task 和 Memory 扩展。
- 关键架构决策说明理由和取舍，并按照开发规范留痕。

## 原会议 MVP 阶段非目标

- 说话人识别、分离及真实人员映射。
- 复杂实时 LLM 分析和增量会议理解。
- 复杂 RAG、知识图谱及复杂 Memory 系统。
- 多 Agent 产品能力、主动 Agent 和复杂 LangGraph Workflow。
- 周报模块和跨周分析的具体实现。

上述内容仅描述原会议 MVP 的阶段边界，不限制当前已确认的公司汇报方向。开发流程中的实施 Agent 与验收 Agent 分工不属于产品功能范围。
