# Spec 030 — 全项目四维质量修复

## 状态

已实施；四维验收 PASS，证据与未执行边界见 [验收结果](acceptance.md)。

## 背景与当前行为

项目主流程已打通，但全面评估发现：表单保存和会话搜索存在竞态，声纹提取及账号删除存在生命周期缺口，桌面跨语言校验不一致，报告恢复入口与会议状态易误解，部分页面信息过密，以及查询、构建与测试仍有改进空间。

本 Spec 将问题转为可独立验证的修复项。详细证据保留在本地 `artifacts/project-assessment/`，本文件包含完整要求，实施不依赖该忽略目录存在。

## 目标与范围

- 覆盖评估中的六项功能缺陷、说话人错误传递、Web/Electron 界面问题、业务入口不一致、查询性能、交互测试及局部维护性问题。
- 保留现有功能、数据、权限、接口用途与黑白灰视觉风格；让每项修复都有对应回归或界面证据。
- 收敛流程状态的所有权与共享契约，不再进行顶层目录重构，不用文件数量或评分提高作为验收目标。

四个维度都属于必做范围，分别验收；不能只修功能缺陷就宣布整个 Spec 完成。

| 维度 | 修复范围 | 对应要求 |
| --- | --- | --- |
| 功能代码 | 异步竞态、声纹、跨层契约、认证权限、查询与加载性能 | R1～R4、R8 |
| UI 设计 | Web/Electron 信息层级、阅读空间、空状态、响应式及统计呈现 | R6、R7 |
| 流程设计 | 失败恢复、阶段状态、模型配置路径、资料删除和不同入口一致性 | R5，结合 R2、R4 |
| 目录结构 | 状态所有权、组件职责、业务用例复用、共享资源归属及测试组织 | R9 |

非目标：新增企业长期记忆、通用后台多任务自动编排、桌面自动更新或正式签名体系；替换模型、重新评测识别准确率、部署生产、重做登录页。这些是能力或发行边界，不是本次已发现缺陷。既有多步骤任务、上下文和报告入队行为仍需回归。

## 一、功能代码

### R1．保存与搜索的异步一致性

- 工作编辑、进展修正、报告编辑、汇报规则保存期间，禁用参与提交的字段及重复提交；已有草稿和失败恢复保留。
- 成功回调仅清理本次账号、记录、草稿版本对应的数据。切换记录、关闭重开或晚到响应不能清掉新的草稿，单纯禁用按钮不算修复。
- 使用小型可复用提交状态机制，不引入整套表单框架；创建工作、成员等已正确处理的表单保持现有行为。
- 会话搜索、游标和分页请求由同一 Hook 管理。切换关键词、关闭弹层、切换账号时取消旧请求；写回时再次校验请求代次。
- 加载更多期间防止重复请求；改名、删除、恢复上次会话和失败重试仍正常。

### R2．声纹提取与资料生命周期

- 子进程 stdout 循环读取至 EOF，按累计字节执行现有上限；stderr、超时、退出码、取消及子进程回收继续有界处理。合法分块 JSON 不能误报组件未就绪。
- 删除员工账号时同时移除该员工的服务端声纹模板及登记录音，释放登记额度，停止在途提取，阻止迟到结果重新落库。停用账号不删除资料。
- 数据库先持久化删除意图，再清理文件；失败可恢复和重试，不产生产品内无法管理的孤立资料。
- 既有已删除员工的遗留声纹提供管理员显式清理路径和影响预览，不在启动或数据库升级时静默删除。
- 保留工作、报告等业务历史；重新创建同名账号不继承旧声纹。服务器不追删已经离线的桌面副本，沿用原有同步及清缓存规则。

### R3．桌面契约与错误提示

- 说话人姓名上限统一为现有写入允许的 100 字符，按 Unicode 码点计数，覆盖 UI、IPC、Python 与文字分页读取；中英文、emoji 的校验不得互相矛盾。
- 既有 41～100 字符姓名可以直接读取，不要求用户重新命名或重跑识别。带姓名和纯文本视图都正常。
- 通信层保留经过审查的说话人领域错误，如时长超限、处理中、版本变化、目标无效；未知内部异常仍转为安全提示，不泄露路径或堆栈。

### R4．认证限流与业务权限一致性

- 密码登录按既有身份和时间窗口执行原子限流，保留目前失败次数语义；多个请求不能共享过时计数绕过限制。
- 限流不持有公司业务锁，不以临时关闭限流、增加密码限制或无限串行密码计算作为修复。
- 沿用管理员可以删除本公司任意员工报告的既有要求，包括未提交报告；**不因此开放未提交正文和私人材料的读取权限**。
- HTTP 与 Agent 共用删除授权、影响预览、版本检查和执行用例。对明确目标只返回确认删除所需的最小元信息，不增加草稿浏览入口；Agent 无明确目标时询问，不猜 ID。
- 员工不得删除已提交报告；跨公司、已撤权、目标变化、重复确认和共享来源清理规则保持有效。管理员删除关联原材料，不递归删除其他已确认工作或报告。

### R8．查询与加载性能

- Web 按路由延迟加载管理类页面；保持路由权限、返回、深链接和错误恢复。加载占位不导致整页白屏或已输入内容丢失，PDF 保持独立加载。
- 模型用量统计、筛选选项和分页下推 SQL，保留未知状态、时间边界、稳定排序及 token 缺失语义；不把整个期间用量记录先加载进 Python。
- 旧团队统计/明细接口保持兼容，复用授权后的 SQL 查询、聚合和有界分页，保留历史修订、可访问来源及员工口径。
- 将明确无写入的查询从公司级排他锁改为可并发的读路径；写入、撤权和删除继续保持必要排他保护。不得仅按 GET 方法一刀切去锁，也不得产生共享锁升级死锁。
- 用固定测试数据比较查询次数、读取记录数、锁等待与耗时；保留可复核前后结果，不承诺脱离环境的固定性能倍数。

## 二、UI 设计

### R6．Web 页面层级与响应式

- 空内容工作详情提供“补充工作内容”的直接入口；只读用户不显示无权执行的操作。已有摘要、进展、来源和历史正常展示。
- 手机端保留一个当前页标题和清楚的返回入口；完整层级仍可访问，避免重复面包屑/标题占两层。桌面多级面包屑保持完整。
- 手机团队报告只常驻关键统计、搜索与周期；其他筛选集中到可展开面板，展示已生效条件数量并支持清除。折叠不重置 URL 筛选或统计口径。
- 模型服务的连接信息、模型和用途有明确视觉层级，高级参数按需展开；窄屏文案不再指向不存在的“左侧”。
- 用量页成功率旁直接显示已知结果分母与未知次数；无已知结果时显示“暂无”，不伪造 100% 或把未知当成功。统计与列表使用同一筛选范围。

### R7．Electron 阅读空间

- 合并会议详情的标题、元信息与主要操作，减少重复小标题；详情页“开始会议”降为次级入口，功能仍可达。
- 模型版本、处理信息和说话人高级设置按需展开；错误、进行中状态及必须采取的操作不隐藏在折叠区。
- 在 1240×820 常用窗口、默认折叠状态下，文字正文可视高度至少 300 个逻辑像素；较小支持窗口仍能访问全部操作，无横向溢出。
- 播放器、进度跳转、快捷键、姓名/纯文本切换、引用回听、编辑说话人与纪要分析保持正常。
- Web 与 Electron 独立维护样式，保留浅/深色、键盘访问、合理焦点与减少动态效果设置。

## 三、流程设计

### R5．操作路径、失败恢复与状态含义

- 报告失败页只保留错误信息和一个“重试”按钮，使用最新有效模型配置；沿用工作助手的就地反馈方式，不让用户在两套配置之间选择。
- 点击后立即展示排队/处理中并防止重复提交，不弹等待任务完成才关闭的确认框；重试不重复创建报告、不覆盖已提交版本或人工编辑。
- 模型配置已失效时给出正常可操作错误，不能静默退回旧模型。自动重试仍固定当前执行轮次配置，不改变工作助手每节点的重试规则。
- 报告成功入队只显示“已开始生成”，通过已有任务状态展示结果或入口，不冒充“报告已生成”；不新增通用持久化任务编排系统。
- 桌面列表明确区分“录音完成”“文字处理中”“纪要待重试”等状态；主要提示突出下一步，不同时用模糊“已完成”掩盖失败阶段。
- 本次只调整报告手动恢复策略，其他独立 ASR/文档任务不因复用组件而意外改变行为。
- 模型服务围绕“连接服务 → 选择并测试模型 → 分配用途”组织。保留自定义地址、协议、手动模型、推理预设、多服务与未保存密钥处理，不增加重复配置向导。
- 恢复当前账号上次选中的服务；仅有一个服务时默认选中；服务被删除或切换账号时正确回退，不自动创建或保存服务。
- 连通性测试结果必须对应当前配置版本；输入改变后旧结果不能仍显示为当前有效。
- 删除员工时预览声纹和登记录音清理影响；遗留资料单独预览后清理，失败展示可恢复状态。具体保留规则见 R2。
- 手工界面与 Agent 对同一报告使用相同权限、确认和结果语义，具体边界见 R4；不让用户通过更换入口得到不同结论。

## 四、目录结构

### R9．职责、依赖与共享资源

- Web 保存、会话分页、模型配置各有单一状态所有者；通用提交机制留在公共 Hook，业务分页和模型控制器放各自 feature，组件只负责呈现与事件。
- Electron 按实际职责提取会议详情头部、文字工具区和模型配置 Hook；录音、播放器及其生命周期保留稳定所有权，详情页签切换和折叠不重复创建播放器。离开会议工作区沿用卸载并释放资源的行为，不新增跨页面持续播放。
- 后端 HTTP 与 Agent 复用报告业务用例，声纹清理由所属模块统一管理；底层锁、任务与资源工具不反向依赖界面或应用装配。
- 共用说话人权重移入现有 `packages/voiceprint-engine` 的资源目录，桌面和公司构建都从同一入口读取，保留固定版本、哈希、许可证及署名；不复制一份权重或重新下载。
- 开发默认路径更新，显式 `PAA_VOICEPRINT_MODEL` 配置仍优先；发行包内资源路径和模型 ID 不变，用户已下载转写模型、声纹缓存和会议数据不迁移。
- 新增 DOM 用例归入 `tests/web/dom/`，保留现有测试分区；同步真实变动的架构和路径说明。不机械按行数拆文件，不移动无关目录，也不合并两端私有样式。

## 技术约束与兼容

- 后端 HTTP 与 Agent 复用业务用例；前端 API 仍通过唯一客户端。公开接口保持兼容，新增 DTO 字段同步共享类型。
- 草稿、分页、模型配置分别有单一状态所有者；不靠增加全局状态容器解决局部竞态。
- 认证、权限、锁和持久化相关修改按 S3 验证；纯样式按直接影响检查，不为每个视觉调整重复完整测试。
- 真实业务环境只用于非破坏性的界面/流程查看；删除、并发、故障注入使用临时测试数据。不得操作生产或输出凭证。
- 不修改日常 CI 的触发和重检查范围。独立验收读取实施证据，对缺口补验证，不机械重复已通过检查。

## 验收标准

### 功能代码

- [x] R1：慢响应下的继续输入、关闭重开、切换记录/账号不丢新草稿；旧会话分页响应不会污染新搜索。
- [x] R2：合法分块、大输出、超限、失败、取消均正确处理；删除员工清理服务端声纹和登记录音，停用保留，在途提取不能复活资料，遗留清理可恢复。
- [x] R3：姓名合法上限、超限、emoji、旧数据及文字分页覆盖；领域错误安全且可操作。
- [x] R4：并发登录严格遵守限流窗口；HTTP/Agent 删除权限、预览和副作用一致，草稿正文不因删除能力泄露。
- [x] R8：路由分块生效；查询结果及权限与原口径一致；并发读不互斥，撤权/写入仍安全，并提供查询对比证据。
- [x] 本次新增竞态回归使用真实 React DOM 挂载与异步响应，不只模拟 Hook；既有测试保留。

### UI 设计

- [x] R6：工作详情空/有内容、手机筛选与导航、模型配置各区域、用量未知状态均实看并有截图；两种主题符合设计基准。
- [x] R7：桌面文字区域达到高度目标；纪要、播放器和说话人流程无回归；浅/深色和最小支持窗口可用。

### 流程设计

- [x] R5：报告只有一个手动重试入口；最新配置、版本保护和幂等有效；录音/文字/纪要状态含义明确。
- [x] 模型服务添加、选择、测试、用途分配、返回恢复及配置变更流程连贯；旧测试结果不误导用户。
- [x] 员工删除、遗留声纹清理及报告管理具有一致的影响预览、确认和恢复路径，和 R2/R4 权限规则一致。

### 目录结构

- [x] R9：提交、分页、配置状态各有明确所有者；拆分后的组件/Hook 职责清楚，没有重复业务逻辑或反向依赖。
- [x] 共享权重仅保留一份，开发/冻结/公司镜像资源定位正确；原路径消费者全部更新，哈希与许可证保持一致。
- [x] 测试归属、改造目录及架构说明与实际实现一致，无无关目录迁移。

### 集成交付

- [x] 相关 Web、服务端、桌面模块全量测试、类型检查、Lint、格式和普通构建通过；缺少的跨平台/发行证据明确列出。
- [x] 独立验收按四个维度分别给出结果与证据；任一维度存在未解决的范围内问题，整体不得标为通过。
