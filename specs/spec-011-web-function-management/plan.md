## 接口、数据与恢复

- 新增业务 `Conversation`，与现有登录 `Session` 区分；带公司、所有者、标题、更新时间及必要版本／删除状态。`Message` 增加会话归属，旧消息按原用户迁入默认会话，原 ID／回复／附件／任务关系保持。迁移不调用模型、不移动原文件。
- 会话提供列表／搜索、新建、读取、重命名与删除接口；消息列表、发送与草稿按会话定位。服务端检查公司／所有者、会话状态及 replyTo 归属。分页、重命名冲突和重复删除沿用现有接口约定，路由／来源跳转保留会话 ID。
- harness 的聊天历史仅加载当前会话，已确认工作可按权限跨会话检索。checkpoint 继续按既有任务／输入版本隔离，不直接改成共享的会话 ID；保留现有按用户串行调度，不因多会话增加并发模型请求。结果只能写回原始会话，切换页面不取消别的会话已接受任务。
- 工作／报告编辑沿用 revision 接口；删除接口在服务端区分员工、管理员、本人对象及报告是否曾提交。读取／修改／删除分别授权，不因管理员有报告删除权自动授予员工草稿内容读取或代提交权限。
- 管理员删除报告先解析其修订来源至消息 ID，按确认的 R2 清理原始内容和附件；不能按日期或所有者扩大范围。事务内标记删除并使相关任务失效，文件清理与失败恢复须可追踪；接口不得在原文件清理失败时谎报全部完成。只保留必要的无正文删除元数据。
- 关联删除同时处理回复、进展草稿、工具待确认结果、已捕获的模型上下文／checkpoint 等引用，避免已删原始文本继续被读取或重新生成。其他工作／报告的已确认摘要保留，来源显示已删除；原始消息清理不等于承诺删除已交付第三方的输入或历史备份。
- 删除会话和删除业务来源按 R7 分别执行；保留的来源不恢复为聊天历史。删除、编辑、确认、提交和 worker 写回采用一致锁序／版本判断；普通查询、统计、工具和任务恢复检查删除状态。报告周期唯一约束保留，已删周期不自动或经员工重试复活。
- 成员接口仅返回／创建／维护员工；账户自助改密不受影响。关闭管理员个人报告入口与新建／调度路径，助手／工作继续运行；不删除存量管理员材料。
- 面包屑使用类型化页面上下文、有效本地返回路径和对象归属构造，避免无限嵌套点击历史；刷新／直达能恢复合理父级，无权限时不泄露名称。时区集中复用中文标签、保留 IANA 值；时间选择按浏览器能力提供整框可用交互。
- 仅聊天文字区使用固定高度和内部滚动，父容器在短屏保证操作可达；每个会话独立保留草稿／附件状态，录音切换明确处理。限制弹窗复用实际校验，保留有效输入，不把网络或设备错误当作超限。

## 迁移与相称验证

当前文档为 S0，仅查 diff／引用／需求一致性。实施中的权限、删除及持久化属于 S3，公司 Web 属于 S2；只检查对应子系统。

- 增量迁移先备份，核对旧用户／消息／附件／来源／回复完整性；演练可用的恢复路径，文档阶段不修改数据库。
- PostgreSQL 固定样本覆盖角色／跨公司权限、已提交后再编辑不能删除、共享消息删除、会话来源保留、上下文隔离及删除与在途结果竞态。模型使用固定响应，不触及用户真实资料。
- Web 定向检查覆盖会话管理与草稿切换、来源导航／刷新、管理动作失败、固定输入与限制反馈；整理改动文件格式，执行相关 lint 和 `typecheck:web`。只有新增入口／构建受影响时补普通 Web build。
- 日常浏览器在桌面、390px 与短屏检查多级导航、两类角色入口、会话管理、时区／四个时间控件、连续换行／粘贴／删除和底部操作。使用现有账号观察，删除与竞态使用专门样本，不删除用户资料。
- 不主动运行 CI、Electron／ASR／安装包或生产部署验证；独立验收复用未变的通过证据，不机械重跑全站截图与全套测试。
