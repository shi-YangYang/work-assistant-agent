# Web 顶部 Noria 宠物与外观弹窗

## 状态

保留原版小熊与最初的眨眼效果。取消转头、建模与视频方案，保留浮层入口和主题弹窗。

## 背景

现有全局 Topbar 重复展示页面标题，并占用右侧内容区域。参考 Muse 的顶部宠物入口，以 Noria 小熊提供轻量陪伴和外观设置入口。点击后使用模态框。

## 目标

- 移除登录后全局 Topbar 的标题／面包屑、主题按钮和搜索按钮。
- 所有登录后页面共用一个位于右侧内容区域顶部中央的 Noria 宠物，工作助手与其他页面采用不同的闲置动效策略。
- 点击宠物打开外观模态框；保持导航、返回、搜索和通知可用。

## 非目标

- 不改 Electron，不改变 Agent 人设、执行权限或任务状态。
- 不增加宠物养成、活动记录、审批中心、改名、上传头像或 AI 换装。
- 不增加主题后端、账号同步接口或轮询，不重做各业务页面。
- 不调整登录页翻书结构与品牌。

## 当前行为

- `app/layout/Topbar.tsx` 在 Shell 内统一渲染，包含面包屑、移动导航开关、主题切换、员工汇报通知和搜索。
- 侧栏已有“查找页面与操作”，支持 `Cmd/Ctrl+K`；页面自身仍有标题、筛选及业务操作。
- 面包屑包含详情返回，且会读取记录名称；移除后不能留下额外请求或丢失返回入口。
- 外观设置已有浅色、深色、跟随系统，使用 `lib/theme.ts` 和浏览器本地偏好。
- Noria 目前使用共享的白底圆形小熊静态资源，没有专用宠物动作素材。

## 目标行为

进入页面 → 顶部中央显示小熊 → 点击打开“Noria 外观” → 选择外观立即生效 → 关闭后继续原页面。

宠物不另建会话、不触发模型调用，也不打断正在编辑、上传、录音或执行的任务。

## 功能需求

### 1. 移除全局 Topbar

- 删除原有整条横向背景、分隔线、标题／面包屑及其主题、搜索入口，不保留空壳占位。
- 保留业务页面自己的标题与操作，如工作筛选、报告切换、助手人设和会话管理。
- 搜索保留侧栏入口及快捷键；员工汇报通知迁至侧栏，保持未读数量、阅读和跳转行为。
- 手机／平板保留左上角独立导航按钮，不为它恢复整条 Topbar。
- 工作、报告、消息来源等详情页需要返回时，在页面内容附近提供单一返回入口，复用现有返回上下文；直接打开链接有明确的列表／助手回退。
- 历史工作版本继续保留“返回上一步／返回最新版本”，不增加重复按钮。

### 2. 顶部宠物

- 覆盖工作助手、我的工作、我的报告、团队看板、成员管理、全部设置及详情页；随现有角色权限显示页面。
- 相对右侧主内容区域居中，侧栏展开／收起时自动对齐，不能按整个浏览器宽度居中。
- 使用 Noria 小熊、白底圆形形象与紧贴下方的名称胶囊；胶囊使用轻阴影、柔和边界，浅深色均保留小熊原色。默认大小建议桌面 48～56px、手机 40～44px。
- 在 Shell 中常驻，切页不闪现、不重复入场。宠物以独立浮层覆盖在主内容上方，不参与文档流、不占据整行高度、不通过全局 padding/margin 重新制造空白。内容可从其下方滚动；浮层外围点击穿透，不能遮挡首屏标题、业务按钮和错误操作。窄屏仅对实际发生冲突的标题／操作布局做最小避让。
- 工作助手页面仅提供低频短暂眨眼，约 8 秒一次；使用原品牌头像与最初的闭眼素材，仅覆盖眼部，身体、外圆和名称胶囊固定。不转头、摇晃或上下浮动。标签上沿覆盖头像下缘，连接处没有空隙。鼠标悬浮／按压不额外缩放、旋转、改变阴影或触发动效，键盘保留静态焦点指示；其他页面默认静止。位置、尺寸和点击行为一致，不在页面间放大／缩小。
- 模态框内可预览同一眨眼效果。闭眼素材失败时保留原头像，原头像失败时显示 N；不使用视频、建模或实时 3D 依赖。
- `prefers-reduced-motion` 下使用静态形象；页面不可见时暂停循环；尺寸预留，资源失败不影响页面操作。

### 3. 外观模态框

- 只放宠物预览和页面主题选项：浅色、深色、跟随系统；不照搬 Muse 的多个功能页签。
- 复用已有 Modal 的遮罩、关闭、Esc、焦点约束和焦点返回；手机宽度适配，不出现横向滚动。
- 选择即生效并保存，无额外“保存”按钮；关闭不撤销已选择主题。
- 和“设置 → 外观”共用主题选择组件及 `lib/theme.ts`，刷新、切页、浏览器标签页同步仍按现有机制生效。
- “换颜色”仅指现有页面主题，不修改宠物毛色／围巾配色，不增加任意主题色。
- 默认不显示“已连接／执行中”等无可靠数据来源的状态。
- 按钮使用“Noria 外观”可访问名称与悬浮提示；设置页保留清晰的“外观”入口，避免只能靠猜测宠物用途找到主题设置。

## 显示范围调研与建议

- [Notion 官方指南](https://www.notion.com/help/guides/everything-you-can-do-with-notion-ai)描述页面角落与侧栏的 AI 入口；[Edge Copilot 官方说明](https://support.microsoft.com/en-us/microsoft-copilot/getting-started-with-copilot-in-microsoft-edge)提供浏览器右上角入口，跨网页打开侧栏。它们支持全局可达的设计思路，但不是“所有页面应放动画宠物”的证据。
- [Carbon 动效准则](https://www.carbondesignsystem.com/building-blocks/foundations/motion/overview)建议任务操作使用克制的动效，表现性动效留给少量重要时刻。
- 对 Noria 的建议：所有登录后页面保留同位置的小熊，只有工作助手有闲置动画。页面主题属于全局偏好，统一入口便于找到；工作、报告和管理页面使用静态形象，减少持续运动对阅读、编辑的干扰。
- 只在工作助手展示也可行，其他页面仍能通过设置更换主题；代价是宠物入口随页面消失、产品陪伴感较弱。全页面持续播放动画则增加与业务内容争夺注意力的风险。
- 这是结合产品目标的设计判断，尚未做 Noria 用户对比测试。Muse 的聊天页形象与点击行为已实看，其所有页面的显示范围未确认，不作为全页面覆盖的证据。

## 边界条件

- 顶部宠物不能让聊天列表、输入框或页面加载组件发生尺寸抖动，右侧仍使用既有滚动容器。
- 导航抽屉、业务弹窗打开时，遵循现有模态层级与焦点机制，不让宠物抢占输入。
- 切换主题不清空草稿、重建会话或触发数据刷新；现有统一错误出口继续有效。
- 管理员不新增员工汇报通知，员工不能通过调整入口进入管理员页面。
- 只清理 Topbar／面包屑移除后已无调用的前端代码，不删除业务读取接口或服务端 API。

## 技术约束

- CSS Modules 与组件就近维护；顶部布局属于 `app/layout`，可复用的主题选择属于公共展示组件。
- 品牌动作素材集中在 `packages/ui-web/brand/pet/`，各端不散放副本；此次只有 Web 使用新增动作。
- 沿用黑白灰设计准则。实施后在设计文档中更新顶部布局，并明确宠物低频动效作为陪伴入口的例外。
- 仅加载同源品牌图片，不新增业务网络请求、模型调用或运行时动画依赖，不改身份认证与业务权限。

## 兼容性要求

- 继续读取原主题偏好，保留外观设置路由和现有深链接。
- 详情返回、历史版本、通知跳转及搜索快捷键保持可用。
- 不改变数据模型、部署配置、聊天和业务操作合同。

## 验收标准

- [x] 登录后所有路由移除旧 Topbar，页面自身必要标题和功能保留。
- [x] 宠物以不占行高的浮层相对右侧内容区域居中；内容起点不下移，外围点击穿透；桌面、窄屏和抽屉展开均不遮挡操作。
- [x] 原版圆形小熊与名称胶囊贴合，仅保留短暂眨眼；减少动态效果及资源失败时正确静态回退。
- [x] 工作助手低频闲置动画、其他页面默认静止；切换页面不改变入口位置、大小和点击含义。
- [x] 点击宠物打开模态框，关闭／Esc／焦点返回正常。
- [x] 三种主题与外观设置双向同步，刷新保留，不产生额外业务请求。
- [x] 搜索、通知、移动导航、详情及历史版本返回均可用。
- [x] 打开弹窗或换主题不丢失聊天草稿、工作编辑内容，不重启任务。
- [x] 所有路由有视觉检查记录，覆盖管理员／员工、浅／深色、桌面／手机；不要求无关业务全量测试。
