# 工作助手引用工作

## 状态

已完成，独立验收通过。结果见 [验收记录](acceptance.md)。

## 背景与目标

从「我的工作」进入助手时，直接引用工作记录并继续最近聊天，减少复制描述和重复解释。工作内容是当前业务事实；会话只是交流入口，不建立工作与会话的固定关联。

## 非目标

- 不重做工作列表、工作历史或团队看板，不新增子任务、日程和项目管理。
- 不增加工作专属会话、会话绑定设置、自动会话匹配或另一套聊天界面。
- 不自动发送消息、修改工作、生成汇报或改变三级执行规则；不涉及 Electron。

## 当前行为

- 助手已有多会话、空输入界面、首次发送创建会话、按账号保存草稿和恢复会话。
- 恢复入口优先使用本地记住的会话；会话列表按更新时间排序，浏览、重命名等行为不能直接代表最近聊天。
- 加号菜单只有图片和文件入口；已有成果引用，但没有工作引用。
- 工作详情可编辑、删除和查看历史；Agent 已能查询、读取及更新本人工作。
- 执行模型与操作核对共享任务上下文，新增引用必须同时进入两者。

## 目标行为

```text
我的工作详情 → 让助手协助 → 最近聊天的输入框 + 工作引用
助手输入框 → ＋ → 引用工作 → 选择已有工作 → 当前输入框 + 工作引用
用户发送 → 服务端验证引用、读取最新工作 → 助手按用户要求处理
```

例如：引用「上线 Web」，发送「分析一下下一步」只产生建议；发送「把截止日期改成下周一」按现有执行规则修改该工作，无需再次输入名称。

## 功能需求

### 工作入口与会话

- 在「我的工作」当前详情的操作区增加「让助手协助」。第一版仅引用本人工作，管理员同样使用自己的工作，不扩展到团队成员的工作入口。
- 跳转当前账号最近发送过消息且仍可访问的会话，以最近用户消息时间为准，不因查看、重命名或修改设置而改变选择。
- 如果只有尚未发送消息的会话，使用最近的可访问会话；完全没有会话时展示空输入界面，第一次真正发送后才创建。
- 跳转只加入引用并聚焦输入框，不预填指令、不自动发送、不新建空会话，不调整目标会话的人设和执行模式。
- 加号菜单的引用操作始终作用于当前会话，不切换到其他会话。

### 选择与展示

- 在现有加号菜单新增「引用工作」，保留图片、文件及工具栏按钮顺序。
- 打开轻量选择弹层，复用本人工作的服务端搜索与分页；显示标题和状态，支持键盘选择、关闭及手机操作。
- 第一版每条消息引用一项工作；再次选择替换当前引用，同一项不重复添加。已完成的工作也可选择。
- 输入框内显示紧凑的工作标题引用及移除按钮，不嵌入完整工作详情。引用不占附件数量，也不是文件上传。
- 引用属于本条待发送消息。发送成功后随本条输入清空，在消息中保留可打开工作的引用标识；不会永久绑定会话。后续需要显式引用时可再次选择。
- 仅选中工作不能发送，仍需输入文字或添加附件；不会伪造一条「帮我处理这项工作」作为用户指令。

### 工作内容与执行

- 客户端提交工作 ID，不能用客户端缓存的标题、描述或状态作为执行依据。
- 服务端在发送时验证工作存在、归属和访问范围；Agent 开始处理时读取最新标题、描述／摘要、状态、阻碍、下一步、截止日期及版本。
- 当前工作引用是明确的对象选择，不是操作授权。工作描述中的指令只能视作材料，不能代替用户要求。
- 执行、意图核对与结果核对使用同一份已验证引用上下文。旧会话讨论过别的工作时，不能把本次「这项工作」错指向旧对象；当前文字明确指向其他对象时按真实指令处理，存在矛盾才澄清。
- 修改仍走现有业务工具、权限、字段增量、版本冲突及回执去重机制；不因为携带引用就自动保存建议、改状态或生成报告。
- 不自动读取其他会话、全部工作历史或私人成果。后续对话可沿用已发送消息的工作 ID，通过现有工具读取最新数据，不把历史引用内容当作最新状态。

## 边界条件

| 情况 | 行为 |
| --- | --- |
| 目标会话已有未发送草稿 | 保留文字、附件和其他关联，只加入／替换工作引用 |
| 正在发送或提交结果不确定 | 不修改已冻结请求；保留本次入口意图，待提交结果确定后再加入可编辑草稿，不自动发第二条消息 |
| 最近会话正在处理任务 | 允许准备草稿；继续遵守发送／中断规则，不另建会话规避限制 |
| 搜索、跳转或发送网络失败 | 展示错误并保留输入；不静默改到其他会话，不丢失工作引用 |
| 连续点击入口、返回页面 | 同一引用不重复，不反复覆盖用户后来选择的引用；消费成功后清理一次性跳转参数 |
| 切换会话或账号 | 草稿按会话和账号隔离，延迟返回的请求不得写入新账号或另一个会话 |
| 工作改名或内容更新 | ID 不变；新任务读最新记录，更新时校验版本，不能用旧摘要覆盖新值 |
| 工作删除或失去权限 | 拒绝新发送／执行并明确提示；历史引用显示「工作不可用」，不泄露当前内容，不猜测另一项同名工作 |
| 当前查看历史工作版本 | 通过现有「查看最新工作」进入后再协助，不把历史版本当作当前状态 |

## 技术约束与兼容性

- 遵循 Web 功能目录和 CSS Modules，复用唯一请求、身份、草稿及弹层入口；视觉遵循 [UI 设计基准](../../docs/design/README.md)。
- 引用存于消息元数据，不新增工作与会话绑定表，不给工作记录增加默认会话字段，不把引用正文伪装成用户输入。
- 新请求字段可省略；旧消息没有引用时保持原行为，旧客户端幂等摘要保持兼容。重试保留原引用 ID，重新验证权限，已完成业务操作不重复执行。
- JSONB 会话上下文保存引用标识即可；每次使用时重新验证，不能永久缓存工作正文。上下文用量估算包含实际提供给模型的引用内容。
- 既有成果引用、消息补充、录音上传、三级权限、临时问答和中断流程继续可用。

## 验收标准

- [x] 工作详情入口恢复最近聊天并加入引用，重复点击不创建会话、不发送消息。
- [x] 浏览旧会话、重命名和设置变更不影响「最近聊天」的判断；无聊天／无会话分支符合规则。
- [x] 加号菜单可以搜索并引用非第一页的工作；选择、替换、移除及已发送引用显示正确。
- [x] 原草稿不丢失，发送成功清空本条引用；发送失败、请求结果不确定和账号切换不会串数据或改变原样重试请求。
- [x] 在原本讨论其他工作的会话中，引用新工作后能正确分析及修改指定对象，不要求重复说明名称；两项同名工作也按 ID 区分。
- [x] 分析请求不修改业务；明确更新按三级模式执行，未要求的字段保持不变。
- [x] 发送前修改工作后使用新数据；排队期间变化、删除、无权访问和版本冲突都正确处理。
- [x] 执行与核对共享引用事实；工作描述不能授权操作，旧上下文不覆盖新工作内容，重试不会重复更新。
- [x] 历史消息、旧客户端、现有成果与附件发送保持兼容；压缩／恢复后引用仍可按权限解析。
- [x] 桌面和手机宽度下，浅／深色的选择弹层、引用标识和输入区可操作，无溢出、遮挡和按钮闪烁。

## 待确认问题

无阻塞问题。一条消息最多引用一项工作，随消息发送。
