# Agent 决策流转与上下文：问题与修复记录

## 当前结论

v8 必要系统返工已完成，独立验收 [PASS](acceptance-round-8.md)，无待实施的具体系统缺陷。后续搜索工具首轮可见调整也已[独立通过](acceptance-search-preload.md)，明确接受少量输入增长以减少工具加载往返，不属于再次用提示补丁纠正模型。已有迟问／材料 ID 及无效回执填写经过实际输入归因，按模型错误保留，不继续补提示或重测。真实全覆盖关闭未触发、R07 low 回退及其他历史限制见[总验收](acceptance.md)。以下保留历次返工依据，不代表当前仍需重复实施。

## v8 前的纯读取收束缺口（已修复）

独立 v7 审查确认，共享收束并未覆盖纯读取任务：仅模型在非探索调用上主动提交有效 `ready` 才关闭探索；未返回工具调用的 `pending` 不能代表尚缺用户需求，最终正文后的 delivering 也不能提前阻止多余探索。真实候选从未提交 `ready`，不能据此笼统归因模型。

- 在同一次主模型决策中表达下一步及尚缺事实，并关联实际工具回执；程序校验一致性和流转，语义充分性仍由模型判断。
- 不能新增独立审核模型回合，不能以调用次数、读取成功或目录返回判定充分；不要为了凑一次通过追加长提示。
- 已完成的全局错误分类、来源边界、保存及授权纠错验证保留；不能用单例成功替代此项设计验收。
- v7 两个定向真实保存成功，但授权累积纠错未触发，且 R02 仍迟问。结果单列，原 v6 失败及中位数不变。

## 第六轮共享授权纠错返工

真实 R02 high 续接暴露授权契约纠错振荡：四次响应在错误旧事项 ID 与缺失材料字段之间来回切换。共享 `authorize_intent` 采用首错即抛且重试只附加最近错误，已纠正约束下一轮消失。用户实际答复、目标与材料字段输入均完整，不是用户提示不足。基线未触发不能证明候选精简是唯一原因。

- 在单次核对请求闭包内按错误类别去重、有界保留约束；复用已有重试，不增轮次或模型节点。
- 对 Schema 合法且前提成立的输出可聚合独立引用／字段错误；无效前提仍安全拒绝。
- 最终必须由同一响应通过全部原校验，不能拼接多次输出放行。
- 新提案、来源或输入请求不继承上次约束，错误说明不进入会话历史或用户正文。
- 只复验该缺陷及相邻真实退化案例，保留冻结 v6 的完整矩阵和原失败，不重跑全部案例。

## 已发现问题

1. **可选收束提示变成执行障碍。** R03 low 明确追加 11 份成果，基线 21.91 秒、2 次主模型和 2 次既有核对；首版候选 62.66 秒、6 次主模型和相同 2 次核对。两次 `insufficient_receipts` 拒绝使模型继续加载工具、读取成果目录，最后去掉 `_flow` 才执行。前后均保存 11 份并保留原附件；增加的拒绝往返有直接代码证据，纯时间差还包含并发和模型波动。
2. **工具事实适配不一致。** 独立检查发现 `read_work_material` 准备页面引用被视为正文事实；部分实际图像／音频文字回执又被视为未知。两者分别有过早关闭与无谓补查风险。
3. **来源失效范围过大。** 每条回执保存整个上下文的材料和工作版本。读取 A、B 后修改 A，会错误使 B 的凭据失效。
4. **精简削弱字段语义。** `materials` 字段旁的“只传选中材料”和保留已有材料说明被移除；主模型并未收到授权模型的整段 `TASK_POLICY`，不能拿后者证明主模型知道追加规则。原有“不默认新建”也被泛化。恢复明确契约并合并重复规则，不能增加场景专用长提示。此次具体误传的概率归因仍未确定。

## 返工要求

- 以共享决策机制为修复单位。先按全部已注册工具列出输入、结果状态、证据类型、来源版本及恢复路径的覆盖表，再修同类问题；真实案例是回归样本，不是特殊放行条件。不得写员工、文件数量、具体话术或场景编号特判。
- 同一工具结果在原进度控制与新决策控制中保持成功、失败、部分完成及等待语义一致；需要统一适配时复用共享事实层，不各自累加互相矛盾的判断。
- `ready` 只控制探索是否关闭；无效标记保持探索开放，不凭它拒绝原本合法的执行。原有权限、来源、版本、幂等检查继续生效。
- 目录不等于全文，挂载附件也不以全文读取为前提。按真实工具结果明确已读事实、准备中引用及覆盖限制。
- 回执只关联真实涉及的来源，局部变更局部失效；无来源依据时不虚构完整性。
- 检查必要恢复是否被固定一次读取过早截断，有实际反例才扩展修复范围。
- 保留首版源码清单、失败回复和耗时。新候选另行冻结，只重测受影响场景；其他已通过结果不反复重跑。
- 在不同业务任务中验证同一规则，包括工作关联、文档及页图、音频、表格、网页、异步生成和执行后的补查；优先复用固定真实矩阵与最小确定性边界测试，不扩大为无关业务或整个仓库的重构。

## 第二轮共享契约返工

- 根据真实输出统一 `state=conflict`、`state=invalid_reference` 的失败与可恢复含义，覆盖成果、工作建议、督办及任务上下文。保留权限拒绝和终止状态，不能把全部错误泛化为可重试，也不增加固定模型回合。
- 图像像素完整不等于回答覆盖全文；直接图像与工作材料图像入口统一使用局部事实，除非有真实完整输出契约。针对性回答仍可支持局部问题。
- 测试使用真实输出形状，不额外添加工具根本没有返回的 category 来使测试通过。已经通过且未受改动影响的 R03 v2 low/high 结果保留，不为凑候选版本机械重跑。
- 详见 [第二轮独立 FAIL 报告](acceptance-round-2.md)。
- 实际输入计量发现 `_flow` 定义逐工具重复，文档和搜索治理输入反而增加。协议只说明一次、各工具使用紧凑对象声明，运行时继续严格验证；只合并已有重复语义，不删除必要事实、权限或恢复规则。主模型、授权模型、工具封套分开计量，不跨角色抵扣后宣称主提示词缩短。详见 `artifacts/agent-decision-flow/input-size-audit.md`。

## 第三轮共享流程返工

- 权限拒绝、取消、未知执行结果、明确停止及用户／系统负责的处理优先于通用失败。异常 wrapper 保留机器分类，嵌套与顶层结果统一解释；未知失败不能自动重新开放探索。
- 授权核对的拒绝与用户缺项冲突时仍拒绝写入；仅有效、可证实的用户缺项进入既有澄清路径，不能把明确拒绝改成继续追问授权。诊断理由不回流为用户正文。
- 首次工具决策必须区分用户选择与必要事实；普通直接回答保留短路径。结构化信息复用现有模型响应，不增加独立分类调用或完整任务表；无字段的旧调用保留原安全兼容路径，不制造格式修复循环。
- 详见 [第三轮独立 FAIL 报告](acceptance-round-3.md)。共享机制和实际首问都修复后再继续固定矩阵，不能只凭单元测试通过交付。

## 尚需观察

- v4 两档 R01 首轮均声明 `execute` 并加载工具，仍未首轮提问；第二轮因宿主合盖休眠超过租约而取消。首轮语义观察保留，空回复及约 50.7 秒单调时钟不作为质量／完成耗时结果。不得据此增加关键词补丁或重跑到符合预期。

- R01 low 首问从 75.57 秒／4 次主模型降至 33.15 秒／2 次主模型，但仍先加载工具，不满足首轮即可澄清的目标。实际答复后两版均保存成功，候选曾把原附件纳入新增列表而被原选择校验拒绝；不能仅凭一次结果归因为本次改造。
- R05 low 两版直接回答预算与交期，分别 3.53／3.35 秒。候选另写“交付以需求确认为前提”，超出材料明确表述；保留为质量疑点，不能只凭数值正确判全通过。

## 第四轮后续读取边界

- 实际成功操作造成事实或来源版本变化时，允许原请求尚未完成的必要查询；新版本、真实回执与具体缺口共同支持局部重新读取，不能把成功当作无条件重开所有工具。
- 产生终止冲突的业务层返回明确停止契约，恢复层继续允许真正可修复的版本／参数冲突。检查同类结果，不根据中文报错匹配。
