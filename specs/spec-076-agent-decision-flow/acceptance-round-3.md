# 验收

## 结论

FAIL。独立验收仍发现共享恢复分类缺陷；冻结 v3 的真实 Web 首问也未达到及时澄清目标。

## 需求覆盖

- 前两轮的裸冲突失败分类、视觉局部事实、无效 ready 兼容和紧凑协议修复方向成立。
- 真实权限检查仍拦住未确认的写入。问题是错误继续探索与迟问，不是权限绕过。
- 低强度 Web R01 在约 139.53 秒后问题落盘可用，总耗时 139.70 秒；经过 4 次主模型和 2 次既有辅助核对。不能把问题落盘时间当作精确浏览器显示时间。
- 明确回答后续接 45.83 秒，新增 11 份材料、保留原 1 份，正文及状态未变；不能用续接成功抵消首问失败。

## 验证

- 独立验收只读核对共享适配及实际工具 wrapper，以注入 HTTP 403 的纯边界探针检查真实返回形状；未运行模型或重复模块套件。
- 主 Agent 在浏览器完成真实发送、问题回答、结果和工作详情核对；记录位于 `artifacts/agent-decision-flow/web-v3/`。
- 本轮业务模块检查沿用实施阶段 109 项有效通过记录；这些检查不证明真实首问及时性。

## 问题

1. `recoverable_result` 将泛化的 failed/unavailable/error 判为可恢复，未完整处理嵌套分类、明确 stop 和恢复责任。业务、成果、生图、记忆、执行工具的部分异常 wrapper 丢失 HTTP 权限分类；团队查询嵌套错误；提问将 HTTP 403 归为参数错误。
2. 真实 `saved_step_conflict` 和 `interaction_already_processed` 的 `recovery.nextAction=stop` 被忽略，重新开放了不应继续的探索。
3. R01 首轮所有调用均未带可选控制信息，实际顺序为加载工具、查工作、尝试更新、范围与授权核对、提问。提问仍默认“追加附件”，没有先确认操作含义。
4. 授权输出同时包含 not_requested 与有效用户缺项时，归一化丢弃缺项，主模型再改写问题。流式输出曾出现内部拒绝理由；最终正文正常不能证明流式没有泄露。

## 回归风险

未知错误不能自动开启探索；也不能反向禁止版本刷新、参数修复及必要目录到正文读取。首次语义决策依然由模型承担，程序不能声称能够独立识别全部歧义。

## 待处理问题

按全部注册工具统一机器分类和恢复优先级；保留拒绝的同时将安全、有效用户缺项直接转入既有提问路径。首次工具决策补足明确的短契约，覆盖预加载入口，不增加独立模型回合，不写员工、文件数或原话特判。返工后冻结新候选，由新的独立验收 Agent 验收，再继续固定真实矩阵。
