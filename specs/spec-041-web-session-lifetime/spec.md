# Web 登录有效期与自动续期

## 状态

已实施，独立验收 [PASS](acceptance.md)。验证范围见 [实施结果](implementation.md)。

## 背景

Noria 当前登录固定 8 小时后失效，即使用户一直使用也需要重新登录。改为闲置过期与最长有效期结合，减少日常使用中的登录打断。

## 目标

- 登录后按 7 天闲置期限续期，从本次登录起最长保留 30 天。
- 随正常业务请求续期，不增加保活请求、轮询或登录操作。
- 保留退出登录、密码修改、账号停用和权限变化时已有的会话撤销机制。

## 非目标

不增加“记住我”、会话管理页面、管理员时长配置或过期倒计时；不改用 JWT／Refresh Token；不改登录页视觉、钉钉授权流程或桌面端的离线声纹策略。

## 当前行为

- 账号密码与钉钉登录共用会话签发逻辑，数据库 `Session.expires_at` 与 Cookie `Max-Age` 均为 8 小时，不续期。
- 服务端保存会话令牌摘要、创建时间与到期时间，浏览器使用 HttpOnly Cookie；写请求另有 CSRF 和来源校验。
- 桌面授权目前直接继承 Web 会话的到期时间，需要避免被本次 Web 改动顺带延长至数周。

## 目标行为

| 场景 | 行为 |
| --- | --- |
| 密码或钉钉登录成功 | 初始有效期 7 天，记住本次登录时间 |
| 有效期内继续使用 | 正常业务请求按需续至当前时间后 7 天，不超过本次登录后第 30 天 |
| 长期没有使用 | 当前闲置期限到期后重新登录 |
| 连续使用达到 30 天 | 重新登录，成功后开始新周期 |
| 关闭浏览器后再次打开 | Cookie 未被清除且服务端会话仍有效时保持登录 |
| 退出、改密、管理员重置密码或停用账号 | 按已有撤销范围立即失效，续期不能恢复旧会话 |

例如：周一登录，周五继续使用后可续至下周五；即使每天使用，也不能越过本次登录起的 30 天上限。

## 功能需求

### 续期与请求

- “使用”指已登录用户的有效业务访问，不监测鼠标移动或键盘活动。整页打开／刷新身份、普通列表查询及业务提交可触发续期。
- 只处理鉴权成功且响应成功的请求；身份不明、账号失效、权限不足、CSRF／来源校验失败、校验错误和服务器错误不续期。
- SSE 订阅及心跳、任务状态恢复查询、后台自动轮询、健康检查不作为续期活动。切回可见标签页或网络恢复时，已有的一轮身份／业务同步可以续期，不为续期新增同步。
- 同时被自动刷新使用的读取接口统一排除：报告列表／详情、工作详情、汇报待办、通知、团队工作区、业务来源及声纹列表。仅在 SPA 内阅读这些接口的数据不续期；整页重新打开时的身份请求及正常业务写入仍可续期。
- 登录签发、退出和改密响应不再叠加普通续期 Cookie，避免覆盖新登录或清除 Cookie 的结果。
- 同一会话通常最多每 30 分钟写入一次续期；首次访问旧会话和最后一次补齐 30 天上限可例外。闲置期限以最近一次记录的续期为准，与最近一次业务访问的偏差不超过 30 分钟。
- 正常业务返回后，由浏览器接收更新后的 Cookie；不弹出“已续期”提示，不改变现有接口响应体。

### 会话有效性

- 服务端时间为准；有效截止时间为 `min(续期时间 + 7 天, 登录时间 + 30 天)`。到期即无效，不允许过期后的请求续回有效状态。
- 复用现有 `created_at` 和 `expires_at`，登录时间在续期时不改变。令牌、CSRF 值和会话 ID 不因续期而更换。
- Cookie 有效期依据服务端已确认的到期时间计算，保留 HttpOnly、SameSite、Secure 和 Path 规则。只有经过短事务重新确认当前会话仍有效后才可回写续期 Cookie；节流期间不根据请求开始时的快照补发，避免旧请求覆盖切换账号后的 Cookie。
- 并发续期不得回退数据库到期时间、重复创建会话或复活已撤销会话。续期失败不把已经成功的业务操作变成失败，保留原有效期，也不能发送未经持久化确认的延期 Cookie。
- 续期只作用于当前会话，不延长同一账号的其他设备会话。

## 边界条件

- 长请求和后台任务不因运行而无限续期；响应时已过期的会话不能续期。已提交任务继续按原有任务生命周期执行，再次读取受登录校验约束。
- 断网不续期，恢复后只在原会话仍有效时续期。保留现有网络错误与登录过期的区分，不自动重发业务写请求。
- 多标签页共享 Cookie；账号切换继续清理原账号前端缓存。任何旧令牌都不能绕过服务端撤销校验。
- 隐私模式、用户清除 Cookie 或浏览器限制存储可能提前结束登录，不承诺客户端一定保存满有效期。

## 技术约束

续期规则集中在认证模块，由 HTTP 层统一接入；业务页面不各自实现续期，不引入外部缓存或每个请求的额外数据库写入。保持现有公司隔离、锁顺序和权限检查。

## 兼容性要求

- 无数据库结构迁移，不批量延长已有会话。尚未过期的旧会话在下一次符合条件的访问时续期，30 天从其原创建时间计算；已经过期的会话仍需登录。
- 发布时不强制所有用户退出。旧 Cookie 若在用户再次访问前已到期，仍需要重新登录。
- 密码与钉钉登录使用同一 Noria 有效期规则，钉钉授权码、state 和身份核验证明的短有效期不变。
- 桌面端不新增滑动续期。新签发桌面令牌最多有效 8 小时，并且不超过授权时 Web 会话的有效截止时间；已签发桌面令牌保持原到期时间。Web 会话撤销对桌面授权的关联失效保持不变。

## 验收标准

- [ ] 密码与钉钉登录均签发 7 天会话，关闭并重新打开页面后可复用有效 Cookie。
- [ ] 正常业务访问按规则续期，数据库和 Cookie 都不超过原登录时间后 30 天。
- [ ] 30 分钟内连续请求不反复写入；新页面访问和正常读写无需专用续期请求。
- [ ] 后台订阅／恢复查询不续期，错误响应与未授权请求不续期。
- [ ] 到期、撤销、改密、账号停用后的令牌无法续期或访问数据；并发续期不恢复失效身份。
- [ ] 数据库提交失败或续期失败时不会宣称延期成功，不诱导重复执行业务操作。
- [ ] 旧会话可平滑过渡且保留原登录时间；过期旧会话不会复活。
- [ ] 桌面授权保持最多 8 小时，钉钉临时授权期限不变。
- [ ] 登录过期跳转、账号切换、CSRF、多标签页和助手任务订阅无回归；没有新增轮询或前端闪烁。
