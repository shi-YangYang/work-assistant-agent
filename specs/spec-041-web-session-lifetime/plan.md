## 修改顺序

1. 在认证模块建立统一期限计算：7 天闲置、30 天绝对上限、30 分钟节流；以现有 `created_at` 作为本次登录起点。
2. 修改公共会话签发逻辑，使密码与钉钉登录自动采用同一策略，Cookie 与数据库使用同一时间基准。
3. 增加响应阶段续期适配，复用鉴权写入的 `request.state.session`，统一判断成功响应及可续期请求。明确排除订阅、任务恢复、后台轮询和会话签发／撤销端点，禁止各业务模块散落续期代码。
4. 实现短事务条件更新与 Cookie 回写，验证与退出、改密、停用及并发请求的交互。
5. 限制桌面授权交换的令牌期限，保留现有授权协议和撤销关系。
6. 补齐相关测试与架构说明，交新的独立验收 Agent 检查。

## 数据流与并发

```text
业务请求 → 原有鉴权、权限与 CSRF 校验 → 原有业务事务
         → 成功响应前判断是否符合续期条件
         → 必要时短事务更新原会话 → 提交成功后附加 Set-Cookie
```

- 不符合条件或未达到节流阈值时直接返回，不额外开启续期事务。
- 节流期间不补发 Cookie，避免慢请求携带的旧快照覆盖新登录状态。自动刷新复用的 GET 接口按集中路由集合排除，纯 SPA 阅读这些接口不视作活动；不增加前端活动标记或请求。
- 到期时间最多推进至 `min(当前时间 + 7 天, created_at + 30 天)`；距上次推进不足 30 分钟通常跳过。旧 8 小时会话的有效期明显短于候选期限，可在首次有效访问时直接升级；临近绝对上限允许最后一次补齐。
- 在续期事务中重新核对当前成员和会话，沿用公司锁顺序；使用带有效期、原会话身份与新期限条件的更新，不依赖请求开始时的旧对象直接覆盖。不插入或恢复会话记录。
- 并发请求只有符合条件的更新落库；未更新者不得用旧快照生成更长的 Cookie。服务端校验始终为最终依据。
- 若续期响应丢失，浏览器可能仍在原 Cookie 期限到期时要求重新登录；不为掩盖这种网络边界而在每次请求补发令牌。
- Cookie 按已提交的有效截止时间计算剩余秒数，不能每次响应无条件写满 7 天；保留已有 Cookie 的安全属性。
- 普通续期不得覆盖响应中登录签发或注销删除的 Cookie。续期故障只记录服务端错误，保持成功业务响应及原会话期限。
- 不在模型请求、附件解析或 SSE 生命周期中持有续期事务或数据库锁。

## 接口变化

现有路径、请求参数、响应体和错误码不变。仅在登录成功或符合条件的业务响应中更新 `Set-Cookie`；不添加 `/refresh`、前端定时器或请求活动上报。保持现有 401 登录过期处理和非认证错误的展示。

## 测试计划

实施属于 **S3：认证与持久化会话逻辑**。使用可控时间和隔离测试数据库，不等候真实天数，不调用真实模型或钉钉服务。

### 服务端

- 新登录、第 7 天／第 30 天前后边界、30 分钟节流与最后一次上限补齐；检查数据库到期时间、Cookie 属性与剩余期限。
- 密码与钉钉签发一致；旧有效会话升级、旧过期会话拒绝；临时 state／授权证明不随普通访问延期。
- 普通读写、身份恢复与错误响应；订阅／恢复查询持续发生时，会话仍按原期限失效。
- 同会话并发、退出并发、改密并发、成员停用／权限撤销；更新不倒退、不复活会话。检验锁顺序及事务失败后的响应。
- 多账号与多会话隔离；桌面交换最多 8 小时，Web 退出仍撤销关联桌面令牌。

### Web 回归

复用现有认证与缓存检查：

```sh
npm run test:web -- tests/web/dom/login.test.tsx tests/web/api.test.ts tests/web/query-resource.test.ts tests/web/session-drafts.test.ts
```

用本地浏览器验证登录、刷新、关闭后重开、主动退出、切换账号、过期后重新登录，以及发送消息和接收进度。通过测试时钟或隔离会话模拟到期；查看网络记录确认无额外续期请求，不改真实用户会话。

检查通过后停止；仅具体失败或发现其他会话入口受影响时扩大范围，不默认运行真实模型、桌面打包或全产品测试。

## 风险与迁移

- **无需 schema migration**：沿用 `created_at` 和 `expires_at`。部署不批量更新旧数据，访问时仅延长仍有效的原会话。
- **响应与提交顺序**：业务提交后再续期，续期提交后才写 Cookie；覆盖字典响应、显式响应和异常路径，避免头部与数据库不一致。
- **后台保活**：核对现有自动请求来源，按请求职责统一排除，不依靠 HTTP 方法猜测所有 GET 都是用户活动。
- **跨端耦合**：桌面令牌新签发采用 `min(交换时间 + 8 小时, Web 会话到期时间)`，不直接继承数周期限。
- **回滚**：旧代码仍能读取现有字段，但已延长的会话不会自动缩回 8 小时。紧急回滚如需恢复旧期限，只能显式缩短现有 `expires_at`，不能重置创建时间或延长已过期记录；浏览器残留 Cookie 仍由服务端拒绝。
