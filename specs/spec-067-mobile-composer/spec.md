# Spec 067：手机端聊天输入栏与功能面板

## 状态

已完成，独立验收 PASS。采用紧凑输入栏与下方功能面板，思考强度、执行权限和上下文全部收进“＋”；视觉继续沿用 Noria 的颜色、图标及控件。验证范围与真机限制见 [验收记录](acceptance.md)。

## 背景

手机端文字区下方同时排列附件、执行权限、上下文、思考强度、录音和发送。固定的文字区最小高度和密集操作区占据较多屏幕，图标含义也不够直观。

## 目标

- 手机端常态输入栏保持单行起步，把空间优先留给输入和聊天内容。
- 次要功能通过带文字名称的面板访问，保留所有现有能力及可见状态。
- 正确处理软键盘、功能面板、附件预览、录音和任务运行之间的切换。

## 非目标

- 不改变桌面布局，不增加表情、位置、通话、红包等参考图中的其他业务。
- 不修改 Agent 提示词、工具、任务执行流程、模型强度值、全会话执行权限规则或 API。
- 不重新设计人设、会话列表和顶部导航；不改动录音时长上限、上传限制及长按判定阈值。
- 不新增 UI 依赖，不实施整站弹窗改造。

## 当前行为

- `MessageComposer` 同时承载文字、附件、引用和控制项；手机文字区当前最小高度约 65px，控制项另占一行。
- “＋”展开附件浮层，支持添加图片、添加文件和引用工作；现有第三项是“引用工作”，不是独立文件库。
- 思考强度来自管理员配置，执行权限是账号级设置；上下文面板展示当前估算及处理状态。
- 语音支持点击开始／停止并预览后发送，以及长按录音、松开发送、上滑取消。
- 发送按钮在任务运行时变为中断，未确认发送结果时提供原样重试；这些业务状态必须保留。
- 页面已有可视视口适配、附件横向预览和输入区高度测量机制。

## 目标行为

### 1. 主输入栏

```text
空白： [语音] [询问 Noria…              ] [＋]
草稿： [语音] [文字内容…       ] [＋] [发送]
运行： [语音] [文字内容…       ] [＋] [停止]
```

- 手机沿用现有 `760px` 断点。左右按钮与文字区横向排列，图标位于文本框之外，避免把所有操作包在一张大卡片里。
- 空白时不显示无效的发送按钮；有可发送的文字或附件时出现发送按钮；任务运行／中断中、重试待确认等状态不能因草稿为空而隐藏主操作。
- 输入区单行起步，随内容增高到约四行后内部滚动；保留 `询问 Noria` 占位文字。输入文字建议 16px，常用触控目标不小于 44px。
- 收起状态、无附件且无录音／提问提示时，主体高度目标约 60～72px（不含底部系统安全区）。高对比、大字体或多行内容下允许自然增高，不截断操作。
- “＋”在有文字时继续保留，可以边写边添加附件；发送／停止固定在最右侧。
- 发送、上传、录音、权限设置保存、身份恢复等禁用条件沿用现有规则；任务运行时不额外开放原本不允许的操作。

### 2. 更多功能面板

点击“＋”在输入栏下方展开，面板与输入栏连成底部区域，上方聊天区相应缩小，不使用遮住整页的模态框。

```text
[添加图片] [添加文件] [引用工作] [上下文]

思考强度                         high  ›
执行权限                     逐项确认  ›
```

- 第一排为带图标与文字的四个入口，支持窄屏自动调整列数，不照搬参考图的大尺寸图标。
- 思考强度及执行权限使用两条紧凑设置行，直接展示当前值；思考强度未配置时沿用原有不展示规则，不编造默认档位。
- 执行权限仍须保留开启自主执行时的确认，不因入口迁移而跳过；设置失败不先显示保存成功。
- 上下文展示实际估算状态并可查看详情；不新增计算请求或轮询，不将已有错误／恢复提示仅藏在关闭的面板里。
- 面板不做横向分页或空功能占位；高度随内容及可用视口限制，必要时内部滚动。
- 添加图片／文件继续使用系统文件选择器；“引用工作”沿用现有选择流程。进入选择器前收起功能面板；取消选择后保留草稿，不自动弹出键盘。
- 上下文入口名称与占用比例同一行；执行权限行只显示名称与当前值，范围说明保留在自主执行确认中。
- 手机端上下文、思考强度和执行权限均复用居中弹窗，支持关闭按钮、遮罩和 Esc；桌面保留原浮层。同一时刻只打开一项详情或选择层。

### 3. 键盘与面板切换

- “＋”打开面板时让文本区失焦并请求收起键盘；键盘收起期间按实际可视高度约束面板，避免两者叠加遮住输入栏。
- 点击文本区先收起面板，再由这次用户手势唤起键盘；不使用异步延迟焦点假定移动浏览器能自动唤起键盘。
- 再次点击“＋”或点击聊天内容区域收起面板；不自动发消息，不丢草稿，不强制唤起键盘。
- 切换会话、切换账号、离开聊天或进入桌面断点时关闭面板及附属浮层；保持现有草稿恢复语义。
- `aria-expanded`、入口名称、键盘关闭和焦点返回完整；可用物理键盘时 Esc 先关闭最上层，再关闭功能面板，不干扰输入法组合输入。

### 4. 录音、附件与特殊状态

- 保留点击录音／停止后预览发送，以及长按、松开发送、上滑取消；不新增需要先切换模式的“按住说话”页。
- 开始录音时收起功能面板；申请权限、录音秒数、停止处理及取消反馈仍清晰可见。开始录音的失焦处理不能触发现有长按取消流程。
- 待发图片、文件、语音及工作引用放在主输入栏上方的紧凑区域，有内容时才出现；继续支持横向浏览、移除和预览。
- 文字、附件、工作／成果引用、补充消息关联及发送幂等键继续由原草稿逻辑管理，面板只管理显示状态。
- 语音转写、上传失败、离页录音保护、发送结果待确认、问题补充及任务中断仍有明确入口，不因压缩高度而被隐藏。
- 长按手势被取消、麦克风权限拒绝、键盘弹出或系统文件选择器返回时，不能误发送或发出两条消息。

## 边界条件

- 覆盖 320、390、430px 宽度，横屏、软键盘弹出和底部安全区；没有内容时不能保留功能面板的空白高度。
- 用户停留在历史消息时，面板开合不强制滚动到最新消息；原本贴底时保持最后消息与输入栏之间的合理位置。
- 更改主操作显示与布局不能造成录音控件、输入框或请求 Hook 重挂载而丢失状态，不能同时挂载两套有效移动／桌面控制项。
- 面板关闭后，内部按钮不保留在 Tab 顺序或辅助技术可访问树中。
- 钉钉 WebView、Safari、Android 浏览器对键盘和文件选择器行为不同，自动化仿真与真机验证分别记录。

## 技术约束

- 继续使用 React、CSS Modules、Lucide 及现有基础控件；手机功能组件就近放在 assistant/composer 中。
- 复用现有录音、附件、执行权限、思考强度与上下文状态。新增状态仅限面板开合及交互协调，不复制后端状态。
- 沿用 `useMobileViewport`、`--app-height`、`--viewport-top` 和输入区 `ResizeObserver`；不叠加另一套全局视口高度或固定键盘高度。
- 只调整前端呈现与事件协调，不新增模型请求、服务端接口或数据库迁移。

## 兼容性要求

- 桌面输入框保留现有布局与快捷键；手机保持 IME 组合输入安全、附件粘贴和发送／原样重试语义。
- 原有上下文更新、全会话权限、下一条消息强度、长按发送和离页录音保护继续生效。
- 不减少图片、文件、引用工作、上下文、强度及权限功能的可用性。

## 验收标准

- [x] 手机空白输入栏单行起步，常态只显示语音、文字输入和“＋”；草稿及任务状态下正确出现发送／停止／重试。
- [x] 其余功能通过带名称的面板访问，当前强度与权限值准确，桌面布局保持原样。
- [x] 浏览器及固定事件验证中，键盘与面板切换无空白残留、重叠遮挡和焦点循环；聊天滚动位置符合上述规则。
- [x] 添加／移除／预览附件和引用工作正常；固定事件验证系统选择器取消后保留草稿且不误发。
- [x] 点击录音和长按发送的固定事件用例通过；拒绝权限、上滑取消、指针丢失、切页及系统打断沿用现有控制器与回归用例，真机录音未验收。
- [x] 运行中断、失败重试、提问面板、录音及转写状态可达；发送与设置保存的禁用规则无退化。
- [x] 手机窄屏、桌面、浅／深色及键盘操作定向验证通过；真实设备未验证部分明确标注。
