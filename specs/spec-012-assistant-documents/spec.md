# Spec 012 — 工作助手文件发送与解析

## 状态

**PASS · 2026-09-13。** 已实施并通过返工后的独立验收；范围、修复历史与未验证项见 [验收记录](acceptance.md)。

## 背景、当前行为与目标

用户希望在工作助手发送 PDF、Word、PPT、TXT、JSON 等文件并让助手理解，同时明确文件如何保存，将“语音文件”入口改为“文件”。当前 `Attachment` 只有图片／音频，非图片上传按音频校验，原文件在服务端私有 `PAA_MEDIA_DIR`，PostgreSQL 保存归属和消息关系；worker 仅处理图片和语音转写。

目标是在现有多会话与业务 harness 中完成“发送文件 → 解析 → 带来源回答／生成待确认进展”，保留原文件、现有消息权限及 [Spec 011](../spec-011-web-function-management/spec.md) 的删除语义。解析、存储取舍见 [决策 0013](../../.ai/decisions/0013-document-ingestion.md)。

## 功能需求与目标行为

### R1 — 文件入口与发送

- 管理员和用户的工作助手将“语音文件”改为“文件”，可选择本轮支持的文档和既有音频／图片；保留拍照／图片快捷入口与录音按钮，不要求用户判断使用哪个解析器。
- 发送前显示文件名、类型、大小与移除动作，支持文字搭配附件和多选；上传、发送、解析分别有真实状态。文件跟随当前会话草稿，切换、失败和重试不能串会话、丢文字或重复创建消息。
- 文档与图片可混合，每条最多 4 个附件、合计不超过 20 MiB；单图仍不超过 5 MiB，音频仍每条 1 段、180 秒／20 MiB，保持单独发送。超限／不支持格式使用现有弹窗，不添加常驻限制 tip。
- 消息中的文件卡片提供解析状态、查看已提取内容、下载原文件和失败后的明确处理入口；手机卡片、长文件名及内容查看延续当前主题和全宽响应式，不增加全局文件管理侧栏。

### R2 — 格式与解析边界

| 类型 | 首版范围 |
| --- | --- |
| PDF | 提取文字层，保留页码；PDF 表格按可提取文字处理，不承诺复杂表格关系或版式完全还原 |
| Word `.docx` | 按正文顺序提取段落与表格文字，以段落／表格定位，不伪造 Word 页码 |
| PowerPoint `.pptx` | 提取幻灯片文字、表格及已有演讲备注，以幻灯片定位 |
| `.txt`、`.json` | TXT 保留行号；JSON 校验语法并保留字段结构和定位，不执行其内容 |
| `.md`、`.csv` | 首版直接支持，分别按文本／行列提取，不执行嵌入 HTML 或公式 |

- 首版格式为 PDF、DOCX、PPTX、TXT、JSON、MD、CSV；旧版 `.doc`／`.ppt`、Excel 等其他格式不在本轮范围，选择时给出转换格式的明确提示。不能把不支持的扩展名放进可选白名单再伪装成解析成功。
- 本轮仅处理文档内可直接读取的文字，不做扫描件 OCR 或文档内图片／图表的视觉理解。若只能读取部分材料，明确展示缺失范围；无可提取文字时提示原因，不让助手声称全文已读。已有图片消息处理保持原行为。
- 损坏、加密、无法识别的编码或无效 JSON 给出对应原因；不静默丢弃文件或用乱码生成结论。原文件保持不变，不重写文档。
- 上传和解析异步衔接，失败可重试，已成功的解析可复用。单文件失败不撤销已发送消息或其他成功附件；回复明确已使用和未能使用的材料，不能将部分成功描述为全部成功。

### R3 — 助手理解与业务来源

- 首版支持围绕当前会话文件总结、提问、对照和提取工作信息；只发文件时给出简短内容概览并询问处理意图，不自动把附件内容算成已完成工作或已提交报告。
- 文件以原始消息为业务来源，回答能引用文件名与页／幻灯片／段落／行等实际位置；引用可打开对应提取内容。进展仍通过现有待确认建议落库，日报／周报仍只使用已确认工作。
- harness 通过受控工具按需查找／读取分段内容，遵守现有调用与上下文预算；大文件不能一律整份塞入模型，不能截掉后半篇却宣称做了全文总结。无法在预算内覆盖的请求如实说明范围并允许缩小问题。
- 默认仅读取本人当前会话文件；其他会话已确认工作的来源沿用现有授权追溯，不能检索其他会话闲聊或其他员工的私有附件。管理员的团队来源查看不等于新增跨员工 Agent 问答权限。
- 文件内容是业务材料，不能改变工具权限、系统约束或触发宿主机命令、宏、外部链接请求。解析本身不调用大模型；回答沿用公司已配置的工作助手服务。

### R4 — 存储、权限与删除

- 原文件继续保存到服务端私有持久目录；开发时是本机服务端的 `data/company/media`，部署后是服务器持久卷，不是员工浏览器缓存或容器临时层。旧附件路径和 ID 保留。
- PostgreSQL 保存公司／上传者／消息归属、文件名、校验值、状态、解析版本及可定位的文字分段；原文件二进制不塞入聊天记录。文件按内部 ID 寻址，原始名称只作显示。
- 附件卡片、原文件下载、提取内容和 harness 工具统一执行现有消息权限；未发送文件仅本人可读，已发送员工材料沿用管理员团队查看权限，不产生公开文件链接。
- 上传未发送的孤立文件沿用既有 24 小时清理；文件成功发送后的留存由消息／业务来源决定。删除会话保留已成为业务来源的文件；管理员按报告关联清理原消息时，同步清除原文件、解析分段、衍生缓存与相关任务上下文，保留其他已确认摘要。
- 删除与解析／模型在途任务共享版本及失效约束，晚到结果不能恢复已删材料。备份包含数据库与文件并支持配对恢复；历史备份按保留周期管理，不能把删除在线材料表述为已经清除全部备份或第三方历史输入。

## 非目标与兼容约束

本轮不做扫描件 OCR、旧 DOC／PPT／Excel 格式解析、公司级知识库／向量检索、完整 Office 在线预览或编辑、跨员工问答、文件生成导出、网盘目录管理、云存储资源创建或 Electron 改造。文件解析不新增模型配置，文档问答沿用公司工作助手服务；以后需要 OCR 时再确定独立的识别用途和服务适配。

沿用 React／Python／PostgreSQL、现有 worker 与 harness，不新建 Agent runtime。限制解析耗时、内存、解压量、页数及提取文本量，超限明确失败或标记不完整；具体上限在 Plan 中维护，不承诺小服务器可处理任意文档。

## 验收标准

- [x] 已确认格式均可发送、保存、解析并在会话刷新后查看；图片／音频入口继续可用，“文件”命名及控件符合主题。
- [x] 文件卡片、长名称、多选、草稿切换及桌面／手机布局可用，异常反馈与实际状态一致。
- [x] 固定文件样本覆盖正文、表格、中文／英文、JSON 结构与来源定位；扫描／损坏／加密／超限不假报成功。
- [x] 助手能读取非开头片段，按文件问题回答并引用来源；工作／报告仍保留人工确认与权限约束。
- [x] 原文件与解析结果私有存储；跨公司／跨员工／未发送附件／伪造引用均按权限处理。
- [x] 解析重试、进程中断、删除竞态及既有共享来源保留正确，旧图片／语音与资料不因迁移丢失。
- [x] 仅执行相关解析、存储、harness 与 Web 定向检查；日常页面用专门样本，不删除用户资料，不默认运行重型 CI 或真实付费调用。

## 待确认问题

无。用户已确认上述范围；后续 OCR 是否使用专用服务、复用兼容视觉模型或部署本地识别引擎，届时按需求决定，不纳入本轮配置。
