# Plan — Spec 012

对应 [Spec](spec.md)，实施及独立验收已完成。模块方案如下，实际验证与返工见 [验收记录](acceptance.md)。

## 实施顺序与模块

1. **数据与存储**：扩展现有 `Attachment` 为文档种类及解析状态；新增解析版本／分段记录，按附件、顺序和定位存储。原文件继续私有 ID 路径，增量迁移不改旧文件、不把旧音视频标成待解析文档。
2. **文件解析**：在 `paa_server` 内集中格式识别与解析。采用 `pypdf`、`python-docx`、`python-pptx`，TXT／JSON／MD／CSV 使用标准库；依据与限制见[决策](../../.ai/decisions/0013-document-ingestion.md)。实施前按 Python 3.12 核对兼容并锁定实际新增依赖，不升级整个依赖树。
3. **消息与 worker**：上传流量有界、落盘后关联消息，worker 在文档输入准备阶段解析，再调用模型。解析不依赖 Key，有效提取在模型配置缺失或调用失败时仍保留；复用原消息任务、租约与恢复，不另加 Redis／任务平台。
4. **Harness**：加入授权的文件目录／分段查找和读取工具，将文件名、版本、可读范围与实际来源传入；模型按需读取，输入版本绑定解析版本。摘要只作导航，完整可读分段是回答依据；确定性分段无需 embedding。
5. **Web**：统一 `Assistant.tsx` 的文件选择和草稿校验，扩展 `company-contracts.ts`，文件卡片及提取内容查看复用现有 UI；团队原始上报、来源引用和删除后缓存一同兼容文档。

## 状态、接口与故障恢复

- `POST /uploads` 保留附件身份契约，按扩展名、MIME 与实际结构共同校验；文档下载采用鉴权的 attachment 响应，安全显示原文件名，禁止直接内联执行活动内容。旧图／音频预览保留。
- 消息写入仍由幂等键及会话授权控制；文档卡片区分未发送、上传中、等待解析、解析中、可读、部分可读与失败，不能用模型任务状态代替解析状态。
- 提取记录含附件 checksum、解析器版本、解析 revision、定位、文字与覆盖／错误信息。分段读取分页且有界；不在消息列表响应中返回所有文档正文。只读接口与重试入口必须核对附件的当前有效归属。
- 解析放在可终止的受管子进程，默认每个现有 worker 同时解析一个文件。设置耗时与资源上限、解压后大小／条目数和 XML 安全解析；不得执行宏或跟随文档外部关系，不把整份文件读入 API 常驻大内存。
- 首版解析上限：每文件 60 秒、512 MiB 内存、100 个 PDF 页／幻灯片、20 万字符／2000 分段；Office 解压合计 64 MiB、2048 条目、单项 16 MiB，并限制压缩比例。PDF 解压亦有界。平台资源限制方式及实测证据见实施／验收记录。达到限制需显式输出已覆盖范围或失败；不能静默截断并标记全文成功。
- 解析成功以租约、附件存活和输入版本校验后原子发布；中途失败不留下半份“成功”记录。只重试失败解析，重试模型复用已成功的同版本提取，避免多次计费或重复建议。
- 将文档分段加入现有 `deletion.py`、`clean_files` 与 checkpoint 清理，删除确认影响包含文档；处理删除与子进程晚到结果竞态。未发送文件的清理继续遵循现有 TTL，不引入永久孤立副本。

## 存储演进与迁移

首版私有卷由 API／worker 共用；PostgreSQL 保存权限、引用及提取内容，备份两者。文件访问集中在小型存储边界，业务表和引用使用附件 ID，不存临时下载 URL；后续 OSS 实施时再增加适配和迁移工具，不预装对象存储服务或创建收费资源。

迁移前备份，确认旧图／音频、消息来源、报告删除及本地凭证未受影响。若回退，采用配对旧数据库／文件备份和旧应用；不能在新文档写入后假称无损降级。具体字段和迁移编号在实施调研时确定。

## 相称验证

文档维护为 S0，只查 diff、引用和需求一致性。业务实施含上传安全、持久化、权限及删除（S3）和 Web 交互（S2），按子系统定向验证：

- 小型固定二进制文档验证真实解析器，覆盖中文、段落／表格／备注、后半部分内容、JSON 错误、无文字、损坏、压缩超限和可终止超时；不为了样本下载大模型或安装 Office。
- 专用 PostgreSQL 测试库验证隔离、幂等、重试、失效输入／删除竞态和共享来源；harness 用固定模型响应调用真实读取工具，不能用伪造“解析成功”替代实际解析检查。
- Web 定向检查文件选择与组合、状态、草稿及引用；整理实际改动文件格式，相关 lint、`typecheck:web`，新增依赖／入口需要时补普通 Web build。
- 日常 Web 在桌面和 390px 用非敏感样本验证发送、卡片、内容查看和原文件下载。若需要真实大模型质量联调，集中确认样本及服务授权；不把历史真实调用授权自动扩展到新文件。
- 不默认触发 CI、Electron、发行包、OCR／真实 ASR 或全站重复验收。实施后由新的独立 Agent 复核，未执行的设备／部署能力如实记录。
