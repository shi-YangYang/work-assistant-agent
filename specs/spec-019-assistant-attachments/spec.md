# Spec 019 — 工作助手发送与附件体验

## 状态

DONE · 2026-09-16。前五项已实施，定向检查与本地界面验证通过；画廊键盘问题已返工关闭，新独立工程验收结果为 [PASS](acceptance.md)。其后音频来源误判由协调 Agent 直接修复，真实混合附件定向复测通过，详见 [联调记录](implementation.md#真实模型联调--2026-09-16)；设备、平台与识别效果范围仍按验收报告限定。

## 背景、当前行为与目标

员工需要直接发截图、手机照片、表格，并配一句语音说明。当前入口只有文件选择；图片／文档可混合，但语音必须单独发送；不支持 MP3、HEIC／HEIF、XLSX。图片没有应用内画廊，PDF 只能下载原件或查看提取文字；模型输入统一缩到 2048 像素并转 JPEG，未显式纠正照片方向。

本轮打通“方便添加 → 发送前核对 → 混合提交 → 带来源理解 → 随时查看原件”，保留工作进展确认、报告生成和权限规则。沿用 [Spec 012](../spec-012-assistant-documents/spec.md) 的私有附件与受控解析，以及 [Spec 018](../spec-018-web-pilot-experience/spec.md) 的身份草稿、原请求重试和诊断约束。

## 功能需求与目标行为

### R1 — 粘贴与拖拽

- 工作助手输入区支持粘贴截图／剪贴板中的实际图片文件，支持将本地文件拖入当前会话；出现轻量落点提示，放下后进入待发送附件，不自动上传或发送。
- 粘贴普通文字保留原行为；同时包含图片文件和网页 HTML 的剪贴板不额外抓取远程图片、不执行 HTML，也不重复插入同一截图。网页地址、文件路径文字和目录不当作已上传文件。
- 选择、粘贴、拖拽共用格式、数量、大小校验和待发送卡片。批量不合法时整批拒绝并说明原因，原草稿不变；超限提示仍只在被拦截时出现。
- 仅在当前可编辑会话接收附件；发送、录音或原请求结果待确认时不绕过锁定。切换会话、退出账号与迟到事件沿用身份／会话隔离；文件拖入输入区不能让浏览器跳去打开文件。

### R2 — 语音与图片／文档混合发送

- 一条消息可包含文字、图片、文档和最多一段语音。统一保持最多 **4 个附件、合计 20 MiB**；单图最多 **5 MiB、2,000 万像素**；语音最长 **180 秒**，也计入总数量和大小；文字仍为 8,000 字符。
- 已添加图片／文档后可录音，已有一段语音时提示先移除或发送；录音结束合并到原草稿，不覆盖图片、文字或关联消息。移除附件只影响目标项，录音试听及语音文字修正保持可用。
- 服务端重复校验组合与归属；所有附件绑定同一消息。上传成功项可复用，原样重试沿用同一正文／附件快照与幂等键，不重复创建消息或自动重调模型。
- 图片、文档文字、语音转写与用户文字作为同一消息的材料进入既有 harness。语音转写失败时保留消息与附件，明确提示重试，不悄悄忽略语音生成完整业务结论；文档部分失败沿用既有“已读／未读范围”规则。

### R3 — 扩展常见格式

| 新增格式 | 行为与边界 |
| --- | --- |
| MP3 | 与现有语音走同一播放、时长校验、转写和纠正流程；验证真实媒体内容，不只增加扩展名白名单 |
| HEIC／HEIF | 支持可解码的静态主图；保留原件，生成浏览器预览和模型输入。方向／透明背景处理与其他图片一致；多图容器、连拍或动态内容只取主图并说明范围 |
| XLSX | 只读提取可见工作表的非空单元格，保留工作表名、实际行列／单元格地址、数字、日期及文本；回答可定位到对应表格内容 |

- XLSX 不执行公式、宏、外部链接或自动重算；公式保留表达式与文件已有的缓存结果，结果注明为文件保存值。缓存缺失／错误值不能当成 0 或实时计算结果；未读取的隐藏表／行／列明确说明，表内图表及嵌入图片不作视觉理解。
- 沿用解析进程和文本量／分段上限，并限制表格遍历、解压量、媒体像素和耗时；超过处理范围标记部分可读或明确失败，不能静默省略却声称读完。损坏、加密、扩展名伪装等保留可理解的错误。
- 旧 DOC／PPT／XLS、含宏 Office、视频理解仍不纳入。现有 MP4 继续只处理音轨，不改变为视频分析。

### R4 — 图片与 PDF 预览

- 图片发送前、发送后均可在应用内放大查看；同一草稿／消息内图片支持上一张／下一张、缩放、适应窗口、关闭，发送后可下载原件。桌面支持 Esc 和左右键，手机保留可见触摸按钮与缩放／拖动操作，不依赖悬浮。
- HEIC 浏览器不能直接显示时，发送前采用明确的待转换卡片；用户主动打开预览才触发私有转换，成功项在发送时复用，不因预览创建消息或调用模型。失败保留移除／重试入口。
- PDF 在发送前和发送后均可打开原页预览，支持页码、上一页／下一页、缩放、适应宽度和下载；已存在的“查看提取内容”与引用定位保留。能预览扫描页不代表助手已识别页中文字。
- 预览沿用当前视觉体系，内容占据可用空间；窄屏可用，加载／失败状态明确，关闭后回到原输入或消息位置并释放资源。PDF 渲染按需加载、只渲染当前页及有限邻页，不一次创建整份文档的画布。
- DOCX、PPTX、XLSX 等继续提供提取内容和原件下载，本轮不做完整 Office 排版预览或编辑器。

### R5 — 图片处理质量

- 原文件与可展示／推理的派生图片分离；保留原件下载，正确应用照片方向，透明图片采用可读的背景或保留透明度，不直接转出黑底文字。派生图片不包含 GPS 等无关元数据。
- 避免对所有输入无差别缩到 2048 像素并转 JPEG。截图和文字图优先保留细节；普通照片按显示／模型需要生成有界尺寸。长图需要分块时，保留阅读顺序及覆盖关系，计入同一消息的模型图片预算。
- 图片预处理不调用新模型、不新增用户模型配置。派生块数、总像素、编码体积与处理资源有界；无法覆盖全图时明确说明或要求裁剪，不承诺任意长图都能完整理解。
- 用固定的旋转照片、透明截图、细字截图、长截图和手机 HEIC 检查方向、背景与实际输入细节；对照结果记录样本和处理参数，不把尺寸变化冒称真实模型准确率提升。

## 边界、兼容性与技术约束

沿用 React／公司 API／worker／PostgreSQL 和私有文件存储，不更换 runtime 或开通云服务。原件、预览、提取结果都按同一公司／成员／业务来源授权；派生缓存不能成为公开链接，身份失效、撤权与删除后不能由迟到任务恢复。未发送的预览上传沿用孤立附件清理；删除、备份、恢复涵盖派生文件。既有消息和原件不批量重写，旧引用与语音修正继续有效。

手机目标沿用 iPhone Safari／Android Chrome，能力不支持时保留文件选择入口。浏览器可能将照片转为 JPEG，也可能交付 HEIC，以实际收到的内容校验；桌面窄屏不能替代真机验证。共享 Web 与服务端改动不自动扩展到 Electron。

## 非目标

扫描件 OCR、文档内图表／图片理解、长音频／视频理解、旧 Office 转换、Office 在线编辑、跨刷新草稿、公司级知识库、公开附件分享、生产部署及更换模型服务均不在本轮范围。
