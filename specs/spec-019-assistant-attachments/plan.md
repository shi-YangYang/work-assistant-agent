# Plan — 工作助手发送与附件体验

## 对应 Spec 与状态

[Spec 019](spec.md) · DONE，[独立验收通过](acceptance.md)。行为与边界以 Spec 为准，选型理由在 [0013](../../.ai/decisions/0013-document-ingestion.md#spec-019-扩展决策)。

## 模块、修改顺序与数据流

1. **附件契约与资源边界**：梳理 `files.ts`、`schemas.py`、上传／发送 API 的格式和混合校验，保留最多一个音频与现有消息级转写字段。明确原件、展示预览、模型派生图的职责及版本，不先改数据库表。
2. **服务端格式与转换**：MP3 接入现有 FFmpeg 检测／有界转码；HEIC 用 Pillow 的 HEIF 解码插件；XLSX 用 openpyxl 只读模式，加入既有受管文档子进程。扩展内容签名、Office 容器检查、遍历和缓存结果处理。
3. **混合消息**：调整组合校验、录音加入草稿和 worker 输入拼装；汇合转写、可读文档和视觉材料后再进入 harness，不为每种附件另开 Agent 运行。语音修正／文档重解析仍使旧尝试失效。
4. **添加与查看**：三个入口统一进入 `addFiles`；拖放只在工作助手处理本地文件，粘贴不抓远程内容。图片画廊复用模态交互，PDF.js 用本地依赖与 worker 按需加载，读取本地 File 或同源私有附件字节，界面使用项目控件。
5. **图片派生与兼容**：统一方向修正、透明背景、照片／截图编码和长图覆盖策略，前端展示与模型预处理各取所需；原件不重写。复核缓存版本、授权、删除和预览对象 URL／画布释放。

新增依赖仅限公司侧 HEIF 解码、XLSX 解析和 Web PDF 预览所需；选稳定兼容版本并增量更新各自锁文件。不得让图片解码直接占满事件循环；沿用有界并发，对新解码路径补必要的像素、内存与超时限制。PDF worker、字体／字符映射资源随 Web 打包，不依赖公共在线预览站或运行时 CDN。

## 接口、存储与迁移

- `POST /uploads` 仍返回 `Attachment`；扩展格式和混合限制不改消息幂等契约，不增设多个音频转写结构。待发送 HEIC 主动预览通过现有上传取得附件身份，成功后同一文件复用上传结果，失败／回包未知不冒称未产生临时文件。
- 为图片提供同源 `GET /uploads/{id}/preview`，由现有 `visible_attachment` 授权后返回无敏感元数据的浏览器可读派生图；仅接受图片，派生过程有界。前端按需请求，不能从文件名拼接路径。PDF.js 可经既有私有原件端点获取字节，不改变其他文档的下载行为。
- 展示预览不参与模型调用；worker 从私有原件生成所需的模型输入。清单记录附件顺序／分块覆盖位置，并限制单次模型输入；既有上下文与请求预算必须覆盖新增图片块。
- 派生物按附件 ID＋转换版本保存在私有目录，采用临时写入后原子发布；不覆盖原件。旧文件按需生成；并发与删除校验涵盖最终发布，未发送孤立清理和报告关联删除同步处理派生物。
- XLSX 提取加入现有 `DocumentChunk`，位置示例为 `工作表「项目进度」!B12:D12`；读取公式与缓存值时保持同一单元格对应。可见内容、隐藏内容和合并单元格均有明确口径；禁止依赖不可信的工作表 dimensions 无界遍历，损坏 dimensions 不得导致静默空结果。
- 当前设计无需新增业务表。若调研发现保存处理版本／状态确需 schema 变化，应说明必要字段并增量迁移、先备份，不重建或清空既有数据；实装后的技术与部署依赖同步到技术栈及使用指南。

## 实施资源口径

- 上传、图片像素、音频时长沿用 Spec；普通附件上传仍有现有请求预算，不能因新解码无限延长等待。
- XLSX 沿用子进程内存／时间、64 MiB 解压、20 万字符／2,000 分段上限；最多遍历 20 个工作表、20,000 行、256 列、500,000 个槽位和 20,000 个非空格，单格最多 8,000 字。达到上限说明未读范围；缓存缺失标注而非计算。
- 图片受管子进程内存上限 512 MiB、超时 30 秒，每进程最多并发 2 个解码任务。展示预览最长边 8,192 像素、总计 12 MP／4 MiB；原图仍完整保留。
- 模型派生每图最多 4 块、合计 8 MP／3 MiB；单消息最多 8 块、16 MP／6 MiB。保持顺序和原图覆盖坐标，超额说明部分覆盖或要求裁剪；不将展示预览强制套用模型缩图策略。常量集中在图片解析与媒体模块。

## 预计文件与实施分工

- Web：`apps/web/src/{Assistant,Documents,ui}.tsx`、`files.ts`、`audio-capture.ts`、`styles.css`；可按职责新增小型预览组件，不把发送状态另建一套。
- 服务端：`services/company/src/paa_server/{api,schemas,media,documents,document_parser,worker}.py`；必要的附件 DTO、部署依赖与共享契约。
- 检查：现有 `tests/web/` 附件／录音／会话用例，`tests/server/` 文档、媒体、消息及授权用例；真实格式的小型固定样本按测试职责放置，不提交用户材料。
- 业务涉及上传、预览、worker 与来源生命周期，默认交给一个实施 Agent 串行完成；结束后交新的独立 Agent 验收。不要为了并行让多个 Agent 同改附件契约或 API。

## 验证计划与风险

文档阶段 **S0**：只查 diff、范围与引用，不运行测试／构建。实施涉及私有附件 API、解析与新增原生依赖，按 **S3** 识别风险，但只验证相关子系统：

- Web 定向验证三种添加入口、混合录音草稿、容量边界、上传结果复用和原键重试；UI 实查图片前后预览、PDF 翻页／缩放、Esc／触摸关闭、长文件名和窄屏，不重跑整套桌面流程。
- 服务端样本覆盖 MP3、旋转／透明 HEIC、文本长图、可见／隐藏表格、公式缓存缺失、日期／合并单元格及伪装／解压／像素边界；验证混合材料输入、跨成员／跨公司预览拒绝、并发派生及删除后不能重新发布。
- 用固定模型响应核对混合素材进入同一次任务、来源和转写纠正；不能据此证明真实视觉／ASR 准确率。实际供应商联调与实体手机结果单列，未执行不能称通过；文档阶段不调用模型。
- 改动源码格式化，运行 Web 类型和涉及文件 Lint。PDF worker／依赖改变构建产物，需一次普通 Web 构建；HEIF 原生包需确认 macOS 开发与 Linux 部署安装及样本解码，Windows 服务兼容性用现有可用环境定向验证并如实记录，不能拿 macOS 结果代替。
- 小型媒体／表格定向用例可留现有快速测试入口，不增加默认录音实机、模型下载、付费调用、Electron 打包或整套重型 CI。无设备／HTTPS／目标系统时记录具体验证缺口，不自行开通资源。

主要风险是解码体积远大于上传体积、图片细节与模型输入预算冲突、公式缓存不代表实时结果、预览缓存绕过既有授权。控制与回退沿用现有边界；新功能不可用时保留原件下载和明确错误，不伪造成功。
