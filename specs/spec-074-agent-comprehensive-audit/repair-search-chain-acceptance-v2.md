# 搜索工具链精简二次独立验收

## Result

**FAIL**。上一轮发现的工具回执恢复不一致已修复；真实 AFTER 首条链接用例暴露了来源状态互相矛盾：搜索刚返回的真实链接，随后的读取失败却被标成“从未发现、不可引用”。不能把该任务失败单独归因为模型忽略结果，也不能据描述缩短或模块通过宣布搜索优化完成。

## 已通过的代码边界

- [`tool_progress/service.py`](../../apps/server/app/agent/runtime/tool_progress/service.py#L64) 按固定键序追加首次派生字段；首次 `webFeedback` 与原进度记录在同一既存事务保存。同一调用恢复时复用字段，不重复统计证据与停滞；旧记录没有字段时返回原始回执，不用后续状态倒算历史增量。
- 回归覆盖新增证据、零增量提示、网页失败提示、空反馈及旧记录，核对完整 `ToolMessage`、真实请求序列化后的模型身份和执行次数。正常 checkpoint 恢复从当前待执行步骤继续，并非从第一轮重建全部历史工具；本结论不扩张为任意超大工具批次的故障证明。
- 描述与统一研究规则 4,022 → 1,700 字符；没有新增模型轮次、搜索服务、事务、调度阶段或次数上限。保留参数、正文与摘要区别、指定来源约束、权限和访问限制。
- 最多 400 字符的摘要仍为真实 `search_snippet`；成功读取正文后清除旧摘要，后续较低等级来源不能降级正文证据。公开来源 DTO 仍使用白名单，未加入内部 `snippet`、`webFeedback` 或增量计数。

## Required Rework

**P1：来源已由搜索发现并交给模型，失败读取却撤销其发现状态，误导模型拒绝交付。**

真实证据均来自 AFTER 首轮 `L-links-low`，job `1be774f6-5a92-409b-8316-15a207659cfc`，见 [`trace.jsonl`](../../artifacts/spec074/20261019-search-chain/after/trace.jsonl) 与 [`result.json`](../../artifacts/spec074/20261019-search-chain/after/results/L-links-low/result.json)：

1. `1792391139.2555609`，`web_search` 返回 `https://learn.chatgpt.com/docs`、标题 `ChatGPT | ChatGPT Learn`，以及产品概览摘要，类型为 `search_snippet`。
2. `1792391139.509602`，下一次真实模型 HTTP 请求已经包含该搜索工具回执。该来源没有因批次等待或消息裁剪而漏传。
3. `1792391146.755084`，同一地址的 `web_fetch` 失败回执却包含 `sourceDiscovered=false`、`evidenceLevel=unverified_url`，并称“未取得网页正文或发现该来源”，缺少 `availableEvidence`。网页读取失败本身不应抹除已成立的搜索发现事实。
4. `1792391147.177883`，真实模型输入同时包含前述成功搜索和否定发现状态的失败回执，两条均未截断。现有研究规则明确规定 `sourceDiscovered=false` 不可引用，因此这是工具链向模型提供矛盾依据，不是“模型没有收到结果”。
5. 最终仅交付 Anthropic 链接，OpenAI 被标为 `blocked`，正文称“没有给出 OpenAI 链接”。原题只需两家各一个官方产品页面链接，并未要求网页正文可读。

[`web.py`](../../apps/server/app/agent/tools/resources/web.py#L26) 将“是否曾发现”直接取自当前 `job.result.webSources`，同文件第 72 行按字典迭代顺序取最后 40 个未读来源。该顺序经过 JSONB 回读后不代表发现时间，因此不是可靠的“最近 40 个”窗口。实施侧对真实轨迹的离线重放定位到：约 234.71 秒加入链接，约 234.72 秒同批下一次搜索保存即将它淘汰。独立验收也核对到两次实际搜索回执时间仅相差约 0.012 秒，后一次返回的是既有来源；随后读取失败错误地报告从未发现，与此链路一致。

已发现来源的身份不能与可淘汰的展示／摘要窗口混为一谈；应在现有存储链路中保留本轮可引用来源的真实发现事实，不能靠再加提示词解决互相矛盾的工具字段，也不能取消访问安全校验来掩盖问题。

这条首次证据确认了工具链缺陷，但对应状态判定与 40 条裁剪在基线已经存在，不能称为本次描述精简引入。后续修复保留首轮失败证据，由新的实施与验收流程处理。
