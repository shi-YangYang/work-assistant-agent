# 材料问题修复说明

## 改动

- `read_images` 的同会话目录现在区分独立图片和文档，提供文档真实 ID、原格式／转换格式以及 `readPages` 入口。把文档 ID 误传给图片工具时，返回明确的文档页图入口；混合请求保留独立图片 ID，不假装已读取。权限、分页与消息时间边界沿用原逻辑。
- `find_documents`、`read_document` 和 `get_message_context` 共用精简文档目录。公开附件 API 的 DTO 保持原样；不用新增转换、查库或模型调用扩充信息。
- 实际装配的页图标注 `attachment_id` 和页码入口，避免历史页图 ID 与原附件 ID 混淆。页面仍经现有授权、修订校验与预算装配，不把目录当作像素，也不自动重新读取所有历史文件。
- 文字读取回执新增 `readScope`：此次返回分段数、已提取分段数、是否涵盖可提取文字，显式标明此回执不含图片。`sourceComplete` 继续表示解析准备状态，不能用它声称整份文件已读。
- 系统范围尾注改为“本次材料范围”。`detach_material_coverage` 分离已存储的精确系统尾注；旧记录只识别系统固定范围句式。历史记录投影、终稿存储的接线由协调 Agent 完成，避免旧尾注被模型复制为本轮读取事实。

## 验证

风险 S2，涉及读取工具与上下文装配；未改 schema、原件生命周期或解析器版本。

- 图片目录、授权、分页、恢复与真实文档渲染、范围装配的首次子系统检查：65 通过、1 失败。失败是本地没有配置正文流 Redis（`reply_stream_not_configured`），发生在图片读取断言之后。
- 使用已运行的本地 Redis 和专用 `spec074-repair-materials` namespace 重跑失败项与改名后的 readScope 用例：2 通过。
- 精简目录字段、保留公共 DTO 后，目录、错误 ID 授权恢复和读取范围定向检查：3 通过。
- 文档与独立图片混合请求的重定向不会丢失图片 ID：1 个定向用例通过。
- 固定输入／受控模型只用于验证确定性分支，不作为真实模型回答准确性或耗时证据。low／high 原案例复验由协调 Agent 统一安排。

## 限制

这些修复消除了错误工具入口和范围状态混用，不能保证模型永不算错或措辞失误。T74 空行数多算 1 行属于算术问题，没有为了该单例修改解析器指纹或让旧附件统一重解析；应按需使用现有计算工具核验。没有新增正常请求的模型核对轮次。
