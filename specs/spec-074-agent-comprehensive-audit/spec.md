# Spec 074：Agent 全量功能、可靠性与性能测试

## 状态

测试执行与问题汇总完成，保留明确的未执行／未触发分支。基线为 `26db8f9bb8af64da403696362b158df7a94ebe1a`；未修改产品行为。结果见 [主报告](report.md)、[覆盖索引](coverage.md)、[问题清单](issues.md)、[性能基线](performance.md)和 [独立验收](acceptance.md)。

## 背景

[Agent 专项测试](../spec-059-agent-comprehensive-testing/spec.md)和 [Web 全量测试](../spec-068-web-comprehensive-testing/spec.md)已建立真实模型、隔离故障、调用轨迹和浏览器取证方法。此后附件即时上传、广泛文本支持、旧 Office 转换、完整文件读取与图文理解、材料生命周期、手机语音和输入交互均有变化，历史通过结果不能代表当前版本。

本次以当前实际工具、业务动作、角色与任务状态为范围依据，覆盖用户从输入到获得可用结果的完整流程。全量指覆盖已提供的能力及适用边界，不声称穷举所有自然语言组合。

## 目标

- 验证普通聊天、写作、检索、材料分析、代码执行、文件／图片交付及公司业务操作是否正确完成。
- 重点排查重复工具调用、目录加载空转、无进展循环、重复写入、假成功及异常恢复。
- 核对模型实际获得的材料、最终答案、业务回执和持久化结果，定位漏读、误报完整读取及跨账号污染。
- 分解用户等待时间，区分排队、上游模型、工具、解析、持久化和前端显示，形成后续修复可复用的性能基线。
- 全部可执行分组完成后统一提交问题列表；发现产品问题先记录，不立即修复。

## 非目标

- 不重新进行全站 UI 审计，不测试 Electron 打包、本地声纹模型或桌面会议全流程。
- 不改提示词、权限、模型强度、预算、超时、附件处理策略或数据库结构来提高通过率。
- 不添加运行时模型核对、反思轮次、额外同步写入或新的业务步骤。
- 不以精确作文长度、固定文风或指定工具顺序作为通用成功标准；不把模型知识错误一律归咎于 Agent，也不据此忽略真实任务未完成。
- 不操作生产或员工真实数据，不把真实模型调用、破坏性测试加入默认 CI。

## 当前行为

- 工具按图片、工作、报告、检索、文档、文件执行、记忆、任务上下文等分组暴露；另有目录与收尾工具。已注册直接调用存在兼容机制，目录可见性不等于数据授权。
- 管理员和员工权限不同，管理员不等于可以执行所有员工写入。执行模式有逐项确认、自动审核和自主执行；新账号默认自主执行，不能覆盖旧账号选择。
- 文件选择后即时上传，上传阶段不解析、不启动 Agent；消息发送后由 worker 处理材料。旧 Office 转换与页面处理不依赖代码执行沙盒。
- 原件及处理产物跟随附件生命周期；取消处理产物的独立资源额度，不等于取消上传、安全、模型输入和任务执行边界。
- 图片生成使用独立模型，一次请求支持批量串行生成；当前单消息最多 4 张，生成、排队、完成后加载与取消各有不同状态。
- 任务通过真实 API、worker、工具、回执及正文流交付，存在中断、恢复、租约、幂等和内部预算。运行时数值由实施时读取的实际配置确定，不照搬历史 Spec。

## 目标行为

每条测试记录稳定 case ID、角色、权限、人设、强度、初始数据、用户操作、预期结果、禁止结果和证据。结果为 `PASS / FAIL / BLOCKED / NOT_RUN / N/A`；N/A 说明不适用原因。

分别给出测试交付结论与产品结论。测试报告可以验收通过而产品仍有缺陷；阻塞、跳过或未执行不能算作产品通过。

## 功能需求

### 0. 真实调用硬性要求

- 本次任务、浏览器、性能、故障恢复及并发测试中，凡进入模型阶段，必须调用当前配置的真实服务商模型。禁止模型桩、预制答案、历史响应回放或由测试 Agent 代写被测 Noria 的回答、工具决策和生成成果；生图与语音转写也必须调用对应真实服务。
- 可以预先制作测试材料、用户问题和用于判分的事实真值；判分答案不能写入模型响应、工具回执或实际结果。工具选择、参数与后续回答由被测 Agent 的真实流程产生，不能为了覆盖工具而伪造模型调用。
- 每次调用保留 case／message／job 关联、服务商与模型、实际参数、请求时间、响应状态、脱敏响应／工具调用及用量；上游提供 request ID 时一并记录，未提供时明确标注。仅有界面文字或数据库里的答案不构成真实模型调用证据。
- 故障可在真实链路注入断连、超时、HTTP 错误、响应丢失或破坏实际返回的传输数据，但不得编造成功内容或工具调用；记录注入点及是否已经到达上游。故障移除后的模型恢复必须真实调用。未触发的模型行为如实记为未复现，无法执行的场景记为阻塞／未执行，不能用假答案补齐。
- 上传未发送、发送前校验拒绝等本来不应调用模型的步骤，仍验证零模型调用；不为满足形式而额外请求模型。已有 mock 单元测试不能替代或计入本次真实任务覆盖。

### 1. 冻结范围与先验预期

- 实施开始时冻结应用 SHA、未提交差异指纹、依赖、迁移版本、API／worker 实际载入版本、网络／代理、模型服务和参数、角色、权限、任务预算、沙盒开关。
- 从真实注册表、动态工具目录、业务动作和任务状态生成覆盖清单。每个适用工具／动作映射正常、边界、权限拒绝、故障与恢复断言，不用旧测试文件数量代替覆盖。
- 每例开始前冻结真值、允许写入的对象／字段／数量及禁止副作用；测试驱动不能无条件确认 Agent 提出的操作。
- 保留首轮结果。历史缺陷作为回归种子重新验证，已确认保留的目录兼容、完整回答等取舍不能按过期规则判失败。
- 当前能力和具体旅程见 [测试矩阵](test-matrix.md)，实施时补到可执行 case，不留只有领域名称的空覆盖。

### 2. 分层覆盖与样本

1. **固定输入与边界层**：冻结材料、问题与先验断言，通过真实模型观察重复调用、交替循环、永久错误恢复和写入后丢回执等场景。业务、权限、存储及调度使用真实实现；固定的是输入，不是模型答案。难以自然触发的模型行为保留覆盖缺口，不伪造工具序列。
2. **真实模型层**：至少 80 个不同任务，至少 40 个为 3～8 轮连续流程；管理员、员工各至少 30 个，至少 20 个为未沿用旧答案的新保留样本，至少 24 个专门观察重复／循环。数量为底线，不替代工具与边界覆盖；重复运行不算新的任务。
3. **浏览器层**：至少 12 条完整旅程，其中桌面、手机各至少 4 条，其余按覆盖缺口选择；双方角色都覆盖。必须经真实 UI 发送、真实模型响应、等待、切页、刷新、取消、确认及查看／下载结果，不能用接口拦截填入预制答案或用直调后端替代全部流程。
4. **故障与并发层**：隔离 API／worker 连接真实模型服务，验证恢复和用户隔离；并发数与故障由测试端控制，模型答案不受测试端控制。服务商限流与本地承载问题分别报告。

真实文本模型只使用当前管理员用途绑定的 `low`、`high`，不测试 `max`，不静默降档。至少 12 条复杂／高风险任务在两档都执行；图片、ASR 按各自实际模型配置验证，不附加文本推理档位。模型不支持所需能力时记录阻塞及受影响范围。

### 3. 重复调用与循环

关联 user turn → message → job／attempt／fence → 模型请求 → 工具调用 → 实际执行尝试 → 业务回执 → 数据／文件。

- 分开统计模型提出的调用、被拦截的调用、实际执行、底层自动重试、恢复重放、外部请求与最终副作用。最终只写一条仍可能存在七次无效工具调用。
- 同名同参且无新状态／证据的两次调用标为重复候选；相同无进展调用三次、A→B→A→B 或更长闭环标为循环候选。该规则仅用于测试分析，不改变生产调用限制。
- 覆盖改写查询但没有信息增量、目录反复切换、无下一页仍继续翻页、永久错误重试、反复保存相同记忆、生成同一图片／文件及收尾再次规划。
- 以对象版本、分页游标、结果摘要、请求目的及新授权核对候选。合法分页、状态变化后的重查、用户明确重新生成、临时故障恢复必须有反例，不能仅按工具名判重。
- 验证已有预算和停止机制能终止无进展任务，同时不截断有实质进展的合法长链。报告停止原因、触发位置和已交付结果；不能只写“最终没有无限循环”。

### 4. 回答与副作用真实性

- 用有标准答案的合成材料核对事实、数字、日期、来源和所问事项；语义审查接受等价表述，不以关键字出现代替正确回答。
- 对完整／部分／失败／未提供、已预载／已传入模型、文字／页图／原件执行分别核对。重点验证文末、隐藏表／行、图表／备注、扫描页及跨多批上传的早期文件。
- 上传成功不能表示已读取；模型说成功不能表示工具成功；UI 完成不能表示数据库或文件存在。执行后读回真实对象、版本、所有者、字段、文件格式与内容。
- 无工作时生成周报不创建空报告；明确基于聊天整理内容的请求与业务报告生成区分，按当前已确认的产品规则判定。
- 保留已保存的工作正文、清单、报告、成果及旧消息兼容。错误分类必须指出输入是否实际到达模型、工具是否执行、权限是否允许，证据不足标为待定位。

### 5. 耗时与质量对照

- 至少 8 个代表性任务进行 low／high 同题对照，每档 3 次，交错顺序、独立会话、相同输入／人设／权限；覆盖普通问答、写作、搜索、工作操作、短文本、图文、文件执行和多步任务。可以与上述 12 条高风险配对重合。
- 记录每次发送、受理、出队、上游首个正文、浏览器首个正文、工具执行、首份可用成果、最终可见结果、数据库完成的时间点；没有浏览器观测的请求不冒称“用户已看到”。
- 记录排队、解析／转换／渲染、模型请求及重试、工具、持久化和前端补字时间。重叠区间按时间线分析，不能简单累加或相减制造系统耗时。
- 普通问答另做同模型、同强度的直接 API 小样本，使用相同用户输入；明确 Agent 的上下文／工具不同，这只是定位上游等待，不能冒充严格等价性能对照。
- 处理产物首次生成和复用分别采样；冷读、热读不能混为一个性能结论。记录上下文长度、网络异常、实际参数，禁止通过只测 low 或复用产物解释 high 变快。
- 公开单次数据、中位数、范围和任务完成情况。失败／取消没有首字时填空值，单列终态耗时；小样本不宣称稳定 p95。当前阶段建立基线，后续若修复，用同一套冻结输入对比修改前后。

### 6. 隔离破坏性测试

- 覆盖网络中断、响应丢失、SSE 重复／乱序、模型 403／429／5xx／超时／异常响应、权限撤销、数据库断连、worker 退出、租约恢复、媒体读取失败、转换卡住、沙盒失败和资源边界。
- 在接收任务前后、执行前、写入后回执前、流式输出中、取消与恢复交错时注入；验证已完成操作不重复、取消后不继续写入、失败不假报成功、剩余数据可追溯。
- 提示注入、跨租户 ID、SSRF、路径穿越和恶意文件用受控目标与合成数据。文档里的指令不能成为写业务、读取他人文件或改变执行权限的授权。
- 杀进程、断库、限磁盘等只能作用于本次 manifest 明确拥有的独立进程／容器／卷。独立 schema 不等于独占数据库服务，禁止停止日常共享服务。
- 真实模型并发按 1／5／10／30／50 个独立测试用户递增，每档投递窗口最长 60 秒，随后停止新增并追踪已接收任务至终态或现有任务时限；不能将投递窗口当作模型回答时限。检查排队、公平性、取消可达、连接／进程／内存和跨用户混流。隔离失效、持续上游限流或资源逼近宿主安全边界时停止升档，记录未测档位；不得改用假模型补测，也不将服务商瓶颈归为本地容量结论。

### 7. 发现问题与交付

- 产品问题先保存首次证据、最小复现与影响，继续不依赖该问题的分组，不修改产品源码、提示词、模型配置或旧断言。
- 仅可修正本次测试脚手架／夹具错误，记录原错误及受影响结果；不能借测试修复偷偷改变产品条件。
- 分类为系统实现、模型行为、服务商、网络／运行环境、测试假设／工具错误；同一事件可以有多个原因，不能全部归为模型或网络。
- 问题记录预期／实际、次数、耗时、数据副作用、证据、置信程度、建议修复方向及可能的速度影响。相同根因合并但保留原 case 关联。
- 交付覆盖报告、问题列表、性能基线、截图／轨迹索引和资源清理记录。新的独立验收 Agent 只验收测试覆盖与证据，产品修复等待用户审查。

## 边界条件

- 只用合成账号、材料、音频与业务数据。所有密钥、Cookie、授权头和原始隐私不进入文档、截图或提交。
- 实际麦克风、系统权限和钉钉真机不属于自动模拟可证明的内容；使用固定音频验证上传／转写／改文字及任务流程，缺少真机条件如实记录。
- 测试看门狗与产品超时分开；无法得到终态时记录诊断并清理自有资源，不无限等待、追加重试或静默重跑到绿。
- 不设置与覆盖无关的总调用硬上限，也不无限扩张样本。外部服务持续不可用时停受影响组并列出阻塞，其余组继续。

## 技术约束

复用 `scripts/company/web-acceptance/agent-audit/`、已有隔离环境、`tests/server/`、Web DOM 与 Playwright。启动前核查旧驱动是否替换模型，禁用本轮的桩响应／历史答案回放路径；复用代码不等于沿用模拟测试方式。除登记的故障注入外，测试侧观测不能修改请求、授权、工具结果或业务限额；不要求模型输出隐藏思考链。

## 兼容性要求

本轮 suite、样本和证据单独保存；不覆盖 059／068／073 的基线及首轮记录。适配旧驱动时保持默认 suite 和原用例行为，不放宽资源归属校验。无产品接口、迁移或部署变更。

## 验收标准

- [x] 实际工具／动作／状态和权限清单完整，每项映射可复核断言。
- [x] 所有进入模型阶段的测试均有真实服务调用证据，无预制、回放或测试 Agent 代写答案；无调用步骤和故障注入如实标注。
- [x] 固定输入、真实 low／high、多轮、浏览器、故障和并发分组均有明确结果及缺口。
- [x] 重复／循环区分模型调用、实际执行、重试、恢复与副作用，有合法反例。
- [x] 新增附件、图文、旧格式、批量生图及语音流程经过完整用户路径验证。
- [x] 正确性基于输入覆盖、回答、回执和最终读回，首轮失败及模型质量问题没有被隐藏。
- [x] 每类代表任务有可解释的耗时数据，未把冷／热读、不同强度和失败样本混算。
- [x] 产品基线未改变，资源归属与清理可核对；问题统一汇总且未提前修复。
- [x] 新的独立验收给出测试交付 PASS／FAIL，产品结论与未验证项单独说明。

完成项表示测试证据和报告交付要求已满足，不表示所有产品能力或矩阵变体通过。未覆盖专用工具、独立 document job、冷热耗时配对、部分故障／安全守卫及负载变体，详见主报告；这些不计为通过。

## 待确认问题

无新增关键决策。全部模型阶段必须真实调用，先汇总再修复，文本只测 low／high，破坏性测试限隔离环境。
