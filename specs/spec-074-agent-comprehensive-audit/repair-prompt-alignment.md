# 提示精简与事实错误归因

## 已确认的原因

本次追溯实际模型请求、工具回执和原文件，不能把所有问题归为工具错误，也不能全部归为模型幻觉。

| 问题                               | 证据与归因                                                                                        | 处理                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 周日说成“周六辛苦了”               | 重建的系统提示 SHA 与真实请求一致，明确给出周日；报告工具日期也正确。属于模型额外添加的事实错误。 | 不增加日期核对模型或冗长提醒。                              |
| 没有隐藏行却说“隐藏内容未读”       | 原文件无隐藏行列，统计正确；负向 `hiddenRowsExcluded=false` 和通用范围文案容易误解。              | Agent 投影区分不存在、存在但未读、未知；兼容旧产物。        |
| 把消息 ID 当附件 ID                | 历史元数据泛称 `id`，当前服务端包装叫“原消息 ID”；模型确曾传错引用，工具正确拒绝。                | 明确 `messageId`、服务端元数据与用户正文；附件仍用真实 ID。 |
| 把局部字符位置当全文位置           | 长文按行范围分组，再在组内切片；`字符 3001–3164` 实际属于该行范围，标签没有说明。                 | 修正工具位置表达；不求全文绝对坐标、不重新提取。            |
| 把转换文字、关键词命中说成原件完整 | 工具已给转换保真未知、实际读取和搜索范围，模型仍会扩大结论。                                      | 保留必要边界，删除重复提示；不能因此保证模型不再过度推断。  |

原文件核心金额、日期、标记、数量和表格末行没有错返。DOC 连排文字被直接解释为“事项／负责人”属于未经充分证据的确定化，尚未证明对应值本身错误。长文全文关键词检索与投递给模型的文字段数不同：仅收到部分段落，并不证明没有检索全文。

完整归因证据：[原始诊断](../../artifacts/spec074/20261018-prompt-alignment/facts.md)。

## 提示与工具改动

- 文档目录、预载和工具说明不再重复整段规则；具体范围由 `readScope` 表达，系统保留事实／推断、转换保真及权限边界。
- 只有实际已提供的正文直接复用；历史目录存在但正文未提供时，沿已有 `readSource` 按需读取，不误称必须重新上传。
- 局部问题只取必要证据；图片能力单独加载时仍保留文档页图工具入口。
- 消息来源和隐藏区域只调整 Agent 投影，不改持久格式、不增加数据库查询、模型核对、全文扫描或默认页图渲染。搜索保持暂停，没有修改研究规则。

实际系统提示与工具 schema 合计：普通问答不变，documents 减少 184 字节，images 减少 82 字节，两种能力同时加载减少 266 字节。这是小幅去重；明确当前消息来源的包装反而增加 21 个字符。不能把模型少调用几次造成的累计输入下降，表述成系统提示大幅压缩。

同一 `deepseek-v4.1-flash`，low/high，原问题和附件，独立账号与环境。每侧 8 个案例、16 轮：旧 DOC 各前两轮、长文各前两轮、稀疏表各三轮、普通问答各一轮。没有模拟模型回答或重跑到绿。

| 模型 HTTP 请求           |               52 |               48 |

核心字段两侧均正确；修后未再出现本样本中的消息 ID 误用或隐藏行误述。历史执行输入复用已由真实模型自然触发，并使用正确引用再次执行，不再仅有模块验证。

质量仍有边界：DOC 字段关系和提取能力表述过满，稀疏表仍会尝试不适用的工具后恢复。长文 high 变慢必须单列：第一轮有一次上游响应持续 62.86 秒，不能归因为长时间反思；第二轮确有额外模型和工具调用。总耗时下降约 11.9% 只描述这次采样，不代表稳定提速或所有回答质量提升。

详细逐轮结果、输入大小口径和首次错误：[真实对照](../../artifacts/spec074/20261018-prompt-alignment/prompt-alignment-comparison.md)。此版本独立验收发现字符位置歧义并要求返工，原记录保留，不用后续样本覆盖这 32 轮。

## 字符位置返工的单独复验

工具、预载、最终引用和报告材料复用同一个位置投影。例如原 `行 2581–2602 · 字符 3001–3164` 现在为 `行 2581–2602 · 该范围内字符 3001–3164`，页、段落、表格等同理。旧持久分段、正文、引用 token 和权限查询均不改变。

只复验原长文 low/high 各前两轮，共 4 轮。四轮核心字段正确，实际工具和引用使用新标签，模型未再把局部字符编号当全文坐标。但首轮两档仍扩大到“全文没有其他条款”，追问后才收紧范围；high 追问还直接输出了内部格式标记，实际模型响应本身已有该内容，不能归为工具错返。

最终候选的长文 low 两轮约 **111 秒**、high 约 **128 秒**，对应修前约 **119／91 秒**。实际模型 HTTP **22 → 25**、工具尝试 **37 → 73**；工具探索增多不能仅用网络波动解释，也不能用前一个候选 16 轮的总量下降掩盖。新代码没有新增调用要求，但一次采样无法证明这些变化由位置标签引起。**位置歧义已修，稳定提速与模型过度推断仍未全部解决。**

剩余慢点已定位到材料查找路径：共 57 次 `find_documents`、12 次 `read_document`；没有错误恢复或超时。两档首轮反复在已准备的 0–90 段内换关键词，其中 low 23 次、high 17 次为空，较晚才按 `nextCursor=90` 继续准备后半部分。拿到目标后仍有非必需补查。这不是工具返回了错误数值，也不能全部称为完全相同的重复调用，而是模型没有及时推进读取范围；本次尚未改动这一检索流程。详见[最终四轮调用分析](../../artifacts/spec074/20261018-prompt-alignment/after-location/location-rework-comparison.md)。
