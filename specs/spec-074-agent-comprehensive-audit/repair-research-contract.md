# 检索任务与证据层级契约

## 根因

修后第三轮的只找链接任务已找到所需两个真实链接，仍继续核验未读正文，并把正文不可访问标为任务未完成。`CORE` 的“仅引用实际读取的来源”与 `web_search`／`web_fetch` 已有的“真实搜索命中／页面发现链接足以交付链接任务”存在歧义。全局停滞没有触发，不能再归因于运行时强制停止。

第三轮证据保留在 `artifacts/spec074/20261017-repair-comparison/after-v3/search-analysis.json`：low 已找到两链接后又用约 189 秒，high 又用约 467 秒。这是修订契约的依据，不作为新版本验证结果。

## 修改

- `prompts/main.py` 的核心引用规则改为须有实际输入或工具来源依据，研究能力规则区分搜索标题／URL／摘要、页面发现链接与已读正文。
- 只找链接／入口时，满足用户要求的数量、机构和主题即交付；未读正文不自动升级为额外任务或阻塞项。搜索摘要只能支撑其中实际事实，正文结论／摘要仍须读相应原文；不凭链接猜正文或官方归属，`sourceDiscovered=false` 的失败回显不是来源。
- 保留原工具定义、来源元数据、硬／软停滞保护、预算、授权和材料规则，不加入意图关键词分流、预设官方域名、额外模型核对或网络操作。

核心提示从 325 到 327 字符（+2）；research 规则从 131 到 237 字符（+106），仅加载该能力后出现。字符数不等于模型 token 数。普通问答没有新增能力规则、模型轮次、数据库操作或网络请求；实际延迟影响不能仅凭长度判断。

## 验证与限制

实施时曾运行员工、管理员两项提示词组合断言（0.15 秒）。复核发现它们主要逐字检查新增文案，不能证明模型行为，且会造成脆弱的文案测试，故未保留该新测试文件，也不将其计作有效质量回归。已检查最终 diff、按需能力加载路径及真实工具契约：核心规则不再要求每个引用必须读正文，同时保留摘要／正文证据和失败地址边界。真正的行为验证使用随后同题 T09 low／high 的新版本首轮真实调用。

涉及 Python 文件不在当前项目 Prettier 范围，局部 diff 检查通过；没有运行全仓检查。实际速度、交付与终态是否改善，需随后同题 T09 low／high 的新版本首轮真实复验确认。旧失败与旧耗时不得覆盖或合并为新版本通过。
