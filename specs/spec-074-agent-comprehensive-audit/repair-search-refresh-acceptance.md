## Spec Coverage

- 独立检查[相对 v7 的精确差异](../../artifacts/spec074/20261019-search-refresh-guard/implementation.patch)：在既有进度记录增加 `readError`，同一作用域、URL 和依赖状态下，最新已执行的 401／403／`blocked_url` 失败不能用 `refresh=true` 绕过重复读取保护。工具描述同步替换原来一概允许刷新拒绝页面的表述；保留 v7 的四行终态文案和 v3 的来源、恢复修复。
- **局部契约 PASS。** 原成功页、404／410、超时／429／503、新地址、新输入作用域仍可刷新。旧记录没有 `readError` 时保留旧行为，旧完成回执重放不追溯分类；实际读取失败不会升级成已读来源。没有新增模型、搜索服务、提示词段落、事务、数据库迁移、预算或搜索次数上限。
- 保护依赖既有最多 32 条进度记录及依赖快照，不是永久 URL 黑名单；记录淘汰或作用域／依赖改变后可以再读取。拦截沿用已有重复操作计数，不把不同查询、不同来源直接归为无进展停止。
- 独立比较实际冻结目录与工作区 450 个 Python 文件，逐字节一致。API／worker 均载入 `d59775a7be82e89e30b7e83427a7e46bfb9c969f593c262e27b57aaa85227e61`；[出站请求重构](../../artifacts/spec074/20261019-search-chain/after-v8/outbound-proof.json)与实际 HTTP 请求 SHA 一致。不能用旧 worker 未加载解释本次结果。

## Issues

1. **真实刷新保护未触发。** 六题没有任何 `refresh=true`，明确拒绝后的刷新及保护拦截次数均为 0，见[实际刷新审计](../../artifacts/spec074/20261019-search-chain/after-v8/refresh-guard-audit.json)。因此不能宣称真实模型验证了新拦截，也不能把抓取数下降归功于它。v7 曾自然出现的 403 后刷新缺陷目前只有本轮确定性全路径修复证据。
2. **两档链接题仍有大量多余探索。** low 在 worker 开始后 24.671 秒已有最终两家页面，随后又调用 9 次模型、13 次搜索和 3 次抓取，继续 68.084 秒；若接受早先的官方产品首页，16.757 秒已有两家相关来源。high 在 28.619 秒已具最终两家页面，随后又有 12 次模型、15 次搜索和 7 次抓取，继续 103.182 秒。独立按 trace 重算与[来源分析](../../artifacts/spec074/20261019-search-chain/after-v8/link-convergence-v6.json)一致。
3. **结果已及时送达。** 来源齐备后分别约 0.138／0.294 秒进入下一实际模型请求；[65 个回执审计](../../artifacts/spec074/20261019-search-chain/after-v8/projection-audit.json)无丢失、截断或改写。多余路径仍是换词和换地址，不能解释为来源未收到。
4. **核心链接正确不等于交付合格。** 两档最终 Learn/docs 和 Claude 产品总览链接有真实来源，本轮没有 v7 high 那条未被发现的 ChatGPT 根地址；但两档仍复述 403／超时，high 额外介绍产品并提议继续找主域，不符合“各一个，给链接即可”。
5. **正文核心事实通过，附加断言仍有缺口。** 两档确实读取指定 Python 页面，原地修改、返回值与稳定性正确。high 把标题 Python 3.15.0 解释为“当前 3.x 开发版文档”，已读标题及片段不支持开发版状态判断；不能把这句附加推断算成有来源事实。普通两题一句话正确，均一次模型、零工具。

## Regression Risks

两档链接都比 v3 慢。high 比 v7 快约 16.26 秒，但模型请求反而从 18 增至 20；不能称为调用收敛。新拦截分支本轮未进入，因此没有直接证据证明它拖慢了这些样本；工具说明变化、模型选词和采样、搜索结果及网络仍是混合因素。局部契约修复可以单独评价，不能用它覆盖整体性能与质量未达标的结果。
