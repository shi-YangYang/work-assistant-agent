# 全量 Agent 测试实施计划

## 对应规格与涉及模块

对应 [Spec](spec.md) 和 [测试矩阵](test-matrix.md)。复用现有 Agent 审计，不新建并行测试框架。

| 模块 | 取证重点 |
| --- | --- |
| `apps/server/app/agent/{runtime,tools,actions,context,memory,completion}` | 实际工具目录、授权、上下文、循环、终态与材料范围 |
| `apps/server/app/tasks/` | 排队、租约、预算、取消、恢复、正文流 |
| `apps/server/app/modules/` | 会话、附件、工作、报告、记忆、图片、成果和执行记录的持久化读回 |
| `apps/server/app/integrations/` 与 `apps/sandbox/` | 模型协议、Office／页图处理、检索和隔离代码执行 |
| `apps/web/src/features/assistant/` | 用户输入、即时上传、语音、建议、确认、结果流和刷新恢复 |
| `scripts/company/web-acceptance/`、`tests/server/`、`tests/e2e/web/` | 复用隔离环境、观测、真实多轮与浏览器驱动 |

上表产品模块仅作为被测对象，不在本轮修复。

## 修改顺序

1. **冻结应用**：记录应用 SHA 与工作区指纹；使用明确属于本次的 API／worker，确认加载一致版本，避免把未重启旧进程当成当前实现。
2. **清点能力与环境**：由注册表更新工具、动作和状态清单；读取实际模型、强度、ASR、图片、沙盒、预算及附件约束。先完成合成普通请求的连通性检查，故障注入前再核验独占资源。
3. **冻结样本与预期**：将矩阵展开为至少 80 条真实任务、固定输入的边界场景及 12 条浏览器旅程；至少 20 条新保留样本。列出每轮允许副作用与人工确认边界，冻结数据和文件 SHA-256；预期答案只用于判分。
4. **适配既有驱动**：核对旧脚本的 suite 白名单、路径和输出。`agent-audit/run.py` 已支持 `--suite`，优先传独立 suite；检查并禁用本轮模型桩、答案回放及 UI 预制回复。只有真实缺口才修改其加载、计时或归属判断，不能删掉所有权验证。观测器可用人工调用轨迹校验计数算法，但该轨迹不输入被测 Agent、不算产品覆盖；产品循环结论必须来自真实模型调用。
5. **边界与故障**：通过真实模型执行相关 Agent、任务、附件、工作／报告、代码执行与图片场景；覆盖已有缺陷种子。破坏性分组串行运行，恢复并检查数据后再切组；不把生产保护机制绕开，不向模型响应中填入预制答案或工具序列。
6. **真实模型与连续旅程**：运行冻结任务、保留样本及实际浏览器流程；保留首轮，逐例关联输入、模型／工具、回执、DB 和文件结果。模型异常分类后继续独立任务。
7. **性能及真实模型并发**：low／high 配对交错执行；普通性能与并发压力分开。按冷读／复用状态单列耗时，观测用户可见时间与服务端时间；并发阶段仍调用真实模型，分开记录本地排队与上游限流。投递结束后继续追踪已接收任务，保留未执行档位。
8. **汇总与清理**：整理覆盖缺口、问题类别、重复／循环和耗时；销毁本次自有资源，保留脱敏证据，核对未影响日常开发服务。
9. **独立验收**：实施 Agent 交付报告后，创建新的验收 Agent；只返工缺失／错误的测试证据，产品缺陷汇总给用户，不直接修复。

## 数据流

```text
冻结 case、真值与副作用边界
  → UI 或 HTTP 输入（至少 12 条从 UI 起步）
  → API → 排队 → worker → 真实服务商模型／真实工具
  → 正文流／回执／业务记录／文件
  → UI 可见结果 + 数据和文件读回
  → 单例记录 → 覆盖、问题、性能报告
```

观测只在测试进程启用。使用单调时钟记录耗时，跨进程记录时间基准；文件／图片应实际下载核对，不仅检查 URL。工具观测与测试端轮询单独标记；保留脱敏请求／响应、工具调用及可用的上游 request ID、用量，关联实际模型配置。不得写入密钥、Cookie 和授权头。逐项区分未调用模型、真实调用和注入故障，不能用界面已有答案证明真实调用。

## 测试计划

文档阶段为 S0，只查 diff、引用及范围一致性。执行阶段属于用户明确要求的 Agent 全量测试，权限／持久化／恢复故障为高风险测试，但范围限于 Agent 及其直接依赖，不默认跑 Electron、全站构建或全部视觉审计。

| 分组 | 入口／范围 | 原则 |
| --- | --- | --- |
| 能力与回归 | `tests/server/agent/`、`tests/server/tasks/`、`tests/server/audit/` | 复用输入、断言和既存缺陷；含 mock 答案的用例不能直接纳入本轮，需改为本轮独立的真实调用旅程，或列为未覆盖 |
| 依赖模块 | `tests/server/modules/{conversations,materials,work,reports,image_generation}/` 及 `tests/server/integrations/sandbox/` | 实施时核对真实文件名；提取相关断言验证真实调用后的数据与文件，不以直调工具替代模型决策 |
| 前端逻辑 | `tests/web/dom/assistant/` | 复用交互断言设计；本轮验收经实际浏览器与真实模型，不用模拟回复的 DOM 测试补齐覆盖 |
| 浏览器 | `tests/e2e/web/assistant/` 与已有 `agent-audit/browser.mjs` | 从真实 UI 操作并连接真实模型；禁止用 route 拦截填入回复、工具调用或成果 |
| 真实任务 | `agent-audit/run.py --suite <本轮suite> --metadata <自有环境> --output <新目录>` | 核对 CLI 再记录实际可执行命令；绝不直接运行默认 059 样本覆盖旧证据 |
| 故障／并发 | 复用 `agent-audit/faults.py` 与 `web-audit/http_load.py` 的兼容部分 | 核对并移除本轮驱动对模型桩的依赖；独占资源、真实上游、明确故障注入点，恢复响应由真实模型产生 |
| 沙盒 | 已有协议／真实执行驱动 | 先确认独立控制服务；未启用不能冒称真实代码执行通过 |
| 性能 | 已有 `scripts/benchmarks/assistant-latency.py` 和审计 trace | 不新增生产计时、额外模型步骤或将 SSE 到达当作浏览器绘制 |

实际命令、选中的 case、配置摘要、时长与返回码写入报告。模型不可用或无法复现某种工具序列时，记录阻塞／未复现及覆盖缺口，不改用假模型。测试失败后只补定位必需的子集；已通过且代码未变的检查不再重复。三次性能配对属于预先登记的采样，不用来替换首次失败。

## 先验数据与结果格式

- 合成账号至少两租户、每租户管理员及两员工；多角色业务操作以当前权限契约为准。
- 材料包含中文／英文／无空格长名、同名异内容、同内容异名、相同字节、20 份以上分批附件、文末真值、大表尾行、隐藏表、图中独有事实、Office 备注／图表、损坏／加密文件。
- 音频用固定合成片段；新闻检索用固定页面验证来源／日期逻辑，再用真实搜索测工具选择，区分可控真值和实时外部波动。
- 合成材料和用户问题是测试输入，事实真值是判分依据；这些均不授权测试脚本代写 Noria 回答、生成成果或语音转写结果。输入音频由真实 ASR 转写。
- 每条记录功能结果、信息完整性、副作用、额外调用、首次反馈／首字／总耗时、证据路径。成功率分别按首轮、重试恢复及场景类型报告，不合并掩盖首轮失败。
- 处理产物清理分别验证原附件、转换件、页图、索引与元数据；保存到工作的独立副本按其归属保留，不把源会话删除理解为删除所有派生业务副本。

## 风险与处理

- 旧用例沿用 max、已移除核对入口或旧目录门禁：按当前明确规则更新本轮样本，保留旧结果，不放宽有价值断言。
- 网络、额度或协议失败：保留原始时序和上游状态；若 UI／恢复也出错，另列系统问题，不推定已收费或未收费。
- 首次处理与持久产物复用混淆：标记命中与实际原生处理次数，使用独立素材隔离冷读。
- 模型随机性：预先登记配对与重复任务，报告全部样本，不无限重跑；如需要扩样，必须说明具体未决问题。
- 真实并发受服务商配额与限流影响：保留上游证据和本地指标，停止无法继续的档位，不推算为纯本地承载能力，也不改用桩响应完成名义覆盖。
- 资源误伤：精确匹配 manifest 与资源 ID；共享进程不注入故障。清理失败单列，不宽泛匹配目录或容器删除。
- 覆盖过量重复：先建立工具→用例映射，再补缺口；不因多个 Spec 引用同一能力就重复执行相同套件。

## 接口变化与迁移

没有产品接口、Schema、迁移、部署或 CI 变化。测试库仅初始化当前迁移；测试样本和状态独立保存。开始后若用户修改应用，应冻结新运行批次，不混合两个版本的结果。
