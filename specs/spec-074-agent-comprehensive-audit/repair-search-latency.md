# 搜索等待与重复读取修复

## 实现

- 新建 `web_fetch` 和 `web_search` 节点总计最多两次尝试，保留一次瞬时网络恢复机会；模型及其他工具仍用原四次。节点保存自己的 `maxAttempts`，已存在节点沿用保存的策略，旧记录缺少字段时保持四次；展示、进程中断后的耗尽恢复与执行策略一致。没有调整 HTTP 超时、总预算或模型强度。
- 网络失败保留兼容的 `web_network`，以 `errorCategory` 区分 DNS、连接、超时、TLS、证书、传输、HTTP 超时、限流及服务端故障；未知原因保留 `network`。分类随原节点回执保存、恢复，不增加请求或模型轮次，不根据超时推断地域封锁。HTTP 拒绝访问、人机验证和不安全地址仍按已有规则终止；代理配置另行处理。
- 网页两次尝试耗尽后返回明确 `attemptsExhausted`。同轮、同一完整 URL 的后续 `find`／`offset` 变化不能再次触发网络读取；单次临时失败仍可恢复，`refresh=true`、其它 URL 和后续轮次可重新尝试。成功刷新后允许继续读取新的正文片段，历史失败不会永久封锁该页面。
- 失败回执保留该 URL 此前真实获得的标题、来源类型和读取范围。只需链接且来源已齐时直接交付；需要正文事实时仍须读取相应证据。未发现过的失败 URL 不成为来源，失败也不产生正文或伪装成成功。
- 没有按机构／域名／问题关键词分流，没有新增分类模型或核对轮次，没有把低增量搜索自动判为任务完成，也没有关闭尚需的业务工具。来源判断仍由原有模型完成，因此不能仅凭代码或模块测试承诺消除所有多余搜索。

## 轻量网页抓取

搜索仍使用 Bing RSS；生产抓取由原 HTTP transport 改为 Python `curl_cffi`，使用固定版本的完整 Chrome 请求头、TLS／HTTP/2 指纹，只覆盖需要的语言与 RSS 接收类型。工具名称、分页、来源账本和任务内正文复用不变，不添加模型步骤或系统提示词段落。取消 Chromium 候选及其安装、沙盒、发布预检和进程管理，不保留浏览器兜底或第二套自动 HTTP 重试。

每一跳先校验公开 URL 和全部 DNS 结果，再由 libcurl 连接已验证 IP，保留原 Host、SNI 和证书验证；禁止自动跳转、环境代理和非 HTTP(S) 请求。沿用总时限、连接时限、正文大小和外层重试预算，接收解压后的正文时即限制大小，取消应终止底层请求。Cookie 与连接状态限定到当前抓取，不携带应用或用户凭据。人机验证页返回明确失败，不作为可引用正文；不执行网页 JavaScript，依赖动态渲染的页面仍可能不可读。

请求层对照发现，原 HTTP 和 Chromium 访问 OpenAI 原地址均收到挑战页；`curl_cffi` 的 Chrome 150 配置得到正常 301，跳转到 `chatgpt.com` 后国内直连 TCP 超时。单独给测试进程配置 `127.0.0.1:7897` 后，同一目标返回 HTTP 200、标题“概览 | ChatGPT”，提取 1,121 字符，含跳转 1.497 秒。该代理不进入日常服务或线上配置。完整原始失败和成功结果见[轻量抓取对照](../../artifacts/spec074/20261019-curl-fetch/summary.json)与[临时代理结果](../../artifacts/spec074/20261019-curl-fetch/proxy-7897-result.json)。这只能证明具体请求可读，不能代替 Agent 全流程耗时或证明多余搜索已经解决。

实现按 S3 做定向网络边界、压缩／超限、超时／取消、错误分类与来源兼容检查。测试不调用模型；真实网页对照沿用上述证据，不反复请求已确认受国内网络限制的地址。撤回的浏览器候选仅保留于本地验证产物，不作为当前架构。

实现后的相关模块通过 63 项检查，随后新增不受信任 TLS 证书与 IPv6 地址用例；修正 IPv6 固定地址格式后，两项相关检查通过，合计 65 个不同用例通过。人机验证失败的重复读取保护另在独立测试 schema 通过 1 项，测试 schema 已清理。实际受控服务器观察到原域名 Host／SNI、取消与超时后的连接关闭；不受信任证书在发送 HTTP 请求前被拒绝。首次失败及修复后的结果分别保存在[抓取验证目录](../../artifacts/spec074/20261019-curl-transport/)，不替换首次失败记录。这些结果不代表真实模型搜索收敛已经修复，也不代表日常 worker 已重启加载。

首次[独立验收](repair-curl-transport-acceptance.md)发现慢速拒绝正文回归：服务端立即返回 403 响应头、随后不发送正文时，原 HTTP 路径 0.014 秒返回明确拒绝；初版 curl 等待正文至测试的 0.15 秒预算耗尽，错误变成可重试的网络失败。返工要求在响应头已能确定拒绝、跳转、挑战、不支持格式或超限时立即结束读取，保持原错误分类和跳转处理，正常正文仍按解压后大小限制接收。

返工后由同一响应头策略驱动 curl 提前结束和原有状态处理；主动结束不转为网络失败，100／103 临时响应继续等待最终响应。新增 11 个实际受控网络回归，涵盖慢速拒绝／跳转、挑战、格式、已知大小及正常正文反例。相关抓取、解析、回执恢复模块共 105 项通过，耗时 9.96 秒，见[返工检查结果](../../artifacts/spec074/20261019-curl-transport/header-rework-tests.xml)。新的[独立验收通过](repair-curl-transport-acceptance-v2.md)，首次失败报告保留。未重复真实模型评测或改变日常服务配置。

## 无进展研究收束与跳转证据

最新有效复测使用 [awake 原始记录](../../artifacts/spec074/20261019-search-rerun/awake/)，查链接 low／high 分别为 111.63／196.40 秒。high 已收到足够来源后仍继续探索；同页网络尝试耗尽后，模型使用 `refresh=true` 又获得一组重试。这些是当前修复的直接依据。
