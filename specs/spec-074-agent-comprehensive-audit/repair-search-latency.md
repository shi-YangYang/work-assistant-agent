# 搜索等待与重复读取修复

## 实现

- 仅新建 `web_fetch` 节点改为总计两次尝试，保留一次瞬时网络恢复机会；搜索、模型及其他工具仍用原四次。节点保存自己的 `maxAttempts`，旧记录缺少字段时保持四次；展示、进程中断后的耗尽恢复与执行策略一致。没有调整 HTTP 超时、总预算或模型强度。
- 网页两次尝试耗尽后返回明确 `attemptsExhausted`。同轮、同一完整 URL 的后续 `find`／`offset` 变化不能再次触发网络读取；单次临时失败仍可恢复，`refresh=true`、其它 URL 和后续轮次可重新尝试。成功刷新后允许继续读取新的正文片段，历史失败不会永久封锁该页面。
- 失败回执保留该 URL 此前真实获得的标题、来源类型和读取范围。只需链接且来源已齐时直接交付；需要正文事实时仍须读取相应证据。未发现过的失败 URL 不成为来源，失败也不产生正文或伪装成成功。
- 没有按机构／域名／问题关键词分流，没有新增分类模型或核对轮次，没有把低增量搜索自动判为任务完成，也没有关闭尚需的业务工具。来源判断仍由原有模型完成，因此不能仅凭代码或模块测试承诺消除所有多余搜索。

## 检索来源诊断

从真实工具轨迹发现，多条不同 OpenAI 查询返回同一组公司介绍／百科结果；`Introducing ChatGPT` 查询返回单词 introducing 的词典页。直接调用当前集成时，Bing RSS 的频道标题包含完整搜索词，排除本地只发送首个词的拼接错误。`+` 与 `%20` 两种空格编码返回相同 XML 摘要；当前网络下 `www.bing.com` 跳转 `cn.bing.com`。`Python list sort stable` 返回 Python 主页、下载和入门页，没有直接返回所需排序文档。

针对该查询补查国际参数、地区参数及 global 域名，仍未得到相关排序片段；直接 HTML 搜索也返回相同类型泛化结果。因此不能用更换编码或简单替换 RSS 为 HTML 作为已验证修复。这是当前环境及样本的检索质量问题，不代表 Bing 在所有地区失效，也不能解释来源已齐后的全部模型探索。
