# 业务回执、报告与中断修复

## 修改结果

- **A074-02**：报告生成、编辑、提交的成功回执附带对应版本的 `reportSnapshot`。它记录四个实际栏目、空栏目、截断标记以及正式内容／候选内容的区别，提交成功不再只有“已提交”这一条笼统信息。摘录每栏最多 240 字，避免把整个报告再次送入上下文。工具说明要求按回执描述已保存内容，聊天中提到的事项不等于已经写入报告。
- **A074-04**：报告子任务失败、等待重试或取消时，业务卡片同步呈现失败／取消，不再一直显示执行中。底层仍关联同一个子任务和回执，原位重试后可以恢复执行并完成，不另外创建重复报告。补充模型无效响应与报告解析失败的结构诊断，区分未正常结束、流不完整、非法字段和空报告。
- **A074-08**：没有来源时明确说明“只有工作正文或计划还不能生成报告”，引导记录工作进展或根据当前会话整理正文。没有改变工作记录的取材规则。
- **A074-09**：取消任务时按已提交的业务回执保留成功工具节点及完成结果。已创建的工作仍显示成功，未执行完的步骤显示取消；读取取消结果不会再次把成功回执清空。取消过程中只读取已提交结果，不推进后续提交确认。

按 S2 选择报告、模型响应解析、业务回执及任务状态相关用例，没有运行全项目测试或构建。

1. 响应诊断、流错误、报告回执、无来源报告、任务回执恢复：最初 `67 passed, 2 failed`。其中新用例插入位置错误已修复，并在下一组通过；另一项在准备模型服务时被共享测试库中旧密钥阻挡。
2. 回执恢复与投影、执行权限、报告恢复、答复交付、报告回执：`93 passed, 1 failed`。失败项是共享旧测试库中账户权限数据库默认值仍为 `auto`，当前迁移要求 `full`。
3. 增补报告解析诊断后，报告回执、报告可靠性、工作上下文：`38 passed, 4 failed`。4 项均在准备模型服务时被同一个共享旧密钥问题阻挡，没有进入模型流程。
4. 使用已有 `web-acceptance/environment.py` 创建本机 `paa_company_test` 中带所有权标记的独占 schema，完整迁移后只复验上述 6 项环境阻塞用例：**`6 passed, 93 deselected in 3.41s`**。独占 schema、私有凭据和临时目录随后清理。没有修改共享测试库或密钥校验逻辑。
5. API 合同按项目 Prettier 格式化；实现 diff 无空白错误。

新增验证覆盖了提交版本与随后修改分离、候选内容标记、空字段、无效响应的脱敏计数、子任务失败后同一回执重试，以及真实提交成功后取消 API／反馈仍保留成功结果。

以上模型用例使用可控测试服务，验证产品边界与协议；不是线上模型准确率或耗时对照。真实供应商验证由协调任务统一执行。

## 性能与限制

- 正常流程没有新增模型请求、核对轮次、自动重试或超时时间。报告证据复用当前已加载对象及已有业务写事务，不增加报告读取查询。
- 只有取消操作增加读取业务卡片和草稿回执，以准确反映已经提交的结果；不进入正常回答等待链路。
- 报告回执摘录有上限并带明确截断标记，不能代替完整报告读取。成功回执能帮助模型判断真实结果，但不能保证任意模型都永不产生与证据矛盾的描述。
- 原审计的无效响应缺少当时的结束标记等证据，不能追溯断定是哪一种原因；本次新增诊断用于以后可靠分类，原始证据不足仍如实保留。
- 未修改报告来源政策，没有自动把正文、计划或聊天风险转写成正式工作进展；未加 schema migration，未提交或推送。
