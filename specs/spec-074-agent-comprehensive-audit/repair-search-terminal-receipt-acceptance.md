## 未解决问题与因果边界

1. **来源足够后仍继续。** low 在 worker 开始后 23.511 秒已有最终两家产品来源，此后又有 7 次模型请求、6 次搜索和 5 次抓取，继续 55.198 秒。high 在 24.874 秒已有最终交付的两家有效产品来源，此后又有 13 次模型请求、18 次搜索和 7 次抓取，继续 122.874 秒；若接受最早的 Claude 官方产品首页摘要，8.218 秒已经有两家相关来源。
2. **新终态文案没有消除后续调用。** low 的 34.107、50.204、66.575 秒回执已明确自动尝试结束，同时保留 Learn 产品摘要，后续仍换词及抓取；high 的三次耗尽回执后也都有后续动作。low 对已返回 403 的同一个 URL 又显式 `refresh=true`，实际再次发出请求并得到 403；这是不同于换词搜索的可观测重复请求。
3. **不能把所有额外调用归咎于“请稍后再试”。** low／high 在来源齐备后的首次额外正文抓取分别为 32.396／30.534 秒，早于首次网络耗尽回执 34.107／66.054 秒；但都晚于首次 403 回执 16.328／17.931 秒。已验证措辞更准确，尚未证明它能控制模型何时结束任务。
4. **回复仍有交付和依据问题。** 两档都额外解释 403、抓取过程及重复入口，不符合“各一个官方产品介绍页面，给链接即可”。high 还推荐 `https://chatgpt.com/`，本轮只有失败地址回显、`sourceDiscovered=false`，没有搜索项、页面链接或正文依据；不能用 Learn 子域来源替它背书。low 的 `www.anthropic.com/claude` 有实际重定向到产品页的传输证据，不因来源清单只保存最终 URL 而误判为捏造。
5. **正文核心事实通过，但不能声称全部附加说明有依据。** 两档实际读取指定 Python 页面，原地修改、返回值及稳定性三项正确；high 只读 0–3000、3770–6770 两段后，又断言整个页面没有单独明确说明 `reverse` 的稳定性。已读片段不能支持这种全页否定。两档普通题均一次模型、零工具，一句话正确回答。
