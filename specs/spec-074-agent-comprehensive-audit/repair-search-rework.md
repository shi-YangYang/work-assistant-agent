# 检索停滞范围返工

## 根因与改动

首轮 AFTER 的 T09-low 将不同查询没有新增摘要、新网址的 HTTP 403 和网络失败一并计入全任务停滞，六次后直接进入收尾。单次请求没有被误拒，但下一轮工具全部关闭，导致尚有预算时无法继续寻找第二个官方来源。详见 [首轮复核](repair-search-followup.md)，原始失败与耗时保留。

- `tool_progress/evidence.py` 区分不同搜索请求与同一操作重复。不同请求成功返回已有／空摘要，以及新网址首次 HTTP／网络不可用，属于软停滞；参数错误、被禁止地址和无法可靠分类的错误仍走原有控制。
- `tool_progress/state.py` 对软停滞保留已有硬停滞次数：既不累加到强制收尾，也不清零伪称获得新证据。仍保存结果指纹与 `softStall`，可复核为何未推进。
- `tool_progress/service.py` 保留实际没有新增证据／未读到正文的提示。网页访问在既有有界 journal 内记录地址摘要，防止同地址通过换查找词反复失败逃过控制；相同成功搜索、已有片段和明确拒绝的网址仍不重复执行。显式刷新、新分页与暂时故障的首次恢复仍可进入，重复无进展继续受限。

阈值、总工具预算、模型预算和总时限不变；其他业务写入、目录循环及租约／重放边界不变。没有新增模型、网络请求、数据库查询或独立持久化步骤，也没有扩大全局提示词。小规模摘要比较沿用既有工具记账事务；普通问答没有新增调用。
