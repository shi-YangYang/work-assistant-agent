# 实施计划

## 范围

先共享读请求，再统一失效和恢复事件。沿用已有后端接口，不把多个端点机械包装成一个大请求。

身份隔离、共享请求取消及恢复属于高风险边界，按 S3 验证；用户要求全量覆盖 Web 请求与工作助手多流程，执行 Web 全量测试及公司 API 回归。一个实施 Agent 串行完成，新的独立验收 Agent 验收。Electron、发行打包不在本次范围。

## 实施顺序

1. 扫描 Web 所有请求入口，整理“方法＋路径＋调用功能＋测试证据”清单。在固定会话数据、同一账号下记录进入、恢复、focus、切回可见、发送和任务完成的请求基线；开发 StrictMode 与普通挂载分别计数。
2. 在 `query-resource` 实现共享结果、请求订阅和显式失效。所有实际 HTTP 仍走 `api()`；资源模块不能反向引用业务或请求客户端，避免循环依赖。
3. 为现有资源 Hook 增加显式接入方式，不改变未接入页面。共享订阅不能由单个组件的 AbortSignal 直接中止底层请求；最后一个订阅离开后按有限生命周期清理，兼容立即重挂载。
4. 接入身份初始化、会话恢复、面包屑和会话详情；随后接入历史、操作卡、活动任务、问题及上下文。不同返回形状、分页参数与身份代次必须使用不同资源键。
5. 会话级协调器接管被接入 Hook 的恢复监听；合并可见／在线事件，取消独立 focus 刷新。保留跨标签页活动事件和手动重试，不增加后台时钟刷新。
6. 梳理发送、改名、改人设、改权限、批准、回答、任务终态的更新范围；充分返回的数据直接更新共享资源，余下资源标为失效。被动读取与真实失效使用不同入口。
7. 对照请求预算验证，并检查正文、操作卡、临时问题、上下文图标及发送／中断按钮的状态。仅当结构说明发生变化时更新架构文档。

## 数据流

```text
标题／面包屑／聊天组件
  → assistant 查询入口
  → 按身份和查询参数隔离的共享资源
  → 唯一 api 客户端 → 现有服务端接口

写接口结果／SSE／在线与可见事件
  → 会话刷新协调器
  → 更新明确的新值，或使指定资源失效
  → 需要时执行一次读取 → 通知所有订阅者
```

资源没有版本依据时不能用“后返回”作为更新依据。消息按任务 attempt／fence／seq、业务对象按 revision、身份按 epoch 隔离；初始 HTTP 与 SSE 的合并沿用现有有效规则。

## 接口与迁移

- 不新增或修改后端 HTTP／SSE 字段；不迁移数据库和历史数据。
- 公共 Hook 使用新增的可选接入参数，其他调用方保持原语义。只读共享不改变写请求幂等键、重试入口和授权检查。
- 回滚可恢复旧资源调用，不能重新引入已经删除的定时轮询和无限重连。

## 全量验证计划

### 请求清单

- 覆盖所有 Web 功能入口：登录／钉钉／桌面授权、助手会话与消息、附件、工作、报告与提醒、团队、成员、账户、汇报规则、模型配置与用量、反馈及声纹。
- 每个“方法＋路由＋关键参数分支”映射测试或浏览器证据。分页、搜索、文件字节流、上传、认证跳转、SSE 均纳入；无需为同一请求在多个组件重复建立同义用例。
- 共享请求重点检查重复订阅、取消、身份变化和失效；未接入页面检查请求语义、刷新与写操作不受影响。外部回调、供应商等无法实际连通的入口注明采用受控响应或未执行，不假称真实通过。

### 工作助手多流程

| 流程 | 必须核对 |
| --- | --- |
| 空会话发首条 → 连续追问 → 切走再回来 | 只创建一个会话，消息不丢，正文与用量持续更新 |
| 多会话切换 → 搜索／翻页 → 改名／人设／权限 → 删除 | 标题与面包屑一致，草稿、分页、缓存不串会话 |
| 文字／图片／语音／文档及混合附件 → 解析／转写 → 补充或修正 | 原文件、解析状态、正文和来源一致；重新解析能更新 |
| 联网查询 → 继续追问 → 中断或失败 → 手动重试 | 节点、来源、正文、终态正确，无重复搜索任务或写操作 |
| 创建工作 → 引用工作 → 修改 → 确认／取消 | 三种执行权限生效，保存内容和版本正确，卡片及时更新 |
| 生成报告 → 等待独立任务 → 修改／提交／删除 | 回执与实际报告一致，独立任务状态可刷新 |
| 助手提问 → 临时回答 → 续接任务 | 问题不丢，批准与回答不重复提交；旧页中的待办仍可找到 |
| 请求未确定是否成功 → 断网恢复 → 重试 | 使用原幂等信息，无自动重发、重复消息或重复业务记录 |
| 多标签页并行操作 → 退出 → 更换账号／角色 | 同步收敛，旧响应无效，不能短暂展示前一账号数据 |

使用管理员、普通员工和不同公司身份；材料、业务记录和故障注入使用隔离测试数据。组合流程包含顺序变化，不只执行各功能单独的顺利路径。

### 破坏性场景

- 连续点击发送、重试、确认、中断；读取未完成就切换会话／退出／卸载组件。
- 连续 offline／online、focus／visibility 事件，SSE 突然关闭或重复终态，旧任务事件迟到。
- 注入超时、断流、401／403／404／409／429／5xx、慢响应与响应乱序；GET 在写操作前开始、在写操作后返回。
- 一个订阅者离开、其他订阅者仍等待；StrictMode 重挂载；历史多页、活动任务不在首屏、空结果、删除分页锚点。
- 各场景均断言请求停止条件、数量、最终 UI 和真实业务记录，不能仅凭没有控制台错误判断通过。

### 执行与证据

- 执行 `npm run test:web`、`npm run test:server`、`npm run typecheck:web`、`npm run build:web`；只格式化并 lint 改动文件。公司测试使用独立测试数据库，不能清理用户业务库。
- 浏览器检查正常加载、恢复、错误与连续对话组合；受控模型提供可重复的工具／问题／报告流程，不把受控输出称为真实供应商调用。外部真实服务仅在已有有效授权和配置范围内使用。
- 保存请求覆盖清单、流程结果、必要截图／网络计数到 `artifacts/`，验收文档链接证据并分别列出通过、失败和未执行项。任何与本次改动相关的覆盖缺口均不能直接判定验收通过。
- 独立验收核对覆盖清单及真实断言，不能用“全部测试通过”替代逐项覆盖。相关问题修复后只重跑受影响检查；全部要求满足后停止。

## 主要风险

- 缓存导致旧身份、权限或任务覆盖新状态：通过身份代次、真实版本和失效处理防护，服务端授权保持不变。
- 去重吞掉写入后的最后刷新：被动读取只合并，真实失效必须记录，并在旧请求结束后补读一次。
- 将独立的资源需求误当成冗余：保留会话范围的任务／问题／操作卡读取，不仅依据首屏消息推断。
- 公共 Hook 影响其他页面：显式接入并保留原默认行为，避免顺手迁移全站。
