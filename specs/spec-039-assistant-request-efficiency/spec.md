# 工作助手请求共享与按需刷新

## 状态

请求精简已实施，返工复验通过；全量验收未通过，仍有 2 项 Web、3 项 API 既存失败。结果与证据见 [验收报告](acceptance.md)。

## 背景

工作助手已取消定时轮询和断线后的连续重连，但页面初始化、多个组件订阅相同数据、恢复网络和切回页面仍会产生重复读取。请求成功不代表每一次读取都有必要。

## 目标

- 相同资源由多个组件共享读取结果和正在执行的请求。
- 同一次页面恢复只执行一轮必要刷新，任务事件只更新受影响的数据。
- 保留消息、确认卡、临时问题、上下文用量、单任务限制和断线提示的现有功能。

## 非目标

不改 Agent、模型调用、业务权限、数据库或 Electron；不做全站数据层迁移，不新增聚合接口、持久缓存、轮询或自动消息重发。不以关闭 StrictMode、隐藏日志或延迟显示页面减少表面请求数。

## 当前行为

- 会话恢复、面包屑和会话标题分别请求会话详情，结果没有共享。
- 工作助手分别读取历史消息、未显示在历史中的操作卡、活动任务、临时问题和上下文用量。
- 多个 Hook 独立监听 `online`、`focus`、`visibilitychange`，同一次返回页面可触发重复读取。
- 历史消息加载后又触发活动任务与上下文恢复；任务卡和输入框共享 SSE，但刷新回调仍可能重复读取。
- 开发模式的 Effect 重挂载可能中止并重新发送相同初始化请求；身份初始化也受影响。

## 目标行为

| 场景 | 行为 |
| --- | --- |
| 打开已有会话 | 会话详情由标题、面包屑和会话恢复共享；其他必要资源各读取一次 |
| 新会话且没有消息 | 不查询不存在会话的历史、活动任务、问题或用量；首条真实消息仍自动创建会话 |
| 页面无操作 | 不产生工作助手定时查询 |
| 窗口重新获得焦点 | 不单独触发整页刷新 |
| 标签页从隐藏变为可见、网络恢复 | 由统一入口合并一轮同步；已有健康 SSE 不重开，也不额外查询其反馈 |
| 任务执行 | 节点、正文片段、问题和操作卡优先使用已有 SSE 数据，不随每个 token 查询历史 |
| 任务结束 | 读取一次必要的完整结果并同步状态；多个订阅者不重复触发同一查询 |
| 修改名称、人设、权限或确认操作 | 使用写接口的完整返回值更新对应数据，缺失部分才重新读取 |
| 断线或读取失败 | 保留稳定提示；不循环重连、轮询或自动重发；恢复网络或手动重试可重新读取 |

## 功能需求

### 1. 共享读取

- 请求标识至少包含身份代次、已知的公司／成员／角色范围、资源类型、会话 ID 和完整查询参数。不同会话、分页和搜索条件不能混用。
- 同一资源的并发读取只发出一个请求；同一轮初始化的后续订阅者复用已取得的数据。
- 共用内存状态和请求，不将聊天、认证结果或业务数据新增保存到 localStorage、文件或 IndexedDB。
- 保留唯一 `api/client.ts` 请求入口，沿用认证、CSRF、超时、错误处理和取消机制。共享只适用于明确接入的读操作，不能合并或重放 POST／PATCH／DELETE。
- 订阅者离开只取消自己的等待，不能中止其他组件仍需要的请求。开发 StrictMode 的立即重挂载不能制造重复 HTTP；实际无人使用的资源须释放，不能无限积累。
- 身份初始化 `/auth/me` 仅共享同一次启动的读取，不跨退出登录或重新登录复用认证结果。

### 2. 统一刷新来源

- 工作助手的数据 Hook 不再各自绑定整页恢复事件；由会话级入口统一管理。其他页面原有刷新策略保持不变。
- 区分“想读取当前结果”和“数据确实失效”：重复的被动读取加入正在执行的请求，不额外排队；请求期间发生写入或新版本失效时，最多补一次后续读取，不能漏掉最后结果。
- 网络恢复与页面可见事件重叠时合并请求；手动重试仍遵守 Retry-After，不启动新的重试定时循环。
- 当前消息加载或普通重渲染不能重复读取相同会话的活动任务、上下文用量；SSE 的任务版本优先于较旧 HTTP 响应。
- 替换工作助手中无差别的“记录变化后全量刷新”，将名称、消息、操作卡、问题、任务和用量的失效范围分开。其他业务仍可使用既有通知入口。

### 3. 完整性与隔离

- 不能因为首屏消息自带 job、actions、interactions 就删除会话范围查询：活动任务、待回答问题、保留来源的操作卡可能不在当前页内。
- 名称、人设、执行权限修改后，标题、面包屑和选择按钮一致；失败或版本冲突不能提前显示保存成功。
- 任务完成、失败、中断、重新执行、回答问题和批准操作后，正文与卡片均更新，发送／中断按钮不因旧请求反转。
- 保持当前已展开的历史分页范围、折叠状态、滚动位置和输入草稿。文档独立重新解析、独立报告生成保留手动刷新状态入口。
- 退出、切换账号或身份代次变化时，清理旧资源并丢弃迟到结果；403／404 或权限失效时不可继续展示对应受保护内容。服务端始终重新校验写操作和对象权限。
- 页面返回时不能永久停留在内存旧值；跨标签页任务开始、完成或业务更新后，通过明确事件或一次返回同步获得最新状态。

## 技术约束与兼容性

- 本轮沿用 React、现有 Hook 和资源控制器，不新增查询库；公共层只处理资源与订阅，业务失效规则留在 assistant。
- 请求共享为显式接入，未接入的页面保持现有行为，不把全局 `api()` 改成隐式缓存。
- 保留现有 HTTP／SSE 契约、后端连接池修复和历史会话兼容；没有数据库迁移。
- 不承诺“整个页面只有一个请求”。不同资源仍可独立请求，先消除同一资源的无效重复。

## 验收标准

请求精简的数量预算针对工作助手；兼容性验收覆盖 Web 全部请求入口，包括未接入共享读取的页面。通过拦截网络记录方法、路径、参数和触发场景，不以当前缺少时间／方法的日志直接推断请求频率。资源文件、预检、通知等按实际用途另记，不能把重复写入隐藏在总数下降中。

- [ ] 已登录用户直接打开已有会话，接口正常且没有并发业务变化时：会话详情、消息首屏、操作卡、活动任务、临时问题、上下文用量各至多 1 次 GET；首次整页启动额外至多 1 次 `/auth/me`。
- [ ] StrictMode 下达到同样预算；从 `/assistant` 恢复已记住的会话时，校验读到的详情由目标页复用。失效会话回退查找单独计数并说明。
- [ ] 进入无消息的新会话不发会话相关 GET；不打开会话列表或工作选择器时不预取其列表。
- [ ] 静置 60 秒、普通重渲染或仅窗口 focus，不新增工作助手 GET；合并恢复事件后每个必要资源至多读取一次。
- [ ] 消息卡和输入框共用一个 SSE；反馈更新不制造重复历史读取，终态必要数据各刷新一次。
- [ ] 写入发生在旧 GET 未结束时，能获得最新结果；重复被动刷新不产生排队读取；较旧版本不覆盖新版本。
- [ ] 任务在首屏之外、确认卡／问题在旧消息中、历史分页已展开时，仍可正确展示和操作。
- [ ] 断线、恢复、失败、手动重试、中断、任务续接均正常，没有自动消息重发或持续查询。
- [ ] 快速切换会话、账号切换、403／404、迟到响应和取消订阅不泄露旧数据、不误取消其他订阅者。
- [ ] 按 Web 请求清单逐项关联测试：GET、写请求、上传／下载、认证跳转与 SSE 均有覆盖；遗漏项必须明确列出，不能用总通过数代替覆盖结论。
- [ ] 工作助手的普通对话、附件分析、联网、工作／报告操作、临时问答、三级权限、失败恢复及跨会话组合流程通过；核对实际结果与数据变化，不能只断言 HTTP 成功。
- [ ] 快速重复点击、连续切换、断网抖动、慢响应、乱序响应、服务器错误、版本冲突等破坏性场景没有重复写入、丢消息、串账号、状态卡死或重新出现请求循环。
- [ ] Web 全量自动测试、公司 API 回归、Web 类型／构建及改动文件检查通过；完成浏览器多流程检查，记录请求数量前后对比和未覆盖项。不把受控模型测试写成真实供应商测试，不把网络耗时变化当作必然提速。

## 待确认问题

无。保留真实切回标签页和恢复网络的一轮同步，取消单独窗口 focus 引发的整页刷新；实施范围不扩大，全量验证覆盖 Web 请求与工作助手多流程。
