# 实施计划

## 对应 Spec

[工作助手任务进度展示](spec.md)。按已确认方案实施。

## 涉及模块

- Agent 运行层：根据真实工具调用及执行位置生成名称与有限摘要。
- 节点层：持久化可选展示信息，查询和流式反馈使用同一序列化入口。
- Web jobs 模块：集中派生当前活动、可见操作、异常和计数，组件负责呈现。
- 原重试与执行层保持现有职责，展示信息不参与身份摘要和恢复判断。

## 修改顺序

1. 对照已注册工具确定摘要字段白名单和活动分类，补充旧节点回退规则。
2. 扩展可选展示信息，接入工具入口及模型处理阶段，保持原调用和输出协议。
3. 增加纯展示投影函数，统一可见行、活动状态及计数，再调整进度组件。
4. 验证定向后端、前端和浏览器流程；由新的独立验收 Agent 检查结果。

## 数据流

```text
实际工具参数 / 已授权结果 / 当前运行阶段
  → 集中的名称与摘要规则
  → 原执行节点（附可选展示信息）
  → 同一 node_dtos → 任务查询 / 流式反馈
  → Web 展示投影 → 当前状态 + 操作列表
```

不为状态文案访问模型或增加业务读取。完成后的摘要更新与原节点结果一起保存，不额外创建执行节点。

## 接口变化

- `TaskNode` 保留现有字段，增加可选 `presentation`，区分操作／内部活动并携带有限对象摘要；名称仍通过 `label` 提供。
- 原始节点保留全部运行信息；完成的模型和内部节点仅在展示投影中省略。
- 无展示信息的旧记录按 `kind` 和原 `label` 回退；不从历史自由文本猜测对象。
- 节点字段对查询与流式反馈同步生效；不改变公共任务状态、重试 API 或业务工具参数。

## 测试计划

实施涉及共享任务契约与持久节点适配，按 S3 对相关子系统验证，不默认运行全项目测试或完整沙盒验收。

| 检查 | 覆盖 |
| --- | --- |
| 后端定向测试 | 工具摘要白名单、缺失和超长字段、URL 清理、旧节点、查询／流式一致；节点身份、回执恢复、重试次数不受影响 |
| 前端定向测试 | 显示投影、同名不同对象、并发、普通问答、部分失败、内部重试、压缩、确认与中断；终态不能误报完成 |
| DOM 交互 | 展开后持续更新、同节点名称补全、键盘操作；避免每次节点切换重置展开 |
| 类型及格式 | Web 与改动契约的类型检查；只格式化本次改动文件 |
| 浏览器截图 | 桌面和手机分别观察运行中、展开、完成、长标题及重试状态 |

预计定向命令：

```sh
.venv-server/bin/python -m pytest tests/server/test_task_progress.py tests/server/test_task_retry.py tests/server/test_feedback_connections.py
npm run test:web -- tests/web/task-progress.test.ts tests/web/dom/task-progress.test.tsx tests/web/dom/job-notice.test.tsx
npm run typecheck:web
```

后端使用项目既有测试虚拟环境和独立测试数据库。先跑定向自动检查，通过后做一次固定流程集的界面验证：普通问答、查询工作并导出、搜索并阅读多网页、失败重试、等待补充／确认、中断与刷新恢复。使用固定测试输入和可控反馈，不把界面验证绑定到真实模型随机选择的工具次数；如使用真实模型补充观察，单独记录实际调用与限制，不重复跑到满意为止。

## 风险与迁移

- 过度精简可能掩盖失败：异常与等待状态优先于隐藏规则，任务最终结果独立于可见操作数。
- 工具标题不可信或过长：仅使用白名单字段，纯文本、有界输出，缺失时回退。
- 改展示时误改重试身份：展示字段不得进入 identity、幂等参数或工具输入。
- 历史记录没有对象摘要：保留旧名称，不回填数据、不请求模型或业务 API 补齐。

无数据库结构迁移。回滚展示代码后仍能使用原有节点字段，重试和业务回执不受影响。
