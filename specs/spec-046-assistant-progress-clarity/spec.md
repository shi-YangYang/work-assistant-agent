# 工作助手任务进度展示

## 状态

已实施，独立验收通过。

## 背景

当前 todolist 展示底层执行节点。每次模型调用都出现一行“思考中”，工具只显示固定名称；任务越长，用户越难看出具体做了什么。

## 目标

- 每项操作说明动作及对象，让用户看懂当前进度和已完成的工作。
- 减少重复的模型处理记录，保留真实失败、重试和等待信息。
- 沿用现有轻量折叠列表、状态图标和文字光带。

## 非目标

- 不新增任务规划工具、用户可编辑待办或第二套进度面板。
- 不展示模型内部思考内容，不为生成步骤名称增加模型调用。
- 不改变工具能力、执行权限、重试策略、调用预算或任务完成判断。
- 不改 Electron、独立报告任务及其他页面。

## 当前行为

- `agent/runtime/model.py` 将普通模型调用统一标为“思考中”。
- `agent/runtime/tool_nodes.py` 按工具名选择固定标签，没有查询对象、文件名等摘要。
- `TaskProgress` 逐行展示全部节点，并将成功的模型、工具和内部核对节点一起计入步骤数。
- 原始节点还承担重试、恢复与幂等职责，不能为了精简界面删除。

## 目标行为

例如用户要求“查找上线 Web 的工作，导出 Excel”：

```text
执行中：
整理工具结果 · 处理中
  ✓ 查找工作：上线 Web                  已完成
  ✓ 导出表格：工作清单.xlsx             已完成

完成后：
已完成 · 2 项操作
  ✓ 查找工作：上线 Web                  已完成
  ✓ 导出表格：工作清单.xlsx             已完成
```

名称与文件名仅为示例，实际展示必须取自本次工具参数或已授权结果。执行途中不预估总步数，不显示虚构的未来步骤。

## 功能需求

### 1. 操作名称具体化

展示“动作 + 对象”，状态在右侧单独显示。工具开始时即可展示可靠信息，完成后可用实际结果补充对象，不改变行的身份和位置。

| 操作 | 示例 | 信息来源 |
| --- | --- | --- |
| 查询工作 | 查找工作：上线 Web | 实际查询条件；无条件时为“查找我的工作”等准确范围 |
| 读取、更新工作 | 更新工作：登录页优化 | 已授权的工作名称；只有 ID 时先使用通用动作 |
| 查询报告 | 查找周报：9 月 21—27 日 | 实际报告类型、日期条件 |
| 搜索、阅读网页 | 搜索资料：北京今日新闻；读取网页：页面标题 | 查询词、已取得的标题，缺少标题时使用域名 |
| 文件、表格 | 读取文件：需求说明.pdf；导出表格：工作清单.xlsx | 文件展示名、导出文件名 |
| 图表、文档、幻灯片 | 生成图表：销售趋势；生成文档：实施计划.docx | 实际标题或文件名 |
| Python 执行 | 运行代码：计算季度同比 | 现有执行标题；没有可信标题则使用“运行代码” |

- 统一维护标签及摘要规则，覆盖当前全部已注册工具；新增工具缺少摘要规则时仍可显示通用动作。
- 不把原始参数、代码、提示词、数据库 ID、文件路径或完整结果直接放入列表。
- 显示文本按纯文本处理，限制长度、移除控制字符；网页地址不展示凭据、查询参数和片段。
- 无法确认对象时使用准确的通用名称，不猜测任务目的、成功结果或未授权记录的名称。

### 2. 模型处理与内部核对

- 普通模型调用作为当前活动显示，不累计成多行“思考中 · 已完成”。
- 阶段名根据实际运行位置确定：首次处理可用“理解请求”，工具返回后用“整理工具结果”，明确的答复修复阶段用“完善答复”。无法进一步区分时用“处理请求”。
- 不根据时间推测已进入“生成答复”，也不读取模型思考文本来编造阶段名。
- 正常完成的内部授权、回执恢复及核对步骤不计入用户操作数量；必要的运行中状态仍可展示。
- 上下文压缩保持明确提示；内部步骤失败、重试、需要回答或确认时不能被隐藏。隶属操作的异常可汇入该操作，必须保留原因、状态和重试次数。
- 当前活动结束后撤下活动提示；普通问答没有工具时，不出现“已完成 0 项操作”或空折叠栏。

### 3. 状态与数量

- 完成摘要使用“已完成 · N 项操作”，只统计展示的成功操作；等待确认、需要补充、失败和中断不算成功。
- 任务整体是否完成继续依据现有任务结果，工具全部成功但最终答复失败时不得显示整项任务已完成。
- 同一节点自动重试不增加操作数；同名工具处理不同对象必须分开，不能按标签去重。
- 自动重试总数包含隐藏的内部节点，但嵌套节点的次数不能重复累计。
- 沿用原错误信息和单个重试入口，不新增重试按钮或恢复请求。

### 4. 展示稳定性

- 节点更新、补充名称和下一节点开始时，保留用户选择的展开状态。
- 使用稳定节点 ID，当前活动变化不能导致已有操作行重新挂载或跳动。
- 保留文字光带、运行图标、键盘操作及减少动态效果设置；不增加卡片背景、二级详情面板或常驻诊断信息。
- 长标题在可用宽度内截断或合理换行，状态与图标对齐；手机不横向溢出。

## 边界条件

- 网络中断、中断任务、重试及恢复后，展示以最新真实节点状态为准，不创建额外轮询。
- 多工具并发时展示各自运行状态，不声称只有一项正在执行；总体阶段使用准确的集合描述。
- 部分工具失败但任务仍可继续时，保留失败操作，不能因为后续成功而全标成功。
- 找不到对象、没有文件名、异常结果或旧节点缺少展示信息时，使用受控回退名称。
- 旧会话允许使用已有 `kind`、`label` 和状态精简展示，不扫描或重写历史数据，不额外查询业务记录补标题。

## 技术约束

- 原始执行节点完整保留，展示规则不能改变节点身份、输出、权限与恢复逻辑。
- 后端集中生成有限的展示摘要，前端集中投影为操作列表和当前活动；不在组件中解析工具 JSON 或复制业务规则。
- 复用节点事件、任务查询和现有数据存储，不新增接口、定时请求、数据库迁移或专门的模型请求。
- 样式限定在工作助手任务进度组件内，遵循现有黑白灰设计。

## 兼容性要求

- 新展示信息为可选字段；新前端兼容旧记录，旧前端仍可使用现有 `label`。
- 任务查询与流式反馈中的节点采用同一序列化规则，刷新前后展示一致。
- 历史失败、重试、中断及业务回执继续可恢复；展示更新不触发工具重跑。

## 验收标准

- [x] 示例流程不再留下四行“思考中”，展示具体的查询和导出对象，成功操作数为 2。
- [x] 普通问答、纯分析任务有准确的运行提示，完成后没有空列表或虚构操作。
- [x] 所有现有工具均有受控标签；有可靠参数时展示对象，缺少信息时准确回退。
- [x] 搜索多网页、多文件处理及并发工具的对象可区分，不误合并同名操作。
- [x] 失败、自动重试、确认、补充、中断及压缩状态准确；成功数和任务最终结果不混淆。
- [x] 展开状态、节点身份、文字光带及状态对齐保持稳定，手机长文本无溢出。
- [x] 旧记录、刷新、流式反馈与重试恢复兼容，不新增模型调用或网络请求。

## 待确认问题

无。采用“实际操作列表 + 当前处理状态”，普通模型轮次和正常内部核对完成后不保留独立行；操作显示简短对象，数量按“项操作”统计。
