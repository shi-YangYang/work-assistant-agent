# Spec 071：旧版 Office 兼容与附件解析流程优化

## 状态

已实施，本地独立验收通过。新增 Office 格式统一由 worker 启动固定转换进程，再复用现有解析器；不依赖 Agent 代码执行沙盒。已有格式保持直接读取。验证范围及未执行环境见[验收报告](acceptance.md)，耗时与采样限制见[性能对照](performance.md)。

## 背景

员工有实际 `.doc` 文件无法使用。现有系统明确拒绝 `.doc/.xls/.ppt`；此前广泛文本支持仅解决源码和文本读取，不能代替旧 Office 的专用解析。

本规格接续[附件即时上传与广泛文本支持](../spec-070-attachment-upload-and-text-support/spec.md)。保留“选中即上传、发送后读取”，不通过提前解析或增加模型判断掩盖等待时间。

## 目标

- 员工直接提交常见旧 Office 材料，用于分析、问答及既有代码执行任务，无需自行更改后缀。
- 保留原文件、文件名、独立附件身份、来源引用和真实读取范围。
- 新增 Office 格式采用一套转换流程，不另建 XLS／ODS 专用正文解析器；已有格式保持直接读取路径。
- 减少重复解析、重复转换和轻重文件混排造成的额外等待，不增加模型调用或工具往返。
- 用修改前后对照验证既有功能与耗时，单独报告新增格式的兼容性和成本。

## 非目标

- 不承诺所有历史 Office 版本、所有 WPS 私有格式或任意二进制文件均可读取。
- 不增加 OCR、文件夹上传、通用压缩包解压、文件预览编辑器或像素级版式还原。
- 不执行宏、刷新外部链接、运行嵌入对象、破解密码或将材料发送到第三方转换网站。
- 不调整模型、思考强度、Agent 系统提示词主体、全局任务预算和既有附件容量上限。
- 不自动运行上传的源码，不新增语言运行环境、跨用户内容缓存或常驻 Office 转换服务。
- 本次不扩展 GBK 等通用文本编码支持，不以兼容 Office 为由重做上传、语音或图片流程。

## 当前行为

- 前后端读取 `input-rules.json`，将 `.doc/.xls/.ppt` 列入 `legacyOffice` 并拒绝上传。
- PDF、DOCX、XLSX、PPTX 使用专用解析器；其他允许文件尝试 UTF-8／带 BOM 的 UTF-16 文本读取。RTF 尚未按富文本解释，ODF 容器没有专用支持。
- 文档上传只保存，发送后 worker 准备本条消息的文档；准备结束后启动模型。此行为与模型随后按需读取分段是两个阶段。
- 文档准备已有最多 2 个并发及独立解析进程资源限制；当前消息内相同内容、相同解释方式可复用解析，附件本身已有持久化分段。
- 去重范围包含公司、用户、消息、文件类别、哈希、大小和后缀，不合并附件 ID；本规格不能把这些既有能力再次表述为新增提速。
- API／worker 镜像没有 LibreOffice。现有 Agent 沙盒具有文档工具，但其职责是执行代码任务，本规格的文档准备不接入该服务。

## 目标行为

```text
选择文件 → 轻量上传检查 → 保存原文件 → 等待用户发送
发送 → 校验所属消息与文件身份 → 确定读取策略
  ├─ 已有 PDF／OOXML／文本：原有直接读取
  └─ DOC／XLS／PPT／RTF／ODT／ODS／ODP：worker 固定转换进程
      → DOCX／XLSX／PPTX 临时文件 → 复用现有受限解析进程
      ↓
独立记录每个附件的成功／部分可读／失败
      ↓
沿用现有 Agent 问答、读取分段、引用与代码执行入口
```

混合附件中，快文件可先更新自身读取状态；首版仍在本条消息所需准备步骤结束后启动模型，不把后台并行误称为“无需等待材料即可完整回答”。

## 功能需求

### 1. 格式范围与读取质量

首版范围按以下 7 种新增格式设计；既有格式继续支持。“统一转换”针对这些新增 Office 格式，不要求已能直接读取的文件重复转换。

| 范围 | 格式 | 读取策略与承诺 |
| --- | --- | --- |
| 核心 | `.doc` | 常见 Word 97–2003 → DOCX；读取正文与普通表格 |
| 核心 | `.xls` | 常见 Excel 97–2003 → XLSX；读取工作表、单元格与可保留的公式信息 |
| 核心 | `.ppt` | 常见 PowerPoint 97–2003 → PPTX；读取文本、普通表格、可提取备注 |
| 扩展 | `.rtf`、`.odt` | 转 DOCX；读取中文、正文及普通表格，不把控制标记当正文 |
| 扩展 | `.ods` | 转 XLSX；保留工作表与单元格定位，验证公式及数值差异 |
| 扩展 | `.odp` | 转 PPTX；明确版式和视觉信息限制 |

- 支持不等于完整还原。转换后段落编号仅代表提取结果，不能冒充原 DOC 的页码；图表、图片、嵌入对象及复杂版式不宣称已理解。
- XLS／ODS 统一经过 Calc 转换，再由现有 XLSX 解析器读取。不主动调用全表重算或刷新外部链接；配置可用的禁止自动重算选项，但不能据此承诺所有旧 XLS 的缓存值均原样保留。
- 转换样本必须核对金额、日期、精度、公式表达式及保存结果，覆盖易变函数、过期缓存、外部引用和不支持函数。转换后值不能未经验证就称为“原文件保存值”；缺少结果不能推断为 0。
- 转换表格携带来源说明，明确读取的是转换结果。可识别的缺失或失真必须标记部分可读／失败；已知会静默改变关键数据的样本阻塞该格式验收，不能只加提示后判定通过。无法建立可靠边界时先报告具体限制，不擅自改回多套正文解析方案。
- 旧表格可增加受限的公式缓存完整性核对，比较原件与转换件的对应单元格保存结果；此检查不承担正文提取。值发生变化或公式缓存无法可靠核对时，该附件明确失败并建议另存为新格式，不静默使用重算值；普通表格和核对一致的公式继续支持。检查纳入同一处理预算，不调用模型。
- 表格保留日期、布尔、空值、错误值、合并单元格说明及行列定位；隐藏区域沿用 XLSX 的跳过与提示规则。不能只取第一个工作表或把全部表格压成一段无定位文本。
- 对支持范围内的限制给出准确提示；空白文件与无法读取不是同一种成功。达到分段／字符／表格边界时标记部分可读。
- `.wps/.et/.dps`、`.xlsb`、模板类、Pages 等不随本次自动放行或承诺。WPS 软件保存的标准 DOC／DOCX 等按实际标准格式处理，与 WPS 私有格式区分。

### 2. 上传、格式识别与安全边界

- 前后端共享格式能力表，支持项从“旧 Office 一律禁止”改为明确读取路由。现有程序、安装包、压缩包和显式宏格式禁止规则保留。
- 上传阶段仍不读取正文、不转换、不调用模型；仅进行现有权限、大小、名称及必要文件头检查。浏览器 MIME 为空或为通用二进制不能单独作为拒绝旧 Office 的依据。
- 发送后依据后缀与实际结构选择一次读取策略；OLE 文件头不能单独证明内部是 Word、Excel 或 PowerPoint。
- 对 `.doc` 实为 RTF／DOCX 等已支持内容的常见兼容情况，识别明确结构后进入对应分支，并保留原名。无法可靠识别的伪装文件提示重新导出，不按任意二进制尝试所有解析器。
- 宏、活动对象、外部链接的处理在专用读取阶段完成，不给所有文本增加扫描步骤。显式宏后缀继续拒绝；旧 Office／ODF 中检测到宏或不支持的活动嵌入对象时，停止该文件读取并提示移除后重新保存。
- LibreOffice 由 worker 启动独立子进程，使用独立临时目录与 profile、固定参数和非 shell 调用；显式禁用宏、可信位置及外部内容更新，转换环境变量不继承模型密钥、数据库凭证或代理配置。不将 `--headless` 本身视为安全措施。
- 转换进程以非 root 身份运行，设置 CPU、内存、耗时、输出及进程树清理边界。worker 内子进程仍共享容器权限；清空环境变量和设置工作目录不等于文件系统／网络隔离，不能宣称具备 Agent 沙盒的安全边界。宏和外链配置须用受控样本验证。
- 输出必须同时通过进程结果、文件存在、格式结构和资源边界校验；命令退出成功不能代替转换成功。加密、损坏、格式不支持和依赖不可用分别处理。

### 3. 流程优化

- 根据已确定的格式直接路由，不增加“让模型判断文件类型／决定转换／核对转换”的调用，不新增暴露给 Agent 的转换工具。
- TXT、代码、PDF、DOCX、XLSX、PPTX 的正常路径不启动转换进程，也不每条消息探测转换依赖。
- 将直接读取与重转换分开调度。普通解析保留已有上限；转换初始每 worker 进程最多 1 个，等待受任务总预算限制。部署容量按 worker 进程总数核算，不能把单进程信号量描述成全局上限；不新增队列服务。
- 转换排队不占据直接解析的信号量；不能让两个排队的旧文件占住全部轻量解析位置。保留上传顺序和引用对应关系，不按完成顺序改变附件编号。
- 复用同一附件已有成功结果，以及同一消息内相同内容、相同读取策略、相同解析／转换版本的在途结果。不跨账号共享结果，不仅凭文件名复用。
- 每个等价附件仍校验自身身份、保留独立 ID／分段／引用。取消一个子任务不得误取消仍有使用者的共享转换；取消整个消息必须释放所有关联运行。
- 不缓存排队超时或转换进程故障为永久失败；用户重试可重新尝试失败项。成功项不因另一附件失败而重复转换。
- 按实际读取策略维护版本指纹；新增旧格式支持不能令所有既有成功解析失效。复用已有持久化分段，不为单纯重复转换新增文件库或全局缓存表。
- 无附件消息不增加数据库扫描、哈希计算或转换探测。文件哈希使用既有上传 SHA-256 和必要完整性校验，不因新流程额外完整扫描原文件多遍。

### 4. 状态、错误与用户体验

- 选择 `.doc/.xls/.ppt` 后，立即在输入框附件区域显示一条轻量兼容提示，上传中即可看见，不等发送或解析失败再提醒。文案：**“旧版 Office 文件可能解析失败或内容不完整，建议先用 Microsoft Office 或 WPS 另存为 DOCX、XLSX、PPTX 后上传。”** 不表述为一定失败，也不承诺转换后一定可读。
- 提示根据已有文件格式信息显示，不读取正文、不调用模型；同一草稿的多个旧文件合并为一条提示，移除全部旧文件后消失。普通新格式不显示该提示；RTF／ODF 如需提示，使用“此格式需要转换”的准确措辞，不统称为旧版 Office。
- 使用桌面和手机均能直接看到的行内提示，不依赖鼠标悬浮，不弹确认框，也不阻止用户继续上传／发送；上传未完成或上传失败时仍遵守既有禁止发送规则。提示与实际上传错误、发送后读取失败分别呈现，不将兼容性提醒显示成已失败状态。
- 上传成功仍只表示已保存；发送后在现有附件状态中区分等待处理、正在转换、正在读取、可读、部分可读及失败。
- 尽量复用现有 `pending/processing/ready/partial/failed`，通过可选阶段字段表达转换，不增加全屏等待页、弹窗或虚假进度百分比。短阶段沿用现有防闪烁处理。
- 失败及时显示在对应文件上，不等待模型解释。可重试故障沿用重新解析入口；格式、密码等问题给出明确的下一步。

| 情况 | 用户提示示例 |
| --- | --- |
| 未安装转换依赖 | 暂时无法读取此格式，请联系管理员，或另存为 DOCX、XLSX、PPTX 后上传。 |
| 转换进程故障 | 文件转换暂时不可用，请稍后重新解析。 |
| 加密文件 | 文件已加密，请解密后重新上传。 |
| 不支持的格式变体 | 暂不支持此文件格式，请用 Word／WPS 另存为 DOCX、XLSX、PPTX 或 PDF。 |
| 超时或资源超限 | 文件处理超时或超出资源限制，请拆分或重新导出后上传。 |
| 不能确定具体原因 | 文件读取失败，请确认能正常打开，或重新导出后上传。 |

- 一份附件失败不取消其余附件；回答必须保留缺失材料提示，不能据其内容得出确定结论，也不能自动反复转换相同失败文件。
- 手机、桌面和工作材料入口使用同一格式规则。窄卡片文案保持省略与可查看详情，文件名不撑宽布局。

### 5. 原文件、代码执行与清理

- 原附件字节、名称与下载链接不被转换结果覆盖；内部中间文件不创建聊天成果卡片，也不作为新的用户附件计数。
- 原始附件仍可按现有授权作为代码执行任务输入。分析问答的转换由 worker 固定流程负责，未部署 Agent 沙盒也能完成，不需要模型写转换脚本。
- 不把“能提取文字”扩大成“既有所有表格工具都原生支持 XLS／ODS”。本次保留现有代码执行文件引用；原件与内部转换件必须明确区分，不能静默将原件替换为转换件。
- 临时转换文件在成功／失败／取消后清理；工作材料复制、原消息删除、任务重启、重新解析时保持现有来源权限和版本隔离。
- 转换不产生 Agent 工具调用或沙盒执行回执，内部处理信息纳入既有附件元数据。进程 ID、宿主路径和内部错误不直接返回浏览器。

### 6. 故障收敛与服务可用性

- 格式识别、排队、转换、输出检查、解析和持久化均有明确的失败出口；异常必须落到对应附件的可见状态，不能遗留永久“处理中”，也不能吞掉异常后写成成功。日志保留附件／任务关联与阶段，不泄露正文或凭证。
- 单文件损坏、转换进程崩溃、资源超限或清理失败，不得直接终止整个 worker 或取消其他用户任务。失败项保留原件和可操作提示；剩余材料正常处理，回答明确未读到哪些材料。
- 等待转换期间不长期占用数据库连接／事务；输出日志有界消费，避免子进程输出堵塞。取消、超时、异常路径都要释放并发槽位、文件句柄和进程资源，清理操作可重复执行。
- 存储故障与 worker 重启按既有租约恢复机制收敛；数据库尚不可用时不虚报状态已保存，恢复后对账终态。不能通过无上限重试、扩大所有超时或重启全部服务来处理单个坏文件。
- 测试必须验证故障后的服务可用性：其他账号能登录和处理普通任务，同一 worker 可继续处理下一份正常文件；仅返回健康检查成功不足以证明恢复。实际 worker 被终止的测试单独验证重启恢复，不冒称进程未中断。

## 边界条件

- 多批文件、同名不同内容、同内容不同名、大小写后缀、超长文件名、缺失 MIME、伪装后缀及旧文件与图片／语音混合。
- 现有并发上限下，一慢多快、全部旧文件、多用户同时转换；队列满须有界返回，不无限挂起。
- 转换中取消、worker 重启、进程失联、结果晚到、删除与解析竞争：不得复活已取消任务、覆盖更新后的版本或重复发布结果；不得遗留长期占用资源的转换进程。
- 已有历史附件不全量重解析；之前按文本误读的 RTF 等，仅在明确重新解析时更新版本，并使旧引用按已有规则失效。
- 文档所含文字属于材料，不成为操作授权或系统指令。

## 技术约束

- 沿用现有 FastAPI、worker、解析子进程及 PostgreSQL 附件记录，仅在 worker 镜像安装 LibreOffice Writer／Calc／Impress 及必要运行依赖；API 镜像保持原边界，不新增常驻容器或第三方转换服务。
- 不修改 Agent 沙盒协议、执行镜像或工具 Schema；不依赖沙盒配置、连通性、配额或队列。转换前后仍保留附件身份、租约、版本及完整性校验。
- 转换进程与现有解析子进程分开：现有解析器禁止创建子进程，不能为启动 LibreOffice 而放宽所有解析任务的限制。转换完成后使用现有解析器处理产物。
- 本地 worker 需要对应 LibreOffice 安装；依赖检查在部署预检／启动阶段完成并准确提示，缺失只影响新增格式。锁定并记录生产转换组件版本，不升级无关依赖。
- 仍使用既有上传 20 MB、提取 20 万字符、2000 分段及表格边界。单文件转换与后续读取共享现有 60 秒执行预算，不能简单叠加成两个 60 秒；排队另计且受现有任务总预算约束。
- 准备阶段完成才进入既有模型流程。减少模型等待的目标不允许通过遗漏材料、偷偷截断或弱化权限校验实现。
- 实施属 S3：涉及文件解析安全、子进程管理及 worker 镜像，做相关子系统验证与受控破坏性测试，不自动叠加完整桌面验收。

## 兼容性要求

- 公共上传／发送 API、附件 ID、下载与引用协议保持兼容；解析阶段等新增字段可选，老客户端仍能显示正在解析或失败。
- 优先使用 `extraction_info` 和已有分段，不预设数据库 schema migration；若实施确认必须新增持久结构，先更新方案再实施。
- worker 镜像随业务发布构建并验证真实转换能力，不要求安装或更新 Agent 沙盒；原件和已保存分段兼容原有数据结构。
- 转换依赖缺失只影响新增格式；普通问答和已有附件继续工作。正式环境开放该能力前必须通过真实 Writer／Calc／Impress 转换冒烟。
- 本地启动、CI 和 CD 必须覆盖必要依赖及版本一致性；本次 Spec 不授权操作线上部署。

## 验收标准

- [x] 桌面与手机选择旧 Office 时即显示兼容提示；多文件不重复刷提示，移除后消失；不触发提前解析，不改变正常上传与发送条件。
- [x] 真实 DOC／XLS／PPT 样本可从选择上传到最终问答、来源查看、刷新、追问完整使用；不是仅把后缀加入允许列表。
- [x] RTF／ODT／ODS／ODP 通过同等真实文件验证；中文、表格、工作表、备注与关键数据符合固定预期。
- [x] XLS／ODS 转换后的公式及数值与固定预期核对；不主动重算或更新外链，不冒称缓存无损保留，已知关键数值失真不得通过验收；原文件未被改变。
- [x] 上传完成但未发送时，转换、正文解析、模型调用次数均为 0。
- [x] 未部署 Agent 沙盒也能读取全部本次新增格式；普通格式不启动转换器。同消息重复内容只执行一次有效转换／解析，名称相同但内容不同不会误合并。
- [x] 取消、超时、崩溃、队列满、临时文件清理及租约恢复均有受控验证；其他账号和公司无法访问原件或派生数据。
- [x] 一个坏文件与多个正常文件混合、转换资源超限、输出异常、存储故障及取消后重试，均验证附件终态与清理；故障后其他用户及后续正常任务可用，无永久占槽或持续增长的孤儿进程／临时文件。
- [x] 宏不执行、外部内容不刷新；格式伪装、解压膨胀、异常输出有界失败，资源限制与取消清理有效，原解析进程限制未放宽。准确记录 worker 子进程权限边界，不冒称完整沙盒隔离。
- [x] 工作材料保存后删除源消息仍可读；分批上传后读取较早材料、生成成果和刷新引用保持正确。
- [x] 按 AGENTS.md 的完整流程要求验证浏览器操作、真实 API／worker／转换器／存储链路及最终交付；核对正文、附件状态、引用、成果内容和刷新后持久化，不以单接口成功或模型口头“已读取”代替。报告分别列出模块、流程、组合覆盖及未执行项。
- [x] 给出修改前后受控耗时对照，普通聊天和既有格式没有新增模型轮次或明显性能回归；新增格式单独报告，不虚报提升。
- [x] Web 相关模块、服务端解析／附件、worker 真实转换及部署能力检查通过；未执行的环境单独列明。

无新增架构决策待确认。按上述 7 种格式准备实施；WPS 私有格式和 XLSB 不在当前范围。具体版本的公式兼容性、进程资源上限需用样本验证，不能用未经验证的承诺代替验收。
