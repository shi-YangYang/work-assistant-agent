# 完整性与目标版本返工

独立验收要求补齐易变公式、不支持函数、缺失／过期缓存，以及生产固定 LibreOffice 7.4.7.2 的七格式完整样本；原来的三类发布预检不能替代这些检查。

## 修复

- 7.4 导出的正常 ODS 在尾部保存大量重复空行／空单元格，原完整性检查把它们计入 50 万展开槽位，误判为文件过大。现在无公式、无值类型、无子内容的空占位仅推进坐标；实际内容和公式仍保留展开预算，ZIP／XML、进程资源与解析预算不变。百万空行不影响原坐标，50 万以上重复公式仍拒绝。
- 7.4 可以把 `1=1` 的 ODS 缓存保存为数值 `1`，转换 XLSX 后却标为布尔 `true`。现在仅对严格相等的 `0/1` 数值与布尔缓存恢复原件类型；既有反向处理同样保留。只修派生 XLSX 的类型，不改变原件、数值或公式，不从展示文字推断类型。`n=0`／`n=0.5` 与 `b=1` 仍拒绝。
- ODS 的布尔保存值严格接受 XML 的 `true/false/1/0`；缺失或非法值明确拒绝，不能通过原先的 `else false` 补零。

## 验证

新增 19 个定向用例；未重复原来的全模块或普通性能套件。

| 检查 | 结果 |
| --- | --- |
| native 新增公式边界（`-k formula_boundaries`） | 9 passed，12.55 秒。随后 ODS 修复导致相关路径变化，进行下列最小复验。 |
| 空白／重复公式及受影响 ODS 边界 | 7 passed，11.02 秒。 |
| 布尔原类型、非等值拒绝及正常 ODS | 5 passed，6.56 秒。 |
| 布尔 `1/0` 保值、缺失／非法值拒绝 | 4 passed，6.39 秒。 |
| 固定生产镜像 `noria-spec071-worker`，Linux ARM64／LibreOffice 7.4.7.2，最新源码只读挂载、网络禁用 | 七格式及边界合计 25 个真实检查通过。前四格式已通过后未重复；修复后从失败的 ODS 继续 17 项通过，再定向补布尔严格值 4 项通过。 |

目标版本七格式断言包含原件字节不变、阶段、段落／表格文字、金额与日期、原公式与保存值、布尔／错误／字符串类型、合并范围、隐藏工作表提示、工作表／单元格定位与演讲备注。

| 目标版本公式样本 | 实际结果 |
| --- | --- |
| XLS／ODS 的 NOW、RAND | 重算值与原保存值不同，明确失败，无提取分段。 |
| XLS 未知函数 | 转换后的错误值变化，明确失败。 |
| ODS 未知函数 | 保留原 `#NAME?` 错误及定位，正常提取，不将错误变为数字。 |
| XLS／ODS 缺失缓存 | 明确失败，不补零。 |
| XLS／ODS 过期缓存 | 转换值与保存值不同，明确失败。 |
| ODS 原生布尔／数值 1 | 分别保持原件的 `True`／`1` 类型和值。 |
| ODS 布尔 `1/0`、缺失／非法值 | 合法值保持 `True/False`；缺失和非法值明确失败，无提取分段。 |

证据保存在 `artifacts/spec071/integrity/`：`production-7.4.jsonl`、`production-7.4-ods-diagnostic.jsonl`、`production-7.4-final.jsonl`、`production-7.4-boolean.jsonl`，复现入口为 `target_runtime.py`、`boolean_cache_runtime.py`。材料由真实 LibreOffice 导出；边界样本仅修改已知公式的序列化缓存或重复空白／公式属性，不使用真实员工文件或 mock 转换。

本次仅修改完整性检查与测试，不改变模型轮次、队列或正文解析器。此前 native 26.8 的 30 组性能采样在本次 ODS 修复前完成；未将该数据冒称修复后的生产 7.4 性能。ARM64 容器结果不代表生产 AMD64 或真实 Windows 已测。最终结论仍由新的独立验收 Agent 给出。
