# Plan：旧版 Office 兼容与附件解析流程优化

## 对应 Spec

[需求、范围与验收标准](spec.md)。新增 Office 格式由 worker 统一转换，已有格式继续直接读取；按以下顺序实施并独立验收。

## 涉及模块

- 共享附件规则：区分直接解析、需要转换、明确不支持，前后端共用。
- 文档解析：格式识别、转换后的 OOXML 复用、统一分段与错误。
- worker 准备：轻重文件分开调度、同消息复用、取消、租约及解析版本。
- 转换进程：worker 管理 LibreOffice 的固定调用、预算、输出检查与清理。
- Web：沿用附件状态组件，补转换阶段与准确失败原因。
- 部署：只在 worker 镜像增加 Writer／Calc／Impress，本地开发补对应依赖说明；不增加服务或 Agent 沙盒依赖。

## 修改顺序

### 1. 固定基线与样本

- 实施前记录基线 Git SHA、镜像摘要、worker 数量和资源配置；建立临时数据集，不使用真实员工材料做破坏性测试。
- 使用真实 DOC／XLS／PPT 容器作为样本，不能通过给 DOCX 改名来代替兼容性验证。覆盖 Word/WPS 导出的常见版本；测试材料自建或使用许可明确的公开样本，记录生成方式。
- 先记录既有格式正常流程的解析次数、模型调用次数与耗时，避免实施完成后再凭印象比较。

### 2. 格式路由

- 共享输入规则新增明确的文档能力分组；上传层只做轻量类型核对，发送后再识别实际容器。
- 新增 `formats.py` 维护读取路由与版本指纹；识别结果应包含原格式、实际解析类型和是否需要转换。
- DOC／RTF／ODT → DOCX，XLS／ODS → XLSX，PPT／ODP → PPTX；不新增 `xlrd` 或 ODS 正文解析器。
- 现有 PDF、OOXML、文本与代码保持原解析入口。不要为统一流程把现有支持格式也先转换一遍。
- 宏／活动对象检查只在新文档分支读取必要结构，拒绝不支持的活动内容；不为普通源码增加额外处理阶段。

### 3. worker 固定转换进程

- 在 `integrations/parsing/` 新增 `office_conversion.py` 负责转换路由、结果与临时文件；`office_process.py` 负责固定命令、进程树、资源预算及退出处理。参数仅允许受支持的输入种类和固定目标格式，不接受模型提供的命令或任意过滤器。
- 非 shell 调用，输入／输出使用内部生成名称和独立临时目录，原文件只作为输入，不能被覆盖。进程使用非 root 身份、独立 profile 和最小环境，不继承凭证／代理配置。
- 明确配置宏禁用、可信位置为空、外部内容不更新，必要时通过固定加载适配程序设置文档加载属性；不能仅传 `--headless` 就声称完成限制。用可观测的宏／外链样本验证，无需新增常驻 UNO 服务。
- 设置 CPU、内存、输出及墙钟时间边界，取消／超时回收整个进程树。父进程异常退出和 worker 重启后的孤儿进程、临时目录也必须处理；不能只终止外层包装进程。
- 当前 worker 容器持有业务权限，子进程不是独立安全沙盒；不把环境变量白名单或临时目录称为网络／文件系统隔离。保持现有受限解析进程不变，不放宽其禁止启动子进程的策略。
- 验证转换输出存在、大小及结构后，再传给现有 DOCX／XLSX／PPTX 解析器。无需服务间传输或执行回执；产物不发布为聊天成果。
- 实施首先完成真实表格转换可行性验证：检查金额、日期、公式、易变函数、外部引用与缓存差异。不主动调用全表计算，关闭支持的自动重算选项；旧 XLS 不能仅凭 Excel 2007 的配置选项推断兼容。关键数据失真的样本先定位并阻塞验收，不以提示文案掩盖。
- 为 XLS／ODS 公式增加有限的保存结果完整性核对，覆盖数值、字符串、错误、缺失结果与单元格定位。转换改变结果或无法可靠验证时拒绝该附件，保留原件及另存建议；不另建正文解析器，不用普通文本提示掩盖已知数据变化。必要的 OLE 结构检查依赖锁定版本。
- 记录转换器与固定转换策略版本；部署预检校验实际 Writer／Calc／Impress 转换，不只检查二进制存在。普通请求不额外运行依赖检查。

### 4. 准备流程、复用与恢复

- 在 `prepare_document` 中统一路由、阶段与成功持久化；保持原有身份、完整性、revision 和租约检查。
- 解析与转换分别排队，普通解析仍最多 2 个，重转换每 worker 进程初始最多 1 个。整体容量按实际 worker 进程数及容器资源预算计算；不引入额外队列服务，也不把局部信号量当全局限制。慢转换不能占用轻量解析信号量。
- 消息内按内容身份与实际策略建立共享任务；不同附件使用独立结果写入。实现中注意共享 task 的取消传播与使用者引用，整条消息取消则统一回收。
- 保留同一附件已成功结果，失败重试只重新准备失败项。策略指纹不能无差别改变已有格式的 parserVersion；历史格式未变化则继续命中原结果。
- 转换预算扣除已用时间，剩余时间传给后续解析；排队由任务总 deadline 限制。不在原 60 秒外再无条件添加 60 秒；冷启动能否满足预算以真实样本确认。
- 处理阶段与转换来源写入已有元数据，公开 DTO 显式选择安全字段；进程 ID／路径不暴露。持久化提交前再次检查版本和租约，重启恢复不能使用旧输入产物或让取消后晚到结果变成成功。
- 不改变 `DocumentChunk` 与附件 ID 的关系；优先不新增数据表。若无法安全复用现有持久字段，先更新 Spec 的数据迁移设计。
- 为各阶段定义明确错误分类与终态，单附件错误局部收敛；转换等待不持有长数据库事务，日志输出有界消费。释放信号量、关闭句柄、回收进程和临时文件放在可重复执行的清理路径中，清理异常不得覆盖原始错误或中断其他任务。
- 存储故障时保留可恢复信息，沿用租约恢复与版本核对；不把数据库提交失败伪装成附件处理成功，不增加无上限自动重试。

### 5. UI、部署与文档

- `Attachment.extraction` 增加可选处理阶段、原格式与转换说明；保留现有状态枚举，旧客户端无需改动即可显示处理／失败。
- `Documents.tsx` 复用现有附件状态与重试入口，转换等待不显示模型思考，不重做附件卡片。
- `ComposerAttachments.tsx` 在选择旧 Office 后显示 Spec 中的兼容提示；使用共享格式能力识别、按草稿合并展示，移除全部对应附件即隐藏。采用紧凑行内样式，桌面与手机均可见，不能挤压卡片、遮挡发送或引入确认步骤。
- 在 `deploy/company/Dockerfile` 的 worker 阶段安装固定版本的 LibreOffice Writer／Calc／Impress 与必要字体，不能放入 API 共用基础阶段。既有镜像构建流程继续复用。
- 本地开发说明补充 LibreOffice 安装与查找方式；启动预检只报告一次能力状态，缺失时原有功能可启动，新格式给出明确失败。不在每条消息执行版本探测。
- 更新现有发布检查，在 worker 镜像内验证真实 DOC、XLS、PPT 转换，再开放新格式能力；检查失败应明确标记未就绪。无需启动或更新 Agent 沙盒，不修改其协议。
- 老镜像回滚继续保留原件与已生成分段；新格式暂停处理需有明确提示，不删除用户材料。

## 数据流与接口变化

- 公共上传／发送接口路径与参数不变；仅扩展共享允许能力与可选解析信息。
- 转换为 worker 内部函数与受控子进程，不增加公共转换 API、私有沙盒协议或模型工具 Schema。
- 转换复用身份绑定用户、消息、附件内容／revision 和转换版本。不要只用文件名或未含租户信息的哈希。
- 原文件是分析与后续沙盒任务的来源；中间文件仅用于读取，清理后以持久化分段继续回答。不把转换中的内部 URI 作为用户下载链接。
- 任务时序指标在既有 `context.timing` 上增加格式识别、排队、转换与缓存命中；不将正文写入性能日志。

## 测试计划

实施风险为 S3，验证范围限定为附件解析、worker 转换进程、相关 Web 展示和部署能力。文档起草本身按 S0，不执行下列业务检查。

### 功能与完整流程

- 依照 [AGENTS.md 的完整用户流程规则](../../AGENTS.md#全量测试完整用户流程与高风险组合) 设计用例；范围覆盖本次附件能力及其直接关联的跨批次、工作材料、代码成果流程，不扩张为与本次无关的全产品验收。
- 转换后解析：每种承诺格式至少有正常中文样本和损坏／边界样本；核对实际提取文字、表格值和定位。XLS／ODS 额外覆盖多个工作表、日期、合并、隐藏、公式保存值缺失、错误值、外部引用、易变函数与过期缓存，检查是否发生非预期重算或数值变化。
- 路由：DOC 实为 RTF／DOCX、错误 MIME、OLE 非 Office、伪装程序、ZIP 非 ODF 等不能误报成功；已有普通代码／文本仍走原路径。
- 工作流：选择→上传但不发送→发送→读取→有依据回答→刷新→追问；验证转换／模型何时开始及调用次数。
- 组合：多批累计超过单次限额、9 个附件含旧／新 Office 与媒体、同内容重复、同名不同内容、取消后重试、已保存工作材料的源消息删除。
- 受控模型验证工具结果和最终来源覆盖；真实模型仅补 low／high 样例，不把文风或字数作为解析准确性标准。

### 用户流程与高风险组合矩阵

以下为最低覆盖，实施时结合实际接口补紧邻边界。使用自建、有已知答案的真实 Office 文件和临时账号／数据；成功路径必须实际经过上传、API、worker、LibreOffice、现有解析器和数据库。受控模型仅替代外部模型响应，不能用 mock 转换结果代替转换链路验收。

| 场景 | 连续用户操作 | 必须核对的结果 |
| --- | --- | --- |
| 首次上传与提示 | 桌面／手机选旧文件 → 看提示 → 上传完成但不发送 → 删除／重新添加 → 发送 → 问答 | 提示合并与消失、发送条件、发送前转换／解析／模型调用为 0，最终回答有真实依据 |
| 新旧格式与媒体混合 | 同一消息混合旧 Office、新 Office、图片和语音 → 发送 → 查看逐文件结果 → 追问 | 数量与顺序正确；普通格式直读；正文、定位、状态与实际读取范围一致 |
| 多批与历史材料 | 分批累计超过单条消息附件上限 → 后一批要求读取前一批 → 合并分析 → 生成成果 → 流式完成 → 刷新再追问 | 不绕过单次限制、不漏较早材料；成果实际内容、来源与持久化完整，不能只验证能下载 |
| 重复与重命名冲突 | 同内容不同名、同名不同内容、接近长度上限的名字、自动编号后再次撞名 → 发送 | 不覆盖文件、不误合并；转换／解析次数符合复用规则，附件 ID、引用及显示名称对应正确 |
| 单文件故障 | 坏文件和正常文件一起上传 → 发送 → 查看失败 → 替换或重新解析 → 再问问题 | 错误落到具体文件，其他文件可读；失败项不被当作已读依据，无死循环和永久处理中 |
| 取消与重试 | 转换排队／运行／完成待保存时取消 → 刷新 → 发新消息／重试 | 无晚到成功覆盖取消、重复分段或孤儿进程；并发槽位回收，后续正常文件可处理 |
| 工作材料生命周期 | 保存工作材料 → 删除源消息 → 重新打开材料 → 读取与下载 | 原件、分段、来源与权限仍正确；派生文件不冒充原件，不生成额外附件卡片 |
| 多用户与恢复 | 多账号同时发快慢文件 → 一个转换异常／资源超限 → 另一个账号登录、普通聊天、上传正常文件 | 故障不扩散；新任务能完成，队列等待有界，CPU／内存与进程数量符合配置 |

- 浏览器验收覆盖桌面与手机宽度、提示和错误可见性、上传／发送／取消／刷新；后端确定性集成用例覆盖同一业务链路及故障，二者分别报告，不能用 DOM mock 测试称为端到端通过。
- 断言覆盖用户最终看到的正文、状态、数量、引用、实际成果内容以及数据库持久化和文件副作用；“200”“任务 succeeded”“文件存在”均不能单独作为成功标准。
- 验收报告按矩阵逐项列出证据、结果和未覆盖限制。真实模型偶然未执行某条工具路径时补受控链路验证，不把未触发当作通过；相关缺陷修复后补该条件及紧邻边界，不用反复重跑掩盖问题。

### 安全与故障

- 仅在隔离测试环境验证宏、外链、活动对象、畸形 OLE、ZIP/XML 膨胀、异常输出、文件路径越界与跨租户访问。
- 不部署 Agent 沙盒仍能通过全部新增格式正常用例；模拟 LibreOffice 缺失、排队超时、转换超时、进程失败、worker 被终止及结果晚到，核对卡片终态、完整进程树回收与分段版本。
- 校验转换退出成功但无输出／输出损坏仍失败；单个文件失败不会吞掉其他文件结果。
- 注入子进程崩溃／卡住／超量输出、内存或输出配额超限、临时目录权限错误／空间不足、数据库短暂不可用及清理失败。每项检查可见终态、并发槽位、句柄／临时文件清理；随后实际完成同账号及其他账号的正常请求，不能仅检查进程存活。
- 对固定数量的连续失败／取消验证资源是否持续增长；对 worker 强制退出单独核对重启后的租约、残留进程及晚到结果。故障注入只影响本次拥有的测试进程／临时目录，不填满宿主磁盘、不终止共享服务或触碰用户数据。
- 本地与 worker 镜像验证真实转换；CI 使用小固定样本做模块验证，镜像与受控破坏性验证放现有集成或发布检查，不给所有 CI 叠加整套产品验收。

### 性能对照

| 组别 | 对照方式 | 重点 |
| --- | --- | --- |
| 无附件普通消息 | 修改前／后，受控模型相同 | 没有新增探测、解析或模型调用 |
| TXT／代码／DOCX／XLSX／PDF | 同一文件、同一环境前后配对 | 准备与模型开始时间不回归 |
| 新增旧 Office 格式 | 新版首次读取、同附件重试、同消息重复 | 转换成本和复用收益；旧版不支持不能算速度基线 |
| 混合附件与多用户 | 相同容量，一慢多快，至少 4 个同时任务 | 队列公平、轻量结果先就绪、CPU／内存峰值 |

- 固定输入与受控模型下，每组先预热，再进行至少 30 组前后配对，报告 p50／p95、样本量、异常值和是否命中缓存；冷启动另列，不与热运行混算。
- 记录上传耗时、发送确认、文档排队／读取／转换、模型请求开始、首段正文与最终完成。用户输入期间提前完成的上传不计为模型提速。
- 既有普通路径的附件准备及模型请求开始前耗时，p95 回归不得超过 `max(基线 p95 × 10%, 100ms)`；模型调用次数不得增加。若超出，先定位，不靠扩大阈值宣称通过。
- 新格式没有旧版成功路径，报告绝对耗时与同内容现代格式参考值。重复文件至少验证实际转换／解析次数，而非只看最终答案相同。
- 真实 low／high 在同模型服务、同输入、同附件缓存状态下各至少 3 对请求，交错执行并报告所有耗时；仅作为端到端样例，不用少量真实样例计算有代表性的 p95，不将服务商波动归因于系统优化。
- 低延迟文件不得因转换队列占满轻量解析资源；混合消息仍等待必要文件，报告这一实质限制。

### 检查入口

- 服务端使用项目 `.venv-server` 与现有 pytest 配置，定向运行 `tests/server/modules/materials/` 中涉及文档、上传生命周期、重复附件，`tests/server/modules/work/test_work_materials.py` 的相关用例，以及新增 `tests/server/scenarios/test_legacy_document_workflow.py` 的完整链路与恢复用例。
- 转换使用新增 `tests/server/modules/materials/test_office_conversion.py`；固定调用行为、预算与清理可模拟，真实转换样本在已安装 LibreOffice 的本地／worker 镜像验证，未安装只能报未执行，禁止指向线上。
- Web 使用 `npm run test:web -- <相关文件>`、`npm run typecheck:web` 及改动文件 lint；如修改公共 helper／共享测试装配，再运行一次完整 Web 测试。
- 发布和本地运行验证只补受影响的 `tests/deploy/` 与启动脚本检查，不默认执行沙盒测试、Electron 打包、模型下载或物理设备测试。
- 实施完成后由新的独立验收 Agent 核对 Spec、diff、真实样本与性能数据；未通过项目明确返工，未运行项不得写为通过。

## 风险与迁移策略

- 新格式和转换兼容不等于无损还原；复杂对象、缺失字体及公式缓存差异需展示限制，不能用模型猜测修补。
- 统一转换减少维护多套格式解析器的成本，不代表一定比专用直接读取更快。新增格式报告冷启动及转换成本，已有格式保持原路径；同内容复用避免重复开销。
- 转换与其他 worker 任务共享 CPU／内存，单进程并发上限还需结合 worker 数量验证。不擅自调整线上容量，也不新增服务掩盖资源争用。
- 普通 worker 子进程不提供 Agent 沙盒同等隔离；固定操作、禁宏／外链、资源控制及原解析限制都需验证，转换器漏洞仍属于剩余风险，部署版本需持续维护。
- 只有更新 worker 依赖并完成真实部署冒烟后，才能声明环境可用；API 与 Agent 沙盒不增加转换依赖。回滚保留原件、已存分段和附件身份，不批量删除或重解析材料。
- 首版不计划数据库 migration，不批量重解析历史材料。新增信息写入既有 JSON 元数据，公开返回做白名单序列化；如需结构变化另行补齐迁移和回滚计划。
