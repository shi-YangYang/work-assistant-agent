# Spec 068：Web 全量测试与体验审计

## 状态

原测试报告已交付，独立验收 PASS（仅报告交付）；原产品结论 FAIL，保留未执行及受阻范围，不宣称全量通过。应用基线为 `0fd76fed8400d064d2585c4e753d542343eb864f`。见 [报告](report.md)、[问题清单](issues.md)与[原独立验收](acceptance.md)。

后续确认问题已按“尽量不增加 Agent 处理耗时”的约束修复，修补范围通过新的独立验收。见 [修复报告](repair-report.md)、[修复验收](repair-acceptance.md)及[修复计划](rework.md)。原审计结论与证据保留；最终报告状态补丁通过原失败回放验证，未冒充重新实模全绿。

## 背景

此前的 [Web 全量测试](../spec-054-web-comprehensive-testing/spec.md)与 [Agent 工具循环排查](../spec-059-agent-comprehensive-testing/spec.md)提供了隔离环境、浏览器检查、真实模型样本和故障注入基础。此后新增或调整了工作清单、侧栏导航、图片生成、通知公告、模型用途和手机输入框，旧用例及截图不能代表当前产品质量。

本次覆盖当前 Web 产品整体，包含其依赖的 API、worker 和 Agent 链路。以实际路由、角色、接口和工具清单确定范围，不以旧测试文件数量代替覆盖。

## 目标

- 管理员、普通用户分别走完所有适用页面、标签页、详情及关键操作，检查 UI/UX 和功能一致性。
- 核对页面结果、接口响应、数据库记录、任务回执与真实文件，发现假成功、重复写入及恢复不一致。
- 覆盖桌面与手机，重点验证输入、弹窗、滚动、加载、切页及弱网场景。
- 测量从用户发送到看到状态、正文、首张图片和最终结果的时间，定位前端、排队、模型、工具及保存环节的等待。
- 持续关注重复工具调用、无效循环和账号隔离；报告中区分产品、模型、服务商、环境和测试脚手架问题。

## 非目标

- 不新增产品能力，不重做全站设计，不调整提示词、执行预算、强度或超时以提高通过率。
- 不验收 Electron 安装、打包、本地转写或物理录音设备；Web 的桌面授权入口仍在范围内。
- 不在生产环境、日常数据库或员工真实数据上执行写入、故障和负载测试。
- 不引入第二套测试框架，不将真实模型、破坏性测试和整站截图加入每次提交的默认 CI。
- 不要求精确作文长度、固定语气或固定工具顺序；不为知识性错误恢复逐条模型核对、增加运行时模型往返。
- 不声称穷举所有自然语言和所有设备组合。

## 当前行为

- Web 使用 React、CSS Modules 和共享弹窗；存在管理员、员工及匿名入口，部分页面仅管理员可见。
- 系统设置已改为侧栏二级菜单；外观入口在宠物设置中，兼容外观路由仍存在。不能按旧菜单验收。
- 手机输入框为紧凑主栏和“＋”面板；上下文、思考强度、执行权限使用居中弹窗，桌面保持原菜单。
- Agent 正文流、工具任务、图片生成和浏览器图片加载是不同状态；通知与公告、工作正文与勾选清单也有各自的数据规则。
- 现有测试涵盖 Web DOM、API、浏览器、Agent 审计与沙盒；部分脚本仍固定旧 suite 白名单和证据目录，需要先核实适配。
- 最近已知 Web 类型检查有 `notifications.test.tsx` 的 `ByRoleOptions.exact` 错误，实施时重新记录当前结果，不能继承“已通过”或默默顺手修复。

## 目标行为

为每个覆盖项建立稳定编号、角色、前置数据、动作、预期、禁止结果、验证方式和证据。结果使用 `PASS / FAIL / BLOCKED / NOT_RUN / N/A`；不适用项必须说明理由。

分别给出“测试交付是否完整”和“产品是否通过”的结论。测试可以完整交付一份产品不通过的报告；存在阻塞或未执行项时，不能称为全量通过。

## 功能需求

### 1. 基线与覆盖清单

- 实施起点冻结应用 SHA、工作区差异指纹、依赖、迁移版本、API／worker 运行版本、浏览器、时区、测试数据、模型及强度。规划参考提交为 `0fd76fe`，实际测试仍以启动时冻结的版本为准。
- 从 `App`、`AppRoutes`、侧栏、设置、隐藏兼容路由及动态详情整理页面清单；从 OpenAPI 和动态 action 整理 Web 相关接口清单；从实际注册表整理工具、后台任务及权限模式。
- 清单必须映射到已执行断言，不能把“注册过”“请求过”或“有测试文件”记为通过。
- 先冻结预期再运行。保留首轮结果；测试样本或脚手架错误可修正，但须记录原因和受影响范围，不覆盖原始证据。

### 2. UI/UX 与浏览器覆盖

- 每个适用角色的页面及主要子页至少取得桌面和手机截图，使用有代表性的合成数据；空态、加载、失败、长内容和弹窗按矩阵展开。
- 主要基线为桌面 `1440×900`、手机 `390×844`；320／430px 窄宽屏、768px 平板、低高度及横屏针对公共布局和高风险控件补充。每条路由检查浅／深色；共享样式的边界不机械展开全部笛卡尔积。
- 逐页检查对齐、margin／padding、内容宽度、顶部高度、按钮层级、搜索和分页、字体截断、表格溢出、空白占位与页面间一致性。
- 实际验证点击、触控、Tab／Enter／Esc、焦点返回、前进后退、深链刷新、列表定位与草稿保留；截图不能代替行为验证。
- 对切页加载、流式正文、宠物工作状态、图片占位、录音及键盘切换采集短视频、事件轨迹或连续截图，检查闪烁和布局跳动。
- Chromium 执行全套浏览器检查；WebKit／Firefox 覆盖登录、导航、输入、弹窗、上传、流式和下载等兼容关键链路。仿真手机与真实 iOS／Android／钉钉结果分开，无法访问真机的项目列为待验，不伪装成通过。

### 3. 功能、API 与数据

- 范围详见 [测试矩阵](test-matrix.md)，包含聊天、工作、清单、报告、团队、成员、记忆、设置、模型、通知公告、反馈和声纹。
- 所有适用列表检查空数据、单条、单页上限、上限加一、多页、空搜索、快速筛选和删除末页最后一项。
- 写入校验真实记录与版本：重复点击、丢回包后重试、并发修改、失败回滚、刷新后读回，不仅检查成功提示或 2xx。
- 使用至少两家公司、每公司独立管理员与员工夹具验证匿名、过期身份、同公司他人、跨公司访问。管理员管理权限不等于可读个人聊天、记忆或任意文件。
- 对通知已读、公告删除、工作勾选、材料增删、模型配置和任务取消等近期功能检查副作用与历史；旧工作正文、旧消息和已有图片仍可正常读取。
- 在隔离环境验证当前部署形态下的深链、静态缓存、代理流式与健康检查；不直接操作线上部署。

### 4. Agent、真实模型与性能

- 固定模型响应覆盖权限、参数、状态转换、工具错误、预算、重试、取消和恢复；真实模型验证意图、选工具及多轮衔接，两类结果分开。
- 真实文本模型只测试 `low` 和 `high`。管理员未配置或服务商不支持某档时列为阻塞，不能悄悄替换档位；图片、ASR 使用其实际独立配置，不附加文本推理档位。
- 冻结至少 24 个不同任务，其中至少 8 个多轮、8 个经真实浏览器入口；管理员和员工各至少 8 个。新样本不少于四分之一，覆盖普通问答、写作、联网、材料、工作清单、报告、记忆、编码／文件与图片。数量是覆盖底线，不替代工具清单。
- 对至少 6 个代表性文本任务进行 low／high 同题对照，每档 3 次，顺序交错，输入材料、历史和配置一致。记录每次数据及中位数、范围，小样本不声称稳定 p95。其它真实样本首轮一次，具体失败才定向复现。
- 对每次任务分别记录：受理、首个可见状态、首个上游正文片段、首个浏览器可见正文、工具开始／结束、首张图片可见、最终可见结果、持久化完成。异步或重叠阶段不得直接相加，缺少观测点标为未知。
- 分开统计模型工具请求数、工具实际执行数、底层重试数和数据库副作用数。相同参数重复或 A→B→A→B 为候选，结合分页、新证据、恢复和用户新授权判断，不误报合法调用。
- 性能观测不能引入生产提示词、二次模型核对、同步数据库等待或新的业务步骤。服务商耗时、网络与系统开销分别归因；首轮报告记录现状，后续修复再用同条件对照，不拿不同强度或旧截图直接计算提速。

### 5. 先验、故障与受控负载

- 先明确“允许怎样成功”和“绝不能发生什么”：取消不能变完成、重试不能多写、未授权不能泄漏、只改勾选不能重写正文、未生成图片不能当成果展示。
- 使用已知表格合计、固定日期、版本、所有者和文件内容作真值；同义改写、行顺序改变、换账号和同幂等键重放验证不变量。
- 隔离环境覆盖断网、SSE 丢失／重复／乱序、模型拒绝／429／超时、数据库断连、worker 被杀及恢复、媒体读取失败、磁盘限额与恶意输入。对写入前、已写入未回包、取消与恢复等时点注入。
- 破坏性测试必须验证拥有的测试进程、独立容器、数据库及媒体目录标识，不能仅用 URL 看似本地作判断。不能停止共享日常 API／worker／PostgreSQL／Redis，也不能放宽旧脚手架的环境归属校验来运行。
- 并发登录、浏览、消息和独立任务使用受控模型，按 1／5／10／30／50 个合成用户递增，每档最长 60 秒。先记录测试机资源；错误持续上升、资源耗尽或隔离失效时停止升档，保留已完成档位，不追求压垮宿主。
- 并发报告包含错误率、连接池、排队、CPU／内存、延迟及清理结果；数据足够时计算 p50／p95。不同资源机器的结果不直接宣称为线上 8H16G 容量。

### 6. 问题与交付

- 每项缺陷包含编号、严重性、角色／设备／主题、最小复现、预期／实际、首轮证据、影响范围、根因判断及建议。证据不足写“待定位”，不统一归因于模型或网络。
- 问题分类：产品实现、UI/UX、模型行为、服务商、环境、测试代码／夹具；同根因合并，保留关联失败。
- 先完成全量测试与报告，统一汇总问题，再由用户审查并决定修复。期间只调整测试脚手架和隔离数据，不修改产品源码、提示词、Schema 或降低断言。
- 严重安全问题立即停止受影响分组并报告，其余安全独立分组继续；这不等于自动修改产品。
- 交付 `report.md`、`issues.md`、覆盖映射、截图索引和原始证据目录。独立验收检查范围、证据、断言与报告真实性，不要求把所有产品失败修到绿。

## 边界条件

- 仅使用合成账号、资料、图片、音频和业务记录；真实模型调用所用凭据留在本地，不写入 Spec、日志或截图。
- 钉钉真实授权、实际麦克风和真机软键盘需要真实外部条件；未取得条件时只验证受控逻辑并注明差距。
- 图片单消息数量、附件大小、模型能力等限额从当前契约读取，再测边界；当前图片 1／4／超过 4 张及批量串行场景列为重点，规格不擅自调高限制。
- 测试看门狗与业务超时分开；不为“通过”无限等待、无限重试或反复运行已通过分组。
- 外部依赖失败单独归类；如果系统对该失败的处理也有缺陷，两者分别记录。

## 技术约束

- 复用 Vitest、pytest、Playwright、现有验收与 Agent 审计脚本；测试和证据就近归入既有目录。
- 新 Spec 的运行标识、证据目录及环境归属独立，历史报告只读；不覆盖旧数据，不创建可在生产启用的故障开关。
- 文档阶段按 S0，不运行测试或构建。实施阶段是用户明确要求的全量验收，可运行完整 Web／服务端相关检查；不连带跑桌面打包、下载真实转写模型或安装卸载。
- 本地修改测试源码时按项目配置格式化；测试命令和证据指向实际运行提交。

## 兼容性要求

- 测试过程不能改变正式业务行为、已有数据、模型设置、提示词或运行时长。
- 历史样本和预期随当前确认的产品规则核对；过期断言作为测试问题记录，不能据此恢复已移除功能。
- 保留原有 CI 默认触发与 Git 流程，不将本次验收变成每次提交的重检查。

## 验收标准

- [x] 当前页面／标签页／接口／工具／异步任务清单完成映射，适用项均有结果或明确阻塞原因。
- [x] 两个角色的桌面／手机页面截图与交互检查完成，主题及窄屏问题有逐项记录。
- [x] 正常、空、边界、失败、取消、重试、并发及身份隔离均有业务断言与证据。
- [ ] 近期手机输入框、居中弹窗、图片批量、工作清单、通知公告和设置流程完整覆盖。
- [x] 真实模型仅 low／high，任务完成与调用／执行／写入次数可核对；所有耗时口径清楚，无掩盖首轮失败。
- [ ] 隔离故障与负载按清单执行，测试资源清理可核对，真机和外部条件限制如实列出。
- [x] 问题列表有复现、影响和优先级，测试完成与产品通过两个结论明确区分。
- [x] 新独立验收 Agent 复核证据和报告；有未运行或阻塞项时不宣称全量通过。

近期流程完整组合及全故障清单仍有缺口，上述两项保持未勾选；已执行范围及未执行／外部阻塞原因均列入报告。报告交付通过不改变这些产品验收限制。
