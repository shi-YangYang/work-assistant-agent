## Required Rework

**P2：报告子任务完成后，父消息仍显示 partial，并追加相互矛盾的完成／未完成说明。**

证据：[v2-report-explicit-low-2-candidate](../../artifacts/spec068/repair-performance/v2/observations/v2-report-explicit-low-2-candidate/result.json)。请求明确要求在「我的报告」创建并保存本周周报草稿，不提交。

- 实际周报已成功保存，revision 为 2，未提交，只有一份报告。
- 公开 `taskOutcome.completed` 包含「生成报告《2026-10-12 周报》」，但 state 为 `partial`，remaining 为「本周周报草稿仍在生成处理中，尚未确认保存完成」。
- 回复同时包含原模型的等待说明、系统追加的「已完成」，以及「本次请求仍有操作未完成」。
- 从消息发送到持久结果读回为 44.04 秒；保留该首次失败，不重发或覆盖为成功样本。

`tasks/feedback/report_waits.py` 的现有完整句式规则未识别「生成处理中」及「尚未确认保存完成」的组合。这是已知同一报告等待残留问题的真实表达变体，不能仅当作未知措辞限制而宣称目标已经完成。

应在保留精确报告归属和真实未完成项保护的前提下，进行最小本地回放返工。不得新增模型核对、网络往返或通过直接删除所有 remaining 来修复；原模型正文不做任意关键词改写。之后由新的独立验收 Agent 复核。

## Performance and Limits

v1 的 24 条正式观察和 4 条原意图诊断完整保留，包括报告终态失败及 high 图片中位数增加 1.32 秒；不能以其它场景变快抵消已观察到的额外纠错轮次。v2 另有冻结的 16 条报告／图片对照，当前尚未全部完成，本验收不预判其整体结果。

两版 worker 并发 1、文本模型仅 low/high、每格两次；图片供应端为相同 250ms 的受控实现，不能宣称真实服务商生图总耗时或生产容量。普通问答沿用未受后续报告／图片逻辑影响的 v1 对照，不称为最终 v2 全场景重新实测。API／worker 读回也不是浏览器绘制时间。

历史已结束消息未批量迁移；真机／外部系统和原审计未覆盖项仍保留限制。没有实现图集上下张等新功能，未 commit／push。
