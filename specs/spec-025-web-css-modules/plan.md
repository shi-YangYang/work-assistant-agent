# Web 样式模块化实施计划

范围与验收以[功能规格](spec.md)为准。

## 迁移顺序与涉及文件

1. **建立样式基线**：从 `styles/index.css` 记录全局导入顺序、公共类使用方及跨文件覆盖；按 `app/AppRoutes.tsx` 的实际页面与身份入口截图。先区分有效覆盖与无引用规则，不把现有视觉问题顺手改成新设计。
2. **拆开两端基础样式**：将 `packages/ui-web/src/{theme,select,brand}.css` 分别落到 `apps/web/src/styles/` 与 `apps/desktop/src/renderer/styles/`；修改 Web `base.css` 与 Desktop `styles.css` 的导入，保留各端原加载顺序。修正 `brand.css` 中图片 URL，保留品牌图片共享，必要时补资源导出。两端均迁移后删除共享 CSS 及其导出，不删除仍被图标／静态资源使用的包。Web 整理最小全局工具类白名单和公共布局 Module，不新增统一聚合所有 Module 的入口。
3. **迁移公共组件与应用壳**：从 `surfaces.css`、`controls.css`、`overlays.css`、`navigation-controls.css`、`data-lists.css`、`network-feedback.css` 和 `app/layout.css` 拆出各自所有者。优先处理 Modal、Actions、PanelSection、FormField、空状态、分页、搜索、导航和反馈组件；同步迁移 `responsive.css` 的对应规则。
4. **迁移工作／报告／团队和普通设置**：将 `features/records/styles` 中混合规则分配到已有 work、reports、team 或公共展示层；不创建重复业务模块。继续处理 members、settings、feedback、sources、voiceprints。
5. **迁移模型服务与工作助手**：明确公共弹窗、折叠栏和表单的定制入口，再迁移服务编辑器、用途、用量、会话列表、消息卡、输入器、媒体／文档与业务操作卡。配套维护局部响应式与状态选择器。
6. **迁移认证外观**：分配 `LoginBook`、登录表单、钉钉及桌面授权样式，保留动画和尺寸约束；核实旧登录背景规则是否还有调用，只有无依赖才删除。
7. **收尾**：删除已迁移的全局定义／导入和空的旧样式目录；更新 `docs/architecture.md` 的样式规则与 `constitution/tech-stack.md` 的实际技术描述。旧 Spec 保留历史结论，不复制 Decision。

每次迁移同时更新 CSS、TSX 引用、状态和相关 JS 查询，每端保持一个样式所有者；端内不能长期保留新旧两套规则，两端各自的基础定义是明确的维护边界。全局层叠耦合较强，由一个实施 Agent 串行处理，再由新的独立验收 Agent 检查；决策阶段不创建子 Agent。

## 数据流与接口

Web 样式依赖改为“组件 → 自有 Module／Web 公共 Module → Web 主题变量”，应用入口仅引入本端全局基础。Desktop 从自己的 renderer 样式目录获取基础定义；两端没有 CSS 依赖关系。业务数据流、服务接口与数据库不变，不需要数据迁移。

重点处理：

| 已有依赖 | 迁移要求 |
| --- | --- |
| `Shell.tsx` 查询 `.page, .settings-layout` | 为实际滚动容器保留稳定语义标记或 ref，保持详情返回的位置 |
| `ConversationChat.tsx` 查询 `.chat-content` | 维持内容尺寸观察目标及清理，验证贴底／非贴底行为 |
| `Actions.tsx` 切换 `above` | 改为对应 Module 类或局部状态属性，保持视口边缘翻转 |
| `useMobileViewport.ts` 操作根 `keyboard-open` | 作为明确的全局环境边界，消费者规则仍归本地 Module |
| 模型服务访问 `.dialog-body`、`.panel-section-status` | 由公共组件提供必要的定制入口，移除私有选择器穿透 |
| 状态标签、主题预览、翻书和附件类型动态类 | 显式本地映射／状态属性；未知状态保留原有回退 |

CSS Modules 默认 TS 声明允许任意类名键，类型通过不代表类名无遗漏；构建与真实界面对照共同验证。现有组件测试如使用旧类名定位，同步改为角色、标签或稳定语义标记，不断言生成的 hash，也不删除行为断言。

## 验证范围

当前 Spec 文档按 **S0**，只检查 diff、需求一致性和引用。实施按 **S3 的 Web 范围验证，并补桌面样式迁移的定向检查**：依据是 Web 全应用样式迁移及两端基础 CSS／资源导入受影响，不扩展为全仓库验收。

- 编辑时只格式化本次文件；分批运行被改动行为的定向检查，不每批重跑全量。
- 最终代码运行一次 `npm run test:web`、`npm run typecheck:web`、`npm run build:web`，以及 Web／相关测试的 ESLint 和改动文件 Prettier 检查。已在最终代码通过的同项不重复执行。
- 在已有 `tests/web/architecture.test.ts` 中按需加入轻量导入边界检查：全局入口不再引入业务 CSS，普通全局样式导入有明确允许范围，两端无共享包 CSS 或跨端 CSS 引用。保持现有架构约束，不引入新测试框架或强制文件数量／行数目标。
- 验证实际 CSS 输出与页面布局，不能仅用源码字符串断言或 Node 环境组件测试替代浏览器检查。浏览器另以普通生产构建检查代表性页面、弹窗和直接路由加载，捕获开发／构建层叠差异。
- 桌面基础 CSS 迁移后运行一次普通 `npm run build` 验证样式／品牌资源解析，并在日常 `npm run dev` 环境对照浅深主题、品牌图标及选择控件。共享样式声明保持原样时不扩大为桌面全量功能验收。
- 不运行完整后端测试、Electron 打包、真实 ASR／LLM或远端 CI，不操作生产数据。

## 界面对照

在现有本地环境保存对照截图到 `artifacts/spec025/`，沿用真实页面与权限；临时数据明确标识并清理，不改真实记录、不消耗模型配额。以当前路由表为清单，不只抽查首页。

| 页面组 | 重点状态与操作 |
| --- | --- |
| 登录、钉钉结果、桌面授权 | 书本关闭／翻开／直接登录、表单错误、键盘焦点、短视口与减少动态效果 |
| 应用壳、菜单、命令搜索 | 侧栏展开／收起、设置菜单、面包屑、通知、菜单边缘翻转、路由滚动恢复 |
| 工作助手、来源、附件预览 | 空／有消息、会话选择、编辑器错误、附件、转写、Markdown／PDF、贴底和新回复提示 |
| 我的工作、我的报告及详情 | 空／有数据、筛选分页、状态、编辑校验、提交／删除弹窗、详情返回 |
| 团队与成员 | 看板工作／汇报页签、筛选、详情入口、成员表单与重置密码 |
| 全部设置页面 | 账号、外观、汇报规则、模型服务／模型弹窗／用途、用量、钉钉、声纹、问题反馈 |

全部页面至少覆盖桌面 1440px、手机 390px 的浅／深主题，对比同一数据状态；导航和设置布局补 900px 折叠断点，登录／聊天／弹窗补短高度、长内容和必要的 320px 边界。页面基础截图全覆盖，交互状态按表定向覆盖，不要求所有状态与所有尺寸做笛卡尔积。视口模拟不声称是真机测试。

## 风险与恢复

主要风险是 specificity／加载次序变化、跨组件私有类失配、动态类与 JS 查询遗漏、动画名称及弹层继承改变。逐组迁移并保留相同状态的视觉基线；修复归属和接口，不叠加覆盖补丁。回退限于本次模块改动，无数据回滚；不得覆盖用户已有修改。
