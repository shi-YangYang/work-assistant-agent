# Web 样式作用域与组件维护

## 背景与当前行为

Web 已按业务拆分 React 文件和 CSS 文件，但样式仍经 `main.tsx → styles/index.css` 全局加载。源码现有 28 个 CSS 文件、约 5,949 行，入口直接聚合 25 份样式，没有 `.module.css`。

- `styles/responsive.css` 同时修改导航、聊天、工作列表、团队和弹窗，调整一个组件需要到多个文件找规则。
- 模型服务通过 `.model-settings-dialog .dialog-body`、`.model-editor .panel-section-status` 修改公共组件内部；工作／报告的 `features/records/styles/` 也混合多业务和公共状态样式，存在隐式依赖。
- `Shell.tsx` 用 `.page, .settings-layout` 保存滚动位置，`ConversationChat.tsx` 用 `.chat-content` 监听内容尺寸，`Actions.tsx` 操作 `above` 类名。类名改写会影响行为。
- 翻书登录已通过 `.book-login` 前缀限制大部分规则，但依然全局加载，书本与表单的样式关系需要保留。
- Web 与 Electron 当前都从 `packages/ui-web` 引入主题、选择器和品牌 CSS；两端控件与适配需求已分化，后续改动不应通过共享 CSS 相互传播。

## 目标与方案

采用 **Web／Desktop 样式独立维护，Web 内部使用 CSS Modules**。两端各自拥有主题和基础控件 CSS；Web 组件直接引入自己的样式，减少同名冲突、跨文件覆盖和隐式加载顺序依赖。拆分时保持现有外观及功能，此后按各端需要独立演进，不建立自动同步样式机制。

[Vite 7 原生支持 `.module.css`](https://v7.vite.dev/guide/features#css-modules)，无需增加框架或插件。[CSS Modules](https://github.com/css-modules/css-modules) 对类名和动画名提供局部命名；普通 CSS 即使从组件导入，选择器仍是全局的。Modules 也不隔离继承、裸标签选择器或 CSS 变量，不能当作 Shadow DOM。

## 非目标

不重新设计 UI，不修改认证、请求、业务规则或后端；Electron 只迁移原共享 CSS 及引用，不做其内部样式模块化或组件重构。不换 Tailwind、CSS-in-JS 或 UI 库，不新增路由懒加载，不重构无关 TSX。组件引入样式不等于只在组件显示时下载或卸载 CSS，本次不承诺首屏体积或运行速度收益。

## 目标行为与功能需求

### 样式归属

| 范围 | 维护方式 |
| --- | --- |
| Web 基础 | 主题、选择器、品牌呈现 CSS 归 `apps/web/src/styles/`；`styles/index.css` 只汇总本端基础样式、reset、字体、滚动条、基础表单、键盘焦点、减少动态效果和少量通用工具规则 |
| Desktop 基础 | 原共享 CSS 归 `apps/desktop/src/renderer/styles/`，由现有 `styles.css` 引入，保留桌面其余结构 |
| 公共组件 | `components/Modal.tsx` 与 `Modal.module.css` 等就近配对，由组件直接导入 |
| 业务组件 | 默认使用相邻的 `组件名.module.css`；同一业务内确实共用的组合样式可留在该业务 `styles/*.module.css`，由使用者显式导入 |
| 应用布局 | 由 app 内的布局／导航组件维护对应 Module，包括自己的断点规则 |

- 新增或迁移的业务专用样式不进入全局入口。没有独有样式的组件不强行创建 CSS 文件，也不为每个 DOM 节点建立组件。
- 两端不得互相引用 CSS，也不再从共享包加载 CSS／主题变量定义。初始相同的主题值允许各自保留，后续修改无需同步另一端。Logo 图片等静态品牌资源以及 HTTP 类型、纯业务工具不属于本次样式拆分范围，保留合理共享。
- 公共外观由公共组件或明确的共享 Module 维护，不复制到每个页面。跨业务共享样式遵循现有向下依赖边界，不反向导入另一业务的私有 CSS。
- 保留少量现有全站通用类，如 `muted`、`sr-only`、基础按钮修饰等，实施时在架构说明中列明实际白名单；不能把聊天、工作、报告、模型等业务规则改名为“通用”后继续全局加载。
- 响应式、悬浮、选中、错误、禁用和动画规则跟随所属组件迁移。全局响应式文件不继续管理各业务页面。

### 组件边界

- 使用 `import styles from './组件名.module.css'` 并显式引用类名；动态状态用本地映射或 `data-*`／ARIA 属性，不继续拼接隐含的全局状态类。
- 业务不穿透公共组件私有类。现有跨组件定制优先通过布局包装、受限的 `className`／样式变体或 CSS 变量表达；只增加实际需要的接口，不建设通用样式配置系统。
- Module 内的标签／属性选择器必须受本地根类约束；`:global` 只用于已存在的主题、键盘状态或第三方边界，并说明用途，不能用大范围 `:global` 绕过隔离。
- 同步迁移 JS 中依赖旧类名的查询与切换，优先使用已有 ref 或稳定语义属性。数据属性、DOM ID、ARIA 关联和主题标记不机械哈希化。

## 边界条件与兼容性要求

- 保持翻书封面、动画、登录表单静止、直接登录、焦点与小屏滚动边界；不改变该页面独立配色。
- 保持深浅主题、系统跟随、手机键盘避让、安全区域、减少动态效果、菜单翻转、原生 dialog 顶层及第三方内容展示。
- 保持滚动位置恢复、消息自动滚动和“新回复”提醒；不通过重新挂载组件解决样式问题。
- Markdown、PDF 预览、图片／音频附件及弹窗内容的样式需有明确归属。弹层不能依赖实际 DOM 中不存在的页面祖先。
- 直接进入任意路由、刷新及不同顺序切换页面，外观一致；开发与生产构建均有效。
- 不改 URL、HTTP 接口、权限、持久状态、主题存储键、数据和部署入口；保持目前支持的浏览器回退，原生选择器和日期控件不能退化。

## 技术约束

沿用现有 React／TypeScript／Vite 和业务目录，主题变量名称与当前取值先保持，各端独立定义。Web 内部先保持规则结果，再收敛重复声明，不用批量改后缀或增加 `!important` 掩盖层叠问题。确认无 JSX、动态状态、JS 查询或第三方依赖后才删除旧规则；共享包的旧 CSS 在两端迁移完成后移除，保留仍使用的图片资源与导出。

## 验收标准

- [x] Web 业务和组件专用样式由使用者显式引入 Module，全局入口不聚合业务 CSS；遗留规则均属于说明过的基础范围。
- [ ] Web 与 Desktop 各自维护主题和基础控件 CSS，无跨端或共享包 CSS 引用；静态图片引用、两端原有外观与主题切换正常。
- [x] 从组件可直接找到其样式和断点；无跨业务私有选择器依赖、重复兼容副本或失效导入。
- [x] 旧样式类名查询已处理，滚动恢复、聊天内容观察、菜单定位及动态状态不回退。
- [x] 全部可访问 Web 页面有迁移前后截图对照，覆盖电脑／手机宽度及浅深主题；重点交互与空／有数据状态按计划核对。
- [ ] Web 测试、类型、Lint、改动文件格式和普通生产构建通过；浏览器核对包含生产产物，不能仅用测试通过证明视觉一致。
- [x] 现有架构说明与技术约束更新为按端独立维护样式，说明 Web 内部复用边界；未夹带 Electron 组件重构。
