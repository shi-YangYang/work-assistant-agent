# Spec 050：Web 全页面排版与组件一致性

## 状态

已实施；[独立验收 PASS](acceptance.md)。

## 背景

Web UI 审查覆盖管理员、员工及公共入口，共留存 222 张截图，发现 3 项明确缺陷、8 项一致性与易用性问题。本 Spec 全部纳入修复。

审查证据位于本地 `artifacts/ui-audit-20261007/`；该目录不纳入 Git，下面的需求表保留完整问题定义，不依赖截图才能实施。

## 目标

- 修复文字不可读、导航重叠和抽屉标题挤压。
- 统一页面起始线、列表密度、按钮层级、搜索和表单布局。
- 手机端优先呈现内容，保留所有现有筛选、操作和业务能力。
- 员工、管理员分别逐页截图验收，覆盖浅色、深色及关键交互状态。

## 非目标

- 不新增业务功能，不修改后端、接口、权限、Agent 工具或数据库。
- 不改 Electron，不更换 UI 库，不重新设计登录翻书交互、品牌及宠物。
- 不恢复全局顶部栏，不给宠物增加占据整行的容器或全局顶部留白。
- 不为所有页面强制套用相同卡片、相同行高或相同内容宽度。

## 当前行为与目标行为

当前不同页面自行定义标题避让、筛选、按钮和容器，页面级 CSS 还会进入抽屉。目标是复用少量明确的布局模式：页面标题、详情导航、列表工具栏、列表行和表单区域；业务组件继续管理自己的数据和行为。

## 功能需求

编号与审查结果对应。

| 编号 | 当前问题 | 修复要求 |
| --- | --- | --- |
| UI-01 | 深色主题 Markdown 表头接近白底白字 | 工作助手和消息来源的表格使用有效的语义色变量，背景与文字同步切换；普通字号表头文字对比度至少 4.5:1。 |

| UI-03 | 手机团队工作／报告抽屉继承页面标题避让规则，标题仅约 95px 宽 | 明确区分独立页面与嵌入详情。抽屉不继承页面导航偏移，标题按抽屉可用宽度自然换行，日期不被机械拆开。 |
| UI-04 | 手机标题、返回文案被挤成窄列，成员数量和操作零散换行 | 标题、元信息、返回和操作使用统一布局规则；空间不足时有序分排，不以固定半屏宽度挤压短标题和返回入口。 |
| UI-05 | 团队、报告筛选区及模型服务列表占用过多首屏 | 主视图切换、搜索与常用条件紧凑排列；低频条件折叠并显示已生效的筛选状态及清除入口。窄屏模型服务列表改为紧凑选择器，保留新增服务、服务状态和未保存草稿提示。 |
| UI-06 | 工作／成员平铺，团队／报告／设置嵌套大圆角面板 | 页面以全宽画布和统一内边距呈现，列表不用整块外层卡片包裹。分组优先用标题、留白和轻分隔线；独立信息、编辑区域、弹层保留必要容器。 |
| UI-07 | 桌面单列表单铺满千像素，保存按钮离字段过远 | 账户、反馈、用途分配、登录配置等单列表单最大宽度 640px，靠左对齐页面内容起始线；操作跟随表单边界。双列配置按内容需要布局，不压缩列表或详情正文。 |
| UI-08 | 刷新、添加、保存的外观和动作权重不一致 | 统一主要、次要、轻量图标、危险四类按钮。同一工具栏高度与间距一致；模型空状态避免同时出现两个同等强调的“添加服务”。保留按钮的真实业务区别及可访问名称。 |
| UI-09 | 工作、团队、成员、报告列表的信息层级不稳定 | 建立普通记录与含摘要记录两种布局。标题为第一层，摘要最多两行，状态／时间进入稳定的元信息区；阻碍等重要状态仍直接可见，完整内容可进入详情读取。 |
| UI-10 | 搜索框宽度、位置、边框和聚焦效果不一致 | 工作、成员、团队、声纹统一为左侧搜索与就近筛选、右侧附加操作。搜索框使用一致底色、尺寸和单一聚焦轮廓，窄屏自然换行。 |
| UI-11 | 手机模型用量表右侧列需要横滑，但不易发现 | 保留横向表格，用边缘提示或简短文字显示尚有隐藏列；固定时间关键列，窄屏简写时间并提供完整值。提示随滚动位置更新，不遮挡单元格，键盘与触摸均可访问所有列。 |

### 排版基准

- 沿用[现有设计规范](../../docs/design/README.md)的黑白灰、状态色、字体和圆角，不另建一套主题。
- 普通页面横向内边距：桌面 32px、手机 16px；抽屉按自身容器处理。已有助手阅读宽度和输入区宽度保持独立。
- 间距采用 4、8、12、16、24、32px。标题与工具栏、工具栏与结果形成稳定间隔，相关控件距离小于不同分组距离。
- 桌面工具栏控件统一为 36px 高；手机按钮和输入等主要交互目标至少 44px，图标约 16～20px。多行按钮、textarea、富文本编辑区不套用固定高度。
- 桌面列表搜索默认宽 320px、最大不超过容器；手机按可用宽度铺开。单列表单限制内容宽度，不把整个页面改成居中卡片。
- 390×844、默认筛选、有数据的团队／报告页面，首屏应完整显示至少一条业务记录；已选服务的模型配置首屏应出现可编辑字段。不靠隐藏重要信息或缩小字号达标。
- 宠物继续独立悬浮、按原规则眨眼。仅对会冲突的页面标题和操作局部避让；抽屉不避让页面宠物，正常内容仍可从宠物后方滚动。

## 边界条件

- 测试长中文标题、连续英文／URL、多行错误、空数据、搜索无结果、加载与禁用状态；避免整个页面横向溢出。
- 手机导航、宠物和业务操作不能互相覆盖点击区域；键盘焦点不得被容器裁切。长标题可自然换行，必要时占据下一行。
- 折叠筛选不能清空条件；切换视图、返回详情、浏览器前进后退继续恢复现有 URL 条件和页码。
- 模型服务的窄屏切换沿用现有草稿与离开确认，不因组件替换丢失输入或密钥。
- 保留搜索的中文输入法处理、300ms 防抖、清空、Enter 和 Escape 行为；保留成员不足 20 人也显示分页。
- 表格只在自己的容器内横滑，固定列使用不透明的主题背景；无溢出时不显示横滑提示。
- 普通页面保持右侧内容区域滚动，抽屉独立滚动；不新增多层正文滚动条。

## 技术约束

- Web 使用原有 React、CSS Modules 和功能目录；公共布局只接受展示内容和回调，不读取业务接口或反向依赖 features。
- 移除造成冲突的宽泛标题选择器，使用明确的页面／嵌入场景；不继续叠加更高优先级 CSS 补丁。
- 优先复用现有按钮、搜索、分页和表单能力，不创建完整的新组件库，不引入依赖。
- 不因布局或响应式切换重新挂载表单、重复请求、丢失焦点或触发自动保存。

## 兼容性要求

登录、权限、主题持久化、表单校验、业务请求、搜索筛选、分页、报告提交、工作材料与历史记录全部保持。工作助手的发送／中断、权限、人设、上下文、附件与临时回答行为不变。
