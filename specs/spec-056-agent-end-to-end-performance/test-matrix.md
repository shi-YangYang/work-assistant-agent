# 性能与系统正确性覆盖矩阵

所有场景在隔离环境执行。矩阵用于定位现有能力的调用路径与系统回归，不要求为每个场景补足真实模型次数。下表中的内容质量依据保留作样本观察；字数、一般知识及逻辑错误不阻塞性能验收。

## 任务类别

| 类别           | 代表旅程及必要分支                                                           | 正确完成依据                                               |
| -------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 普通问答       | 身份、知识解释、闲聊、简单测试输入；无需工具的问题不强制工具／澄清           | 回答正确、切题，未触发无关业务操作                         |
| 写作与改稿     | 1000 字作文、邮件、方案；指定风格、多个要求、局部重写                        | 必需内容、篇幅及格式满足；未改部分保留                     |
| 编码问题       | 解释代码、定位错误、编写代码；需要运行时实际运行，再修复具体运行错误         | 固定样例／独立断言通过，不谎称运行或测试                   |
| 计算与数据     | 自定义 Python、CSV／XLSX 检查、聚合、空值和异常输入                          | 与固定答案核对，不自行删行或补数据                         |
| 文件成果       | CSV、XLSX、图表、Word、PDF、PPT；下载、续改、再次导出                        | 文件真实可下载、格式可打开、内容／计算正确、版本一致       |
| 公开研究       | 新闻日期、多个来源比较、搜索后抓正文、同页补读、失效链接                     | 来源真实可追溯；发布日期与抓取日期分开；结论有依据         |
| 当前材料       | 单／多图片、语音、文档、混合附件；仅附件、空语音、部分解析失败               | 分清各材料；不得漏读后假称完整；错误准确且不阻塞无依赖部分 |
| 历史与工作材料 | 当前工作引用、工作材料、历史消息／文件、长文分段                             | 正确定位所需对象与版本，已有完整上下文不重复读             |
| 工作查询       | 名称／状态／期间、详情、材料、历史、分页、重名                               | 真实数据，条件和分页完整性准确，重名不猜对象               |
| 工作写入       | 新建、正文／属性修改、添加／移除材料、局部进展、整体完成、删除               | 仅改用户要求，保留其他内容；有真实回执且只执行一次         |
| 报告           | 待办、日报／周报生成、查询、改稿、提交、管理员删除                           | 正确日期与真实业务事实；实际报告就绪／提交才算完成         |
| 管理员业务     | 姓名／期间查询团队、统计、来源追溯、关联本人督办                             | 不读取员工私人聊天／未授权草稿，不代改员工工作或代提交报告 |
| 记忆           | 开关、读取、保存、忘记、人工编辑后跨会话使用                                 | 当前要求优先，禁用不使用，不保存引文／临时任务／秘密       |
| 澄清与授权     | 真正缺信息、用户补充；三档权限，批准、拒绝和修改提案                         | 最少必要提问；确认范围明确，等待不冒充完成，拒绝不执行     |
| 多轮与混合     | 需求材料→实施计划→前两项写入工作→只改第二项；搜索→代码分析→文档→按需汇报     | 跨轮对象／条目稳定，全部所需成果可用，不无关恢复旧任务     |
| 长上下文       | 多轮、工作引用、记忆共存；临近压缩阈值、压缩后继续、摘要失败                 | 必要事实／指令保留，内部摘要不外泄，不重做已完成操作       |
| 失败与恢复     | 首字前断流、生成中断、限流、服务超时、工具失败、版本冲突、保存失败、用户中断 | 重试成本可解释；无假成功、重复副作用或旧内容覆盖新结果     |
| 资源与并发     | 独立用户同时聊天；两个沙盒任务及第三个排队；冷／热执行；worker 重启          | 无串流、饥饿或泄漏，排队归因准确，资源有界且回收           |

## 工具和动作清单

覆盖不能只按题目数量判断。为当前注册表生成清单，每个可用工具映射至少一个成功样本和适用的失败／权限样本；只有旧协议可达的入口标为兼容检查。

| 能力       | 必须映射的入口                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| 发现与任务 | `load_tools`、`set_task_context`、`request_user_input`；`finish_task` 旧交付兼容                                         |
| 工作       | `find_work_items`、`get_work_item`、`list_work_updates`、`list_work_materials`、`read_work_material`、`propose_progress` |
| 操作与报告 | `execute_business_action`、`get_business_actions`、`query_reports`、`query_report_obligations`                           |
| 管理员     | `find_team_members`、`query_team_business`、`read_team_source`、`propose_followup`                                       |
| 材料与成果 | `find_documents`、`read_document`、`get_message_context`、`read_file`、`save_deliverable`、`read_deliverable`            |
| 研究       | `web_search`、`web_fetch`                                                                                                |
| 执行       | `run_python`、`read_execution`、`inspect_table`、`export_table`、`create_chart`、`create_document`、`create_slides`      |
| 记忆       | `save_memory`、`forget_memory`                                                                                           |

`execute_business_action` 分别覆盖 `create_work`、`update_work`、`delete_work`、`generate_report`、`edit_report`、`submit_report`、`delete_report`。正文、材料及属性的原子分组不得因统一工具名而漏测。以实施时注册表为准，新增／移除入口必须解释差异。

## 横向组合

- 员工、管理员、另一个用户、另一个公司；身份和权限在执行中变化。
- 三档执行权限、Noria／专业人设、实际可配置强度；真实性能主对照 low／max，所有配置的参数传递用受控检查覆盖。
- 新会话、多轮承接、工作引用、无关换题、有效持续指令、撤销持续指令。
- 附件 1 个／9 个、语音 1 段／3 段、图片大小边界；高负载用固定文件，不用随机巨大文件消耗真实 API。
- 首次与重复读取、内容和版本变化、权限撤回、缓存过期、显式刷新。
- 来源注入、引文中的命令、用户“不要保存”、同名不同对象、追加误覆盖、局部完成误改整体状态。
- 失败前无副作用、写入成功但返回丢失、只完成部分步骤、重试与取消竞争、浏览器离开及恢复。

按风险选择组合，不机械做全笛卡尔积。并行、缓存、授权、持久化被修改时，上述相关反例必须真实覆盖，不能只测理想路径。

## 判断与证据

每个用例冻结输入、初态、依赖、预期成果、质量标准和清理范围。每轮保留配置摘要、完整时间线、调用次数、用量、回答、实际文件／业务差异、成功或失败原因。

性能报告按类别和强度分表，列前后完整可用时间、首字、活跃处理、人工等待、各阶段成本、质量判定和差值；业务后续作业未完成不能提前停止计时。

系统正确性用固定数据、数据库读回、工具回执及文件实际下载核对，确保用户请求、模型输出和工具结果没有在系统内被丢弃或篡改。开放文本不再追加盲评或补测；不能仅由被测模型自称“完成”判定业务／文件已经交付。

对照前写下具体假设，例如“重复读取同一资料导致两次外部请求”“独立抓取被串行”“终态后仍在排打字动画”，再用受控延迟证明或证伪。没有证据的瓶颈不作为确定结论。

已有短作文与事实错误样本及原判断继续保留，作为模型观察单列，不更改为质量通过，也不再为此调参。当前验收单列系统结果；若发现本次修改造成输入丢失、结果截断／过滤、无效循环、越权或重复写入，仍须修复。未给出用户要求的成果不冒充完成，耗时可用于分析调用负担。
