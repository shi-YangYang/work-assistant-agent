# 必要返工

## 流式连接复用

独立验收确认：非流式四次请求共用一条连接，但成功 SSE 请求在 `[DONE]` 后提前停止读取 HTTP 响应，四次仍建立四条连接。不能用非流式结果代表聊天主路径。

- 正常消费 HTTP 响应结束后才能复用连接；尾部不关闭、异常或过大时必须有界退出，不能无限等待。
- 保留已完整收到的合法答案、取消传播和协议保护；不得把尾部清理变成再次生成理由。
- 复用[独立复现](../../artifacts/spec056/acceptance/stream_reuse_probe.py)，补流式成功、异常尾部、等待上限和取消检查；不重跑已通过的无关模块。

## 多轮业务重复发现

前条消息成功创建工作，当前授权历史已有真实回执，但下一条修改只暴露 `load_tools`，必须重新发现工作工具。[实际请求证据](../../artifacts/spec056/tool-discovery-audit.json)同时显示慢请求仅有 1,052 字符 system、615 字符工具定义，不能直接将全部 419.77 秒归因提示词体积或发现入口。

旧候选的发现调用为 2.49 秒，随后已暴露工作工具的下一主调用仍用了 417.08 秒后超时。与成功 low 请求的 system、schema 体积相同；发现优化不等于已解决这段上游生成等待，完整输入语义、思考强度与上游因素尚未拆开。

只复用紧邻上一用户回合的服务端已核实业务回执来准备 `work`／`reports` 工具定义。普通下一回合不继续积累工具；不从历史助手文字猜能力，不回溯已失效回合，不沿用授权或对象版本。当前角色过滤、来源校验、独立写入授权继续生效。

用固定模型响应和真实回执验证少一轮发现，覆盖无关换题及失效来源；独立验收后，仅补一次 max 工作创建→修改实际计时。历史两组超时保留，单次不同时段对照不宣称稳定收益。
