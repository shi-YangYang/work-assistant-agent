## 修改顺序

1. **冻结基线。** 速度回退以 `70ba0f7` 的父提交 `48452f69c8cd6b79c3005f8a698ae63a42b8b9ad` 为源码基线，先对比测试修复提交 `70ba0f7` 本身引入的变化，再检查后续优化。`70ba0f7` 和 `3d0a0d1` 的既有测量只作中间版本记录，不能替代修复前版本。固定模型服务修订、实际请求参数、输入、角色、记忆、历史、资料和资源，用同输入的定向对照检验；禁止改日常账号配置。
2. **补齐分段证据。** 接通浏览器提交／呈现、API 受理、worker claim、各模型与工具、子作业、最终提交的关联。补安全的网络阶段与最近有效进度计时；先用固定延迟校准，证明观测不会阻塞回复。
3. **绘制实际执行路径。** 按类别列出模型次数、工具依赖、重复读取、检查职责、锁／排队时间及关键路径。先证实瓶颈，再确定实施文件，不按文件清单全部重写。
4. **改造共用流程。** 优先消除不必要调用、重复上下文和重复检查；再评估独立读取并行、连接与缓存复用、沙盒传递和收尾。高度耦合的权限、任务状态与恢复由同一实施 Agent 串行修改。
5. **验证与配对计时。** 每项跑直接相关的受控回归，复用已取得的真实样本，只补能验证具体瓶颈的对照。模型一般内容质量不触发返工；任务未交付保留耗时，不能计为完成提速。
6. **独立验收。** 新的验收 Agent 检查证据、依赖边界与系统正确性；缺失数据标记未验，不能以首字或一次快样本代替总耗时结论。

## 数据流

浏览器发送 → API 接收 → 队列 claim → 材料／上下文就绪 → 主模型与工具循环 → 必要授权／用户交互 → 实际业务或文件成果 → 最终提交 → 浏览器完整呈现。

报告与执行子作业挂接原任务；人工等待单列。工具中的辅助模型保留父子关系，计算关键路径而非把所有耗时相加。原来的 PostgreSQL 最终事实、Redis 临时正文、SSE 增量通道保持分工。

## 测试计划

### 隔离与校准

- 独占测试数据库及 Redis 命名空间、合成公司／管理员／员工、临时文件与沙盒任务；不使用真实员工资料。
- 验证 API、worker、数据库、Redis、沙盒、模型绑定和任务 claim 均就绪。对照环境顺序运行；不能让同数据库全局 worker 锁导致基线空等。
- 基线与优化版使用相同观测实现；必要的观测补丁不得改变基线业务流程。记录源码、模型配置、fixture 与用例摘要。
- 注入固定模型／工具／数据库延迟验证计时、并行、错误分类；真实上游与浏览器证据另列。

### 配对规则与停止条件

- 矩阵所有类别先完成受控功能与依赖覆盖；真实样本覆盖正常、业务、搜索、编码／文件、材料、多轮与混合任务。
- 已有八条核心旅程及补充样本继续保留，不再执行剩余大矩阵。普通问答、写作、工作、报告、研究、代码／文件、材料、长会话按路径整理现有证据，避免为开放答案评审反复调用模型。
- 新实测必须对应具体假设：提示／工具定义负担、重复模型轮次、授权循环或交付阻塞。先用已有记录与受控输入确认机制，再以相同模型／强度／输入补最小受影响对照；不得以泛泛覆盖为由追加样本。
- 报告逐次原值、各阶段、模型／工具次数、输入体积及配置；单次结果仅作观察，缺少足够配对时不声称稳定中位数或 p95。
- 前后轮次交替运行，历史和业务初态重建；同一旅程内多轮按原对话承接。冷启动和已就绪结果分列。
- 外部故障不静默剔除，不无限重跑；先保留失败与阶段证据。只因具体代码修改或已确认环境修复补测受影响项，记录新原因，不覆盖首次结果。
- 受控检查通过后不反复执行；只有新修改、失败或明确未验分支才扩展范围。具体机制和回归已验证即停止，不补满历史预算、不跑到答案满意为止。

## 接口与迁移

不预设公共 API、数据库 schema 或部署依赖变更。计时优先用现有日志与测试侧浏览器观测；必要关联字段向后兼容。若测量证明必须改变公共接口或持久化结构，先补齐方案、兼容测试和本计划，不能偷偷扩大范围。

## 风险与回滚

- 合并检查可能丢失独立判断：先写保护职责与反例，再评估是否能复用；不能把主模型自己的提案当独立授权证据。
- 并行可能增大资源竞争：固定资源下测多用户与沙盒并发 2，若单任务快但总体排队恶化则不算改善。
- 缓存可能陈旧或越权：仅在合法作用域复用，权限、版本或指令变化即失效。
- 模型／网络波动可能掩盖收益：用受控因果证据和配对真实计时分别说明，不把误差解释为确定提速。
- 按瓶颈分批提交，可单独撤回无收益或退化的优化；保留既有最终保存、授权和旧 checkpoint 恢复协议。
