## 数据与接口

- 成果由公司、创建者、会话限定；版本不可变，内容和条目顺序属于版本，条目 ID 跨修改保持稳定。
- 一条成果条目可以关联实际工作及所用版本；删除或改名不靠名称寻找替代项，明确副本可保留多条关联。
- 消息增加可选成果引用（成果、版本、所选条目），旧客户端省略时仍支持自然语言定位。选择不是写入授权，意图校验仍读取用户请求和服务端上下文。
- 增加会话内成果查询、详情、版本的受权接口，保持同一套 DTO；不新增文件生成与下载链路。
- 私人成果操作与业务操作分别提供真实回执。已有工作／报告服务继续负责写入、并发版本和确认，成果工具不绕过它们。
- 保存用户指定写入的业务内容及明确附带的材料；内部私人出处与管理端可见来源分开，所有读取入口共用检查，不增加分享设置页面。

## 实施顺序

1. 实测简单 HTTP 搜索来源，核对可用性及限制，不新增供应商管理或未确认的付费依赖；不再询问已明确的写入决定权与简洁交互。
2. 统一写入校验，先保护工作、进展建议、督办和报告，新增无业务副作用的回归。普通请求不增加一轮模式分类模型调用，复用已有核对机制。
3. 增加成果版本、稳定条目、关联、服务层和迁移。复用原队列／检查点／租约，实现幂等与按需读取；个人成果保存不进入报告来源或团队统计。
4. 接入成果工具和会话恢复。共同上下文供主助手、授权与答复核对使用，防止模型能看到方案而校验器看不到；不把历史授权复制到新任务。
5. 接入业务关联与来源快照。修改关联工作前读取当前版本；旧成果、取消操作和重试不能覆盖用户新修改。
6. 实现局部成果 UI：正文优先、长内容按需展开，修改沿用对话，次要操作收纳；不新增导出、管理页面、模式切换或重复状态组件。检查桌面、窄屏、长文、空态、失败及版本冲突。
7. 用现有 HTTP 客户端实现 curl 等价的请求能力，封装 `web_search(query)`／`web_fetch(url)`；沿用节点重试、进度和来源展示，限制目标与重定向，不开放任意命令执行。
8. 跑相关回归、真实多轮任务与浏览器交互，再由新的独立验收 Agent 检查。

## 验证

实施按 S3：涉及持久化、来源授权与跨端契约。只覆盖相关服务端与 Web 模块，文档调整单独按 S0 检查。

- 服务端：成果／消息／业务操作／来源权限／报告相关模块，包含迁移前后旧记录、越权读取、选中版本失效、确认与重试、并发修改。
- 联网：固定响应验证正文、大小限制、超时、跳转与 DNS／私网边界；真实公开网页和所选搜索来源验证连通与引用，不将不受控外网变成普通 CI 依赖。
- 前端：相关 DOM 测试、Web 类型检查；实际浏览器检查聊天与成果区的电脑和手机布局、选择、复制、继续修改、切换账号和失败恢复。格式化只处理修改文件。
- 真实模型：至少 12 类完整任务，每类两种表达、交叉覆盖员工／管理员及两种人设；至少 6 类包含连续 3～5 轮修改。包含用户未要求写入、明确写入、否定／撤回、混合范围、材料注入、计划重排、部分成功和长上下文恢复。
- 核心样例必须完整跑通：客户材料 → 生成计划 → 修改计划 → 前两项加入工作 → 定位第二项 → 改日期 → 查询核实。分别核对成果版本、工作数量／字段、报告和建议表是否出现未授权变化。
- 确定性权限／重试用固定模型测试，真实模型验证理解和实际调用；评分异常与产品失败分开，原始结果保留，人工阅读最终回答。使用已有授权配置，不输出密钥、不修改日常业务数据、不模拟成功。
- 保留相关检查与真实结果证据，不因本 Spec 重跑桌面模型、打包或自动触发 CI。检查通过后停止，具体失败只定向返工复测。

真实验证脚本和原始结果保存在 `artifacts/spec032/`，不加入普通 CI。

## 风险与兼容

- 新来源快照不能成为扩大管理员访问的捷径；旧规则与新记录须可区分，原有可访问记录保持兼容，不隐式迁移私人聊天。
- 计划编号会重排，稳定条目关联是工程保证；仍有多个合理指代时保留必要澄清，不承诺模型永不误解。
- 长成果按需读取，不能扩大上下文到无限或增加多层无必要模型调用；记录执行耗时与调用次数，比较同类任务的增量。
- 失败保留前一个有效成果和已完成业务回执；只有全部必要步骤完成才能表示整个任务完成。
- 应用回退保留新增数据，禁止为回滚删除成果或业务记录；旧客户端可以继续读写原有工作／报告。
