# 工作助手任务执行与自主汇报

## 状态

已实现，验收通过。支持对话协助、连续修改、按需写入工作／报告，以及两个轻量联网工具；不新增文件导出或分享设置。

## 背景与目标

工作助手围绕员工的目标分析材料、制定方案、撰写内容、调用工具和持续修改。工作与汇报系统是它对接的业务系统，是否写入由用户决定。

- 保留个人提效和进展汇报两类能力，不要求用户先选择模式。
- 打通“材料 → 方案 → 修改 → 按需写入业务 → 继续调整”的连续任务。
- 让成果可查看、修改、复用，让系统写入有明确授权、对象和结果。
- 两种人设使用同一套能力、事实规则和权限。

## 当前行为

- 已支持多模态材料、文件读取、自由撰写、本人工作操作、报告生成、业务回执和节点重试，不从头重做这些能力。
- 会话上下文可承接历史方案，但辅助引用仅选取最近 12 条消息，并限制助手正文长度；没有独立的成果版本和条目关联，长计划或多次改写后存在指代丢失风险。
- 普通进展描述仍可能触发 `propose_progress` 保存待确认建议；该工具没有与正式业务操作统一的写入意图校验。不满足“是否进入汇报系统由用户决定”的新边界。
- 当前来源追溯可以沿工作修订找到原始消息与附件。个人任务成果转成业务记录后，哪些原文对管理员可见需要明确控制。
- 任务状态、重试、幂等和确认已有实现；成果目前主要以聊天正文展示。

## 目标行为

| 用户表达 | 预期 |
| --- | --- |
| “看这份客户需求，整理实施计划” | 读取资料，区分事实与建议，交付可继续修改的计划，不创建工作、进展建议或正式报告 |
| “今天完成了初稿，还有两个问题，帮我想想” | 分析和讨论，不因为提到进展就写入汇报系统 |
| “把计划前两项加入我的工作” | 定位明确的成果版本和条目，创建对应工作并保留关联，展示真实结果 |
| “第二项时间太紧，调整一下” | 找到对应事项；目标日期未确定且没有自主安排授权时，给调整建议或只问一个关键问题，不要求用户重述对象 |
| “第二项改到下周五，其他不变” | 按请求时间和公司时区确定日期，读取最新工作版本，只修改该项截止日期 |
| “记录到我的工作／整理成待确认进展” | 写入相应业务对象；待确认建议与正式工作状态分开 |
| “写一份日报示例” | 交付个人文稿，不生成正式业务报告或虚构已完成成果 |
| “根据我的工作生成今天的日报” | 生成正式报告草稿；正式提交继续需要本人确认 |
| “只改方案，不更新工作” | 仅生成新的个人成果版本，已关联业务记录不变 |

这些是验收示例，不是固定任务类型白名单。用户可以自由组合要求；能力不足或真实歧义时说明具体缺口，不机械拒绝或反复索取已知信息。

## 功能需求

### 交互原则

- 从用户要完成的任务出发，沿用一个对话入口；不新增提效／汇报模式、任务类型选择或独立成果管理页面。
- 简单结果直接显示正文；长文、表格等确需独立阅读时才提供展开入口，不默认弹出侧栏或堆叠卡片。
- 当前结果保留一个明确的主要操作，复制、历史版本等按需展开。条目选择仅在需要选择时出现，不把所有能力同时铺在界面上。
- 用户可以直接说“改第二项”“把前两项加入我的工作”，不必先点击选择器。对象明确就执行，存在影响结果的歧义才澄清。
- 使用“查看方案”“加入我的工作”等具体文案，明确操作对象和结果；避免含糊的“保存／同步／发布”，不向用户展示内部 ID、快照或工具参数。
- 复用一处任务进度和结果反馈，不同时堆积状态卡、toast 和重复回执；重试沿用单一入口。简洁不能省略必要确认、错误原因和部分成功结果。

### 任务与授权

- 普通聊天、分析、计划和内容创作允许保存到用户的私人会话／成果空间；这与写入“我的工作”、进展建议、日报周报是不同操作。
- 不把“创建一个方案”“帮我做一份清单”“今天做了什么”按关键词等同于创建业务记录。结合当前请求及明确承接的上下文判断。
- 用户明确要求或点击有明确目标的操作入口后，才写入业务系统；待确认进展建议也适用，不先偷偷保存再等待用户确认。
- 明确的低风险创建、编辑沿用现有直接执行行为，不新增通用二次确认。正式提交和删除仍使用既有确认流程。
- 拟定计划不证明工作已发生；真实进展来自用户说明或已授权业务来源。个人成果不能绕过正式报告的事实要求。
- 混合任务逐项执行，例如“修改方案，但只把第一项加入工作”；禁止把其余内容一并同步。

### 个人成果与连续修改

- 对需要持续使用的方案、文稿、清单和表格提供成果记录；简单问答不强制生成成果，也不要求每次回复都展示卡片。
- 成果有稳定标识、版本、所属会话及创建者；计划条目有稳定标识，排序、改名和修改不凭标题重新猜对象。
- 展示和选择使用具体版本。修改产生新版本，不覆盖用户已引用的旧版本；工具读取时按需获取正文，不依赖截断的聊天文本还原成果。
- 成果条目写入工作后保存条目与工作 ID 的关联；后续按关联读取最新业务版本，再应用明确修改。
- 改成果不自动改已写入的工作，改工作也不偷偷覆盖整个方案。需要同步时由用户明确选择目标。
- 重复请求、刷新重发和工具自动重试不重复创建成果或工作；用户明确要求另建副本时可以新建。

### 结果交付

- 方案、文稿、清单和表格直接在聊天中展示，支持复制、追问和继续修改。本期不新增 Markdown、Word、Excel 文件导出能力。
- 聊天展示必要摘要和成果入口，电脑按需打开侧边成果区，手机进入全屏成果视图；默认不常驻压缩聊天宽度。
- 成果区以阅读当前内容为主，修改继续通过对话完成；版本和条目选择按需出现。普通回复不堆“保存／汇报”按钮，不强制每轮推荐上报。
- 沿用 Web 黑白灰设计、CSS Modules、现有错误和任务进度组件；失败保留输入和上一个有效成果。

### 轻量联网能力

- 只提供 `web_search(query)` 和 `web_fetch(url)` 两个工具，用户通过对话使用，不新增联网模式、搜索页面或搜索服务管理。
- `web_fetch` 请求公开网页并提取正文、标题和链接；`web_search` 请求搜索来源并整理标题、链接和摘要。采用简单 HTTP 请求，可用 curl 等价方式，优先复用现有 HTTP 客户端，不引入新的 Agent 框架。
- 搜索来源由实施时选定并实测，优先不需要用户另配密钥的方式；遇到验证码、限流或不可访问时明确返回失败，不绕过限制，也不把付费搜索服务作为未确认的前置条件。
- 复用任务进度展示“正在搜索／读取网页”，回答保留来源；无法访问、内容不完整或没有结果时如实说明，不用模型记忆冒充检索结果。
- 只访问公开 HTTP(S) 页面，限制请求时长、大小和重定向，并校验实际连接目标，禁止访问服务端内网；网页内容视为资料，不能授权工具操作。搜索词只包含任务所需信息，不自动发送整段私人对话或附件。
- 不引入浏览器自动化或任意 shell 执行。搜索不可用时，网页阅读及其他任务仍可使用；仅抓到网页不代表已完成搜索验收。

### 接入汇报系统与资料可见性

- “把前两项加入我的工作”只创建这两项工作，不连带向管理员开放整段聊天或全部附件。无需新增分享设置；需要附带材料时由用户明确提出。
- 个人成果及其历史版本默认仅创建者可见。管理员身份不自动获得员工私人会话、成果或未提交报告权限。
- 发布快照保留出处和版本用于追溯，但“存在内部出处”不等于管理员可以读取该出处的私人全文。
- 所有读取途径执行相同边界：详情、团队工具、来源接口、附件下载和重试，不仅隐藏前端入口。
- 现有已确认工作和已提交报告继续可用，不重写或删除旧记录；新业务修订保存授权写入的内容，与旧来源规则显式区分。

## 非目标

本期不提供任意代码执行、登录第三方网站、发送邮件或钉钉消息等外部操作。

不新增组织架构、派单系统、审批流、跨会话自动画像；不改 Electron、登录页或全站视觉体系。

## 技术与兼容要求

- 沿用现有 harness、会话、任务队列、模型配置、人设、节点重试和检查点，不另建一套 Agent runtime。
- 个人成果工具与业务写入工具分开；业务意图校验复用并统一覆盖正式操作、进展建议和督办建议，不靠前端按钮或 prompt 单独控制写权限。
- 用户选中的成果 ID／版本／条目作为请求上下文，不作为授权本身；后端复核所有权、版本和当前请求。附件、引用及历史指令不能授权额外动作。
- 已删除、过期、同名歧义或版本冲突时不能猜测另一个对象。重试沿用已保存回执，部分成功明确展示，不重放已完成步骤。
- 旧消息、工作、报告和客户端请求兼容；新增成果与关联采用增量迁移。历史自然语言没有唯一映射时只澄清必要信息，不批量推断关联。

## 验收标准

- [x] 未明确授权时，提效对话不会新增或修改工作、进展建议、报告；私人会话和成果正常保存。
- [x] 同一会话自然切换提效、讨论、汇报，正确执行混合请求，不要求切换固定模式。
- [x] 客户材料 → 计划 → 修改 → 选择前两项入库 → 修改第二项日期完整通过，最终成果、工作字段和数量一致。
- [x] 计划重排、同名条目、历史消息超出窗口、刷新继续后，仍按实际版本和关联定位；真正歧义才询问。
- [x] 成果修改与业务修改相互独立；指定只改日期时其他字段不变。
- [x] 聊天中查看、复制、继续修改及电脑／手机成果交互可用，无模拟保存。
- [x] 核心任务可直接通过对话完成，无强制模式切换、版本选择或多余确认；长内容按需展开，主要操作清晰，反馈不重复。
- [x] 搜索与网页阅读可参与任务，来源可查看；检索失败、私网地址、恶意网页指令不导致虚构结果或额外授权。
- [x] 真实汇报建议、正式报告草稿、提交确认及来源追溯继续可用；计划不被包装成已完成成果。
- [x] 新旧来源权限、账号隔离、重复请求、并发改动、取消／失败／重试通过对应检查。
- [x] 员工／管理员、两种人设使用真实模型完成多轮场景，分别核对最终显示与实际写入；外部接口失败单独记录。

## 联网来源

使用 Bing RSS 搜索和 HTTP 网页正文读取，已完成真实连通验证，无需额外密钥。来源限流或不可访问时如实返回失败。
