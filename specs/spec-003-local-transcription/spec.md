# Spec 003 — 本地转写与 Transcript

## 状态

DONE · 2026-09-10 · [独立验收 PASS](acceptance.md)。实际质量、物理录音和双平台 CI 集中见 [验证记录](verification.md)。

## 背景

[Spec 002](../spec-002-meeting-recording-and-storage/spec.md) 已提供麦克风录音、WAV / SQLite、历史与回放；本阶段补齐 Meeting MVP 的文字输入层。

## 目标

应用内准备模型后离线转写，录音中分批出字、结束后补尾；文字和检查点持久化，旧录音可补转写，中断可继续。

## 非目标

LLM / 纪要 / 行动项、云 ASR、逐字即时字幕、翻译、说话人分离、热词训练、编辑 / 导出 / 搜索 / 外部音频导入、多模型 / GPU 设置、系统音频、安装包。

## 当前行为

实施前只有录音与播放，SQLite schema 1 不含转写任务或片段，转写能力未接入。

## 目标行为

设置中显示模型状态、来源、下载量与空间要求，用户点击才下载。模型未就绪仍可录音，开始前提示之后可补转写；就绪后新会议自动启动转写。录音保存和转写完成分别展示。关闭可保留进度，下次由用户继续，不自动启动麦克风或重任务。

## 功能需求

### R1 — 模型与离线边界

- 采用 [决策 0007](../../.ai/decisions/0007-local-transcription-baseline.md) 的 faster-whisper + small 多语言模型、CPU INT8，中文为主并保留英文原文，不执行翻译。
- 固定来源、revision、文件清单和校验值；staging 下载，校验及实际加载成功才发布就绪。显示真实字节进度，支持取消 / 失败重试，不要求断点续传。
- 模型放 userData，缺失、损坏、网络 / 磁盘 / 加载失败有可操作错误，不使录音核心不可用，不要求用户操作 pip 或模型路径。
- 模型下载明确联网，推理只用本地完整文件，不隐式补下载、外发音频 / 文字或转向云服务。

### R2 — 解耦与调度

- 独立受管进程负责加载、重采样、VAD 与推理，不进入录音回调、writer 或控制请求循环。
- 按已写完整帧生成有序块，目标约 10 秒、可调 5～15 秒，与驱动块分开；记录稳定序号和原始帧范围，重采样保留会议时间映射，不改 WAV。
- 以磁盘音频和检查点承接积压，内存只保留有限描述和当前窗口；不丢弃未转写范围。静音检测及有限上下文避免持续假句、边界漏字和整句重复。
- 全局最多一次推理，活动录音优先，历史在块边界让出；开始 / 停止录音不等推理。worker 崩溃 / 超时 / 内存错误仅影响转写，保留已提交文字并可重试，不重启正在录音的核心。

### R3 — 文字与展示

- 片段含稳定 id、meetingId、chunkId、sequence、startMs / endMs、text、可空 speaker / confidence；时间限于对应音频，不伪造说话人或置信度。
- 片段与块进度同事务提交后才展示；静音无文字也推进检查点。查询有界分页 / 游标，不每次返回全文或传音频。
- 按时间追加，用户翻看上文不强制滚动，提供回到最新；点击片段定位现有播放器，录音期间禁播。
- 空态区分未开始、处理中、未检测到语音和失败。

### R4 — 补尾与重试

- 录音结束按最终有效帧封口，处理不足一块的尾部；所有有效范围处理完才 completed。Meeting.status 只表示录音状态，恢复音频来源不完整须持续标明。
- 历史可播放会议提供生成转写；已完成不默认全量重跑。重复开始 / 继续或超时后重试幂等，超时查权威状态。
- 失败保留原音频和已提交文字，从最后检查点按任务锁定的模型 / 分块配置继续，不覆盖整篇或生成重复任务 / 片段。

### R5 — 生命周期

- 切页 / 最小化持续转写。录音中退出遵循原停止保存确认，保存音频后可保留转写进度退出，无需等全文推理。
- 仅转写活动时可选继续处理或保留进度退出；停止新块调度，保留已提交内容、回收 worker，未提交块下次重做。
- 强退、休眠、核心异常后任务可恢复为 paused；先恢复录音再核对音频范围，不可读显示错误，不能跳过缺失范围宣布完成。

### R6 — 兼容与安全

- schema 1 增量迁移，保留会议 ID、元信息、WAV 和回放；失败回滚保留原库，不删除重建。旧会议初始未转写，不升级即批量推理。
- 录音能力、模型就绪与会议转写状态分别表达。保持 sandbox、来源 / 参数校验；renderer 只传会议 ID 和受控操作，不提供任意下载 URL、路径或进程命令。

## 数据与状态

ModelState：modelId、revision、missing / downloading / verifying / ready / error、字节进度和错误。任务：meetingId、模型 / 配置快照、已处理帧、最终目标帧（录音时可空）、错误；状态 not_started / queued / running / draining / completed / paused / failed。块保存稳定序号、连续有效帧范围、有限上下文和完成标记；片段字段见 R3。

进度按已处理音频帧计算，含静音；paused / failed 保留检查点，draining 表示尾部处理中。

## 边界条件

模型缺失、下载断网 / 取消 / 重启 / 损坏；中文 / 英文术语 / 数字 / 跨块短语、长静音 / 噪声 / 短会议；慢推理、崩溃、重复请求与回复丢失；Windows WAV 读取与收尾重命名、数据库锁、磁盘不足、中文 / 空格路径和恢复范围变化。

## 技术约束

沿用 Electron / React / TypeScript、Python 3.12、stdio、SQLite 和已有目录；只实现一个真实 Provider，业务不依赖模型库返回对象。不引入额外 HTTP / 消息服务；锁定依赖和模型，正式分发遵守 [决策 0005](../../.ai/decisions/0005-self-contained-desktop-distribution.md)。

## 兼容性与性能要求

至少实际验证 macOS ARM64 和 Windows x64 的安装、真实模型推理和相关 Electron 流程；新增 Windows 场景不能依赖 POSIX 脚本或真实麦克风。其他架构、GPU 和最低系统不未经验证承诺。

以 M5 / 16 GiB 为性能参考：模型预热后，固定两分钟清晰中文样本累计推理不超过音频时长，首批文字目标 20 秒内；未达标须调整并记录，不改为仅会后转写，也不外推所有电脑实时。原文件累计性能与用户指定的短公开语音物理回采延迟分别测量，详见验证记录。

## 验收标准

- [x] 应用实际下载 / 校验 / 就绪，取消与失败可重试，无模型仍可录音。
- [x] 真实 Provider 离线转写中文和中英混合，无外发或隐式下载。
- [x] 真实物理麦克风经 Electron 完成分批文字、补尾、重启与定位播放；按用户指定用公开人声声学回采，非文件注入或用户现场发言。
- [x] 固定人工参考中文 CER≤20%，术语、静音和跨块无确定性整句漏字 / 重复。
- [x] 记录设备、revision、参数、加载 / 首字 / 累计时间并核对性能目标。
- [x] 慢 / 失败 Provider 不阻塞采集和控制，帧增长、积压可见、队列有界。
- [x] 尾块、静音、幂等、重试及退出恢复不丢已提交内容或重复片段。
- [x] 旧库迁移后可查 / 播放 / 补转写，注入失败后原库可读。
- [x] 两平台实际自动检查、模型及新增桌面场景通过，记录跳过项。
- [x] 实施与独立验收报告齐备，明确未验证范围。
