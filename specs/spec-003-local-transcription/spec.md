# Spec 003 — 本地语音转写与 Transcript

## 状态

`DONE` — 2026-09-10。模型准备、持续转写、历史补转写和恢复已实现，[独立工程验收](acceptance.md) 为 PASS。最终代码 `0b84fe1` 的 [macOS / Windows CI](https://github.com/shi-YangYang/work-assistant-agent/actions/runs/34451673078) 均已通过；真实麦克风与模型质量证据及限制见 [verification.md](verification.md)。

用户已确认中文为主、兼顾中英混合，首次使用由应用提示并下载默认模型。沿用既有目标：本地、持续转写，录音不受推理阻塞。Spec 决策由协调 Agent 直接处理，不创建子 Agent 验证。

## 背景

[Spec 002](../spec-002-meeting-recording-and-storage/spec.md) 已交付麦克风录音、WAV / SQLite 保存、历史和回放。本 Spec 完成 [Meeting Agent MVP](../../constitution/mission.md) 的文字输入层，为后续会议纪要提供能追溯到音频的完整 Transcript。

## 目标

1. 用户在应用内准备默认模型后，可以离线将会议语音转成文字。
2. 录音期间分批显示带时间的转写片段；结束后补齐剩余音频。
3. 保存转写和处理进度，重启后可以查看，失败或中断可以继续处理。
4. 现有历史录音也可以生成转写，不要求重新录制。

核心流程：**准备模型 → 开始会议 → 持续录音并显示文字 → 结束录音 → 补齐转写 → 重启查看文字及对应录音。**

## 非目标

- LLM、会议纪要、行动项提取、周报、Memory 或云端 ASR。
- 逐字即时字幕、说话人分离、人员映射、翻译、专用热词训练。
- 转写人工编辑、导出、全局搜索、外部音频导入。
- 多模型商店、自定义模型导入、GPU 配置界面和自动切换多个 ASR 引擎。
- 系统音频采集、改变录音格式、签名安装包及内置运行时制作。

## 实施前行为

- 录音通过 Python 原生输入流与写入线程持续写入单声道 PCM16 WAV，采样率取自设备。
- SQLite schema version 1 仅保存会议和音频元信息，没有 Transcript 或转写任务。
- Electron 通过受限 stdio / preload 接口管理会议，转写能力显示未接入。
- macOS 与 Windows 的现有 CI 已通过；Windows 有 4 项既有平台受限冒烟测试跳过，不等于 Windows 实机录音或 ASR 已验证。

## 目标行为

设置页显示“本地转写模型”的准备状态、下载说明和操作。用户点击下载后才访问模型来源；下载完成并验证可加载后显示就绪。模型未就绪时，原有录音和回放仍可用，开始会议前明确提示本场暂只录音、之后可补转写。

模型就绪后，新会议自动启动转写。会议工作区持续展示已保存的文字和时间；处理落后时分别展示录音进度、已处理音频位置和待处理状态。

结束会议仍先停止并保存录音，随后在详情页继续转写尾部。音频已保存和文字已完成分别表示。关闭应用可以保留转写进度并退出，下次打开后由用户继续；不会为了等待整场推理而无法退出。

## 功能需求

### R1 — 模型准备与离线边界

- 首版只提供一个默认多语言模型，中文为主、保留中英混合原文，采用转写任务而非翻译任务。
- 基线为 `faster-whisper` + Whisper `small` 多语言模型，CPU / INT8；具体依赖版本和模型 revision 在实施首步验证并锁定。依据见 [决策 0007](../../.ai/decisions/0007-local-transcription-baseline.md)。
- 下载前说明来源、所需下载量与磁盘空间；下载期间显示真实字节进度，支持取消和失败重试。本次不要求断点续传。
- 只下载受控清单中的模型文件，固定 revision、文件清单与校验信息；临时下载与可用模型分开，校验及加载成功才发布为就绪。
- 模型缺失、文件损坏、网络不可达、磁盘不足、加载失败应有可操作提示，不能导致整个录音核心不可用。
- 模型置于应用用户数据目录，不能进入 Git、依赖源码或临时构建目录；普通用户不需要操作模型路径、pip 或解释器。
- 模型下载是明确的联网行为；音频与转写不外发。就绪后的推理必须仅使用本地文件，不隐式联网补文件或切换云服务。

### R2 — 录音与转写解耦

- 保留既有录音生产链路；ASR 在受管理的独立工作进程运行，模型加载、重采样、VAD 和推理都不进入录音回调、文件写入线程或控制请求处理循环。
- 从已经写入的完整音频帧生成有序业务块。初始目标每约 10 秒推进一次，配置可在 5～15 秒间调整，与驱动回调块大小分离。
- 块记录稳定序号和原始采样帧范围；重采样到 ASR 输入格式时保留相对于原会议的时间映射，不修改原始 WAV。
- 以可恢复的磁盘音频和持久进度承接积压，内存只保存有限待处理描述和当前音频窗；慢推理不能造成无界 PCM 队列或丢弃未转写内容。
- 使用静音检测和有限上下文处理分块边界，避免持续静音生成假文字；重叠上下文不得重复写入同一句话。
- 首版全局最多一个推理任务执行，新活动会议优先，历史任务在块边界让出执行机会。录音开始和停止不等待模型推理结束。
- 工作进程失败、超时或内存不足只影响转写；保留已提交片段并提示重试。不得为了恢复 ASR 强制重启正在录音的核心。

### R3 — Transcript 展示与保存

- 每个片段有稳定 ID、meetingId、chunkId、顺序、会议内 startMs / endMs、text、可空 speaker / confidence；时间位于所处理音频范围内。
- 首版 speaker、confidence 均可为空，不生成不存在的说话人或将模型内部得分伪装成用户可理解的置信度。
- 已确认片段与该块完成标记在同一事务提交后，才作为持久结果显示。静音块可以没有文字，但必须推进处理进度。
- 界面按时间有序追加结果，用户翻看上文时不强制滚动到底部；提供回到最新内容的操作。
- 查询采用有界分页 / 游标，不在每次轮询返回整场 Transcript，不通过 JSON 传输音频。
- 详情页同时提供 Transcript 和现有音频播放器；点击片段可定位回放，遵守录音期间禁止回放的既有规则。
- 空转写应区分尚未开始、仍在处理、未检测到语音和处理失败，不能把失败描述为空会议。

### R4 — 结束、历史补转写与重试

- 结束录音后以最终有效帧数封口，处理不足一个完整块的尾部；只有所有有效帧范围都处理完毕，才显示转写完成。
- `Meeting.status` 继续表示录音状态，转写状态独立。原录音中断时，只处理已恢复的音频并明确来源不完整，即便该部分转写已经完成。
- 现有可播放的历史会议提供“生成转写”；已完成会议不默认全量重跑。首版重试只继续未完成部分，不提供覆盖整篇 Transcript 的重转写操作。
- 同一会议重复开始、继续或请求超时后重试，不得生成并发重复任务或重复片段。客户端超时后查询权威状态。
- 失败时保留已提交文字和原始音频；重试从最后已提交块继续，使用该任务锁定的模型和分块配置。

### R5 — 生命周期与恢复

- 切换页面或最小化不暂停正在运行的转写。
- 录音中关闭窗口仍遵循 Spec 002 的停止保存确认；音频保存成功后，可保存转写进度并退出，无需等待全部推理结束。
- 只有转写活动时，关闭提示可保留进度并退出或继续处理。退出前不再调度新块，已提交数据保留，未提交块下次重做；工作进程须回收。
- 强制退出、休眠或核心异常后，运行中的转写标为暂停并可继续，不得留成永久运行状态。下次启动不自动开启麦克风或重任务。
- 恢复先完成已有录音文件恢复，再核对任务音频范围；不可读取的音频显示错误，不能跳过缺失范围后宣布全文完成。

### R6 — 数据兼容与能力状态

- 增量迁移现有 schema version 1，保留会议 ID、元信息、原始音频与回放行为。迁移失败回滚并保留原数据，不删库重建。
- 旧会议初始显示“未转写”，只有用户发起后才处理，不在升级时批量推理历史记录。
- 录音能力、模型准备状态、转写任务状态分别表达；未准备模型不阻断录音，模型就绪不等于某场转写成功。
- 保留 sandbox、来源与参数校验；renderer 只使用会议 ID 和受控操作，不能指定任意下载地址、文件路径或进程命令。

## 数据与状态约定

| 对象 | 最小信息 |
| --- | --- |
| ModelState | modelId、revision、missing / downloading / verifying / ready / error、下载进度、可空错误 |
| TranscriptionJob | meetingId、状态、模型与配置快照、已处理帧位置、最终目标帧数（录音中可空）、可空错误 |
| AudioChunk | 稳定 ID / 序号、meetingId、原始有效帧范围、有限上下文范围、完成标记 |
| TranscriptSegment | id、meetingId、chunkId、sequence、startMs、endMs、text、speaker / confidence |

任务状态为 `not_started`、`queued`、`running`、`draining`、`completed`、`paused`、`failed`。录音结束但尾部尚未处理为 draining；暂停与失败都保留进度。进度按已处理音频计算，包含静音，不能按文字数量估算百分比。

## 边界条件

- 模型准备前开始或结束录音，下载期间断网、取消、重启和文件校验失败。
- 中文、英文术语、数字、短语跨块、长静音、背景噪声及不足一个块的短会议。
- 推理速度慢于采集、工作进程异常退出、重复请求、块提交后响应丢失。
- 活动 WAV 收尾重命名时存在读取者，特别是 Windows 文件句柄占用。
- 数据库锁、磁盘不足、旧版本数据库升级、中文和空格路径、恢复音频范围变化。

## 技术约束

沿用 Electron / React / TypeScript、Python 3.12、stdio、SQLite 与既有目录。仅实现一个真实 ASR Provider，不引入 FastAPI、消息服务或多套模型框架。业务不依赖 faster-whisper 的返回对象，Provider 输出规范化片段。依赖与模型来源必须锁定；正式分发仍遵守 [自带运行时约束](../../.ai/decisions/0005-self-contained-desktop-distribution.md)。

## 兼容性要求

目标仍为 macOS 和 Windows。实施至少验证 macOS ARM64 与 Windows x64 的依赖安装、真实模型推理和相关 Electron 流程；其他 CPU 架构、GPU 和最低系统版本不得未经验证作出承诺。Windows CI 新增的转写场景不得依赖 POSIX 脚本或真实麦克风来运行。

默认参数以当前 Apple M5 / 16 GiB 开发机作为性能参考，先做真实样本验证。模型预热后，以 2 分钟清晰中文样本为基准，目标首批文字在开始后 20 秒内出现，累计推理耗时不超过音频时长；不将该结果外推为所有 Windows 笔记本的实时保证。未达标应记录瓶颈并调整方案，不能把“准实时”悄悄改成仅会后转写。

- [x] 断网且模型就绪后，真实 Provider 能转写中文及中英混合音频，没有音频外发或隐式模型下载。
- [x] 至少一场真实麦克风讲话经 Electron 完成录音、分批出字、结束补齐、重启查看和片段定位回放；真实讲话与测试注入证据分开记录。
- [x] 固定非敏感中文样本使用记录在案的人工参考稿；清晰中文样本规范化字错误率目标不高于 20%，中英混合样本核对关键术语，静音不产生连续假句，跨块样本无重复整句或确定性的截断漏字。

- [x] 尾块、静音块、重复请求、失败重试和退出恢复不会丢失已提交内容或生成重复片段。
- [x] schema 1 数据迁移后原会议仍可查询和播放，旧记录可补转写；注入迁移失败后原库仍可读取。
