# Plan — 本地语音转写与 Transcript

## 对应 Spec

[Spec 003](spec.md)，状态 DONE，[独立验收](acceptance.md) PASS。实施涉及持久化迁移、共享 IPC、下载边界和进程生命周期，按 S3 验证相关子系统；暂停竞态返工与实际 CI 修复均已闭环，最终平台及实录结果见 [verification.md](verification.md)。以下保留实施计划和测试范围供追溯。

## 涉及模块

| 模块 | 职责 |
| --- | --- |
| 模型管理 | 受控下载、进度、取消 / 重试、完整性校验、就绪状态与本地加载路径 |
| ASR Provider / Worker | 隔离 faster-whisper，加载一次模型、重采样、VAD、推理及规范化片段；有界并发和退出清理 |
| 转写调度 | 根据已写音频范围分块，持久检查点、任务优先级、尾块、失败 / 暂停恢复 |
| Repository | schema 迁移、任务 / 块 / 片段事务、分页查询；保留现有会议和音频关系 |
| 桌面 / 协议 | 受限模型与转写接口、参数校验、能力状态及退出协调 |
| 界面 | 模型准备、活动 Transcript、积压状态、历史补转写 / 继续及回放定位 |

## 修改顺序

1. **真实引擎可行性。** 核对 Python 3.12 对应的 macOS ARM64 / Windows x64 wheels，选择固定发布版本；锁定模型 revision、实际文件大小、校验值及许可证。用默认 small / CPU INT8 跑固定中文与混合样本，记录质量和耗时。仅凭安装成功不能进入“已验证”状态；失败时先调整最小参数或提交具体方案问题，不同时引入第二套引擎。
2. **存储与恢复。** 从 schema 1 增量升级至 2，新增转写任务、块与片段表；旧会议保持未转写。明确唯一约束、状态恢复和迁移事务，在真实数据副本 / 隔离 fixture 验证，禁止拿用户数据库试错。
3. **模型与工作进程。** 实现一个 Provider 和受管理的 spawn 工作进程；下载任务、主控制循环、录音和推理互不等待。模型下载使用 staging，校验后启用；推理只加载完整的本地目录。
4. **接入已有音频。** 先完成已结束 WAV 的分块、VAD、片段提交和尾块，再接活动录音的已写帧水位；不复制完整会议到内存，不在录音线程执行 ASR。
5. **贯通桌面。** 扩展 Python 协议、TypeScript 契约、主进程与 preload，更新退出 / 暂停语义；界面接真实模型状态、Transcript、继续按钮和片段定位。
6. **针对性验证与交付。** 完成 Spec 的真实模型、真实讲话与可重复故障检查，保留平台证据，更新实际架构 / README / 技术栈和实施报告；由新的独立验收 Agent 审查，复用明确的已通过证据。

## 数据流

```text
麦克风 → 既有有界采集队列 → 既有 WAV writer → 已写完整帧水位
                                                   ↓
                      调度器 → 有界音频窗 → ASR 工作进程
                         ↑                        ↓
                 SQLite 任务 / 块检查点 ← 规范化片段
                         ↓
              受限分页查询 → Electron → Transcript 界面

用户点击模型下载 → 受控来源 → staging → 校验 / 加载 → 本地模型目录
```

- 原始 WAV 是可恢复输入；调度器可从已提交块位置和已写帧水位重新生成待处理范围。推理积压只增长磁盘上的未处理范围，不积累整场 PCM。
- ASR 输入由可信核心按会议 ID 解析，短时读取确定的完整帧后关闭原文件，推理使用有界独立缓冲。避免 Windows 下长期持有 `recording.wav` 阻止 `audio.wav` 收尾重命名；读取与重命名仍需最小协调和明确重试。
- Chunk 的有效区间连续且不重叠，上下文窗口可以有界重叠；片段时间映射回原采样帧范围。保留边界候选直到确认所属块，采用稳定的边界归属 / 去重规则，不简单按字符串全局去重。
- 全局单个推理任务，活动会议优先；历史队列只在块边界暂停。模型 / 分块配置随任务固定，重启后继续相同任务。

## 接口变化

拟扩展类型化业务操作，命名可以随现有代码习惯细化，职责不能改变：

| 操作 | 语义 |
| --- | --- |
| `getTranscriptionModel()` | 模型准备状态、固定模型信息、下载进度和错误 |
| `downloadTranscriptionModel()` / `cancelModelDownload()` | 受控默认模型下载，不接受任意 URL 或目标路径 |
| `startTranscription(meetingId)` | 为历史音频创建任务或继续同一未完成任务，重复请求幂等 |
| `getTranscriptionStatus(meetingId)` | 状态、已处理音频位置、总音频范围、待处理与错误 |
| `listTranscript(meetingId, cursor)` | 每页最多 50 个片段，带下一游标；有效片段不超过现有协议行大小限制 |

复用已有状态订阅或单路非重叠轮询，切页取消订阅；避免模型进度、录音和 Transcript 各自产生无界并发。ASR Worker 使用内部受控协议，所有日志写 stderr，不暴露执行入口给 renderer。

## 迁移策略

- version 0 新库建立最新结构；version 1 在事务中创建新增表 / 索引并更新 `user_version=2`；未知版本继续明确拒绝。
- 迁移不重写或删除旧会议，不移动 WAV。片段和块完成标记原子提交，唯一约束防止重放重复；静音块同样提交进度。
- 正常退出提交已完成块并将未完成任务置 paused；强制退出后将遗留运行状态恢复为 paused。恢复录音成功后再校验转写源范围。
- DDL 失败回滚。提供迁移前备份和恢复说明；不承诺旧程序能读取新版 schema，不通过自动降级删表来回滚。

## 测试计划

按改动点分批执行，检查通过后不重复；后续相关代码变化或具体失败才重跑。下列是不同风险所需证据，不要求在每一步都跑一遍。

- Python 定向测试：重采样时间映射、边界 / 静音 / 尾块、慢与崩溃 Provider 隔离、进度事务、幂等重试、schema 1 升级和失败回滚。使用跨平台 fixture，SQLite 与音频句柄显式关闭。
- 桌面定向测试及 `npm run typecheck`：新增契约、受限参数、分页界限、任务状态、退出保存与 worker 清理。
- `npm run test:smoke`：实际 Electron 中模型状态、分批出字、补转写、结束 / 关闭 / 重启和已有录音回放。模拟推理用于稳定制造故障，真实 ASR 另有集成证据。
- 真实模型集成：macOS ARM64 和 Windows x64 使用同一固定非敏感音频、锁定默认模型与参数，记录实际文本 / 时间范围。CI 缓存模型但验证清单，缓存未命中时走受控下载，不让测试默默 skip。自动化下载为测试专用路径。
- 真实麦克风：本机用可见录音状态采集非敏感讲话，并在模型就绪后离线完成实际 Electron 流程。需要用户讲话或首次 OS 授权时说明具体操作；设备不足不得以静音或预置文字冒充实测。
- 质量 / 性能：至少 2 分钟清晰中文、含英文术语的短样本、静音 / 噪声和跨块短句；记录人工参考、中文 CER 规范化规则、术语识别情况、模型冷启动与预热后的延迟、处理耗时及机器信息。
- `npm run lint` / `npm run format:check` 在对应 TS / CI / 构建文件修改后运行，保持现有双平台 CI 必需步骤。声明远端通过必须对应实际提交的两个任务结果，不能用本机结果代替。

未执行项写明原因、替代证据和影响，不生成虚假的 PASS。文件证据放 ignored `artifacts/spec003/`，不提交会议录音、数据库、模型或私密 Transcript。

## 风险

- CPU small 模型可能达不到参考机的延迟或中文质量目标：以首步实测决定参数可行性，必要时带证据调整技术决策；不自行取消准实时目标。
- 模型来源在用户网络不可达：显示可重试错误，保留录音能力；不擅自加入不可信镜像或云端转写。
- 短窗上下文不足、VAD 错判及静音幻觉：使用固定边界 / 静音样本调校，不把模型输出当作确定事实。
- 推理占用 CPU 仍可能影响采集：限制进程和线程并发，记录慢推理时的录音帧与设备溢出情况；进程隔离不代表物理资源无限。
- Windows spawn、文件句柄和退出清理：实际运行双平台相关场景，不继承现有 POSIX 合成录音 shim 的平台跳过方式。
