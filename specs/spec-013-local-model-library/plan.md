# Plan — 桌面转写模型库

## 对应 Spec

[Spec 013](spec.md) 已确认，用户于 2026-09-14 启动实施。主 Agent 完成决策；业务由实施 Agent 开发，新的独立 Agent 验收。语料准备和基准脚本由独立实施协作者负责，不修改业务模块；最终 Provider 稳定后再运行完整矩阵，避免重复测试。

## 涉及模块与修改顺序

1. `paa_core/model_manager.py`：单模型常量变为受控目录；各自维护文件、revision、许可和状态，共享一次准备队列。先兼容旧 small 缓存，再加入默认模型／语言持久化和删除引用保护。
2. `transcription.py`、`asr_worker.py`：按任务快照解析模型与模式，去掉旧任务对全局常量的依赖。worker 按路径＋完整配置加载，下载校验不可抢占活动推理。
3. 扩展 `transcript_store.py` 和摘要／搜索关联，完成旧会议重转写的候选结果原子发布，再接 UI。
4. `contracts.ts`、stdio 分发、`core-manager.ts`、`preload.ts`：受控模型操作与实际任务配置。`Transcription.tsx` 的 ModelSettings 改为列表，App 就绪判断改看当前默认，会议页显示实际配置；复用主题、选择和折叠组件。
5. 固定评测样本并运行小型真实矩阵，接入错误率和峰值内存说明，不展示耗时／速度。音频、权重与详细输出留 ignored artifacts；轻量结果／来源入仓库。实现完成后更新 README 使用步骤与技术栈实际状态，不复制日志。

## 模型来源与生命周期

- tiny／base／small／medium／large-v3 使用 SYSTRAN 对应 CTranslate2 权重。small 保留已有 revision，不按同名最新版替换。
- faster-whisper 1.2.1 的 turbo 映射原为 `mobiuslabsgmbh/faster-whisper-large-v3-turbo`；2026-09-14 已跳转至 [dropbox-dash/faster-whisper-large-v3-turbo](https://huggingface.co/dropbox-dash/faster-whisper-large-v3-turbo)。固定实际 canonical 来源、revision 和清单，不运行浮动别名；文件精度与 CPU 运行精度分开处理。
- 实施时从真实模型复核每个运行必需文件的大小和 SHA256，不填占位值。tokenizer／vocabulary／preprocessor 按模型自身清单准备，不能复用 small 的文件列表；缺失时不隐式访问 Hub。
- 下载 staging、校验和发布按模型隔离，空间预检查按真实清单与暂存策略计算。一次准备一个，保留取消和重试语义，不伪称断点续传。
- 校验后在推理空闲边界试加载，不能重置占用中的 worker。启动时不把全部已下载大模型逐一加载。选择、删除、任务引用检查通过同一协调边界串行化，避免检查后才被任务占用的竞态。

## 语言和接口数据流

| 模式 | 建议 Provider 配置 | 核对点 |
| --- | --- | --- |
| 中文 | `language='zh'`，保留简体通用提示 | 不用后处理伪造识别正确，仍检查英文术语。 |
| 英文 | `language='en'`，去除中文提示 | 原语言转写。 |
| 中英混合 | `language=None`、`multilingual=True`，不带中文专用提示 | 1.2.1 支持逐段检测，不等于逐词；真实检查句内切换与短英语。 |

保持 `task='transcribe'` 和既有 VAD／分块／上下文归属。配置加入解码版本，旧任务继续旧语言及提示策略。混合样本若出现误译或漏句，记录具体问题再调整，不无限增加候选解码。

建议接口：目录／状态、下载／取消指定模型、保存默认模型及语言、删除指定版本；任务状态返回实际快照和缺失版本。只接收受控 ID，不允许路径／URL；继续旧任务不接受覆盖快照的新参数。默认修改只作用于第一次创建任务，模型缺失与录音可用分别表达。

## 持久化与重转写

- 默认设置原子保存，旧环境缺省 small／中文。任务既有 `modelId/revision/config` 为权威，目录负责找对应路径；旧 small 目录无必要不搬迁。
- 引入候选运行 generation 与块／片段身份；提交、恢复、完成钩子和会议删除一起校验 generation。每会议最多一个候选任务，原文字仍是已发布版本，候选进度独立显示。
- 完成事务检查会议未删除、来源音频和 generation 未变化，再切换文字／搜索索引并标记摘要来源过期。旧游标及引用需检测版本失效，不能拼接两版文字或跳错时间；旧 worker 晚到结果拒绝提交。
- 重转写的完成事件不得再次触发普通自动摘要付费调用；首次转写保留原策略。取消／失败仅清理候选，不先删旧文字。新摘要基于最新已发布转写，旧摘要保留到生成成功。
- schema 字段和编号在实施时按现有迁移序列落实；迁移前备份，核对旧库与恢复。新数据写入后不宣称旧版本无损兼容；结果一致性不依赖内存状态。

## 真实评测方案

- 每语言组约 2 分钟、至少 10 段，先固定样本 ID／版本、音频 hash、参考稿和筛选规则，再看模型输出。六款模型同组同音频、同业务分块链路、各模式规定参数；不扩展为全数据集跑分。
- 中文／英文候选为 [Google FLEURS](https://huggingface.co/datasets/google/fleurs) 对应验证集，保留 CC-BY-4.0 来源归属。旧中文样本可用于历史回归，但标明曾参与参数调试，不能称全新盲测。
- 混合候选为 [ASCEND](https://github.com/HLTCHKUST/ASCEND) 的真人混合对话，实施前核对音频数据许可与固定清单；代码仓库 MIT 不自动当作音频再分发许可。若获取条件不满足，说明缺口并换有明确许可的真人语料，不能用单语拼接或 TTS 冒充真实句内切换。样本不随应用分发。
- 固定 NFKC／大小写／标点规则：中文按字、英文按词、混合按中文字＋英文词并约定数字切分。保留原输出、标准化结果、编辑次数与分母，以累计错误／累计单位数汇总；不事后加入同音、繁简等价来降低分数。静音无分母，单列幻觉。
- 结果绑定模型 revision、配置、硬件、样本与测试日期，明确为“本应用参考机实测”，不是每位用户电脑的结果。UI 结果更新与实际记录保持一致，未经测试留空并说明。
- 内存以独立转写进程的峰值 RSS 为统一口径，包含模型加载及该语言样本解码，按平台统一单位；每模型／语言使用新进程，避免之前模型的历史峰值污染。UI 仅投影错误率和峰值内存及必要依据；加载／推理耗时可留内部证据用于超时判断，不新增用户可见性能面板。
- 实施阶段在日常环境准备模型；文件基准读取公开语音，不新增虚假用户会议或自动生成纪要，不消耗真实 API Key。

实测后的 worker 预算为加载 90 秒、单块推理 180 秒：large-v3 混合组曾达到约 85 秒，原统一 90 秒余量不足。仅调整有界等待，不改变识别配置、录音线程或自动重试规则；显式短预算保留用于故障测试。具体测量见 [验证记录](verification.md)。

## 相称验证与风险

本轮文档为 S0，只检查 diff、引用和一致性。实施涉及持久化／资源管理为 S3、界面和 Provider 配置为 S2，按相关子系统验证：

- 小型固定文件／替身检查下载、取消、引用保护、配置绑定、旧库以及候选发布事务；替身不能替代真实精度。
- 一次模型×语言真实矩阵记录质量和资源，不重复已通过且未修改的项。资源不足明确停止对应项；依据实测区分加载与推理超时，保持有界，不无限延长等待。
- 日常 `npm run dev` 检查选择、语言、重启和宽／窄布局；旧资料原样保留。自动故障／删除测试用专用临时数据，不能直接重转写或删除用户会议作为测试。
- macOS 本机记录真实结果；Windows 用现有机制定向覆盖路径、文件占用、迁移。没有 Windows 模型实测时如实列出，不能外推 Mac 结论；不默认新增重型 CI、全套麦克风验收或双平台打包。
- 重点风险：大模型 CPU 延迟／内存、混合误判、任务与模型删除竞态、重转写后的引用一致性。录音保存优先；具体问题关闭后停止扩大验证。
