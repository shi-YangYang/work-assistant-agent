# Spec 013 — 桌面转写模型库与语言模式

## 状态

DONE · 2026-09-14。业务实现、返工、真实模型矩阵与日常 GUI 补充检查完成，新的独立验收为 [PASS](acceptance.md)。base 中文基准异常中断如实保留，具体结果与适用边界见 [实测记录](verification.md)。

## 背景与当前行为

Electron 目前只支持固定 revision 的 Whisper small；模型路径、下载清单和恢复任务检查均绑定它。识别语言固定为 `zh`，提示词为“简体中文”，没有独立语言设置。现有任务已经保存模型、revision 和解码配置，可作为扩展基础。

旧 small 在固定清晰中文样本上的业务分块 CER 为 6.52%，不代表日常会议通用准确率；条件和局限见 [Spec 003 实测](../spec-003-local-transcription/verification.md)。

## 目标

让用户依据速度、资源和识别效果选择模型，下载后离线使用；清楚区分默认设置和会议实际使用的配置，保留旧资料与可靠恢复能力。

## 非目标

Web／服务端配置、云 ASR、GPU／Metal 新后端、自动模型路由、训练、翻译、说话人分离、任意模型地址导入，以及面向用户的完整基准测试平台。

## 目标行为与功能需求

### R1 — 模型列表与解释

首版提供以下六款多语言模型：

| 模型 | 参数量 | 选择说明 |
| --- | --- | --- |
| tiny | 39M | 最轻量候选，更看重资源占用时可先比较其语言实测。 |
| base | 74M | 轻量档，提供 small 之外的资源折中。 |
| small | 244M | 初始默认，延续已有使用方式。 |
| medium | 769M | 更大容量候选，通过实测判断增加的等待是否值得。 |
| large-v3-turbo | 809M | large-v3 的加速变体，比较速度与效果的折中。 |
| large-v3 | 1550M | 完整 large-v3；不承诺任何录音都比其他模型准确。 |

参数量来自 [Whisper 官方说明](https://github.com/openai/whisper#available-models-and-languages)，turbo 的取舍见[模型卡](https://huggingface.co/openai/whisper-large-v3-turbo)。官方 GPU 显存及速度不能作为本应用 CPU 的资源要求或速度承诺。

- 不额外列出 `.en`、旧 large-v1／v2 或其他引擎；三语言模式无需各下载一份权重。默认延续 small，识别已有缓存，不自动换成 large。
- 每项展示名称、简短用途、真实下载大小、已占用空间、准备状态、是否默认，以及可展开的识别效果。参数量、文件体积、运行内存分别表达。
- 允许多个模型并存，一次准备一个；支持下载、取消、重试、设为默认和删除下载文件。下载完成不自动切换，只能选择已就绪模型。
- 删除前确认释放空间。当前默认、正在加载／推理及被未完成任务引用的版本禁止删除，并给出具体原因；已完成任务不再占用模型引用。删除模型不删除录音或文字。

### R2 — 中文、英文、中英混合

- 设置页顶部提供当前默认模型和三种语言模式，初始为中文。中文优先简体，英文保留英文，混合保留各自原文，均不翻译。
- 混合模式必须改变真实识别配置；自动检测不等于句内切换准确，需要真实混合语音验证，不能只修改标签。
- 默认设置持久保存，只影响之后首次创建的转写任务。自动转写在录音开始建任务时锁定；未准备模型而仅录音的会议在首次补转写时锁定。
- 运行、暂停和失败任务都沿用自身模型 revision、语言和配置快照；中途修改默认不混用前后片段。旧任务所需模型缺失时，提示下载它原来的版本，不暗中换模型继续。
- 会议文字记录展示本次实际模型／语言，不能把全局新默认冒充已在历史会议生效。

### R3 — 旧会议重新转写

- 为已结束且有可用录音的会议提供“重新转写”，显式选择模型／语言并确认。切换默认不批量重做历史；继续原任务与重转写是不同操作。
- 同一会议有转写或纪要正在运行时禁止重转写。原音频不变；候选文字独立生成，失败／取消保留原文字和纪要，成功后一次发布新文字并更新搜索与时间定位。
- 旧纪要保留并标注“文字记录已更新，纪要待更新”；无效的旧引用不能跳到不相干的新片段。本次重转写不自动发起付费纪要生成，由用户手动重新生成；普通首次转写保留现有自动纪要规则。
- 不新增面向用户的版本历史管理；内部候选发布与故障恢复遵循 [Plan](plan.md)。

### R4 — 有依据的识别效果

- 开发阶段用同一批固定、带参考文字的公开真人语音比较六款模型，结果随应用展示。用户打开设置时不跑推理，不增加日常 CI 大模型基准任务。
- 中文使用 CER（字错率），英文 WER（词错率），混合 MER（中文字／英文词混合错误率）；均越低越好，记录替换／删除／插入和分母。不能把 `100%－错误率` 当通用准确率，也不直接比较不同单位的分数。
- 效果指标只展示错误率与参考机转写进程的峰值内存占用；不增加加载时间、转写耗时、速度或延迟指标。内存说明包含模型及解码开销，不等同于文件大小、整应用内存或每台电脑的保证值。
- 主列表保持简洁，展开“识别效果”按三语言查看上述两项指标及必要测试条件。硬件、模型版本、样本时长／数量和来源用于解释指标，不作为额外评分项；厂商基准和本应用实测分别标注。未测／资源不足明确显示，不填写估计百分比。
- 耗时可记录于内部验证证据，用来判断积压和有界超时，不在产品模型说明中展示。
- 尽量完成全部模型×三语言，small／turbo／large-v3 为重点。未测项列出原因交用户审查，不能算通过；低分也原样展示，不挑样本、改参考稿或无限重跑让大模型胜出。静音幻觉、整句遗漏和混合误译单列。

### R5 — 交互与资源

- 延续 Electron 主题、现有选择框、紧凑间距和响应式宽度：顶部默认设置，下方模型列表，说明／基准折叠展开，避免六张长说明卡占满页面。
- 文案面向用户；版本、hash、解码细节放展开依据。下载空间、内存和等待反馈真实可操作，不新增开发过程提示。
- 沿用 CPU INT8、单个受管推理 worker、有界音频块。新模型试加载不重置正在推理的 worker；大模型较慢时允许文字积压，录音仍继续，不静默改回 small。

## 边界条件与技术约束

受控模型 ID、来源、revision、文件清单与校验；用户不能传任意路径／URL。下载使用现有网络和 TLS，推理只读本地，不隐式补下载。覆盖取消、断网、空间不足、损坏、文件占用、退出恢复及过期任务结果；各模型使用自己的 tokenizer／预处理配置。

## 兼容性要求

保留 macOS／Windows、现有 Electron／Python／SQLite／stdio 和内置核心分发。旧 small 缓存与任务原位兼容；必要 schema 增量迁移并备份，不重建用户库、不自动重转写。用户无需安装 Python 或 CUDA；平台结果分别记录。

## 验收标准

- [x] 确认范围内模型具备真实来源、说明与大小，下载／取消／选择／重启／受限删除符合 R1。
- [x] 三种语言配置真实生效，新任务锁定、旧任务按原配置恢复，不混用默认模型。
- [x] 旧会议重转写的结果替换、失败保留、纪要过期、引用／搜索与恢复闭环通过。
- [x] 效果只展示错误率和参考机峰值内存，条件与来源可追溯，未测项如实列出；不展示耗时或制造通用准确率。
- [x] 原音频、文字、默认 small 行为保留，大模型异常不阻塞录音或丢失已提交片段。
- [x] 日常 Electron 的宽／窄窗口交互检查通过；实施阶段完成新的独立 Agent 验收。
