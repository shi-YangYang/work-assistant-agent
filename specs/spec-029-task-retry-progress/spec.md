# Spec 029 — 工作助手 Agent 节点重试与执行反馈

## 状态

已实施；[独立验收通过](acceptance.md)。

## 背景与目标

工作助手由模型调用、检索、业务操作与结果核对等节点组成。暂时性故障会中断整条任务，当前阶段提示无法说明失败节点和重试进度。

- 每个节点默认有 3 次重试机会，即首次执行加 3 次重试，最多执行 4 次。
- 只恢复失败节点，保留已完成结果；业务写入不重复执行。
- 建立独立、可复用的重试机制，统一节点状态和前端展示。

## 范围

仅覆盖 Web 工作助手 Agent 一次执行中的主模型调用、授权核对、答复核对、只读工具与业务操作工具。节点进度仅在工作助手的对应消息中展示。

Agent 调用“生成报告”工具时，本次仅覆盖发起／入队这个工具节点；后续独立报告 Job 不接入新重试机制。读取已解析文件的 Agent 工具属于范围内，文件上传、解析和语音转写等前置处理不属于。

不调整其他页面、独立后台任务或 Electron，不增加工作流编辑器或管理员重试配置页面，不自动切换模型，不展示模型内部思维链。

## 当前行为

- 模型请求通常限制为 60 秒；harness、worker 和调用预算另有限制。
- 失败后主要依靠用户手动重试整个 Job；已有 checkpoint、业务回执及部分结果恢复机制。
- `Job.feedback` 保存最新阶段，聊天通过 SSE 接收快照；缺少节点列表、失败分类和重试次数。
- 部分工具将业务拒绝转换成文本返回，不能仅根据是否抛异常判断执行成功。

## 目标行为

### 节点与次数

- 一次具体模型请求或工具执行是一个节点。同一工具被有意调用两次属于两个节点；同一节点重试保持输入、模型配置与操作标识不变。
- 自动重试计数独立于 `Job.attempt`（用户手动重试），不混用 worker 的租约 `fence`。
- 默认退避为 1、2、4 秒，增加小幅随机抖动；服务商有效的 `Retry-After` 优先，等待不超过任务剩余期限。
- SDK、HTTP transport、harness 与外层任务不叠加重试。同一次实际调用只能由一个重试执行器负责。
- 节点标识、尝试次数、下次执行时间和结果持久化；刷新页面或 worker 恢复不会重置次数。
- 执行期间持续维护租约；每次尝试前检查权限、输入版本、配置有效性与剩余预算。取消、租约丢失或输入变化立即停止。

### 失败分类

按以下策略执行：

| 情况 | 处理 |
| --- | --- |
| 网络连接、响应超时、连接中断、临时限流、可恢复的服务端错误 | 最多重试 3 次；模型请求已发出时，前一次用量如实记录为未知 |
| 模型输出截断或结构无法解析 | 可重试，丢弃不完整输出；不执行半截工具参数 |
| 数据库死锁、序列化冲突等可恢复事务错误 | 回滚后用新事务重试，先检查已提交回执 |
| 密钥无效、配置错误、余额不足、无权限、输入不合法、业务版本冲突 | 立即给出可操作错误，不重复同一无效请求 |
| 无数据、需要用户补充、授权核对拒绝或事实核对不通过 | 正常业务结果，进入现有澄清／纠正流程，不靠重试碰出通过结果 |
| 未知异常、取消、租约失效、权限撤销 | 停止；未知异常不自动重试 |

HTTP 状态码结合受控错误分类判断，例如临时 429 与额度耗尽不能视为同一种问题。工具的结构化失败和异常使用同一判断入口，不通过自然语言关键词识别错误。

### 副作用与恢复

- 创建、修改、报告入队等写操作使用稳定幂等标识和已有业务回执。结果不确定时先查询回执，已成功则恢复结果，不重新提交。
- 无法证明可安全重复的写操作停止并提示核对，不盲目执行。
- 删除和提交仍需用户确认；重试不能产生额外确认授权。
- 嵌套调用有父子节点关系。子模型失败只消耗该子节点的预算，不让外层工具再乘一次重试次数。
- 业务规划中的下一次模型调用、参数纠正和新业务操作不是故障重试，沿用原有逻辑步骤限制。
- 调整现有耗时／调用预算，使其区分逻辑步骤和实际重试；每次外部调用记录真实用量。任务总期限和安全上限仍有效，提前终止时明确原因，不伪称已重试 3 次。
- 自动重试耗尽后提供“重试此步骤”；服务端从失败位置恢复，保留成功结果。手动重试开启新一轮次数，历史自动重试记录保留。
- “使用当前配置重新处理”保留；配置变化时沿用现有输入与 checkpoint 隔离，并保留业务幂等约束。

### 前端交互

使用现有黑白灰设计和 CSS Modules，将工作助手消息中的 Agent 阶段提示替换为紧凑的可展开进度组件；语音转写、文件解析等前置阶段保留现有提示。

- 默认显示当前节点，如“思考中”“查找工作 · 调用中”“创建工作 · 执行中”“核对结果中”。标签由服务端受控映射，不显示函数名和技术参数。
- 失败等待时显示“模型暂未响应，2 秒后重试 · 1/3”；开始重试显示“思考中 · 正在第 1/3 次重试”。首次调用不写为第 1 次重试。
- 展开后按实际顺序显示已执行节点、当前节点及状态；并行节点可同时运行，不伪造固定流程或百分比。
- 节点状态包含等待、执行中、等待重试、成功、失败、待确认和取消；用户确认卡继续独立展示。
- 成功后折叠为“已完成 N 个步骤”，有重试时保留次数摘要；不持续占据大块聊天区域。任务状态以业务结果为准，报告入队成功不能显示为报告已生成。
- 自动重试期间不弹确认框或错误 toast。耗尽后在失败节点就地展示原因与手动入口，保留前面已完成步骤。
- 浏览器刷新、切换会话、断线重连后显示服务端快照。旧尝试、旧账号和旧租约事件不能覆盖新状态；断网不能伪装成任务失败。
- 窄屏纵向布局，支持键盘展开和减少动态效果；倒计时不逐秒打断屏幕阅读器。

## 技术约束与兼容

- 通用重试核心只依赖操作回调、策略、失败分类、时钟／等待和事件接口，不依赖 FastAPI、数据库、LLM SDK 或 React。
- 由工作助手 Agent 适配层显式启用；共用同一个模型类、HTTP 客户端或 Job 组件不能让其他业务自动加入重试。
- 任务适配层负责租约、持久化、用量和业务回执；模型与工具接入薄适配层，不分别实现重试循环。
- 节点摘要有数量／大小上限和清理策略，不建立无限日志系统；不保存密钥、原始模型响应、工具敏感参数或思维链。
- SSE 沿用账号／公司授权与 `attempt/fence/seq` 排序，扩展结构化节点快照；旧 Job 没有节点数据时兼容原阶段展示。
- 节点结果与恢复状态使用现有事务、checkpoint 和业务记录，避免出现两套相互冲突的成功判断。

## 验收标准

- [x] 首次失败后最多重试 3 次，第 4 次失败停止；中途成功不再继续。
- [x] 工作助手 Agent 的模型、核对与工具节点使用同一重试核心；嵌套节点不存在重试次数相乘。
- [x] 语音转写、文件解析、独立报告任务和其他页面保持原有重试行为与展示。
- [x] 确定性错误、取消及权限变化按规则停止，完整输出和业务校验保持有效。
- [x] 写入成功但回执交付中断时，恢复不重复创建、修改或入队报告任务。
- [x] worker 恢复、并发领取和手动重试不重置错误计数或重复已完成步骤。
- [x] 每次实际模型调用独立记录状态和用量，未知值不伪造；未发出的请求不计为已调用。
- [x] 前端真实展示节点、退避及重试次数；刷新、切换账号、乱序事件和断网恢复正确。
- [x] 浅／深色、电脑／手机下检查执行中、自动重试、成功、失败和待确认状态。
- [x] 使用现有本地模型配置验证完整业务流程；故障重试由可控注入验证，不反复制造真实付费失败。
