# Spec 054：Web 全量测试与先验验证

## 状态

本轮实施和测试已完成；真实任务有效首轮通过率 85%，未达到下方 95% 验收目标。明确代码缺陷已修复并定向回归，限制与未通过项见 [实施报告](implementation.md) 和 [独立验收](acceptance.md)。真实评测没有设置累计调用或费用上限。追加修复与独立复测见 [修复验收](acceptance-repair.md)，不覆盖首轮结果。

## 背景

Web 已包含聊天搭子、工作记录、报告、团队看板、成员管理、记忆和模型配置。流式输出、执行权限、思考强度和跨会话记忆需要与原有流程一起验证。

现有基础包括 Vitest、pytest、Web Playwright、真实模型评测和沙盒测试，可复用。已发现测试资产与现状存在差异：浏览器页面清单缺少记忆页、声纹标题仍为旧名称，部分验收入口固定旧规格的路径与数据约束。静态列出接口或收到成功状态不代表覆盖了行为。

## 目标

- 覆盖所有现有 Web 入口、用户角色、关键状态、公开 API、Agent 工具和后台流程，建立可追溯的覆盖清单。
- 验证真实用户能完成任务：页面操作、服务端保存、Agent 回复、工作记录和报告相互一致。
- 先写预期和禁止发生的结果，再执行测试；既检查历史回归，也主动寻找新缺陷。
- 在隔离环境开展破坏性测试，验证失败可理解、数据不串号、操作不重复、恢复有边界。
- 分开报告工程正确性、UI/UX、模型任务质量和外部依赖可用性，保留首轮失败证据。

## 非目标

- 不新增产品功能，不重新设计全站，不引入 RAG、任务层级或新的权限模式。
- 不验收 Electron 本地录音、打包和安装；其依赖的 Web 授权页与公司 API 仍在范围内。
- 不在生产服务器、用户日常数据库、个人聊天或原始文件上做破坏性测试。
- 不承诺穷举任意自然语言及所有组合，不把模型偶尔答错转化为无限调参。
- 不把整套真实模型、压力和沙盒测试加入每次代码 CI。

## 当前行为

- 管理员和员工共享部分页面，但报告、团队、成员和设置的可见范围不同；后端执行数据权限。
- 消息经 HTTP 接收、worker 执行、SSE 推送；模型正文流与前端打字呈现是不同环节。
- Agent 支持问答、联网、附件、个人成果、公司业务、记忆及可选沙盒；是否写入业务由用户意图与执行权限决定。
- 现有测试分布在 `tests/web/`、`tests/server/`、`tests/e2e/web/`、`tests/sandbox/`；验收编排在 `scripts/company/web-acceptance/`。

## 目标行为

每个范围项都有稳定 ID、角色、前置数据、动作、预期、禁止结果、检查方式和证据。实际结果标为 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`；确实不适用的组合记录 `N/A` 和原因。环境不可用、测试跳过或未做语义检查不能算通过。

详细范围和先验样本见 [测试矩阵](test-matrix.md)。范围以实施起点的路由、OpenAPI、工具注册表、后台任务和现有产品规则共同确定，不能只从旧测试反推。

## 功能需求

### 1. 覆盖清单与基线

- 冻结代码 SHA、未提交差异摘要、页面／接口／工具清单、用例版本、时区、浏览器与运行配置；不保存密钥。
- 页面包括登录、辅助授权入口、所有角色可见路由、详情、历史、标签页、弹窗和关键非默认状态。
- 接口以运行应用实际注册的 `HTTP method + path` 为准；动态 action、SSE、上传下载和后台触发另列分支。
- 工具以各角色实际可用注册表为准；记录正常结果、参数错误、权限拒绝、失败与重试适用项。
- 首轮保留既存失败，区分实现错误、过期测试、依赖故障和样本／评测器错误；不能先改代码再声称无既存问题。

### 2. UI/UX 与可访问性

- 管理员、员工分别检查全部可达页面；匿名访问检查登录和授权边界。
- 所有页面和主要详情至少覆盖桌面／手机、浅色／深色；平板、低高度、长标题、大数据、弹窗和错误态按布局风险补充。
- 截图之外实际操作：点击命中、Tab／Enter／Escape、焦点回归、触屏入口、滚动、返回和草稿恢复。
- 检查对齐、内外间距、内容宽度、文字截断、双重边框、按钮层级、分页、空白、错误重复、加载抖动和浮层遮挡。
- 检查流式生成、任务步骤、录音、附件、主题切换与 Noria 宠物的连续过程，不能只用最终截图判断动效。
- 以当前明确产品要求和 [设计基准](../../docs/design/README.md) 为准。设计文档与后续明确要求冲突时记录差异，不能让旧截图覆盖新行为。

### 3. 功能、API 与数据一致性

- 覆盖正常、空值、边界、错误输入、重复点击、并发冲突、刷新、前进后退、失效身份和删除后的访问。
- 每个 API 有合法结果断言；需要权限的接口增加匿名、越权与跨公司检查；写入接口增加失败无副作用、幂等／版本冲突等适用断言。
- 不能只断言 2xx：检查响应契约、实际记录、历史版本、任务数量、文件和副作用；拒绝访问不泄漏对象存在性或敏感数据。
- 检查会话有效期与续期、账号切换、CSRF、钉钉回调、成员删除、凭据脱敏、分页稳定性和日期／时区边界。
- 迁移在空库和升级副本验证；备份恢复使用合成数据，核对记录、版本、媒体与来源的一致性。

### 4. Agent 全流程

- 受控模型用于穷举工具契约、状态转换、故障时机和权限；真实模型用于理解意图、选工具、多轮衔接和回答质量。两类结果单独统计。
- 真实评测至少 60 个不同用户任务，其中至少 40 个为 3～6 轮连续流程，管理员和员工各至少 20 个；至少 12 个通过真实浏览器输入完成，其余经过真实 HTTP、队列和 worker。数量是最低覆盖要求，不是执行上限；发现明确覆盖缺口时补充场景。
- 首次冻结时保留至少 20% 新样本作为保留集，不用于修改提示词和修复拟合。历史已公开样本只能算回归集。
- 覆盖两种人设、三档执行权限、模型配置的可选思考强度、流式开关；不为数量机械展开全部组合。
- 检查普通问答不强制保存工作，不无故进入等待补充；必要提问应具体且可继续，执行权限不得放宽身份权限。
- 多轮流程检查对象、条目 ID、版本、用户纠正、引用工作、保存意图、材料授权和上下文切换，不能仅检查最终回复语气。
- 生成文件实际打开或解析，必要时渲染；核对数值、文本、中文字体、页数、链接和后续修改，不以“下载成功”代替内容正确。
- 记忆检查关闭、编辑、忘记、跨会话使用、人工内容保护和账号隔离；上下文检查用量、容量、压缩及压缩后继续任务。
- 真实联网验证有来源、有日期且回应当前问题；服务商拒绝、超时和限流记录原始类别，不冒充成功，也不统一归因于系统。
- 仅采集用户可见进度、必要工具参数／回执、可见答案与状态，不要求或保留模型隐藏思维链。

### 5. 先验测试

先验指从用户目标、契约和业务不变量推导测试，先冻结预期再观察输出；不是先验收现有实现。

- 设计正例、反例、边界例和组合例；每例说明允许的多种合理结果，不强制固定工具次序或一字不差的回复。
- 使用独立真值：合成表格的已知合计、固定时间的报告范围、预置权限、精确字段差异、已知文件内容。
- 使用变形测试：同义改写不改变授权；顺序调整不改变总和；重复提交不新增记录；切换人设不改变事实；压缩前后不丢失明确限制。
- 优先验证系统不变量：零越权、零虚报写入、零重复副作用、取消后不发布迟到成果、旧响应不污染新身份、未提供字段不被覆盖。
- 不能在看到失败后悄悄改预期；样本有误时保留首轮结果，记录理由并发布新用例版本。

### 6. 破坏性测试与受控负载

- 覆盖断网／恢复、请求丢失、SSE 截断／乱序／重复、重复提交／确认、并发编辑、任务中断和迟到结果。
- 对测试进程注入 API／worker／数据库／沙盒重启、租约失效、限流、超时、磁盘／内存／执行配额不足；验证恢复和资源回收。
- 覆盖恶意 Markdown／HTML、文件名路径穿越、伪造文件类型、损坏文档、受控压缩炸弹、提示注入、伪造对象／来源／成果 ID、SSRF 边界。
- 沙盒验证禁止宿主文件／凭据／网络访问，用户和会话隔离；缺少 gVisor 不降低隔离改在宿主运行。
- 普通 HTTP 使用受控模型，从 1、5、10 个并发用户递增，每档最多 60 秒；沙盒测试“配置并发数 + 1”的排队、取消和公平性。到资源边界及时停止，不以压垮宿主为目标。
- 收集 p50／p95、错误率、请求次数、队列等待、CPU／内存和清理结果；不把小样本结果宣称为生产容量承诺。

### 7. 结果与缺陷处理

- 分别输出页面覆盖、接口覆盖、工具覆盖、先验不变量、真实任务首次完成率和故障恢复结果。调用过、列入计划、存在测试文件均不算已验收。
- 真实任务分别报告首轮成功、用户澄清后完成、自动重试后完成、人工重试后完成、失败和阻塞；分母包含计划样本及未运行数量。
- 每个缺陷记录严重性、复现步骤、期望／实际、责任层、证据和影响范围。修复后只复跑失败用例及明确受影响范围，保留首次结果。
- UI/UX 主观问题附截图与具体问题；提出大范围交互变更时先交用户决策。
- 发现明确代码、样式或测试资产缺陷后直接修复并回归；涉及产品规则或明显改版再讨论。不能删断言、吞异常、增加无限重试或写关键词特判来伪造通过。

## 边界条件

- 默认使用专用 `paa_company_test` 数据库下本次拥有的 schema、测试媒体目录及独立 Compose 项目。删除与停止前同时核对运行标记和实际资源归属。
- 使用合成员工、管理员、同公司另一员工、另一公司成员和被删除账号。测试消息、文件和记忆不复制真实业务内容。
- 真实模型配置仅从指定本地配置只读获取，密钥保留在权限受限的运行文件或内存中，不进入截图、日志、Git 或普通报告。
- 对外联网仅做任务需要的正常查询；破坏性流量只发往受控目标，不攻击模型服务或第三方网站，不发送真实邮件／通知。
- 钉钉真实回调、物理麦克风、特定手机与缺失模型能力如不可用，分别标记受控验证与真实未执行，不能用 Mock 代替真实通过。
- 模型、评测器、ASR 和重试不设总费用或累计调用次数上限。记录实际调用和 Token 用量；有可靠价格时记录费用，无价格时标明未知，不因此阻塞测试。

## 技术约束

- 复用已有测试工具与目录，不新建另一套验收框架。确需扩展旧路径参数时保留隔离检查及旧入口兼容。
- 决策和本文按 S0；实施涉及全量测试与受控破坏，按 S3 组织隔离和证据。只有变更相关内容才追加复测。
- 固定输入的自动测试不依赖真实密钥、真人录音或公开网络；真实依赖测试显式启用且单独汇总。
- 取消评测总量限制不改变产品重试规则、单请求超时、沙盒隔离或资源保护。按覆盖清单、缺陷回归与验收标准完成后停止，不重复通过项、不无限重跑失败项。

## 兼容性要求

- 不改变 Web、公司 API、沙盒、共享契约的现有分层，不迁移业务目录。
- 保留原测试入口及历史证据；本次输出独立目录，不能覆盖旧评测首轮结果。
- 仅经确认的修复才修改业务代码；接口／迁移变更另行说明兼容与回滚方式。

## 验收标准

- [ ] 全部页面／入口、API、Agent 工具及后台流程均有清单、责任用例和结果，无未解释的缺口。
- [ ] 所有角色可达页面完成规定截图与操作；关键动效有连续证据，不能只检查页面可打开。
- [ ] 受控检查覆盖全部适用权限、版本、幂等与错误分支；“被调用”与“断言通过”分开统计。
- [ ] 完成冻结的真实 Agent 样本及保留集，逐项核对答案与实际结果，披露首次通过率及未执行项。
- [ ] 无越权、数据损坏、重复业务副作用或虚报成功；此类缺陷不能被总体成功率抵消。
- [ ] 核心用户流程均有成功证据；真实任务首次完成率目标 ≥95%，所有失败有分类。受限／缺信息用例按预设正确拒绝／提问判定，不要求强行执行。
- [ ] 破坏性测试有注入点、受影响资源、恢复结果和清理证据；无遗留进程、容器、测试身份或私有文件。
- [ ] 既存失败、过期测试、环境问题和新增缺陷分别说明。任何 P0／P1 未解决，或必需项 BLOCKED／NOT_RUN，不能给无条件 PASS。
- [ ] 最终报告覆盖修复后版本；已通过且不受修改影响的证据可沿用，但保留其 SHA 和影响分析。
- [ ] 用户确认实施后，由实施 Agent 执行，新的独立 Agent 按冻结预期验收。
