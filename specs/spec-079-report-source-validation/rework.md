# 创建纠错的连续参数失败

以下两项已完成返工并由新的独立 Agent 验收 PASS，历史复现保留，详见 [验收记录](acceptance.md)。

独立验收发现：同一创建请求第一次参数错误返回事项 A，第二次不同参数错误显式携带 A，服务端仍登记 B；最终授权并成功保存 A 后，B 残留，最终结果仍为部分完成。见 [验收记录](acceptance.md) 和 `artifacts/report-source-validation/phase-b/acceptance-multiple-invalid-probe.py`。

修复已有事项的连续失败关联，使同一请求纠错成功后能以真实保存回执收束。工具传入的事项标识仍需服务端校验，不能成为授权，不能按同名、步骤号或模型自报完成清理失败。不同来源、对象、副本、共享附件和独立事项继续隔离；失败原始诊断保留，不增加模型节点或重试次数。

由新的 `high` 实施 Agent 处理上述边界，再由新的 `high` 验收 Agent 独立验收。验证仅限连续无效参数重放及受修改影响的身份隔离断言；已通过的报告检查和真实模型样本不重跑。

## 授权期间的并发追加

连续失败关联补修后，独立验收复现：授权正在核对 A 时，另一并行工具向 A 追加不同无效提案；授权仅看见旧尝试链，最终绑定却清除了新失败。见 `artifacts/report-source-validation/phase-b/acceptance-concurrent-invalid-probe.py`。

在已有持锁绑定／保存边界核对授权实际看到的尝试链快照。快照变化时，旧授权不得完成未核对的新尝试；同样保护绑定后、成功回执前的追加窗口。不得增加独立模型回合、扩大重试或按标题清理失败。只验证这两个并发窗口及直接受影响的正常恢复路径，已通过的来源和报告验证不重跑。
