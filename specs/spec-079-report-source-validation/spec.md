# 周报来源契约、程序校验与真实模型验收

状态：阶段 A／B 系统实现独立验收 PASS，历史失败、模型限制及未覆盖范围见 [验收记录](acceptance.md)。阶段 B 已修复创建纠错后的失败状态残留，并将周期内对应工作的完整内容交给 AI 归纳周报，取消必须有独立进展的门槛及报告二次模型事实审查。全产品扩展验收尚未完成，本结论仅覆盖已实施范围。

## 阶段 B：创建结果收束与完整工作来源

- 首次工具参数错误仍如实记录；同一创建请求纠正并实际保存成功后，最终任务状态、操作卡和节点展示应一致，不再把已恢复的尝试当作未完成用户需求。不重复创建，不删除诊断历史。
- 用服务端关联的操作身份和真实授权／保存回执关联纠错；不能仅凭同名、同一步骤序号或后续任意创建成功就清除另一项失败。多个工作、不同副本、不同来源及真正未完成请求保持独立。优先复用现有授权回合，不增加模型调用或恢复次数。
- 周报沿用公司时区和汇报周期，收集周期内创建或发生正文、清单、属性、进展变化的本人未删除工作。取消按 `_changeKind=content` 排除正文和清单的门槛，也不要求先新增独立进展记录；已有记录的删除、纠正和来源权限继续生效。
- 将对应工作的标题、正文（含清单文字及勾选状态）、工作状态、周期内进展、阻碍和下一步一起提供给模型，附带稳定工作身份、不可变来源身份及时间关系。正文不再整体标为只能用于计划；模型按实际内容归纳，不把整项工作存在或某项勾选等同于整项完成。
- 采用 AI 自由归纳及现有四栏输出。程序检查来源归属、周期、快照、权限、结构、并发、租约与幂等；不声称能验证自由文本每句话，不增加关键词判定或第二个模型审查。
- 一起移除报告生成和助手改写的二次事实审核／判词纠错，更新旧草稿恢复和相关工具／prompt，不改变意图授权及提交确认边界。
- 本次验证限定创建纠错及周报链路：确定性检查必须包含多项请求不可误合并、仅正文／清单可生成、来源历史与写入保护；实际模型采用隔离合成数据保留低／高档真实回复、调用顺序和落库证据。已有真实的错误参数作为程序回归输入，不能伪称模型再次触发；纯模型失败留档，不加补丁或重跑到绿。
- 不修改用户日常工作、已有报告或旧会话的持久化结果；旧失败会话可只读复核，修复后的新流程用隔离账号验证。

## 阶段 A：工作以当前内容、进展与修改记录呈现

### 已确定的行为

- 工作页面、历史入口、工作引用卡及正常助手答复不再将每次变更呈现为“第几版”。默认展示当前内容；只有首次创建、尚无后续修改时隐藏整块修改记录，有后续修改时再展示创建、状态变化、正文修改、勾选、材料和进展等历史。历史入口称“查看当时内容”，返回入口称“查看当前内容”或“返回当前工作”。
- 保留内部工作、进展和材料修订标识、历史快照及旧历史链接兼容，不引入第二套对外版本号，不迁移或清理历史数据。时间可用于展示，内部身份仍用稳定 ID 和修订标识，不能只按标题或时间猜测。
- 工具 Schema、说明、回执、工作引用上下文和有效 prompt 一起调整。`revision`、`expected_revision`、`workRevision` 等兼容字段仍用于读取、来源绑定与写入防冲突，明确其内部用途；不得删除、猜测或自动递增请求中的标识，必须使用真实读取结果。用户无须提供、选择或确认版本号。
- 工具结果区分当前工作、不可变历史来源及具体操作效果。保存回执说明实际变更，不把修订增长解释成新建一项工作、重复生成或工作已完成。不能为了不提版本而隐藏真实冲突、来源失效或未完成操作。
- 复用并精简现有工作说明，不叠加多处同义提示；保留其他实体的合法版本语义，如文档、附件解析和私人成果版本，本阶段不作全局替换。
- 编辑已有进展时，规范化后的文字、材料及随附工作属性均无实际变化，则复用原记录与修订，不增加工作／进展修订、不刷新业务修改时间。检查仍在身份、权限、预期修订与租约校验之后，不能成为跳过保护的捷径。
- 新建进展即使文字与旧进展相同，仍可能是新的真实事件，不按文字去重；真实编辑、状态变化、删除和材料变化继续保留可追溯快照。重放同一幂等请求继续复用原结果。
- 历史摘要按可见、相邻快照解释变化，不跨不可见或缺失历史推断；不重复展开当前全文。不以删除旧快照、减少安全校验或合并多个独立操作来压低修订数量。

### 验收边界

本阶段覆盖工作详情／修改记录／历史内容、相关引用卡、工具输入输出、工作 prompt 与无变化进展编辑。其余报告生成算法、报告审查、意图授权模型和全产品改造尚未完成，不以本阶段通过宣称整个 Spec 完成。

- [x] 工作正常页面与历史入口不显示“第几版”，仍可通过旧链接访问准确的历史内容。
- [x] 历史摘要准确描述变化，当前正文不重复展开；不能跨权限缺口推断历史。
- [x] 工作工具和有效 prompt 清楚说明内部修订用途，真实读写和来源回执保护保留。
- [x] 无变化编辑不新增修订；同文新进展、真实变化、过期标识和越权请求仍按既有规则处理。
- [x] 定向真实 low/high 助手流程验证工作读取、修改、正常答复与持久化；保留实际回复、调用顺序、耗时及失败，不使用替身冒充真实模型，不为纯模型措辞错误加补丁或重跑。low 措辞失败已记录，不表示正常答复措辞全部通过。
- [x] 新独立验收 Agent 给出本阶段 PASS／FAIL，与整个 Spec 的待完成项分开报告。

## 背景

生产周报生成被“报告内容与来源不一致”阻断。只读核查发现，同一工作在周期内先处于进行中、后改为完成，两份快照均在任务来源中；二次模型审查却称不存在完成记录。按实际函数重建的输入及模型绑定摘要与任务保存的输入摘要一致，支持该来源判断。生成结果还将同一工作改名前后的名称分别列为工作。

报告生成输入只传来源内容，丢失工作 ID、来源 ID、修订号和时间；旧状态与新状态之间的关系未由程序表达。这是确定的输入契约缺陷。审查模型的否定结论与实际输入冲突也是事实，但不能据此认定缺少身份字段是此次错误的唯一原因。

既有测试主要验证周期、删除后重新生成、权限和持久化，模型替身默认返回有效审查结果；此前真实模型验收未覆盖这条完整周报路径。模块测试通过不能代表真实生成及最终内容正确。

生产身份、原始业务正文和访问凭据不写入版本库；回归材料用合成数据复现相同关系。

## 目标

- 删除报告生成和助手改写报告中的第二次模型事实审查，以及依赖其判词的自动纠错、再次审查回合。
- 程序负责来源身份、版本、周期、结构化状态、访问权限、结果结构和写入条件；不再让模型猜测这些关系。
- 核查真实用户入口至持久化、页面展示和任务恢复的完整链路，使用真实配置的模型验证涉及模型的验收场景。
- 保留真实失败和验证限制；不通过新增提示补丁、审核节点、提高预算或反复采样消除已确认的纯模型错误。

## 非目标

- 不修改线上用户数据，不部署，不提交或推送代码。
- 不调整模型或搜索服务，不新增意图分类、充分性审核、规划、润色等独立模型回合。
- 不放松现有意图授权、角色与租户权限、来源访问、幂等、租约和并发版本保护。
- 不将无调用者的评测辅助函数误报为生产必经审查；不按 `review` 或 `_verification` 关键词批量删除逻辑。
- 不把来源 ID 合法等同于自由生成的每句话都真实，不用关键词匹配冒充语义事实验证。

## 当前行为

1. 报告页、待办或调度创建任务，固定来源快照，模型生成四个字符串栏目。
2. `agent/reports.py` 调用 `verify_report` 再次让模型判断事实。存在写作指令时，还可能纠错后再审查；审查失败可阻断保存，重试可能只重复审查同一草稿。
3. 助手修改报告在 `agent/actions/operations.py` 也先调用 `verify_report`，随后才执行现有意图授权和业务操作。
4. 保存层已有来源访问、版本、租约和候选保护，但这些规则不能修复生成输入中的身份与历史状态歧义。
5. `draft_report` 等备用写入函数、评测辅助审查器需按实际可达性分类；仅有函数定义不证明线上会执行。

工作记录接口可同时传入 `status`，但它修改的是整项工作的状态，并写入对应 `WorkRevision`；`WorkUpdate` 本身没有独立状态字段。报告来源投影保留该快照的 `status`，记录正文使用 `_updateText`。本次完成状态已进入输入，缺陷不能表述为“工作记录状态漏传”；缺失的是事实条目之间的工作身份、修订和时间关系。

已核查的额外模型调用与程序检查：

| 入口 | 当前机制 | 调用条件与边界 |
| --- | --- | --- |
| 生成／助手改写报告 | `verify_report` 模型事实复核 | 实际生产路径；生成还可能纠错后再复核，本次删除对象 |
| 助手创建／修改／删除工作，生成／编辑／提交／删除报告，工作／团队跟进建议 | `authorize_intent` 独立模型核对用户意图 | 有效新操作进入授权；复用回执或前置拒绝可跳过，不能称为纯程序检查 |
| 助手修改已有工作 | `work_change_plan` 模型提取允许修改的字段，再进入意图授权 | 未命中有效缓存时提取；字段范围冲突可再提取一次。模型范围判断与授权可能重叠，列入调用清单分析，权限保护不能随之删除 |
| 普通答复收尾 | `delivery.assess` 程序核对协议和回执 | 不调用模型判官；特定缺失操作、正文或协议错误可触发模型补答／恢复，属于有条件的额外回合 |
| 通用答复事实／数值审查辅助函数 | `completion/review/reply_review.py` | 当前生产收尾无调用；导入结果类型不等于执行模型审查 |

以上是当前源码调用链核查，不代表所有分支已用真实模型执行，也不把额外调用的存在直接判定为必须删除的缺陷。检验必要性时区分硬权限、用户意图解释、事实判断和恢复流程。

## 目标行为

入口 → 程序构建带身份和时间关系的来源包 → 现有模型生成或改写 → 程序校验结果契约 → 事务内重查权限、来源、版本与租约 → 保存正文或候选 → 展示真实回执。

报告事实复核不再调用模型。助手既有意图授权模型用途不同，本次不因删除事实审查而一并移除；服务器权限检查始终独立生效。

### 1. 来源契约

- 每项事实绑定稳定工作 ID、不可变来源 ID、修订号、事实时间及来源类型；标题只作展示，不能用于合并或判定身份。
- 保留周期内进展事件、属性变化、完整工作正文与清单状态、材料关联和用户手填内容，不以是否独立记录进展筛掉整项工作。输入内容本身不等于本期全部已完成。
- 由程序按现有汇报周期和公司时区确定来源范围，表达同一工作的状态演变及适用状态；周期后的修改不能倒灌为本期事实。
- 同一工作改名不重复计为两项；不同 ID 即使同名也不合并。不能只保留最新快照而丢失本期进展、阻碍及依赖。
- 结构化工作状态与局部成果分开：进行中工作可以有已完成的局部进展；完成后重新打开也不能抹掉真实历史成果。自由文本含“完成”不触发整项工作完成。
- 来源包完整性、容量限制与失效原因显式表达，不静默截断后宣称来源齐全。

### 2. 程序校验及正文边界

确定由程序校验：字段类型与长度、来源存在性与身份、引用版本、时间范围、结构化状态的来源、权限、目标版本、写入租约、幂等及结果回执。来源关系由程序从真实记录构建，不由模型猜测。

正文采用 AI 自由归纳，保留 completed、ongoing、blockers、next 四个字符串栏目。完整工作内容交给现有模型；程序不尝试证明任意改写句子都无编造，不增加语义审核或关键词硬拦截。真实回复与来源的对应情况由实际验收如实记录，不能称为完整语义保证。

保留用户手填报告的能力，并区分用户明确补充的内容与系统从工作记录生成的内容；助手只改用户要求的栏目，不得冒充用户补充事实。

### 3. 保存、失败与恢复

- 生成、重新生成、助手改写、待办准备和调度使用同一程序校验边界；核查备用写入路径，避免绕过。
- 不新增模型审查或纠错循环。程序拒绝时提供可定位的错误类别和简短用户提示，不能把内部字段、协议或模型判词直接倾倒到页面。
- 不覆盖已手改或已提交版本；现有候选机制、主动采用、提交授权与原文保留规则继续生效。
- 旧 `reportDraft` 的 review、correcting、corrected_review、ready、rejected 状态必须有明确兼容策略。旧审查通过或失败不作为新程序契约的证据，也不直接放行旧草稿。
- 已有 `reportSaved` 回执继续幂等复用；删除、权限变化、来源失效、租约丢失或目标并发变化后不得迟到写入。
- 用户重试能够进入新流程；不能继续重放已删除的审查节点，不能无限重生成，也不能把 HTTP 202 当作保存成功。

## 全量检查范围

必须覆盖周报全链路：报告页生成／重新生成、助手生成／改写、汇报待办、定时生成、手动编辑、候选采用、提交、删除后主动重建、失败重试与页面刷新。并核查所有实际可达的报告读写入口、工具描述、结果契约及任务状态。

“全量”是否进一步包含公司 Web 全部 AI 能力，待确认。扩展范围包含聊天与澄清、搜索／网页／文档读取、工作创建与更新、附件／成果导出、任务等待与续接；每项均要有真实用户流程及权限边界验收，不能用周报检查替代。这一扩展会增加真实模型调用和执行时间，不涉及桌面录音、物理设备或线上写入。

无论选择哪一范围，都扫描相应范围的生产模型调用链，区分事实审查、意图授权、结构化解析和仅供评测的代码，记录调用入口及去留依据；发现范围外问题先记录，不顺手重构。

## 边界条件与技术约束

- 无来源、角色无权或对象不可用时，预期是零次模型调用；不能为满足“真实模型”要求绕过前置拒绝。
- 程序能判定的错误使用确定性规则；不加入员工、标题、固定文件数量或案例编号特判。
- 冻结实际模型用途、参数和输入；不改变产品 low/high 选择，不提升推理或输出预算掩盖失败。
- 无法证明因果时保留待归因结论；充分、正确、清晰的输入下发生的纯模型错误保留失败记录，不补提示、不新增审核、不反复重跑。
- 验收不使用另一个模型作为最终真伪裁判；程序断言、数据库状态与人工阅读真实回复共同构成证据。

## 兼容性要求

- 保留周报四栏的公开读写与展示能力；新增内部来源契约不直接泄露到用户正文，来源入口继续可用。
- 现有正文、手填事实和已提交报告不得被后台重写或清理；不恢复已移除的日报。
- 模型输入／草稿协议升级与用户可见报告版本区分；恢复不能制造重复版本或重复业务操作。
- 不引入严格摘录模板或新的公开报告格式；内部来源契约调整保持四栏读写兼容。

## 验收标准

- [ ] 范围内所有实际入口、模型调用、输入输出与写入边界有清单；未覆盖项明确列出。
- [ ] 两个报告入口均无二次模型事实审查、判词纠错和复核回合；意图授权与服务器权限保护未被删除。
- [ ] 同一周期“进行中 → 完成”、完成后重新打开、改名及同名不同 ID 均按结构化身份与时间正确处理。
- [ ] 本期有效进展、阻碍、否定和条件保留；计划和周期外事实不冒充本期成果。正文保证的结论不超过已选方案的能力。
- [ ] 所有报告写入路径执行确定性校验；缺失／伪造／错绑来源、越权、失效版本及迟到任务不能写入。
