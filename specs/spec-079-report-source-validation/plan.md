## 实施顺序与数据流

1. **建立入口清单**：从报告页／助手／待办／调度追到任务、模型、操作与持久化。标注每个模型调用的用途、次数及可恢复状态；区分生产可达路径、备用代码和评测辅助函数。扩展范围确认后同步补全其他 AI 能力清单。
2. **冻结回归输入与预期**：以合成工作复现同周状态演变、改名、同名异 ID、多个进展与周期边界。预期由结构化源记录和产品规则写定，不使用模型的判词作为答案。
3. **明确来源与结果契约**：程序建立来源关系及周期状态；模型接收稳定身份、不可变版本和完整工作内容并自由归纳。保持四栏接口，保存前执行共享程序校验；不增加摘录模板或正文语义判官。
4. **删除模型事实审查**：移除生成、改写两条路径中的 `verify_report` 调用、专用模型配置使用、判词纠错及审查状态流转。保留其他用途的共享配置与意图授权，不按名称批量删除。
5. **接通写入与恢复**：保存前、事务内和回执恢复时保持权限／来源／版本／租约检查。核查备用写入入口；旧草稿使用契约版本和输入摘要判断是否可由程序验证或需要重新生成，不信任旧审查结论。保存过的任务不重复生成或落盘。
6. **验收真实用户流程**：完成相关确定性回归后，按冻结矩阵运行真实服务，检查最终回复、页面、报告内容、来源及落库状态。独立验收复核证据，不无理由重复已通过调用。遇到系统缺陷修复对应边界，遇到确认的纯模型问题保留失败。

目标流转：入口请求 → 权限与周期 → 不可变来源包 → 现有模型 → 程序契约校验 → 事务重查 → 正文／候选与回执。语义生成不再依赖额外审查回合。

## 真实模型验证协议

- **隔离环境**：本地独立账号／数据库与合成材料，不向生产陈列测试数据，不使用真实员工的私有正文作提交到版本库的样本。真实调用使用已有配置的服务与安全凭据，不在日志输出密钥。
- **实际配置**：记录用途、真实模型名称、low/high 等实际推理参数和预算。报告专用路由按其现有配置运行；支持用户 low/high 选择的助手路径分别覆盖。模型不支持的档位记为不适用，不能替换模型伪造覆盖。
- **同条件对照**：对受影响的正常生成、事故状态演变和助手改写路径，使用相同数据、请求、模型参数及隔离库起点作改动前后对照。每个指定条件先运行一次；仅确有性能比较需求才预先声明追加采样数量，不事后挑选更快结果。
- **真实全流程**：从产品入口创建任务，经实际 API／worker／模型，到最终回复、报告正文／候选、刷新后的内容与来源。直接调用一个函数、HTTP 202、模型传输成功或工具成功均不能代替完整流程成功。
- **完整记录**：记录代码版本、样本与配置摘要、请求／响应原文、工具顺序、模型调用用途／次数／耗时、总耗时、提示及 Schema 大小、实际状态与持久化结果。未产生工具调用的报告路径明确记为无工具调用；敏感内容不提交。
- **程序与人工判断**：程序比对稳定 ID、状态、版本、引用、权限和最终写入；人工逐项阅读真实生成文本，检查主体、否定、条件、阻碍和计划。不得新增模型判官给出最终事实结论。
- **分支覆盖诚实**：真实模型未触发无效输出或冲突时，该异常分支仍属未实测；用确定性故障注入补测程序保护并单独标注，不把构造回复称为真实模型回复。
- **零调用路径**：无权限、无有效来源、日报旧入口等前置拒绝验证零次调用；无需额外触发模型。手填、采用和提交等无模型步骤仍用真实应用验证状态。
- **终止规则**：模型已收到正确完整的输入仍出错，保留原始失败；不临时补提示或重跑到绿。只有代码改动、具体归因需要或传输结果不明确才能定向重测；不重新启动既有 Spec076 整个矩阵。

## 周报必要场景组

以下为覆盖组，不等于已执行次数；实施前按确认范围拆成固定场景并标注入口、模型配置、预期状态和调用上界。相同场景可覆盖多个边界，但不能省略实际入口验证。

| 场景组 | 必须检查的结果 |
| --- | --- |
| 同周进行中转完成 | 生成时知道为同一工作，适用状态准确；不因旧记录错误拒绝，保存及刷新一致 |
| 完成后重新打开、进行中有局部成果 | 整项状态与局部进展分别表达，历史成果不丢失，不宣称整项已完成 |
| 改名与同名异 ID | 同 ID 改名不重复，不同 ID 不合并或张冠李戴 |
| 多条进展、纠正与删除 | 有效进展保留；废弃内容不沿旧缓存进入结果 |
| 跨周、时区与周期后修改 | 使用目标周期事实，不将当前状态覆盖历史周期，不混用边界时刻 |
| 只有工作正文／清单／计划 | 允许进入生成，完整传入工作内容和清单状态；检查真实回复是否准确归纳，无对应工作时仍为零模型调用 |
| 材料、否定、条件、阻碍与下一步 | 不丢关键前提，不把计划变成果或材料变授权；实际自由文本失败单独归因 |
| 页面、助手、待办与定时入口 | 各自走到相同校验和真实持久化；提示及回执与结果一致 |
| 助手改写与用户手填 | 保留手填来源语义；改写不扩大授权，不用旧报告证明矛盾事实 |
| 生成期间手改／提交 | 用户正文不被覆盖，按现有规则形成候选；采用与提交只发生一次 |
| 删除后重建、重复请求 | 新报告身份正确，旧任务及回执不回写，幂等保护有效 |
| 旧审查草稿重试 | review／correcting／corrected_review／ready／rejected 不再调用审查，旧结果不被无条件放行 |
| 权限／来源／租约变化 | 读取和落盘均保护，迟到结果无权写入，不泄漏私有来源 |
| 格式错误、假来源及中断 | 程序明确拒绝并保留原文；真实失败与定向构造异常分别标注 |

公司 Web 全范围若获选择，还须逐项建立聊天澄清、搜索读取、文档版本、工作写入、文件导出及等待续接的真实入口矩阵；不能仅扩大关键字搜索后声称完成。

## 兼容与风险

- 内部契约版本变化不能等同于用户报告新增版本。旧草稿不能因取消审查直接保存，也不能陷入无限生成；旧保存回执继续保护已完成操作。
- 程序读取最新适用状态不能抹掉历史进展；自由文字中的局部成果、否定与条件不交给不可靠关键词规则裁决。
- 保留 AI 自由归纳，程序校验来源和保存条件，不能证明自由文字的全部语义；真实模型错误如实记录。
- 删除事实复核不删除意图授权模型或服务器权限检查；真实调用数量报告须分别统计，不宣称助手整条路径只剩一次调用。
- 对线上原故障的处理，本次只提供代码及隔离复现证据；用户授权部署之后才能验证线上恢复，不提前宣称生产问题已经消失。

## 验证级别与停止条件

规格决策及文档整理按 S0，检查 diff、需求及引用，不为文档运行模型、测试、lint 或 build。阶段 A 已按工作子系统的 S3 范围完成必要检查及定向真实 low/high 流程，具体结果与限制见 [实施报告](implementation.md) 和 [验收记录](acceptance.md)，不追加验证。

后续实施按 S3，依据是共享报告写入、来源契约和任务恢复涉及持久化及权限边界；验证限定实际影响模块，加上用户明确要求的真实模型完整流程。优先复用已有保护测试，补有价值的来源身份、时序和拒绝回归，不重跑无关已通过检查。

交付分别报告：程序检查、真实模型完整流程、性能对照、未触发／未覆盖项及纯模型失败。发现系统缺陷应定向修复；确认纯模型失败按用户约束留档，可判 FAIL，不以循环采样追求 PASS。已确认范围满足、必要验证完成且无未解决系统问题时停止。
