## 问题

**P1：同一请求连续两次不同 Schema 错误，实际保存后仍为 partial。**

最小路径：用户仅要求创建一项资料整理工作；第一次将 `append_checklist` 错嵌入 `append.blocks`，服务器返回事项 A；第二次改成格式仍不正确的 `body`，显式传回首次服务器响应中的 `task_item_id=A`，却返回新的事项 B。三次调用属于同一用户消息，来源均为空、无私人成果或共享附件，副本均为默认 `copy_index=1`。第三次传正确正文，既有授权收到 `failedItemCandidates=[A,B]` 和 `recoveringItem=A`，确认后生成真实成功回执并绑定 A。既有结果收束只能清理授权绑定 A 的失败，B 未获同一身份确认、也没有成功回执，故 B 的 `invalid_arguments` 留在 `toolOutcomes`，最终 `derive` 返回 `partial` 和“这项操作暂未完成”。这是已保存业务效果与最终状态不一致，不是模型语义质量问题。

根因位于 `agent/actions/task_items.py:175-185`：`invalid_attempt` 只在完整 `attemptedOperation` 相等时复用本次已绑定事项；不同的无效参数尚未进入授权，不满足相等条件便无条件创建新事项。传入既有事项 ID 没有形成可供最终授权确认的连续失败关系；最终成功只能收束一个事项，不能解决这个重复登记。
