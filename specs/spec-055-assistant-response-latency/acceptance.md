## Previous Round FAIL and Rework

1. **旧客户端撤回未清除正文。** 上轮 v1 复现已收到正文后仅获得新版撤回事件，没有空快照。现空闲来源失效、新快照授权失败、Redis 封口、generation 交接统一按版本输出：v1 得到空文本／`withdrawn` 的 `snapshot`，临时正文合并先于去重。
2. **最终与恢复保存都失败时主动删除缓存。** 上轮实际处理器的纯桩复现显示两次数据库故障后仍清空缓存。现仅落库成功或权限／来源／租约撤回清空；持续保存故障关闭发布任务并冻结快照，保留正文、来源、身份、游标与原 TTL。`closed` 拒绝当前及后续 generation 迟到写，恢复读取仍验证来源，不显示成功，不重放模型或工具。

返工证据为上列 13 项定向检查，本轮独立代码审查确认两项修复符合原要求。

## Regression Risks and Evidence Limits

- Redis 为可丢失缓存；worker 硬崩溃或 Redis 重启可能丢失未保存尾部，已保存消息与副作用回执以 PostgreSQL 为准。
- 七轮合计读回耗时 1271.43s → 743.02s 混合成功与失败：基线长文和工作修改各触及未变的 420 秒时限。不能据此宣称稳定整体降幅、p95 或正常成功速度比例；同页阅读和代码样例本次也未变快。
- 优化后知识题首次因评测脚本 `redis.py` 遮蔽依赖而在零模型调用时失败；原故障保留，修正后仅补一次匹配账号样例，执行顺序因此不同。
- 真实对照运行的是启动时冻结源码；期间修改的四个服务端文件只涉及 v1 撤回和持续保存失败边界，成功 v2／模型路径未变。报告保留哈希差异，最终边界由返工测试和新的浏览器检查覆盖，不宣称模型对照是精确最终树运行。
- 模型样例首字是 SSE 接收时间，浏览器指标来自单独受控场景，不能拼接成真实模型端到端绘制耗时。
- 未执行全仓库测试、发行打包、生产部署或远端 CI；没有提交／推送。
