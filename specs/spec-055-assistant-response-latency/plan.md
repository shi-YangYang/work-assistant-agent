## 涉及模块

- 任务执行与用量：记录排队、输入准备、模型／工具阶段及完成时间。
- Agent 交付：减少单纯格式包装调用与重复输出，不改变业务授权。
- 网页读取：任务内有界快照与同页读取复用。
- 流式发布：API／worker 之间增加临时流通道，正文增量传输，结束或中断时持久化。
- 运行配置：新增 Redis 服务、连接生命周期、资源预算与开发／部署接入。
- 验证：复用现有真实 HTTP、worker、浏览器及隔离环境入口。

## 修改顺序

1. **冻结与测量**：保存 `4e4da8a` 基线、参数、用例与来源数据；加轻量分段计时。先核对时间归属，不因模型请求占比大便只归因供应商。此前解除的正文字符限制和保留的 2 MiB 接收保护继续有效。
2. **交付链路**：普通正文直接交付，移除字数元数据、在线计数与自动长度改写；旧任务恢复不重新要求填写整套表单。保留有界格式修正与旧 checkpoint 兼容，不添加第二个意图分类模型。
3. **网页复用**：抽出页面下载与切片能力，在 RunContext 注入有界快照。保持原工具返回结构，增加抓取时间／缓存状态及可选刷新语义。
4. **流协议与存储**：先定义身份、游标、快照／增量交接、缓存上限及撤回，再实现 Redis 通道；新增依赖只覆盖该职责。
5. **发布与保存**：受管理的发布任务合并增量，API 订阅事件；拆掉逐批正文写库，接入完成、失败、取消封存和旧客户端兼容。
6. **开发与部署**：本地自动启动 Redis，Compose 接入健康检查与内网连接；隔离测试补真实跨进程验证和资源／故障验证，不操作用户线上服务。
7. **证据驱动补充**：若步骤 1 仍显示明显连接建立／准备／传播等待，限定在对应模块优化；无证据则不动数据库连接池、worker 领取策略或前端动画。
8. **定向回归与对照**：一次执行受影响子系统检查，固定真实样本前后各一次，浏览器核对首字及完成态。仅失败或相关代码再改时复测。
9. **独立验收**：按项目 Spec 实施规则由实施 Agent 开发、新验收 Agent 审查，复用已通过结果；报告收益和剩余限制。

## 数据流

```text
发送 → 入队／领取 → 附件与上下文准备 → 主模型
                                      ├─ 必要工具 → 主模型继续
                                      │   ├─ 网页安全下载 → 任务内快照 → 多次切片读取
                                      │   └─ 业务变更范围／授权 → 真实写入回执
                                      ├─ 按需加载工具组 → 原业务工具／授权
                                      └─ 合法普通正文／旧 finish_task.answer 增量
                                           → worker 有界发布缓冲
                                           → Redis 增量事件＋恢复快照
                                           → API 来源／归属校验 → SSE → 浏览器
完整交付 → 本地结构／引用／真实状态校验 → PostgreSQL 最终提交 → 终态 → 清理临时流
中断／普通失败 → 封存已授权部分正文及状态 → 清理临时流
权限／来源撤回 → 使旧生成失效 → 清空不可展示正文
```

首字和业务提交是不同事件；不能把预览当成最终确认。任务级指标只聚合实际阶段，不将嵌套工具内模型请求重复记为总时长。

## 临时流通道

- **建议实现**：Redis Streams 承载有序增量，单独保存最新恢复快照。API 用阻塞事件订阅读取新内容；无需另加 Pub/Sub、消息代理或前端轮询。
- **进程边界**：API、worker 分别持有异步 Redis 客户端，应用退出时关闭。内存实现只供单元测试，不作为分进程部署的隐式降级。
- **原子交接**：快照带最后序号，发布时原子更新快照与事件位置。订阅从该游标之后读取；游标被裁剪时重取快照，前端按生成身份和序号去重，不能先取快照再无游标订阅。
- **身份与权限**：服务端构造租户／用户／任务／attempt／fence／generation 键，不信任浏览器指定身份。缓存不包含隐藏推理或原始工具参数；读取缓存不等于有权展示，沿用来源校验。数据库事务不跨 Redis 等待、SSE yield 或订阅等待持锁。
- **缓冲与背压**：每次生成一个可取消的发布任务，合并最新候选再计算 delta；队列只保留有界待发布状态。来源检查／发布失败回传任务处理器；出现缺口用快照追赶，绝不无限创建异步任务。
- **初始预算**：每次生成的正文快照与事件合计不超过 1 MiB、事件最多 256 条；需预先裁剪并限制单条负载，不能仅靠近似条数限制。活跃键 TTL 15 分钟并随活动续期；终态提交后清理，漏清理依靠 TTL。缓存到顶可停止预览，最终答案不截短。
- **部署预算**：Redis 初始 `maxmemory` 64 MiB、容器内存 128 MiB，关闭持久化，采用拒绝新写入而非静默淘汰活跃数据；记录实际峰值，预算不足时明确降级。只存短期正文数据，不挤占现有数据库或沙盒预算；不改 worker 并发。
- **故障处理**：Redis 不可用时后台生成仍有机会正常结束并写数据库，SSE 明确结束预览，既有状态快照负责通知结果。最终保存失败保留原任务身份与可用缓存，有限重试保存，禁止重新调用模型／执行工具补救保存失败。
- **恢复范围**：用户返回页面或使用现有恢复入口可重新订阅；不新增自动重发消息和持续请求。API 重启与 worker 崩溃分开验收；内存及无持久化 Redis 不保证进程崩溃后的未保存正文无损恢复。

## 接口变化

- HTTP 路由与数据库 schema 不变；现有 events 路由增加流协议版本协商。分段计时使用现有日志、用量和隔离测试产物，不公开隐私诊断。
- 普通回答不要求 `answer_length` 或任务表单；旧长度字段仅供读取兼容，不执行字数校验。旧工具 schema 与存储对象兼容分开，不把历史字段要求重新注入模型。
- `web_fetch` 保留 `url/offset/find/match_index`，新增可选 `refresh=false`；返回明确的抓取时间与快照复用标记，来源含义不变。网页快照只能由任务上下文提供，不能由模型提交缓存内容。
- 现有 `snapshot`／`replyStream` 保留任务状态和完整恢复文本，新增正文 `delta`、恢复 `sync`、撤回与预览不可用事件；统一携带尝试身份、generation 与序号，不混用任务状态 `seq` 和正文游标。
- Web 请求新版事件协议，唯一请求层完成增量归并，再向现有展示组件提供完整当前文本；不让组件各自建立订阅。未声明新版的客户端由 API 从临时流组装旧快照，不恢复正文写库。
- 完成通知必须晚于最终数据库提交。预览中断不等于整个任务失败；Redis 故障不可触发自动重新发消息。刷新读取已完成消息时以持久化结果为准。
- 新配置建议 `PAA_REPLY_STREAM_REDIS_URL`，仅 API／worker 使用。开发脚本自动启动并等待本地服务；生产 Compose 内网连接，不暴露 Redis 公网端口。最终镜像与客户端版本在实施时锁定。

真实对照预先冻结六类任务：普通知识问答、约 150 字短文、约 1000 字长文、同一网页多片段阅读、明确要求代码实测、创建后继续修改同一工作。业务任务两轮，其余一轮，即每个版本七轮；每版按相同顺序执行一次，回答错误不追加抽样。已有历史耗时仅作背景，不能代替同条件基线。

- 同模型、强度、角色、工具配置与隔离数据；网页性能主对照使用固定公开内容副本，真实外网冒烟单列，不把网页变化当回归。
- 保存每轮首字、完整耗时、调用次数及原因、输入／输出 Token、实际字数与工具副作用；附每轮明细和两版总时长。
- 这是小样本示例对照，不声称 p95、稳定提升百分比或供应商能力排名。外部异常导致不可比时报告限制；不反复重跑直到更快。
- 受控流／延迟注入证明具体工程收益，真实模型检验整体使用效果；不得仅凭秒数变小推断所有优化有效。
- 所有写入、故障与取消在本轮拥有的测试资源进行；结束清理 API／worker、schema、容器和临时凭据，不停止用户日常服务。
- 单独注入慢数据库，对比首字与上游消费是否脱离逐批正文写入；任务、工具与 checkpoint 的正常写入不记作正文写入。Redis／来源查询耗时照实记录，不能归入供应商推理。

## 风险

- 强制工具选择的兼容性不同，且普通正文不能可靠承载任务元数据；禁止用本地猜测绕过交付和权限规则。
- 终态与晚到增量、取消与旧 fence、恢复快照与新分片存在竞争；先定义序号与提交顺序，不能用删除状态检查换取流畅。
- 新增 Redis 带来部署和故障处理成本；缓存不持久化会丢未保存的尾部。必须显示正确状态，不承诺崩溃恢复模型连接或无损重放。
- 网页快照可能影响实时性和常驻内存，采用任务范围、短有效期、显式刷新和容量淘汰，不跨任务复用。
- 连接池与同页缓存不是同一问题；不能因实施缓存顺便放宽 DNS 校验、引入全局可变校验状态或扩大并发。
- 若保留的授权和模型生成占主要耗时，应如实交付测量结果，不擅自拆掉安全职责或改用户选择的模型。

## 迁移与回滚

无数据库 migration。旧 `Job.feedback.replyStream` 仍可读取已保存历史或中断快照；新生成不再反复更新它。保留旧长度字段输入与 checkpoint，临时流不是工具执行成功的依据。

先部署健康的 Redis，再更新支持新旧协议的 API，排空旧 worker 中的任务后更新 worker，最后切换前端。实施需核对现有发布脚本能否保证顺序；若不能，采用短暂停止接收新任务并排空的发布窗口，不宣称混合版本无损滚动升级。Redis 未配置时给出明确的预览降级状态，不静默走旧高频写库模式。

回滚前同样停止新任务并排空在途任务；旧版本仍能读取最终回复、操作回执与历史快照。临时键按版本隔离并自然过期，不清空共享 Redis，不删除业务数据。网页缓存和本地缓冲随任务结束释放。
