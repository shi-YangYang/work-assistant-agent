# Spec 049：成员管理改造

## 状态

已实施，[独立验收通过](acceptance.md)。

## 背景

成员管理目前只有账号列表和操作菜单，缺少查找与姓名维护。此次补齐日常操作，取消启停功能，用删除账号处理移除成员的需求。

## 目标

- 快速找到成员，看清姓名、账号与创建时间。
- 在同一页面完成添加、更正姓名、重置密码和删除；移除停用／启用账号功能。
- 升级时将历史停用员工账号按现有删除流程统一清理，不保留历史停用管理分支。
- 从成员进入已有团队工作视图，不重复建设工作看板。
- 遵循 Noria 黑白灰、全幅画布和紧凑布局。

## 非目标

部门树、岗位、管理员授权、日常批量导入／删除界面、邀请系统、员工绩效排名、在线监控、聊天记录查看。账号名称不可修改；不改钉钉绑定、登录方式配置、会话策略和 Agent 工具。一次性历史停用账号清理属于本次范围。

## 当前行为

- `/members` 仅管理员可访问；接口返回本公司未删除的员工，不包含管理员。
- 每行只展示姓名、账号、角色与启用状态，没有搜索和状态筛选。
- 可添加员工、重置密码、启停和删除；启停使用浏览器原生确认框。
- 创建／重置密码已有字段级校验，密码为 4～128 位；删除前已有影响预览。
- 后端已保存账号创建时间，但成员接口尚未输出；修改接口只接收 `active`。

## 目标行为与功能需求

### 1. 列表与查找

- 顶部保留“成员管理”、成员总数、刷新和“添加成员”；不加统计大卡片或新的全局顶栏。
- 工具栏提供姓名／账号搜索，不增加启用／停用筛选和状态统计。
- 桌面列为“成员（姓名＋账号）／创建时间／操作”。不重复展示所有人都相同的员工角色和正常状态，不增加历史停用标签。
- 搜索去除首尾空白，账号忽略大小写；姓名、账号可部分匹配。关键词保存到 URL，刷新、返回后保留；旧 `status` 参数不再影响结果。
- 沿用当前完整成员列表，先搜索全部成员，再按每页 20 人分页；本次不引入分页接口。页码保存到 URL，搜索变化回到第一页，删除后页码越界回到最后一个有效页。列表加载后始终显示分页控件，单页或空列表时上一页、下一页均禁用。
- 搜索时显示匹配数量与总数；翻页和搜索无需重新请求成员。
- 无成员提供添加入口；无匹配提供清除搜索；首次加载、加载失败和已有列表刷新分开处理。请求未返回时不显示虚假的“0 人”。

### 2. 日常操作

- 操作菜单增加“编辑姓名”；账号只读，复用现有姓名规则和逐字段错误提示。保存成功更新列表，失败保留输入，空白／超长姓名不能保存。
- 保留添加与重置密码流程；账号重名定位账号输入框，不显示整页重复错误。
- 删除前端停用／启用菜单、确认流程和请求调用；后端不再接受管理员通过成员修改接口设置 `active`，不能只隐藏按钮。
- 删除是唯一移除账号的操作。保留影响预览、撤销登录、停止待处理任务与提醒、保留历史业务、释放账号名及钉钉绑定的行为；新账号不继承旧资料。
- 提交期间禁止重复操作；失败不提前更新列表，保留重试入口。操作成功刷新一次成员列表，保留关键词；记录不再匹配搜索时正常移出结果。

### 3. 查看该成员工作

- 操作菜单提供“查看工作”，跳到已有团队看板，带成员 ID 和当前工作视图。
- 不在成员页展示工作详情、汇报统计或聊天内容。看板无工作时展示真实空状态；返回成员页保留查找条件。

### 4. 历史停用账号清理

- 升级时执行一次数据清理，范围为 `role=employee`、`active=false`、`deleted=false` 的账号；正常账号和管理员不受影响。
- 复用现有删除业务流程，不能只修改 `deleted` 标记或物理删除成员行。撤销会话、停止待处理任务和提醒、释放账号名及钉钉绑定，并按既有规则清理声纹、登记录音和材料访问。
- 历史工作、报告和原始消息继续保留，归属 ID 不变，按原权限在团队历史中查看；清理后的账号不再出现在成员管理。
- 清理可重复执行：已删除账号不重复处理；中断后可继续，文件清理沿用现有持久任务重试。输出成功、失败及待清理数量，失败不能报告全部完成。

## 边界条件

- 同名成员使用账号区分，操作对象始终使用成员 ID；长姓名和长账号不能挤压操作入口。
- 员工、跨公司对象、管理员对象及已删除账号的写操作继续由后端拒绝，不能仅隐藏按钮。
- 姓名修改只改姓名，不改变账号、角色、启用状态、密码、归属和已有历史快照；不触发汇报资格重算或撤销会话。
- 姓名更新只接受姓名；空对象、显式空值和 `active` 等不支持字段返回校验错误。
- 创建时间指账号创建时间，不标为入职时间或最近登录。
- 历史停用账号清理不能变成恢复登录，也不能转移历史资料；删除后同名重建仍是独立的新账号。
- 保留底层 `active` 字段及登录检查，用于已删除账号和历史数据兼容；不借此重构认证、团队历史筛选或数据库结构。
- 删除不等同钉钉禁止注册：仍在企业授权范围内的用户，可依既有规则重新注册新账号。需阻止再次钉钉登录时，在钉钉侧移除其应用授权范围；相关说明不能继续要求使用已移除的停用功能。

## 技术约束与兼容性

- 复用请求入口、表单字段、菜单、模态框、错误范围与设计变量；CSS Modules 就近组织。
- 列表增加 `createdAt`，以成员列表专用类型扩展既有 `Member`；不改变身份响应和其他消费者的必填字段。
- `PATCH /members/{id}` 改为仅接受必填 `name`。旧客户端发送 `active` 必须明确失败，不静默忽略，也不保留可绕过界面的启停入口。
- 无数据库结构迁移；使用已有 `created_at`，增加一次性历史账号数据清理。无新增轮询或逐成员详情请求。

## 验收标准

- [x] 搜索与数量一致；刷新和返回保留关键词，无匹配可恢复全部结果。
- [x] 添加 → 搜索 → 改姓名 → 重置密码 → 删除 → 同账号名重建全流程可用。
- [x] 前端无启停菜单、状态筛选及请求；旧 `active` 更新请求被后端拒绝。
- [x] 历史停用员工被完整删除，正常账号和管理员不受影响；历史工作与报告保留，登录和绑定按删除规则回收。
- [x] 清理重复执行、中断恢复、文件清理失败均有正确结果，不重复副作用、不漏报失败。
- [x] 重置密码、删除的既有登录和数据保留规则不回归；改姓名不触发这些副作用。
- [x] 非管理员、跨公司、管理员对象、已删除对象和无效输入均在服务端拒绝。
- [x] “查看工作”进入指定成员视图，返回不丢关键词；被清理成员的历史资料仍可在团队看板按原权限查看。
- [x] 页面、弹窗错误各在所属区域展示一次；取消、键盘、重复点击和失败重试行为正确。
- [x] 浅／深色、桌面／手机，以及空、加载、错误、长文本状态可用；宠物与导航不遮挡主要操作，页面无横向溢出。

## 待确认问题

无。范围为员工列表、搜索、姓名编辑、添加／重置／删除、查看工作入口，以及历史停用员工清理。
