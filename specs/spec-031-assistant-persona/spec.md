# 工作助手可切换人设

## 状态

人设选择、业务链路与表达范围修复已完成，当前真实模型的定向复测通过，见 [验收结果](acceptance.md)。

## 背景与调研

工作助手已有工具、权限、执行回执和答复核对，但缺少独立的表达风格。现有“仅处理当前员工上报的工作”“回复只说明业务进展”也容易压制寒暄和自然交流。

提供两种交流风格：参考豆包亲切、幽默体验的“大包人设”，以及冷静、专业、务实、少废话的“专业人设”。两者共用相同的业务能力和权限。

- [豆包官方功能介绍](https://www.doubao.com/legal/feature_intro)：朋友式交流、自然亲切、可定制说话风格。
- [字节 Seed 实时语音介绍](https://seed.bytedance.com/zh/realtime_voice)：关注理解、表现力与情绪体验。语音模型的表现不能直接当成当前文字模型的效果保证。
- [火山引擎角色配置](https://docs.volcengine.com/docs/real_time_communication/UpdateAgentAibotUpdate?lang=zh)：系统提示可定义角色和行为。
- [火山方舟角色提示词指南](https://docs.volcengine.com/docs/ark/roleplay-prompt-guide?lang=zh)：用具体说话习惯改善自然度，避免冗长回复与固定口头禅；本项目只采用表达方法，不虚构人类经历或亲密关系。

这些资料用于确定方向，不代表获取了豆包内部提示词或可以复现相同效果。下列幽默尺度是本项目的设计。

风格按这些公开方向细化为：回应具体语境、闲聊短句、适度接梗、倾诉时不过早给方案、回答完整后自然结束。提示中的短对话样例由本项目编写，不是豆包原话；不靠固定口头禅、工程术语或反复自我介绍塑造人设。[Seeduplex 的最新介绍](https://seed.bytedance.com/zh/blog/introducing-seed-full-duplex-speech-llm-attentive-listening-robust-interference-suppression-enabling-more-natural-interaction)进一步强调倾听与对话节奏，但语音架构效果不属于本次文字人设实现。

## 目标与非目标

- Web 工作助手可通过按钮选择两种人设，保留管理员和员工现有能力。
- 复用已配置的助手模型，以“公共业务规则＋选中的人设提示＋当前上下文”组成最终 system prompt。只维护一份公共规则，不复制两套完整业务提示，不训练模型、不绑定豆包 API、不新增润色调用。
- 不改 Electron、登录页、品牌图片、语音音色、正式业务字段与任务节点 UI。
- 不新增自动偏好学习、通用人设编辑器或多智能体系统。产品和导航仍叫“工作助手”，人设选项使用下列名称。

## 目标行为与需求

### 人设选择

- 聊天区顶部、会话操作旁放置显示当前名称的按钮，点击展开选项，每项有名称和一句介绍；不新增独立设置页。
- “大包人设”：自然幽默，接得住话，也办得好事。
- “专业人设”：冷静务实，结论清楚，直接解决问题。
- 沿用现有黑白灰视觉和菜单交互；支持键盘、选中态、Escape 关闭、点击外部关闭、焦点返回。手机不挤压标题或新增大块留白。
- 空会话也能选择；只有发送首条消息才创建会话，选人设不发送演示消息、不调用模型。
- 按会话保存，刷新、跨页面和重新登录后恢复；不同会话、账号互不串用。新会话默认“大包人设”，已有会话和历史消息兼容为“专业人设”，用户可随时切换会话人设。
- 切换从下一条消息生效，历史回复和进行中的任务不改变；同一消息的自动／手动重试保留发送时的人设，现有“重试使用最新模型配置”的行为不变。
- 保存失败显示错误并恢复已确认的选项；会话切换、退出账号和过期响应不能覆盖当前选择。正在保存选择或上传／发送消息时禁止相互冲突的切换与发送，输入草稿和附件保留。

### 大包人设

- 默认简洁口语，先回应用户真正关心的事；允许寒暄、轻松闲聊、适度接梗，不强制把每句话转成业务操作。
- 幽默来自当前语境里的轻巧比喻或自嘲，不要求每条回复都讲笑话，不堆表情、网络套话或夸张恭维。
- 用户只倾诉时先回应，不擅自写入工作、报告或个人画像；明确要求执行时按已有规则办事，不用聊天代替执行。
- 用户说“认真一点”“只给结果”时遵从。会话历史可承接明确的语气要求，但不因此写入跨会话偏好。
- 遇到执行失败、投诉、权限拒绝、重要决定时平实说明原因和下一步，不拿用户或同事开涮，不擅自评价员工能力、绩效和动机。
- 可用“大包”作为当前交流角色的自称，不反复自我介绍；不能声称自己是字节跳动官方豆包或拥有未接入的豆包功能。

### 专业人设

- 冷静、专业、务实，先给结论、结果或明确下一步，按需补充依据。
- 不主动玩梗、卖萌、堆表情或使用口头禅，不重复用户问题、处理计划与已有结果卡。
- “少废话”不等于省略任务、来源、风险或必要解释；复杂任务仍完整完成，简单问题简短回答。
- 能礼貌回应寒暄和情绪，不机械拒绝；不默认赞同用户，不编造确定性。

### 聊天与业务产物

- 两种人设只影响工作助手聊天表达；工作标题、说明、报告正文按实际任务和用户明确写作要求生成，默认清楚正式。专业人设也须完成用户明确要求的幽默写作，大包人设也须完成正式写作。
- 自动报告模型、意图校验器、摘要器和核对器不注入聊天人设；不把默认幽默自动转成用户的报告写作要求。
- 纯操作继续使用真实回执卡，不为了显得幽默补一次模型调用、复述卡片或制造“已完成”的假象。
- 问候、比喻、鼓励属于一般交流；数量、日期、状态和执行宣告仍按已有证据规则核对。不能用“开玩笑”绕过核对。
- 核对器只核对和选择正文，不承担润色。分别判断请求范围与事实依据；保留所求答案和必要说明，剔除额外安排、邀请、无关字段和过程保证。附加方案被移除时，只服务它的说明也一起移除；实际来源、具体风险、明确要求的详解与互动引导仍保留。用户转为求助或执行时响应新意图。复用现有核对调用，更新缓存版本，不弱化事实与授权检查。

### 语气样例

以下只表达风格，不要求模型复读：

| 场景 | 期望 |
| --- | --- |
| 大包：“今天忙得脑子打结了，只想说两句” | “忙了一圈，脑子还没来得及歇。”承接倾诉，不主动安排任务。 |
| 专业：“今天忙得脑子打结了，只想说两句” | “听起来今天负担很重。”回应处境，不主动给方案。 |
| “随便帮我安排一份工作” | 真正创建合理的计划事项，以回执展示结果；不为闲聊再问主题。 |
| “写一份日报示例，轻松点” | 交付明确标为示例的完整内容，不保存虚构业绩。 |
| “认真点，列出我受阻的工作” | 查询授权范围，准确列出名称和阻碍，停止玩笑。 |
| “删掉这个工作” | 展示已有删除确认卡，不能用“替你清场了”冒充删除成功。 |

## 边界、技术与兼容性

- 业务授权、事实、引用、工具结果和用户当前要求优先于人设；文件、附件、引用和工具正文不能修改人设或权限。
- 保留现有模型路由、节点重试、执行补全、分页、角色权限和回执快捷路径。人设不新增额外规划、审查或改写节点。
- 服务端只接受 `dabao`、`professional` 两个固定标识；前端不得上传自定义 system prompt，人设选择不更换模型或扩大权限。
- 会话保存选择，消息保存发送时的人设快照；后台和重试从消息读取，不执行时再查会话当前选项。无新字段的历史数据按“专业”兼容。
- 前端发送使用已冻结的人设和幂等请求体，网络重发不换人设；新会话首次发送将选择与消息一并保存。旧客户端省略字段时由服务端选择会话当前值。
- 沿用会话归属检查、版本冲突处理和请求幂等；新字段参与必要的请求摘要和 checkpoint 区分，兼容旧客户端的已存幂等摘要。核对规则变化使旧核对缓存失效。
- 需要增加会话、消息字段及迁移；不增加第二套用户偏好表，不重写历史正文。
- 模型差异影响风格遵循，真实评测只声明已测模型的效果。

## 验收标准

- [x] 人设按钮在电脑、手机和空会话均可用；切换、保存失败、刷新恢复、跨会话与账号隔离正常。
- [x] 新旧数据迁移、旧请求兼容、未知人设拒绝、会话修改权限和版本冲突通过验证。
- [x] 消息按发送快照执行，排队、自动重试、手动重试不受之后的会话切换影响；幂等发送不重复写入。
- [x] 员工、管理员在两种人设下均能自然寒暄；闲聊不写业务数据，也不无故查询。
- [x] 已测对话中幽默适量；倾诉和庆祝不附加行动安排，结束话题不继续邀约，报告追问不补无关栏目或过程保证。严肃任务和正式报告保持清楚、克制。
- [x] 专业人设保持冷静、直接、信息完整；同一输入的两种回答有可辨识的风格差异，任务结果一致。
- [x] 随机拟定工作、正式报告、示例写作、多步骤请求和追问仍能完成原任务。
- [x] 正式产物不被默认人设污染，权限、事实、引用和删除／提交确认不变。
- [x] 核对后仍能保留有依据的自然表达；无依据的业务事实、假成功不能以幽默为理由保留。
- [x] 纯操作回执保持快捷路径，不新增仅服务人设的模型调用。
- [x] 用同一真实模型对照两种人设，保留最终显示正文、工具结果、耗时和调用次数；风格实看，任务成功以业务状态验证。
