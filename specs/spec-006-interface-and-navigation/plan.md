# Plan — Spec 006

## 状态

ACCEPTANCE，对应 [Spec](spec.md)。一个实施 Agent 已完成耦合的 renderer 改动，现由新的独立 Agent 验收；协调 Agent 负责日常环境交互、提交与对应 CI 核对。

## 涉及模块与顺序

1. 以已确认方向及原型作为设计输入，覆盖会议列表、会议工作区、服务设置、当前会议与外观；原型中的模拟状态不得替代应用现有逻辑。
2. 在 `src/renderer/` 内建立语义色值、排版、间距及基础交互组件；复用现有图标和播放器能力，不另建业务根目录。
3. 从 `App.tsx` 提取应用框架、会议页面、设置子页与导航。录音／核心状态位于页面之外，服务草稿与后台订阅明确归属，避免卸载页面丢失状态。
4. 重组 `ModelSettings.tsx`、`Transcription.tsx` 的设置区域，保留多服务、预设与下载行为；高级内容复用 `CollapsibleSection.tsx`。
5. 调整 `MeetingMinutes.tsx`、`AudioPlayer.tsx`，组织页签、单一播放器、引用与原文定位；接入紧凑录音条和命令面板，与按钮共享操作和可用性判断。
6. 独立验收已确认需求及回归；按具体缺陷返工，完成提交与对应 CI 核对。

## 导航、状态与数据流

- 建议用 renderer 内存中的类型化视图状态与历史记录管理子页；主进程按精确 renderer URL 校验 IPC，不为导航放宽校验，也不直接引入改变 URL 的 hash 路由。
- 核心／录音订阅 → 应用级状态 → 当前会议与控制条；路由不负责启动或停止采集。
- 会议 ID → 详情、纪要与全文页签 → 引用目标及音频定位。播放器挂在会议工作区，按会议 ID 唯一实例化。
- 服务 ID → 对应草稿、模型目录与请求状态 → 设置子页；切页不重复请求，晚到结果不覆盖另一服务。
- 主题使用 `prefers-color-scheme` 与只保存外观选择的本地偏好，不混入服务密钥或业务数据。

## 接口与迁移

预期复用 `window.paa`，不需要业务数据库或用户目录迁移。原文跨页定位先核对现有按片段 ID 查询能力，避免把当前加载的 50 段当作完整会议。

## 验证计划

- 当前决策文档按 S0 检查内容、引用与 diff；设计原型做轻量页面与关键交互自查，不安排子 Agent 或独立验收，不运行业务测试或构建。
- 实施跨多个 renderer 模块，预计 S2：格式化涉及文件，运行类型检查及导航、播放器、服务草稿相关测试。实际改到安全、公共接口或构建配置时才依据风险扩大范围。
- 本机按 AGENTS.md 执行 `npm run dev`，使用用户日常数据，通过 CUA 验证页面、菜单、键盘与窗口布局；故障注入及清理脚本不得指向真实数据。
- CI 沿用临时数据，更新现有 smoke 的导航与断言，保留重复播放器、设置保存、录音互斥及安装版回归。等待当前提交 macOS / Windows 必需检查，不复用旧 SHA 结果。
- 色值对比度检查结合实际页面观察，不新增只复述组件实现的测试。

## 风险

页面卸载导致草稿或订阅丢失、重复播放器与隐藏浮层、跨会议异步结果覆盖、主题切换后状态色不清、快捷键冲突。均在对应模块与定向验收中处理，不借机重构 Python 核心。
