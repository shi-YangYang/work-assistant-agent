# Implementation Report

## Summary

工作助手增加可选的独立 Python 执行服务，支持计算、上传资料分析和 TXT、Markdown、JSON、CSV、XLSX、PNG、DOCX、PDF、PPTX 交付。普通问答、写作、联网和公司业务继续使用既有流程；文件归入原有私人成果版本，由用户决定是否转成工作。

## Files Changed

- `apps/sandbox/`：私有控制 API、持久回执、公平队列、runsc 执行环境、固定受限文件解码器和预装依赖。
- `apps/server/app/modules/executions/`、`integrations/sandbox/`、`agent/tools/execution.py`：授权输入、稳定执行身份、取消／恢复、配额和原子发布。
- `modules/deliverables/`、迁移 `0022_sandbox_deliverables.py`：不可变版本文件、鉴权下载、来源失效和回收。
- Agent 注册、核对、任务租约：按配置暴露工具，保留节点重试／SSE，并复核实际读取过的附件与成果来源。
- Web 成果组件和 API 契约：紧凑文件列表、PNG 预览、鉴权下载、历史版本与身份切换清理。
- `deploy/company/`、环境示例及架构／部署说明：可选自部署执行器、固定镜像、资源与存储限额。
- `tests/sandbox/`、`tests/server/test_sandbox*`、`scripts/benchmarks/sandbox-evaluation.py`：协议、真实隔离／恢复和真实模型测试。

## Important Decisions

- 生成代码只在真实 gVisor `runsc` 环境执行。启动时验证内核和非 root 身份，运行时缺失或探针失败则关闭执行，不退回宿主 subprocess 或普通 runc。
- 每次执行全新环境、无网络、无凭据、只读根目录；输入按授权复制，输出限定格式、数量与大小，禁止符号链接、活动文档内容和路径越界。控制服务解析文件使用固定降权子进程，并设置内存、CPU 和超时限制。
- 默认每次 1 CPU／1 GiB／60 秒，并发可配置。控制端保留短期回执，未知执行不盲目重放；发布再次检查租约与输入版本。
- 来源跟随本任务实际读取记录传播，不依赖模型继续传 `input_refs`。来源失效后下载、成果列表及原消息恢复均隐藏相关成果。
- 默认每用户 512 MiB、服务器总计 4 GiB 的成果额度；全局事务锁防并发超额，永久总量包含等待清理的孤儿文件。
- 中文 PDF 必须带可移植的嵌入字体；Office 与 PDF 的格式检查不冒充排版检查。工具回执区分逐格式验证项。

## Tests

- 公司后端全量：693 通过，3 个默认跳过的真实运行时用例另行真实执行全部通过。随后新增配额与文件回执检查使用定向测试验证。
- Web 全量：491 通过；类型、普通构建和相关 ESLint 通过。真实浏览器覆盖 20 项既有页面流程及 6 项成果文件流程。
- 快速协议测试：10 通过，包含不可信归档、损坏文件、Office 活动内容、PDF 转义动作、非嵌入中文字体、Word 简单／拆段复杂字段、幂等与公平队列。CI 测试入口将两个 `app` 包放在独立解释器及独立 `PYTHONPATH`。
- 真实 gVisor：九格式生成、双用户同名隔离、跨执行文件拒绝、无网／非 root／只读、恶意输出、取消子进程、输出／内存／磁盘／PID／超时限制通过。PID 耗尽会使 gVisor 容器失败关闭，控制服务和后续任务正常。
- 真实恢复：两个同时运行、一个排队；控制进程被 KILL 后重启不重放未知任务；排队取消；无心跳 47 秒回收；并发 1 下三个用户按轮次执行。
- 真实数据库与 gVisor：提交响应丢失后查询旧回执、不重复执行；导出后租约撤销不发布；执行 worker 子进程被 KILL 后回收，3 项通过。
- 真实模型覆盖 12 个流程：通用问答／翻译／代码解释、附件去重／退款／空值计算、连续文件修改、九格式交付、联网到文件、个人方案到两项工作、双用户同名文件。Excel 实际单元格分别为 120 和 200，JSON／CSV 总额为 14；旧版本保留。
- 初轮 PDF 中文渲染暴露缺失 CMap 和非嵌入字体问题，已修复运行镜像及发布校验。仅重测相关 PDF／Office：旧非嵌入 PDF 被拒绝，新 PDF 中文提取及渲染正常，真实模型重新生成两页中文 PPTX／PDF 与 DOCX。
- 部署脚本 `bash -n`、使用虚拟环境参数的 Compose 合并检查通过；控制和执行镜像已实际构建，未更改生产服务器。

证据位于 `artifacts/spec042/`：`server-final.log`、`sandbox-*.json`、`real-model-validated.jsonl`、`real-model-office-portable.jsonl`、`pdf-portable-check.json` 及浏览器／渲染目录。初轮评测中的普通问答队列状态、Excel 合计标签断言错误保留原始日志；复核依据真实 `taskOutcome` 和文件内容，不靠重复调用获得通过结果。

## Known Limitations

- 本机验证为 macOS 上的临时 Linux Docker／gVisor 环境，未对在线服务器进行故障注入。总计 4 CPU／8 GiB 限额下，两个执行任务并发、第三个排队，748 次 API 请求全部成功，p95 为 16.77ms；不代表正式服务器或长期满负载容量。
- 沙盒首次启用需要部署 gVisor、构建镜像并配置私有服务令牌；未配置时普通助手功能可用，执行工具不暴露。
- 固定格式校验能拒绝损坏或活动文件，不能证明开放式任务的全部内容与排版都正确。已实际检查本次样本，不能宣称任意任务都能成功。
- 真实模型曾将 PDF 字体嵌入泛化为三个格式均嵌入，文件本身可用；工具已明确返回逐格式检查范围，保留这条观察，不用一次样本承诺模型永不泛化。
