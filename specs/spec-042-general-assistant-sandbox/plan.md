## 涉及模块与数据流

```text
用户消息／引用文件
  → 原有 Agent 判断任务
     ├─ 直接回答／联网／公司业务工具
     └─ run_python(code, input_refs)
         → 公司后端：鉴权、固定输入版本、记录执行身份
         → 独立执行服务：创建受限环境、运行、返回日志／文件清单
         → 公司后端：复核租约与来源权限、校验并保存文件
         → 原成果版本与消息回执
  → 聊天正文／图表／真实下载
  → 后续消息读取已有输入和成果，按需继续执行或写业务
```

- 工具层负责模型可理解的参数和结果；业务模块负责归属与持久化；集成层只处理执行协议；沙盒服务负责隔离运行。
- 执行器不读取数据库或决定业务授权，不直接发布用户可见 URL；客户端不传容器 ID、宿主路径或资源提升指令。
- 私有执行本身不调用业务授权 LLM 逐次审批。现有三级规则只在对应公司写操作上生效。

## 接口与数据约定

- 新工具拟为 `run_python(code, input_refs)`；输入引用限定附件 ID 或成果 ID／版本。执行 ID、所属会话、资源额度由后端补全。
- 读取/保存成果工具扩展文件引用；只接受同一授权范围内真实执行返回的文件，不接受模型随意生成的 URL 或文件系统路径。
- 内部协议至少有提交、查询、取消、导出、释放。仅可信 worker 访问，独立身份验证；控制凭据不进入运行环境，执行服务不对公网开放。
- 状态采用 `queued/running/succeeded/failed/cancelled`；执行请求包含租约 fence，成功回执可重读。控制服务重启后可以识别已有任务，不能把“状态未知”当成“从未执行”。
- `Execution` 关联公司、用户、会话、消息、节点、输入摘要、代码摘要、运行镜像版本和结果；stdout/stderr 有上限并脱敏。
- 公司与用户身份从认证上下文取得，后端校验会话、消息与任务归属，再生成执行 ID。控制服务维护执行 ID 与独立环境的映射；所有查询、取消、导出及回执关联同一身份和 fence，不能由模型或浏览器任意指定所属用户。
- 成果文件关联现有不可变版本，保存存储键、类型、大小、摘要和来源。下载继续走认证 GET，默认不缓存敏感内容，不修改原上传模型的发送状态。
- 文件发布先暂存并验证，再提交数据库关联；提交失败清理暂存，已发布版本保持不变。对取消／权限变化和提交使用同一任务边界复核。
- 新增文件预览／下载接口纳入既有请求合并、会话续期与错误呈现约定；不因生成能力新增前端轮询。

## 执行环境

- 只实现自部署执行器；业务后端通过独立协议调用，避免与具体隔离运行时耦合。
- 同机试点的起始预算建议：全局同时执行 1 个任务，每个环境最多 1 CPU、1 GiB 内存，单次代码 60 秒；任务总预算复用已有 deadline，限制 PID、磁盘与导出总量。上述是压测起点，不是未经测试的承载承诺。
- 一个控制服务管理执行队列和多个环境：每个独立执行请求到达运行位置后创建全新隔离实例，完成后销毁；重复提交同一执行只返回已有状态。共享只读镜像与依赖，不共享用户进程、可写卷或临时文件。
- 按用户公平调度并限制排队额度；队列满或等待超过预算时明确返回。排队取消不占运行名额，运行失败／取消后释放名额；普通聊天和业务请求不进入沙盒资源队列。资源验证通过后可提高并发，实例隔离方式保持不变。
- 非 root、只读基础镜像、移除 capabilities、禁提权、隔离 PID／网络／挂载；控制平面与生成代码分开。生产启用前验证强化隔离运行时及资源约束是否真正生效。
- Python 预装 pandas、NumPy、openpyxl、matplotlib、python-docx、python-pptx 和 PDF 生成所需库及中文字体；执行镜像包含文档与演示文稿渲染依赖，用于检查分页、溢出和布局，渲染同样受资源限制。
- 固定镜像与依赖可复现；缺库返回明确原因，不自动放开联网安装。运行 CPU 即可，不因执行代码购买 GPU。
- 本地开发可关闭执行服务；需要真实执行时使用同一协议的开发沙盒，不能以无隔离 subprocess 冒充。

## 修改顺序

1. **隔离验证**：验证自部署隔离运行时在目标环境可用，确定资源预算和协议。未通过不得开放生成代码执行。
2. **执行基础**：新增执行实体、适配器与独立运行环境；完成超时、中断、幂等、重启恢复、暂存清理和真实边界检查。
3. **真实成果**：扩展版本文件、下载、来源复核、删除和引用，打通“输入 → 运行 → 文件打开”。
4. **Agent 接入**：登记工具，调整能力说明、工具选择与交付核对，沿用节点进度。使用不同表达的任务验证，不为某几个句子写关键词分支。
5. **界面接入**：扩展现有成果区，紧凑展示图表与下载，处理窄屏、主题、失败、过期和版本选择。
6. **集成验收**：运行 Web 前后端全量回归、真实执行、多流程模型样本、浏览器与沙盒破坏性测试；由新独立验收 Agent 对照 Spec 检查。

## 测试计划

实施涉及执行隔离、授权、持久化与发布，按 S3 完成 Web 前后端全量验证及沙盒破坏性测试。

| 范围 | 验证内容 |
| --- | --- |
| 通用对话 | 无工作记录的问答、翻译、改写、解释代码，不触发无关业务读写或沙盒 |
| 计算与交付 | 已知结果的汇总／空值／重复数据／单位处理；各格式实际生成、下载、打开；PPTX 连续修改、可编辑性与逐页渲染检查 |
| 连续任务 | 多次改筛选与样式、引用旧文件、压缩上下文、回收环境后继续；无重复文件版本或错误业务变更 |
| 多用户调度 | 不同用户／公司及同一用户不同会话交错提交；同名文件、伪造执行 ID、串行残留、并行串用、队列配额与公平性、取消不误杀 |
| 执行恢复 | 提交丢包、重复请求、执行中断、代码修正、超时、OOM、输出超限、worker／执行服务重启 |
| 安全隔离 | 跨租户／会话、失权、路径穿越、符号链接、宿主／元数据网络访问、进程／磁盘耗尽；检查失败关闭执行 |
| 业务回归 | 三级权限、临时问题、工作引用、正式报告、原附件与成果、消息重试和账号切换 |
| UI | 两种主题、桌面／手机、长文件名、多个文件、展开状态、下载、失效与错误，真实截图检查 |
| 部署 | 4 核 8 GiB 等效环境并发队列与资源回收，业务 API 可用性；不擅自在在线服务器运行破坏性测试 |

### 全量回归与破坏性测试范围

- 全量运行公司后端测试和 Web 单元／DOM 测试，以及对应格式、Lint、类型和普通构建检查；浏览器覆盖现有各页面主流程、登录、角色权限、工作、报告及助手。建立请求覆盖清单，新增执行／文件请求逐项包含成功、错误、越权、取消与恢复场景。
- 助手真实模型测试包含普通问答、联网、上传分析、各格式生成、连续修改、公司业务写入和混合任务；交错多用户执行，核对答案、生成文件实际内容、版本及数据库副作用。
- 在可销毁的隔离环境中注入死循环、受控内存／磁盘／进程耗尽、巨量输出、损坏文件、越权路径、符号链接和禁止的网络访问。测试进程及环境也有外层资源上限与超时，避免测试器本身耗尽开发机资源。
- 在排队、启动、执行、导出和发布期间注入断连、重复／乱序响应、终止 worker／执行服务、租约失效和用户取消；验证不重复发布、不串用户、不遗留进程，恢复后队列可继续处理。
- 在测试环境分别以并发 1 验证排队，以并发至少 2 验证同时运行的隔离；使用带不同标记的同名文件核对输出、日志、下载与取消目标。运行超限任务时验证另一个用户和业务 API 仍可用，任务结束后检查资源释放。
- 破坏性测试仅使用测试账号、独立测试数据库和临时存储；不用真实公司资料，不对在线服务器注入故障。验收报告逐项区分通过、失败和未执行，不以单次真实模型成功替代全量回归。

- 确定性测试先覆盖协议、权限、恢复与文件内容；代码执行和安全用真实隔离环境，不以 mock 通过冒充。
- 真实模型语料至少包含上述主要任务族和未用于调提示词的多轮样本；不预先承诺样本数量即可证明所有任务通用成功。固定数据集核对结果，人工检查开放式交付质量，保留调用失败。
- Web 全量回归完成后检查执行镜像与部署配置；本次不涉及 Electron，未受影响的桌面打包与 ASR 推理不纳入上述全量范围。
- 沙盒关闭时的既有 Web／业务流程必须通过；容器或外部模型不可用时记录未测范围，不能标记该项完成。

## 风险与迁移

- 新表增量迁移，原 Markdown 成果不要求补造文件；新客户端兼容无文件字段，旧接口继续可用。
- 执行节点恢复与导出回执应先完成，再允许自动重试，避免发布多份结果或覆盖旧文件。
- 同机内存／磁盘争用与隔离运行时兼容是部署门槛；不能仅提高限制或重试次数掩盖失败。
- 关闭执行功能仍保留历史成果下载。回滚禁止删除文件或恢复到绕过沙盒的执行方式。
- 同机隔离或容量验证不通过时，先报告限制；新增独立执行服务器需另行确认，不自动采购或改用第三方托管服务。
