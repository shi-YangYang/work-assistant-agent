# Spec 042 — 通用助手与沙盒任务执行

## 状态

已实施，独立验收通过。

## 背景

Noria 需要同时承接公司业务与个人求助：用户可以问知识、讨论问题、写作、分析材料，也能委托助手计算、处理数据并交付文件。公司工作管理与汇报是可调用的业务能力，不应成为所有对话的前提。

## 目标

- 用一个聊天入口完成问答、检索、分析、创作、计算和文件交付，不要求用户先创建工作或选任务类型。
- 需要执行时，模型编写代码，隔离环境运行，助手依据真实结果回答；不需要执行时直接回答。
- 支持连续修改同一成果，用户决定是否写入工作／报告。
- 保留现有模型配置、人设、三级执行权限、任务节点、重试、中断与会话恢复。

## 非目标

- 不以本次迭代承诺复刻 ChatGPT、DeepSeek 的全部产品能力或保证任意任务成功。
- 首期不提供浏览器代操作、第三方账号登录、自动发邮件、付款、网站部署、任意宿主机 Shell 或用户安装软件。
- 不新增图像生成、视频生成、模型训练、GPU 推理、跨会话长期记忆和新的 Agent 框架。
- 不改 Electron，不增加独立的成果管理页面或常驻代码编辑器。

## 当前行为

- `agent/policies.py` 已允许普通问答、闲聊、私人材料分析与文稿创作；需要检查实际能力介绍、核对和收尾是否仍将通用任务错误限制为公司业务。
- 已有 `web_search`／`web_fetch`，可以查询公开资料；没有浏览器操作能力。
- 已有附件解析、带版本的 `save_deliverable`／`read_deliverable`、工作与成果关联；成果主要为 Markdown 和结构化条目，没有通用的生成文件交付链路。
- `agent/harness.py` 使用受控工具注册表与虚拟 `StateBackend`；`execute` 明确排除，虚拟文件读取不等于真实代码执行沙盒。
- API、worker 共用公司后端；当前 worker 能访问数据库、模型密钥及媒体目录，不能直接在该进程运行模型生成的代码。

## 目标行为

| 用户请求 | 预期路径与交付 |
| --- | --- |
| “解释递归”“帮我润色这段话” | 直接回答或改写，不查询公司数据、不启动沙盒 |
| “查一下最近的行业新闻” | 现有联网工具获取依据，正文给结论和实际来源 |
| “帮我分析这个销售表，按月份汇总并画图” | 授权文件进入沙盒，运行计算，返回口径、结果与图表 |
| “把结果做成 Excel 给我” | 生成有效文件并持久保存，给真实下载入口 |
| “排除退款订单，再把图改成折线图” | 读取原输入与上一版成果，生成新版本，不要求重复上传 |
| “写个 Python 脚本，帮我运行这个样例” | 在允许的运行环境中执行，返回实际输出与必要解释 |
| “把建议里的前两项加到我的工作” | 沿用成果引用和业务工具，按现有三级权限真正执行 |
| “这次只是聊聊，不要写工作” | 正常协助，不创建工作、建议卡或正式报告 |

## 功能需求

### 1. 通用任务与工具选择

- 任务是否属于公司业务不能成为拒绝普通求助的理由；无须员工、项目、日报等背景即可回答。
- 模型根据当前目标选择直接回答、联网、读取材料、运行代码或业务工具，可在一项任务内组合；不增加每条消息必跑的分类模型。
- 知识解释、翻译、写作和代码说明通常直接完成。需要可靠计算、批量处理、图表或文件时使用执行工具，不能只把代码贴给用户当成执行结果。
- 能执行的代码语言以工具实际能力为准。其他语言仍可解释和撰写，不谎称运行成功。
- 沙盒未启用、资源不足或功能未支持时，说明具体限制，继续完成可完成部分；不得退回宿主机执行或伪造结果。
- 能力介绍、正文交付与结果核对共同认识新增工具和成果回执。普通解释与建议不强制要求公司记录作依据；具体计算、文件和业务成功仍以真实回执为准。

### 2. 首期执行与文件范围

- 首期运行 Python，预装固定版本的数据分析、绘图、表格与文档库，包含中文字体；不在用户任务中任意安装依赖。
- 支持 CSV／XLSX／JSON 数据处理、数学计算、静态图表、基础图片处理与代码样例验证。
- 首期输出 TXT、MD、JSON、CSV、XLSX、PNG、DOCX、PDF、PPTX。支持生成和连续修改演示文稿，文字及常规图形保持可编辑；已有 PPTX 上传解析保持支持。
- 模型可自由编写处理逻辑，不只支持一组固定报表模板；执行资源和可访问数据仍受平台约束。
- 数值结论说明实际使用的字段、筛选与必要假设。空值、重复行、单位、日期与零分母不能默默产生误导结果。
- 文件可打开才算交付成功：检查结构、名称、格式和内容；图表检查中文、单位、图例与数据；文档检查分页和裁切；演示文稿渲染检查文字溢出、元素重叠和中文字体。CSV／表格默认不把不可信文本当公式或外部链接执行。

### 3. 沙盒边界与生命周期

- 提供独立的执行服务与适配接口，模型通过工具使用；不把执行器嵌入 FastAPI／worker 的业务进程。
- 按公司、用户、会话和任务隔离。只放入本次被授权选中的附件／成果副本；有权限的公司资料也须通过原有业务工具读取，再按任务需要传入。
- 一个沙盒服务负责调度多个独立执行环境，不代表所有用户共用一个解释器。每个独立执行请求分配独立进程和文件空间；不同用户、会话和任务不能共用可写目录或 Python 内存，结束后销毁，后续任务重新创建。
- 后端从已认证会话确定公司与用户，将会话、任务、执行 ID 和租约绑定；沙盒实例 ID 仅在可信服务间使用。查询、取消、导出与下载都核对归属，不能仅凭用户提交的 ID 取得权限；结果按执行归属回传，不依赖全局“当前用户／当前会话”。
- 不注入模型 API Key、数据库连接、登录 cookie、应用主密钥，不挂载源码、数据库、全部媒体目录或容器控制 socket。生成代码不能调用内部业务 API。
- 首期执行环境默认断网；联网信息由现有工具获取。网页、文件和执行输出都是数据，不能改变权限或新增授权。
- 限制 CPU、内存、进程、磁盘、输出大小、执行时间和全局并发；超过限制给可理解的结果，不拖垮聊天与业务服务。排队支持中断。
- 容量不足时排队，到达执行时再创建环境。设置用户排队配额与公平调度，避免单个用户占满队列；取消、失败和超限只影响所属执行。提高并发只增加同时运行的独立环境，不降低隔离要求。
- 沙盒文件与 Python 内存是临时状态，不能成为多轮对话的唯一数据来源。输入引用、脚本、运行记录和已交付成果可在后台恢复；后续任务用这些持久信息重建，不要求容器永久在线。
- 中断、超时、失去任务租约后停止执行及其子进程；迟到结果不得发布。任务结束回收环境，服务重启后清理孤儿任务与临时文件。
- 普通容器不能被视为绝对安全边界。生产开放任意生成代码前须验证强化隔离运行时；同机条件不足时评估独立的自部署执行主机。能力不足时禁用执行，不静默降级为宿主 Python。

### 4. 重试与结果真实性

- 执行请求拥有服务端生成的稳定身份，绑定任务、节点、输入版本与代码摘要。响应丢失先查询同一请求，不能重复启动执行。
- 基础设施暂时故障复用现有节点重试机制和次数；确定的语法／数据错误返回模型，允许在任务预算内修改代码后再次执行，不盲目重复相同失败代码。
- 代码修改属于新的执行尝试，有独立输出；不与基础设施自动重试混为一谈。安全拒绝、缺依赖和用户中断不得通过换代码规避。
- 退出成功、文件可用和内容正确是不同条件。助手依据退出状态、计算输出、校验结果和已保存文件回答，不只凭模型文字声称完成。
- 部分成功保留已交付文件，明确剩余失败；重新生成采用新版本，不覆盖用户已下载或引用的旧版本。

### 5. 持久成果、权限与清理

- 扩展现有 `Deliverable` 及其版本体系，为生成文件增加元数据与授权下载，不新建一套与现有成果重复的产品。
- 数据库保存归属、版本、文件标识、大小、摘要、来源与执行关系；二进制使用现有媒体存储体系的独立命名空间，禁止把大文件/base64 放入会话 JSONB。
- 已交付文件随所属会话保留，不设置默认短期失效；临时执行环境及时销毁。会话／账号删除与源资料权限变化沿用现有访问规则，并同步使相关派生成果不可访问、清理无引用文件。磁盘配额耗尽时停止新增并明确提示，不静默删除已交付成果。
- 用户通过认证接口下载，服务端生成路径与文件名；模型不能指定任意磁盘路径或伪造下载 URL。禁止路径穿越、符号链接、特殊文件和超限输出。
- 文件默认仅本人可见，管理员不自动获得员工私聊成果。下载、预览、再输入和发布前都重新检查身份与源权限。
- 再次引用生成文件复用既有成果引用方式与版本语义，不要求用户先下载再上传。公司业务记录仅在用户要求时更新。

### 6. 极简交互

- 保留同一输入框、附件入口、人设和权限选择，不增加“通用／公司／代码模式”按钮。
- 复用节点列表，按真实执行展示“运行代码”“生成文件”“修正代码”“等待执行资源”等状态；保持展开状态、中断与重试体验，不新增持续轮询。
- 结果以正常聊天正文、图表和紧凑文件条目展示；文件提供名称、格式、大小、版本与下载，主要操作只有查看／下载，继续修改用聊天。
- 代码和执行详情按需展开；默认不展示容器、PID、内部路径、原始堆栈或私密环境信息。
- 预览不在应用同源环境执行生成的 HTML／JS／宏；首期图片和已有安全文档预览按类型处理，其他类型下载打开。
- 遵循现有黑白灰、全屏画布与 CSS Modules，覆盖浅／深色、手机、长名称、多个文件、加载、失败与失效状态；普通问答不堆文件卡。

## 边界条件

- 三级执行权限继续控制业务写入；私有材料计算和成果生成不逐次弹确认，“自主执行”也不扩大沙盒网络、文件或公司数据权限。
- 同一会话继续沿用单任务执行约束；不同用户可以排队，不因一个超时任务长期占用所有资源。
- 输入已删除、附件解析失败、文件损坏、同名文件、多表数据、旧成果引用、会话压缩与断线恢复都要有明确行为。
- 沙盒能执行代码不保证 LLM 数学解释、搜索覆盖或第三方模型审核一定成功；应如实说明能力边界与失败原因，不绕过模型服务规则。

## 技术约束

- 复用当前模型供应商和工具调用协议，不强制迁移 OpenAI API，不让每个模型单独实现沙盒。
- 保留现有队列、租约、节点重试、幂等、任务快照和 SSE；执行器的内部状态与这些机制对齐，不建立第二套聊天任务系统。
- 采用自部署 CPU 执行服务，不接入第三方托管沙盒。先按现有 4 核 8 GiB 场景设计小并发，再以隔离与资源实测决定能否同机试点；新增服务器另行确认。不部署 GPU 模型，不引入 Kubernetes。
- 后端保持 `apps/server/app/{agent,modules,integrations,tasks}` 分工；独立执行服务放在 `apps/sandbox/`。

## 兼容性要求

- 老会话、原附件限额、原成果与下载、工作／报告、两套人设和权限语义保持兼容。
- 新功能可关闭；未配置执行器时普通问答和现有业务照常使用。
- 新表和字段增量迁移；关闭功能／回退应用不删除已交付文件，保留授权下载的兼容路径。

## 验收标准

- [x] 知识、翻译、写作、代码解释在无公司工作记录时正常完成，不多余执行或写业务。
- [x] 已知答案的数据集完成汇总、清洗、图表和文件生成，核对数值、单位与文件实际内容。
- [x] “上传 → 分析 → 下载 → 连续修改 → 引用旧版本”闭环通过，沙盒被回收后仍能继续。
- [x] 用户明确选择内容后才写工作／报告，三个权限档和管理员／员工边界无回归。
- [x] 执行失败可合理修复，中断停止子进程，迟到结果被拒绝；重复请求、响应丢失和 worker 重启不重复执行或发布。
- [x] 跨用户／公司／会话、角色变更、账号退出、文件删除和来源失权均不泄露输入、日志与成果。
- [x] 多用户及同一用户不同会话交错执行，同名输入／输出不覆盖、不串数据；排队公平、取消不误杀，顺序复用容量不残留文件或内存，并发上限可验证。
- [x] 网络、宿主文件、密钥、容器控制接口不可访问；无限循环、内存和磁盘耗尽、进程泛滥、恶意输出受到实际限制。
- [x] 真实浏览器验证桌面／手机及错误状态；文件能实际下载和打开，图表和文档经过视觉检查。
- [x] 在部署目标同等配置上验证队列、资源回收和 API 响应，不以开发机通过替代生产隔离验收。
- [x] 真实模型样本和确定性检查分开记录，未知题材与多轮改写纳入；如实报告失败，不以提示词命中几个例子宣称通用任务全通过。
- [x] 完成 Web 前后端全量回归与沙盒破坏性测试，覆盖各请求类别及多流程任务；记录覆盖清单、失败与未测项。故障注入仅使用可销毁的测试环境、数据库和文件，不影响真实用户与在线服务。

无。首期包含 PPTX 生成，沙盒自部署，已交付文件随会话保留。
