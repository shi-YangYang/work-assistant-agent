# 实施计划

对应[规格](spec.md)与[测试矩阵](test-matrix.md)。实施与验证按以下顺序进行。

## 模块分工

- `tasks/budget/`：策略与状态模型、原子预占、轮次生命周期、收尾判断、内部预算快照；不依赖具体工具或前端。
- Agent 运行适配：将模型／工具执行接入预算，在每轮主模型请求注入临时快照，工具耗尽后转入收尾。
- 交付适配：预留模型收尾机会；硬上限下复用现有回执／正文交付和本地校验，避免丢结果或重做业务。
- 反馈与 Web：沿用 Job DTO、SSE、订阅和任务进度组件，只投影用户可见活动、耗时与结果，不传递内部预算。

## 修改顺序

1. 固定现有普通问答、研究、业务和沙盒旅程的调用路径与计数基线；记录会影响新额度的全部聊天限制，区分无关资源限制。
2. 实现纯预算策略与状态计算。将初始化、计数、截止、提醒和收尾预留收敛到同一来源，按任务轮次冻结配置。
3. 接通持久化预占与恢复。复用现有租约／锁与节点／用量事务；先恢复已有结果，再判定是否需要新预占。明确预占完成后崩溃的保守计数。
4. 接入 worker、模型、工具和 LangGraph。统一聊天执行路径，包括同步辅助模型；调整派生图步数、节点容量与累计输入保护，保留非聊天作业现有政策。
5. 实现软收尾、硬上限降级、主动中断与旧任务适配；验证手动重试刷新预算但不重复写入。
6. 核对现有事件与进度契约，必要时补充执行阶段和计时信息；隔离内部预算，处理旧 DTO、断线、终态、乱序和新轮次。
7. 执行矩阵内必要测试，修复直接相关问题；由新的独立验收 Agent 检查规则、证据、权限、性能和 UI。

高度耦合的运行、持久化与前端协议由一个实施 Agent 串行完成；实施完成后创建独立验收 Agent。

## 数据流与状态

1. worker 开始消息处理时创建 `Job.result.taskBudget`；策略版本、执行轮次与计时先于材料准备。节点 scope 仅用于结果恢复，不决定预算重置。
2. 模型／工具申请 → 校验租约、轮次、截止和阶段 → 同事务预占并记录唯一消费 ID → 释放事务 → 外部执行。
3. 节点结果和消耗关联；恢复已有输出无需再扣，实际模型重试另占一次。保留不确定调用的消耗，防止崩溃窗口超额。
4. 用户可见活动变化触发现有 feedback seq 更新；Job 与 SSE 共用进度投影，不携带预算。单纯内部计数或提醒阈值变化不增加公开事件。时间阈值由已有运行观察任务调度，不增加客户端轮询。
5. 每轮主模型请求读取快照，临时注入；执行中、提醒与收尾均由服务端判定。收尾预算仅允许指定答复路径使用。
6. 终态持久化结束时间、消耗与原因；手动重试创建新轮次，旧 SSE 事件和旧 worker 不能覆盖新轮次。

预算 JSONB 保留版本化当前状态及必要的有界恢复标识，不另建完整事件账本。不要保存每秒倒计时快照。

## 接口变化

不新增公开 `budget` 字段或预算查询接口。`Job.result.taskBudget` 仅由服务端使用，序列化时不得直接展开到 Job、SSE 或节点详情中。

现有节点、活动与计时字段足够表达执行和收尾，Web、共享类型、Job DTO 与 SSE 无需新增字段或组件。临时澄清／确认沿用新 Job，主动重试在既有 `reopen_failed` 内重置预算，不改对应路由。

模型运行时快照可包含剩余额度；用户答复仅说明结果与未完成范围。保持现有 `attempt/fence/seq` 事件顺序，时间基准只用于时钟校准，不触发每秒业务事件；旧客户端与旧消息格式保持兼容。

预算收尾允许可选隐藏头 `remaining`，只表述具体未完成项；普通正文不多填任务表单、不新增模型核对。服务端已观察到的未执行项不能被空列表消除，完成的答复不会仅因额度到阈值被改成部分完成。

内部错误区分提醒、收尾、硬耗尽和独立网络故障；预算停止不自动按网络失败重试。对用户输出经过映射的结果说明，工具原始预算错误不得透传；业务成功回执和状态不因预算阶段改变。

## 派生限制与性能

- 图步数根据实际 middleware／model／tool 超步关系推导，不能简单等于工具数；用最长合法受控串行路径证明不会抢先终止。
- 节点总数容纳新预算与有界历史；恢复所需节点输出不得为腾空间被提前删除。输出大小与缓存上限不随调用次数无限增长。
- 累计输入保护随模型调用预算一致调整，保持每次真实上下文容量检查；不恢复固定输出 token 上限。
- 模型用量、节点创建及预算消费尽量合并事务；不新增逐 token SQL、模型核对或额外公共查询。
- 定向比较普通回答和工具任务的请求数、SQL／事件量与首字／总耗时；外部模型波动与应用开销分列。

## 测试计划

实施属于 S3：涉及持久任务恢复、核心执行基础设施和公共反馈契约。执行[矩阵](test-matrix.md)内直接相关模块及组合流程，不默认全站重测或桌面打包。

- Python：隔离数据库／Redis 下运行预算新测试及受影响的 retry、interrupt、model deadline、tool catalog、reply stream、task progress 模块；业务、记忆、文件恢复复用现有定向用例。
- Web：使用项目现有 Vitest 配置运行执行阶段、任务进度、事件连接及任务同步测试，验证不展示内部预算；公共类型变化执行 Web typecheck，修改源码按项目格式化器处理。
- 浏览器：已有 Playwright 隔离环境执行预算旅程，并查看桌面／窄屏进度展示。受控小时钟验证长任务，不为时间边界真实等待 30 分钟。
- 真实模型：普通问答、跨多个网页研究、业务写入后继续分析、文件生成四条旅程；冻结配置，采集真实请求与工具次数、首字／总耗时和结果。只验证机制与交付，不因字数、文风或一般知识偏差反复调模型。
- 不将受控测试、真实模型测试、沙盒真实执行、远端 CI 互相替代。修改内容不涉及部署，不触发 CD。

## 迁移与回滚

- 不新增 schema migration。新任务采用新策略；旧在途任务按原计数与截止时间惰性适配，历史任务只读兼容。
- API、worker 与前端按同一版本部署，发布前停止／排空旧 worker；这是使用既有发布流程，不新增发布系统。
- 回滚前结束或停止新版在途任务，保留已提交业务与成果。旧版本可忽略新增预算 JSONB，不能宣称旧代码可以继续执行新版扩大额度的在途任务。

## 风险

- 增大额度使单个长任务占用 worker 更久：保留中断、独立槽位与现有并发，通过长短任务并行场景验收。
- 辅助模型绕过预留或并行超发：统一消费入口，额度不足时先拒绝新操作，不能先写业务后补授权。
- 预算重置诱发重复业务：预算轮次与业务幂等键分离，复用真实回执，验证重试与恢复竞态。
- 硬截止丢失成果：提前预留，超时后本地有界保存；任何未获成功回执的操作保持未知或未完成。
- 反馈引入耗时、闪烁或额外请求：共用事件、状态稳定、客户端计时，验证请求计数与布局。
