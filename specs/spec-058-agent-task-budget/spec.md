# Spec 058：Agent 统一任务预算与进度反馈

## 状态

已实施，独立验收通过。首次验收发现的交付校验遗漏已修复，见[返工验收](acceptance-rework.md)；实际测试范围和既存失败见[实施报告](implementation.md)。

## 背景

复杂搜索任务会在收集资料时碰到工具上限。现有约束分散在模型、工具、节点与图执行入口，模型无法提前安排剩余操作，用户也难以判断任务是否仍在推进。

## 目标

建立可复用的任务预算机制，集中管理配置、消耗、恢复、收尾和反馈。支持普通问答、公开搜索、业务操作、记忆、附件处理及沙盒任务；有足够依据时及时交付，不要求耗尽预算。

## 非目标

- 不新增管理员配置页、用户额度选择器或独立进度面板。
- 不改变模型、思考强度、人设、业务授权、跨账号隔离与操作确认规则。
- 不恢复二次模型核对，不增加预算判断模型，不强制限制单次输出 tokens。
- 不扩大沙盒 CPU／内存／并发／单次执行时限、附件与响应体大小限制。
- 不统一放大网络故障等待；节点自动重试仍最多 3 次，即首次执行加 3 次重试。
- 不扩大独立报告、文档解析后台作业的运行额度，不改部署拓扑与 CD。

## 当前行为

| 约束 | 当前实现 |
| --- | --- |
| 工具调用 | 当前执行 scope 最多 16 个工具节点；达到 14 个时要求收尾，所有工具共用 |
| 模型调用 | 聊天执行最多 32 次实际调用；达到 29 次时要求收尾 |
| 总时限 | 节点初始化后 420 秒，worker 外层另有 450 秒；附件准备尚未统一纳入 |
| 图与节点 | 图执行限制 36 步，持久节点总数上限 96，分别独立判断 |
| 恢复 | 自动恢复、输入 scope 变化及手动重试使用不同计数重置路径 |
| 反馈 | 有节点、正文流和耗时显示；没有统一剩余预算快照，临近上限时才提示收尾 |

## 目标行为

任务开始 → 冻结预算策略 → 调用前原子预占 → 执行与记录结果 → 更新模型内部预算与用户可见进度 → 正常完成，或预算临近上限时收尾 → 保存实际结果。

### 初始配置

| 项目 | 值 | 含义 |
| --- | --- | --- |
| 本轮执行总时限 | 1,800 秒 | 从 worker 开始本轮消息处理起计时，不包含队列等待 |
| 工具调用 | 64 次 | 实际启动的逻辑工具调用数，含失败调用 |
| 模型调用 | 96 次 | 实际请求次数，包含自动重试和同步辅助模型 |
| 内部提醒阈值 | 剩余工具 8 次、模型 12 次或时间 180 秒 | 任一满足即提醒模型，仍可完成必要操作；不向用户展示额度提醒 |
| 收尾预留 | 模型 3 次、时间 120 秒 | 探索阶段不得消耗；专供答复与必要的本地交付处理 |
| 图步数、节点容量 | 从上述额度推导 | 覆盖框架中间节点、重试与恢复，不早于业务预算截断 |

以上为产品起始配置，不是完成目标或行业统一标准。配置仅有一个服务端来源，新轮次冻结策略版本与取值，在途任务不随配置修改忽然增减。

## 功能需求

### 统一预算模块

- 提供策略、初始化、快照、调用预占、阶段判断和结束接口；工具实现不自行维护额度或拼接预算提示。
- 运行状态存入现有 Job JSONB，以 `job + 执行轮次` 隔离，不按整个会话累计。状态包含策略版本、限额、开始／截止／结束时间、调用计数、预占标识、阶段与触发原因。
- 阶段为执行中、接近上限、收尾中、已结束；工具次数、模型次数、时间和框架保护各有可辨识原因。
- 复用任务租约与事务锁，保证并行调用原子预占；实际请求不能超发。预占后外部结果不确定时保留消耗，不乐观退还。
- 不把完整工具输入、模型输出、密钥或隐含推理存入预算状态；消费标识有界，仅用于幂等。
- 复用现有节点与用量事务，不为每个 token 增加数据库读写或阻塞正文流。

### 计数、重试与恢复

| 场景 | 规则 |
| --- | --- |
| 首次执行工具 | 预占 1 次；同批 N 个工具各占 1 次 |
| 工具失败后自动重试 | 同一逻辑调用继续使用原工具名额；消耗真实时间，仍受单节点重试限制 |
| 模型自动重试 | 每次实际请求均计入模型额度；只恢复已有结果不计数 |
| 工具定义发现 | `load_tools` 不占工具额度；触发发现的模型请求正常计数 |
| 同步辅助模型 | 意图授权、内容转换、压缩等归属当前聊天执行时，共用模型额度 |
| 读取工具缓存 | 新发起的一次工具调用正常计数；恢复同一节点的已保存输出不重复计数 |
| 输入 scope／版本修复 | 可重建图或重新读数据，但继承本轮已消耗额度和截止时间 |
| worker 重启／租约交接 | 继承持久预算；停机时间仍计入当前截止时间，不免费重置 |
| 浏览器刷新／重新连接 | 恢复当前任务进度，不改变或向浏览器返回内部预算 |
| 用户主动重试 | 开新执行轮次，获得完整新预算；沿用业务幂等回执，不重做已成功写入 |
| 等待澄清或确认 | 结束当前活动轮次，冻结耗时；用户回答后按现有续接任务开启新轮次 |
| 异步报告／沙盒作业 | 父任务计发起工具与实际等待；子服务沿用自身限制，不双计或暗中放大子作业额度 |

材料准备、同步工具等待、模型思考／生成、退避等待均计入本轮时间。纯排队、已结束后的人工等待不计；不占用 worker 空等用户。确认卡只授权其对应操作。

### 给模型的反馈

- 每轮主模型请求前注入一份简短的服务端预算快照：剩余工具次数、可用于探索的模型次数、剩余总时间、当前阶段。
- 示例：“还可调用工具 12 次，探索模型请求 8 次，剩余 180 秒。优先补齐关键依据，信息足够就直接回答。”
- 临近上限提示缩小到必要步骤；收尾阶段撤掉工具并要求交付已有结果、说明未完成范围。
- 使用运行时临时消息或指令，每轮替换；不追加进会话历史、长期记忆或上下文摘要，不持续改变可缓存的固定系统前缀。
- 明确预算仅供安排执行，不在用户答复中复述调用次数、限额、预留或内部停止原因；需要收尾时说明已有结果和未完成范围。
- 后端执行强制约束，不能依靠模型自行遵守。并行批次不得超过剩余额度；不足时执行已获预占的项，其余返回明确未执行结果。

### 收尾与中断

- 工具额度耗尽、探索模型额度耗尽或进入时间预留区时，停止新探索，进入收尾。达到提醒阈值本身不强制失败。
- 已在执行的合法调用可在总截止时间内完成；收尾阶段不再发起业务写入、网页读取或新沙盒执行。
- 预留额度用于最终答复；必要的协议修正仍受同一总预算约束，不开展额外模型核对。
- 总期限或全部模型额度耗尽后，不再请求模型；执行有界的本地保存与资源清理。依据现有授权回执、已保存成果与安全正文片段交付可用结果，不能伪造完成或泄露原始工具内部数据。
- 有实际未完成项时使用现有 `partial`／`blocked` 结果表达，不把“本轮结束”展示为“全部完成”；已经完成用户目标时允许正常结束。
- 内部区分预算停止与网络故障，不把前者当网络失败自动重试。对用户说明已完成与未完成内容，不显示“工具额度已用完”等内部原因。停止后不保留“等待执行”或持续转动的节点；沿用既有重试、继续提问和中断入口，不新增按钮。
- 中断优先于预算收尾；中断、断线、超时不能回滚已提交业务，也不能将结果未知的写操作盲目重复执行。

### 给用户的反馈

- 复用消息下方现有任务进度区域，仅展示真实活动、已用时间和执行结果。不增加预算组件，不显示已用／剩余调用次数、总限额、预留额度、剩余执行时间或额度警告。
- 保持“思考中 · N 秒”和现有文字光带；搜索、读取网页、执行代码等使用真实节点名称。已有工具活动时不重复展示无依据的模型活动。
- “等待模型响应”只能依据实际调用状态展示；不暴露思考链，不生成虚假进度、预计完成百分比或费用提示。
- 接近预算上限不新增用户提示。实际进入收尾时可在同一区域显示“正在整理结果”；结束时说明完成了什么、还缺什么，不在输入框、页面顶栏复制提示。
- 从现有任务 SSE 和 Job DTO 接收进度；时间由服务端时间基准加浏览器本地计时展示。只推送用户可见的活动变化，不因内部预算计数变化单独发事件，不新增周期 GET／POST、SSE 连接或预算接口。
- 计时不每秒写数据库。服务端独立检查截止和阶段转换；内部接近上限不映射为虚假的新活动，当前工具仍在执行时继续显示真实工具状态。
- 保持折叠状态、稳定布局与已有防闪烁逻辑；结束后停止计时。断线时沿用既有提示，不把本地计时误报为仍有服务端进展。
- 刷新、切换会话、多标签页和重连按任务身份与 `attempt/fence/seq` 接受进度，必要时增加轮次标识；旧事件不得覆盖新一轮状态。

## 边界条件

- 0 次工具的普通回答；恰好达到上限；同批跨越上限；失败调用、自动重试、取消与额度耗尽同时发生。
- 长时间 max 思考、有正文增量、只有连接心跳、真实网络断开分别处理；任务时限增加不延长独立网络静默判定。
- 授权模型也计数；不足以完成授权的写操作不得先执行。不能让共享的“收尾额度”被辅助模型绕用。
- 缓存／回执恢复须先过现有权限、来源与版本校验，预算可用不代表获准操作。
- 30 分钟任务仍受现有 worker 槽位和沙盒并发约束，不新增并发。验证一个长任务不会跨账号抢占预算或阻止其他可用槽位处理短任务。

## 技术约束

- 保持现有 FastAPI、Deep Agents／LangGraph、PostgreSQL、Redis 和 SSE 结构，不新增依赖或计费系统。
- 统一任务预算取代聊天路径中的散落常量；框架与存储保护仍有界，不能简单关闭或无限放大。
- 非聊天作业、网络超时、单节点重试、业务单次批量限制、沙盒资源限制保持各自职责。
- 不增加模型往返，不因更新进度刷新会话全文，不改变正文先流式输出、最终统一持久化的分工。

## 兼容性要求

- 预算留在服务端持久状态和模型运行时输入，不进入公开 Job DTO、SSE、节点详情或用户错误信息。优先复用已有进度字段；确需补充时仅增加可选执行阶段／计时信息，旧消息缺失字段时沿用现有展示。
- 使用现有 JSONB，不新增数据库表或 schema migration。历史作业不批量回填，读取历史消息不触发预算创建。
- 旧在途任务首次由新版执行时，从已存截止时间、节点和调用计数构造旧策略快照，不能自动获得全新 30 分钟预算；用户明确重试后采用新策略。
- 发布和回滚按已有流程停止／排空旧 worker，禁止同一轮由新旧计数逻辑交替执行；已保存结果与业务回执始终可读取。

## 验收标准

- [ ] 限额、阈值与预留来自同一策略；30 分钟／64 次工具／96 次模型和派生保护配套生效。
- [ ] 受控任务超过旧的 16 工具、32 模型、36 图步和 420 秒边界仍能继续，在新边界准确停止。
- [ ] 并行预占、自动重试、缓存恢复、worker 重启、输入修复及用户重试按规则计数，无绕过与重复扣减。
- [ ] 模型每轮看到最新快照，临近上限能收尾；无额外模型调用、消息历史污染或成功操作重放。
- [ ] 用户在同一进度区域看到真实活动、耗时与结果；刷新与乱序事件不闪烁、不重置、不混用账号数据。
- [ ] API、SSE、页面、节点详情和最终答复不暴露内部预算；不新增额度组件、倒计时或接近上限警告。
- [ ] 用尽预算可保存可用结果，准确表达未完成范围；网络故障、人工等待、中断独立处理。
- [ ] 普通聊天、搜索、公司业务、记忆、附件、沙盒与多流程组合完成定向回归；两种角色均有覆盖。
- [ ] 修改前后的真实模型旅程保留调用次数、首字／总耗时和实际执行结果；不承诺开放答案语义绝对正确。
- [ ] 独立验收记录通过、失败、未执行及环境限制，不以 mock 或测试时钟替代真实端到端证据。

## 待确认问题

无。采用以上初始配置，预算仅供模型与服务端使用，用户沿用现有进度区域；实施过程中若涉及新增产品入口或扩大业务权限，应另行确认。
