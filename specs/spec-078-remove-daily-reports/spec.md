# 移除日报功能，仅保留周报

## 状态

已实施并通过[独立验收](acceptance.md)，旧日报确认等待遗漏已修复。历史日报正文、修订及关联业务快照直接删除的迁移已在隔离库验证；尚未部署或执行真实用户库迁移。

## 背景

产品将停止提供正式日报。日报与周报共用报告模块，不能只删除前端的“日报”切换按钮：旧接口、助手工具、定时调度、历史待办及任务恢复都可能继续读写日报。

## 目标

- 从员工、管理员、助手工具和后台任务中移除正式日报能力，报告业务只支持周报。
- 同步清理日报配置、待办、提醒、统计、快捷建议和有效使用文档，避免留下可以继续生成或提交日报的入口。
- 保留周报的完整生成、修改、版本、提交、来源、删除后重建和汇报安排能力。

## 非目标

- 不删除工作、工作进展、原始上报消息、附件、会议或聊天记录；这些不是日报功能。
- 不取消周报定时生成及提醒，不取消公司时区或员工汇报资格保护。
- 不限制通用聊天写作：用户可以要求一段按天总结的文字，但系统不再将其保存、提交为正式日报；移除主动推荐日报的产品入口。
- 不改写历史 Spec、历史验收证据和已执行的数据库迁移，不把所有出现 `daily` 的内容一律删除。
- 不新增历史档案页面，不重命名整个 reports 模块，不增加独立模型节点、模型调用或重试。
- 不修改生产数据，不部署或推送。

关键代码依据：

- `apps/web/src/features/reports/components/overview/ReportsOverview.tsx`、`ReportObligations.tsx`：页面和待办默认 daily。
- `apps/web/src/features/team/components/TeamWorkspace.tsx`、`report-period/`：团队日报入口和按天选择。
- `apps/server/app/modules/reports/schemas.py`、`router.py`、`scheduling/`：公开契约、读写与安排。
- `apps/server/app/tasks/maintenance/scheduling.py`：当前周期和历史补偿两条调度路径都需要收口；只改 daily／weekly 循环不足以关闭旧安排。
- `apps/server/app/modules/reports/commands.py`、`modules/operations/receipts.py`：缓存回执、旧待办、生成后提交也可绕过新页面入口。
- `apps/server/app/modules/team/metrics.py`、`sources.py` 及共享业务读取：报告统计与来源展开并非全部带 kind 过滤。

- 日报实现集中在公司 Web／API／worker；本次源码搜索未发现 Electron 会议端的独立日报实现，不安排桌面重构。

以上为当前源码调研，未查询生产数据数量或生产任务状态。

## 目标行为与功能需求

1. 正式报告只支持 weekly。新页面与缺省请求均进入周报；移除日报类型选择和按天生成。团队工作自己的日期筛选不受影响。
2. 保留既有报告路径及共享动作名称。需要保留的 `kind`／`report_kind` 字段限定为 weekly，缺省改为 weekly；明确传入 daily 的请求必须拒绝，不能悄悄生成周报。
3. 列表、按 ID 访问、历史修订、来源展开、详情抽屉、候选采用、编辑／提交／删除、待办准备和工具调用全部遵循同一支持范围。拒绝旧日报前仍执行所属公司与权限保护，不能泄露其他人的记录是否存在。
4. 旧日报列表链接可回到周报列表并提示能力已移除；旧日报详情、来源和操作链接显示不可用，不能跳到另一份周报。历史聊天文字保留，相关卡片不再提供有效日报操作，也不能将旧日报快照误标成周报。
5. 删除日报配置输入、输出和默认值。现有公司中的 daily 配置及日报计划按迁移方案停用／清理，不能在首次调度或历史追赶中重新创建；周报配置、版本、时区及生效周期不重置。
6. 旧日报待办退出进行中的待办列表、逾期统计和通知计数。移除其通知，不恢复其汇报义务；周报待办及通知不受影响。
7. 关闭旧日报 queued、running、failed、awaiting_retry、awaiting_input 等任务的继续执行路径。任务启动、恢复、保存和后续提交都核对报告类型，沿用租约与版本保护；在途响应不能继续写回或自动提交日报。
8. 历史幂等请求和业务操作不能直接复用旧日报成功回执，等待续接不能永久等待已停止的任务。清理与防护仅针对日报关联记录，不能清空全部聊天 checkpoint、任务、操作或幂等表。
9. 删除助手主动建议、工具描述和能力说明中的正式日报能力；普通写作与正式保存保持区分。用户明确要求正式日报时告知已取消，不能把请求擅自改为周报并执行。
10. 周报来源、事实核对、授权、原文／来源版本、幂等、并发与删除后重新生成保护保持有效。

## 历史数据方案

直接删除既有日报，包括未提交、已提交和已删除日报残留的正文、候选、历史修订及关联业务快照，不建设数据库正文档案或只读日报页面，不自动转换成周报。

迁移先识别日报及关联任务／操作／待办，再清理日报通知、安排、待办和公司 daily 配置；撤销任务与操作的继续执行能力，清除任务结果、业务回执和幂等缓存中的日报内容／成功结果；最后按外键顺序删除日报修订及主记录。可保留不含正文的失效标记与必要审计元数据，使旧链接与等待有明确终态。不能仅设置 deleted 而留下日报正文。

关联业务快照是结构化日报结果、候选和回执，不包括用户原始聊天文字或普通写作；不能按“日报”关键词整段删除聊天。旧来源凭据失效，不级联删除原始工作进展、周报来源、上传材料或其他业务记录。涉及日报的上下文只定向失效，不清空整库 checkpoint。

执行真实数据库清理前有可恢复备份，并停止旧 API／worker 的日报写入；破坏性迁移不提供恢复正文的假 downgrade，恢复需备份。本次开发和验收使用隔离测试库，不执行生产清理。

## 技术约束与兼容性

- 原位精简 reports／team／operations／tasks／agent 边界，优先复用统一查询和动作校验，避免每页各补一套规则。
- 使用新增迁移，不改历史迁移。共享表中的 kind 可继续区分旧记录；不得为了删日报而误删周报表、索引或来源快照。
- 迁移与 worker 升级有明确顺序；不能让旧版 worker 在迁移后重新执行日报调度。失败时保持事务一致，回滚采用确认的数据策略。
- 文档调研按 S0 检查范围、引用和 diff；实施涉及公开契约、迁移、共享任务与权限边界，按 S3 运行受影响子系统检查，不运行全仓矩阵或真实模型评测。

## 验收标准

- [x] 员工、管理员、手机与桌面 Web 共用入口不再显示正式日报或日报配置，报告默认周报；已检查源码及相关 DOM，未运行完整浏览器视觉验收。
- [x] 工具 Schema、API、旧 ID、旧参数、来源访问和已持有操作凭据均不能继续提供正式日报能力。
- [x] 日报当前调度、历史补偿、待办准备、提醒和未读计数停止，周报保持正常。
- [x] 旧日报任务重试、恢复、迟到响应、生成后提交及幂等回放均不能恢复日报；等待能够明确结束。
- [x] 团队列表、报告统计、员工报告与助手业务查询仅返回周报；原始工作和进展仍然可用。
- [x] 隔离库验证历史日报正文、候选、修订与关联业务快照清理，旧任务不能重建；迁移保留周报、工作、附件、聊天和必要审计关系，真实用户库尚未执行。
- [x] 周报的生成、来源、修改／候选、提交、删除重建、权限与租约保护的相关检查通过。
- [x] 使用文案和当前有效测试同步，历史验收结果未伪改；普通写作仍可使用。
