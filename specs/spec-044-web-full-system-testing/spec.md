# Spec 044 — Web 全功能与破坏性测试

## 状态

部分修复，尚未全部通过。状态、工作字段、查询依据、联网失败恢复及数值场景已定向复测；S04／F04 技术条件准确性仍未达标。首轮及返工失败均保留，见[返工说明](rework-implementation.md)和[独立返工验收](rework-acceptance.md)。

## 背景

Web 已涵盖对话、任务执行、工作、报告、团队管理、模型配置与沙盒。已有单元、接口和专项评测，但分散的通过记录不能替代当前版本的完整业务验收。

上一轮目录整理记录了 Web 516 项、公司后端 695 项通过，以及部分浏览器操作；这些是历史依据，不算本次执行结果。现有正式 Playwright 配置主要覆盖 Electron，Web 的完整浏览器流程需要补齐。

## 目标

- 覆盖当前 Web 所有页面、可见操作及其 API、worker、模型和沙盒依赖。
- 同时检验正常流程、输入边界、权限隔离、失败恢复、并发一致性及实际 UI。
- 用员工和管理员的完整任务验证助手，检查真实数据和成果，不只检查回复是否说“成功”。
- 形成可重复运行的测试资产、明确的缺陷清单和可追溯的验收结论。

## 非目标

- 不测试 Electron 本地会议、桌面推理、安装包和移动原生 App；Web 桌面登录授权页及其服务端协议纳入。
- 不攻击线上服务、第三方模型、钉钉或外部网站，不改线上配置或部署。
- 不借测试改变产品规则、重构无关模块，或新增当前尚未承诺的业务能力。
- 不把“全量”表述成全部可能输入、100% 代码分支覆盖或所有设备均无缺陷。

## 当前行为与覆盖依据

盘点以当前代码为准：

- 页面：`apps/web/src/app/App.tsx`、`AppRoutes.tsx`、导航、功能组件和弹窗。
- 请求：各 feature 的 `api/`、公共请求层、SSE、上传、预览和下载。
- 后端：`apps/server/app/http/routers.py`、实际注册的 OpenAPI 操作、worker 任务及 Agent 工具。
- 既有测试：`tests/web/`、`tests/server/`、`tests/sandbox/`；真实评测复用 `scripts/benchmarks/`。

不能将已有请求契约中的 mock 调用算成真实 API 测试，也不能将直调 harness 算成浏览器 → API → worker 的完整验收。

## 目标行为

每项功能都能回答：谁可以操作、正常结果是什么、失败会怎样、数据是否正确、由哪个用例验证。测试结果关联代码提交、环境、用例、执行方式与证据。

### 1. 覆盖清单

- 实施时冻结页面、操作、`HTTP 方法 + 路径模板`、异步任务和工具清单，与[功能矩阵](matrix.md)逐项对应。
- 每个页面覆盖有权限角色的主要操作、深链接及刷新；受限页面补无权限访问。
- 每个纳入的 API 操作覆盖成功和适用的鉴权／归属／输入失败。文件 URL、SSE、回调和动态 action 分支单独列出，不能只数 URL。
- 每个持久写入覆盖实际落库；支持幂等的接口补重复请求，不支持幂等的操作检查现有并发／版本契约。
- 不适用项写原因；未执行、失败和受阻分别记录，不能静默跳过或从覆盖分母删除。

### 2. 全功能浏览器验收

范围包括登录与会话、导航、助手、附件／录音、工作、报告、团队看板、成员、模型服务与用量、声纹、钉钉、账户、外观、汇报规则、通知和反馈。

- 使用真实本地前后端与测试账号完成业务操作；外部故障可由明确标记的可控服务注入。
- 每个独立页面查看实际截图；列表检查空态、有数据、加载和错误，关键弹窗检查打开、提交、关闭与恢复。
- 检查白屏、遮挡、横向溢出、滚动、字段错误、按钮禁用、焦点、键盘、深浅主题、重复错误提示与视觉抖动。
- Chromium 覆盖完整主流程；Firefox、WebKit 覆盖登录、发消息、附件、工作／报告和关键弹窗。检查桌面宽度及 390px、360px 窄屏。
- 浏览器模拟窄屏、WebKit 引擎不等同真实 iPhone/Safari；物理麦克风、手机系统权限、真实钉钉扫码需单独标明实测情况。

### 3. 模拟真实用户的完整流程与 Agent 多轮任务

- 流程测试是独立必测项。测试者分别扮演员工和老板／管理员，从用户目标出发，在工作助手中实际发送消息、上传材料、回答问题、确认／拒绝操作，并去工作／报告／团队页面核对结果。
- 根据助手的实际答复继续追问和操作，不能只顺序发送预写提示词。用例预先固定角色、材料、目标、允许的分支和验收结果；下一句表达可以适应真实回复，但不能为了让助手通过而降低目标、提示内部工具名或替它完成任务。
- 同时检验结果正确性与使用流程：能否承接“第二项”“按刚才的改”、减少重复描述、避免反复确认、清楚解释卡点；完成后是否可查看、编辑、下载和继续使用。
- 覆盖半途改主意、信息不足、用户误操作、拒绝授权、暂不汇报、切页后回来、刷新与断线恢复；每条流程从初始状态走到完成、合理拒绝或明确取消的终态。
- 正常问答、解释、写作不得强制转为工作或报告；业务写入须符合用户意图和当前执行权限。
- 覆盖 Noria／专业人设、三种执行模式、员工／管理员，以及新会话、旧会话、工作引用和上下文压缩后的任务。
- 请求包括直接表达、省略对象、指代、纠正、反悔、切换目标、多个子任务、随机生成示例、任务部分完成及连续修改成果。
- 场景覆盖联网、图片、语音、文档、代码、文件交付、创建／修改工作、生成／编辑／提交报告、团队查询及组合任务。
- 真实模型建议首轮 60 条独立场景，至少 30 条为 3 轮以上对话，其中至少 8 条是 5～8 轮的完整用户流程，总计不超过 200 条用户消息。目标、事实、分支和预期在调用前冻结，至少 20% 留作未参与修复调试的保留样本；达到轮次预算仍未走完，明确记为未完成，不省略关键步骤后算通过。
- 不为凑数把同一场景的措辞替换算成独立业务覆盖；既有大规模语料先分类复用，不默认重复运行全部付费评测。
- 至少 12 条真实场景经过浏览器、实际 API 和 worker，其中包含上述 8 条完整用户流程，覆盖问答、联网、附件、业务写入、确认／补充、中断／重试和沙盒成果；其余可通过真实 HTTP 驱动。完整流程中不得调用隐藏接口、直接改库或预置成果来替代用户操作；只允许在准备阶段构造已声明的初始数据。
- 使用固定合成材料验证结果：业务字段、版本、来源、文件结构与数值必须有可计算的预期。开放式回答由独立验收审查任务完成情况；模型评分不能单独决定通过。
- 每条保存首轮结果；有依据的修复后复测单独记录，不覆盖失败。区分产品缺陷、模型能力、供应商审核／限流和测试假设错误。

### 4. 破坏性与一致性测试

在隔离环境执行：

- 删除成员、会话、工作、报告、附件关联或成果后的引用与清理；账号禁用、权限变化、密钥不可用。
- 请求发送前、服务端接受后、业务写入后、正文流式返回中分别断线；丢响应、重复提交、乱序响应、SSE 截断。
- 双标签页编辑同一记录、确认同一卡片、连续点击发送／中断／重试；不能重复产生业务记录或覆盖较新版本。
- 在任务读取、执行、保存和交付阶段终止本次测试的 API／worker／sandbox，恢复后验证租约、checkpoint、操作回执及最终状态。
- 模型超时、连接失败、429、5xx、格式错误、无效工具参数、审核拦截、连续失败；重试策略和 UI 节点必须一致且有限。
- 附件伪造类型、损坏内容、尺寸边界、路径穿越、受限体积的解压异常样本；沙盒越界读写、越权取文件、禁用网络、执行超时、输出超量与受限资源耗尽。
- 使用合成提示注入内容测试文档／网页／工具输出不能扩大权限或泄露密钥；所有目标、诱饵与数据均属于测试环境。

故障恢复不预设“必须自动轮询”：以现有请求精简约定为准。恢复网络／切回标签页的一轮同步、显式重试和正常流连接应能恢复正确状态，不能产生后台请求风暴。

### 5. 性能与资源

- 固定测试数据覆盖分页边界、100／1,000／10,000 条工作或消息历史；统计查询数、响应大小、首屏与筛选耗时，验证完整搜索和列表一致性。
- 在本地测试服务做有界的 1／10／25 客户端并发，包含读写混合、排队与取消。压力流量使用可控模型，不压测付费供应商。
- 测试前冻结机器配置、数据量、持续时间、请求数、资源上限及预期；记录 p50/p95、失败率、队列排空与资源回落。不能测试后为了通过而改阈值。
- 4 核 8GB 是部署背景，本机结果不冒充同规格云服务器承载能力；不在本次 Spec 中操作线上机器。

## 边界与环境隔离

- 使用专用 `paa_company_test` 数据库中的独立 schema，或隔离 PostgreSQL 实例中同名数据库；执行入口校验库、schema 和本轮标记，拒绝普通业务库。
- 创建两家合成公司，各有管理员、员工；另含同公司其他员工、禁用／删除账号、匿名访问。管理员不是员工私人会话的超级读取者，按现有权限契约验收。
- API、worker、媒体、主密钥、浏览器 Cookie／缓存、声纹缓存和沙盒工作区独立。副作用与进程终止只能命中本轮资源。
- 普通账号数据、现有上传和用户正在运行的服务不受影响。需要模型时只读取获准的连接配置，不复制真实聊天或材料。
- 网络故障在测试浏览器／代理注入；数据库中断只操作隔离数据库实例，不能停止共享本地 PostgreSQL。资源耗尽只发生在受限测试容器中。
- 清理绑定创建清单和本轮标记，异常退出也能清理或明确列出残留。保留脱敏证据，删除临时凭证、Cookie、临时业务数据和大体积无用产物。
- 钉钉真实绑定／解绑不操作真实员工账号；没有专用测试条件时记录受阻，并用协议测试验证可控分支，不冒充真实登录通过。

## 技术与兼容约束

- 本次实施属于 S3 全系统验收；本轮 Spec 文档按 S0，只检查 diff 和引用。
- 复用 Vitest、pytest、Playwright 与现有评测，不另建生产监控平台，不让真实模型／破坏性测试进入默认 CI。
- 不修改生产 API、数据结构、权限、超时和重试次数以迎合测试。修复明确 bug 并补回归，产品规则变更另行讨论。
- 覆盖汇总来自实际执行记录，不能用源码搜索命中、截图数量或测试文件数量替代断言覆盖。
- 沙盒控制端与公司 API 都使用私有 `app` 包，继续使用独立解释器运行对应测试。
- 通过的检查不无故重跑；缺陷修复后运行失败用例及受影响回归，跨模块修复才扩大范围。

## 验收标准

- [x] 当前版本所有 Web 功能、请求操作、异步任务和 Agent 工具有覆盖映射与状态，无未解释的遗漏。
- [x] Web 全量模块测试、公司 API 全量测试、沙盒协议测试及 Web 类型、格式、Lint、普通构建完成；失败逐项解释并处理。
- [x] 全部页面完成真实浏览器操作与截图检查，桌面／窄屏、管理员／员工、正常／异常路径有证据。
- [x] 多轮真实模型测试按确认规模执行，交付与持久数据核对；首轮、修复后、供应商失败分别统计。
- [ ] 员工／老板的完整用户流程实际走通，逐轮记录用户输入、助手答复、界面操作与结果；核验指代承接、目标变更、跨页面交接、重复确认和遇错后的可继续性。
- [ ] 权限、幂等、并发、删除、中断、断网、重启和真实沙盒破坏性场景完成，无越权、假成功、重复写入或未终止的失控任务。
- [x] 请求量与性能记录包含环境和限制；未实测真实设备或部署规格明确列出。
- [x] 每项缺陷有复现、期望／实际、原因分类、严重程度和处理状态；关键失败或必测项受阻时不得宣布全量通过。
- [x] 清理完成，原数据／服务未变，凭证与个人数据未写入仓库和报告。
- [x] 新的独立验收 Agent 审查覆盖、断言和证据，给出 PASS／FAIL。只有用户明确调整范围或接受限制，才能在注明范围后接受交付。

## 已确定的实施范围

- 直接修复可复现的明确 bug 并补回归；涉及新功能、权限规则或交互方案变化另行讨论。
- 使用本地已保存的模型配置，首轮 60 条场景、最多 200 条用户消息。模型内部核对、自动重试和工具后续调用另计，实际调用数与 token 用量单列；修复复测另列，不自动追加大批量调用。
