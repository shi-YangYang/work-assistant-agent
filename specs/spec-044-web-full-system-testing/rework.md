# 剩余问题修复

用户要求修复全部已发现的剩余问题，保留原始失败，结果单独记录。

| 范围 | 修复目标 |
| --- | --- |
| 权限拒绝 | 无法通过补充信息解决的请求标为阻塞，不诱导用户反复回复 |
| 工作字段 | 独立提取六字段变更计划，再校验提案；不遗漏状态或进展，追加进展保留原说明，不改变无关字段 |
| 查询依据 | 服务端统一生成范围说明，不与模型正文重复叠加 |
| 回答质量 | 避免日期／星期冲突、概念混淆、遗漏适用条件；区分来源正文、摘要与推断，纠正原样本中的错误 |
| 联网故障 | 有限重试后的普通网页故障不抹掉已有结果；只要链接的任务不强制获取全文，不绕过网站访问控制 |

修复采用通用字段、状态和来源契约，不写问题关键词补丁，也不为所有普通回答增加一轮无条件审稿。无法保证所有未来回答零错误；本轮逐项复测已知问题及相邻反例。

先运行受影响子系统检查，再用保存的真实模型配置验证原失败问题及相邻表达；不会重复全部已经通过的 60 个场景。网页仍不可读时如实返回限制，成功与失败分开记录。使用新建隔离环境，不恢复已清理的旧测试数据，不接触线上服务。

工作变更计划只用于 `update_work`，按当前消息、目标版本及有效上下文缓存。仍经过原有权限、确认、版本与幂等校验，不由计划自动补写字段。普通问答不增加无条件核对调用。

真实复测仍发现数值正确、文字解释互相矛盾的答复。含多个数值及等式、合计、组成等关系时，复用现有核对检查口径和必要假设；不因缺少外部资料否定假设示例。已有核对不重复调用，错误仍沿用原有纠正上限。日期、网址、编号、代码数字不作为触发依据。

技术条件核对尝试未达标：两条真实错误在固定回放中仍漏检或触及输出上限。新增的自动技术来源门禁及其专用存储撤回，避免新增答复阻塞；原有业务和用户明确要求的核验保留。S04／F04 准确性问题继续标为未通过，不算已修复。

协议归一化与正文纠错各最多一次，持久化计数并保留恢复幂等；不能让格式整理耗尽正文纠错机会，也不能因两阶段拆开而重复业务操作。来源条件判断先用已保存的错误答复、实际原文及正确反例验证，再复测原对话，不靠重复发送同一问题碰巧通过。

## 按任务选择证据

- 普通知识、写作和翻译直接交付；不默认追加来源审核。
- 网页与文档结论对应实际读取片段，保留原文条件，区分资料事实与推断；不要求每次读取全文。
- 有争议或依赖运行时的代码行为、非简单计算按需使用现有隔离沙盒。最小实验打印实际结果，版本相关结论报告实际环境；单次实验不证明所有版本或全部输入。
- 用户要求不执行、执行环境不可用或执行失败时如实说明；不把推演说成已运行，不因不能执行就拒绝所有可以回答的部分。
- 公司业务继续按权限、字段、版本和回执验证，不引入新的外部审核服务或通用在线门禁。
- 将个别题目的提示词补丁替换为通用证据规则。回答质量和工具／业务执行正确性分别评测，不能用任务终态代替语义判断。

按 S2 验证相关后端模块。真实测试冻结 8 个场景、12 条消息，复用原 S04／F04 的前两轮，并覆盖普通回答、不执行要求、相邻代码行为、计算和文档条件。每条只执行一次并保留首个结果；有具体修改才定向复测。使用本地保存配置和新建隔离环境，记录实际工具、审核调用、耗时及答案，独立审查准确性，不以模型自评定通过。前后非同期结果不作为严格性能对照，原失败报告保留。

真实追问还暴露了收尾字段问题：核验原话引用了上一轮，原先直接在交付后判错。提前接入既有的一次协议纠错，并明确当前用户原文；只允许修正收尾，禁止重做业务或实验，后置校验继续保留。证据提示规则不构成事实正确性的保证，当前准确性结论见 [证据策略验收](evidence-acceptance.md)。

## 证据读取与专项核验

- 历史实验增加独立读取工具，按当前会话与来源权限访问；保留已保存的环境信息，不把读取当重跑。
- 长网页增加字面关键词定位，无命中不视为观点不存在；不新增爬虫或改变网络访问边界。
- 显式事实核验去除业务操作上下文，保留用户原话、来源、候选正文及回答完整性；沿用原审核与纠错次数，使用有界推理配置，不给普通回答加通用门禁。
- 定向检查后冻结 S04、F04、实验追问共 6 条真实消息，逐句判断范围。工程通过与模型答复准确性分别记录，不因状态成功或审核空问题判准确。
