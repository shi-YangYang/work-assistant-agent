# Plan — 工作助手执行业务操作

对应 [Spec](spec.md)，已具备实施条件。当前文档按 S0 检查，下面验证范围用于后续代码实施。

## 模块与修改顺序

1. **共享业务服务**：从 `api.py` 提取工作写入、报告编辑／提交和删除准备的实际规则，与 `service.py`、`deletion.py`、`report_schedule.py` 组成 API／Agent 共用入口。保留现有事务和锁顺序，不让工具回调自己的 HTTP 接口或复制另一套权限判断。
2. **工作入口与契约**：增加手动创建接口和编辑器模式；可空截止日期贯穿工作／修订／建议的输入及 DTO。无消息来源的正式工作使用空来源列表，不伪造 Message；报告与团队读取正常包含这些记录。
3. **执行与确认状态**：建立最小持久操作记录，关联成员、发起消息、动作、目标、参数摘要、预期版本、确认状态及结果引用。直接操作和需确认操作共用提交路径，业务变化与成功凭据在同一事务保存。
4. **Harness 工具**：在现有按角色工具集内接入本人工作操作、报告／待办及团队待办查询；保留从普通材料提取建议的工具，重写“只能建议”的策略和对应完成断言。
5. **异步任务衔接**：报告仍交专用生成任务，聊天返回 job／report 引用后结束当前处理；由原反馈接口更新结果，不能持有当前成员运行槽等待同成员报告任务，避免串行队列互相阻塞。
6. **Web 交互**：Assistant 显示服务端操作卡、澄清候选和报告任务状态；Records 补手动创建、截止日期与相应列表更新。复用现有主题、反馈、路由及窄屏弹层。
7. **针对性验证和规则更新**：实施 Agent 完成相关检查后交新的独立验收 Agent；更新实际失效的业务决策与技术约束，不扩写流水账或复制全部 Spec。

## 数据流与执行契约

```text
用户消息 → 现有任务／harness → 查询最新业务 → 明确操作或澄清
                                           ↓
                      服务端校验身份、意图上下文、参数和目标版本
                                           ↓
                          直接执行 ／ 保存一次待确认操作
                                           ↓
                         共用业务服务 → 事务结果 → 会话卡片

页面表单 ───────────────────→ 共用业务服务 → 同一业务记录
```

- 动作白名单及是否需确认由程序定义，模型不能传入 `confirmed=true` 绕过。语义意图使用当前真实用户请求及明确绑定的澄清上下文；记录请求与来源版本，不把模型生成的授权解释当作唯一证据。
- 持久操作 ID 在执行前分配并绑定原始请求；同一动作恢复不依赖模型每次生成的新 tool-call ID。复用现有 `Idempotency` 机制，记录结果对象／修订，防止成功写入后回复丢失造成重复执行。
- 修改使用读取到的版本和明确字段补丁；服务器重新授权、检查对象存活及版本，不能把模型返回的整份旧对象无条件覆盖。
- 待确认操作保存规范化参数、对象版本、删除影响摘要及所需来源依赖。确认接口从服务端记录取参数并重新计算影响，前端提交确认 ID／版本，不接受替换目标的参数。
- 删除可能清除原消息、任务结果和 checkpoint；成功凭据不能仅依附会被清除的 `Job.result` 或原消息正文。保留不含已删除正文的最小结果，原记录仍依照现有规则清理。
- 操作状态与聊天任务状态分离：业务成功不因后续模型失败退回未执行，报告任务仍生成中不标记报告已生成。结果展示不依赖模型最后是否说出正确句子。
- 多步骤使用已保存的逐项结果推进，不引入通用 DAG 引擎；前置失败停止依赖项。重试重新授权并跳过已成功操作；参数改变视为新动作，不能借旧幂等键执行不同操作。
- 查询本人报告复用本人 DTO；管理员报告查询只投影已提交版本。团队汇报待办输出状态和周期，不附带草稿、私人消息或无权读取的员工资料。

## 接口变化

- 增加 `POST /api/v1/work-items`，使用既有幂等请求头、公司／本人授权；现有工作更新接口保持兼容并调用共用服务。
- 工作、建议与修订契约扩展可空 `dueDate`，采用公司时区的日历日期，不引入时间提醒。旧请求省略该字段时不清空已有值，显式 `null` 才移除日期。
- 消息详情增加可恢复的操作结果列表，旧消息默认为空；状态、对象类型、结果引用、修订、允许操作等由服务端返回。引用详情再次走原有权限检查，不把后台异常或工具参数直接显示给用户。
- 增加限当前用户的操作确认／取消接口；读取待确认状态和执行确认时均复核权限、版本和依赖，响应与重试幂等。具体路径和类型名称在实施时统一，不新增通用任意操作入口。
- 报告生成工具调用 `ensure_report` 共用入口并返回真实任务引用；员工待办准备与页面采用相同周期及规则快照。提交成功继续关闭现有汇报待办。
- 保持当前报告生成用途、配置快照、候选采纳、来源约束和费用／重试处理；明确给出的报告草稿修改不额外触发第二次报告生成。

## 迁移与风险

- 增量迁移保留业务 ID、资料和历史；新增操作记录为空，旧工作日期为空，旧建议维持原状态。新字段读取提供兼容默认值，不补执行任何旧聊天指令。
- 核心风险是意图误判、写入后重复执行、管理员权限扩大、确认后对象已变及聊天／报告同成员任务互相等待，分别用明确输入边界、持久结果、共用授权、版本绑定和异步任务引用处理。
- 工作 `content` 为 JSONB，日期需在所有来源的工作／修订契约中保持一致，不只加一个列表显示字段；既有旧客户端完整更新请求不能悄悄清空日期。
- 部署迁移前按现有流程备份；回退应用前评估新状态兼容性，不以删除操作记录或业务数据作为回退手段。不改部署拓扑或 CI 默认范围。

## 验证计划

实施涉及写入权限、API 和持久恢复，按 S3 对相关服务子系统验证，不据此运行 Electron 或全平台发行包检查。

- 使用固定模型工具响应与测试数据库覆盖：明确命令／普通陈述／引用／否定、同名澄清、跨公司／跨用户／管理员写权限、字段保留、日期、报告生命周期、删除材料、确认失效和多步骤部分成功。
- 在真实事务边界注入“提交后回复前中断”、重复消息／tool call／确认、租约换主和并发编辑；断言业务数量、实际版本和操作卡状态，不能只断言助手文本。
- 保留既有确认建议、团队来源失效、专用报告生成与提交边界的有效测试，调整仅针对“所有请求都只能建议”的旧假设，不放宽授权断言。
- 通过实际项目入口运行相关 server 测试；若脚本不支持选择参数，按其环境加载方式直接执行 `.venv-server` 下 pytest 的目标文件。前端按变更选择 `npm run test:web -- <文件>`，共享契约变化时补 `npm run typecheck:web`；格式化仅本次覆盖文件。
- `npm run dev:company` 下检查桌面／手机宽度的创建、澄清、确认及跳转。经已有授权使用保存的真实模型配置进行最小文字／报告联调，使用可辨识且能安全清理的测试业务，不操作用户原有工作或提交／删除真实报告。
- 真实联调分别核对工具返回、数据库业务和页面结果；外部模型报错如实记为未通过该步骤，不将固定响应通过等同真实端到端通过。必要检查完成后停止，不追加无关测试。
