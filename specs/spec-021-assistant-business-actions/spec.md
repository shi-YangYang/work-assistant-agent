# Spec — 工作助手执行业务操作

状态：已实施，独立验收 [PASS](acceptance.md)。实施摘要见 [Implementation](implementation.md)。

## 背景与目标

让自然语言和页面操作成为同一套业务的两个入口。用户明确要求办事时，助手应调用业务服务完成操作，返回可以打开的真实记录；不能只总结、承诺已经完成，或把所有明确指令都变成待确认建议。

本次覆盖 Web 的工作、日报／周报、汇报待办与管理员团队查询，建立可复用的执行方式；不把能力限定为“AI 创建工作”。

## 当前行为

- 工作支持查询、编辑、删除，但新建依赖确认 `ProgressDraft`，没有独立手动新建入口。工作尚无结构化截止日期。
- harness 明确要求进展只能生成建议；管理员督办也只能调用 `propose_followup` 等待确认。员工报告生成、编辑、提交及汇报待办已有页面和业务接口，但聊天尚未接入这些操作。
- 已有公司／本人授权、业务来源校验、修订、幂等记录、后台任务和反馈，直接复用。报告生成已走专用结构化流程，不退回通用聊天工具自行保存报告的旧方式。

## 目标行为与功能需求

### R1 — 按意图区分办事、建议和查询

| 用户表达 | 目标行为 |
| --- | --- |
| “帮我创建工作：周五前完成报价方案” | 创建本人工作，返回实际截止日期及记录入口 |
| “把报价方案标记完成” | 找到明确目标、读取最新版本并更新；同名时先列候选 |
| “今天讨论了报价，下周可能需要做” | 可提出可编辑建议，不直接创建或完成工作 |
| “帮我生成本周周报” | 启动现有报告任务，在会话中呈现进度和实际草稿入口 |
| “把周报下一步改成跟进合同” | 更新明确报告的草稿，不改写已提交快照 |
| “我还有哪些日报没交” | 查询本人汇报待办，展示周期、截止时间和准备入口 |
| 管理员：“小张有什么阻碍？给我建一个跟进事项” | 授权查询后创建管理员本人的关联工作，不给小张派单 |

- 明确要求创建、修改本人工作或报告草稿，且信息足够时直接执行，不追加机械确认。普通讨论、问答、假设、否定及单纯上传材料不授予写入权限。
- 缺少必要内容、同名对象或指代不明时，在同一轮集中补问。已明确的信息不重复询问；不凭相似标题合并工作。
- 承接当前会话的目标，但执行前重读业务记录。跨会话可按权限检索正式业务，不把其他私人会话拼入当前上下文。
- 一句话包含多个操作时展示各项结果；只有依赖步骤成功才执行下一步。例如“完成报价工作，再生成周报”，先保存工作，再固定报告来源；部分失败不能说全部完成，也不回滚已成功操作来制造整批失败。

### R2 — 首版业务范围与权限

| 业务 | 员工 | 管理员 |
| --- | --- | --- |
| 本人工作 | 手动／对话创建、查询、编辑进展与日期、完成、删除 | 相同；支持已有员工业务来源的本人督办 |
| 日报／周报 | 查询本人报告；准备／生成、编辑草稿、提交；删除未提交报告 | 查询授权员工已提交报告；按既有权限删除可定位的员工报告，不生成或代交个人报告 |
| 汇报待办 | 查询本人待办、准备对应报告 | 查询本公司员工的提交／未提交情况 |
| 团队业务 | 不开放 | 沿用现有已确认工作、已提交报告及关联来源问答 |

- 查询不隐式修改状态、标记通知已读或发起催办；准备报告不代表完成汇报。
- 管理员查看员工不意味着能创建、修改、完成员工工作或代交报告；不读取其他管理员的私人业务、员工会话及未提交草稿。新增操作不扩大原有读取范围。
- 权限由当前登录身份与数据库成员状态确定；每次读取、写入、确认、恢复和结果返回都复核公司、对象归属及资料依赖。前端隐藏、模型自报身份或持有对象 ID 都不是授权。

### R3 — 页面与助手共用业务规则

- “我的工作”增加紧凑的新建入口；标题必填，说明、阻碍、下一步和截止日期选填，默认进行中，负责人为当前用户。创建不依赖模型配置，不制造占位聊天或虚假原始消息。
- 工作增加可空的截止日期，列表、详情、编辑与助手结果一致展示。相对日期按公司时区和消息发送时间解析，回复中显示具体日期；不明确时补问。旧工作没有日期，不猜测补齐。本次不增加工作到期提醒或新的自动逾期状态。
- 手动创建和明确指令创建都直接成为正式工作，具有相同修订、检索、报告来源和团队统计资格；既有“待确认建议”仍需本人确认。管理员督办继续保留来源依赖及权限撤销处理。
- 更新只改用户要求的字段，保留其余内容。操作已完成的工作时返回当前结果，不反复增加同一修订。
- 工作来源区分手动录入、明确指令和建议确认；只保留必要来源，不增加常驻开发提示或操作流水页面。没有消息来源的手动工作可以正常查看、编辑和纳入报告。
- 报告自动汇总沿用本期正式工作及专用报告用途模型。用户明确给出的报告文字可按手动填写规则保存到草稿，不把待确认进展当成已完成事实，也不凭空生成无依据的工作成绩。
- 同一员工、类型、周期沿用同一报告；已有内容和已提交版本遵守现有候选／更正规则。重新生成不静默覆盖人工编辑，失败保留原内容；生成期间用户修改报告时仍能保留双方结果供选择。

### R4 — 提交与删除的确认边界

- 创建和普通编辑按 R1 直接执行。报告提交、工作删除、报告删除先展示操作卡：具体对象、修改／发布内容或删除影响，以及“确认”“取消”；不再叠一层重复弹窗。
- 报告提交须能查看即将提交的完整版本。即使用户说“生成并提交”，也先生成草稿、展示内容，再确认发布。管理员不能代员工确认提交。
- 删除报告沿用既有语义：员工不能删除已提交报告；管理员删除员工报告会清理该报告关联的原始消息和附件，先展示服务端计算的范围与数量。不递归删除其他独立工作或报告。
- 确认绑定当前用户、明确操作、参数、对象版本和影响范围；不接受只有模型声称“用户已确认”的参数。确认前对象、依赖或删除范围变化时，重新展示影响，不使用旧确认覆盖新内容。
- 重复确认只执行一次；取消不改变业务，刷新可恢复尚有效的确认卡，已删除／无权限的对象不能通过旧卡恢复。模糊的“好的”不能授权未明确绑定的操作。
- 首版删除针对明确的一条记录；“删除全部”等批量破坏性操作不执行，提示缩小范围，不自动把搜索第一页当成全部。

### R5 — 结果可信与故障恢复

- 业务工具返回结构化结果，区分等待补充、等待确认、排队／处理中、成功、失败及版本冲突。聊天里的结果卡从服务端保存结果生成，含实际对象入口和必要变更摘要。
- 只有业务事务提交成功才能显示“已创建／已更新／已提交／已删除”。报告只入队时显示“正在生成”，不能用模型的一句完成声明代替落库结果。
- 已保存业务但模型后续答复失败、断网或 worker 重启时，仍能展示成功记录；重试不能重复创建工作、增加修订或提交报告。确认卡与结果不只保存在会丢失的流式文本中。
- 用户明确要求再创建另一项时允许创建；不以标题相同就全局去重。系统重发同一请求和用户新的业务意图须区分。
- 页面编辑与聊天同时写入时检查最新修订，冲突后说明发生变化；不自动覆盖。部分成功后重试只继续未完成且仍获授权的动作。
- 历史操作卡展示当时结果和版本，查看对象时读取最新状态；来源失效、删除或权限撤销后按现有规则隐藏敏感内容，不复制一份能绕过权限的正文快照。

### R6 — Harness 与输入边界

- 复用现有 harness，提供有类型、有限范围的业务工具；API 和工具调用同一业务服务。后续新增业务接入同一授权、确认和结果规则，不新增一套与页面分离的数据。
- 用户发出的文字和输入框直接录制的语音指令，与被引用的聊天、文件内容、图片、上传音频的转写材料、历史模型输出分开处理；材料中“删除记录”等文字不能自行授权执行。用户明确要求按某份材料办事时，仍校验实际目标与操作范围。
- 工具执行校验真实请求上下文、操作白名单、参数、权限、版本及必要确认，不只依赖提示词或匹配“创建／完成”等关键词。超出能力的请求明确说明，不假装执行。
- 沿用现有工具／调用预算、任务租约和同成员串行；不开放任意 SQL、网络、命令执行或模型自行扩权。既有短语音／文件解析继续使用当前入口，本次不新增常驻语音助手。

## 页面与兼容性

- 沿用 Web／Electron 的共享主题、工作卡片和移动端布局。会话中就能查看结果、处理澄清及确认，跳转详情后能返回原会话；电脑和手机不出现额外常驻侧栏。
- 保留旧工作、进展建议、会话、报告历史及权限来源；旧建议不自动确认，旧聊天指令不补执行。既有页面管理入口继续可用，手动操作不需要模型在线。
- 沿用[公司业务方向](../../.ai/decisions/0011-company-agent-direction.md)和[团队授权](../../.ai/decisions/0014-team-assistant-authorization.md)；明确指令可执行不意味着扩大查询权限、报告发布或资料删除范围。

## 非目标与技术约束

不做 Electron 改动、任务指派、组织／角色调整、模型或密钥配置的对话修改、通用审批／工作流编辑器、自动催办／站外通知、无用户指令的自主执行、公司级 RAG、部署或服务商切换。问题反馈、会话管理等其他页面本次保留原入口，不将“接入业务”解释为一次开放所有系统操作。

沿用 React、FastAPI、PostgreSQL、Deep Agents／LangGraph；不替换 runtime 或增加队列服务。增量迁移只服务上述业务与恢复所需状态，不建立独立的通用审计平台。

## 验收标准

- [x] 手动新建无需模型；明确创建／更新指令产生真实记录，普通陈述只提出建议，同名／缺项先澄清，否定或引用内容不误执行。
- [x] 截止日期在手动、聊天、列表及详情一致；旧数据可读，相对日期和时区边界明确。
- [x] 聊天能准备／生成、编辑和确认提交报告，保留专用报告流程、人工更正、已提交版本及无来源时的现有行为。
- [x] 员工可问本人待办，管理员可问团队提交情况并创建本人督办；跨公司、跨员工写入及员工团队查询被服务端拒绝。
- [x] 提交／删除预览绑定实际对象与版本；重复点击不重复执行，取消不修改数据，变更后旧确认失效；管理员删除报告按既有规则清理材料。
- [x] 业务写入成功后模型失败、刷新、断网、租约过期或恢复仍显示实际结果，不重复写入；并发编辑不被旧任务覆盖。
- [x] 结果卡、来源及历史在权限撤销／删除后不泄露；文件和引用中的伪造指令不能触发写入。
- [x] 电脑和手机 Web 可完成创建、澄清、查看结果、提交确认及取消；进行真实服务定向联调，区分业务成功和外部模型失败，不将固定响应测试当作真实联调。
