## 背景

用户感知到 AI 回答问题和执行操作较慢。目标是在回答质量、正确性和权限保护不降低的前提下，减少系统额外增加的耗时。网络因素不做优化；确认是模型自身幻觉、遗漏或不遵循清晰指令的，保留失败记录并停止针对该问题的补丁和反复测试。

原因未定时不能直接归咎模型。必须区分实际输入不完整、工具参数含义不清、程序流转或重复处理，与模型收到正确输入后仍然出错。

## 目标

- 缩短从发送到有效回答、必要提问及实际操作完成的时间，分别报告，不能互相替代。
- 优先消除有证据的多余模型往返、重复上下文处理和程序等待；沿用现有 LangGraph、middleware、工具契约及观测体系。
- 检查共享路径，普通问答不能因某一操作场景提速而承担未经评估的额外开销。
- 用受控检查解释系统改动的效果，用真实 low／high 模型和实际页面流程验证交付结果；失败原样保留。

## 非目标

- 不调整网络、代理、线路、搜索服务或模型供应商，不把外部服务排队和网络波动列为代码缺陷。
- 不换模型、降低用户选择的推理强度、提高任务总预算或重试次数，不靠缩短必要回答内容换速度。报告单次输出上限允许在原有8000任务总额度内调整，具体边界见下方报告截断修复；其他模型／工具预算不扩大。
- 不新增意图分类、充分性审核、规划、润色、语义评分等独立模型回合。
- 不修已确认的模型自身错误，不为了清零失败追加提示、审查节点或采样。
- 不重做此前完成的工具预加载和收束机制，不顺带修复 Spec080 的其他缺陷，也不重跑整个回归矩阵。
- 不优化桌面录音／转写，不做生产部署、线上数据操作或基础设施扩容。

## 目标行为与功能需求

### 1. 先定位关键路径，再决定修改

复用 `tasks/timing.py` 的 job／attempt／fence 和模型调用关联，缺什么补什么，不建立第二套观测系统。至少能分辨入队／领取、准备、主模型与授权等实际调用、工具、持久化、流式发布及页面显示。

每个优化候选记录：真实触发条件、程序增加的工作、耗时证据、可省部分、必须保留的语义与保护、相关检查。没有确认收益来源的候选不直接修改；并行与嵌套 span 不能相加冒充端到端耗时。

模型请求总耗时包含网络、供应商排队和推理。无法分离时标为“外部请求耗时，内部构成未知”，不能全称网络，也不能用总时间减去模型时间就称为纯程序开销。程序触发了本可避免的模型请求，属于本次优化范围，即使其中也包含网络等待。

### 2. 减少程序导致的多余往返

- 从主模型决策、middleware、工具输入／结果契约定位重复加载、读后重复探索、写后无必要补查及重复收尾；只处理当前仍存在且有证据的路径。
- 材料是否足够仍由主模型根据用户需求和事实判断；程序核验实际回执、需求状态及合法下一步。不以工具成功、读到目录或达到次数上限代表充分。
- 缺少只有用户能决定的信息时，沿现有提问框及时提问；已具备依据的请求不新增澄清往返。既有等待、取消、回答与恢复协议保留。
- 纯操作可以沿现有有效回执结束；混合请求中的解释、引用和其他未完成需求不得被省略。异步周报／文件的任务入队不等于生成成功。
- 授权、最新来源检查和并发校验不是可随意删除的模型审核；若发现可复用的既有判断，只能在相同有效输入与约束下复用，不能跨变更沿用。

### 3. 减少输入与本地重复处理

- 精简系统提示、工具 Schema 和结果中重复治理内容，保留字段身份、必要条件、失败语义、引用原文与来源版本；不叠加新的同义提示补丁。
- 分别统计主模型、授权、报告和上下文压缩的调用与输入；不能用一个角色减少的字符抵扣另一个角色增长，也不能把字符数当实际 token。
- 静态 Schema、不可变派生数据或同次请求的重复读取，只有测得实际重复成本后才缓存／合并。可独立的只读准备允许评估并行；共享事务、同一可变上下文及写入操作不据此并发执行。
- 缓存键和失效条件必须覆盖其实际依赖，包括公司／成员／角色权限、源文件与解析版本、请求修订等。授权、删除或来源更新后不得返回旧可见数据；不全局复用携带用户状态的图或模型响应。
- 不提前增加摘要回合，不丢失历史条件、用户纠正、材料内容或正在等待的动作来缩短上下文。

### 4. 减少已证实的调度与显示延迟

仅当分段数据表明相关阶段影响目标路径时，优化领取等待、重复数据库工作、输出合并或前端消费。沿用当前设施和恢复机制，不以更频繁轮询、提高并发／预算、扩大日志量掩盖问题。

首屏必须是经过现有权限和来源保护的有效内容。开始提示、进度动画、未校验 token、提前显示“已完成”，均不能计为回答或操作提速。断线续接、刷新、重试、取消与切换账号后仍按原任务身份隔离。

## 测量与验收口径

质量是速度结论的前置门槛：本轮冻结的用例必须全部正确完成，并通过对应的必要保护检查，才可宣布该候选通过并接受速度优化。任一用例失败、缺失或未完成，整体均不通过；不能用其他成功用例抵消，不能删除失败样本或补采替换首试。历史失败永久保留；有具体修复后才安排受影响用例的有界验证，新的结果不改写旧结果。确认纯模型错误后仍按非目标停止补丁，该失败也不能因此变为通过。

| 指标 | 起止点与用途 |
| --- | --- |
| 首个有效回答 | 用户发送到可见且可用的回答内容；SSE收到时间与浏览器实际渲染时间分别记录 |
| 首个可回答问题 | 用户发送到问题及选项／输入控件可操作；不包含用户思考耗时 |
| 操作回执 | 用户发送或确认到真实提交成功且页面显示对应结果；数据库提交与显示分别记录 |
| 最终完成 | 到正文／报告／文件实际完成并可读取或下载；子任务单列，queued不算完成 |
| 系统与调用成本 | 关键路径各阶段、模型调用类型／次数／输入输出token、工具顺序、重复处理及必要的SQL／锁等待 |

固定用例、数据、权限、模型和 low／high 档位；基线与候选交替执行，区分冷启动、暖缓存和工具选择变化。首字改善和总完成改善分别给结论。小样本只用于观察，不声称统计显著性或全场景准确率不变。

真实验证默认选实际受影响的至多4类场景，加至多2类不应变慢的对照；每类low／high各2对基线／候选，最多48条初始请求。涉及确认／续接的后续用户输入另行登记，总用户输入不超过96条；所有模型节点和内部重试均按实际次数统计并保持现有预算。定位阶段使用的合格基线样本直接复用，不另起一轮基线。实施前冻结具体清单，不为全绿追加采样。

确定性检查验证保护条件和程序路径；真实验证必须保留原始输入、实际模型可见消息／工具 Schema、输出、工具顺序、耗时及必要数据库读回，且只使用隔离合成数据。完整输入取证仅用于本地验收，密钥不写入记录，生产仍采用有界元数据日志。

质量检查由确定性断言和人工核对完成，不增加评分模型。核对事实、数字、条件／例外、引用、需求覆盖，以及实际保存对象、内容、权限和唯一性。归因完成的纯模型失败只记录；候选出现未解释的新失败或系统性质量下降，不得宣称无回退。受影响路径要有真实页面提交与结果检查，不能用脚本生成答案、静态卡片或API入队替代。

## 边界条件、兼容性与技术约束

- 保留角色／公司隔离、执行权限、人工确认、幂等、租约／fence、来源版本和冲突恢复；不改变现有业务规则或持久协议。
- 若优化涉及共享安全或持久化机制，按S3选择该子系统必要检查；普通局部优化按实际S1／S2，不默认全仓测试。
- 不向用户正文暴露需求覆盖表、读取范围或内部协议，来源卡与真实业务回执继续可用。
- 历史失败不抹除；未测、无法归因、环境问题和已确认模型问题分别报告。Spec080 未决项不因本次局部通过而关闭。
- 默认不增加依赖、公共API、数据库schema或独立基础设施；若证据要求这些变化，先更新方案并说明必要性。

## 验收标准

- [ ] 当前实际耗时可关联到用户请求、图节点／模型角色、工具及结果，未知部分明确标注；没有把网络或并行耗时误归因。
- [ ] 每项业务优化有具体系统原因与前后路径证据；已有优化未重复计算，纯模型错误没有新增补丁／审核／重试。
- [ ] 受影响程序路径在受控条件下可重复减少等待或重复工作；真实low／high对照原样报告，未观察到收益的改动不宣称提速。
- [ ] 质量、正确性、权限、来源、幂等与恢复相关检查通过；未归因的新失败没有被“模型问题”掩盖。
- [ ] 普通问答和未受益路径的调用、输入与耗时有对照；若存在具体回退，收窄／撤去对应候选改动，不以其他场景的收益抵扣。
- [ ] 真实页面证据覆盖受影响的回答／操作结果；必要异步交付验证到最终内容或文件，不能停在queued。
- [ ] 分开交付首个有效输出、操作完成、端到端耗时及质量限制；不预先承诺统一百分比，不以小样本宣称普遍提速。
- [ ] 新独立验收Agent给出PASS／FAIL；范围满足且必要检查通过后停止，隔离资源按归属清理。

## 报告截断修复

周报失败已从既有 worker 日志定位为 `finish_reason=length`、`output_tokens=4000`，不是缺失结束原因。报告请求固定单次4000 token，原有报告任务总输出上限为8000；当前唯一生成调用先碰到单次上限。报告生成改为在原有8000任务总额度内使用剩余额度，并受模型已知输出能力限制；这不提高任务总额，但确实把单次请求上限从4000提高至最多8000，不能称为“单次预算不变”。保留显式推理参数、调用次数、截断拒绝、原报告、来源、租约及幂等保护。该修复首先解决生成截断，不能预先计为速度收益。详见[当前失败诊断](acceptance.md#周报失败的新增诊断)。

## 本轮确认范围与质量门槛

仅处理工作变更范围／授权的重复合同、共享业务工具合同精简；不实施首轮工具预加载、worker 唤醒或动画调整。

- 保留变更范围提取不接收助手拟议修改值的边界。不能为了把两轮变成一轮，直接让范围提取看见提案；不能用主模型自报范围替代独立核对。
- 变更范围可改为紧凑传输，但必须显式覆盖全部字段：已修改字段和保留字段互斥、无重复且并集完整；程序不把遗漏默认为保留。内部完整计划、引文、精确状态／日期、清单选择及缓存隔离继续保留。
- 独立范围已产出的原文依据、必需字段和追加模式由程序复用。授权节点负责目标、当前拟议值、材料、确认、续接及完整需求，不再重复生成同一份字段分类；所有已有有效约束须有明确去向。不能把减少字段当作取消检查。
- 保留 work/reports 共享入口的全部 action 和参数，统一精简重复说明；必要的字段身份、工作内容、报告周期、生成与提交区别、来源及幂等语义完整保留。不能按能力硬拆枚举，使工作操作后的周报请求增加加载往返；不增加分类模型，不无条件预加载，旧 checkpoint 和服务器权限检查兼容。
- 原文、条件、例外、来源身份与并发／租约／幂等保护不减少。安全相关拒绝、正确请求的成功率和修改完整性都属于质量，不能只测拒绝率。
- 按 S3 检查受影响授权与工具子系统；使用真实 low/high 做有界前后对照，保留全部首次结果。失败若输入正确且确认属于模型，只记录，不追加提示补丁或重跑到绿。候选出现未解释的新失败或质量下降时撤回对应候选，不用耗时收益抵扣。
- 不承诺小样本证明绝对无回退；只有保护检查和所测真实流程无新增回退，才接受该范围改动。若保留安全边界意味着仍需两次不同职责的模型调用，如实说明，不以调用次数作为硬性指标。

## 扩展执行发现的系统缺陷

工作页直接上传的材料可以没有聊天消息来源。助手实际读取此类材料后，报告子任务不得再把它当作聊天附件强制读取空消息 ID。修复限于报告材料来源解析，继续通过现有工作／附件归属、权限、删除／移除状态、读取版本和最终保存保护；不能仅跳过校验让所有无消息附件可读，不增加模型回合。保留 D09 原始失败，并以受控拒绝分支及正确长来源夹具的真实流程验证修复。模型收到完整正确输入后仍发生的内容遗漏、错误概括和内部读取信息展示仅记录失败，不加提示或审核补丁。

同一次真实请求的工具说明不得同时宣称“不需要预查汇报待办”与“生成必须传入待办 ID”。查询待办工具只在选中已存在待办时说明如何带入其 ID；普通按周期生成无需管理员规则或待办 ID。D07-submit 已确认实际模型输入包含这处说明歧义，修复限于消除该条件歧义，不改变生成、提交、确认和权限规则。

重名工作候选的服务端选项描述必须兼容当前正文存储。只取旧 `summary` 会把有不同正文的工作都显示成相同标题和空描述。本人工作可在缺少摘要时使用已授权正文的有界纯文字预览；继续使用服务端真实标题、对象 ID 和读取版本，不信任模型自填描述，不扩大跨用户访问。保留 C08 原始不可区分的选项证据，用原工具输入的程序重放和浏览器展示验证修复，无需新增模型调用。
