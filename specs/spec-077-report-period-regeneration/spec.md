# 汇报周期与删除后重新生成

## 状态

已实施，独立验收 PASS，见 [验收报告](acceptance.md)。尚未提交或部署。

## 背景与当前行为

“我的报告”的单日选择器标为“报告日期”，但周报取所选日期所在周的周一至周日。用户容易把它理解为提交日期。线上只读排查显示：反馈账号在 2026-10-26 至 2026-11-01 没有可用来源，在 2026-10-19 至 2026-10-25 有 12 条来源；后一周期的报告已被删除。此结果验证了取数条件，不等于找到了包含请求参数的历史请求日志。

报告删除清空内容、候选和修订，取消旧任务并保留墓碑；数据库仍要求 owner_id、kind、period 全表唯一。ensure_report 同时拒绝人工重新生成，导致一个周期被永久占用。定时任务尊重删除是必要保护，人工新请求不应受此限制。

## 目标与目标行为

1. 周报明确展示“汇报周期”、完整起止日期及周一至周日口径，提供本周／上周快捷选择。日报按单日展示“汇报日期”。周定位可以保留原生日期控件，生成前必须能看见实际整周范围，不能仅靠生成后的列表解释。窄屏可换行。
2. 有效用户主动通过报告页、助手或可恢复的汇报待办重新生成时，允许同周期建立新报告、新任务，保留旧报告的删除状态。适用于日报和周报，仍只允许一个未删除报告。
3. 默认不让定时调度重新创建主动删除的报告。显式重新生成后，新报告参与正常待办、生成与提交流程；不能带回旧提交状态、候选、来源、通知或旧任务结果。

## 功能需求

- 按公司时区解释日期；周报与后端统一为周一至周日，支持跨月／跨年。切换周期后清除与旧选择有关的错误展示；展示范围与实际请求一致。
- 无来源时保留原有错误码和保护，但提示实际统计范围，优先提示核对周期；不以“没有记录进展”概括所有原因。正文、材料与计划不会因此自动成为进展事实。
- 重新生成使用新的报告 ID。墓碑、旧 ID、旧任务租约、旧回执与旧来源引用不能绑定或写入新报告。只保留有效报告的周期唯一性，不删除历史墓碑来腾位置。
- 查询先取未删除报告；已有生成任务的复用、生成中写作要求冲突、重复请求幂等与并发串行化保持有效。不能因存在旧墓碑而漏掉新报告，也不能因多条墓碑而选错记录。
- 先校验有效来源，空来源不创建报告／任务、不恢复待办、不调用模型。
- 仅因报告删除而撤销的待办，可在显式重新生成时重新关联新报告并恢复为未提交；不得撤销账号停用、角色变化等造成的取消。必要时用明确的内部取消原因区分，旧记录只能在有可靠依据时恢复。
- 原生成、待办准备的旧幂等回执不得把调用者导向已删除报告，也不能把旧提交／删除请求自动应用到新报告。
- 本人／管理员的删除权限、生成／提交授权、版本检查、来源验证与租约保护保持不变。管理员依然不能替员工生成个人报告；不得自动提交重新生成的报告，除非现有授权流程明确要求。

## 非目标

- 不恢复陈怡希或其他用户的线上报告，不修改生产数据，不部署、commit 或 push。
- 不重做周报写作模型，不增加模型调用、审核或提示补丁，不调整进展事实口径。
- 不扩展回收站、任意日期范围报告或历史已删除正文恢复功能。
- 不重做其他页面的日期选择器、组织规则或团队看板布局。

## 技术约束与兼容性

- 在原 reports、operations、scheduling 边界修复；人工 API 与 Agent 复用同一业务用例。
- 采用未删除报告的部分唯一索引；保留墓碑身份与引用，迁移不读取或恢复业务正文。升级迁移必须兼容已有数据。
- 有同周期多条历史墓碑后，旧全表唯一约束无法直接恢复。回退须明确失败或按项目备份回滚规则处理，禁止静默删除历史记录来降级。
- 现有 API 请求字段、错误码和报告 DTO 保持兼容；工具描述明确 report_date 对周报的含义。
- 验证按 S3：涉及持久化约束、删除与生成并发及任务流转。只运行相关子系统和迁移检查；不跑全项目矩阵或真实付费模型。

## 验收标准

- [x] 周报生成前清楚显示实际整周范围，本周／上周、跨年及日报切换与请求一致。
- [x] 空来源提示含实际周期，无报告、任务、模型调用或待办恢复副作用。
- [x] 日报／周报删除后，新的主动请求能生成、查看并提交新的报告。
- [x] 多次删除重建及并发／幂等请求始终最多一个有效报告，旧墓碑保持删除。
- [x] 旧任务不能完成或重试写入新报告，旧 ID／回执／提交版本不能修改新报告。
- [x] 定时调度不会复活已删除报告；显式重建只恢复因报告删除取消的待办，其他取消继续有效。
- [x] API、助手共享入口与团队可见性保持权限隔离，旧已提交内容不会回流。
- [x] 升级迁移与有重复墓碑时的回退保护实测通过；验证不接触生产数据。
