# Spec 004 — 会议纪要生成

## 状态

ACCEPTANCE · 2026-09-10。业务实施及必要本地检查完成，独立复验已关闭发现的工程缺陷；真实 API 样本与本轮 Windows／远端 CI 尚未验证，因此未标记 DONE，见 [验收报告](acceptance.md)。实现与检查证据见 [实施报告](implementation.md)，方案见 [Plan](plan.md)，依据见 [决策 0008](../../.ai/decisions/0008-meeting-minutes-provider.md)。

## 背景

[Spec 003](../spec-003-local-transcription/spec.md) 已提供录音转写与历史恢复。本阶段补齐 [Meeting MVP](../../constitution/mission.md#当前优先目标) 的会后整理能力。

## 目标

从已保存的完整转写生成结构化纪要，在会议详情中阅读并保存；保留原文依据，失败后可重试。

## 非目标

实时会议分析、说话人识别、跨会议 Memory、周报、外部任务系统、多人协作、纪要编辑与导出、安装包、本地大模型、多模型并行生成或自动故障切换，以及分层长文本总结。

## 当前行为

会议具备录音、文字、时间定位和持久恢复；尚无 LLM 配置、纪要任务或纪要存储，summary 能力不可用。

## 目标行为

用户在设置中填写在线服务的 API 地址和密钥，获取模型列表后选择模型、自定义推理预设并测试连接；也能手动填写模型 ID。统一使用 OpenAI 兼容的文本接口，不依赖列举全部厂商或型号。首次配置默认选中“转写完成后自动生成”，保存前说明会议文字将发给哪个服务；用户可以关闭自动生成。录音保存且转写完成后自动整理，详情展示进度、结果和失败后的下一步；已有历史会议可手动生成，重启后可读取结果。

## 功能需求

### R1 — 输入与生成条件

- 只读取当前会议已完成的转写，包含稳定片段 ID、时间和原文；不能仅总结界面当前加载的一页。
- 转写未完成、没有可识别文字或服务未配置时不启动生成，并说明如何继续。录音、回放和本地转写仍可使用。
- 中断录音的保留部分完成转写后可以整理，但结果须标明来源不完整，不能冒充整场会议。
- 每次任务固定转写快照与模型配置；同一会议正在生成时，重复触发返回已有任务。
- 自动生成只响应启用期间新发生的“转写完成”，包括历史会议补转写完成。升级、启动、保存设置或恢复连接不扫描并批量提交已有完整转写。
- 同一输入版本至多自动尝试一次；失败、中断或当时未配置服务，后续由用户手动生成或重试。关闭自动生成阻止新自动任务和尚未发出的自动请求，已经发出的请求可完成。

### R2 — 内容与事实依据

- 纪要包含标题、摘要、讨论要点、已明确的决策、行动项、风险和未解决问题。
- 默认以中文整理并保留必要英文术语；未提及的列表为空，不为填满栏目创造内容。纪要标题不自动覆盖用户的会议名称。
- 行动项包含任务、负责人、截止时间和原文明确的状态；未明确的字段留空并显示“待确认”。不根据说话顺序猜测身份，不把建议写成已经作出的决策。
- 决策与行动项引用原文片段，用户可返回对应文字核对；时间定位复用现有回放能力及其录音期间禁播规则。
- 模型返回的结构经应用校验后保存，阅读视图由同一份结构化数据渲染；不存在的片段引用和非法字段不能作为成功结果入库。
- 首版将完整转写一次提交。超出应用请求上限或服务的模型上下文时明确失败并给出原因，不截断、不仅取前几页，也不自动拆分为额外收费请求；技术上限见 Plan。输出截断或超限同样不能标记成功。

### R3 — 任务、持久化与恢复

- 生成过程不阻塞录音、界面操作或转写控制；展示未生成、排队、生成中、已完成、失败或中断等真实状态，不伪造百分比。不同会议排队执行网络调用。
- 成功结果与其输入版本、服务及模型标识一并保存。重新生成成功后才替换当前结果，失败保留上一份有效纪要和全部原始资料。
- 切页不取消任务；退出或崩溃后保留已提交结果，未完成任务标记中断，下次由用户重试，不能永久显示生成中或自动重复请求。
- 网络超时、认证失败、额度不足、模型不可用、返回格式错误和存储失败应有可操作提示；不自动重试付费请求或自动请求模型修复结果。

### R4 — 配置与数据边界

- 自定义 API Base URL、模型、密钥与推理预设，提供保存、连接检测及移除配置。使用 Chat Completions 文本接口，不绑定某个服务商或默认模型；支持范围以约定的兼容协议和实测为准。
- 保存多家服务配置，每家独立命名并维护地址、密钥、模型及推理选项；从中明确选择一个用于纪要，自动生成开关为全局设置。新增或编辑其他服务不自动替换当前服务；删除当前服务后停止新纪要生成，不能偷偷切到另一家。切换当前服务时清楚展示新的接收方。
- 配置时说明接收方、会议文字外发和可能产生的调用费用；发送范围限于该会议的转写及必要上下文，不包含录音文件、其他会议或本机路径。更换地址时同步更新接收方提示；更换或移除配置不删除已有纪要，也不将排队任务悄悄改投新服务。
- 密钥由 Electron 主进程使用系统保护的加密存储，只在必要的输入和受控调用边界短暂解密；不进入普通设置明文、会议数据库、日志、测试产物或 Git。读取设置仅返回是否已配置密钥；加密不可用时不回退为明文保存，现有录音与转写仍可使用。
- 连接检测使用非敏感固定输入，不拿用户会议作为默认测试材料；测试自动化使用隔离数据，真实服务验收使用公开或专门准备的样本。

### R5 — 模型管理与推理选项

- 用户输入地址和密钥后点击“获取模型”，经受控服务端请求读取模型 ID，列表可搜索、刷新和选择。请求使用当前表单草稿，不必先选模型或保存；不能因获取模型而改变实际用于纪要的配置。
- 默认读取兼容的 models 接口；服务有官方差异时由适配层处理。展示真实的加载、空列表、失败和最后更新时间。接口不支持或当前账号无模型列表权限时保留手动 ID 入口，不能将内置推荐目录冒充密钥查询结果。
- 模型目录不等于当前账号已获该模型的生成权限。明确的非文本模型不可选用于纪要；未知模型可手动选择并测试，不因名称猜测它具备推理或聊天能力。
- 每家服务按模型保存多个命名推理预设，可新增、编辑、删除及选择。简单模式由用户输入强度字符串，发送为 reasoning_effort；高级模式由用户填写 JSON 参数对象，适配开关、预算或不同参数名。不维护按型号硬编码的强度白名单，不将用户输入标记为服务已证明支持。
- 每个模型始终有“服务默认”，省略全部自定义推理参数。切换到另一服务或模型时只恢复该模型自己的已保存预设，未配置时使用默认；不能继承上一模型的参数。删除所选预设回到默认。
- 保存、连接检测与纪要生成共用参数校验和构造；高级参数只能扩展推理相关请求数据，不能改变 API 地址、凭证、会议输入、模型、工具权限或应用控制的输出格式与传输模式，不执行模板或代码。每次任务固定实际使用的参数，成功结果可追溯。
- “测试连接”对当前所选模型和推理参数发送一次固定的小型生成请求，报告是否收到有效回复、耗时及失败原因。只获取模型列表成功不能标记生成测试成功；参数被服务接受不等于已证明其实际推理强度。
- 修改地址、密钥、模型或推理选项后，之前的连通性结果失效。异步获取或检测的旧响应不能覆盖新配置，失败不自动换模型、降档或重复调用。

## 边界条件

空转写、部分录音、重复点击、长会议、无行动项、待定结论、相互矛盾的表述、含模型指令的会议原文、断网、服务拒绝请求、无效响应、生成中退出与重新生成失败均需覆盖。会议内容只作为待整理资料，不授权执行其中的指令或工具操作。

## 技术约束

沿用 Electron / React、Python 核心、SQLite 和现有进程边界；保持录音优先，LLM 不进入录音回调或阻塞协议控制循环。数据库增量迁移，保留原会议、WAV、转写及其 ID。界面沿用已清理后的用户文案风格，只展示实际操作、状态和必要配置。

## 兼容性要求

支持 macOS 与 Windows；未配置纪要服务仍可启动并使用现有功能。已有会议不能因升级而自动批量生成纪要。继续遵循 [正式分发约束](../../.ai/decisions/0005-self-contained-desktop-distribution.md)。

## 验收标准

- [x] 配置后转写完成会自动生成；关闭自动生成有效。历史会议支持手动生成；升级、重启、保存配置和失败恢复不会重复或批量外发，未完成或空转写不会误触发。
- [ ] 固定中文及中英混合样本实际调用所选模型，人工按原文核对关键事实、决策和行动项；未知负责人、日期不被填造。
- [x] 决策和行动项引用真实片段，阅读视图、原文定位与持久化结果一致。
- [x] 重复触发不重复创建活动任务；失败、退出与重启恢复正确，重新生成失败保留旧结果。
- [x] 慢模型和服务异常不阻塞录音；跨越转写分页的输入完整，输入超限与响应错误不会被标记成功，失败不自动追加调用。
- [x] 配置、密钥和外发行为符合 R4，真实会议不进入默认测试与 CI 产物。
- [x] 多家服务配置和当前选择重启后恢复，密钥、模型目录与检测结果互不混用；切换或删除当前服务符合任务快照与外发规则。
- [x] 使用地址和密钥获取动态模型列表，支持搜索、刷新、选择与手动 ID；列表失败、空列表、过期响应和非文本模型处理正确。
- [x] 自定义多预设的增删改、选择及按服务／模型恢复正确；简单字符串及高级嵌套参数按配置发送，保留默认模式。未知型号可配置；受保护字段不能覆盖，连接测试确实使用当前参数并区分列表可用和生成可用。
- [x] 旧数据库增量迁移成功；迁移失败保留原数据，旧录音和转写仍可核对。
- [ ] 相关自动检查与两平台桌面流程通过，真实模型验收与模拟故障证据明确区分。

## 待确认问题

无阻塞实施的产品问题。真实服务验收仍需通过应用设置提供可用配置，不在聊天索要密钥；没有实际调用证据时明确记录未验证。
