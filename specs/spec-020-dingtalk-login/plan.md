# 钉钉登录实施计划

对应 [Spec](spec.md)。本计划定义实施契约，执行结果记录在验收文档中。

## 模块与顺序

| 顺序 | 模块 | 改动 |
| --- | --- | --- |
| 1 | `services/company/src/paa_server/` | 增量迁移、钉钉配置／身份／授权事务；抽取现有会话签发方法供两种登录复用 |
| 2 | 同目录新增钉钉接入模块 | 官方接口适配、公司成员核验、登录／绑定／重新验证路由、配置管理 |
| 3 | `packages/api-contracts/src/index.ts`、`apps/web/src/` | 登录按钮、登录方式设置、账户密码状态与绑定入口、回调结果及离开保护 |
| 4 | `deploy/company/`、`docs/setup.md` | 公网 IP 证书接入、续期／重载说明、钉钉权限与回调配置步骤 |
| 5 | `tests/server/`、`tests/web/` | 相关认证、迁移、公司隔离及交互验证；再按条件补真实授权 |

## 数据与迁移

在现有 `0008_support_feedback` 后新增迁移，不改写历史迁移。

- `Member.password_hash` 允许空值，空值明确表示本地密码未设置。原有哈希及强制改密状态不变；新钉钉成员 `must_change_password=False`。密码登录对空值执行等价的假哈希验证后拒绝，不能报错或接受空密码。管理员重置仍可设置临时密码并撤销会话。
- 公司钉钉配置：每公司一条，保存 CorpId、Client ID、加密 Secret、启用状态和修订号。复用现有主密钥及 AES-GCM 原语，使用钉钉专属作用域；不改写已有模型密文。Secret 留空保留、显式替换更新；修订冲突返回 409。
- 外部身份：关联公司、应用作用域、钉钉稳定身份和本地成员；数据库约束防止同一身份绑定多人或同一成员重复绑定。以实际成员查询得到的企业 UserId／UnionId 建立对应关系，不使用昵称或手机号作主键。
- 授权事务：只存 state／浏览器校验值的哈希、公司、配置修订、用途、目标成员／发起会话、有效期及消费状态；有效期 5 分钟。过期记录有界清理，不保存钉钉用户 Token。
- 自动账号使用非个人信息的唯一短标识（如 `dd_` 前缀），按现有用户名规则生成，冲突重新生成；姓名只作为显示字段并处理长度／空值。开户、绑定及 `reporting.eligibility_changed` 在同一事务完成，保留汇报待办的既有成员接入行为。
- 已有绑定时，不允许直接切换 CorpId／Client ID 导致静默重新开户；提示先处理应用迁移。Secret 轮换保留身份绑定，配置修订使旧授权事务失效。

## 公司解析与接口

公共登录入口优先使用部署参数 `PAA_LOGIN_COMPANY_ID`；未指定时仅在数据库确有唯一公司时解析。多公司且未指定时关闭公共钉钉入口，不使用 `limit(1)` 猜公司。设置接口继续从已登录管理员身份确定公司。

路由集中在 `/api/v1` 下，避免扩大 `api.py` 的业务职责：

| 入口 | 契约 |
| --- | --- |
| `GET /auth/providers` | 只返回当前部署可用的登录方式；不暴露公司列表或应用凭证 |
| `GET/PUT /settings/login/dingtalk` | 管理员配置，含修订校验和只读回调地址；返回 `hasSecret` |
| `POST /settings/login/dingtalk/probe` | 管理员发起真实授权校验；允许校验已保存但未启用的配置，不能开户或切换会话 |
| `POST /auth/dingtalk/start` | 创建浏览器绑定的登录事务，返回固定钉钉站点授权 URL；校验 Origin 并限流 |
| `GET /auth/dingtalk/callback` | 核验并消费事务、交换授权码、验证成员；成功签发本系统会话，再跳转不含授权参数的结果页 |
| `/auth/dingtalk/account/*` | 已登录用户的绑定、解绑、密码重新验证入口；写操作要求 CSRF，按用途校验目标账号 |
| `POST /auth/password` | 保留旧密码修改路径；扩展为也可接受同账号、短时、单次的钉钉验证凭据，设置／重置后撤销全部旧会话 |

密码验证凭据不经 URL 或浏览器持久存储传递：使用受保护的短时 Cookie 关联服务端授权事务，最终设置密码时原子消费。临时密码账号可访问必要的重新验证入口，但完成改密前仍不能访问业务接口。

## 授权处理

1. 发起端设置 HttpOnly、SameSite=Lax 的事务 Cookie；生产 Secure，开发 loopback 沿用现有开发配置。已有账号的绑定／重新验证还绑定发起会话和目标成员，不能让登录用途的事务直接修改密码。
2. 使用官方浏览器授权码流程，申请组织上下文；服务端通过用户凭证取得身份，再通过企业应用凭证验证指定组织内的成员及通讯录授权范围。管理员须将此范围限定为允许登录员工，并与应用可使用范围保持一致；不把工作台可见性自动等同于 API 数据权限。接口权限未开通、成员不在授权范围或信息不一致时拒绝；真实联调验证范围外成员被拒绝。
3. 使用固定官方 HTTPS 地址、TLS 验证、请求超时及有界响应；不提供自定义授权服务器地址，不把敏感凭证放入诊断。钉钉接口具体路径和最小权限以选用接口的官方文档核对，用户凭证与企业凭证不混用。
4. 回调先原子消费 state，再执行外部请求；不持有公司锁等待网络。完成后在事务中重新校验配置版本／启用状态、成员状态和身份唯一性；失败重新发起，不复用授权码。
5. 登录用途才允许自动开户；绑定、配置试登录及密码重新验证不得创建员工或切换成另一个人。已关联身份与当前目标成员不符时拒绝，不以钉钉新身份覆盖旧账号。
6. 复用现有 8 小时会话、CSRF、成员停用校验及退出逻辑。密码变更、解绑／换绑等身份敏感操作撤销旧会话及相关授权事务，避免验证后状态已改变仍可继续使用。

## Web 交互

- 保留现有登录卡片，只有启用时显示钉钉入口；发现接口失败不能妨碍密码登录。账户页展示账号及密码状态，不要求钉钉新员工输入不存在的旧密码。
- 配置页放在已有系统设置中，沿用共享控件；保存、启用、验证授权分别反馈。失败只展示明确的操作建议和请求 ID，不展示钉钉返回的敏感内容。
- 授权完成后由 `/auth/me` 恢复身份与 CSRF；返回目标使用预设的本系统路径，不接受任意外部跳转地址。绑定／配置验证回到账户／设置页面，普通登录进入工作助手。
- 当前聊天草稿只在页面内存中。跳转钉钉前复用离开保护，有未发送内容时明确提示并允许取消、复制文本或返回密码登录；不静默丢弃，也不为此把正文、附件或凭证写入 localStorage。

## 公网 IP 与后续域名

- 应用同源运行在 `https://<固定公网IP>`，回调路径由受信 `PAA_WEB_ORIGIN` 生成。部署时登记完整 URL，取得实际钉钉后台接受及跳转成功的证据；更换 IP／域名后同步 Origin、证书和钉钉回调配置，不重建身份数据。
- 保留 Caddy，补充显式加载外部 IP 证书及私钥的配置、只读挂载和续期后重载说明；不能依赖当前 Caddy 版本对 IP 默认生成的本地证书，让员工手动绕过浏览器警告。
- 推荐用支持 IP 证书的 Certbot／ACME 客户端获取公开信任证书，配置自动续期和部署钩子。Let’s Encrypt 的 IP 证书使用短期有效期；签发测试证书不能当成生产可信证书。实现时锁定所用客户端版本，按官方流程先验证续期和 Caddy 重载。
- Compose 示例同时保留域名入口的兼容方式，证书路径、IP、密钥不入 Git。只开放 Web／证书验证所需入口，数据库与 API 内部端口维持现状；本轮补配置与说明，不自动购买云资源或修改用户网络。

依据：[Let’s Encrypt 的 IP 证书与 Certbot 支持](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)、[Caddy 地址与 HTTPS 行为](https://caddyserver.com/docs/caddyfile/concepts)。

## 定向验证与交付

实施属于 S3，按改动边界执行一次必要检查，不因新增 Spec 扩大为桌面或真实模型测试。

- 服务端：新增钉钉固定响应测试，覆盖组织准入、并发开户、状态／重放、配置轮换、同账号密码验证、会话失效、密钥无回显及跨公司拒绝；结合现有 `test_company.py`、`test_management.py` 验证密码与成员管理。用 `npm run test:server -- <相关测试文件>` 指定范围，测试库执行迁移。
- Web：验证入口开关、设置／账户显示、错误与离开保护、电脑／手机视口；运行相关 Vitest 文件和 `npm run typecheck:web`，只格式化改动源码。共享契约影响的检查随实际消费范围补充。
- 部署配置：检查 Compose 渲染和 Caddy 配置有效性，证书续期／重载用测试配置验证；没有公网服务器时只报告配置检查结果，不宣称证书已签发或外网已通。
- 真实钉钉与手机：用户取得应用权限、凭证和服务器后，在日常环境完成开户、再次登录、密码设置及权限拒绝验证；从公司网络与手机流量访问。真实数据由用户控制，自动测试不依赖真实密钥。
- 业务实施交给实施 Agent，完成后由新的独立验收 Agent 检查；交付区分软件检查与真实授权／部署结果，外部条件缺失时保留未验证项。

迁移前备份数据库与加密主密钥。停止使用钉钉时先确认管理员密码可用，并为需要密码登录的新员工设置密码，再关闭入口；不删除身份或业务数据。回退旧代码必须处理空密码账号和 schema 兼容，不能仅回退二进制后继续接收登录。
