# Web 钉钉登录

状态：ACCEPTANCE。软件实现与本地验证通过，见 [验收结果](acceptance.md)；真实钉钉授权与公网部署等待外部条件。

## 目标与现状

在现有账号密码登录旁增加「使用钉钉登录」。管理员可以在系统设置中配置钉钉应用并控制入口是否开放。

当前 Web 使用账号密码、服务端会话 Cookie 和 CSRF 校验；账号归属公司，角色为管理员／员工，支持停用和首次修改密码。钉钉登录复用这些账号、会话及业务权限，不建立第二套用户或权限系统。

## 已确认范围

- 对接当前公司的钉钉企业内部应用，通过浏览器点击「使用钉钉登录」进入官方授权页；本轮不做钉钉工作台内免登。
- 首次登录通过公司成员资格校验后，自动创建本系统员工账号并关联钉钉身份；再次登录进入同一账号。账号唯一、不使用姓名或手机号推测已有账号的归属，新建账号始终为员工。
- 配置按公司保存，当前部署显式关联试点公司；不能任选数据库中的第一家公司处理匿名登录。保留数据隔离，本轮不增加多公司选择页面。
- 账号密码登录始终保留。普通浏览器首次使用仍可能需要扫码及授权，不能承诺跳过钉钉要求的确认步骤。
- 员工可在公司、家中或手机流量网络访问；按固定公网 IP＋可信 HTTPS 部署，不要求先购买域名。以后可切换域名，保留账号与业务数据。钉钉对实际回调地址的接受情况须实测。

## 用户行为

### 管理员配置

- 在系统设置增加「登录方式」，沿用现有 Web 的颜色、控件和响应式布局。
- 钉钉配置包含企业 CorpId、Client ID／AppKey、Client Secret／AppSecret 和启用开关；显示可复制的回调地址及必要的钉钉后台配置说明。
- 默认关闭；配置完整后才能开启。保存配置与启用分开，关闭后服务端停止接受新的钉钉登录，登录页隐藏入口。
- Secret 加密保存，读接口只返回是否已配置；编辑留空保留原值，显式替换才能更新。普通员工不能读取或修改公司登录配置。
- 区分「配置已保存」与「真实授权验证成功」，提供试登录入口，不把字段校验当作连通性验证。

### 登录与账号关联

- 服务端核对授权组织与配置的 CorpId，并验证用户属于该公司的有效成员及应用允许的范围；失败或无法核验时不开户、不登录。不能仅凭钉钉个人信息或浏览器提交的 CorpId 自动接纳用户。
- 自动开户与外部身份关联在同一事务完成；并发首次登录只创建一个员工。已停用的关联账号不能通过重新开户绕过限制。
- 已有账号可在「账户」页验证本系统身份后主动绑定，保留公司、角色和业务数据；不按同名自动合并，不把钉钉管理员身份映射成本系统管理员。
- 「账户」页显示登录账号和绑定状态。解绑或更换需要再次验证本系统身份；没有其他可用登录方式时先设置本地密码，避免解绑后无法进入。
- 原有临时密码账号继续遵循首次修改密码要求；新钉钉账号的本地密码行为见下节。公司不匹配、绑定冲突或无进入权限时给出明确提示。
- 用户取消、授权过期、网络故障或配置错误时可重新发起，不能留下半绑定账号，也不能把钉钉错误原文和凭证直接展示给用户。
- 配置关闭或应用身份变更后，在途授权作废；已登录的本系统会话仍遵循现有退出、到期和成员停用规则。
- 每次钉钉登录重新核验成员资格；本轮不实时同步离职事件，本地密码和存量会话的访问回收仍需管理员停用本系统账号。

### 本地账号与密码

- 自动生成唯一且可复制的登录账号；首次钉钉登录直接进入系统，初始不开放本地密码登录，不生成需要展示的随机初始密码。
- 「账户」页显示账号和「未设置密码／已设置密码」。未设置时由本人按需设置；之后支持修改或忘记密码后的重置，不回显当前密码。
- 设置／重置密码须通过一次新的、与当前账号绑定的钉钉身份验证；已有密码也可按原流程验证旧密码后修改。密码仅保存哈希，强度沿用现有规则。
- 密码设置或变更后撤销旧会话，员工可使用新密码或钉钉重新登录；钉钉登录本身不会覆盖已有密码。

## 技术与安全边界

- 采用官方 OAuth 授权码流程：浏览器访问钉钉授权页，服务端接收回调、交换用户凭证并查询当前授权人的身份，再签发本系统会话。应用 Secret 和钉钉用户凭证不进入前端或 URL，不为登录长期保存钉钉 Token。
- `state` 随机、短时、单次使用，并绑定发起浏览器、公司、配置版本及登录／绑定用途；回调原子消费事务，拒绝重放、伪造、过期和跨浏览器回调。绑定还须关联经重新验证的本系统账号。
- 外部身份按公司与钉钉应用作用域建立唯一关联，保证并发绑定不能抢占同一身份；只使用服务端向钉钉核验后的身份及组织信息。
- 使用固定官方服务地址和受信回调地址；生产使用 HTTPS，回跳仅允许本系统路径。保持现有 Origin、CSRF 与 Cookie 边界，不以接入第三方为由整体放宽校验。
- 回调完成后清除地址栏中的授权参数。日志与问题诊断不记录 Secret、Token、授权码、完整回调查询参数或密码。
- 首期不做通讯录全量同步、钉钉消息推送、审批、自动分配管理员权限或 Electron 登录改造。

## 接入准备与网络

- 请公司钉钉主管理员授予「应用开发子管理员」权限，或由管理员创建应用后配置开发管理权限。需要能管理企业内部应用的凭证、API 权限、可用范围、安全设置与版本发布；不要求获得公司全部管理权限。
- 应用开通基础访问凭证权限 `open_app_api_base`、个人信息读权限 `Contact.User.Read` 和成员信息读权限 `qyapi_get_member`，数据范围覆盖允许登录的员工。不申请考勤、审批、消息等无关权限。
- 管理员登记回调 URL，取得 CorpId、Client ID 和 Client Secret，并发布给目标员工。具体最小接口权限以选用接口及真实授权验证为准，不直接照搬全量通讯录同步的权限表。
- OAuth 回调由浏览器跳转访问：员工设备须能到达应用的公网 IP，浏览器和服务端分别需要访问钉钉授权服务及 OpenAPI。该流程不引入供钉钉服务器主动推送的事件回调。
- 官方教程支持 `http://127.0.0.1:8000` 本机调试，并建议上线后使用公网可达地址；本机调试通过不能替代生产 IP 回调验证。取得权限后先验证目标回调，若平台拒绝再反馈具体限制，不擅自购买域名或更换方案。
- 本机 loopback 只用于本机开发。正式访问使用浏览器信任的公网 IP 证书并配置自动续期，不要求员工逐台安装内部 CA，不关闭 Secure Cookie 或 TLS 校验。
- 当前 Compose／Caddy 示例按域名部署；本轮补公网 IP、外部证书挂载／重载与续期说明，兼容以后按域名部署。申请服务器、实际签发证书和修改公网规则需具备部署条件后进行。

## 验收标准

- [x] 管理员能配置、更新 Secret、启用／关闭钉钉登录；员工越权被拒绝，敏感值无回显。
- [x] 本公司允许范围内的新用户首次钉钉登录自动创建员工，重复／并发登录复用账号；外部人员、停用账号无法开户或登录。
- [x] 已关联的管理员与员工进入原账号；关闭后入口和服务端授权同时受限，原有密码登录可用。
- [x] 账户显示登录账号和密码状态；新员工不设本地密码也能使用钉钉登录。设置／重置验证同一身份、拒绝复用验证结果，变更后旧会话失效。
- [x] 已有账号主动绑定、解绑及冲突处理保留原数据与权限，无法通过解绑锁死自己的唯一登录入口。
- [x] 拒绝无效／重复 state、错误公司、禁用成员和配置失效回调；并发请求不会产生错误绑定或越权会话。
- [x] 桌面与手机 Web 登录布局可用，取消、断网、超时和回退提示清楚；登录过期时切换钉钉授权不得静默丢弃当前未发送内容。
- [ ] 本地定向验证使用固定钉钉响应，真实授权单独记录。取得应用权限并登记实际回调地址后，完成自动开户、再次登录和至少一个外部身份拒绝场景；未取得条件时如实标为待验证。
- [ ] 公网 IP 部署配置包含可信证书和续期方式；实际部署后，在公司网络及手机流量下验证 HTTPS、回调和登录。以后切换域名不重新开户或丢失数据，旧地址会话可要求重新登录。

本轮文档按 S0 检查；实施涉及认证及迁移，按 S3 验证相关鉴权、公司隔离、会话和登录界面，不叠加桌面打包或真实模型测试。

## 外部条件

用户已取得开发权限并保存应用凭证；当前真实成员查询返回缺少 `qyapi_get_member`，待开通后继续授权验证。公网部署另待固定公网 IP 与可信 HTTPS 就绪。当前没有需要再次确认的产品问题。
