# Spec 063：工作勾选清单与轻量 Agent 操作

## 状态

已完成，独立验收 PASS；实现与验证见 [计划](plan.md)、[验收结果](acceptance.md)。真实模型仅验证 low、high 两档，样本范围与测量限制见验收记录。

## 背景

一项“今日待办”可能包含十几件事项，但整项工作只有一个状态，员工无法就近标记其中哪些事情已完成。用户希望增加逐项勾选，同时担心 Agent 不会正确生成清单，或因此增加提示词、模型调用与等待时间。

清单是工作正文的一种格式；工作继续承载内容、材料和修改记录。不自动把清单项拆成独立工作，不建设任务管理层级。

## 目标

- 工作所有者在详情中直接勾选／取消勾选，刷新后保留结果。
- 用户明确要求保存待办或勾选清单时，Agent 能通过简单参数生成、追加清单，程序维护编辑器结构。
- Agent 能读取完成状态，并在用户明确要求时准确修改指定项，保留其他正文、材料与勾选状态。
- 不为此功能增加模型处理阶段；验证普通问答、普通工作操作和清单流程的内容准确性、调用数与耗时。

## 非目标

- 子任务层级、依赖关系、甘特图、自定义字段，以及清单项独立负责人／截止日期／材料。
- 自动拆分工作、自动识别全部历史正文为待办、批量修改线上员工数据。
- 根据聊天推断事项已经完成，或由全部勾选自动把整项工作改为“已完成”。
- 改造通用聊天为任务规划流程，新增模型审稿、分类器或全量测试项目。
- 大改“我的工作”页面布局或团队统计口径。

## 当前行为

- `WorkRichText.tsx` 已接入 Tiptap `taskList/taskItem`，编辑模式有“勾选清单”按钮；详情阅读模式未提供勾选保存操作。
- 后端正文已支持 `taskItem.attrs.checked`；稳定编号主要针对顶层块，不能依赖每个清单项都有持久标识。
- Agent 已能通过 `get_work_item` 读取正文、通过 `execute_business_action` 保存正文。现有 `bodyEdits` 只提供顶层块追加、替换和移除，改单项勾选仍可能需要重写整块清单。
- 工作保存已有权限、版本冲突、幂等、修改记录和三级执行权限机制。前后端纯文本提取会丢失清单勾选语义，必须检查模型和历史展示实际使用的出口。

## 目标行为

| 场景 | 结果 |
| --- | --- |
| “把这些事项保存为今日待办：收周报、打印简历、下午开会。备注：打印机故障。” | 一项工作，三个未勾选事项，备注仍为正文 |
| “再补充寄快递”并明确指向上述工作 | 只追加新项，原有文字、编号、状态和材料不变 |
| 用户在详情点击“打印简历”的勾选框 | 保存该项状态，不调用模型；不改变整项工作状态 |
| “把今日待办里的打印简历标记完成” | 读取当前工作，按真实清单项编号定点设置完成；沿用执行权限 |
| “律师审核完成”对应“律师重审后交负责人确认” | 不据此把复合事项整条勾上；只有明确更新请求且范围不清时才澄清 |
| “还有哪些没做？” | 读取当前状态回答，不写入、不新增工作 |
| “写一个采购方案”或一般知识问答 | 正常回答；没有保存授权时不创建工作、不强制生成勾选清单 |

## 功能需求

### 1. 正文与清单结构

- 复用 `WorkDocument(schemaVersion=1)` 和现有 JSONB 正文，清单状态只有 `checked=true/false`。不新增任务表或另一份待办数据。
- 每个清单项有唯一、稳定的编号。首次创建由程序生成；改文字、排序、追加其他项和勾选不能重置既有项编号。复制一项获得新编号，重新创建不能复用已删除项的身份。
- 默认新项未完成。仅明确给出的完成事实可以作为初始完成状态；“计划做、等待确认、已经开始”不等于完成。
- 保留用户事项的顺序、对象、数量、时间和条件。默认不拆分／合并复合事项；备注和阻碍使用普通正文，不重复生成同一事项。
- 历史嵌套清单可继续显示、编辑；本期简便生成入口只生成平铺清单，不新增层级交互。

### 2. 详情直接勾选

- 本人工作详情的清单项可直接勾选、取消；勾选框放在项首，长文字自然换行。手机触摸区域足够，不添加逐行的大按钮。
- 勾选在当前页面显示保存中，成功后以服务端结果为准；失败恢复已确认状态并就近提示。避免整个正文重载、闪烁或滚动位置变化。
- 同一工作保存期间串行处理／临时禁用勾选，防止快速多次点击产生交错版本；失败不无限自动重试。
- 阅读模式即时保存；编辑模式仍随“保存内容”统一提交，不能边编辑边另发勾选请求覆盖未保存草稿。
- 他人工作和历史版本只读。管理员不因角色获得修改员工正文或清单的权限。
- 不增加独立进展面板。修改记录应呈现“打印简历：未完成 → 已完成”等实际变化，并沿用手动／助手／确认后执行的真实来源。
- 全部勾完、取消一项或修改清单均不自动改变工作整体状态、截止日期、阻碍和下一步。整体状态仍由明确操作修改。

### 3. Agent 生成、读取和更新

- 复用当前工作工具；在正文编辑参数中增加简便清单操作，不新增必须先调用的“任务识别／规划”工具。
- 保存待办时只需生成事项文字及必要的已明确状态，由程序转换为现有正文节点。追加整批事项在一次业务写入完成，不能每项调用一次工具或一次模型核对。
- 用户明确要求把旧正文整理为可勾选清单时，允许指定块转换，保留其他块。普通浏览、模型读工作和部署不触发转换。
- 逐项标记使用已读到的真实项编号及目标布尔值，不能按名称由服务端猜测、按易变化的序号定位，或通过整篇重写修改单项。
- 读取结果需同时保留文字、完成状态、项编号和工作版本；避免新增一份完整正文副本来增加上下文。模型使用的纯文本或报告来源不得把已完成、未完成混为一谈，清单全部完成也不代表整项工作完成。
- 用户要求完成／取消多项时可批量修改；任一编号失效、版本冲突或越权时整批拒绝，避免出现部分勾选却报告全部成功。
- 模糊指代、同名事项、只完成复合事项的一部分时，不猜测完成对象。明确“将这条整项标记完成”的指令可执行；普通聊天中的完成描述不自动授予写入权限。

### 4. 授权、重试与降级

- 简便参数与原有正文操作进入相同的授权、变更范围、预览、回执和事务边界。授权核对能看到项文字与前后状态，不能只看到不透明编号。
- 保留三级执行权限；需要确认时，确认卡显示具体项及状态变化。确认过期后不能覆盖他人或其他页面已经保存的新版本。
- 使用现有幂等键及工作版本校验；重复勾选同一目标状态无多余修改版本，网络重试不会重复追加清单。
- 参数格式和数据边界由程序校验。无效操作返回现有结构化错误，不执行半份清单，不因格式失败加一条新的模型修复流水线。
- 普通正文仍是兼容保存格式。若实际只保存了普通正文，必须完整保留内容并如实说明尚未建立勾选清单；这种结果不能算作清单生成验收通过。不得静默丢项、解析残缺 JSON 凑成清单，或把勾选失败降级为整篇覆盖。

### 5. 性能约束

- 普通聊天不新增清单分类调用、前置数据库查询或工作工具调用；不在通用系统提示中叠加长清单规则和大量示例。
- 说明集中在现有工作工具契约及对应业务规则中，以替换、精简已有说明为主。维持既有模型、思考强度、执行权限和任务预算。
- 相同业务动作沿用已有读取、授权和保存流程，不因每个清单项增加模型调用、查询回执或核对轮次。
- 定点勾选只发送项编号和目标状态，不让模型重新生成十几项正文，也不要求它确认自己刚保存成功的回执。
- 真实模型仅测试 low、high 两档，分别进行改造前后对照，不测试 max 或其他档位。交付分别报告两档的首段可见正文、端到端完成时间、模型／工具调用次数、输入输出 token，以及失败样本。测量口径和停止条件见 [计划](plan.md)。不能仅凭代码判断宣称准确率和速度不变。

## 边界条件

- 零项、空白项、超长文字、重复编号、未知／已删除／其他工作编号、非布尔状态均有明确校验，沿用正文容量上限。
- 多个清单块、重复项文字、换行、格式化文字、图片和材料夹在正文中仍保留原有结构；不把材料说明当成待办。
- 快速点击、双标签并发、先编辑后勾选、失败后重试、退出再进入，以及确认卡等待期间版本变化不能丢内容或重复写入。
- 用户明确给出的日期、对象和顺序不能被示例覆盖；实际日期以现有时区机制为准，测试固定业务日期。

## 技术约束

- Web 遵循 [UI 设计基准](../../docs/design/README.md)，沿用 CSS Modules、唯一请求入口与现有身份处理。
- HTTP 与 Agent 共用工作业务用例；稳定编号、清单转换和局部编辑属于工作领域，不反向依赖 Agent。
- 变更涉及公共请求语义、持久化内容和权限链，实施按 S3 在相关子系统验证；不因此默认运行整个项目所有测试或真实破坏生产环境。
- 使用合成的长清单覆盖线上反馈的形态，不将员工真实内容、密钥或生产数据库写入仓库、测试输入和日志。

## 兼容性要求

- 旧客户端原有 `body/bodyEdits` 和非清单正文继续可用；新写法与全量正文替换互斥，语义不能含混。
- 无编号的旧清单采用可重复得到的兼容编号，首次合法写入再持久化。只读请求不写数据库，不产生新版本；历史快照不回填、不改写。
- 旧纯文本／普通列表不自动转换。上线后可由工作所有者主动整理；本期不直接修改线上反馈者的工作。
- 不需要新的数据库表、离线模型或部署服务。若实施发现必须迁移，应先说明具体原因并更新计划。

## 验收标准

- [x] 详情直接勾选／取消、刷新、移动端及编辑模式保存均正确，其他用户和历史版本不可操作。
- [x] 明确保存多项待办时生成完整、可勾选的一项工作；备注、条件、顺序不丢失，没有拆成多条独立工作。
- [x] 追加、整理、定点勾选和取消只修改授权范围，保留其余内容、材料、编号与状态。
- [x] 读取未完成事项准确；复合事项的局部完成不误标整项，清单全完成不改整体工作状态。
- [x] 版本冲突、重复请求、无效编号和跨用户操作不造成错误写入；确认卡和修改记录反映真实变化。
- [x] 普通问答、普通正文和原工作操作无新增处理阶段、模型核对或重复工具调用。
- [x] 固定输入的相关自动测试及 low、high 两档真实模型流程完成；质量与耗时按档位分别对照，保留首轮失败和测量限制，不用重跑到绿替代结论。
- [x] 独立验收说明通过、失败与未执行项；没有真实对照证据时，不宣称“速度和准确率不受影响”。
