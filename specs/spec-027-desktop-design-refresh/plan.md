# Electron 设计改造实施计划

范围见 [功能规格](spec.md)，视觉依据见 [UI 设计基准](../../docs/design/README.md)。本次 Spec 文档按 S0 检查，业务实施按 S2 的桌面呈现范围验证。

## 模块与顺序

以下路径相对 `apps/desktop/src/renderer/`：

| 顺序 | 模块 | 实施内容 |
| --- | --- | --- |
| 1 | 现有 Electron 页面、归档原型 | 在默认日常环境查看并保留代表性改造前截图；列出页面、子视图和弹层，不调用模型或修改配置来填充页面 |
| 2 | `styles/theme.css`、`styles/select.css`、`styles/brand.css`、`styles.css` | 映射中性语义色，补齐状态、控件、滚动条、弹层与焦点；清理本次替代的硬编码颜色及重复覆盖 |
| 3 | `App.tsx`、`Navigation.tsx` | 紧凑侧栏和顶部路径、铺满主画布、统一标题操作、滚动边界及活动录音条；保留导航和主题所有者 |
| 4 | `MeetingLibraryList.tsx`、`MeetingActions.tsx`、`MeetingWorkspace.tsx` | 会议工具栏、列表、空态、分页、详情头部及菜单；核对滚动恢复和最小窗口 |
| 5 | `Transcription.tsx`、`SpeakerPanel.tsx`、`MeetingMinutes.tsx`、`MinutesAnalysis.tsx`、`MeetingProcessingState.tsx`、`AudioPlayer.tsx` | 录音与文本、说话人分组、分析层级、处理反馈及播放器；优先保留既有生命周期、ref、订阅与功能入口 |
| 6 | `ModelSettings.tsx`、`LocalModelSettings.tsx`、`CompanySettings.tsx`、外观组件 | 设置分区、模型列表／编辑、折叠与错误反馈，覆盖草稿、下载、游客、离线及确认状态 |
| 7 | 改动文件与相关桌面测试 | 清理无使用者的旧样式，完成实际页面截图、定向交互及独立验收 |

主题与页面层叠高度耦合，由一个实施 Agent 串行推进，再由新的独立 Agent 验收。先完成会议列表／详情和模型服务的代表性页面，对照基准后扩展，不到最后才检查视觉。

## 实现边界与风险

- 可按实际复用提取桌面内部展示组件／样式文件，沿用当前目录职责；不为本次视觉改造复制整套 Web feature 结构或迁移所有 CSS Modules。
- 统一语义变量后仍检查局部硬编码颜色、浏览器原生控件、Portal／dialog 的主题继承；避免在样式文件末尾追加大批 `!important` 覆盖。
- `App` 当前用 `hidden` 保留列表和设置视图；调整外层容器不能顺手变为条件卸载，使搜索位置、模型配置草稿或订阅丢失。
- `MeetingWorkspace` 的纪要／文字共享一个 `AudioPlayer`；保留对应 ref、seek、来源定位与退出释放逻辑，不通过改变 React key 或多份播放器解决布局问题。
- 搜索命中定位、页签焦点、原生日期点击、更多菜单及倍速选择均有既有行为。更改 DOM 时同步真实定位关系，不能删除事件和无障碍属性以简化样式。
- 网络反馈、进度、模型指标与说话人信息继续消费现有数据，不添加假进度、占位员工或“默认成功”。没有准备好的状态如实展示。
- API、IPC、存储键、数据库和核心进程不变，不需要数据迁移。回退只涉及本次桌面呈现代码及关联测试。

## 验证安排

### 工程检查

- 编辑时用项目 Prettier 整理本次源码文件，最终只检查改动文件格式；ESLint 限桌面 renderer 与实际修改的测试。
- 执行一次 `npx tsc --noEmit -p apps/desktop/tsconfig.renderer.json` 和 `npm run build`，确认 renderer 类型及桌面资源产物正常。
- 根据实际改动运行相关现有用例；布局影响列表、导航和服务表单时，优先选取 `tests/e2e/desktop/app.spec.ts` 的基础界面、分页、synthetic capture 用例及 `summary.spec.ts` 的服务／纪要流程。固定录音和本地 HTTP 响应不等于真实麦克风或付费模型验收。
- 没有行为变化的纯样式不新增复述实现的测试。调整定位器时保留原有效断言，使用角色／标签，不绑定 CSS 外观求通过。
- 不默认执行全量 Python、Web／服务端测试、真实模型下载／推理、双平台打包安装或 CI。已有检查在最终代码通过后不重复；失败先查明确原因。

### 真实页面核对

在项目根目录 `npm run dev`，使用用户默认数据目录和已保存的录音、模型及配置，不另设 GUI 隔离环境，不输出密钥，不改用户资料。需要故障注入或数据删除的自动测试继续使用自己的临时数据，不能指向日常目录。

逐页截图至少包含：会议列表、当前会议、详情纪要、文字双视图与说话人弹窗、模型服务、本地模型、公司连接、外观和命令面板。对照统一基准及当前 Web 的控件表现，检查颜色、层级、字号、间距、滚动与操作位置。桌面特有页面按同一设计语言判断，不照搬原型的虚构业务。

| 场景 | 检查重点 |
| --- | --- |
| 默认窗口 1240 × 820 | 所有页面和主要子视图，空／有数据、加载与错误；设置区随窗口伸展 |
| 最小窗口 900 × 640 | 工具栏换行、详情正文高度、播放器、录音操作、模型编辑与弹层完整可达 |
| 宽屏 1440 × 900 或更宽 | 主画布铺满，无固定窄卡片居中留白；正文行宽与列表可读 |
| 浅／深／系统跟随 | 所有页面组均覆盖，公共选择器、状态色和弹窗在两种主题检查 |
| 关键交互 | 搜索／分页／返回、单条更多菜单、日期整框、文字来源 seek、播放器倍速、模型参数下拉、折叠、确认、命令键盘导航 |
| 状态保护 | 切页仍录音且操作可达、唯一播放器、服务草稿保留、错误不遮挡主要操作、离线声纹状态与游客入口 |

不把全部状态、尺寸和主题做笛卡尔积。默认不为截图重新下载或重跑全部模型；日常数据没有的危险／失败状态使用既有自动测试验证，记录覆盖方式。未经新的需要不触发公司登录、声纹清理、真实会议重转写或收费纪要生成。

截图和必要日志放 `artifacts/spec027/`，验收文件仅记录覆盖、结果、证据及未测项。macOS 实机与 Windows 未测项分开说明；本机没有 Windows 时不宣称双平台已实测，也不自动触发远端工作流。

独立验收检查需求与实际界面，复用已通过的工程检查结果，只补缺失的定向交互；已闭环后停止，不把历史 Spec 未测项目扩成此次全仓库验收。
