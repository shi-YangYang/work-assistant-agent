# Spec 062：Noria 宠物工作状态

## 状态

已实施，独立验收通过。采用已确认的双爪交替敲键盘样片，按加大后的动作幅度接入正式页面；空闲恢复原眨眼形象。验证范围与限制见 [验收报告](acceptance.md)。

## 背景

借鉴此前观察到的 Muse 交互：没有任务时只显示宠物和名字；处理任务时在名字下显示“努力工作中”，宠物也切换到工作形象。Noria 已有全页面悬浮宠物和眨眼，但与任务执行没有联系，用户切换页面后无法从宠物判断任务是否仍在处理。

## 目标

- 让顶部宠物准确表达当前用户的聊天任务是否正在处理。
- 从发送、上传到后台处理连续展示状态，切换页面不丢失，任务结束后恢复。
- 保持原小熊的角色特征、眨眼、悬浮位置及外观弹窗；以原品牌图为编辑基础制作状态素材。

## 非目标

- 不新增任务中心、任务列表弹窗、进度百分比、完成通知或声音。
- 不修改 Agent 提示词、思考强度、工具流程、任务调度与现有消息状态。
- 不做 Blender 建模，不用平面图片翻转模拟转头，不增加鼠标悬浮放大或摇摆。
- 本期不接入独立的报告生成、Electron 会议纪要或其他用户的任务。

## 当前行为

- `Shell` 在已登录的所有页面挂载 `PetStage`，宠物绝对定位，不占据独立内容行。
- `NoriaPet` 使用原头像及眨眼素材；页面不可见、系统减少动态效果或外观弹窗打开时遵循已有动画规则。
- 聊天页面通过 `useAssistantTask` 查询当前会话任务，使用共享 `job-feedback` 订阅实时状态；切换会话或卸载页面会改变订阅生命周期。
- 现有活动任务查询按会话进行，不能在刷新后直接获知当前用户其他会话的活动任务。
- 发送语音或附件时，消息区域已有发送提示，但顶部宠物没有对应状态。

## 目标行为

以下为已确定的目标行为。

| 场景 | 宠物表现 | 名字下方文字 |
| --- | --- | --- |
| 没有正在处理的任务 | 原形象，保留眨眼 | 不显示 |
| 点击发送，上传或提交尚未结束 | 工作形象 | 努力工作中 |
| 已排队、语音识别、思考、工具执行或生成回复 | 工作形象 | 努力工作中 |
| 所有相关任务成功、失败或已取消 | 恢复原形象 | 不显示 |
| 所有相关任务暂停等待用户补充或确认 | 恢复原形象 | 不显示；具体操作仍在聊天中处理 |
| 已知任务的状态连接中断，无法确认是否仍在执行 | 原形象，不假装仍在工作 | 状态待同步 |
| 刷新页面，首轮状态尚未读取 | 原形象 | 不显示；查询完成后按真实状态展示 |

## 功能需求

### 1. 状态范围与聚合

- 覆盖当前登录用户各会话中的聊天任务，在全部已登录页面展示；管理员同样只看自己的任务。
- 聊天中的搜索、编码、沙盒、公司业务操作及语音解析都沿用同一个聊天任务状态，不增加每种工具的宠物状态。
- 当前浏览器提交期间使用短暂的本地发送状态；收到任务回执后，以同一任务接管，不在中间切回空闲。
- 多个会话同时处理时，只要有一个确认正在发送、排队或运行，就显示工作状态。一个任务结束不能清空另一个任务的状态。
- 没有确定活动任务但仍有无法同步的已知任务时显示“状态待同步”；服务端确认任务结束后才清除对应未知状态。
- 失败消息、历史草稿、待重试任务和等待人工输入不算正在执行。重试被接受后重新进入工作状态。

### 2. 工作形象与布局

- 使用现有高清品牌图生成工作形象，保持原小熊的头身比例、脸型、耳朵、奶白毛色、蓝色围巾与毛绒质感；生成结果需逐项比对，不能假定模型会完全保持角色一致。
- 工作动作明确为两只爪子交替敲键盘：爪子抬起、落下接触按键，不能仅眨眼、晃动整张图或在电脑外侧挥手。
- 预览采用可见的独立浅蓝键盘，避免笔记本屏幕遮住动作。头、脸、身体与键盘保持固定，仅手臂／爪子局部变化；保留白色圆形头像及名字标签。空闲仍沿用现有眨眼，工作时的眨眼可以在打字预览认可后叠加。
- 采用已确认的生成素材与本地 Canvas 双爪按压动画，不依赖付费图生视频套餐。首帧固定角色主体，仅对左右爪子区域交替形变，幅度使用预览中加大后的 32 源像素；避免全图逐帧导致五官、围巾与键盘漂移。
- 在放大预览与实际宠物尺寸下均需看清敲键盘动作，保留循环、暂停与减少动态效果控制；将所需素材归档到正式资源目录，不依赖忽略目录或预览服务。
- 状态文字位于名字下方，作为悬浮组件的一部分，不产生整行占位，不推动正文，不拦截周围区域点击。
- 宠物主体和名字位置不因状态出现而移动。桌面、窄屏及不同主题下均需与标题、会话操作、导航按钮保持可用间距。
- 点击宠物仍打开现有外观和主题弹窗；本期不改变点击行为。

### 3. 连续性与防闪烁

- 工作状态不跟随“思考→工具→生成”等短步骤切换文字，也不在每个步骤之间重新挂载宠物。
- 本地发送与服务器任务交接、重试与新 attempt 交接期间连续显示；不得通过反复读取消息列表弥补状态衔接。
- 工作形象切换复用同一展示容器并预加载素材，避免资源加载造成空白。
- 不人为延迟显示工作状态，也不为了动画播放完整而在明确结束后继续假装工作。极短任务按真实生命周期结束，不强制延长。
- 正文打字机展示继续遵循原规则；宠物反映提交与后台处理，不为前端补播文字单独维持工作状态。

### 4. 同步与恢复

- 状态观察由登录后的应用层持有，不随业务页面卸载；刷新后通过一次当前用户活动任务快照恢复。
- 复用现有任务事件通道。同一账号下同一个 job 的消息区和宠物共享连接，不能分别打开一条相同 SSE。
- 仅在登录／刷新、回到浏览器标签页、网络恢复，以及同账号其他标签页明确通知任务变化时按需同步；同一轮触发合并，取消过期请求。
- 不新增定时 GET 轮询、自动 POST 重发，也不因从其他应用切回窗口就刷新。
- 本页接受的任务立即纳入观察；其他设备新建的任务在上述同步时机发现，本期不承诺跨设备即时发现。
- 断线不能推断任务成功或失败，不展示过期的工作动画；原有错误提示仍由已有区域承载，不新增错误弹窗。

## 边界条件

- 登出、切换账号或身份失效立即释放订阅并清空本地活动状态；旧账号延迟返回的响应不得重新点亮宠物。
- 使用任务 ID、attempt、fence、事件序号区分当前执行和过期事件，继续沿用现有反馈的新旧判断规则。
- 活动快照与刚收到的发送回执发生竞争时，较旧快照不能移除较新的任务；确认为删除、失去访问权或终态的任务应释放。
- 取消请求发出不等于取消成功；收到确认前继续反映已知状态。发送失败要清理对应临时状态，不能影响其他任务。
- 图片加载失败保留现有后备形象；减少动态效果时停动画但仍表达工作状态。关闭外观弹窗后恢复正确形象及动画。
- 上传未完成时保留现有离开／刷新处理，不把尚未提交的本地语音或附件误当成可在刷新后恢复的后台任务。

## 技术约束

- 宠物只投影已有业务状态，不增加模型调用、业务写入或任务心跳，不等待宠物渲染后才提交消息。
- 增加最小的当前用户活动任务只读查询，复用既有身份、公司、所有权和业务可见性校验；返回任务摘要，不返回对话正文、工具参数或模型思考内容。
- 跨页面观察放在公共请求／订阅层，布局通过公共 hook 读取；公共层不得反向依赖聊天功能模块。
- 不新增数据库表、migration、动画库、3D 运行时或浏览器端后台轮询器。
- 不修改生产配置或部署线上服务。

## 兼容性要求

- 保持当前每个会话的发送、中断、重试与人工交互规则。
- 保持全部页面可眨眼、主题选择、手机导航、焦点返回及系统减少动态效果行为。
- 现有会话任务接口和事件协议继续可用，新增账号活动摘要不替代权限校验与消息详情接口。

## 验收标准

- [x] 静态角色与动画预览获得认可后才接入；空闲显示已确认的空闲形象和名字，工作时出现工作形象及“努力工作中”。
- [x] 工作动画中的两只爪子交替接触可见键盘；主体与键盘稳定，实际宠物尺寸下仍能辨认打字动作。
- [x] 普通文本、语音、图片／文件消息从提交到任务接管没有空闲闪断。
- [x] 思考、搜索、业务操作、沙盒和流式回答均可持续表达工作；终态及等待人工输入正确退出工作状态。
- [x] 切到我的工作、成员管理、设置等页面仍显示自己的活动任务；刷新可以恢复，不把管理员当作公司任务监控者。
- [x] 多任务、失败、中断、重试、断线、旧事件、账号切换与查询竞争不会造成卡死工作状态或串号。
- [x] 不新增定时轮询、模型调用、业务 POST 或同 job 重复 SSE；正常聊天耗时不因宠物额外等待。
- [x] 桌面与手机布局不增加空行、不推动正文、不遮挡必要按钮；主题、眨眼、减少动态效果和素材失败后备行为正常。
- [x] 相关定向测试和独立验收通过，实际浏览器结果与未覆盖的真机限制如实记录。

## 待确认问题

无。按已确认动画实施状态与页面接入。
