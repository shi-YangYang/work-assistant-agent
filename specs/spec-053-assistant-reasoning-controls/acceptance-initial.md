## Issues

1. **P2 — 附件上传结束时可绕过强度版本校验。** `apps/web/src/features/assistant/hooks/useMessageSubmission.ts:114` 在上传的 `await` 之后重新调用 `reasoning.reference()`，但未验证结果；该方法在账号偏好保存中返回 `undefined`，`messageSubmission` 随即省略 `reasoning`，第 125 行仍发送消息。会话 A 上传时切换到会话 B 并保存强度即可进入此状态，新客户端请求因此走旧客户端兼容路径，可能接受与预期不同的强度。上述 probe 已记录发送 body 缺少 `reasoning`。首次构造提交请求前应再次确认已保存引用；保存中保留草稿和已上传附件，不能通过省略字段绕过校验。既有不确定请求的幂等重放保持原身份。
2. **P2 — 管理员开放档位开关与文案分离。** `apps/web/src/features/model-services/components/catalog/ReasoningPresetEditor.tsx:120` 仅使用 `layoutStyles['check-label']`，该类没有横向排列规则，继承全局 `label { flex-direction: column }`。`artifacts/spec053/admin-preset-1440-light.png` 与 `admin-preset-390-dark.png` 均显示复选框独自居中、文案在下一行，无法保持现有表单开关的视觉关系。应在预设编辑器的私有样式中使用一致的横向排列与触摸区域，并复核桌面和窄屏。
3. **P1 — 现有助手模型首次开放档位被保存校验阻断。** `apps/server/app/modules/model_services/service.py:77` 使用新模型草稿校验旧用途选择，而第 106 行要求旧选择已引用一个开放预设。当现有助手路由为 `presetId=null`、模型没有预设时，管理员在草稿新建开放的 `low` 并明确选中它，保存仍返回 422“工作助手初始预设必须选择一个已开放的思考强度”；新预设尚未落库，用途页也无法先选它。`apps/web/src/features/model-services/hooks/useModelServiceController.ts:129` 在切换用途页前先保存服务，因此“保存并设置用途”同样失败。主 Agent 的隔离 API 记录与代码一致，且用户当前配置正属于该起点。需要支持在管理员明确选择初始预设后原子保存开放列表与助手初始选择，或提供同等清晰且无需解绑助手／重复保存的配置流程；不能静默猜选第一项。
