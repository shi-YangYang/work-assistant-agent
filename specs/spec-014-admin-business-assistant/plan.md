# Plan — 管理员业务问答与督办事项

业务范围与产品行为以 [Spec](spec.md) 为准。本文件只记录模块、数据流及技术约束；最终实现见 [Implementation](implementation.md)。

## 模块与实施顺序

1. `business_access.py` 统一业务授权和来源读取；`api.py`／`service.py` 复用，不能仅放开现有 owner 过滤。
2. `agent/harness.py` 增加角色工具、版本化读取凭据及结果校验；`worker.py` 贯通任务恢复与发布。
3. `models.py`／迁移保存授权依赖和业务关联；确认、编辑及 `deletion.py` 处理版本冲突与来源失效。
4. 共享契约与 Web 工作助手、来源弹窗、工作页接入；保持原路由、主题及窄屏布局。

## 查询与 Harness 契约

`登录身份 → 任务上下文 → 角色工具 → 授权查询 → 版本化读取凭据 → 来源回答／本人待确认事项`。

- actor 来自服务端会话。角色、公司、owner、资料类型、发布／删除状态和关联关系均在查询及 DTO 前检查；工具不接收 SQL、任意 URL 或身份覆盖参数。停用员工的已授权历史可读，其账号和任务不可继续运行。
- 当前状态读取 `WorkItem`，期间变化读取 `WorkRevision`，报告读取已提交 `ReportRevision`；关联消息、转写和文件提取分别使用实际版本。日期按公司时区的半开区间处理，跨期报告显示原周期。
- 每页最多 20 条；游标绑定公司、身份和筛选。聚合在授权数据集上计算，正文保留有效结构，返回真实计数、范围、`hasMore` 与截断说明。详情不足不能伪称完整。
- 沿用 Deep Agents／LangGraph、`BoundedChatModel`、`ToolBoundary` 和 `GuardedSaver`。模型可见与执行允许的工具集合采用同一规则，执行时仍独立授权；保留原调用、工具、上下文及时间预算，不为查询自动解析文件、识图或转写。
- 来源必须由真实工具读取生成凭据，最终引用由服务端构造。完整授权依赖不等于模型选择展示的 citations；材料和历史回复不能授予工具或写入权限。纯查询不产生工作或报告任务。

## 持久化、恢复与并发

- 在 `0004_documents` 后增量迁移；旧记录采用兼容默认，不自动成为团队共享。业务关联单独保存，不混入 `WorkRevision.source_ids` 的本人原消息 ID 语义；文件引用保持兼容。
- Job 保存初始权限范围及完整读取依赖。依赖贯穿 Message、上下文／摘要、`replyTo`、checkpoint、草稿、工作和修订。每次工具／模型调用前、恢复及发布／返回时复核当前身份；范围改变终止旧任务，不能扩大解释旧 checkpoint。
- 普通修订保留带版本的旧回答；撤权或删除使相关派生回答、未确认建议和模型上下文失效。已确认本人工作独立保留，失效关联不再暴露原材料；降权后隐藏工作中的团队派生内容。
- 删除事务与任务 fence 覆盖跨员工依赖，阻止晚到结果恢复正文。固定锁序：公司锁先于 owner／job 锁；外部模型请求、上传准备和目录测试不持公司锁。
- 督办沿用编辑、确认、忽略与幂等；写入 owner 固定为本人。编辑／解除关联不能丢失既有依赖，确认复核本人工作版本及来源版本。旧会话与员工主流程原位保留，日常库迁移前备份。

## Web 与验证

- Web 只呈现服务端授权投影。正文编号通过服务端引用数组打开来源，不采用模型 URL；历史失效时清理正文／编辑缓存，防止旧在途响应覆盖。来源卡片和当前详情保持返回上下文。
- 按 S3 验证公司子系统：越权及模型输入过滤、历史和在途撤权、来源删除／改版、分页与时间、同名、伪造引用、督办确认和原员工回归；补相关 Web 检查及电脑／约 390px 界面操作。
- 自动化使用固定输入；少量真实模型联调另记服务、配置、失败和恢复，不能互相替代。危险操作仅用专门样本，不修改日常账号权限或真实业务。实施与独立验收分工遵循项目规则，不扩大为 Electron、ASR、打包或重型 CI。
