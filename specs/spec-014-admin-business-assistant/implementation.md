# Implementation — 管理员业务问答与督办事项

2026-09-14 · 实现与返工已完成。需求见 [Spec](spec.md)，独立结论与真实联调见 [验收](acceptance.md)。

## 实现摘要

- `business_access.py` 实现共享授权、版本化来源、日期／状态查询、20 条分页和真实聚合；超出 500 条或读取预算时要求缩小范围。
- Harness 按角色提供四个团队工具，依赖贯通任务、历史、摘要、checkpoint 与发布；沿用现有 runtime、预算和恢复机制。锁序及数据契约见 [Plan](plan.md)。
- 督办复用本人工作与人工确认，独立 `business_links` 保存关联。来源删除保留已确认本人事项、使关联失效；撤权隐藏团队派生内容，不能经编辑或新修订清空授权标签。
- Alembic `0005_business_access` 增加 JSON 授权／关联字段和两个 GIN 索引，旧数据默认权限不变。测试库迁移成功；日常库备份后迁移。
- Web 增加管理员问题示例、服务端来源编号、版本弹窗、查询覆盖范围及督办关联；复用现有工作卡片和页面导航。

## 已关闭的返工

- 首条真实查询的异步生成器收尾错误已修正；从已完成 checkpoint 发布时未增加模型调用。查询范围和引用展示随该轮反馈修正。
- 独立验收发现普通草稿更新督办、工作新增团队原消息来源两条路径会丢失依赖。`inherit()` 现在单向合并已授权依赖和关联，覆盖编辑／解除绑定／直接确认／新修订及派生报告；原复现已纳入正式回归测试。
- 真实模型曾仅回复“已准备建议”而未调用保存工具。提示词消除普通进展工具冲突；最终答复核对数据库建议，最多进行一次持久化补正并受原预算限制。失败如实返回未生成，同名澄清不补正，纯查询不生成督办。
