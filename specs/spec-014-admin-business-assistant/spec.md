# Spec 014 — 管理员业务问答与督办事项

## 状态

DONE · 2026-09-14。[独立验收 PASS](acceptance.md)，实际覆盖、模型接口 500 与恢复记录以验收报告为准。技术取舍见 [决策 0014](../../.ai/decisions/0014-team-assistant-authorization.md)，实施方案见 [Plan](plan.md)。

## 背景、当前行为与目标

公司 Web 已有多会话、员工上报、可纠正工作、日报／周报、团队看板及文档解析。管理员能通过团队页面查看授权资料，但 harness 的工作／文件检索主要限制为本人，尚不能通过助手跨员工整理进展；管理员“我的工作”目前也没有结构化的员工业务关联。

目标是在现有工作助手内形成“询问团队情况 → 查看依据 → 确认自己的督办事项 → 再次查询进展”的流程。Web 继续使用现有会话、工作卡片、团队详情和响应式布局；本轮不改 Electron，也不自动上传本地会议。

## 功能需求与目标行为

### R1 — 可查询的业务范围

- 员工继续查询自己的授权资料；管理员可查询本公司员工的已确认工作与修订、已提交日报／周报，以及与这些业务记录有关联且仍可访问的原始消息、语音文字和已提取文件段落。报告只读取已提交版本，不将更正草稿当成已发布报告。
- 没有关联已确认工作／已提交报告的已发送上报不开放独立检索。现有人工团队查看范围不因本轮自动收缩或扩大。
- 不开放他人的会话列表、会话上下文、助手回复、待确认进展草稿或未发送附件；其他管理员的私人资料始终不纳入团队检索。不能依靠模型猜测哪些消息属于“私聊”；现有消息没有这类隐私分类。
- 图片／音频原件仍通过已有授权入口查看；团队问答使用已有文本及提取结果，不为查询自动重新识图、转写或发起 OCR。资料缺少可用文本时说明缺口。

### R2 — 询问、追问与有依据的汇总

- 支持按员工、时间、工作关键词及状态询问，例如“本周有哪些阻碍”“小张最近在推进什么”“上次提到的报价问题解决了吗”。名称有歧义时列出有权查看的候选并澄清，不随意选择同名员工，不捏造项目归属。
- 本轮无时间参数的“当前进展／当前阻碍”读取最新工作状态；“近期”默认最近 7 天并显示实际日期范围。“本周／上周”按公司时区、周一至周日解释。期间发生了什么依据该期间修订或报告，不能用今天的状态冒充历史情况。
- 回答展示实际使用的员工范围、时间范围与查询时间；区分已确认状态、员工陈述、助手推断和信息不足。未上报／未更新不等于没工作、逾期或工作表现差；没有足够依据不能推断某问题已解决。
- 关键业务判断附可点击来源，显示对象、所属员工、版本／时间。工作跳转现有团队工作详情，报告跳转已提交版本，文件引用保留实际位置。来源无法授权或已经删除时不泄露标题、片段或可猜测的访问地址。
- 连续追问保留当前会话意图，同时重新读取相关业务事实；其他会话可检索已确认业务，但不拼接私人聊天。引用旧答复时明确其时间，不能把旧回答当作最新证据。
- 查询量超过预算时分页或明确只覆盖了哪些记录，允许用户缩小范围；不能把前 20 条概括成整个团队。没有证据时直接说明，不制造引用。

### R3 — 管理员本人的督办事项

- 单纯问答不自动创建工作。用户明确要求“加入我的工作／跟进这件事”时，助手提供待确认建议；管理员可编辑、确认或忽略。确认后才进入本人的“我的工作”，沿用现有工作状态和修订机制。
- 事项保存管理员本人为负责人，以及经过校验的关联员工、工作／报告来源和本人的下一步。关联员工不是被派单人；本轮不通知员工、不代员工确认／提交／修改记录，不自动创建另一人的任务。
- 可关联多个有权限且有明确依据的业务对象；“这个／他们”指代不清时先澄清。创建前检查本人已有相关事项，避免同次重复操作产生重复工作；已有事项更新仍由本人确认并检查版本。
- 再次询问督办事项时展示员工资料的最新变化及来源。员工工作完成不自动把管理员的事项标记完成；管理员事项的修改／完成继续由本人确认。
- 关联源更新时提示当前版本变化；确认前重新检查来源权限与相关版本。来源删除或不再有权限时不沿用旧建议直接确认。已确认的管理员事项作为独立业务记录保留，不因原始材料删除递归删除；失效关联不再暴露原材料，保持 Spec 011 的来源保留边界。

### R4 — 服务端授权与权限撤销

| 操作 | 员工 | 管理员 |
| --- | --- | --- |
| 查询本人资料、管理本人工作 | 沿用原权限 | 沿用原权限 |
| 查询员工团队业务 | 不允许 | 仅本公司、R1 范围 |
| 读取他人私人会话／未提交草稿 | 不允许 | 不允许 |
| 通过助手改写员工业务 | 不允许 | 不允许；只能提出本人事项 |

- 登录会话和数据库决定真实身份、角色、公司与账号状态。用户文本、模型参数、前端传入的角色／公司 ID 不授予权限；员工即使提出团队问题、猜测记录 ID 或直接调用团队接口，也无法取得团队内容。
- 工具按当前角色提供，工具执行仍独立校验；页面接口、来源访问、待确认建议与业务写入复用相同规则。读取权限不授予修改权限，获取一个来源 ID 不授予它相邻资料的访问权。
- 数据在检索与送入模型前完成授权和字段筛选。材料内“忽略权限／读取其他员工”等指令不改变工具范围；原始材料与历史助手输出均不能作为授权依据。
- 每次工具执行、模型调用前、任务恢复及结果落库／返回时复核权限和读取范围。账号停用、降权或公司归属变化时，受影响的团队任务停止，不能继续恢复旧 checkpoint。
- 历史团队回答、来源、上下文摘要和缓存带授权范围及来源依赖；读取历史／追问时再次校验。权限失效或来源被删除后的相关派生回答不再返回正文，也不再送入模型；普通更新可保留标明版本与时间的旧回答，追问使用最新资料。已经交付给用户或服务商的数据不能被描述为可远程收回。
- 被保留的管理员工作内容与其失效来源分开处理；权限撤销后隐藏其中团队派生信息，不将历史关联作为重新读取员工资料的凭据。

### R5 — 页面与交互

- 沿用工作助手的同一输入入口，不新增独立聊天产品或权限配置面板。管理员入口可提供少量可编辑的问题示例，员工不显示团队示例。
- 来源及督办建议使用现有主题与卡片，正文、来源和操作区层级清楚，长名称换行或可展开；来源跳转保留团队与会话返回上下文，直接打开仍检查权限。
- 查询失败、权限不足、资料已变化分别给出具体反馈，保留用户问题；重试遵循现有费用提示，不静默重复付费调用。手机和电脑均能访问来源、编辑与确认建议，不增加常驻开发提示。

## 非目标与技术约束

不做 Electron 同步、公司级 RAG／向量库、员工画像或评分、组织层级／自定义角色、跨公司问答、派单／通知／日历提醒、Agent 自主改写员工记录、云资源开通和生产部署。督办日期可在现有下一步文本中表达，本轮不新增自动提醒或逾期状态。

沿用 React、FastAPI、PostgreSQL 和当前 harness；不替换 runtime、不增加任意 SQL／HTTP／文件系统工具、不扩大调用预算、不新增重型 CI。无破坏性地扩展已有工作、消息和来源数据，保留旧 ID、会话、资料及员工原流程；具体迁移与恢复见 Plan。

## 验收标准

- [x] 管理员能按员工、时间、状态查询与追问，回答范围／时间正确，关键结论可追溯；重复姓名、空结果和预算不足不假报完整。
- [x] 员工、跨公司、其他管理员私人数据、未提交草稿、未发送文件、伪造身份／引用／游标及模型误调用都被服务端拒绝；禁止内容不进入模型输入。
- [x] 停用／降权／权限变化后，在途任务、历史问答、来源、建议、缓存和 checkpoint 不绕过当前权限；删除来源不被晚到结果恢复。
- [x] 本人督办建议支持编辑／确认／忽略、关联源查看和版本冲突处理；重复确认不重复创建，不改动员工记录、不自动发通知。
- [x] 新旧来源引用、旧会话／工作／报告及迁移兼容；来源失效不递归删除已确认工作，也不暴露失效内容。
- [x] 工作助手、来源导航及我的工作在电脑／窄屏可操作，页面风格与现有 Web／Electron 设计原则一致。
- [x] 相关权限、查询、harness、确认／删除与 Web 定向检查完成；少量真实模型联调和独立验收分别记录，不将固定模型响应或未执行项目称作真实通过。

各项实际覆盖、恢复过程与已知边界见验收报告，不将固定输入、真实 API 与界面验证混为同一证据。

## 待确认问题

无。用户在草案建议后要求开始实施，本轮据此采用较窄的已确认业务范围；未把未关联消息视为新增授权。
