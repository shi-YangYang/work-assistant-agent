## 修改顺序

1. 限定验证 sounddevice / PortAudio 在 Python 3.12 和目标平台的安装方式、默认输入参数及 macOS 录音授权归属。只验证本次需要的录音边界，不比较大量无关框架。选定稳定版本后锁定 Python 依赖，避免将开发分支文档版本直接当作已发布版本。
2. 建立应用用户数据根目录、SQLite 初始 schema 与会议状态恢复；测试使用独立临时根目录。当前没有旧业务 schema 迁移，保留已存在文件，不通过删除数据库解决初始化错误。
3. 实现音频输入适配、有界缓冲、流式写入与确定性的结束顺序；先使用测试输入验证状态和故障，再验证真实设备。
4. 扩展带参数且有界的 stdio 命令与主进程 API。健康请求保持兼容，会议查询读取真实仓库，不能保留“仅接受空列表”的骨架校验。
5. 实现权限检查、单实例、录音时退出确认与收尾，避免沿用 Spec 001 直接 kill 核心的退出 / 重连行为。
6. 实现历史列表、录音状态、详情和受限播放资源。生产 CSP 只增加必要的本地音频来源，不能全面放开 file、网络或 renderer 权限。
7. 更新实际依赖安装说明、能力状态及文档，执行与改动相称的检查，写实施报告。
8. 新的独立工程验收 Agent 检查交付与已有验证证据；只有具体遗漏、变更或不明确结果才补做定向检查。验收通过后同步状态。

## 数据流

```text
用户开始 / 结束 → renderer → preload → Electron 主进程 → Python 控制命令
                                                   ↓
麦克风 → RawInputStream → 有界音频块缓冲 → 写入线程 → 临时 WAV / 最终 WAV
                                                   ↓
                                              SQLite 元信息

状态查询 ← 采样进度 / 输入音量 / 当前会话状态
历史查询 ← SQLite
音频播放 ← 主进程核验会议 ID 后提供的本地媒体资源
```

采集回调只复制必要数据并尝试入队，不能做 SQLite、阻塞磁盘写入、长时间锁等待或推理。输入音量在处理路径计算后降频展示。队列满和设备 overflow 必须通知控制状态并收尾，不能静默忽略。

## 录音与存储方案

- 使用系统默认输入设备，启动前校验单声道、PCM16 与该设备可用的采样率；保留实际采样率，不为未接入的 ASR 强制使用 16 kHz。
- Python 标准库 wave 流式写临时 WAV，定期更新可恢复的进度，内存上限与录音时长无关。停止后关闭文件并在同一文件系统内完成命名，再提交最终状态。
- 数据根目录由 Electron 的应用用户数据位置决定，可信主进程通过独立参数传给 Python。数据库保存相对音频路径；不接受 renderer 提供任意文件路径。
- 文件写入与 SQLite 无法整体原子提交：先持久化 starting / recording 状态，再写文件，结束时最终确认。重启按状态与文件实际情况恢复，不能仅凭文件存在就判 completed。
- 恢复以已落盘完整帧为限；可修复临时 WAV 时保留原始文件至恢复成功，失败时显示不可播放原因。不能承诺内存数据或断电未刷盘数据恢复。
- 对 SQLite 初始化和后续 schema 演进记录版本；意外已有不兼容数据时明确报错，不自动清库。
- 不限制用户把项目放在不同目录，也不要求通过启动命令的工作目录找到历史数据。

## 接口变化

计划沿用 JSON Lines 成功 result / error 响应，扩展以下有限方法；具体 TypeScript / Python 字段集中定义，避免散布魔法字符串：

| 方法 | 输入 / 输出 |
| --- | --- |
| health | 保留核心信息，新增真实录音功能就绪情况 |
| recording.start | 幂等操作标识；返回会议 ID 与实际状态，内部选择默认设备 |
| recording.status | 返回唯一活动会话、采样时长、输入音量、设备及错误 |
| recording.stop | 指定会议 ID；返回 stopping 或最终状态，重复停止保持一致 |
| recording.interrupt | 主进程用于系统休眠的中断收尾，不直接向 renderer 公开 |
| meetings.list | 返回真实会议摘要，包含状态、时长和播放可用性 |
| meetings.get | 合法会议 ID；返回详情，可信主进程可取得内部音频描述 |
| shutdown | 只在已完成收尾后正常退出；不由 renderer 直接调用 |

UI 使用有限频率的状态查询，同一轮询最多一个在途请求，卸载后停止轮询。开始 / 结束超时先查询核心状态，幂等标识与唯一活动会话共同防止重复执行。结束命令尽快返回 stopping，由状态查询等待写入完成，不无限拉长所有协议请求的超时。

播放采用主进程受限本地媒体资源与标准音频控件。URL 只携带会议 ID；主进程限定根目录、验证路径归属和文件类型，处理不存在的资源与媒体范围请求，不通过本地 HTTP 业务服务或任意 file URL 暴露文件系统。

关闭窗口、退出、系统中断和核心重试必须共享会话收尾逻辑。系统强制杀进程可能绕过该逻辑，使用下次启动恢复处理，不能宣称进程退出钩子总能执行。

## 测试计划

规格起草阶段已按 S0 仅检查文档 diff。本次业务实施属于 **S3**：实际涉及麦克风权限、受限文件访问、持久化初始 schema、共享 IPC 及退出生命周期；这些是扩大到相关子系统验证的具体依据。

验证按以下边界组织，不因 S3 标签就无条件追加全仓检查：

- Recorder / Writer：用受控 PCM 输入验证帧顺序、时长、音量、正常结束、重复操作、队列溢出和写入失败；无真实设备的测试不依赖麦克风。
- Repository：在临时目录验证重启读取、状态与文件不一致的恢复、中文路径、不兼容 schema 的保护及用户数据隔离。
- Desktop / IPC：验证参数与来源、非法会议 ID / 路径拒绝、开始结束超时恢复、录音中关闭取消与保存、核心退出后状态同步。
- Electron：只保留与本次用户流程直接相关的 UI 场景；验证生产构建的播放器、范围读取和录音能力标识。使用合成输入时测试环境必须明确隔离，正式运行不能自动回退到假录音。
- 实机：显式开始一段非敏感测试录音，结束、重启并回放，核对实际录下的声音。记录 OS、设备和授权方式；没有设备 / 权限时 AC-02 保持未验证，不用模拟输入填 PASS。

沿用 package.json 已有的 Vitest、Python unittest 和 Playwright 入口，实施后按实际新增文件选择定向命令。跨边界类型变化运行相关 TypeScript 检查；生产媒体协议与 CSP 的改动通过一次相关构建 / Electron 检查验证。无需因文档改动重跑代码检查。

实施报告记录命令、结果与对应代码状态。检查通过后，除相关代码变化、明确失败或不确定结果外不重复；验收阶段优先复用这些证据。任何尚未执行的 Windows 设备验证明确单列。

## 风险

- PortAudio 原生采集权限与 Chromium 权限处理不同；Electron 的授权结果不能替代真实 Python 输入流打开验证。若既定方案在目标平台无法满足用户流程，停止依赖它的实现并更新决策。
- 临时音频、最终音频与数据库的交叉失败需要恢复规则；测试不能靠清空数据让状态一致。
- 默认 3 秒控制请求超时不能被当作录音动作失败的充分依据，需处理已执行但回复丢失。
- 录音中直接沿用核心重连、窗口关闭或单纯 kill 进程会破坏数据；本次必须调整这些已存在路径。
- 原始 PCM WAV 占用随时长增长；缓冲有界、磁盘错误及格式容量限制必须显式处理。
