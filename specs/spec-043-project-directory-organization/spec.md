# 项目代码目录整理

范围包含 Web 前端、公司后端与 Electron 渲染层／本地核心。实施完成，[独立验收通过](acceptance.md)。

## 目标

- 从目录名称即可判断组件所属功能，相关实现与私有样式就近维护。
- 明确组件私有样式、业务共享样式、本端公共样式的归属。
- 后端按能力和业务子域归组，保留既有分层与进程边界。
- 保持现有功能、页面视觉、状态生命周期、请求行为和运行方式。

## 范围与非目标

整理前后端中职责混放的目录。具体迁移清单见 [实施计划](plan.md)。

- Web：公共组件、应用布局、助手、模型服务、工作、报告、认证与设置中需要分组的目录。
- 公司后端：Agent、任务运行，以及会话、报告、业务操作、模型服务内已有明确子域的文件组。
- Electron：renderer 内的会议、设置、导航；Python 本地核心内的录音、转写、说话人、模型与纪要。
- 更新受影响的导入、动态加载、测试 mock／源码引用和当前架构说明。

不调整 `apps/`、`packages/`、`tests/` 等顶层结构。沙盒、桌面 main／preload、后端基础层与已清晰的业务目录保持原位，仅在引用迁移文件时更新导入。不改业务逻辑、不重新拆函数、不改 UI、不更换依赖或测试框架、不新增跨端共享。小而清晰的目录保持原状。

## 目标组织方式

### 按功能分组，组件与样式就近放置

- 公共组件按 `actions`、`forms`、`feedback`、`overlays`、`content` 分组。
- 较大的业务组件目录按具体用途分组，例如助手的 `conversation`、`composer`、`messages`、`attachments`。
- 组件保留明确文件名，如 `MessageComposer.tsx`，私有样式仍为同目录 `MessageComposer.module.css`。不统一改成难以区分的 `index.tsx`。
- 一个主组件和它的专用子组件可以共处一个目录；不要求每个小文件独占文件夹，不创建空的 hooks、utils、types 或 styles 目录。
- 现有 feature 下的 `api/`、`hooks/`、`lib/`、`utils/` 已有明确职责，本次保留。公共层不反向依赖 feature。

### 样式归属清晰

- 只由一个组件或紧密关联组件使用的 Module 随组件迁移。
- 已被多个业务使用的公共样式迁入 `apps/web/src/styles/patterns/`，继续显式导入，不复制到每个组件目录。
- 业务内共享样式保留在该 feature 的 `styles/`，或明确归属的组件组内；不得跨业务引用私有 CSS。
- Electron 保留现有本端样式入口和加载顺序，不在目录整理中附带做 CSS Modules 改造。

### 后端按职责归组

- 保留 `app`、`paa_core` 包名与现有运行入口。公司后端继续分为 HTTP、业务模块、任务、Agent、基础设施，不合并进 Web 前端目录。
- Agent 归组上下文、模型运行、提示词、授权动作、结果交付；任务归组调度运行、处理器、反馈、节点执行和维护。已有 `tools/` 与可复用 `retry/` 保持边界。
- 业务模块仅提取清晰子域，例如会话上下文、汇报安排、模型用量。`router.py`、`models.py`、`schemas.py` 等已清晰的入口文件不为目录对称而再包一层。
- 桌面本地核心按录音、转写、说话人、模型和纪要归组；公共仓储与协议入口保留。
- Python 新子包使用精简的 `__init__.py`，不批量导出整个业务域，不增加旧路径转发壳。

## 功能需求

1. 按实施计划建立有实际职责的子目录，一次迁移同时修正全部引用。
2. 公开组件名、props、Hook 签名、路由、请求参数、事件和存储键不变。
3. Web 继续使用 `@web/` 与具体文件导入；移动后就近引用私有 CSS，跨层路径按现有别名规则处理。Electron 保留现有导入机制，不为移动文件新增别名配置。
4. 不在旧路径留下转发文件，不建立统一导出整个组件库／feature 的 barrel。
5. 测试位置不变，只调整被迁移模块的引用；保留原断言与覆盖范围。
6. 当前架构文档同步新目录和阅读路径；历史 Spec 不批量改写。
7. 后端同步普通／延迟导入、字符串模块路径、monkeypatch、进程启动、资源定位和构建脚本中的引用，保持原有懒加载时机。
8. 数据库表、字段、迁移链、API／SSE／IPC 协议、工具名称、提示词、权限、重试与幂等语义不变，不生成数据库迁移。

## 边界条件与技术约束

- CSS 声明、类名、导入先后次序、全局基础样式和公共样式接口保持；只更新必要的相对资源路径。
- 深层移动不得破坏 `url(...)`、动态 import、测试 mock、源码扫描和打包资源定位。
- 不改变 React key、组件组合、Provider 层级、懒加载边界、订阅和清理顺序。
- 不用新增兼容壳、空目录或重复代码掩盖未完成的迁移。
- Linux／Windows 大小写敏感问题需要纳入路径检查；无对应平台实测时如实说明。
- 不删除业务代码、用户数据、缓存、模型或环境配置；删除仅限移动完成后的旧文件路径与失效目录。
- ORM 模型定义、迁移文件、包内资源与应用启动入口保持原位。移动不能导致重复注册、重建数据库或重置会话与任务。
- 保持 checkpoint、会话 JSONB、任务回执及本地 SQLite 兼容。若持久数据记录了自定义类型的模块路径，保持该类型定义原位并修订迁移清单，不能通过清空旧数据解决。
- 桌面核心的源码／冻结模式资源定位与子进程导入均须检查；例如说话人模型路径不能继续使用移动前的 `__file__.parents` 层数。

## 兼容性要求

用户看到的布局、交互与业务结果保持一致。Web 与 Electron 继续各自构建、运行和维护 CSS；现有登录、聊天草稿、错误提示、会议数据、模型配置和 IPC 契约不受影响。`npm run dev:web`、`npm run dev:electron`、API／worker／CLI 与 `python -m paa_core` 入口保持不变，环境文件位置与部署数据卷不变。
