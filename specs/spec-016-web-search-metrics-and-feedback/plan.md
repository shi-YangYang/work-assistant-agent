# Plan — Web 工作检索、看板统计与模型反馈

## 对应 Spec 与实施前提

[Spec 016](spec.md) 已按本计划实施并通过新的独立验收；实际结果与定向返工见[验收报告](acceptance.md)。

## 涉及模块与顺序

1. 公司查询与共享契约：统一可访问工作查询、分页条件和看板指标／明细口径。
2. API 与 Web：接入服务端筛选分页，替换团队看板前端累加，保留路由返回上下文。
3. 模型调用记录：以同一次实际请求为单位保存状态、身份快照、耗时与真实用量，接入管理员统计页。
4. Provider／harness／worker 与聊天：在现有完整响应校验之外增加受控阶段与正文反馈，再接入前端恢复与滚动行为。
5. 对应模块检查和真实页面查看；实施结束后新的独立验收 Agent 按 Spec 验收，避免重复已通过的相同检查。

## 数据流与接口变化

### 工作与团队查询

- 扩展 `GET /work-items`、`GET /team/members/{id}/work`：`q`、`status`、`limit`、`cursor`，返回 `items`、`nextCursor`；保留员工详情的 `member` 字段。默认每页 20，限制单次大小，使用 `(updated_at, id)` 游标，浏览器保存上一页边界。
- 查询复用 `business_access`，不能在取得一页未授权数据后直接过滤而错误宣告到末页；游标不依赖边界记录仍然存在。参数化查询并转义普通关键词，不引入全文检索服务。
- 更新 `GET /team` 的时间、人员与状态参数，返回独立 `metrics`、实际范围和员工摘要。用量与看板的时间解释分别共用公司时区转换，不自行读取浏览器时区替代。
- 聚合和明细复用同一过滤构造器。工作历史使用 `WorkRevision`，先按截止时间确定可访问修订，再计算期间活动；已提交报告使用 `ReportRevision.created_at` 和去重报告 ID。删除与当前授权仍即时生效，不恢复已无权查看的历史材料。
- “已上报／阻碍／已提交报告”的明细沿用团队员工页面，必要时增加带同一筛选参数的轻量明细视图／接口；不复用截断的工作列表计算总量。

### 调用记录与用量

- 在现有 `ModelUsage` 基础上非破坏性扩展：调用标识、关联任务尝试、服务／模型／用途快照、请求生命周期时间、完成状态、错误分类，以及可空的服务商实际输入／输出 Token；原估算和额度预留字段保留独立职责。
- 统一聊天、上下文整理、语音与管理员配置测试的记录入口。预留额度、真正发出请求、收到响应、失败各有状态；一个请求只记一次，事件重放和页面刷新不新增记录。收到有效 usage 后即保留，即使后续业务校验失败也不能丢失已知用量。
- 区分未发出、已发出未完成、明确失败和中断后结果未知；worker 恢复不能把旧请求强行标成功或重复计数。成功率分母仅为已得到明确请求结果的尝试，同时显示未知／进行中数量。
- 新增管理员只读 `/settings/model-usage` 汇总／分页明细 API 与 Web 页面；查询强制公司作用域、日期和分页上限，不返回正文／凭证，不自动扩大每日额度。
- 历史缺项为 `null`／legacy；不得由当前 `ModelService` 反向填充不可靠历史。Token 汇总分别保留已知条数，避免混合“一个字段已知、另一个未知”的情况。迁移不删除既有记录。

### 实时聊天反馈

- Provider 对现有一次请求提供正文增量、完成和用量回调；完整 JSON／工具参数仍经现有校验后才交给 harness 执行。配置为非流式时沿用完整响应，不探测或追加请求。
- harness 仅发布白名单业务阶段和允许显示的正文，不使用原始框架事件作为 Web API。摘要模型、工具参数、系统提示、推理字段和未校验来源不直接显示；团队正文按当前来源授权复核后发布，安全性优先于首字延迟。
- API 与 worker 是不同进程，不能只用进程内队列。使用 PostgreSQL 中有界的任务反馈快照／事件，按任务、attempt、fence 和递增序号区分；正文合并节流，避免每个 Token 写一次库。反馈属于可过期的派生数据，终态历史仍以正式消息为准。
- 增加本人任务的同源 SSE 订阅，Cookie 会话认证，禁止令牌放查询字符串；校验任务所属公司、本人、会话和团队来源依赖。续传／快照恢复、心跳和终态有显式协议，限长与限频；不能靠关闭连接承诺撤回已经展示的信息。
- 浏览器切换会话关闭旧订阅；恢复只读现有任务，按序号去重，用正式结果替换临时结果。保留现有消息分页作历史读取；实时连接失败可退回较低频状态读取，不重新执行模型。
- 生产 Caddy 路径也需支持逐步交付，验证代理缓存／超时不会把结果重新聚合；不因此调整其他发布流程。

## 验证计划

文档阶段 S0，仅检查 diff、需求与链接。实施涉及查询、共享契约、持久化和授权，按 S3 风险选择公司子系统定向检查，不扩展为桌面打包、录音或全项目端到端测试。

- 服务器固定数据：超过 100 条的跨页搜索、同更新时间、游标记录删除、权限过滤；看板时区边界、期间之后的修订、报告多次提交、停用员工及大数据量下统计／明细一致。
- 服务器固定模型响应：真实分块交付时间、混合工具片段、缺失终止、非法内容、取消订阅、恢复／迟到事件和动态撤权；调用记录的已知／未知 Token、失败及超时、管理员测试、历史模型变更和迁移。
- 前端定向测试：页码／筛选／返回状态，旧查询响应丢弃，事件去重与正式结果替换；电脑及手机视口查看输入、历史阅读、筛选和用量布局。
- 实施时使用 `npm run test:web -- <相关文件>`、`npm run typecheck:web`；服务器通过 `.venv-server` 对相关 `tests/server` 文件执行 pytest。新增迁移需在测试库验证升级；格式化仅本轮改动文件。普通 Web 构建用于确认新路由／事件模块集成，不重跑桌面。
- 真实模型调用只使用用户已授权配置和明确测试材料，不向日常会话灌入测试消息、不将真实调用设为 CI 前置条件。若未进行真实服务复测，交付区分固定响应验证与真实接口验证。

## 风险与迁移

- 实时正文可能先于完整响应校验，必须限定可展示事件并保留失败／撤权处理；不能放松 Spec 014 或让局部工具片段落业务库。
- 原调用表混有估算和不完整记录，新增字段与旧字段不能共用一个“实际 Token”含义；历史未知是正确结果。
- 聚合不再取前 100 条，需要针对查询与索引检查，避免转为浏览器一次加载全部原件；不为几十人试用引入 Redis、消息总线或新的搜索服务。
- 数据库只做增量迁移。API 与 Web 同批发布，旧消息／历史记录可读取；回滚前端／API 时保留新增表字段，避免为回退删除数据。具体 migration 与接口契约在实施中完善，遵循已确认的产品行为。
