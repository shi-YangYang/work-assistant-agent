# Spec 016 — Web 工作检索、看板统计与模型反馈

## 状态

DONE · 2026-09-15。已实施并通过独立验收；方案见 [Plan](plan.md)，实现及验证范围见 [实施报告](implementation.md)和[验收报告](acceptance.md)。

## 背景与当前行为

- 我的工作、团队员工工作接口只取最近 100 条；我的工作在浏览器内筛选已返回的数据，无法检索更早的记录。
- 团队看板日期仅筛选工作更新时间；上报人数与报告数量使用历史累计，各指标范围不一致，工作统计还受 100 条限制影响。
- 模型适配层能够读取流式接口，但会聚合完整结果再交给 harness；浏览器轮询消息，主要展示“等待整理／正在整理”。
- 后台已有调用预留、额度限制与用量记录；部分 Token 是预算估算，缺少完整的请求状态、耗时和历史模型标识，不能直接作为真实用量报表。

## 目标

完整查找有权限的工作，明确看板各指标的时间及人员范围，让用户了解聊天处理进度，并让管理员查看可解释的模型调用情况。

## 功能需求与目标行为

### R1 — 工作列表分页与完整搜索

- 覆盖管理员／用户的“我的工作”和管理员的员工详情工作列表；保留现有查看、编辑、删除与来源权限。
- 服务端在全部可访问且未删除的工作中，按标题、摘要、阻碍、下一步进行关键词搜索，并与工作状态组合筛选。关键词按普通文本处理，忽略首尾空白和英文字母大小写，不让 `%`、`_` 成为隐式通配符。
- 每页 20 条，提供上一页／下一页与当前页标识；按更新时间、ID 倒序稳定排列，筛选进入 URL，改变筛选回到第一页。从详情返回保留筛选和翻页上下文。
- 权限过滤先于可见分页结果和统计，不以“先取 100 条再过滤”代替完整查询；没有权限的记录不泄露标题、数量或存在性。
- 空数据、无匹配、加载失败分别显示；删除当前页最后一条时回到可用页。数据未变化时连续翻页不重不漏；数据更新后允许重新加载，不宣称分页期间为冻结快照。

### R2 — 团队看板统计口径

- 默认本周，提供今天、本周、本月、自定义；周一为一周开始，按公司时区解释日期，结束日包含全天。展示实际日期范围，前后端共用同一组筛选参数。
- 人员范围只含本公司员工，默认在职员工；保留查看停用员工的入口，显式选择后列表和指标均使用同一人员集合。管理员不计入员工人数。
- 搜索员工缩小整张看板的人员集合；工作状态只筛选工作及对应明细，不悄悄改变上报人数和报告数的人员分母。各指标可进入同口径明细，不能让卡片与明细各取不同范围。

| 指标 | 统计口径 |
| --- | --- |
| 已上报员工 | 范围内至少发送一条未删除工作消息的员工人数／当前筛选员工人数，按消息发送时间，不把未上报解释为未工作 |
| 有阻碍的工作 | 范围内有已确认更新的工作，取范围结束时最新的可访问修订；未完成且状态为有阻碍或存在非空阻碍描述，按工作 ID 去重 |
| 已提交报告 | 范围内实际提交过的未删除日报／周报，按提交时间、报告 ID 去重；多次提交同一报告不重复计数，未提交草稿不计入 |

- 无符合状态的工作时，对应工作列表为空，员工仍可有上报／报告记录；历史日期内的工作状态不能被日期范围结束后的更新改写。日期与人员筛选对空值、跨月／跨年、夏令时均有明确结果。
- 指标由服务端基于完整可访问数据计算，不通过前端当前页或每人前 100 条累加。卡片文案／简短说明交代口径，不增加常驻长篇开发提示。

### R3 — 聊天反馈

- 工作助手在同一消息位置展示真实阶段：排队、解析文件、识别语音、查询资料、生成回复；仅展示实际发生的阶段，不虚构百分比、排队名次或剩余时间。
- 已启用流式且服务支持时，逐步显示可供用户阅读的回复；未启用或不支持时展示阶段，完成后显示正文。不用收到全文后的打字动画冒充流式，不为获取实时效果额外调用模型。
- 临时正文与正式结果区分。工具参数、思考链、系统提示、原始内部事件不返回浏览器；工具执行仍等待完整响应校验。来源和进展确认卡片在校验及保存成功后显示，临时文字不能代替已保存的业务结果。
- 团队资料及其派生正文沿用 [Spec 014](../spec-014-admin-business-assistant/spec.md) 的授权和来源规则；推送前复核权限，不能直接透传模型原始流。必须完整检查后才能安全展示的内容先显示处理阶段，再交付校验后的结果。
- 临时回复中断时明确未完成，不覆盖正式历史、不启用无效确认操作。刷新或网络重连恢复同一任务的可见状态，不能重新发送消息、重复拼接正文或再次调用模型；旧尝试的迟到事件不得覆盖新尝试。
- 用户向上阅读历史时不强制滚到底部；提供新回复提示。手机与电脑均保持输入区可用。断网、会话过期、任务失败有具体反馈，沿用已有显式重试规则。

### R4 — 模型用量

- 管理员在设置中进入独立“模型用量”页，可按日期、服务、模型及用途查看；用户不显示入口，直接调用接口也不得获取公司用量。不增加员工用量排名。
- 默认查看本周，按公司时区展示调用次数、请求成功率、耗时、输入／输出 Token，并提供分页调用明细。用途区分工作助手、报告生成、语音转写和配置测试；一次任务多次模型调用逐次记录，不能把任务数当请求数。
- 调用记录保存当时的服务／模型／用途，配置改名、撤销或切换不能把历史归到新模型；未保存服务的测试标记为配置测试。明细不包含密钥、请求正文、员工文件或模型思考内容。
- 请求成功率表示模型请求完成情况，不等同于工作建议／报告保存成功率；失败和结果未知分别显示，进行中的调用不作为已完成失败。提供失败分类及可展示的原因。
- Token 只汇总服务商实际返回的值；缺失显示未知，并标注统计覆盖情况。预算估算独立保存、不能混入实际总量；已返回的 0 与未返回区分。语音接口没有 Token 时不伪造数据。
- 旧记录缺少可靠字段时标记历史未知，不猜测模型、成功状态、耗时或实际 Token。
- 保留现有额度限制及重置规则，若显示额度需注明实际重置时间，不能与按公司时区的统计范围混淆。

## 非目标

不包含提醒／通知、多人 worker 调度、报告工具调用可靠性专项、任务取消、员工画像、Electron 修改或同步、云资源开通及生产部署。不升级框架或新增重型 CI。

## 边界、技术与兼容性

继续使用现有 React／FastAPI／PostgreSQL 和 harness、共享主题及响应式组件。身份、公司、来源权限在服务端执行；不得因分页、流式或聚合接口降低已有授权。旧会话、业务记录、模型配置和额度行为保留；必要 schema 变更采用非破坏性迁移。浏览器断开只断开订阅，不隐式取消后台任务。

## 验收标准

- [x] 超过 100 条的工作可完整翻页，旧记录可被关键词及组合状态检索；本人和员工详情一致，权限、删除、返回及空页处理正确。
- [x] 看板全部指标与明细在相同人员、时间口径下可核对，覆盖历史状态、重复报告提交、停用成员和超过 100 条的情况。
- [x] 固定流式响应在结束前可显示允许的正文；非流式、工具混合、断流、刷新、迟到事件和权限失效不会产生伪成功、越权或重复调用。
- [x] 用量正确区分请求与任务、实际与未知、失败与未完成；配置变更不改变历史归属，用户与跨公司请求被拒绝。
- [x] 桌面／手机宽度下分页、筛选、聊天滚动及用量明细可用，沿用当前设计；测试规模与改动范围相称。
