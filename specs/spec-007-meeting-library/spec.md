# Spec 007 — 会议记录管理与检索

## 状态

ACCEPTANCE · 2026-09-12。功能及定向返工已完成，独立工程复验 PASS；日期半输入清除的界面复验因 macOS 锁屏尚未完成，详见 [验收报告](acceptance.md)。技术取舍见 [决策 0010](../../.ai/decisions/0010-meeting-library.md)，模块方案见 [Plan](plan.md)。

## 背景与当前行为

已有会议列表、麦克风录音、本地转写、结构化纪要及引用回放。会议默认按时间命名，列表和转写每页最多 50 条；命令面板仅查找页面与操作。当前没有会议内容搜索、重命名、文本复制导出或会议删除接口。

## 目标与非目标

让用户能从历史会议中找到讨论、调整名称、带走文字资料并清理不需要的会议。核心场景：搜索“项目延期” → 查看命中原文 → 回听确认 → 导出纪要。

首版不包含语义问答、向量数据库、标签／项目体系、纪要或转写正文编辑、批量操作、音频导出、Word／PDF、云同步、回收站或外部任务系统。

## 目标行为与功能需求

### R1 — 搜索与日期筛选

- 在现有会议列表顶部增加搜索框和起止日期，不新增独立搜索导航；支持仅搜索、仅筛日期及两者组合，一键清除恢复普通列表。
- 搜索会议名称、已保存的转写片段以及最近一次成功纪要中的用户可见文字，包括纪要标题、摘要、讨论要点、决策、行动项、风险和待确认问题。失败重试期间仍搜索上次成功内容，不搜索密钥、参数、内部 ID 或错误日志。
- 首版将去除首尾空白后的输入作为连续文本匹配，支持一两个汉字和中英混合，英文字母不区分大小写；`%`、`_` 等按字面匹配。最多输入 200 个字符，不解释为正则或高级查询语法；不要求跨转写片段拼接匹配。
- 日期按用户当前本地时区的自然日解释，使用会议开始时间，缺失时使用创建时间；包含起止两天，允许只填一端，拒绝反向区间。
- 查询覆盖数据库中的全部会议和片段，不只过滤当前加载的 50 条。每场会议只出现一次，按会议时间倒序并用 ID 稳定排序，分页加载；每条结果显示命中来源与有限长度的高亮摘要。
- 点击文字命中进入对应片段，显示时间并允许手动定位播放；点击纪要命中进入对应纪要位置，点击会议标题仍使用现有详情默认页签。打开结果不自动播放。返回列表保留关键词、日期、已加载结果和滚动位置。
- 快速修改查询时旧响应不覆盖新结果；中文输入法组词时不频繁提交查询。显示加载、无结果和重试状态；清除、重命名、删除及明确刷新后重新计算结果。录音／生成过程只检索已持久化内容，不自动启动新任务。

### R2 — 会议重命名

- 在已结束会议的列表操作菜单和详情操作区提供“重命名”；编辑预填当前名称，保存或取消，Enter 保存、Esc 取消。
- 名称去除首尾空白后为 1～100 个字符，拒绝换行和控制字符，允许不同会议同名。保存失败保留输入并提供错误提示。
- 会议列表、详情主标题、搜索结果和导出标题使用保存后的名称，重启仍保留；改名不移动音频文件、不改变会议 ID、转写或引用。
- AI 生成的纪要标题仍作为纪要正文内容保存，重新生成纪要不会覆盖用户设置的会议名称。

### R3 — 复制与导出

- 已结束会议的详情提供“一键复制纪要”和“导出”。复制输出可读纯文本；只有已有成功纪要时可用，不发起模型请求。
- 导出支持 UTF-8 Markdown 和 TXT，默认选择纪要；可选择仅文字记录或纪要加文字记录。选择文字记录时可勾选时间戳，默认开启。
- 内容包含会议名称、日期、时长和所选正文。纪要包含已有结构化章节，未明确的负责人／截止时间保持“待确认”，不补造内容；纯文本中不保留无法在文件外使用的应用内部链接。
- 完整转写按顺序导出所有已保存片段，不能只导出当前页、当前滚动区域或当前展开内容。录音中断、转写未完成时，在导出选择和文件内容中明确说明资料不完整；尚无所选内容时禁止该选项。正在重新生成纪要时可导出上次成功版本，保留其生成时间。
- 每次操作使用一致的数据快照，避免导出中途混入新一轮纪要或部分新增转写。大文本分块处理，不能超出既有通信限制、冻结界面或静默截断。
- 使用系统保存对话框，默认文件名由安全化后的会议名称和日期组成；用户选择位置。取消不写文件，覆盖须经对话框确认，失败不破坏原有目标文件，并显示可操作的错误。剪贴板失败不显示复制成功。
- 导出不包含音频、API 配置、密钥、内部文件路径或调试信息，也不把内容发送到外部服务。

### R4 — 删除会议

- 列表与详情的操作菜单提供单场删除；确认框明确会议名称以及音频、转写、纪要均在处理范围内，取消不会修改数据。
- **二次确认后永久删除，首版不设回收站。** 这里指应用内不可恢复，不承诺安全擦除磁盘、删除系统备份或撤回用户已导出的文件。
- 录音及暂停中的会议不可删除；该会议仍在保存、转写排队／执行或纪要排队／生成时也不可删除，明确说明原因。后端执行时重新核对状态，不能仅依靠按钮禁用。
- 删除前停止该会议的回放并释放文件占用；操作期间阻止新任务和晚到回调重新生成其资料。取消或失败不显示成功，失败保留可恢复状态或明确的重试入口。
- 删除成功后清理会议关联的数据和音频，列表、搜索及详情同步更新；在详情中删除则返回原列表条件下的结果。重启后不重新出现，不影响其他会议、默认模型或服务设置。

## 边界条件、技术与兼容性

- 沿用 Electron / React / Python / SQLite 和现有 IPC 信任边界，方案见决策 0010；不因本 Spec 调整 CI 触发策略或引入额外服务。
- 支持 macOS / Windows、浅深主题、键盘操作及 900 × 640 最小窗口；菜单依附触发器，不遮挡操作，关闭和切页后无残留浮层。
- 搜索高亮、名称和导出均按不可信文本处理；限制请求尺寸，校验字段和 ID，不允许 renderer 指定任意内部删除路径。
- 删除涉及文件与数据库，两者不能假定原子提交。断电、重启、文件占用和权限错误必须有一致的恢复／重试语义，方案在实施前细化到 Plan。
- 长会议查询或导出不能长期占用录音控制通道与写锁。功能测试不读取或输出用户密钥，破坏性场景只使用受控测试数据。

## 验收标准

- [x] 中文短词、英文大小写、特殊字符和日期边界查询正确，能找到第 51 场会议及第 51 个转写片段之后的内容，无重复会议；快速切换查询无旧结果覆盖。
- [x] 搜索结果可到达实际命中内容，原文可手动定位音频；返回保留筛选和阅读上下文。
- [x] 改名在相关界面及重启后保持一致，不改变音频／引用，重新生成纪要不会覆盖手动名称。
- [x] 复制纪要、Markdown／TXT 的内容与所选快照一致，全文导出无分页截断，不完整内容有明确标记，取消／覆盖／失败行为正确。
- [x] 根据用户确认的删除策略，忙碌会议受保护；相关资料处理完整，文件占用和中途失败通过受控故障测试验证，其他会议与配置不受影响；Windows 实机未执行。
- [ ] 最小窗口、菜单、键盘与两种主题下相关操作已检查，定向测试及独立工程复验通过；日期半输入清除修复后的 GUI 复验待解锁补齐。
