## 涉及模块与实施顺序

1. **存储与查询**：Repository 增加筛选查询和专用重命名操作，复用转写与纪要存储。先确认可见文字的匹配、去重、时间比较及分页，再接界面，避免从 renderer 全量拉取历史数据。
2. **通信与权限**：在共享契约、preload、CoreManager、主进程及 CoreService 中补齐对应方法。沿用可信页面及参数验证，保留旧列表调用的默认行为；搜索摘要只返回有限文字及可校验的定位信息。
3. **列表与详情**：接入查询状态、日期、分页和单场菜单；复用 MeetingWorkspace 与 Transcript 的定位能力，纪要命中增加稳定定位。筛选、选中会议、晚到响应及现有可见行轮询共用明确的失效规则。
4. **复制与导出**：在桌面层组织导出和系统保存／剪贴板，核心提供受控的一致快照；将纯文本与 Markdown 格式生成集中在一个模块，两种入口复用。长文本采用有界分块及取消／失败清理，不扩大 JSON Lines 消息上限来传输整个会议。
5. **删除**：完成下述永久删除及中途失败恢复方案，再接确认框及列表更新。删除的请求、任务启动、导出读取和晚到写入共享可验证的会话状态保护。
6. **交付**：更新相关操作说明，由独立验收 Agent 按 Spec 检查实际行为及证据；实施者不能自行宣布独立验收通过。

建议同一个实施 Agent 串行处理相互关联的模块，协调 Agent 维护范围，避免多个实施者同时调整 App、共享协议和 Repository。

## 数据流与接口草案

| 操作 | 输入与输出 | 边界 |
| --- | --- | --- |
| 查询会议 | 关键词、起止时间、分页 → 会议摘要、有限命中预览、定位信息及下一页状态 | 查询所有存量数据；时间转换、请求大小和旧响应失效统一处理 |
| 重命名 | 会议 ID、新名称 → 更新后的会议 | 不接受通用任意字段更新，不按名称移动文件 |
| 导出／复制 | 会议 ID、格式、正文范围、时间戳开关 → 完成／取消／失败 | 用户选择外部目标；内部快照资源由核心管理，不向 renderer 暴露任意路径能力 |
| 删除 | 会议 ID、用户确认 → 完成／忙碌／失败 | 主进程释放媒体资源，核心重新检查任务状态并完成关联资料处理 |

搜索、导出准备及删除使用一个有界后台资料任务队列，stdio 只启动任务或读取状态，保持现有短请求超时和消息限制。搜索在独立只读事务中运行，设置查询执行预算，不持有 Repository 写锁。具体类型随实现写入共享契约，不另建本地 HTTP 服务。

导出先用增量 SQLite backup 建立内部临时数据库快照，再从这份一致快照生成有序正文，避免格式生成期间长时间持有业务数据库读锁。通过受控 token 逐块读取导出文件（每块 16 KiB），桌面层写入用户选定目标旁的临时文件后原子替换。成功、取消、失败、断连和到期释放内部副本及导出快照；renderer 不接触内部路径。复制同样读取完整快照，超出可支持容量时明确失败，不能截断后报成功。

## 迁移与删除一致性

- 当前 schema 为 4，名称字段已存在；直接查询和重命名不要求新增全文索引或迁移。纪要可见字段从结构化内容中提取，避免匹配内部 JSON 字段名与引用 ID。
- schema 5 新增 `meeting_deletions`，记录删除意图和失败信息。持 Repository RLock 复核录音、转写及纪要的活动状态并登记意图；释放锁后在资料 worker 中清理受控音频文件，最后以短事务按依赖顺序删除关联行及会议，再清除意图。
- 失败保留意图和错误，会议列表必须显示可识别的未完成状态及重试入口，普通读取和新任务不能绕过标记。启动时先恢复删除，再执行录音／转写／纪要恢复，避免后台任务重新写入已删除资料；不得把失败的清理当成成功。
- 标记登记、任务启动与晚到写入之间的互斥必须覆盖整个生命周期，不能采用“查一次状态再无保护删除”。按外键依赖处理纪要、任务、片段和分块，不关闭外键检查，不只删除 meetings 行。
- 文件操作仅作用于校验过的会议 ID 对应目录，拒绝越界、符号链接及任意调用方路径；区分原本缺失与访问失败。主进程跟踪媒体请求及流，在删除期间阻止该会议的新请求，并等待既有流的真实句柄关闭；不以播放器 pause 代替 Windows 文件释放，不依靠无限重试。
- 加法迁移沿用迁移前备份及失败回滚，兼容既有 version 1～4 的升级链，迁移本身不修改原始音频。
