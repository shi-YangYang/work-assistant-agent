# 工作助手上下文使用情况与自动压缩

## 状态

已实现，独立验收通过。验证范围和限制见 [验收记录](acceptance.md)。

## 背景与目标

用户需要知道助手当前使用了多少上下文，并在接近上限时自动整理历史，继续当前任务。

## 当前行为

- `harness.py` 在约 12,000 tokens 时执行摘要，通常保留最近 6 条消息；`model.py` 另设 24,000 的单次输入估算限制。
- 现有估算主要计算消息正文，没有完整计入工具定义、工具调用参数等开销。
- 新任务从当前会话筛选历史：最多查询最近 12 条消息，参考材料另有字符预算；checkpoint 按任务隔离。因此上下文不是整个会话历史的累计长度。
- 单任务还存在累计输入 64,000／256,000 的固定限制，会在大窗口模型达到 90% 前提前阻断。
- 前端没有上下文用量或摘要进度入口。

## 范围与非目标

调整 Web 工作助手的模型容量解析、会话上下文存储、自动摘要及交互，移除妨碍真实窗口使用的固定小预算。保留原始消息、附件、工作、报告和成果；不建设跨会话长期记忆，不增加手动压缩按钮、独立设置页面、JSON 文件或 Redis。

## 目标行为与功能需求

### 1. 上下文图标

- 在发送按钮紧邻左侧放置一个环形用量图标，发送按钮位置和输入框尺寸保持稳定。
- 悬浮或键盘聚焦显示简短提示；点击展开详情，手机可直接点按。支持 Escape／点击外部关闭，触摸区域至少 44px。
- 详情显示“上下文使用情况”、估算百分比、已用／可用 tokens、压缩状态。使用既有黑白灰主题、CSS Modules，不增加常驻大面板或浏览器原生提示框。
- 无数据时显示“尚未计算”，加载失败显示“暂不可用”；不能把未知数据显示成 0%。当前用户尚未发送的草稿与未解析附件不计入，详情注明“最近一次助手上下文估算”。

### 2. 模型容量与统一统计口径

- 计算当前任务主助手下一次实际请求将使用的上下文：系统提示、人设、选入的历史／摘要、当前消息、实际注入的材料、工具定义和调用结果。图片采用明确的保守估算，不把 base64 长度当 tokens。
- 分母使用当前服务、模型版本对应的真实上下文窗口。取消统一 24,000 上限，不用旧工程限制冒充模型容量。百炼／Token Plan 的 `deepseek-v4.1-flash` 为 1,000,000；`vanchin/deepseek-v4.1-flash` 为 1,048,576，不能混用。
- 容量来源依次为：管理员明确覆盖、供应商返回且语义已验证的元数据、按服务商和精确模型 ID 维护的官方能力表。记录来源，不能把所有模型统一设为 1M，也不能通过名字包含 DeepSeek 就推断容量。
- 兼容接口的模型列表不保证提供容量。已有模型设置中增加“上下文窗口（tokens）”高级项：已知值自动填充，可手动覆盖；未知时显示“窗口大小未配置”，不编造百分比。旧未知配置仍可正常聊天，但需补齐容量才能保证 90% 自动压缩。
- 明确区分总窗口、服务商最大输入长度和本次输出／推理预留。输入允许量按服务商约束计算；正常在上下文占用达到总窗口 90% 时压缩，若输出预留或单独输入限制要求更早处理，详情明确原因，不能伪报已达 90%。输出预留采用本次请求值，不直接减去模型理论最大输出量。
- 图标、触发阈值和发送前检查共用服务端计量。以未舍入数值判断 `used >= contextWindow × 0.9`；前端百分比不提前显示 90%，超过预算时详情保留实际数值。详情分别显示窗口容量、当前输入估算及必要输出预留。
- 优先从有效会话快照取得历史，再按当前模型容量补入增量；缺失或失效时分页重建，不再无条件只取 12 条或用 12,000 字符截断。超出的较早历史通过摘要衔接，保留明确引用与来源；执行和意图核对读取一致的授权参考，不能主助手看得到而核对器看不到。
- 单任务累计 token 限制与窗口容量分离，按模型输入容量及已有最大调用次数推导执行预算，避免 1M 请求被旧 256,000 累计阈值拒绝。保留调用次数、工具次数、取消、请求大小与资源保护，不借此开放无限任务。
- 每轮主助手调用前、工具结果加入后、压缩完成后更新。摘要、授权核对和答复核对自己的请求不覆盖主助手用量；不能把累计模型用量冒充上下文占用。
- 空闲时展示本会话最近一个有效任务的快照。刷新、重连可恢复；切换会话或账号立即隔离旧值。模型或输入版本变更后重新计算，不沿用旧预算的百分比。

### 3. 达到 90% 自动压缩

- 主助手每次请求前检查，达到当前模型窗口 90% 时先压缩再继续；替换固定 12,000 摘要触发及 24,000 输入判断。编辑草稿、展开图标或刷新页面不触发模型调用。
- 优先压缩较早历史和冗长工具结果，保留当前用户完整要求、近期必要对话、显式引用、未完成步骤、已完成操作回执及来源标识。工具调用与结果必须成对；不机械保留 6 条而导致始终超限。
- 摘要保留目标、约束、用户纠正、关键事实、待办和引用关系。摘要只是参考材料，不能替代当前授权、最新业务记录或独立核对，也不能把计划总结成已完成工作。
- 压缩目标低于有效预算的 70%；必须验证确有缩小且回到 90% 以下后再继续。单次不可压缩输入仍超限时，明确提示缩短本次内容，不静默丢弃用户要求或无限摘要。
- 摘要请求本身也要受所用模型输入上限约束；历史过大时分块处理。接入调整后的任务预算，验证请求体与超时是否支持长上下文；仍保留有界调用与取消，不新增独立无限调用链。
- 复用现有节点重试：可重试失败最多追加 3 次，非可重试错误直接结束。禁止叠加框架内置重试；恢复任务复用有效摘要，不重复执行业务工具。
- 成功摘要保存到当前任务 checkpoint，并发布到会话 JSONB 快照；后续任务直接复用有效摘要及近期上下文，再加入增量。只复用参考数据，不复用旧任务可执行节点；不承诺无损保留所有历史细节。

### 4. 会话级 JSONB 上下文

- 每个会话维护一份可重建的上下文快照，保存历史摘要、近期消息、必要工具结果／操作回执、来源及修订、增量游标和快照版本。业务表仍是原始数据来源，JSONB 不替代聊天记录或业务记录。
- 新任务读取有效快照，检查权限与来源版本，补入新增或修订的消息，再组装模型请求；当前系统提示、人设、工具定义及模型参数按本次任务生成，不固化在历史快照中。内部游标、版本等存储字段不发送给模型。
- 同一任务的后续模型调用使用内存中的上下文，并按既有节点机制持久化 checkpoint，不逐轮重查整个会话。任务完成及压缩成功后增量合并到会话快照；重试不得重复追加同一消息或回执，较早任务稍后完成也不能被游标漏掉。
- 快照保留摘要与必要近期内容，不无限复制全部历史或二进制附件。压缩直接处理当前有效上下文，不为生成摘要重新拼接全部业务历史；需要原文或最新业务状态时按引用查询。
- 源消息纠正、资料删除或权限变化后，不得继续使用受影响的摘要与引用。读取和写回均校验来源及授权；会话或账号删除时清理相应快照。模型／人设切换重新组装提示、计算容量；仍有效的事实摘要可以保留。
- 并发任务通过版本检查合并；旧任务、失效租约和被取消的压缩不能覆盖新状态。摘要未成功持久化时保留上一份有效快照，恢复时继续未完成的发布，不重做已完成业务操作。
- 旧会话首次执行时按需构建，迁移不批量调用模型。列表展示不加载完整上下文；正常增量路径不逐条查询全部历史关联数据。JSONB 仍从 PostgreSQL 读取，不承诺零查询或模型响应本身更快。

### 5. 进度与失败提示

- 压缩时，现有任务步骤显示“正在压缩上下文”，图标同步显示状态；不弹窗、不抢焦点、不新增用户／助手聊天消息。
- 成功后步骤显示“上下文已压缩”，图标更新为压缩后的比例；详情可见本次压缩前后占用。checkpoint 与对应会话快照均持久化后才能展示成功。
- 重试显示“压缩重试中 · 1/3”等既有节点进度。重试耗尽后显示明确错误，沿用任务唯一的“重试”入口；保留原上下文，不能继续发送超限请求或卡在压缩中。
- 取消、输入失效、租约丢失后停止旧压缩，不能回写新任务状态；通知去重，刷新不重复提示。

## 技术约束与兼容性

- 估算、压缩、状态序列化、UI 分组件维护，不把逻辑集中塞进 `model.py` 或聊天页面。
- 复用消息查询、任务反馈、租约和 checkpoint；服务端只向有权访问该会话的用户返回用量，不返回系统提示、摘要原文或其他用户数据。
- 在 PostgreSQL 增加与会话一对一的上下文表，以 JSONB 保存有效上下文，并独立维护版本。任务 JSON 仅保存用量和进度，checkpoint 保存任务执行状态；三者不混用，不向前端暴露上下文正文。
- 模型容量随服务修订和任务绑定保存；重试使用新配置时重新解析容量、上下文与百分比。HTTP／SSE 增加可选字段，旧记录缺字段时正常显示“尚未计算”。
- 执行、意图校验和答复核对继续遵守原有授权、来源与回执规则；不能因为摘要移除了工具正文而丢失唯一校验证据。
- 已完成消息无需重新运行模型即可查看；升级后新的执行采用统一阈值，旧记录不补造统计。

## 验收标准

各项覆盖与未执行场景见 [验收记录](acceptance.md)。

- 图标位于发送按钮左侧；浅／深色、电脑／手机、键盘操作均可用，输入区不跳动。
- 文本、图片、工具定义／参数／结果均按统一口径计入；核对和摘要调用不污染主助手占用。
- 已知 1M 模型显示正确容量，超过旧 24,000／256,000 限制仍可执行；历史不因超过 12 条而直接遗忘。
- 不同服务／模型容量独立，官方能力、手动覆盖、未知窗口、输出预留与服务商输入限制均正确处理。
- 低于 90% 不触发；等于或超过 90% 在请求前触发；工具调用增长过程中同样有效。
- 压缩前／中／后状态真实可见，压缩后低于阈值且计数下降，原始聊天与业务数据不变。
- 多轮连续任务压缩后仍能承接指代、用户修正、成果条目、已执行／未执行步骤，不重复写入工作或报告。
- 后续任务复用会话 JSONB 并补入增量；同任务多轮调用不重复读取整个历史，列表不加载上下文正文，原始记录保持完整。
- 消息修订、删除、权限变化使相关内容失效；并发、重试、旧任务迟到和持久化中断不遗漏增量、不重复追加、不覆盖新快照。
- 旧会话按需构建，快照可从合法来源重建；删除会话／账号清理快照，迁移不批量调用模型。
- 超大当前输入、无可压缩内容、摘要无效、超时、取消和重试耗尽均明确结束，不无限压缩。
- 刷新、断线恢复、会话／账号切换、旧记录、模型配置变化不串状态或重复提示。

## 待确认问题

无阻塞性产品问题。默认图标悬浮／点击查看详情，压缩过程在现有任务进度内提示，不弹窗。
