# 实施结果

## 变更

- 主模型用 `finish_task` 一次提供完整正文和任务摘要；终止后不再复述。普通聊天、写作、材料分析和搜索不固定审稿。
- 专项核对只返回有来源的具体问题，删除逐段分类、支持关系及“额外内容”裁剪；真实业务尝试、回执、建议和显式事实核验决定是否核对。
- 核验要求必须引用本轮用户原文；要求搜索、来源或日期本身不触发独立核验。模型摘要不能赋予权限或替代真实业务结果。
- 旧检查点与候选缓存支持有限协议恢复；修复共用持久额度，已保存操作保持去重。删除旧管理员督办关键词补救分支。
- 工具接近额度时保留收尾通道，超额并行工具不执行且如实返回；没有提高原有上限。
- 正文纠错失败保留已核对的无争议内容与真实回执；手动重试恢复同一纠错节点，缓存正文与摘要保持一致。
- 专项核对成功时合并主模型已声明的正文缺失及核对器问题；空问题列表不清除已知缺失，补齐前不能仅凭成功业务回执判定完成。

HTTP／SSE、数据库结构和 Web 组件保持兼容，无 migration。实际目录见计划。

## 验证

- 相关后端分批覆盖 31 个文件、483 个不同测试；发现的失败已修复并定向通过。包括权限、操作真实性、持续指令、临时问题、上下文压缩、材料、联网、中断、回执恢复、旧协议和收尾预算边界。
- Web 任务进度与 JobNotice：37 项通过。
- 正文缺失标记返工定向执行 `test_response_delivery.py`：26 项通过，其中新增 8 项覆盖业务／显式核验、双方原因合并、修复仍缺失、纠错失败重试和写入去重；无需重复此前通过的其它模块和真实样本。
- 协调 Agent 使用真实 `deepseek-v4.1-flash` 完成 24 例、36 轮；16 个普通任务样本均无专项审核。2 次有明确根因的失败保留记录，修复后只重测对应新闻样本。
- 协调 Agent 检查两组真实会话的桌面／手机截图与刷新恢复，无页面错误和横向溢出。

命令、分批结果和范围清单位于 `artifacts/spec038/deterministic-validation.md`；原始确定性执行输出在本会话工具记录，未为落盘重跑。真实样本、结果与截图位于 `artifacts/spec038/`，总结见 `live-evaluation.md`。未运行无关 Electron、打包或整仓测试。

## 限制

语义解释仍由主模型负责。若主模型同时误判业务意图及正文，结构校验不能证明任意文本正确；权限、实际写入、来源和回执仍由服务端约束。有限真实样本不代表所有开放任务必然成功，供应商审核和检索质量仍可能限制结果。
