# Agent 可靠性专项修补

## 状态

原功能修补和计划 Schema 契约修复已有独立验收。主模型提示去重与工具契约澄清已完成，最终五轮建议转工作复验通过；max 对照波动明显，稳定提速仍未证实。原始失败、测试范围和已知边界见[验收](acceptance.md)及[实施结果](implementation.md)。

## 背景

[Agent 全量测试的问题清单](../spec-059-agent-comprehensive-testing/issues.md)已完成审阅，测试代码和报告提交于 `9519b65`。本次修补以这些证据为起点，原始失败记录不覆盖。

## 目标

- 系统显示的操作结果与实际保存状态一致；改善模型对失败回执的处理，并明确自由正文仍可能错误描述结果的边界。
- 提前制止没有进展的工具调用，允许正常分页、纠错和版本冲突恢复。
- 建议转工作保留必要内容；局部修改只校验当前操作范围，减少误拦。
- 改善提问工具发现、小文件读取、记忆编辑与流式模块边界，修复失效的测试假设。
- 不增加全局模型核对，不靠降低思考强度、增加额度或堆叠提示词解决问题。
- 同一模型、思考强度和任务条件下，修补不能明显增加用户从发问到获得结果的等待时间。

## 非目标

- 不重做 Agent 框架、Web 页面、三档权限、报告制度或 Electron。
- 不为一般知识、文采、开放推理错误逐例加规则，不保证模型绝不产生错误事实。
- 不调整总预算、供应商输出参数或沙盒并发；上游自身耗时单列，但不能把本次提示词或流程变化可能引起的长等待直接排除在性能排查之外。
- 不回填历史回答、重放旧操作或自动修复用户已有工作与记忆。

## 当前行为

- 业务权限和幂等仍有效，测试未发现重复业务写入；正文却可能与拒绝回执矛盾。
- 相同调用、交替调用和目录加载空转，主要依赖全局预算终止。
- 工作变更计划与后续意图校验对字段保留、等值更新和原子操作范围的理解不一致。
- 建议转工作可能只保存标题，随后补正文时继续携带被拒字段。
- 文档读取固定每次三段，小文件也可能需要五次读取。
- 工具目录实际是能力发现机制；角色、来源和数据权限在执行入口独立校验。

## 目标行为

普通问题保持直接流式回答。任务涉及工具时，以真实结果推动下一步；已经获得相同结果且条件没有变化，不反复执行。能自行纠正的参数问题由 Agent 修正，不要求用户重复授权。无法完成时明确已有结果和未完成项。

## 功能需求

### 1. 操作结果交付（A01）

- 使用当前任务的持久回执、操作对象、字段范围和有效版本判断执行结果；不能依赖模型自报成功或回复中的关键词。
- 成功、待确认、处理中、未执行和失败分别呈现。报告入队不等于报告完成，单项成功不等于整个任务完成。
- 已有纯操作回执直达路径继续使用；普通问答、写作和查询不增加交付前模型核对。
- **保留完整回答**：操作失败后，将结构化的真实结果、失败原因和可恢复条件交给主模型；能纠正的参数问题在现有预算内恢复，禁止重做已成功步骤。不能因某项业务失败屏蔽整段收尾正文或建议。
- 操作卡片和任务结果由服务端根据有效回执生成，复用已有展示位置。部分成功逐项呈现，不能以模型一句“都完成了”覆盖失败状态，也不在多个位置复制提示。
- 保留正常流式回答、建议、已保存工作、私人成果和下载文件入口；不为每个答复增加模型审稿、句子分类或关键词删句。
- 部分成功逐项说明；关联失败是否已恢复时必须匹配对象、步骤和原子范围，不能用另一项成功清除失败。
- 不应执行的额外动作被拦截后，不把它显示为“等待用户补充授权”。参数修正无果也不能伪装成缺少用户输入。
- 系统生成的操作结果在流式期间、结束后及刷新后保持一致。纯操作且符合现有回执直达条件时，由回执直接交付；混合请求保留模型正文。
- 该方案保证程序生成的执行状态，不保证模型自由正文绝不出现相矛盾的措辞。A01 的受控错误正文须保留验证，仍发生时记录残留，不能宣称“虚假成功正文已完全消除”。

### 2. 可复用的工具进展控制（A02）

在现有工具中间件和任务预算中接入统一机制，覆盖目录加载、读取、搜索、业务操作、记忆和沙盒。单节点自动重试、幂等和全局预算继续负责各自边界。

| 观察                                           | 处理                                           |
| ---------------------------------------------- | ---------------------------------------------- |
| 参数和有效来源状态相同，结果也无变化           | 识别为重复候选；不再次产生相同副作用           |
| A/B、A/B/C 交替调用，没有新信息                | 识别循环；重复加载目录也纳入观察               |
| 结果已完整且游标为空，仍继续同一范围分页       | 返回范围已读完的结构化反馈                     |
| 参数错误被指出后，只换措辞、保留相同被拒字段   | 提示应删除或更正的字段，持续无改进则停止该路径 |
| 新分页、新来源内容、新对象版本、有效参数修正   | 允许继续；不能仅因工具名相同而拦截             |
| 合法刷新、首次读取不同范围、读取前置条件后重试 | 按实际来源和依赖变化判断，不复用过期结果       |

- 进展证据采用有界摘要：调用指纹、目标与版本、读取范围、游标、结果类别、来源指纹、已提交回执。时间戳变化、调用 ID 变化和仅换错误说明不算进展。
- 先给一次简短、可操作的内部反馈，让主模型修正或换路径；持续无进展则停止该路径，并在无法继续时进入既有收尾流程。不得制造“拦截→再问模型→再拦截”的新循环。
- 对固定单工具、双工具、三工具循环、目录反复加载、重复网页和记忆调用，最迟在第 12 个新工具请求时进入收尾；这一上界只约束无进展轨迹，不是新工具总限额。具体阈值集中配置并由测试固定。
- 节点内部允许的自动重试、checkpoint 重放与模型新发起的调用分别计数。业务结果未知时先恢复回执，不盲目重做；读取复用仍需校验身份、权限和来源版本。
- 状态按账号、公司、任务、输入范围和执行轮次隔离，worker 恢复不丢失。用户新输入或明确重试允许新的纠错机会，但不能重复已成功写入。
- 不建立通用语义判分模型。不能判断等价的不同查询仅记录观察，不能为了零冗余误拦用户需要的探索。
- 用户只看到真实进度、结果和未完成范围，不增加额度、循环计数、内部诊断按钮或轮询。

### 3. 统一工作变更契约（A04、A09）

- 复用并整理现有工作变更计划，让参数规范化、意图校验、执行与错误反馈使用同一字段和原子范围定义。
- 未提交的字段保留原值。明确要求保留、或要求设置为当前值的字段，不因本次 patch 省略而拒绝；`null`、空串和缺省仍按字段语义区分。
- 完整性校验仅针对本次原子操作；权限校验仍覆盖所有实际提交字段。正文操作不能因另一个属性操作尚未提交而被误拦。
- 肯定和否定的意图裁决都受相同范围约束。跨组理由不能直接变成用户缺少授权，也不能直接改判为允许写入；无效裁决通过现有有界修正处理。
- 错误回执提供结构化的缺失、禁止和冲突字段及原因。模型恢复时聚焦这些字段，已成功的步骤不重做。
- 用户明确“把前两条建议加入工作”时，绑定原建议的具体条目和有效版本。默认保存这些条目的目标、内容和必要条件，而不是只复制标题；明确只要标题时仍可创建简短工作。
- 优先在首次创建中提交完整内容。计划内容保存在正文，不能顺带设置实际完成状态、截止日期或未来行动字段。现有来源引用与用户授权分开处理，助手建议本身不产生授权。
- 聊天中的建议尚未成为结构化成果时，沿用现有成果保存与条目关联能力，不强迫用户重新描述，也不依靠标题猜测对应关系。
- 多项操作按现有原子事务执行，不用跨模型调用的大事务。部分成功后只恢复缺失内容，不多建对象、不重复增加版本、不修改另一项工作。

### 4. 提问、记忆和读取工具（A03、A06、A08）

**提问**

- 目录说明和工具契约明确：用户要求使用临时提问框收集本次选择时，使用已有 `request_user_input`；不能只输出 A/B 文本假装已经展示组件。
- 沿用已有 1～3 个问题、用户实际提交后恢复的流程。普通自然追问、测试消息“1”、用户委托自行决定的内容，不新增强制提问。
- 先改善现有能力发现与描述，不新增前置意图分类调用，不通过解析回答文本伪造问卷。

**记忆**

- 保存或忘记的成功状态、是否发生修改，以工具回执为准；`changed=false` 不需要再保存确认。
- 明确区分当前对话偏好与已保存记忆。关闭记忆时不为了纠错把隐藏的记忆全文返回模型。
- 修补局部替换与 Markdown 列表边界的契约，避免在已有列表符号外再次插入列表符号。保持用户未修改的格式、人工标记和有效期，不全局清洗文档，不自动改写已有记忆。
- 冲突反馈仅提供当前可见且有权使用的定位信息，允许修正精确片段；无法唯一定位才询问用户。不得扩大删除范围。

**文件**

- Agent 阅读页按内容量组织短段，并保留段数和字符量上界。T59 的 131 字节文件应一次 `read_document` 读完，不改变原文、段落定位或引用标记。
- 长文件继续分页，游标单调前进，无跳段或重复。搜索命中与连续阅读分别计算覆盖范围；提取不完整时继续声明不完整。
- 不修改原始文件或全量重新解析附件，不通过无限放大上下文解决分页问题。

### 5. 架构与测试契约（A05、A07及旧测试）

- 消除 `tasks.feedback.reply_stream` 与 `tasks.streaming.publisher` 的双向依赖，共享来源快照和失败状态下沉到单向可依赖模块。保留来源撤权、取消、过期事件和最终持久化检查。
- **目录保留现有能力发现机制**：未加载但已注册且当前角色允许的工具，仍可通过完整 schema、权限、来源和执行校验后调用；调用时补齐相关能力规则。未知工具、越权工具和沙盒关闭后的执行能力继续拒绝。
- 将 `remember_legacy_call` 的名称和说明改为符合真实职责的表达，不把新调用假装成旧 checkpoint 兼容。无需增加“先加载才能调用”的产品门禁。
- 43 项旧测试按失败原因迁移到当前协议和故障注入点，保留原来的安全与恢复目标。不得删除有效断言、放宽权限或重跑到绿；已移除行为不重新实现来迎合旧测试。
- 员工删除已提交报告的测试预期修正为权限拒绝；另测允许的删除流程。原测试报告和冻结结果不改写。
- A06 中一般知识解释、无依据客户文案和自由措辞保留为质量观察；本次只修复可由状态、工具和编辑边界保证的部分。

## 边界条件

- 同名不同对象、用户明确要求多个副本、同一对象不同字段、首次读空结果后合法切换范围。
- 并行调用、写后丢回执、确认重复提交、来源撤回、权限变化、版本冲突、worker 重启、取消与重试。
- 拒绝操作后纠正成功；同一任务部分成功、部分失败；历史成功不能证明当前操作成功。
- 关闭记忆后忘记已明确指定的内容；人工修改与 Agent 保存冲突；嵌套列表、代码块及有期限记忆。
- 普通流式回答、短回答、工作加建议、仅查询、报告异步生成和临时提问续答。

## 技术约束

保留现有 FastAPI、Deep Agents／LangGraph、PostgreSQL、Redis 和 SSE。优先使用现有 Job JSONB、任务租约、回执、版本和预算，不新增服务、依赖或数据库 migration。文档按 S0；实施涉及共享 Agent 执行与持久化，按 S3 验证相关子系统。

## 兼容性要求

- 历史会话、已保存操作和旧 checkpoint 可读取；新增内部字段有版本和缺省处理，不批量回填。
- 公开 API 和 SSE 尽量保持现有结构；新增信息仅在工具内部或使用兼容的可选字段，不泄漏内部调用额度。
- 不改变账号、角色、公司和来源权限，不改变三档执行策略、思考强度及现有幂等约束。
- 发布须按已有流程处理在途 worker；回滚不删除新版本已经保存的业务结果。

## 待确认问题

无。采用真实回执反馈、系统操作结果和完整模型正文，保留正常流式与建议，不新增模型审稿。模型正文仍可能误述结果，A01 残留须单独报告。
