# 实施计划

## 范围与顺序

对应[专项规格](spec.md)。一个实施 Agent 串行处理耦合的业务执行逻辑；测试实施分别负责真实流程脚手架和旧测试迁移，文件范围不重叠，共用测试数据库时串行执行。完成后由新的独立 Agent 验收。

1. 将 A01、A02、A04、A08、A09 和来源权限边界转为固定回归，复用原始受控轨迹；记录修复前结果。
2. 统一工作变更的字段、原子范围和错误结构，补齐建议转工作及记忆编辑契约。
3. 接入工具进展控制，复用既有执行节点、预算和回执，覆盖目录调用。
4. 保留完整模型回答，统一真实业务结果，修复流式模块依赖，验证失败不吞掉独立建议。
5. 优化小文件读取、提问工具描述，明确目录职责；迁移旧测试。
6. 执行相关 Agent 回归及预先冻结的真实流程，记录结果和耗时，清理隔离环境，独立验收。

## 提示词精简

- 合并工作、报告、私人成果能力说明与工具契约中的重复规则，参数格式与操作边界保留在工具说明。
- 不改通用核心提示、变更计划、授权核对、工具进展控制、调用额度或运行流程。
- 使用精简前的当前工作树作为对照，固定同一模型、low 强度及合成输入；比较问答、写作、单字段更新的首字、总耗时与调用数。耗时增加超过 30% 且 3 秒时，只追加一轮反序配对，不反复测试到绿。
- 复验建议转工作与定向修改的多轮流程，检查完整正文、来源条目、版本与写入数量。此前 low 证据保留；后续按下方 max 对照计划评估，不用 low 数据替代 max 结论。
- 执行受影响能力的定向回归，由新的独立 Agent 核对契约与证据；不重复全量测试。

## 数据流与边界

### 工作与交付

原始请求／有效承接 → 来源条目和目标版本 → 规范化变更范围 → 当前原子提案 → 角色、授权和版本校验 → 原子写入／拒绝回执 → 恢复或交付。

- 变更计划缓存键继续包含输入、来源、目标及配置版本；修正提案不能偷偷扩展原授权范围。
- 错误结构统一表达类别、字段和恢复动作，不用中文报错字符串判断“是否同一错误”。否定裁决结构不足时走原有有界修正，不直接放行。
- 主模型接收结构化回执与有界的恢复指引，正常正文继续通过现有 Redis／SSE 发布，不因单项操作失败强制撤下整段建议。
- 现有 `completion.py`、`delivery.py` 和 `outcomes.py`复用相同的有效操作证据，分别处理纯回执直达、交付及任务状态；不新增一套正文语义核对器。
- 已有正文标记允许携带未完成事项，普通收尾与预算收尾都合并这些信息；空标记不清除真实失败，不增加工具或模型轮次。该元数据只描述任务状态，不能授权写入或恢复旧任务。

### 工具进展

调用入口 → 身份及允许集合 → 任务范围／进展状态 → 原执行节点与权限校验 → 结果证据更新 → 继续、反馈或既有收尾。

- 通用状态机只接受规范化证据，不直接依赖各业务模型；各工具的目标、范围、版本和增量在 `evidence.py` 适配。
- 持久状态放 Job JSONB，带 schema 版本及输入范围，有界保存。沿用任务租约和锁事务，不能让并行调用丢更新或各自放行重复写入。
- 控制器不取代幂等，也不生成假的成功回执；授权失效时不能为了避免重复查询返回旧私人数据。
- 不把新的调用 ID、错误文案、任意改参当作有效进展；不同查询无法确定等价时不硬拦。
- 循环终止复用预算收尾，但独立记录原因，不将其记为网络错误或恢复时自动重试。全局预算不增加。

## 接口与迁移

- 无计划中的数据库 migration，无历史数据修复。
- 现有工具名与必要参数尽量兼容；内部错误字段、进展证据和 Job 状态使用可选扩展。旧任务缺少状态时从现有回执和节点初始化，不将读取历史会话变成新执行。
- 合并短文件阅读页不合并原始段落 ID；仍返回真实 ordinal、location 和 citation，游标从最后实际返回段落之后继续。
- `streaming/lifecycle.py`承接共享快照／失败分类，不能反向导入反馈入口或发布器。既有架构测试保持原断言。
- 原059冻结清单、SHA、断言与报告不改写。本次脚本显式选择060清单，记录当前应用 SHA，新的结果写入独立目录。
- 回滚沿用现有发布流程；新版写入回执继续可读，任务进展控制的新字段可被旧版忽略，不删除任何业务结果。

### 真实模型与浏览器

- 在隔离账号、独立数据库和测试资源中执行。先冻结角色、人设、权限、模型、强度、必需结果、禁止写入和最大合法副作用，再发送第一条请求。
- 必跑原 T13、T19、T35、T38、T40、T59、T64、T65、T73；浏览器覆盖 B03、B04、B06 首轮提问及选择续答。原始案例直接复用，新增断言写入060清单，不能只检查最终任务状态。
- 补充普通问答、联网查询、编码产物、工作加建议、报告异步生成、拒绝后收尾及中断重试，覆盖员工／管理员、三档权限和两种人设；这些维度分配到代表流程，不跑无意义笛卡尔积。
- B04、B06、T73各预先安排三次独立旅程，防止把偶然成功当成修复；其余真实流程先跑一次。首次失败保留，不以不断重试代替修复。
- 低／高思考强度分开报告；保留至少一组同输入的 low／max 对照，不降低 max 来缩短测试等待。
- 每条记录用户输入、真实工具参数／回执、逻辑调用与内部重试、持久版本、首字／总耗时；附加模型事实质量观察不混入系统正确性结论。
- 普通问题的模型调用数不得因本次机制增加；小文件阅读次数和固定循环长度必须下降。真实时间受上游影响，比较同配置样本并分别列出模型、工具和系统耗时，不承诺固定秒数。

### 通过与停止

- 所有修补组有直接证据，必要权限与恢复回归通过，未引入新的系统错误，再交独立验收。A01 按保留完整回答的边界评定；模型正文残留与系统结果修复分别报告，不能改写原失败证据。
- 真实模型仍省略要求的交互、未交付内容或无法完成业务时如实记录，不能用固定响应测试冒充真实通过；普通知识错误与上游超时单列。
- 验证满足后停止，不重跑完整059大测试来追求更高主观信心。清理仅限本次创建且归属明确的账号、schema、容器、文件和进程。

## 风险

- 保留自由正文意味着模型仍可能误述操作结果；按这一边界如实报告，不能把回执卡正确当成正文错误已消除。
- 过严的进展判断会误伤探索；先依赖客观版本与覆盖证据，不把不同结果粗暴合并。
- 工作创建的内容完整性不能演变为强制长表单；用户只需标题时保留简短创建。
- 记忆局部编辑不能全局重排格式或泄漏关闭后的记忆。
- 旧测试迁移需逐项审阅，不借机放松安全目标，不恢复已移除的昂贵模型核对。

- 仅调整主模型核心、能力和工具说明，合并重复职责、消除成功结果表述歧义；保留权限、来源、局部字段、建议首次完整落库和幂等约束。内部授权／变更计划、重试次数、模型强度与流程不变。

- 原位修改目录：`agent/prompts/main.py`（核心与能力说明）、`agent/tools/actions.py`（调用说明）、必要时 `agent/completion/prose.py`（正文标记说明）；均位于 `apps/server/app/`，不改执行函数或目录结构。证据放 `artifacts/spec060/max-prompt/`，由独立验收核对。
