## 实现约束

- 复用 `src/ui/theme.css`、`src/ui/select.css`；布局尽量限定于 Web。修改已有规则、移除本次替代的覆盖，不在文件末尾不断追加补丁。
- 列表、阅读、编辑保持各自容器职责，外层内容区统一填满右侧可用宽度；按内容区宽度使用 Grid／容器查询，壳层断点控制导航。用户审查后取消固定内容限宽，详见 Spec L01／L04。
- 详情导航保留来源 location 和查询参数，缺少来源才用确定回退页；不能将直接打开详情的用户送回外站。
- 摘要省略仅发生在列表，详情和保存内容不变；员工规则摘要从现有 DTO 派生，不新增接口。
- 保留表单 key、挂载身份和草稿路径；吸底栏预留实际占位，菜单继续管理焦点、外部点击和边界。
- Markdown 使用安全的 React 展示路径，不使用未过滤 HTML。若选择小型依赖，实施时核对已有依赖与官方用法，不引入完整编辑器或无关升级。

## 数据流与迁移

沿用 API → DTO → 页面，以及受控输入 → 原有保存／确认接口。只调整展示组件、布局状态和返回上下文；无数据库迁移、凭证导入、服务端协议变更和批量数据更新。

## 相称工程验证与停止

当前文档 **S0**，只检查 diff、覆盖和引用，不运行测试、lint、类型或构建。实施预计 **S2**，以最终 diff 为准：

- 编辑时用项目 Prettier 整理本次源码文件，不格式化全仓库。
- TSX／类型修改运行一次 `npm run typecheck:web`，lint 限本次修改的 Web 文件。
- 只为确有行为的变化补必要测试，例如 Markdown 的不可信输入、返回路径或草稿保护；使用 `npx vitest run --config vitest.web.config.ts <相关测试文件>`。纯样式不写实现镜像测试。
- 仅新增依赖、入口或影响构建时补一次 `npm run build:web`。
- 不运行服务端、Electron 录音、ASR、安装包或完整跨平台套件；确实修改共享控件才补其桌面定向观察。
- 独立验收复用已通过且内容未变的证据；有具体未解决问题才扩大验证。不主动触发 CI，不重复相同检查。

## 风险

- 过度压缩：短记录有密度基线，正文不强行限高，完整内容可达。
- 全局 CSS 回归：按页面类型收敛，避免更改 Electron 默认值；对受影响模板逐页对照。
- 输入／弹层遮挡或焦点丢失：保留组件身份、草稿路径，检查短视口与底部占位。
- 富文本不可信内容：禁止 HTML 执行和自动外部资源加载，测试安全链接与转义。
- 本机样本不穷尽平台：记录实际浏览器和视口，设备不足时保留实机限制。
