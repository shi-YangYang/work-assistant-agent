# Plan — Web 排版与响应式维护

对应 [Spec 010](spec.md)，DONE。实际检查与边界见 [实施](implementation.md)／[验收](acceptance.md)，本计划只保留实现分工及检查策略。

## 模块与顺序

1. `styles.css`、`App.tsx`、`ui.tsx`：页面容器、间距、紧凑侧栏、标题工具栏、弹窗。
2. `Records.tsx`、`Settings.tsx`：列表摘要、筛选组合、规则摘要、账户／成员表单。
3. `ModelServices.tsx`：连接字段、用途、环境来源、保存区与草稿语义。
4. `Assistant.tsx`、`Markdown.tsx`、`navigation.ts`：输入高度、安全正文及来源返回。

共用壳层和 CSS 高度耦合，一个实施 Agent 串行开发，再交独立验收；用户随后明确要求的宽度返工由主 Agent 独立完成。

## 数据流与实现约束

- 沿用 API／DTO 和保存接口，无服务端、迁移、密钥或业务资料变更。样式限定 Web，复用共享主题／选择器，不累加末尾覆盖补丁。
- 外层内容填满右侧工作区，字段按容器宽度重排，导航按视口断点切换；具体尺寸与行为只在 Spec L01～L09 维护。
- 列表可摘要，详情与保存内容不截断。员工规则从现有 DTO 派生；表单挂载身份、key 与草稿路径稳定，吸底区预留占位。
- 来源保存本地 location／查询，直接进入有确定回退，拒绝外站返回。Markdown 用 React 文本节点，禁止未过滤 HTML，不引入完整编辑器。

## 相称验证

本轮 Web 为 S2：修改文件 Prettier、Web 类型和定向 lint；导航／Markdown 等实际行为补对应测试，新模块入口补普通 Web 构建。CSS 增量按 S0；没有具体问题不重复已通过检查，不运行服务端、录音、ASR、安装包或 CI。

使用日常 Web 和现有资料，以 1440×900、390×844 做逐页前后对照；针对共享导航／工具栏／表单补 320、768、1024px、断点两侧和短屏。浅色逐页、深色选共用状态，不机械穷举全部组合；检查长文、空态、菜单、焦点、草稿和末项可达性。

资料位于忽略的 `artifacts/spec010/before/`、`after/`、`width-rework/`，本机 [总览](../../artifacts/spec010/audit.html)；最终尺寸和覆盖只在验收报告详述。结束恢复身份／主题／视口，清理本轮空草稿，不为画面发送消息或保存配置。无实体设备时保留手机键盘／Safari／Windows 限制，不用截图替代。
