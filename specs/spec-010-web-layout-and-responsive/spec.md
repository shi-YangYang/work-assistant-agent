## 背景与目标

Web 已具备工作助手、工作记录、报告、团队看板与公司设置，但各页面的宽度、间距和操作区缺少统一规则。此次逐页维护，让电脑端有效利用宽度、手机端自然重排，减少组件内部和相邻区域的无效留白，继续遵循 [既有界面方向](../../.ai/decisions/0009-interface-design-direction.md)，与 Electron 的主题、导航和文字层级保持一致。

数据少造成的页面下半部空白属于正常状态，不用装饰卡片、虚假指标或拉伸内容填满。

## 目标行为与功能需求

### L01 — 列表密度

- 工作、报告、成员、团队列表统一主次文字和行内间距。短条目以 64～88px 为基线，多行必要内容自然增高，不固定高度截断姓名、状态和操作。
- 工作列表摘要最多两行，下一步／阻碍作为简短摘要；详情保留完整内容。状态、更多操作靠近标题或固定操作列，不悬浮在长段落中间。
- 宽屏组织标题、状态、更新时间和操作列。列表、详情、聊天和设置的内容区域随右侧可用空间伸展，桌面左右各留 24px，不再用固定最大宽度或动态居中内边距留下大块空白。
- 同一员工详情各标签页的起始边线和工具栏一致；正文可限宽，不强求文字与数据行一样宽。

### L02 — 标题与工具栏

- 标题、辅助信息、页级操作形成稳定标题区；标题／工具栏／列表间采用 16～24px 间距，消除父级 gap 与子项 margin 叠加。
- 间距归纳为 4、8、12、16、24、32px，按文字、控件、组件、区域使用，不直接全局缩小 margin。
- 电脑搜索框优先利用可用宽度，常规范围约 240～420px；状态／类型选择约 128～180px；日期显示区约 160～200px。根据内容自然增长，不能让完整标签无入口地截断。
- 报告类型、日期和生成按钮有明确分组；开始／结束日期作为同一组合，空间不足时成组换行，保持标签和现有筛选能力。

### L03 — 响应式过渡

- 按视口／内容区宽度重排，不按 User-Agent 猜设备，不通过整体缩放解决拥挤。
- ≥1024px 保留文字侧栏；761～1023px 默认使用紧凑图标侧栏，具有名称提示和展开入口，展开不挤压内容；≤760px 沿用手机顶栏和底部导航。设置和成员入口始终可达。
- 通过 Grid／Flex 和容器尺寸调整列数，不挤小文字与点击区域。手机左右留白约 16px、主要点击区域至少 44×44px、输入文字至少 16px；桌面常规字段／按钮约 36～40px 高。

### L04 — 设置表单

- 账户摘要简洁化，密码编辑白色区域与设置工作区同宽；说明位于字段附近，保存独立排列。
- 模型编辑按自身宽度安排字段：适合成对的字段并排，URL、密钥、长选项保留足够宽度，窄屏回到单列。
- 环境配置来源收为紧凑摘要＋展开详情，保留导入能力，不能因布局切换隐式导入／更换服务。
- 设置的标题、标签、说明、输入和操作区共用排列规则，不引入第二套颜色或控件体系。

### L05 — 规则与用途

- 星期选项等宽排列：满足点击尺寸时七列，否则有序换行（例如四列），避免孤立的第七项。
- 管理员保留规则编辑；员工改为时区、周期、生成时间、截止时间的可读摘要，停用周期显示未启用，不再展示整页禁用输入框。
- 模型用途使用紧凑标题＋选择区；默认状态下 1440×900 能看到三项用途和保存入口。复杂预设或错误展开后可自然滚动。

### L06 — 聊天与长文字

- 收敛上报、助手回复、结构化进展卡的留白，保留来源和确认状态层次，避免重复大标题与过多卡片嵌套。
- 助手回复支持基础 Markdown 段落、列表、强调和代码文本。只渲染安全内容，不执行 HTML、不自动加载远程图片、不允许危险链接协议；用户原文保持原样可读。
- 长 URL／标识能够换行；不通过 CSS 删除正文。本次不改模型提示词、生成质量或已保存业务文本。

### L07 — 详情导航

- 原始上报显示正确名称与来源上下文，统一壳层返回，清理重复返回入口；直接打开详情也有确定回退页。
- 从团队进入员工工作／报告后能回到对应上下文；返回保留标签页和筛选，不误导到个人记录。

### L08 — 编辑和操作区

- 聊天空输入区使用紧凑起始高度，随内容增长到上限后内部滚动；上传、录音、发送始终可用。
- 工作／报告文本框按内容增加高度，设最小行数与最大高度；短内容不占四个大空框，长内容也不局限一行。
- 长表单统一保存／取消或稍后继续操作区；吸底时只附着于所属编辑区并预留占位。底部导航、弹窗、键盘不得永久遮住最后一项或保存操作。
- 断点切换不卸载正在输入的表单、不清空草稿、不重复提交，保留未保存保护和版本冲突逻辑。

### L09 — 弹层与辅助状态

- 弹窗标题、关闭、正文、说明和操作分区一致；短屏正文可滚动，取消／保存可达，保留焦点管理和键盘访问。
- 下拉与触发控件对齐，靠边时避让，长选项可读、列表可滚动。更多操作支持鼠标、键盘和触屏，不依赖 hover 才能发现。
- 未保存服务用“丢弃草稿”语义；已有服务保留真实删除影响和确认，不削弱服务撤销行为。
- 空态、错误、忙碌、禁用和焦点延续现有主题；提示贴近操作，保留必要约束／失败原因，避免流程说明式长文案。

## 非目标、技术与兼容边界

- 不新增业务功能、角色、API、字段、迁移、部署，不改服务端 harness 或模型协议；不重设计 Electron、不更换品牌配色、不迁移目录、不批量升级依赖。
- 优先把布局规则限定在 Web，复用现有 React、路由、共享主题和选择器。确需改共享样式时只补受影响桌面控件的定向检查。
- 覆盖管理员／员工、浅色／深色、少量／长内容和空态；320～390、768、1024、1440px 及实际断点两侧没有整页横向滚动、关键文字无法查看或操作被覆盖。
- 本次视口截图不是实体手机或 Windows 实测；未验证真实键盘、Safari 原生日期或所有错误／冲突状态，实施时注明可获得条件和实际覆盖。
- 当前文档按 S0；实施按 S2 的 Web 范围验证，不新增默认 CI，不调用付费模型，不运行录音、转写和发行包验收。
