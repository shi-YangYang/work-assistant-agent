# 项目级测试整理：需求

[实施方案](plan.md)

## 状态

已实施并通过独立验收，见 [验收结果](acceptance.md)。本地项目级测试不接入 CI；既有 CI 已精简为日常静态检查与普通构建，完整测试留本地，平台发布验证按需手动运行。新增统一入口及其 wrapper 当前仅支持 POSIX 执行；Windows 原生命令保留但未验收。未提交、推送或运行远端 CI，具体实测与限制见 [实施记录](implementation.md)。

## 背景

Agent 的 eval 负责判断真实模型是否完成任务、回答是否准确。项目还需要另一条稳定的检查路径：页面能否操作、业务是否正确保存、失败后能否恢复、界面在电脑和手机上是否可用。

项目已有较多测试，问题不是从零搭建，而是入口分散、部分历史用例过时，以及“已有测试文件”和“当前功能已经验证”容易混淆。需要保留有效资产，让维护者能找到用例、选择范围、重复执行，并看懂结果。

## 目标

1. 整理 `tests/` 的归属、运行入口和覆盖关系，优先修复、复用现有用例，不批量搬家或另建测试平台。
2. 同时覆盖 UI 外观、交互行为、业务流程及权限／持久化边界；不能只检查函数返回值或页面能打开。
3. 提供项目级本地入口和清楚的结果汇总，按模块、功能和运行层次选择，不要求每次修改全量运行。
4. 把真实模型评测与确定性产品测试分开，防止普通测试意外调用外部服务或把模型波动当作 UI 缺陷。
5. 首批执行结果可追溯到源码、测试范围、实际环境和证据，失败、阻塞与未测不隐藏。
6. 精简已有 CI 的默认执行范围，避免把本地完整测试再次自动运行；保留干净检出环境的代码检查和必要发布验证。

## 非目标

- 不重建 Agent eval，不重复其数据集、评分器、人工复核机制或真实模型矩阵。
- 不以整理测试为由调整产品规则、补模型提示、改变权限或放宽有效断言。
- 不追求任意的全仓代码覆盖率百分比；首期以需求和流程覆盖为主，测试文件数不作为质量门槛。
- 不承诺穷举所有浏览器、操作系统和数据组合；不将浏览器设备模拟称为真实手机验证。
- 不修改线上数据，不把日常用户资料或凭证变成自动化夹具，不默认运行真实麦克风、模型下载／推理、安装卸载或破坏性沙盒验证。
- 不修改 `AGENTS.md`，不合并或删除 `tests/`、`eval/`、`specs/` 等根目录。

## 当前行为与已有资产

按当前 Git 跟踪文件静态统计，`tests/` 共 440 个文件，其中按 `test_*.py`、`*.test.*`、`*.spec.*` 命名识别到 359 个测试入口文件。它们不是 359 条用例，也不是通过数量：

| 位置                              | 测试入口文件 | 已有用途                                  |
| --------------------------------- | -----------: | ----------------------------------------- |
| `tests/web/`                      |           95 | Web 状态、工具函数和 DOM 交互             |
| `tests/server/`                   |          206 | API、业务模块、Agent 程序契约、恢复与权限 |
| `tests/e2e/web/`                  |           19 | 浏览器页面、布局与业务操作                |
| `tests/desktop/`、`tests/core/`   |       10、11 | 桌面逻辑、Python 核心                     |
| `tests/e2e/desktop/`              |            4 | Electron 窗口、会议、纪要及打包流程       |
| `tests/sandbox/`、`tests/deploy/` |         7、7 | 沙盒协议、部署配置与本地基础设施          |

已定位的整理问题：

- 根 `npm test` 实际只运行桌面单元与 Python 测试；Web、服务端、浏览器有各自入口，尚无项目级运行与覆盖说明。
- Web Playwright 配置及环境夹具依赖 `SPEC044/054/068/073` 等历史变量、白名单和固定端口。部分测试读取 `artifacts/spec044/`、`artifacts/spec050/` 的旧记录，新检出仓库不能仅凭这些脚本重建输入。
- `ui-layout.spec.ts` 仍使用日报记录；`work.spec.ts` 仍寻找“查看此版本”，现有工作页面已使用“查看当时内容”。必须按当前产品规则核对预期，不能直接把历史用例当成有效覆盖。
- `generated-files.spec.ts`、`performance-journeys.spec.ts` 明确依赖真实模型旅程或采样，仍在普通浏览器目录。应归回 eval，普通文件下载和页面行为另由确定性用例覆盖。
- 部分浏览器测试拦截整个业务 API，适合验证前端状态，却不能证明真实保存和恢复。需要标明替代了哪一层。
- 当前 CI 已运行桌面模块、服务端、Web 模块及构建；没有运行 Web 浏览器套件。服务端任务配置允许约 30 分钟，不能把现状称为已经轻量，也不能无衡量地再叠加完整 UI 回归。

另外只读核对了 [2026-10-26 的一次成功 PR 运行](https://github.com/shi-YangYang/work-assistant-agent/actions/runs/40300257922)：Company 任务从启动到结束为 20 分 28 秒，其中 `test:server` 为 17 分 11 秒；macOS／Windows 均执行了桌面单元与 Python 测试。该记录对应 `efe607e`，不是当前变更的实测，也不代表平均耗时。

这些是静态盘点结果，不是本次实测失败。详细入口见 [package.json](../../package.json)、[CI 配置](../../.github/workflows/ci.yml)、[Web 浏览器配置](../../apps/web/playwright.config.ts)。

## 目标行为

开发者从 `tests/README.md` 按目的选择模块、UI 或完整流程，查看将运行的测试和所需依赖，再通过统一入口调用现有 Vitest、pytest／unittest、Playwright 和 Node 测试。原有命令继续可用。

结果同时回答：选了什么、实际执行了什么、替代了哪些外部系统、哪些功能通过、哪里失败或缺证据。完整流程从真实页面操作到服务端保存，再刷新页面并独立读回；控件级测试只对自身边界作结论。

## 功能需求

### 1. 整理目录与用例

- 保留按应用和业务领域组织的目录；普通 Agent 契约测试继续留在 `tests/server/agent/`，不能因为名称含 Agent 就移入 eval。
- 对现有测试及相关脚本登记保留、修正、合并、迁移或退役的理由与去向。只有验证目标相同、有效断言不减少的用例才合并；日报移除、旧入口兼容等有效反向测试继续保留。
- 用原生测试发现结果和少量套件配置建立清单，不手工复制几百个单元用例。功能覆盖映射到实际文件／测试，缺口明确标记，不用一条模块测试代替整段用户流程。
- 删除过时测试须说明产品依据；迁移须检查导入、配置、命令和自动发现，避免漏跑、重复运行或遗留两份实现。
- 真实模型专属浏览器入口迁至 `eval/`，必要共享夹具保留单一实现；历史结果和冻结来源路径不回写。

### 2. 按验证层次组织

| 层次           | 执行方式                                                        | 结论边界                                                 |
| -------------- | --------------------------------------------------------------- | -------------------------------------------------------- |
| 模块与契约     | 现有 Vitest、pytest／unittest、Node 测试；按需要使用专用数据库  | 程序行为与保护边界，不代表 UI 可用或模型正确             |
| UI 状态与视觉  | 真实组件、浏览器布局与交互；故障注入或固定数据明确标注          | 排版、点击、键盘、触摸、加载与错误状态                   |
| 完整业务流程   | 浏览器 → 实际 API → 必要 worker／队列 → 校验与数据库 → 刷新读回 | 应用流程可完成；外部模型使用受控响应时不证明真实回答质量 |
| 平台／外部集成 | 显式选择的桌面、真实沙盒、转写和发布前检查                      | 仅限实际平台、设备和依赖；未执行单独列出                 |

确定性流程默认不读取真实模型密钥、不请求外部模型／搜索／钉钉服务。替代点尽量位于供应商协议边界，程序仍执行实际序列化、状态流转、权限和保存。意外外网请求应报错。拦截业务 API 的前端测试不能标作完整流程。

### 3. 首批功能覆盖

以下每组均须建立当前有效的步骤、结果断言和正常／反向场景。先映射现有测试再补缺口，不机械增加同义用例。

| 功能组           | 必须检查的行为                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 登录、身份与导航 | 登录失败／成功、退出、会话失效、切换账号、直接访问旧链接；员工／管理员入口和跨公司访问边界                                         |
| 会话与任务界面   | 发送与草稿、切换会话、流式展示、断线恢复、刷新、取消与重试；已入队不显示为已完成，旧响应不污染新会话                               |
| 提问和确认       | 1～5 题、单选／自填、自动前进、返回修改、最终提交、刷新续接；确认／取消前后副作用正确                                              |
| 附件、来源与成果 | 上传、解析状态、预览、下载、来源跳转、删除后访问；多批累计、混合类型、同名冲突、长文件名及较早批次引用                             |
| 工作             | 创建、正文和清单、属性、材料、修改记录、无变化保存、并发冲突、删除；初次创建不重复展示历史，刷新后的内容与保存一致                 |
| 周报             | 无汇报规则的手动生成、本周／跨月／跨年、正文／清单来源、真正空周期、生成中状态、编辑／候选／提交、删除后重建、团队查看；日报不恢复 |
| 汇报安排与团队   | 有规则时产生待办、到期／逾期、同周报告复用、调度幂等、团队筛选与详情；手动生成不被规则存在与否错误阻断                             |
| 管理与设置       | 成员、模型服务／用途、执行权限、记忆、外观、通知／公告、反馈、用量、登录配置与声纹入口；字段校验、保存失败／恢复、角色隔离         |
| Electron 与会议  | 窗口启动、主进程／preload／renderer 边界、会议列表、录音状态、回放、固定转写输入、纪要来源、导出、重启保存；真实设备效果单列       |
| 服务基础设施     | 迁移、事务／幂等、租约／并发、任务恢复、文档转换、媒体访问、沙盒协议、部署配置；已有专项按依赖独立执行                             |

跨入口的高风险闭环至少包括：

1. 登录 → 创建工作 → 编辑正文／清单并关联材料 → 刷新 → 生成该周周报 → 编辑提交 → 管理员查看 → 删除后主动重建。
2. 会话分批上传 → 固定工具响应沿实际任务链执行 → 提问／确认 → 写入工作或交付文件 → 刷新 → 下载／读回；核对条目、来源和保存次数。
3. 相同操作遭遇失败、重复点击或并发更新 → 保留原数据与待编辑内容 → 明确恢复 → 成功一次；独立失败不能被另一操作成功抹除。
4. 创建会议／固定音频输入 → 状态切换 → 固定转写与纪要响应 → 原文回溯／导出 → 重启读取；人工麦克风验收与合成输入分开。

### 4. UI 与视觉验收

遵循[现有设计基准](../../docs/design/README.md)，覆盖共享组件和代表页面，不重新设计界面：

- 卡片：统一高度规则、标题省略、图标居中、预览裁切、整卡点击、独立按钮不冒泡误触；附件分组及 hover／focus／触屏动作不引发布局跳动。
- 页面与弹窗：返回／标题／正文间距、工具栏对齐、菜单内边距、弹层不遮挡、短屏可滚动、按钮可达。
- 反馈：加载失败与操作失败分别展示；关闭、切换条件或恢复后清理，错误不挤压页面、不被静默吞掉。
- 控件：空／长／多条内容、加载、禁用、失败、等待确认和完成状态；键盘焦点、Escape、单选与自填均实际操作。
- 主体流程使用桌面与手机宽度；布局专项覆盖 360、390、768、1440 像素以及必要短屏。共享组件覆盖浅／深色。Chromium 为主，Firefox／WebKit 运行关键跨浏览器子集，不穷举全部维度。
- 使用布局、可见性、命中区域和状态断言，并对关键共享组件保留小范围截图对照与人工目视。固定浏览器、字体、主题和时间等条件；仅屏蔽无关动态内容，不能屏蔽错误。新基线须经查看，不自动接受失败截图。

截图生成不等于视觉通过，DOM 测试也不等于浏览器布局通过。软键盘、真实触屏与系统权限未实测时明确保留限制。

### 5. 环境、运行入口与结果

- 首期提供“模块、Web UI、Web 完整流程、桌面、可选集成”的选择入口和运行清单；项目级汇总只薄封装现有运行器，不复制断言引擎。
- Web 复用现有隔离环境管理器，去掉以旧 Spec 编号替代环境身份的耦合。仍严格验证专用测试库、schema 归属、run ID、账号及 UI/API 目标；不能把固定端口改为任意 URL 放行。
- 每轮使用合成数据，前置数据可由夹具建立；待测创建／更新／提交必须走指定入口。禁止依赖已删除的旧 artifacts 或其他用例碰巧留下的数据。
- 自动化桌面测试保留临时数据机制；本机人工桌面验收按项目规则使用日常环境，二者不得混用。故障注入和清理只作用于本轮自有资源。
- 保留原生 JSON／JUnit、截图和必要失败 trace；摘要包含源码身份、环境、命令、耗时、所选／实际运行数量、替代边界和证据路径，产物写入忽略的 `artifacts/project-tests/<run-id>/`。
- 结果分为通过、失败、阻塞、未执行和有理由的不适用。进程提前退出、测试零发现、缺浏览器／数据库、必需项跳过不能算通过。整体通过要求本轮事先声明的必需项全部执行并通过。
- 不自动重跑到绿，不自动更新截图基线；具体修复后只复查受影响项和必要紧邻边界。每次结果保留，不能覆盖首试失败。

### 6. 既有 CI 精简

本地测试负责功能正确性；日常 CI 只验证准备合入的代码在干净环境中能否完成静态检查与普通构建。两者结论分开，CI 绿灯不代表 UI、业务或模型质量全部通过。

| 检查                                                     | 建议执行位置                                               |
| -------------------------------------------------------- | ---------------------------------------------------------- |
| Prettier、ESLint、Web／桌面 TypeScript、项目 Python 语法 | PR 的单个 Linux 检查任务；不做 macOS／Windows 双份静态检查 |
| Web 与桌面 main／preload／renderer 普通构建              | 同一日常任务；不运行桌面应用，不生成安装包                 |
| Web／桌面／服务端完整模块测试、业务流程、UI 与视觉回归   | 本地按范围执行，不在 PR 或标签推送后自动再跑               |
| 真实 Office 转换、沙盒和部署脚本功能测试                 | 本地专项；目标发布环境的必要预检另保留                     |
| macOS／Windows 桌面运行、ASR、打包与安装验证             | 发布前按平台及阶段手动选择，不能因此连带重跑全套业务测试   |
| Agent eval 与项目级统一测试入口                          | 仅本地，不接入任何 CI 自动任务                             |

日常 CI 移除 PostgreSQL／Redis 服务、数据库迁移、完整服务端和桌面 Python 依赖安装，以及 FFmpeg／LibreOffice／字体／Poppler 安装。Python 语法检查不导入业务模块、不安装推理依赖；Node 安装按实际构建需要保留必要脚本，不能用跳过依赖初始化换取虚假构建通过。

维持 PR 合入 main 的检查触发，不增加 dev 推送或合并后再次全跑；既有标签触发只执行轻量代码检查，不自动启动完整桌面／ASR／打包矩阵。手动选择平台专项时只执行所选流程与必要前置，同次流程构建及固定材料能复用就不重复准备。不做根据本地 PASS 自动跳过远端检查的缓存或复杂动态调度。

保留名为 `CI required` 的汇总检查，同步修正依赖与成功／跳过判断：取消、超时、失败、缺失的必需任务都不能变绿。分支保护不擅自关闭；若仓库还要求退役的 job 名称，需明确迁移该必需检查，不能留下永远等待的 PR。

[部署工作流](../../.github/workflows/deploy.yml)及实际发布脚本的来源约束、备份、原生文档转换预检、迁移和健康检查保持原职责。它们验证实际交付环境，不能作为重复测试删除。

取舍是 PR 将不再独立复验业务逻辑。交付时必须分别提供对应源码的本地测试结果和远端检查状态；源码、用例或相关环境变化后，旧结果不能冒充新版本通过。没有足够本地证据时明确未验证，不拿 CI 构建成功补齐。

## 技术约束与兼容性

沿用 npm workspaces、Vitest、Playwright、pytest／unittest 和 Node 原生测试，不引入托管测试平台或在线评分服务。测试不能改变生产代码路径；确需产品修复时先区分测试假设过时和真实缺陷，再按授权范围处理。

项目级运行入口、UI／完整流程套件与汇总只供本地手动使用，不接入 CI，也不把 Agent eval 接回 CI。已有 CI 按上述分工调整默认范围；从 CI 退出的测试保留本地可执行入口，不通过删除有效测试或保护逻辑来减少耗时。

同一轮任务中，已通过且源码、用例与相关环境未变的检查直接沿用已有证据；不因生成汇总、交接或独立验收而重复运行，不建立另一套自动重跑或缓存调度机制。必要复查只针对实际改动、具体失败或证据缺口。真实模型、重型集成和设备效果的结论不由本 Spec 的受控通过替代。

## 验收标准

- [ ] 现有测试有归属和可执行入口；迁移／合并／退役保留理由、有效断言与引用，无意外漏测或重复测试。
- [ ] 新检出仓库按文档准备依赖后，能重建合成输入并运行所选套件，不依赖历史私有产物。
- [ ] 首批功能组均有映射与真实执行状态；关键业务闭环完成页面操作、持久化和刷新读回。
- [ ] UI 外观与交互分别验证，电脑／窄屏和主题证据可查看；支持范围外平台如实列出。
- [ ] 普通套件无真实模型调用；受控响应、业务 API 拦截和完整流程边界标记准确，eval 专属入口归属清楚。
- [ ] 环境归属、权限、幂等、来源、并发与清理保护通过相应检查，不接触日常或生产数据。
- [ ] 缺依赖、提前退出、零发现和必需跳过不会产生虚假通过；能从汇总定位到原始失败。
- [ ] 项目级入口和新增完整回归仅本地手动执行，无新增 CI 接入或自动重复运行；汇总不重新执行已完成的检查。
- [ ] 日常 CI 不启动完整业务测试、数据库和推理／转换依赖；轻量构建可在干净环境执行，平台专项只按明确选择启动。
- [ ] `CI required` 与实际任务条件一致，无失败／必需缺失被视为成功；部署保护保留，远端未实测时不宣称 CI 已通过。
- [ ] 一名实施 Agent 完成耦合修改，再由新的独立验收 Agent 验收；未执行平台或流程不写成全项目通过。
