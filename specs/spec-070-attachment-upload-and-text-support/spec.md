# Spec 070：附件即时上传与广泛文本支持

## 状态

已实施，独立验收通过。既有语音测试的六处类型错误已修复，Web 全量类型检查通过。定向检查与限制见 [验收报告](acceptance.md)。

## 背景

聊天搭子的“添加文件”使用固定后缀允许列表，无法选择并分析常见源码和配置文件。普通附件目前在点击发送后才逐个上传，上传等待与任务处理混在一次发送中。需要放宽文本支持，明确禁止格式，并让上传、发送和读取各自具有清晰的状态。

## 目标

- 支持广泛文本、代码、配置、未知后缀及无后缀文本文件，不维护穷举语言后缀的允许列表。
- 选择附件后立即上传，每个上传中的附件显示空心圆 loading；全部附件上传成功后才允许手动发送。
- 上传仅保存附件并执行必要的上传检查；文档内容读取仍在发送后进行。
- 格式不支持、上传失败、解析失败和部分可读均直接反馈到对应附件，用户不必依赖模型解释错误。
- 保留附件分析问答和将原始附件交给现有 Python 沙盒处理两种用途，不增加模型调用或重复读取。

## 非目标

- 不增加文件夹上传、压缩包解压、任意二进制分析、代码项目导入、多语言运行环境或联网安装依赖。
- 不增加独立文件库、跨设备草稿同步、RAG、病毒扫描服务、模型文件分类或额外内容审核阶段。
- 不提前解析文档、转写语音或执行 Agent 任务；不因选择附件创建消息或任务。
- 不修改现有附件数量、容量、语音时长、文本提取资源限制及沙盒执行预算。
- 不将文件选择器支持范围的调整表述为已查明 Windows 文件夹无法进入的原因。
- 不重做录音、工作材料上传、Electron 或生成文件导出格式；共用后端的调用方只做必要兼容。

## 当前行为

- 前端文件选择器和 `fileSelectionError` 限制 PDF、DOCX、PPTX、XLSX、TXT、JSON、MD、CSV 及现有图片、音频格式；`.py`、`.js` 和无后缀文本不能通过。
- 普通附件选择后保存 `File` 和本地 Blob URL；`useMessageSubmission` 在发送时逐个调用上传接口。HEIC／HEIF 点击“生成预览”有独立的提前上传路径。
- 上传接口创建未关联消息的附件。文档状态为 `unsent`，发送时改为 `pending`，worker 随后解析。图片标准化、音频格式／时长检查已有独立处理，不属于模型分析。
- 文本解析支持 UTF-8、带 BOM 的 UTF-16；JSON、CSV 有既有专用读取，TXT／MD 按行分段，其他后缀尚未进入通用文本读取。
- 附件卡片已有解析状态、错误和部分读取提示；沙盒通过受权限约束的文件引用接收原始文件。
- 后端已有超过 24 小时、未关联消息和工作材料的临时附件清理。草稿移除目前主要释放本地 Blob URL，没有专用的未发送附件删除接口。

## 目标行为

```text
选择／拖入／粘贴文件
  → 格式、数量、大小检查
  → 上传队列 → 附件空心圆 loading → 上传成功，等待发送
  → 全部附件上传成功 → 允许发送
  → 关联消息 → 现有文档读取／媒体识别／Agent 处理流程

发送前移除 → 取消对应上传，清理未发送的临时附件
未发送且被遗弃 → 沿用 24 小时过期清理
```

上传完成只代表服务器已保存文件，不代表内容已经可读；读取失败只能在实际读取后反馈。

## 功能需求

### 1. 文件支持与禁止范围

- “添加文件”不再用穷举后缀的 `accept` 限制可见文件；“添加图片”保留现有图片筛选。
- 文件选择、拖入和粘贴使用一致规则；前端快速提示，后端执行同样的禁止策略，不能仅靠浏览器限制。
- 附件仍分为现有文档、图片、音频类别。已知受支持格式走原有处理；其他未禁止类型作为通用文本候选，不根据浏览器 MIME 缺失或 `application/octet-stream` 一律拒绝。
- `.py`、`.js`、`.ts`、`.tsx`、`.vue`、`.go`、`.rs`、`.java`、`.sh`、`.bat`、`.ps1`、配置文件、未知后缀和 `Dockerfile` 等无后缀文件均可作为文本材料。
- HTML、SVG 等文本材料按源码读取、按附件下载，不直接作为活动页面或脚本渲染。上传代码不构成执行授权。
- 初始禁止列表如下。大小写归一，按完整文件名处理复合后缀；禁止项不能因伪造 MIME 进入图片或音频分支。

| 类别 | 禁止后缀 |
| --- | --- |
| 可执行程序、系统组件 | `.exe .com .scr .dll .sys .ocx .cpl .so .dylib` |
| 安装包 | `.msi .msp .msix .appx .apk .dmg .pkg .deb .rpm` |
| 磁盘、虚拟机镜像 | `.iso .img .vhd .vhdx .vmdk .qcow2` |
| 快捷方式、启动入口 | `.lnk .url .scf .pif` |
| 含宏 Office 文件、插件 | `.docm .dotm .xlsm .xltm .xlam .pptm .potm .ppam` |
| 编译产物 | `.pyc .pyo .class .jar .wasm` |
| 通用压缩包 | `.zip .rar .7z .tar .gz .tgz .bz2 .xz .zst .cab`，包含对应 `.tar.gz` 等复合后缀 |

- 已有旧版 `.doc`、`.xls`、`.ppt` 继续提示转换格式，区别于“禁止程序文件”。
- PDF、DOCX、XLSX、PPTX、现有图片和音频继续允许；不能将“禁止二进制／压缩包”解释成拒绝这些文件，尤其不能仅凭 ZIP 文件头拒绝 OOXML。
- 未识别的二进制文件不增加解析能力：未知后缀可能先上传成功，发送后若不能解码为文本，明确提示不支持读取，不伪装为空文件或读取成功。
- 保留原始文件和可用文件名；继续沿用安全存储名、权限、下载行为及资源上限，不用改后缀为 TXT 的方式丢失来源信息。

### 2. 即时上传与发送门槛

- 普通附件在加入草稿后立即进入上传队列，默认最多同时上传 2 个，避免批量文件无界并发。
- 每个附件独立记录排队、上传中、上传成功或上传失败。排队显示“等待上传”；正在上传的附件显示空心圆旋转 loading，成功即移除，不显示虚构百分比。
- loading 位于附件卡片内，不改变卡片尺寸、不遮挡移除按钮；图片、文档、音频采用一致状态语义。提供可访问状态，减少动态效果模式仍能辨识上传状态。
- 文档附件采用已确认的紧凑卡片：约 48px 高、164～168px 宽，缩小图标和内边距；窄屏适应可用空间，保留足够的触摸操作范围。文件名与状态文字单行省略，不撑宽卡片、不覆盖移除入口；完整文件名可悬浮或轻点查看。图片缩略图和录音试听保留各自已有展示。
- 有排队、上传中或上传失败附件时，手动发送按钮禁用，Enter 等提交入口遵守同一条件；不在点击发送后隐式排队等待上传。
- 上传时用户可继续编辑文字、添加符合限额的文件、移除附件。不能因上传把整个输入区锁死。
- 上传失败显示当前文件的简短原因及重试／移除入口；只重试失败文件，成功附件不重传。无无限自动重试。
- 上传成功后仅保存附件 ID，文档仍为未发送状态；不进行文本提取、ASR、OCR、语义分析或模型调用。保留现有上传必要的格式检查和媒体处理，不额外增加完整内容扫描。
- HEIC／HEIF 预览复用本次上传结果，不能再通过预览按钮重复上传；上传完成前使用现有本地可用预览或占位。
- 真正发送时仅提交已成功上传的附件 ID 和消息参数，沿用消息幂等机制；没有附件的消息发送不受影响。

### 3. 草稿移除与临时文件清理

- 移除排队项时直接出队；移除上传中项时取消对应请求，其他文件继续。若请求已完成或返回晚到，仍清理其未发送附件，不让文件重新出现在草稿中。
- 移除已上传项时调用专用临时附件删除接口，删除原文件及派生预览、转码文件等；本地 Blob URL 同时释放。
- 删除只允许操作本人、同公司且未被消息或工作材料等正式引用的附件。发送、绑定工作材料与删除必须采用一致的并发保护，不能检查后再误删刚刚绑定的文件。
- 删除可重复调用；物理清理失败需保留可恢复的清理记录，由后台继续处理，不能只删数据库记录而留下无法追踪的文件。
- 上传结果不明、页面关闭或网络中断留下的未发送附件，沿用 24 小时过期清理；不依赖 `beforeunload` 请求保证回收。
- 切换会话／页面保留现有内存草稿语义。上传结果只能写回所属账号与草稿；暂停后恢复不得重复上传成功文件。账号切换不能把旧账号附件带入新账号。
- 不新增刷新后恢复本地文件的承诺。过期附件再次发送时明确提示重新添加，不恢复已被清理的引用。

### 4. 发送后的读取与失败反馈

- 继续使用现有发送后文档解析流程；新增通用文本分支，复用现有隔离进程、解码、行定位、分段、缓存及资源上限。
- 普通源码只按文本读取，不编译、不检查代码语法、不执行；语法有误的 Python／JavaScript 仍可用于提问。JSON／CSV 等已有专用格式读取行为保持兼容。
- 编码支持沿用 UTF-8 和带 BOM 的 UTF-16。不能可靠解码、含不支持的二进制内容时返回明确失败，不静默替换乱码。
- 已知文档解析失败不降级到通用文本读取，不依次遍历无关解析器；不自动改用沙盒尝试未知二进制或解压禁止文件。
- 失败直接展示在对应已发送附件上，不等待模型生成说明；可识别的格式、编码、加密、损坏、资源超限分别使用清楚文案。未知原因只报告读取失败，不断言文件损坏。
- 错误中不暴露服务器路径、堆栈或内部凭证；部分读取必须继续标记“部分可读”，不能显示完整成功。
- 多文件中一份读取失败不取消其他文件处理。将成功、失败和部分读取的状态如实提供给 Agent；任务依赖缺失内容时说明限制，不声称已读取，也不反复调用同一失败读取。

| 情况 | 用户提示示例 |
| --- | --- |
| 禁止程序／安装包 | `暂不支持上传程序或安装包：setup.exe` |
| 压缩包 | `暂不支持压缩包，请解压后选择需要处理的文件。` |
| 上传网络失败 | `文件上传失败，请重试或移除。` |
| 编码不可读 | `文本编码暂不支持，请保存为 UTF-8 后重新上传。` |
| 未支持的二进制 | `该文件无法按文本读取，暂不支持此二进制格式。` |
| 无法确定原因的解析失败 | `文件读取失败，请确认文件可以正常打开，或重新导出后上传。` |

### 5. 两种文件用途与性能边界

- 分析问答继续使用文档分段和来源引用；新增文本材料与原有 TXT 走等价读取路径。
- 用户要求计算、转换或基于文件执行代码时，现有工具仍可将授权原文件传入 Python 沙盒，不以提取文字替代原文件，不增加模型路由轮次。
- 文件可上传不代表沙盒具备相应语言解释器；不承诺运行 JS／Java 项目，不扩展 Python 固定依赖和网络权限。
- 文字提取失败与原文件能否被既有工具处理是不同状态；不能因此虚报已读，或一律切断现有受支持 Office／数据文件的沙盒用途。禁止格式和未知二进制不新增沙盒兜底。
- 不增加模型调用、额外提示词审查、完整文件重复扫描或发送前读取；临时文件清理不阻塞正常消息处理。
- 提前上传只优化上传时机。验证分别记录上传耗时、点击发送后的耗时，不把用户输入期间完成的上传宣称为模型提速。

## 边界条件

- 覆盖一次选择多个、分批添加、删除后再添加、失败后重试、长文件名、无后缀、大写后缀、混合 MIME、相同文件名及超限文件。
- 正在发送的消息快照与后来编辑的草稿分离；网络超时后重试沿用已提交快照和幂等键，不误删可能已经提交成功的附件。
- 点击录音后保留在草稿的音频走附件上传状态。长按录音松手直发继续只发送本次语音，不混入原文字／附件、不先闪入待发送预览、不自动重试；只等待本次语音上传，不被其他草稿附件上传阻塞。
- 取消长按录音不产生上传；长按直发失败仍沿用简短提示并清理未提交临时附件。
- 账号失效、权限变化、重复删除、上传与删除响应乱序、发送与删除竞争均不能越权或破坏正式附件。
- 手机／钉钉 WebView 与桌面共用语义，窄屏中 loading、文件名、重试和移除不得互相覆盖。

## 技术约束

- 使用现有 React、CSS Modules、图标、请求入口和草稿管理；不新增上传组件库或全站状态框架。
- 扩展现有共享输入规则保存禁止列表，前后端读取同一策略；不在组件、接口、解析器各自维护不一致名单。
- 上传生命周期在 assistant 业务模块内集中管理，不能继续让页面、发送 Hook、预览组件各自发起同一文件上传。
- 继续保留后端身份／归属校验、文件存储隔离、解析进程资源限制和沙盒隔离；文件内容不作为业务授权。
- 需要新增未发送附件删除 API，实施按 S3 中涉及上传安全、权限和持久化清理的范围定向验证，不因此默认全项目验收。

## 兼容性要求

- 保持已有上传返回结构、附件类别、消息附件 ID、历史附件读取及下载兼容；不清理已发送或正式引用文件。
- 优先复用现有 `message_id`、`deleted`、创建时间与清理机制，不为前端上传状态单独新增数据库状态机。
- 老客户端的发送时上传仍可用；新前端使用即时上传。后端上线后再发布新前端，避免新格式被旧 API 拒绝。
- 原有媒体检查、HEIC 预览、录音直发、任务取消和已上传文件的发送重试保持有效。

## 验收标准

- [x] 文本、源码、未知后缀及无后缀样例可上传并在发送后正确读取；文件名、内容和行引用保留。
- [x] 前后端禁止列表一致；大写、复合后缀、伪造 MIME 不绕过明确禁止项；已有 PDF／Office／媒体正常使用。
- [x] 选择文件即上传，最多 2 个并发；每个上传项有空心圆 loading，完成消失，失败定位到具体文件。
- [x] 有排队／上传中／失败附件时，按钮及键盘均不能手动发送；仍可输入、添加、移除和单文件重试。
- [x] 附件卡片符合紧凑原型；长文件名和状态使用省略号，完整名称可查看，手机端重试和移除可独立操作。
- [x] 上传完成后没有文档提取、语音转写、消息 Job 或模型调用；只有发送后才进入任务处理。
- [x] 发送复用成功上传 ID，HEIC 预览和上传重试不重复上传已成功文件；无附件发送与长按直发保持原语义。
- [x] 移除可取消上传并清理临时文件，晚到响应不复活附件；正式引用、其他账号和其他公司文件不能删除。
- [x] 删除与发送／工作材料绑定的竞争、清理失败恢复及 24 小时过期回收均有定向证据。
- [x] 解析／读取失败直接显示，部分读取不伪装完整成功，混合文件不因单份读取失败整体中止。
- [x] 新文本文件可作为现有 Python 沙盒输入；不新增语言运行能力、工具循环或模型调用。
- [x] 完成相称的桌面／手机交互验证与上传／读取耗时对照；明确区分模拟、真实解析、真实沙盒及未验证项。

## 待确认问题

无。上传阶段不提前读取；临时文件过期沿用现有 24 小时规则；首版不支持通用压缩包与未识别二进制分析。
