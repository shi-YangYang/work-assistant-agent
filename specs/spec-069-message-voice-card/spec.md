# Spec 069：已发送语音卡片

## 状态

已完成，播放器实施经独立验收 PASS；紧凑布局调整经定向测试与浏览器验证通过。采用自定义播放条，将语音转写与修正入口放进同一行；桌面与手机共用组件。真机验证限制见 [验收记录](acceptance.md)。

## 背景

已发送录音使用浏览器原生播放器，外观、控件和尺寸随浏览器变化。语音文字与修正入口另占一个区域，与录音缺少明确的整体关系。

## 目标

- 自行封装轻量音频播放器，以统一、紧凑的语音卡片展示已发送录音。
- 将播放、查看转写和修正文字放在同一组件内，减少分散的操作区域。
- 保留现有播放、转写、修正权限和消息处理行为，不增加 Agent 等待时间。

## 非目标

- 不改输入框中的待发送录音试听、录音按钮、长按发送或失败提示。
- 不增加语音通话、自动播放、倍速菜单、音量菜单、波形分析或逐字音频定位。
- 不修改 ASR、Agent 提示词、模型调用、上传／转码流程、API 或数据库。
- 不把本次重做扩展到 Electron、工作详情及全站所有音频播放器。

## 当前行为

- `MessageCard` 按音频、图片、文档分类显示附件；音频通过 `<audio controls>` 播放，来源优先使用 `previewUrl`，否则使用 `url`。
- `MessageTranscript` 独立展示“语音文字”和“改文字”，正文默认收起。
- `WorkMessage.transcript` 与 `transcriptRevision` 属于整条消息；一条消息的多段音频共用一份转写，并无逐附件转写字段。
- `TranscriptEditor` 使用项目的 React 弹窗，通过现有修正接口提交文字与预期版本；仅本人消息显示修正入口。
- 已有附件数据包含可为空的时长。待发送试听已有单独组件，本次保留。

## 目标行为

单段语音的布局：

```text
┌─────────────────────────────────────────────┐
│ ▶ ━━●━━━━  0:05 / 0:26  转文字⌄ 改文字 │
│ 展开后的语音转写，默认收起                    │
└─────────────────────────────────────────────┘
```

一条消息有多段语音时，使用一张轻量卡片，每段独立一行、播放区等宽排列，行间仅留小间距，不再分别套胶囊外框。卡片底部统一放置一组“转文字／改文字”；展开的文字按消息整体展示，不伪造音频和文字的逐段对应关系。

## 功能需求

### 1. 自定义播放条

- 使用自定义 React 控件替代可见的原生 controls，底层继续使用浏览器音频能力。
- 常态显示播放／暂停、可拖动进度条及当前时间／总时长，不放浏览器自带的多余菜单。
- 点击播放后，按钮与实际媒体事件一致；等待缓冲时有轻量反馈，播放完成后可重新播放。
- 支持鼠标、触摸及键盘调整播放进度；未知时长或不可定位时禁用进度操作，不能显示 `NaN`、`Infinity` 或虚假进度。
- 有有效附件时长时直接显示；实际媒体时长就绪后校正。时长未知时显示 `--:--`，播放与转写入口不因等待时长而整卡阻塞。
- 同一聊天中的已发送语音播放器同时最多播放一段。开始另一段时暂停上一段；组件卸载、音频来源变化或离开会话时停止对应音频并清理监听。
- 播放被浏览器拒绝、网络失败或格式不支持时，在卡片内显示简短提示，保留用户主动再次播放的入口，不循环重试，不重新发送消息。

### 2. 文字与修正整合

- 单段语音中，播放、进度、时长与“转文字”“改文字”位于同一行；多段语音的文字操作移至共用卡片底部。修正入口在正文收起时也可见，不依赖鼠标悬浮。
- 点击“转文字”直接在卡片内操作行下方展开，再次点击收起；继续默认收起，展开与播放互不重置。
- 无转写时保留现有等待识别反馈；转写异步返回时更新内容，不打断播放。单纯音频加载失败不能显示成识别失败。
- 点击“改文字”复用现有 React 编辑弹窗；打开时暂停当前卡片音频，关闭后不自动恢复播放。
- 沿用修正接口、版本冲突处理、长度限制和允许清空文字的行为。保存成功刷新卡片内容，保存失败保留编辑内容并在弹窗内反馈。
- 本人消息允许修正；其他人的可见消息仅提供播放与查看文字，不能因组件封装新增编辑权限。
- 有历史转写、但没有音频附件的消息仍能查看与按原权限修正文字，不渲染空播放条。

### 3. 视觉与布局

- 沿用 Noria 中性灰、主题变量和 Lucide 图标；柔和底色、轻边界和胶囊圆角，展开时收紧圆角，不再叠加一张独立转写卡。
- 卡片对齐用户消息右侧，折叠状态桌面建议宽约 360px，手机最大宽不超过可用区域；不铺成整行大播放器。
- 单段播放区和文字操作区同排，多段播放行使用小间距；播放图标 14px、可见底色 28px，手机触摸目标至少 44px，不为缩小卡片牺牲操作面积。
- 多段音频通过独立播放行区分，可访问名称包含“语音 1／2／3”，原文件名保留为辅助信息；不额外增加文件名或编号标题行。
- 长转写自动换行并限制展开区高度，允许内部滚动；长文件名、长时长和窄屏不能挤出进度条或修正按钮。
- 浅色、深色、手机与桌面均可读；有明确键盘焦点，播放按钮和进度控件有名称，展开状态可供辅助技术读取。
- 不引入持续装饰动画；遵循减少动态效果设置。

## 边界条件

- 覆盖单段、多段、文字与音频混发，以及音频与图片／文档混发；其他附件及原文字气泡保持原有展示。
- 多条历史消息、分页加载或任务反馈刷新不能自动播放、重置仍在使用的播放器或重复下载整段音频。
- 以稳定消息／附件 ID 标识组件；同一 ID 的来源确实变化时才重置该播放器。
- 已有会话刷新后直接使用同一组件显示，播放状态无需跨刷新保存；转写按服务端保存内容恢复。
- 保留既有媒体访问鉴权与资料不可用规则，不通过外链或新的读取通道绕过权限。

## 技术约束

- 公共 `AudioPlayer` 只处理媒体播放和展示，不导入 assistant 业务模块或直接请求转写接口。
- 消息语音组件负责组合播放器、转写和现有编辑弹窗；状态在组件内就近管理，不扩大 `MessageCard` 职责。
- 使用 React、CSS Modules、现有图标与弹窗，不新增音频／波形依赖。
- 保持现有附件播放 URL 选择方式；优先用附件时长渲染，音频按播放需求加载，不为绘制进度批量下载、解码或转码历史录音。
- 不新增 ASR／模型调用、轮询、上传请求或消息发送前置步骤。播放进度更新不触发整个消息列表和输入区刷新。

## 兼容性要求

- 历史录音与新录音共用展示组件，现有媒体格式和预览地址继续生效，不需要数据迁移。
- 长按只发送本次语音、保留原草稿，以及点击录音后手动发送的行为继续生效。
- 本次只修改已发送语音呈现；已有修正后的业务处理语义不改变。
- 钉钉 WebView、Android 浏览器和 iOS Safari 的真实播放兼容性与浏览器模拟结果分别记录。

## 验收标准

- [x] 已发送音频使用自定义播放条，播放／进度／时长与文字入口位于同一张卡片内。
- [x] 定向用例及桌面浏览器验证播放、暂停、定位、结束重播、缓冲和失败；未知时长无异常数值，键盘和点击进度有效。真实触屏拖动未验证。
- [x] 多条消息之间播放互斥；转写更新不打断播放，离页／卸载后音频停止。
- [x] 单条消息多段音频仅一组文字入口；无音频的历史转写仍可访问。
- [x] 文字默认收起，展开可读；本人可修正、其他人不能修正，保存、清空、冲突与失败行为保留。
- [x] 320／390px 手机视口与桌面、浅／深色下无横向溢出、重复边框或明显大块空白。
- [x] 混合附件与历史转写组件回归通过；草稿发送模块未修改，未重复执行其整套测试；不增加 Agent 请求或等待环节。
- [x] 完成相称的组件和消息集成检查、浏览器播放及视觉验证；未执行的真机项记录在验收文档。

## 待确认问题

无。采用简洁进度条、文字默认收起、多段音频共用文字区。
