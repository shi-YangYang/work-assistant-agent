# 沙盒内置工具与统一执行

## 状态

已完成，独立验收通过。

## 背景

沙盒已经能运行 Python，并预装数据分析、绘图和文档库，但常见任务仍需 Agent 重写文件读写、中文字体、分页和排版代码。只封装 Python 库仍要求模型写代码，应进一步提供结构化工具入口。内容理解与计算规则仍由 Agent 根据用户要求完成。

## 目标

- 常规表格、图表、文档和演示文稿任务直接传结构化参数，无需模型编写 Python。
- 工具具备明确输入、输出与错误说明，便于组合和修正。
- 保留 `run_python` 处理自定义计算与特殊任务；两类入口共用执行服务、沙盒隔离和私有成果交付。

## 非目标

- 不另建执行服务、队列、重试体系或前端工具入口。
- 不增加联网、动态安装依赖、任意格式转换和复杂模板编辑器。
- 不封装全部 pandas 方法，不内置公司业务规则，不替代工作与汇报工具。
- 不保证任意知识问答正确，也不将文件可读视为排版已通过视觉检查。

## 当前行为

- Agent 通过 `run_python` 提交代码，每次在独立容器执行；`read_execution` 可读取本会话已有执行记录。
- 已安装 pandas、numpy、openpyxl、matplotlib、python-docx、python-pptx、ReportLab、Pillow、pypdf，以及 LibreOffice、Poppler 和中文字体。
- 已有输入授权、资源限制、输出格式校验和私有文件保存；这些是执行保障，不是供 Agent 复用的高层操作。
- 还没有统一的表格导出、中文绘图、文档排版或 PPT 生成工具库。

## 目标行为

Agent 直接调用表格、图表、文档和 PPT 工具，提交经过 schema 校验的参数。统一执行服务授权输入并提交结构化任务，沙盒通过固定工具注册表调用 `noria_tools`。内置任务不经过 `run_python`，也不把参数拼接成动态代码。

`run_python` 是并列的通用入口，用于特殊计算、实验和内置工具无法表达的处理。它继续在相同隔离环境运行，也可以复用 `noria_tools`。

例如“把这份计划生成 PDF”直接调用文档工具；“按我的特殊规则汇总销售表再画图”可先用 Python 计算，将实际结果保存为文件，再通过真实成果引用交给绘图工具。工具不擅自删除重复行、补齐金额或改变统计口径。

## 功能需求

### 1. 首期工具

| 类别与模型工具 | 范围 | 输出与限制 |
| --- | --- | --- |
| 表格：`inspect_table`、`export_table` | 查看 CSV/XLSX 的列、类型、缺失、重复情况和有限样本；导出明确的数据 | 编码、工作表和类型可指定；大表不整表回传给模型；XLSX 提供表头、冻结首行、筛选和有上限的列宽 |
| 图表：`create_chart` | 柱状图、折线图 | 输出 PNG；支持中文标题、坐标轴、单位和图例；不自动聚合数据或改变数值 |
| 文档：`create_document` | 标题、段落、列表、表格、本地图片 | 输出 DOCX/PDF；处理换行、分页与中文字体；PDF 嵌入字体 |
| 演示文稿：`create_slides` | 标题、要点、表格、本地图片组成的简单页面 | 输出可编辑 PPTX；长内容拆页或明确报错，不静默裁切 |

首期采用固定尺寸、简洁的黑白灰样式，支持标题与坐标标签；不增加配色面板、模板市场或复杂样式系统。

### 2. 结构化入口与内部工具库

- 每个模型工具提供有类型、枚举和长度限制的参数；工具名由所调用的函数确定，不接受模型指定模块路径、函数路径或表达式。
- 文件参数使用附件或成果的真实引用，由业务服务授权并映射为本次输入标识；不要求模型猜测宿主路径。少量内联数据允许直接传入，但必须有请求体、行数与内容长度上限。
- 文档和 PPT 接收结构化内容块，不在工具内部再次调用 LLM。
- 两类入口可通过已有成果引用组合；不依赖跨次执行保留 Python 变量、临时路径或共享文件。
- runner 的内部工具库返回结构化结果、检查和警告；参数无效时给出可修正的错误。它不生成下载 URL 或公司业务回执。
- 先写临时文件，成功后放入 `/work/output`；不将半成品留作成功成果。
- 工具库按需导入，仅在 runner 加载重依赖；业务 API 和控制服务只做请求校验、调度与结果处理。

### 3. Agent 使用方式

- 首期注册上述五个模型工具，内部字体、路径和排版辅助函数不暴露为模型工具。
- 常规任务优先使用结构化工具，自定义任务使用 `run_python`；两类执行均可通过 `read_execution` 查阅历史结果。
- 无需运行的问答、写作任务继续直接回答，不先调用沙盒获取工具目录。
- 沙盒未启用时，两类执行工具统一从可用工具中移除，并在调用边界拒绝；历史成果和执行记录仍可读取。
- 出错后沿用已有执行反馈和有限修正流程，不增加另一套重试。读取历史结果优先使用 `read_execution`。
- 现有任务节点显示“检查表格”“生成图表”“生成文档”等实际操作；等待资源、重试、中断仍使用已有状态机制。
- 只有执行成功、文件通过服务端检查并保存后，才告知用户成果已生成并提供真实下载入口。

### 4. 统一执行与记录

- 扩展现有私有协议，支持互斥的 Python 任务和内置任务。内置任务包含固定工具标识、协议版本和参数；旧的 `code` 请求继续可用。
- 新增内置请求快照字段，记录工具、版本与参数；保留旧代码字段和历史记录。不能把结构化参数冒充模型编写的代码。
- 幂等身份纳入任务类型、工具版本、规范化参数、授权输入及现有任务归属；重复提交恢复原回执，参数或输入变化产生新执行。
- `read_execution` 能区分执行类型，读取实际参数、结果、错误和成果；返回内容有长度限制及明确的截断／续读信息。
- 两类任务共用队列、资源限额、取消、租约、配额和成果版本。内置工具失败不能自动改走宿主机执行或无限重放。
- 表格检查等无文件任务只返回执行结果；不产生空成果卡。文件交付沿用现有私人成果和下载权限。

### 5. 安全与部署

- 工具库只装入 runner 镜像；业务 API 和沙盒控制服务不加载这些重依赖。
- 内置请求只分派到白名单中的固定实现；不使用 `eval`、动态导入模型给定路径，或将用户内容拼接为 Python／Shell 命令。
- 使用现有输入授权、输出检查、配额、取消、幂等和成果版本机制；工具返回值不能绕过这些机制。
- 读文件限制在本次执行的输入和工作目录，输出限制在 `/work/output`；拒绝越界路径。镜像内字体通过固定资源路径读取。
- CSV/XLSX 中用户提供的公式样式文本默认按文本保存；不执行公式，也不声称已经重新计算 Excel 公式结果。
- 不增加网络访问、宿主机目录挂载或凭证传递；公司写入仍受原有权限约束。
- 保持现有 CPU、内存、并发和文件限额，适配当前 4 核 8 GB 服务器。更新镜像随正常部署完成，不在用户请求中安装工具库。

## 边界条件

- 空表、缺列、混合类型、无效数值和乱码明确反馈；账号、编号等字符串可保留前导零。
- 超长标题、大表格、长段落和超高图片必须换行、分页或失败，不悄悄丢内容。
- 缺失字体或依赖给出环境错误，不能返回虚假的成功文件。
- 未知工具、协议版本、冲突的任务类型、超长参数和不存在的输入引用明确拒绝，不静默改成 Python 执行。
- 图片引用只能来自授权输入或本次生成的本地文件；不从远程地址下载图片。
- 新工具库的路径检查是便捷接口约束，真正的安全边界仍是容器隔离与服务端授权、校验。
- 文件能打开、PDF 字体已嵌入与视觉排版正确分别说明，不合并成笼统的“全部验证通过”。

## 技术约束

- 沿用 Python 3.12 与当前已安装的库，首期不新增大型依赖。
- 工具库按表格、图表、文档、演示文稿分模块，公共部分只放路径、字体和结果结构。
- 工具库不依赖公司后端，不包含数据库、账号或业务操作逻辑；业务服务只依赖轻量协议与参数模型。
- 子进程必须能从只读的镜像路径导入工具库，不依赖开发机环境或用户目录。

## 兼容性要求

- `run_python` 参数与旧沙盒代码请求保持兼容；成果 API 不变。执行记录新增可选的结构化请求，旧记录按 Python 类型读取，不改写历史代码和文件。
- 原有纯 Python 和第三方库代码继续可用；不要求所有任务使用新工具库。
- 先更新兼容旧请求的沙盒控制服务与 runner，再迁移数据库、更新业务服务。旧环境不支持内置请求时明确提示环境需更新，不无限重试或降级执行到宿主机。
- Web、Electron 现有功能和公司业务权限不变。
