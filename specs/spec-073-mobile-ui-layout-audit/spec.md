# Spec 073：手机端全量 UI 排版与交互检查

## 状态

审计已完成，独立交付验收 PASS；后续授权的 8 项问题／设计观察已修复并通过独立验收。原审计基线为 `b9afe2ad8d41082008f8dea46ad0673bbf577d16`，原证据保存在 `artifacts/spec073/20261017-015130-b9afe2a/`，修复对照保存在 `artifacts/spec073-fixes/20261017-mui-repair/`。见 [原报告](report.md)、[原问题清单](issues.md)、[修复结果与前后图](repair-report.md)及 [修复独立验收](repair-acceptance-final.md)。真机等未验证范围继续保留，不宣称手机端产品全量通过。

## 背景

手机端近期调整了导航、输入框、语音、附件、图片、通知及报告详情。局部组件测试难以发现真实使用中的遮挡、留白、换行、弹层位置和连续操作问题，需要对当前 Web 产品做一次完整的手机视觉与交互审计。

复用 [Web 全量测试](../spec-068-web-comprehensive-testing/spec.md)的资产和 [AGENTS.md](../../AGENTS.md) 的完整用户流程要求，但本次重点是手机 UI 排版和实际操作体验，不重新开展后端、模型质量或压力全量测试。

## 目标

- 覆盖匿名、员工、管理员的所有可达页面、主要子页、详情、弹窗、抽屉和状态入口。
- 实际操作后截图并逐张审阅，发现视觉层级、信息密度、对齐、截断、按钮位置和遮挡问题。
- 检查连续操作、长内容、异常和恢复，确认用户能完成任务，不以单张截图或 DOM 存在代替可用性。
- 交付可复现、有证据、有优先级及具体设计建议的问题清单，明确未覆盖和环境限制。

## 非目标

- 审计期间不修改产品源码、提示词、模型配置、接口、数据库结构及业务规则；只补检查脚手架和合成测试数据。
- 不重做视觉品牌，不引入新 UI 库，不恢复已删除的菜单或功能。
- 不重跑 Electron、完整服务端测试、部署、压力测试或真实模型性能对照；不增加 Agent 的运行时步骤。
- 不在生产环境创建、删除或修改员工资料，不发送真实公告，不操作员工聊天及文件。
- 不声称浏览器设备仿真等同于真实手机或钉钉容器。

## 当前行为

- Web 使用 React、CSS Modules 与现有公共弹窗；手机导航是抽屉，系统设置切换为二级菜单。
- 宠物默认隐藏，用户可以显示；显示时沿用全站悬浮方式，不给报告页额外占位或移动宠物。
- 报告详情已有独立返回栏、紧凑元信息和手机底部操作栏。本次仍检查其与其他页面的一致性及可达性。
- 手机输入区有文字／录音模式及“＋”面板，附件即时上传，录音手势、转文字、改文字和图片预览各有独立状态。
- 旧设计文档和历史截图有部分已过期描述，例如侧栏品牌、通知入口和宠物默认显示。以当前用户确认的产品行为为准，不能据旧文档判定回归。

## 目标行为

建立“页面／子页 × 角色 × 状态 × 设备条件”的覆盖表。每项有前置数据、操作、预期、实际结果和证据，使用 `PASS / FAIL / BLOCKED / NOT_RUN / N/A`；不适用须说明原因。

检查结论分为两层：

1. **审计交付**：清单是否完整，截图是否实际审阅，问题是否可复现，缺口是否如实记录。
2. **产品表现**：哪些流程通过、有哪些问题、哪些仍无法确认。存在失败、阻塞或未执行时，不宣称手机端全量通过。

## 功能需求

### 1. 覆盖盘点

- 从 `App`、`AppRoutes`、导航、命令搜索和各业务入口核对实际路由；不能只检查左侧菜单可见的页面。
- 包含动态详情、编辑、只读／历史版本、兼容重定向、权限限制、深链刷新及未知路径恢复。
- 各页所有适用 Tab、筛选器、更多菜单、弹窗和抽屉都分配用例；管理员与员工有差异的布局必须分别检查。
- 初始范围见 [检查矩阵](test-matrix.md)，实施时补全到实际控件与场景；发现遗漏先补清单，不能默默缩小“全量”。

### 2. 手机与浏览器矩阵

| 层级 | 条件 | 范围 |
| --- | --- | --- |
| 主基线 | 390×844 CSS px，Chromium，触摸、无悬浮，浅色 | 所有适用角色、页面、子页、主要弹层和关键状态 |
| 窄屏 | 320×568、360×800 | 全部页面／子页至少一项代表数据；关键弹层、表单、工具栏和长标题重点展开 |
| 宽手机 | 430×932 | 输入、列表、报告、团队、模型管理及共享弹层；检查不合理放大和空白 |
| 低高度／横屏 | 390×480、844×390 | 输入、导航、长弹窗、底部操作和滚动；缩小视口只作为低高度模拟 |
| 主题与字体 | 深色、系统主题切换、200% 文本放大 | 全部页面与共享弹层检查深色；字体放大检查导航、表单、消息和详情，允许合理换行 |
| 浏览器兼容 | WebKit 手机视口 | 登录、导航、聊天输入、上传、语音状态、弹层、报告编辑／提交、预览等关键完整流程 |
| 真机／内嵌容器 | Android Chrome、iOS Safari、钉钉 | 有设备时验证软键盘、地址栏伸缩、安全区、录音权限和返回；无条件则逐项标记未验证 |

不机械展开所有笛卡尔积。复用检查需写明共享组件依据；不同布局、不同角色内容不能用一张截图代替。浏览器、视口、触摸配置和主题必须写入证据。

### 3. 排版与产品设计审阅

- **层级与密度**：标题、Tab、统计、筛选、内容和主操作顺序清楚；查找无用途的大空白、重复信息、过大的控件及首次可见内容被挤出首屏的情况，结合页面任务判断，不规定所有页面相同高度。
- **对齐与尺寸**：页面边界、列表起始线、字段和操作对齐；卡片内按钮不随描述长短漂移；手机控件使用明确的触摸区域，主要触摸目标按项目约定至少 44px。
- **文本与内容**：长中文、长英文、URL、文件名、姓名、日期与数字能换行或省略；重要操作和错误原因不能被截掉；全文仍有合适的查看路径。
- **滚动与定位**：页面不出现意外横向滚动；表格／代码的局部横滑有明确范围；固定操作不覆盖末尾内容；背景与弹层滚动互不抢占，关闭后恢复阅读位置。
- **浮层与触摸**：弹层完整位于可视区域，关闭、确认、取消可触达；手机不依赖 hover 显示关键按钮，控件不互相遮挡或误触；聚焦和关闭后的焦点恢复合理。
- **状态与动效**：等待、上传、生成、加载、成功、失败、取消清楚区分；检查首次打开、切换和恢复时的闪烁、布局跳动、双重 loading、按钮漂移与长时间空白。动态场景使用连续截图或短视频，不能靠静态截图判定。
- **可读性与一致性**：浅／深色下正文、辅助文字、禁用、错误可辨识；相同操作命名、图标、间距与主次关系一致，逐页给出具体原因而不是泛称“不好看”。

宠物显示／隐藏都检查，但“显示后没有额外留白”是已确认行为，不作为缺陷。若悬浮宠物确实遮挡不可替代的操作，记录具体条件和候选方案，不擅自恢复报告页特殊占位。

### 4. 完整流程与边界组合

- 从正常 UI 入口逐步操作，保留中间状态；直达 URL 和注入状态只补充边界，不替代完整流程。
- 重点覆盖：多批混合附件 → 删除／重试 → 发送 → 回复与成果 → 刷新／切页回来；文字草稿 → 长按录音 → 上滑取消或松手发送；工作／报告 → 编辑 → 校验失败 → 保存／提交 → 返回原会话；通知 → 已读／详情 → 返回。
- 附件覆盖同名、超长名、不同尺寸图片、多个音频、失败与成功混合、多批累计超过单次上限；保持当前限制及去重语义，验证的是展示、提示和操作结果。
- 表单覆盖未填写、校验错误、保存中、失败后重试、长选项、禁用与只读；列表覆盖空、单条、多页、无搜索结果及删除末项后的状态。
- 使用可控延迟、断网／恢复、图片加载失败、会话完成／中断等条件观察 UI；不停止共享服务，不做数据库或宿主故障注入。
- 页面缺陷之外，记录完整操作的最终结果。浏览器拦截响应仅能证明受控 UI 行为；写入后刷新、文件上传、取消及恢复的真实链路使用隔离 API 数据验证，无法执行时单独列出。

### 5. 截图与问题交付

- 每个适用页面／主要子页至少一张主基线截图；长页面保留首屏和滚动到操作／末尾的视口截图，必要时附全页图。全页拼图不能证明固定按钮或真实可视高度正确。
- 每张截图有审阅结论，记录检查者、用例编号、角色、尺寸、主题、状态、数据来源和问题编号。缩略图总览用于定位，疑似问题必须查看原尺寸。
- 弹窗、抽屉、更多菜单等打开态也必须检查；不通过隐藏元素、缩小全页或关闭动画来掩盖问题。静态截图可冻结无关动画，动效专项保持真实动效并单独检查减少动态效果。
- 缺陷分为 P0 阻断关键任务／无法退出、P1 明显遮挡或高频误操作、P2 排版与阅读问题、P3 一致性细节；设计偏好与可复现功能缺陷分别标注。
- 每项包含：影响页面和角色、最小复现、预期／实际、截图／录屏、影响说明、疑似根因、最小修复建议及相邻回归范围。同根因可合并，但保留所有受影响入口。
- 交付 `report.md`、`issues.md`、覆盖结果和截图索引。先汇总全部问题，再讨论修复；不会因审计而增加 Agent 提示词或模型往返。

## 边界条件

- 使用合成账号和脱敏数据。浏览器响应夹具必须覆盖业务 API、使用假凭据；真实写入只指向确认归属的隔离测试环境。
- 未开放的云搭子仅检查禁用态；权限不允许的页面检查合理拦截，不为截图绕过产品权限。
- 真机软键盘、实际钉钉权限和录音硬件不是缩小视口、设置 User-Agent 或模拟媒体流能证明的；保留明确限制。
- 外部服务未配置时检查产品现有提示，配置齐全态可由受控数据补充，证据标明来源。
- 严重问题阻断某条流程时，保留失败与后续受阻项，继续独立分组；不重复重跑到绿。

## 技术约束与兼容性要求

- 文档阶段 S0，仅检查内容、diff 与引用；不为写 Spec 运行测试或构建。
- 实施使用现有 Playwright 和 CSS／DOM 几何检查，并实际审阅截图；审计脚本不进入业务运行时。
- 基线冻结为实施时 SHA、工作区差异和实际运行版本；报告页提交 `b9afe2a` 仅作为规划参考。
- 不改变默认 CI，不把整站截图加入每次提交；不覆盖 Spec 068 等历史证据。
- 保持当前 Agent 速度、调用次数和业务数据语义；若后续修复涉及这些路径，单独确定验证范围。
