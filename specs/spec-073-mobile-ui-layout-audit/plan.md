# Plan：手机端全量 UI 排版与交互检查

## 对应 Spec

[规格](spec.md)、[检查矩阵](test-matrix.md)。本计划只实施检查与报告，产品修复不在本阶段。

## 涉及模块

- `apps/web/src/app/`：路由、角色、侧栏、全局浮层与宠物的覆盖依据，只读盘点。
- `apps/web/src/features/`、`components/`：业务页面、弹层和共享布局的行为依据，只读盘点。
- `tests/e2e/web/`、`scripts/company/web-acceptance/`：复用隔离环境、合成材料、浏览器登录及截图工具；只补确实缺少的 UI 检查能力。
- `specs/spec-073-mobile-ui-layout-audit/`：范围、矩阵、结果和问题；`artifacts/spec073/` 保存实际证据，不入 Git。

## 实施顺序

1. **冻结清单**：记录 SHA、差异、浏览器版本、实际运行服务与测试数据归属；从路由和控件展开矩阵的子项，写清预期和禁止结果。
2. **准备可重复场景**：正常流程使用隔离服务与合成账号；受控响应用于加载、错误、极长内容和异步状态。仅在受控页面请求被完整隔离时复用现有 Vite，不能把写入漏发到日常 API。
3. **基础页面遍历**：员工、管理员、匿名分开执行主基线；每次由真实入口操作到页面、子页和详情，再截图、记录几何结果及视觉审阅。
4. **弹层与连续流程**：执行矩阵中的完整旅程，覆盖输入、附件、录音、图片、报告、通知和设置。保留起点、中间状态和最终结果，必要时录屏。
5. **边界与兼容**：补窄屏、低高度、横屏、深色和文本放大，运行 WebKit 的关键流程；真机无条件则标明，不扩大为无关整套后端测试。
6. **汇总问题**：逐项审阅原图，合并共同根因，整理优先级与具体排版建议；保留首轮失败，不修改产品源码。
7. **独立验收**：实施 Agent 交付后，新的独立验收 Agent 核对路由覆盖、视觉结论、证据链接和受阻项；只复验报告缺口或具体争议，不重复全套通过场景。

文档由主 Agent 完成；进入实施后按项目规则安排检查实施与独立验收。角色页面可在独立浏览器上下文中运行，共享合成数据写入场景串行，避免互相污染。

## 数据流与证据

```text
当前路由／角色／控件清单
  → 用例、合成数据、预期与基线
  → 浏览器正常入口和连续操作
  → 页面截图、局部尺寸、录屏、最终 UI／隔离 API 结果
  → 逐项视觉审阅、覆盖结果、问题建议
  → 独立验收及交付
```

- 每例保留 `caseId / role / route / viewport / browser / theme / state / dataMode / result / evidence / issues`；每张图补 `reviewedBy / visualVerdict / notes`。
- `dataMode` 区分 `isolated-api` 和 `controlled-ui`。复用共享组件结论时记录来源用例，不复制成实际执行记录。
- 截图命名包含用例、角色、尺寸、主题和状态；运行目录包含唯一 run ID，保留失败原图及后续复现，不覆盖历史证据。
- 日志只记录所需请求路径、状态与时间，不保存 Cookie、授权头、密钥或员工数据。

## 检查工具与执行约束

| 方法 | 用途 | 限制 |
| --- | --- | --- |
| Playwright 现有浏览器设施 | 页面、触控、滚动、截图、短视频、控制网络 | 单独选择本次用例，默认零重试，不触发全部旧 E2E |
| 几何与可见性断言 | 意外横向溢出、控件遮挡、固定按钮、触摸区域 | 合法表格／代码横滑、暂时离屏及隐藏菜单不误判 |
| 原尺寸截图审阅 | 信息层级、留白、密度、对齐、视觉一致性 | 不能用自动截图成功代替设计判断 |
| 隔离 API 与真实浏览器流程 | 上传、保存、提交、刷新和恢复后的 UI 结果 | 模型可受控，不绕过实际受检数据流，不调用生产写接口 |
| 真机人工清单 | 软键盘、钉钉容器、安全区、系统录音权限 | 缺设备不宣称完成，可作为明确保留的验收缺口 |

既有 `apps/web/playwright.config.ts` 带有旧 Spec 输出参数与桌面默认项目，不能直接用默认命令产生“本次手机验收”结论。实施时为本次用例提供显式手机配置、独立输出位置和手动运行入口；准确命令写入报告，不在文档中虚构已存在的一键脚本。不得改变现有日常 CI 的范围。

文档阶段仅做 S0 diff／引用审查。检查阶段按用户要求全量覆盖手机界面；新增检查代码按项目配置格式化并做对应最小检查。既有通过用例不重复；失败只复现相关分组。

## 风险与处理

- **全量只有截图数量**：清单必须覆盖角色、子页、弹层、过程与最终结果，每张图有判断。
- **旧夹具掩盖现状**：基于当前 DTO、导航和组件读取；夹具不预先修正待查文案或布局。
- **慢资源让截图无效**：稳定态等待实际完成，加载态显式控制请求；布局动效另存序列，不混为稳定截图。
- **真机差异**：WebKit 仿真不等于 iOS／钉钉，报告分别说明。
- **视觉偏好当缺陷**：先检查当前确认的交互与页面目标，再写具体影响；宠物不占位、通知入口等沿用已确认行为。
- **产品阻断后假装完成**：记录失败和依赖受阻项，可用受控 UI 检查剩余视觉，但不能替代受阻的真实流程。

## 接口与迁移

无产品接口变化，无数据库迁移、部署或模型配置修改。仅可初始化和清理本次拥有的合成测试资料；日常 API、worker 与容器保持运行。
