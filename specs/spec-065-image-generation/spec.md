# Spec 065：独立图片模型与聊天图片生成

## 状态

已实现并通过定向独立验收：管理员独立分配图片用途，兼容模型按接口与尺寸配置接入，不再限制为一个型号；已有 Wan 配置保持兼容。原 Token Plan 同步接口与后续配置扩展各完成一次真实方图测试。原实现与验证见[实施报告](implementation.md)、[独立验收](acceptance.md)；配置扩展及其真实调用边界见[扩展报告](model-config.md)、[扩展独立验收](model-config-acceptance.md)。

## 背景

用户希望 Noria 具备图片生成能力，并能单独选择用于生成图片的模型。现有聊天模型负责理解、工具调用与回答，图片生成应有独立的用途分配，不能通过替换聊天模型完成接入。

## 目标

- 在现有模型管理中配置图片服务、选择图片模型，并独立分配给图片生成用途。
- 用户在聊天搭子中提出画图需求，Agent 调用图片工具，图片作为真实成果显示在会话中，可预览和下载。
- 复用现有任务、进度、成果、身份隔离与模型用量机制；不增加普通聊天的模型调用阶段。
- 防止重复工具调用、任务重试或恢复造成同一操作反复生成图片。

## 非目标

- 不自部署生图推理模型、不新增 GPU 或 Docker 服务，不通过沙盒安装绘图模型。
- 不做上传图片编辑、参考图生成、视频／音频生成、公开图库、复杂画布、局部蒙版编辑或批量海报工作流。
- 不要求聊天模型本身具备生图能力；图片理解、程序绘图与生成式图片分别处理。
- 不承诺任意生图协议通用；本次支持已实现的多模态同步和图片任务异步两种请求形状。兼容这些协议且返回 PNG 的模型可配置使用，其他协议需新增适配器。
- 不改动 Electron 会议功能、已有业务操作权限或普通聊天的人设和思考强度。

## 当前行为

- 用途分配仅有 `assistant`、`report`、`asr`；公司级路由和模型版本由数据库保存，任务冻结配置。
- 支持聊天及三种语音协议。前后端多处以“不是 chat 就是语音”判断能力，新增生图协议必须替换这些二分判断。
- 模型自动匹配目前明确排除已知生图模型；模型列表可发现一个模型，不代表系统已实现其调用协议。
- Agent 已有按需加载的工具目录、任务预算、操作回执、租约、取消与恢复机制。
- 沙盒可以生成 PNG 图表等文件，但没有调用图片模型的工具。
- 现有个人成果拥有文件、版本、鉴权下载和 PNG 预览。文件落在私有媒体目录，删除会话后的清理由既有任务处理。

## 目标行为

管理员配置公司共用图片模型，用户在聊天中自然使用，不新增普通用户的生图模型选择器。保留阿里百炼原生及 Token Plan 的 `wan2.7-image` 默认配置，同时允许管理员为其他兼容模型选择调用接口和尺寸规则；区域、服务地址和密钥由管理员配置，Token Plan 可复用已有服务。

1. 管理员在模型服务管理中添加服务及图片模型；必要时单独建立图片服务，使用独立 Base URL 和密钥。
2. 在“用途分配”增加“图片生成”，可以选择该公司的可用图片模型，或保持未配置；不自动跟随聊天模型。
3. 用户发送“生成一张简洁的咖啡店海报”等需求，聊天模型按需加载图片能力并调用工具。
4. 现有步骤区域显示“生成图片”，沿用已有秒数、状态稳定机制和宠物工作状态，不再增加重复提示条。
5. 图片保存成功后，会话显示图片成果、预览和下载入口。重新打开会话仍可访问，不依赖服务商临时链接。
6. 未配置或当前协议不支持所需操作时，明确解释当前能力，不伪造图片、下载地址或成功状态。

## 功能需求

### 1. 模型管理与用途分配

- 新增独立图片用途，内部建议使用 `image`。普通用户不能查看或修改公司密钥，沿用管理员配置权限。
- 图片协议显式声明生成能力；只有兼容该用途的模型才出现在选择列表。聊天、语音与图片的验证采用明确能力映射。
- 模型设置显示图片所需选项，不显示不适用的识别语言、聊天上下文、思考强度或文字流式开关；图片模型不继承用户的 low／high 设置。
- 首版默认每次一张，不启用连贯组图。尺寸按下节规则处理，其他未指定的适用选项沿用服务商默认值；不把聊天 low／high 映射为图片模型的思考设置。不给聊天输入框新增一排技术参数。
- 支持图片用途的配置测试：只有管理员主动点击测试时才发起一次生图请求，显示实际成功、拒绝或失败；保存配置、刷新模型列表不得自动生成。
- 服务移除、模型删除、配置版本冲突和用途解除绑定沿用现有规则。旧配置没有 `image` 时按未配置处理。
- 任务保存使用的图片模型版本，管理员中途更换模型不改变已经开始的生成请求；被撤销服务继续遵守现有失效规则。

### 1.1 尺寸与比例

产品交互采用“自动选择 + 自然语言指定”，不让用户面对长尺寸下拉列表，也不为每次生图强制弹窗。

- **分辨率**：未指定时沿用服务商 2K 默认，不在后台偷偷降为 1K。用户明确要求 1K 时使用对应档位；4K 超出本次模型能力，应在请求前解释并询问是否改用支持的尺寸，不偷偷换成 Pro 或放大图片冒充原生 4K。
- **尺寸优先级**：用户明确像素尺寸 > 用户明确比例 > 可识别的用途 > 无约束时默认方图。前两项互相矛盾时一次澄清，不擅自选一个忽略另一个。
- **常见用途**：头像／图标默认方形，电脑壁纸／横向封面默认宽横图，手机壁纸默认长竖图，未指定方向的竖版海报建议 3:4。用途映射是 Noria 的产品选择，不是模型限制；用户指定优先。

| 比例意图 | 用途示例 | 2K 档位发送尺寸 |
| --- | --- | --- |
| 1:1 | 头像、方图 | 2048 × 2048 |
| 16:9 | 横向封面、电脑壁纸 | 2688 × 1536 |
| 9:16 | 手机壁纸 | 1536 × 2688 |
| 4:3 | 横版插画 | 2368 × 1728 |
| 3:4 | 竖版海报 | 1728 × 2368 |

以上像素采用[官方文生图指南的推荐值](https://help.aliyun.com/zh/model-studio/text-to-image)，部分为近似比例，不承诺像素级精确构图。2K 在此是总像素档位，不是所有图片长边不得超过 2048。

- 模型提供比例／档位意图，后端用固定规则转换并验证 `size`，不增加一次专门算尺寸的模型请求。非预设但合法的明确比例按总像素预算计算宽高，计算后再校验，不能静默改成最接近的预设。
- 用户明确合法的宽高时直接传入，不被预设覆盖；仅指定 1K／2K 而无比例时传入该档位；尺寸、档位、比例与用途均未指定时可省略 `size`，使用服务商默认方图。
- 后端分别校验正整数宽高、总像素和宽高比。`wan2.7-image` 允许总像素 768²～2048²、宽高比 1:8～8:1；这不是宽高两个维度分别限制在 768～2048。边界依据[官方 API 的 size 说明](https://help.aliyun.com/zh/model-studio/wan-image-generation-and-editing-api-reference)。
- 不合法尺寸在调用前拦截并给出可行选择，不先请求服务商再反复改参数。用户无特定要求时直接执行，不为了选尺寸打断任务。
- 图片成果记录并显示解码后真实宽高；服务商可能微调输出像素，不能把请求值冒充实测值。首版不增加裁剪、补边或缩放链；精确交付尺寸受此限制约束。

### 1.2 模型与接口解耦

- 模型 ID 不作为接口准入白名单。管理员可为兼容模型选择既有图片协议，再测试并分配用途；模型可发现不代表已验证生图兼容。
- 图片协议保留旧 `dashscope-image` 配置。模型可选自动、`multimodal-sync` 或 `image-async`；自动保持既有 Wan/Token Plan 行为，未知模型必须明确选择实际请求形状，不能凭名称尝试多个接口。
- 多模态同步接口固定为 `/api/v1/services/aigc/multimodal-generation/generation`，图片异步接口固定为 `/api/v1/services/aigc/image-generation/generation`，不提供任意请求路径、模板或脚本。手动配置的兼容服务仍执行地址、DNS、重定向与密钥边界校验。
- 尺寸模式为自动、服务商默认、固定列表。自动使用已知模型预设；未知模型不套用 Wan 的默认分辨率。固定列表采用明确的像素尺寸，默认值必须属于列表，管理员逐项添加，无需编辑 JSON。
- 上节尺寸表与范围是 `wan2.7-image` 的预设；`wan2.7-image-pro` 文生图增加 4K。其他模型按保存的尺寸规则处理，没有规则时省略默认 size；未知规则下仅凭比例不能声称已得到某个精确尺寸。
- 固定列表中不支持的明确像素在请求前拒绝；比例按已有规则确定性选择，不擅自改变用户明确指定的尺寸。服务商默认模式下显式像素须通过通用资源边界，再由服务商判定支持情况，不自动改参数重试。
- 配置保存在现有模型版本 JSON 中，草稿、服务测试和任务绑定携带同一配置。已有操作恢复使用已冻结的配置及尺寸，不能因管理员换模型而重新生成。
- 图片工具描述不再固定宣称所有模型默认 2K、均不支持 4K；后端根据模型规则执行，无新增规划模型轮次。
- 保留一次请求一张、文本生图、PNG 私人成果。文件解码采用独立资源上限，可容纳 4K，同时继续拒绝过大、损坏、多帧或恶意文件，不以 Wan 的输入尺寸范围充当通用文件安全规则。

### 2. Agent 调用与性能

- 提供独立图片生成工具，输入是用户意图、必要的图片参数及稳定操作标识，输出是持久成果引用和状态；不把密钥、Base64 或临时下载地址放入模型上下文。
- 沿用按需工具加载，常规问答、查询工作、搜索资料不主动加载完整图片工具定义，不增加前置规划、提示词润色或事后图片核对的模型轮次。
- 区分“生成图片”“写生图提示词”“分析已有图片”“生成数据图表”。没有画图请求时不因话题提到图片就调用生图服务。
- 需求已足够执行时直接生成；仅缺少会实质影响结果的必要信息时澄清，不强制询问尺寸、风格等所有选项。
- 图片生成不自动创建工作或报告，不因图片成功后聊天模型输出失败而再次生成。普通回答的 low／high 行为保持原样。
- 同轮相同操作的重复工具调用复用回执。下一轮用户明确要求“再生成一张”属于新操作，可以产生新图片。

### 3. 结果交付与交互

- 图片作为个人会话成果，通过现有 PNG 成果预览展示，不冒充用户上传的附件；继续复用鉴权预览和下载，仅补实际宽高等必要元数据。
- 原图通过后端鉴权读取，支持桌面和手机适配；多张结果按返回数量有序展示，不挤占输入框或横向撑破页面。
- 用户可下载已持久化原图；预览失败只重试读取图片，不能触发生图。
- 提交成功但图片持久化／发布尚未完成时不得报告全部成功；已保存图片立即可交付，不依赖后续长篇文字回答结束。
- 刷新、切页、再次进入会话通过现有任务和成果恢复，不创建新的生成操作；完成、失败、取消均应结束工作状态。
- 生成中的图片无需模拟文字打字机或渐进成图；第一版不要求厂商图像流式协议。

### 4. 持久化、恢复与重复请求

- 生成操作保存公司、所有者、会话、消息、逻辑操作标识、配置版本、有效参数摘要、来源、外部请求／任务标识、状态及成果引用。
- 先短事务领取操作，再执行外部请求，最后短事务确认结果。生成、轮询、下载期间不持有数据库连接或行锁。
- 并发执行、租约丢失、重复工具 call ID、同消息重试不能重复发布成果；幂等范围同时考虑稳定操作槽位和规范化请求，不能只依赖模型每次生成的新 call ID。
- 百炼原生接口采用异步创建／任务查询，取得 task_id 后持久化并复用查询；Token Plan 官方接口采用同步返回，持久化图片结果回执后恢复原结果下载，不伪造 task_id。提交已发出但尚未取得或持久化回执时，仍可能无法确认结果，必须保留未知状态，不盲目重放；不承诺外部提交具有端到端 exactly-once 保证。
- 下载暂时失败优先恢复同一生成结果的下载；外部链接已失效且无持久结果时明确失败，不默默重新生成。
- 用户显式重新生成属于新的操作；取消后不发布迟到结果，不自动重试已经被取消的任务。
- 沿用已有任务预算与并发边界；必要的图片请求时限与响应大小单独按已确认协议配置，不改大所有聊天请求的限制。

### 5. 文件安全与资源管理

- 图片服务适配器负责请求协议，业务模块负责归属、幂等与成果发布，不能把生图记录写成沙盒执行记录。
- 服务端取得结果后校验真实 MIME、大小和像素范围，安全落盘；不把 HTML、SVG 脚本或错误 JSON 当作图片。
- 对服务商返回的下载 URL 及每次重定向校验目标，禁止读取本机、内网、元数据地址和本地文件；下载时不转发模型服务密钥。
- 复用私有媒体目录、存储配额、成果授权与清理机制；未发布图片和恢复中的临时文件必须有明确保留／清理规则，防止既有孤儿清理误删正在恢复的图片。
- 员工、管理员均只访问权限允许的个人会话成果；管理员身份本身不授予其他人的私人生成图片访问权。
- 生产日志和前端错误不泄露密钥、内部地址或完整私有提示词；用户看到可理解的错误，管理员可通过内部请求标识诊断。

### 6. 用量与测试可观察性

- 模型用量增加“图片生成”，记录实际服务、模型、耗时、状态及请求标识。
- 服务商未返回 token 或费用时显示未知，不把图片数量伪装成 token，也不推算无依据的价格。
- 内部回执区分生成请求、结果查询及本地下载重试，便于核对重复外部生成；普通用户界面不显示内部预算和费用推测。

## 边界条件

- 有图片配置但没有可用聊天模型时，不新增绕过聊天入口的独立生图页。
- 未配置生图、失效密钥、不支持的模型／尺寸、429、内容拒绝、空结果、断网和超时均有稳定错误，不循环改参数直到成功。
- 服务商响应有多张图片或部分文件无效时保留成功部分，说明实际交付数量，禁止整批重放造成重复结果。
- 同时处理多位用户、历史会话删除、成员删除、角色变化和配置撤销时，生成和交付都重新验证有效权限。
- 用户要求修改上传图或上一张图时，明确首版暂不支持图片编辑；纯文本重新生成不得冒充保留原图细节的修改，也不能擅自把附件传给图片服务。

## 技术约束

- 沿用现有 API／worker 和任务运行机制，不新增独立常驻服务、队列产品或浏览器直连模型服务。
- 不直接扩充现有聊天 JSON 响应限制来容纳 Base64 图片；图片适配器独立处理与限制图片数据，避免阻塞事件循环或无限读入内存。
- 模型服务字段、用途、配置快照、测试接口和 Web 类型同步更新；相关权限与迁移按 S3 实施验证，本文档编写按 S0。
- 首批按[万相 2.7 原生 API](https://help.aliyun.com/zh/model-studio/wan-image-generation-and-editing-api-reference)和 [Token Plan 多模态生成 API](https://help.aliyun.com/zh/model-studio/token-plan-multimodal-gen)分别适配异步和同步协议。只对精确 Token Plan 官方主机选择同步路径，保持同域名和密钥；不能以同名模型推定任意网关兼容。返回 PNG 链接后及时私有化保存。

## 兼容性要求

- 现有公司缺少图片配置仍能正常登录、聊天、ASR、生成报告和使用沙盒。
- 旧任务快照不被追溯修改；缺少图片绑定的旧任务按不可用处理，明确使用新配置重试时才进入新配置轮次。
- 已有 PNG 图表和其他成果文件继续可读、可下载；本次复用 PNG 支持，不扩大成果文件类型许可。
- 配置旧客户端保存时不能无意清空新图片用途；区分字段缺失与显式解除绑定。

## 验收标准

勾选表示已有受控验证证据。未勾选项含真实服务或完整交互待补部分，不代表功能尚未实现；逐项证据及限制见[独立验收](acceptance.md)。

- [ ] 可以独立添加、测试和分配图片模型，图片服务不会被当成 ASR；权限和配置版本行为正确。
- [x] 固定 Agent 流程能从用户需求调用实际适配器契约，返回真实可预览、下载且可刷新恢复的图片。
- [x] 未配置、服务拒绝、空结果、网络失败等不伪报成功、不发生工具循环。
- [x] 同操作重复调用、并发、worker 恢复、发布失败及图片下载重试不重复提交已确认的生成请求。
- [x] 外部结果未知时不自动重放；用户明确要求新图可发起新操作。
