## 实现

- Worker 默认 3 个独立处理槽，配置范围 1～8；数据库成员约束保证同一员工串行。单 worker 进程锁避免误开多个进程放大容量；槽启动失败会退出，关闭有界等待并回收任务。未发送预约可重新排队，已开始且结果未知的请求保留人工重试；领取／恢复遵循公司、成员、任务锁序。
- 报告改为一次明确的 JSON 栏目生成，经权限、来源、结构和版本校验后事务保存内容／候选及成功凭据。保留旧 `reportSaved` 恢复识别，重复恢复不额外请求。报告用途连通测试同步检查栏目结构，不再要求工具往返；工作助手仍保留原 harness。
- 新增安排版本、员工有效区间、周期待办、合并通知。新规则／成员从后续周期加入；当前周期优先，历史补齐及提醒更新分别限批。无来源仍有待办，过期历史不触发模型；提交、删除、停用同步完成／撤销提醒，停用同时隔离未完成任务的晚到结果。
- Web 新增“我的报告 → 汇报待办”、团队看板“汇报情况”、桌面／手机顶部通知。筛选在 URL 中保存，列表有界，管理员只读提交元数据及授权的已提交报告。规则展示提醒选项与生效周期。
- 增量迁移 `0007_report_obligations` 保留原有账号、报告和配置；部署示例补并发变量与 worker 的 20 秒退出窗口，运行说明见 [部署说明](../../docs/setup.md#后台处理与汇报安排)。

主要实现位于 `worker.py`、`report_generation.py`、`report_schedule.py`、公司 API／models／迁移、共享 API 类型和 `ReportObligations.tsx`；相关既有页面、模型探针、测试同步调整。
