# 用户流程与性能对照

本文件定义实施后的验证，不代表任何用例已执行。测试必须覆盖 [Spec](spec.md) 的原文件可达性、图文输入、准确来源及等待时间；不能仅凭状态为 succeeded 或模型声称读完验收。

## 基线与样本

- 当前可比较基线为 `3916434b2059b7366ba5f81d01c1e55eaa5afc23`。实施开始若存在相关后续提交，先记录实际基线及差异，再做对照；不把错误版本或不同强度作为旧版。
- 样本使用自建原件和已知答案，包含文字头部／中部／尾部、仅图片中存在的随机标记和跨页关系。答案不写进文件名、元数据或测试问题。
- 为每个格式记录支持、排除及未知内容区域。只有显示“部分可读”但无法继续获取缺失正文，不算解决提取截断。
- 同内容的新／旧格式用于兼容对照；不得把转换产生的内容差异算成模型幻觉，先核对真实派生文件和模型输入。

## 最低功能矩阵

| 组别 | 输入与操作 | 必须验证 |
| --- | --- | --- |
| F01 普通路径 | 无附件聊天；短 TXT、MD、PY、JS、DOCX、XLSX、文字 PDF | 无新增模型阶段；短文正文实际提供、来源正确，不重复查读；普通路径不渲染 |
| F02 文字截断 | 超过 20 万字符、2000 分段的文本／代码／Word；超长单段和单元格，问题答案在边界后 | 续提取能读取尾部，游标前进，无重叠遗漏；已有引用保持稳定 |
| F03 页数截断 | 超过 100 页 PDF、100 张 PPT，尾页带唯一事实；搜索未提取尾部 | 原件后部可定位读取；搜索范围和结束标志真实，不能返回假“未找到” |
| F04 表格范围 | 超过旧工作表／行列／非空单元格输出边界，稀疏表、合并单元格、超长单元格、公式保存值 | 有界范围读取到目标数据；统计使用完整目标范围；隐藏内容、缺失公式值和排除项明确 |
| F05 Word 混排 | 正文＋嵌入图片＋图表＋文本框＋嵌套表格；页眉页脚、脚注独立事实 | 支持范围有事实依据；图文对应；无法提取对象有补读或明确限制，不能默认全部成功 |
| F06 PPT 混排 | 流程箭头、图表、组合图形、截图文字、备注、只有图片的幻灯片 | 整页关系与备注正确；图中事实进入主模型，不经过单独描述模型 |
| F07 PDF 混排 | 文字与扫描页交错、纯扫描、空白／旋转页、小字、跨页图表 | 无文字可视觉读取，空白页不误判故障；必要时细化读取，未看清不编造 |
| F08 旧格式 | DOC／PPT／XLS 及现有 RTF／ODF 正常样本，至少一份 Word／演示混排旧文件 | 真实 worker 转换和页面渲染；不依赖 Agent 沙盒，原件可下载 |
| F09 任务差异 | 同一长材料分别问单点、全文总结、完整条款列表、两文件所有差异 | 单点不强制全文；全量要求有完整范围或显式缺口，不能只依赖前三条搜索结果 |
| F10 部分失败 | 正常文档与损坏文档一起发送；文字可用但渲染失败；视觉服务拒绝 | 其他资料可用，失败落到具体范围，提示简短且不与状态冲突；不循环重试或换模型 |
| F11 图像预算 | 多份混排文档＋独立图片，总页图超过单次预算；一张超大页面 | 共用预算、批量推进，页序和来源正确，不能静默漏页或整条消息全部失败 |
| F12 注入与权限 | 文档文字／图片包含越权指令，引用另一用户 ID／缓存，恶意路径 | 材料不成为授权；返回和模型输入都不泄露他人资料 |

F02～F04 同时测边界内、边界上、边界后，不能只测改后更大的新上限之内。对于仍然触达硬资源限制的样本，验收可恢复范围及准确失败，不要求绕过安全控制。

## 完整用户流程与故障组合

| 组别 | 连续操作 | 最终断言 |
| --- | --- | --- |
| J01 上传时序 | 桌面／手机选择混排文件 → 上传完成但不发送 → 删除／重新添加 → 发送 | 发送前提取、渲染和模型调用均为 0；发送条件、卡片与最终答复正确 |
| J02 多批历史 | 多批累计超过单次附件上限，包含文档／图／语音 → 要求读取较早批次 → 合并分析 → 生成成果 → 刷新追问 | 不绕过上传上限，不漏早期材料；检查最终正文、真实成果内容、来源和持久化 |
| J03 重复与同名 | 同内容不同名、同名不同内容、自动编号后再撞名、长文件名 → 发送 → 追问 | 附件身份独立，处理次数按既有去重规则；正文／页图不串文件，缓存命中仍鉴权 |
| J04 跨任务复用 | 第一次询问 → 追问同页 → 查询另一页 → 刷新 → 再问尾部 | 不重复转换已缓存原件；不同页继续处理；上下文被压缩后细节仍可重取，引用不失效 |
| J05 工作材料 | 保存文件为工作材料 → 删除源消息 → 刷新工作 → Agent 读取文字／页面 | 原件与授权来源保留，可重建派生物；不依赖已删除源附件的唯一缓存 |
| J06 取消恢复 | 排队／提取／转换／渲染／保存前取消，随后重试；隔离 worker 终止再启动 | 有效批次可复用，无重复分段、假覆盖或晚到覆盖；无孤儿进程和永久处理中 |
| J07 并发故障 | 至少 4 个临时账号同时处理快慢文件，一个重任务失败，其他账号继续登录／发消息 | 不串用户、不耗尽资源；后续正常请求完成，排队和资源回收可观测 |
| J08 删除清理 | 页面缓存已生成 → 删除附件／移除材料；包含仍被引用和清理失败重试 | 只清理应清理内容，保留仍被引用材料，重试无权限扩大或误删 |

- 用例实际经过 API、worker、数据库、解析器及渲染器。受控模型可替代外部响应，但不得替代原件处理或跳过工具装配边界。
- 浏览器验收核对桌面／手机可见状态、来源、刷新和追问；后端集成核对范围、身份、版本、取消、存储和调用次数，分别报告证据。
- 故障注入包括子进程崩溃／卡住／异常输出、权限失败、磁盘不足、解析资源超限、数据库写入失败和租约丢失。只使用测试拥有的进程、临时目录与配额，不操作线上或用户资料。
- 不仅检查失败请求，还需在同账号及另一账号完成后续正常请求，确认槽位、句柄和临时文件已恢复。

## 准确性验收

- 确定性检查要求预期支持范围全部可达、稳定来源定位和零跨来源串用；模型输入检查确认必要文字／图像真正发送，不只检查磁盘上有文件。
- 固定问题覆盖文字事实、图中事实、布局关系、末尾限定条件、跨页完整列举、表格精确数字及不可读范围。逐项评分并保留实际答案，不评文风和是否恰好写满某字数。
- 旧版可正确处理的问题，改后不能因本次提取／输入／工具流程丢失事实、条件或来源；模型随机错误与系统传错／漏传分别标记，不能一概归因于模型。
- 新能力至少证明旧截断区域及图中事实已可正确回答；“提示缺失”仅能验收真实不可恢复的故障，不能替代正常文件新增能力。
- 低清、渲染不支持和无法处理完的文件可以给有限回答，但必须标明相关范围。模型声称“已读全”、引用数量和向沙盒提供原件均不能单独证明覆盖。

## 性能对照

### 指标与控制变量

- 统一从用户点击发送计时：发送确认、worker 排队、提取／转换／渲染、首次模型请求、首段可见答案、完整答案显示。分别记录模型各轮耗时、模型／工具调用次数、输入输出 token、图像块、缓存状态及峰值资源。
- “首段可见答案”不包括状态提示、读取中、空白或占位；流式开始及完整显示时间均须来自实际客户端或等价流事件记录。
- 同一硬件、服务、模型、提示、人设、思考强度和附件内容配对，A/B 交错运行；固定输出内容用于确定性系统开销对照。记录 provider 失败和缓存差异，不挑最快结果。
- 冷启动、首次转换、已有缓存、在途复用分组报告；不把提前上传耗时挪出统计后声称模型回答更快。

### 等价能力回归组

无附件普通问答、短文本／代码、文字 PDF／Word、结构化表格，以及重复材料追问，修改前后使用相同可完整读取的内容。

- 受控模型下各代表路径预热后至少 30 对，报告 p50／p95 与所有失败；普通路径不新增固定模型阶段，不额外触发模型探测或页面渲染。
- 系统新增处理开销 p95 的回归上限为 `max(基线 p95 × 10%, 100ms)`，分别检查首轮模型前和轮次之间的处理开销。任何新增串行模型调用必须有与任务相关的内容依据，不能以系统阶段很快掩盖多轮等待。
- 真实模型只测 low、high。选普通问答、短文本／代码、纯文字 Office／PDF、表格和重复材料追问五类，每类每档至少 3 对，交错执行。报告每次首字、总耗时、轮次与质量，不用小样本声称 p95 或统计显著提速。
- 真实请求每类每档的中位首字／总耗时若回归超过 `max(基线中位数 × 10%, 1s)`，必须检查调用链和系统阶段。可明确归因服务商波动时保留证据并标为性能结论受限；无法归因或确由系统引入时不得直接验收为无回归。

### 新增完整读取／视觉能力组

- 代表样本包含长文件尾部、Word 混排、PPT 流程图、纯扫描 PDF、跨页完整列举及含图表的表格。low／high 各至少一次真实端到端验证；不足以得出稳定耗时结论时明确标注样例性质。
- 旧版读取遗漏与新版完整回答不按同质量直接计算“慢了百分之多少”。并列报告实际读取范围、事实得分、首次准备成本、首字和总耗时。
- 在新版上比较首次与缓存命中，以及相同目标范围的批量读取和逐批对照，确认复用真实减少了转换／渲染次数；不得仅凭时间波动证明缓存有效。
- 新能力不设置虚假的通用秒数保证。存在不必要的重复转换、重复页输入、独立描述模型或固定核对阶段即为流程不通过；必要完整读取成本则量化列入交付。

### 执行与证据边界

- 真实调用是实施验收中的有限样例，不放入默认 CI；使用获授权的本地已保存服务，不输出密钥、不调用线上员工材料、不改服务配置。
- 如果服务额度、403、网络或能力阻塞，记录未执行的具体项；确定性测试通过只能证明系统数据流，不能代替真实 low／high 质量与速度。
- 测试结果、调用摘要、答案和安全计时数据放本次 `artifacts/` 目录，报告引用结果并说明原件／模型输入覆盖；不将 base64、凭证、用户资料或冗长原始日志写进 Spec。
- 由独立验收 Agent 对矩阵逐项标记通过、失败、未执行及原因；完成相称验证后停止，不反复跑到满意结果。
