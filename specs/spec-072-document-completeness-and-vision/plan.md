## 涉及模块

| 模块 | 职责与边界 |
| --- | --- |
| `integrations/parsing` | 有界范围提取、固定 Office 转换与页面渲染；不执行模型代码 |
| `modules/attachments` | 来源权限、持久范围、派生物引用、缓存和清理；不放 Agent 调度逻辑 |
| `tasks/processing` | 发送后的准备、轻重调度、租约／取消、批次持久化；不在长事务内跑转换 |
| `agent/tools/resources` | 沿现有文档工具提供范围搜索、续读和页面请求；复用来源校验 |
| `agent/context`、`agent/runtime` | 精简正文预载、页面图片装配、预算、真实输入覆盖、重放与上下文压缩 |
| `modules/work/materials` | 保证独立保存材料及源消息删除后的读取／缓存重建 |
| 共享类型与 Web 媒体组件 | 可选范围状态、简洁失败提示及页面来源定位；不重做附件卡片 |
| 部署、样本与基准脚本 | worker 依赖、真实转换／渲染检查、质量与耗时对照 |

## 修改顺序

1. 固定修改前提交和样本，采集现有正常路径的调用链及计时；构造尾部事实、图中事实和跨页关系，不先修改基线。
2. 定义原件范围、提取代次、续读游标、覆盖分类和派生物引用；实现有界续提取及搜索，保持旧引用兼容。
3. 实现 worker 页面转换／渲染与私有缓存，补齐取消、幂等、清理和工作材料保存路径。
4. 扩展文档读取工具，加入批量范围／页面请求；接入主模型图像输入及输入预算、重放和失效机制。
5. 加入小文档正文预载及覆盖记录，替换失效的“正文只能通过工具读取”说明；只改材料相关工具／短提示，不扩充通用系统提示词。
6. 更新必要的 DTO、卡片状态、来源定位与安装说明；完成测试矩阵及 low／high 对照，修复本次相关问题。
7. 实施 Agent 返回实现、性能证据和限制；由新的独立验收 Agent 验收。未通过项返工，不由验收 Agent 修改业务代码。

各步骤高度耦合，默认由一个实施 Agent 串行开发。文档起草由主 Agent 完成，不创建子 Agent；用户要求实施后再进入实施／验收流程。

## 数据流

```text
选择附件 → 上传原件 → 等待用户发送
                           ↓
                    权限、版本和任务租约
                           ↓
          复用有效派生结果／有界提取初始结构与文字
                           ↓
      小文件必要正文和少量视觉页面预载／长文件目录与范围
                           ↓
                      主模型正常处理
                           ↓ 按需
      文档工具批量定位、续提取、读取文字或请求页面图片
                           ↓
       worker 固定解析／渲染 → 缓存 → 记录本批可用范围
                           ↓
             下一次主模型请求携带授权内容和图像
                           ↓
          流式回答＋有效来源＋必要的未完成范围说明
```

渲染、来源核对及覆盖记录均用确定性代码；不插入第二个模型做图像描述或全文完整性复核。全文任务仍可能需要多轮正常读取，不能把它描述成无条件一次模型调用。

## 提取、范围与持久化设计

### 原件范围

- 建议统一内部范围结构为 `unit + start/end + offset`：unit 对应页、幻灯片、段落／表格、工作表／单元格或文本位置。范围字段需版本化并验证，不接受任意文件路径。
- 分离 `nextExtractCursor` 与现有分段 `nextCursor`；查询返回 `searchScope`、未搜索范围及是否遍历完指定范围，避免现有空游标被错误解释。
- 普通续提取在同一代次追加分段，保证已发引用不变；范围执行记录支持幂等和原子发布。失败批次不覆盖已完成批次，不在恢复时追加重复行。
- 对超长单段、单元格及文本，游标必须精确到内部偏移；不能每次重读前缀后再次撞上同一限制。对需要顺序遍历的格式复用中间产物，记录剩余的扫描成本。
- 搜索可按批继续扫描原件，匹配仅返回定位及少量上下文；未扫描完不得返回“完整无匹配”。只遍历原件不意味着全文已提供给模型。
- 原来用于限制单次内容输出的页数／字符／分段限制改为批次边界；解压、防畸形结构、进程资源等硬限制保留。不可恢复限制返回原因和已处理范围，不无界扩容。

### 存储与兼容

- 优先复用 `Attachment.extraction_info` 的版本化清单、`DocumentChunk` 和任务结果，不预设必须加数据库表。范围明细规模必须有界；大量明细可放在私有派生清单中，数据库只保存摘要、版本和受控引用。
- 私有处理产物位于既有媒体根下按附件身份隔离的专用目录；路径由服务端生成，包括转换后的可读文档、用于视觉的 PDF、指定页图像与范围清单；不新增用户可见附件。它们随附件持久化和删除，不按页数或短期 TTL 淘汰，不设总量或单附件累计容量额度；只回收过期的未发布临时文件。磁盘空间保护在共享重任务锁内执行，空间不足只中止新的相应页面准备，保留已读正文和既有引用；恢复办法写入运行说明。
- 原件 SHA、解析器、Office 转换器、渲染器和策略版本构成缓存指纹；文字与视觉缓存分别判定，分辨率变化不应无故重做原有文字提取。
- 同一授权范围内的重复处理按既有去重规则复用；独立附件／工作材料必须拥有可恢复的来源，不保存指向可能删除的其他附件的唯一缓存指针。
- 源内容／策略变更建立新代次，发布前校验租约和原件哈希；续提取不触发 `InputChanged`，真正重解析仍须使旧证据失效。
- 旧附件无完整性清单时保持可读，后续按需扩展；历史引用仍能解析，不后台全量转换。若实现确需 schema 变化，先更新本计划和目录树，补增量 migration、旧数据默认值及回滚检查，不直接修改线上数据。

## 页面视觉与模型接口

- 复用固定 LibreOffice 流程导出 Word／演示文稿 PDF，优先使用 worker 的 Poppler 固定命令栅格化；添加必要版本／字体配置，不加入 API 或独立 Agent 沙盒依赖。
- 渲染在受限子进程中运行，禁宏和外链；遵循现有 Office 进程树回收、超时、环境清理和容量边界。不能把“固定命令”当作与执行沙盒等价的隔离。
- 原件 PDF 页码与原生幻灯片号可直接定位；Word 转换页码明确属于转换后的页面。不可无依据把原生段落号映射成 Word 原始页码。
- 结构检测、相关正文和页面映射应帮助定位视觉页；无文字页面必须仍可发现。重复水印可复用像素缓存，但不能删除正文可能引用的视觉信息。
- 扩展既有 `read_document`／`read_work_material` 的可选范围、视图和批量参数，保留旧调用参数；优先避免额外建立一组职责重复工具。页面请求输出短 JSON 回执及私有引用。
- 在模型请求装配边界，将已授权派生引用解析成支持的图像消息块；避免依赖服务商支持 ToolMessage 内直接携带图片。保持工具调用／回执配对，禁止把文档页包装成新的用户指令。
- 新增页面范围进入输入摘要、任务依赖和失效检查；重放校验权限、版本和实际发送情况。日志／工具进度保留引用和摘要，不能累积大段 base64。
- 上下文估算覆盖本轮文字和图像；图片未装配或模型请求未送出时，不能记录为已提供。压缩掉的旧页只保留来源与必要摘要，需要细节时重新按需加载，不能把历史已提供记录当成当前上下文仍存在。
- 本次保留既有独立 `read_images` 行为，仅复用其图像尺寸／预算等必要能力；文档页面不再经过它的额外描述模型调用。

## 输入预算与性能约束

- 首个候选方案：以现有一次文档读取的 12000 字符作为整条消息正文预载上限，并受当前剩余上下文约束；这不是原件长度上限或新输出限制。小文件能完整放入才声明完整，多附件公平分配，未放入的文件仍有目录及续读入口。
- 页面预载仅用于预算内少量、确有必要的视觉材料；长文档及重渲染按需准备。具体页数和分辨率依据既有图像预算及固定样本计时选定，不为了赶首字只发送模糊缩略图。
- 无附件消息零新增提取／渲染操作；纯文字直读路径不启动 LibreOffice／页面渲染。不增加默认模型探测、分类、OCR 描述或审查调用。
- 解析、渲染共享有界重任务容量，轻任务保持可运行；并发上限按实际 worker 总数量评估，不仅看单个进程的 semaphore。不得通过新增无限并发掩盖等待。
- 缓存命中、冷转换、排队、实际模型耗时分别计量；正文开始时间与完整答案时间均需报告。进度提示提前不算答案变快。
- 具体前后配对、指标门槛和异常判定以 [test-matrix.md](test-matrix.md) 为唯一来源，不在多份文档重复维护不同数字。

## 风险与迁移策略

- Office 转 PDF 的布局可能因字体或对象支持不同而变化；保留原件和结构化文字，转换页用于补充理解，不保证像素级一致。
- 页图增加输入 token 和处理时间；通过选页、批量及缓存控制，新增视觉／完整读取成本必须透明计量，不能承诺所有场景绝不变慢。
- 单纯文字关键词无法定位所有图中事实；扫描件和只问视觉内容的任务需覆盖相关页或声明范围，不能完全依赖文字检索。
- 文件处理扩大到后部内容会增加 CPU、存储和 I/O；使用有界批次、磁盘空间检查和附件删除清理，同时保留原件可重新读取。清理不能干扰在途请求或引用材料。
- 图片输入必须通过现有模型适配与用量记录，不能直接跨过模型绑定、任务预算、鉴权或流式流程。
- 首版优先向后兼容元数据，不批量修改原件。发布前检查 worker 能力；回滚停止新的范围／视觉准备但保留原件与既有引用，不清空业务附件或破坏历史结果。
