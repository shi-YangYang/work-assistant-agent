# Spec 072：完整文件读取与图文联合理解

## 状态

已实施并通过本地独立验收，限于 [验收报告](acceptance.md) 列出的实际验证范围。本次补齐原件续读和图文联合输入，保留既有上传交互；准确性与耗时对照见 [performance.md](performance.md)。high 稀疏尾表因网络故障未取得答案，模型漏答和阅读范围表述过度单列为限制，不宣称所有回答或所有矩阵组合均通过。未提交、推送或部署。

## 背景

旧 Office 已能在 worker 中转换并提取文字，但“文件已上传”“文字已提取”“内容已提供给模型”是三个不同阶段。目前文件尾部可能因提取上限缺失，图片与图表也可能完全未进入模型输入；仅改善提示无法解决实际遗漏。

现用模型的独立图片识别已验证可用，但这不等于 Word、PPT、PDF 中的图文联合读取已打通。目标是在保留准确来源和完整性边界的前提下补齐读取能力，并尽量减少用户从发送到收到答案的等待。

## 目标

- 对目前支持的文档、文本和代码，提供可继续读取原文件的路径，解决只保留开头内容导致后文永久不可达的问题。
- Word、PPT、PDF 结合文字、表格和页面图像理解；旧格式沿用 worker 转换后进入相同流程。
- 区分原文件提取范围、本次实际提供给模型的范围和无法读取的范围，避免局部读取被描述为全文分析。
- 小文件减少读取工具往返；长文件按任务读取；派生结果复用，不新增常规模型核对阶段。
- 以真实用户流程、确定性数据验证和 low／high 模型对照共同评价质量与耗时。

## 非目标

- 不新增向量数据库、全局知识库、独立 OCR 模型或第三方文件转换服务。
- 不修改用户选择的模型／思考强度，不用减少回答内容、调低强度或取消安全边界实现提速。
- 不扩展上传后缀、文件数量及容量上限，不恢复“查看提取内容”入口，不要求用户选择读取模式。
- 不自动执行宏、外链、嵌入程序，不破解加密文件；不承诺任意文件、原生对象和复杂版式无损还原。
- 不把整份文件永远塞入系统提示词，不增加分类、审核、总结再转述等固定串行模型调用。
- 不重做既有历史独立图片工具、语音处理或报告生成业务；文档页面能力应复用共有基础设施并保持这些路径兼容。

## 当前行为

- 上传仅保存原件；发送后 `tasks/processing/documents.py` 在独立受限进程中提取，旧 Office 经 worker LibreOffice 转换。
- `document_parser.py` 当前最多输出 20 万字符／2000 分段；PDF 与 PPTX 最多处理前 100 页／幻灯片。XLSX 还有工作表、行列、遍历数量和单元格长度限制。
- 触达提取上限时记录 `partial`，但后续内容没有持久化，也没有原文件范围续提取接口。扫描 PDF 无文字时会失败。
- `find_documents` 只能搜索已提取分段；`read_document` 每次返回最多 40 分段／12000 字符。其 `nextCursor = null` 仅意味着已保存分段结束，不证明原件结束。
- 当前文档以目录进入模型，正文需调用工具；新上传的独立图片可以直接进入主模型，但文档内的图片、图表和版式不在此路径。
- 已有附件哈希复用、分段引用、版本校验和读取记录；代码执行使用原件时，现有记录不能证明其实际遍历了全部内容。本规格扩展这些能力，不重复宣称它们是新增优化。

## 目标行为

| 材料／需求 | 目标路径 |
| --- | --- |
| 无附件普通聊天 | 保持原流程，不增加文档探测或模型调用 |
| 可在预算内完整提供的短文本／源码／纯文字文档 | 一次提供必要正文及来源，避免先查目录再读正文 |
| 少量图文混排页面 | 文字与页面图片成批进入当前回答模型，保留对应关系 |
| 长文档定点问答 | 搜索可覆盖原件后部，读取命中位置及必要上下文；需要视觉时补相关页面 |
| 全文总结、完整列举、逐页检查、多文件完整比较 | 按要求范围分批覆盖；有缺口时说明实际范围，不把检索命中当作全量结果 |
| 表格统计／筛选／精确核对 | 使用单元格原始保存值及范围读取，必要时复用现有隔离代码执行；不能以预览片段或截图作为完整统计输入 |
| 仅扫描图片的 PDF／幻灯片 | 可通过页面视觉读取；文字提取为空不再直接等同于文件不可用 |

用户仍只需上传、发送、提问。策略是内部读取行为，不新增设置项或必答确认。

## 功能需求

### 1. 可继续提取的原文件读取

1. 将“每次处理资源边界”与“原件总范围”分开。保留进程、内存、时间、解压及输出限制，通过有界批次继续处理，不能简单取消安全限制或只提高一个全局上限。
2. 支持稳定定位：PDF 页、PPT 幻灯片／备注、Word 段落／表格与其他受支持文字区域、表格工作表／单元格范围、文本行／字符范围。不得为未渲染的 Word 编造原始页码。
3. 每批结果声明本批范围、剩余或未知范围、续读位置、失败／排除项及来源版本。可以继续时必须有真实可用的续读入口；硬资源限制与不支持对象不能伪装成可无限重试。
4. 定点读取可以到达原来上限之外；内容搜索不得把“已提取范围未命中”包装为“全文件不存在”。未完成全范围搜索时返回剩余范围，允许继续扫描原件，且不返回无关大段正文。
5. 正常续提取追加同一解析代次的稳定分段，不改已有 ordinal／引用，不触发自身版本失效；原件、解析策略或转换版本变更才建立新代次。
6. 优先支持主流正文、嵌套表格、PPT 分组内容与备注；页眉页脚、脚注、文本框等内容应纳入支持矩阵，能提取则定位输出，不能提取则报告范围并提供适用的页面视觉补读。不能只覆盖正文段落就宣称完整。
7. 延续隐藏工作表／行列等现有可见性规则，明确排除范围；“全部”只可针对明确声明的范围。公式继续使用保存值，不重算、不刷新外部数据，缺少保存值时不能编造数值。

### 2. 图文联合读取

1. PDF 可读取原页面；DOCX／PPTX 以及已支持的旧 Word／演示文稿格式，可在 worker 内生成用于理解的 PDF 页面派生物。无需启用 Agent 沙盒。
2. 默认使用页面文字与整页图片保持布局关系；小字或局部细节允许按需提高分辨率／裁剪，不为每份文件默认生成多套高清图。
3. 纯文字路径不强制渲染。依据现有结构信息选择轻量直读；已知有图表、图像、绘图对象或文字缺失时提供视觉入口。检测不能保证发现所有视觉信息，用户要求查看版式或图表时必须仍可指定页面补读。
4. 新的文档视觉路径将图片直接放入主模型当前或下一次正常请求，不先调用另一个模型生成描述再交回主模型。提供页码、附件及提取代次的映射；工具回执和日志不存重复图片 base64。
5. 本轮上传图片与文档页面共用实际图片数量、像素、请求体和上下文预算。超过单次输入预算时分批处理，不静默漏图，也不能让一张页面超限使同消息可读材料全部报废。
6. Excel 的主体保留结构化单元格；嵌入图表／图片按明确工作表或对象范围补充视觉，避免默认渲染整个工作簿。视觉不能替代完整数值核算。
7. 模型不支持视觉、服务拒绝图像或渲染失败时保留可读文字，明确“图片部分没读到”等局部限制；无文字可用时给出明确失败提示。不得静默换模型或持续尝试同一失败请求。

### 3. 输入组织与读取覆盖

1. 短文件正文预载按整条消息共享预算计算，并计入上下文估算，不按每个附件各分配一份大预算。已有正文不重复请求；不把截断预载标为完整。
2. 大文件预先提供轻量目录、可用范围及限制；主模型根据本次任务决定读什么，不新增单独模型分类阶段。支持一次请求多个页／范围，后端在资源限制内准备结果。
3. 工具能够区分“已有分段已读完”“原件仍有未提取部分”“原件支持范围已处理完”。续读产生新范围才算进展；相同请求无新内容时复用结果或明确结束，不循环读取。
4. 分开记录：原件可读取／已提取范围、页面渲染范围、实际交给模型的文字／图像范围、代码执行的输入与可验证处理范围。渲染成功不等于已交给模型，交给模型也不等于模型理解完全正确。
5. 完整性信息由程序汇总；只在材料相关输入和工具回执中提供精简结构，不给所有普通问答追加长提示词，不新增自动模型核对／纠错轮次。
6. 定点回答不强制扫全文；全文任务必须覆盖指定范围或明确未完成部分。完整性验收检查真实调用及输入证据，不能仅相信模型自称“已阅读全部”。
7. 来源引用保持可追溯。文字沿用现有分段引用；视觉依据应能定位实际提供过的文档页面／区域，不允许引用未提供页面。沿用现有来源展示，不重建提取内容查看页。

### 4. 缓存、生命周期与故障恢复

- 转换文件和页图属于附件的持久化处理产物，随附件保留和删除，不设总量或单附件累计容量额度；保留实际磁盘空间检查及单次处理资源边界。这里的缓存指处理结果复用，不表示可随意过期或淘汰的临时文件。
- 复用既有附件身份和内容去重规则；缓存键包含授权归属、内容哈希、解析／转换／渲染版本及页／范围／分辨率。同内容重复附件可复用处理，来源身份不合并，同名不同内容不能复用。
- 派生物是私有可重建缓存，原件始终保留。同一范围并发读取应合并进行中的工作，避免重复转换；缓存命中仍执行权限检查。
- 首次转换可能处理整份 Office 文件才能生成 PDF，不能声称任意页都能独立快速转换。缓存 PDF、按需栅格化页面，分别计时首次成本与复用收益。
- 取消、超时、worker 重启和租约变更不会让晚到结果覆盖新状态；已完成有效批次可复用，未完成批次不能标记完整。清理失败可重试，不遗留永久处理中。
- 附件删除、历史追问、保存为工作材料、删除源消息后继续读取均覆盖原件和派生物生命周期。不得因共享缓存清理误删仍被引用材料；工作材料须可用自己的原件重建缓存。
- 转换／渲染不得长时间持有数据库事务。并发有界，不让重文档耗尽普通聊天、登录和轻量附件的运行资源。

### 5. 用户反馈

- 保留“上传只上传，发送后处理”。上传中不调用 Agent、不提取、不渲染。
- 沿用现有文件卡片、读取进度和错误通道，合并重复提示，不增加每页一条的进度列表。
- 使用短句表达实际问题，例如“部分页面没读到”“图片部分没读到”“文件无法读取，请重新导出后上传”；只在与回答有关时补具体缺失范围。
- 后台保留结构化原因和范围，用户不看 token、内部游标、预算或堆栈。无文字但可看页面的文件不显示整体读取失败。

## 边界条件

- 一条消息内文档／图片／语音混合、多批累计、历史引用、同名异内容、同内容多身份以及源消息删除。
- 扫描 PDF、图文交错、无匹配关键词但答案在图中的页面、重复页眉／水印、空白页、旋转页和字体缺失。
- 字符、页数、分段、工作表／单元格等旧截断边界前后；超长单段和单元格不能因分页重复或漏掉尾部。
- 原件损坏、加密、活动对象、压缩膨胀、渲染崩溃／卡住、磁盘不足、取消和多个 worker 争用；仅在隔离测试环境注入故障。
- 上下文压缩、图像预算耗尽和任务时限仍有效；任务无法完整覆盖时明确交付范围，不无限续读或假称完成。

## 技术约束

- 保留项目架构、worker 转换边界及原件存储，优先复用现有库；页面渲染依赖仅进入 worker，不增加新常驻服务。
- 文档内容和图片文字都是不可信材料，不能变成指令、授权或扩大文件访问范围。
- 派生物路径及缓存引用由服务端构造；不允许模型传宿主路径、外链或跨用户缓存键。不得将未授权原件交给模型或代码执行。
- 本次文档起草按 S0；实施涉及持久化、模型输入和文件处理安全边界，按 S3 做相关子系统验证，不默认扩成整个产品全量验收。

## 兼容性要求

- 老附件、旧任务、已存引用、工作材料和现有客户端可继续使用。没有新元数据时标为历史／未知范围，不能推定已完整读取。
- 新能力首次访问时按需准备，不批量重解析历史文件；失败时保留原有可读分段及原件。
- 普通文本／代码、独立图片、语音、生成文件、业务权限和现有流式输出不回归。
- 不自动迁移线上环境；本地及部署配置修改需如实说明新增 worker 依赖，发布另按用户授权执行。

## 验收标准

以下完成标记对应验收报告中已验证的代表范围；具体未执行组合、网络阻塞和模型输出限制以该报告为准，不表示穷尽所有文件或回答。

- [x] 原来字符、页数、分段和表格范围边界之外的已知事实能通过真实原件续读到达；搜索不把局部未命中当成全局不存在。
- [x] Word／PPT／PDF 混排样本中的文字、仅存在图片中的事实和布局关系进入正确模型输入，并能追溯到来源。
- [x] 纯扫描 PDF 有视觉读取路径，旧 Office 转换后同样可用；损坏和不可读范围有准确终态。
- [x] 分批、预载、缓存、重试与恢复不伪造覆盖、不重复计数、不破坏已有引用；全文任务与定点问答行为符合各自范围。
- [x] 上传未发送时没有提取／渲染／模型请求；卡片及提示保持简洁，桌面和手机真实流程可用。
- [x] 重复附件不重复处理、同名不同内容不混淆，保存工作材料后删除源消息仍可正常读取。
- [x] 故障后资源释放、后续正常请求成功，无越权、网络访问或执行文档活动内容。
- [x] 既有普通路径无新增模型阶段，定向耗时指标满足测试矩阵；新增完整读取的额外成本单列，不能用遗漏内容的旧结果证明提速。
- [x] low／high 真实模型对照及确定性完整流程验证均有可复核证据；明确区分通过、失败、未执行，不以 mock 模型证明真实质量和延迟。

## 待确认问题

无阻塞性产品问题。具体批次、预载预算和渲染分辨率作为工程参数，在不扩大安全边界的前提下通过对照测试确定并记录；如需改变数据权限、引入新收费服务或牺牲既有完整性，应停止该方向并提交决策。
