# 文件理解准确性与耗时对照

## 当前结论

普通路径的对照支持“增加文档能力而没有增加固定模型往返”：受控五类各 30 对后，仅对确有返工的两类补测；真实 low／high 每类各 3 对。曾测出纯文字 Word 视觉误判导致的追问耗时回归，修复后的定向对照中已消除，原失败数据完整保留。短材料的实际模型轮次普遍从 2～3 轮降为 1 轮。

新增能力共 28 次尝试，26 次产生最终答复；按所问事实人工评分，旧版 26/56、新版 55/56。另有每臂 2 项事实因 high 稀疏尾表网络故障无法评分。新版的一项漏答、读取范围表述过度以及必要图像处理成本均在下文列出，不能宣称全量准确率 100%。缓存命中确实避免了再次原生渲染；批量仅减少工具调用，首读渲染没有测出加速。

## 对照环境与口径

- 基线：`3916434b2059b7366ba5f81d01c1e55eaa5afc23`，通过 `git archive` 冻结在 `artifacts/spec072/performance/baseline/`，未切换或修改开发分支。
- 源码、原件 SHA-256、服务名称／版本／模型／参数均记录在每个结果目录的 `environment.json`。正式发送前校验源码，变更则停止，不混用不同实现。
- 使用本机独立 PostgreSQL 17.11 容器的 `paa_company_test`，每个基准 worker 独立 schema；独立 Redis 7.4.2 容器及命名空间。仅从开发库读取已保存模型配置，所有业务、用量、checkpoint 写入测试库。凭证在内存解密后用临时主密钥重新加密，结果中不包含凭证。
- 原件为自建固定数据；文件名、元数据和用户问题不包含待识别随机标记。评分 oracle 只供基准程序使用，不传入模型。正式样本冻结在 `artifacts/spec072/performance/fixtures-v2/`（revision 2，稀疏表尾值位于 B22050/C22050，超过旧 20000 行边界）；pilot 使用的原 `fixtures/` 保留不变。尾部、视觉事实与完整列举样本在 `tests/server/_support/materials/spec072_samples.py`。
- 从真实 API 发送开始，经过真实 worker claim、`process_job`、解析／渲染子进程、业务工具、模型适配与最终持久化。API 使用本进程 ASGI；不包含 HTTP 网络、浏览器绘制及空闲 worker 定时轮询。
- 首段答案为实际 Redis 接受的首个非空回复事件，属于客户端可获取的流数据，不是“思考中”等状态。如果没有流事件，则单独标注最终 API 快照时间，不能冒充流式首字。
- 上传时间单列。旧文档首次准备、重复材料初次问答和后续追问分别留存。固定模型仅用来测系统开销；真实模型只使用 low／high，不降低强度或更换模型。
- 总耗时减去各轮模型 transport 时间作为系统时间；另记录首次模型前时间、轮间时间、提取调用和输入图像块。该口径包含数据库、图框架及观测成本，不能把全部剩余时间都归因于解析器。
- `ru_maxrss` 记录是进程及已退出子进程的历史最高 RSS，不能当成单任务实时峰值或生产容量测量。

- 文末 TXT 两档均读到了旧 200000 字符上限以后的第 170～173 段，Z9P4T7、6842、禁止预付款正确。但 low 实际向模型提供 23/174 段、high 10/174 段，回答却概括“全文其余条目均……”或暗示完整阅读全文，属于模型范围表述过度。此样本只证明定位文末事实成功，不证明完整审阅全文。附加的系统范围信息保留了实际读取数量，没有把未读内容标成已读。
- 六页条款在新版首轮前已提供全部 6/6 个文字分段，ALPHA～ZETA 与 47 天均正确；本例未请求页面渲染，完整读取不会固定添加图像流程。模型“没有隐藏条款”等泛化说法不能成为所有文档的完整性保证。
- high 表格＋图表样例已向主模型提供 8/8 单元格分段和一张页面图，回答正确列出 A=23、B=33、C=39、最高 C39 和 R7K9Q2，但漏了用户要求的合计 95，人工保留为 3/4。这是输入已到达后的一次模型漏答，未追加固定复核或重跑把它改成通过。
- low 稀疏表在第一次请求前已提供 B22050/C22050 两项事实；模型仍选择读取了一页表格图片。该额外工具成本属于这次模型选择，并非系统对所有表格固定渲染。
- 本批同一新版 worker 先执行 low 再执行 high，相同原件的私有页面缓存可复用。low 的视觉页为首次处理，high 的 Word、PPT、扫描 PDF、图表均命中缓存、没有新的原生处理，但仍真实传入图像。不能将两档之间的时差只归因于思考强度。

### 时间构成与网络终态

文末 TXT 的 low 新版共 42.784 s，其中 7 次模型 transport 合计 37.773 s，系统部分 5.011 s（首次模型前 0.756 s、轮间 3.989 s）；两次文本解析合计仅 135.5 ms。新增原件续读确有成本，但不能把 42.8 秒归因于文本解析。high 同样取到了尾部，4 轮模型，总 24.832 s、系统 2.700 s、两次解析 124.0 ms。未为缩短这个样例而添加特化提示或固定核对。

首次 low 的 Word、PPT、扫描 PDF、表格＋图表原生处理合计分别约 1485.4、1192.7、270.4、1444.4 ms；此外还有文本解析、数据库、输入装配等成本。low 图表总时长比旧版增加约 4.07 s，同时补上旧版读不到的图片编号，不可说成无代价增加能力。每次调用的原生、模型、系统耗时及 token 都在原始记录与 CSV 中。

最后一对 high 稀疏表都没有正文。旧版 job `7616d101-b644-4cb7-a9a1-c2d444cccab2` 在 3 个成功模型请求后发生取消／网络错误；新版 job `427cc57f-5905-49d2-89ba-fd08335e6965` 的 4 个候选请求均为 network / not_sent，终态都是 awaiting_retry。新版在第一次请求前已准备好 3/3 单元格分段，所问两个事实也已经在模型输入中。候选请求次数不等于服务商收到请求，更不能据此推断费用。该配对没有首字，CSV 留空，不用 0 秒表示；失败耗时不能参与正常提速结论。原始请求计时与用量错误记录均保留。

之后只做了无鉴权 GET `/` 的只读连通性检查：DNS 用时 10.3 s，HTTPS 返回 404。它只说明检查时该主机可连接，不证明故障时原因或模型 API 已恢复；没有重试模型请求，也未重跑到通过。

证据：`artifacts/spec072/performance/formal-new/` 下的 `before/results.jsonl`、`after/results.jsonl` 是不可替代的原始答案、请求、用量、图像摘要和读取覆盖；`observations.csv`、`answers.md`、`manual-review.json` 是派生整理，`connectivity-after.json` 是后续只读网络检查。每臂 `environment.json` 固定源码、模型参数及原件摘要。

## 相同六页范围的批量与缓存处理

使用同一硬件、同一六页 `clauses.pdf`，每臂独立上传／存储缓存。真实 API 上传和发送、worker 文档准备、`read_document(view=pages)` 与实际图片输入装配；无模型和服务商请求，测量范围从页面工具调用开始，不包含先前上传和文字准备。本组特意要求六张页面图，与上面仅需全文文字的六页问答不同。批量为 `[1,2,3,4]`＋`[5,6]`，逐页为六次单页调用；每臂随后重复相同范围验证缓存。

| 方式         | 缓存状态 | 工具次数 | 原生处理次数 | 原生处理合计 | 工具及图片装配总耗时 |
| ------------ | -------- | -------: | -----------: | -----------: | -------------------: |
| 批量 4＋2 页 | 首次     |        2 |            6 |     39.827 s |             40.565 s |
| 逐页         | 首次     |        6 |            6 |     38.377 s |             38.976 s |
| 批量 4＋2 页 | 命中     |        2 |            0 |            0 |             396.3 ms |
| 逐页         | 命中     |        6 |            0 |            0 |             492.1 ms |

两种方式均真正装配 6 张图；热缓存六页全部 cacheHit=true、原生调用 0。批量减少了工具调用次数 6→2，但当前原生实现仍逐页处理 6 次；该次批量首读反而更慢，不能宣称批量原生渲染提速。本组首次单页原生处理约 6.4 s，是此次观测的实际成本，不能用此前单页扫描样本的 270 ms 代替，也不能将单次微基准外推为生产容量或 p95。缓存可以避免这部分重复处理；完整阅读多个必要页面仍需付出首读代价。

证据：`artifacts/spec072/performance/page-processing/{environment.json,results.json}` 与生成脚本 `page-comparison.py`；源码摘要与新增能力最终版本相同。浏览器另有同页追问命中且未新增原生调用的独立证据 `artifacts/spec072/browser/cache-observation.json`。
