# Implementation — Web 试点使用体验

2026-09-16 · 实施完成项及验证记录；最终结论由独立验收维护。

## 实施

- 公司反馈独立保存，支持本人／公司授权、分页筛选、并发提交去重、频率限制及处理修订冲突；诊断字段严格受限，不进入业务数据或模型上下文。
- Web 统一网络错误与请求编号，补同页身份隔离草稿、原请求恢复、角色示例、反馈页面和手机操作适配；30／120／180 秒请求预算，取消静默，旧身份请求与录音回调不能写回新工作区。角色与未知结果恢复细节见 Spec。
- 增量迁移 `0008_support_feedback` 在专用测试库通过；日常数据库备份到忽略的私有 artifacts 后执行同一迁移，未删除既有业务资料。开发环境通过 `npm run dev:company` 启动。

## 验证与返工

- 服务端新增反馈定向 5 项及既有安全／幂等 1 项通过，共享契约 Prettier／ESLint 通过。

- Web 相关用例共 50 项通过，覆盖 HTTP 异常、身份隔离草稿、发送快照、诊断白名单、录音、分页与单通道反馈恢复；`npm run typecheck:web`、涉及文件 ESLint／Prettier／diff 检查通过。后续修正只重跑受影响项。
- `npm run build:web` 通过（1904 modules）。未扩大为桌面构建、全仓测试或发行包检查。
- 日常 Web 人工操作：管理员登录；390×844 下空会话示例只填入、已有文字不被覆盖；1366×900 下反馈页面与可审阅诊断；用户登录后 360×780 下三个示例及仅本人反馈入口。未发送测试工作消息或调用模型。
