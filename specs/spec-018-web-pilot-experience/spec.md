# Spec 018 — Web 试点使用体验

## 状态

ACCEPTANCE · 2026-09-16。四项范围已实施，软件实现与本地验证经[独立验收](acceptance.md)通过。首版站内反馈不含截图；iPhone Safari／Android Chrome 的实体设备与 HTTPS 实测条件尚未提供，真机项目保留待验收，不代表上线验收通过。

## 背景与当前行为

公司 Web 的上报、工作确认、报告、看板与提醒已建立，本轮完善试点日常使用，不改变业务流程。

- `api.ts` 统一按 JSON 解析响应，缺少统一超时与网络错误分类；代理返回 HTML、空响应或断网时可能出现技术错误文案。401 会卸载工作区，未发送内容可能随之丢失。
- 消息已有幂等键、附件上传状态和任务反馈恢复；服务端已有请求编号，但前端没有保留用于用户反馈。
- 管理员空会话已有三个示例按钮，用户侧只有说明文字；无独立问题反馈入口。
- 已有窄屏布局、媒体格式选择、切后台停止录音与三分钟上限。视口模拟不能证明实体手机的软键盘、权限、文件选择和录音均可用。

## 目标与目标行为

用户能理解当前失败、保留尚未提交的操作并安全继续；新用户能直接开始真实上报；试点问题能够描述、提交和定位；手机完成与电脑相同的业务流程。

## 功能需求

### R1 — 网络异常体验

- Web 共用请求入口将网络连接失败、超时、401、403、429、5xx、无效响应分别转为简短中文提示和合适动作；不将 HTML、JSON 解析异常、堆栈或未经筛选的上游响应直接展示。用户主动离开导致的取消不报故障。
- 请求等待有上限，普通读取、上传、模型配置检测按实际处理预算区分；客户端超时不等于服务端取消，不把已提交但回包丢失显示成“确定未发送”。
- 网络异常时使用紧凑状态提示，正常时不常驻连接标签；浏览器联网提示仅作线索，不据此禁用所有功能。重新联网恢复当前可见数据和既有任务状态，不自动重放消息、报告提交、删除或付费模型重试。
- 同一消息的原样手动重试沿用提交快照与幂等键，回包丢失后仍只产生一条业务消息。内容变化不能复用旧请求键；结果未知时保留原提交的恢复入口，避免把修改后的输入混入前次请求。已成功上传的附件可复用，待上传或失败项有明确状态；不承诺未回包上传在磁盘上绝不产生临时孤儿文件。
- 登录过期时停止授权请求、隐藏原工作区内容，显示一次重新登录入口。同一页面内暂存未发送聊天文字及仍在内存中的附件；只有重新验证为同一公司、同一成员且权限仍有效才恢复，已保存业务数据重新读取。切换账号、主动退出或失去权限时清除暂存，不恢复密钥等敏感表单。
- 重试动作与失败原因一致：无权访问不反复重试，限流按服务端等待提示操作，列表失败可重新加载；实时订阅与轮询恢复不得叠加重复通道、拼接旧尝试正文或重复触发模型。

### R2 — 首次使用体验

- 在确认会话为空且读取成功后展示轻量角色化入口；管理员复用已有团队问答示例，用户增加记录工作、补充进展、查询本人工作的三个入口，具体短文案沿用现有产品语气。
- 示例只填入可编辑输入框，由用户主动发送；点击不创建会话、业务消息、工作或报告，不调用模型。输入框有内容时不静默覆盖，保留附件和已有补充对象。
- 用户无会话时直接输入，首条成功发送的真实消息才创建会话；有会话时继续保留现有恢复最近会话行为。不插入演示消息、虚构公司数据或冒充已经完成的工作。
- 入口只在空会话展示，开始对话后让位给消息；窄屏可触摸，桌面可用键盘操作。不新增强制教程弹窗、长篇提示或新的首页。

### R3 — 问题反馈与定位

采用用户已确认的方案：**站内文字反馈，由本公司管理员处理**。

- 在账户／帮助区域提供“问题反馈”，错误提示中提供同一入口；可填写问题描述，查看并复制本次诊断摘要。无故障也可主动反馈使用问题。
- 诊断字段限定为发生时间、前端版本（可取得时）、页面名称／路由模板、错误分类、HTTP 状态、请求编号、浏览器／系统与视口信息。不自动采集聊天、报告、文件、截图、密钥、Cookie、请求正文或完整 URL 参数；缺失字段标为未知，不伪造请求编号。
- 复用 API 返回的请求编号；服务端最小日志可按编号定位到路由模板、状态和耗时，异常记录类型，不记录业务正文或凭证。前端描述和诊断均视为用户输入，不能作为授权依据。
- 员工和管理员均可提交并查看自己的反馈；管理员额外查看本公司反馈，按“待处理／已处理”筛选，填写一条处理说明并更新状态，员工可看到处理结果。列表分页，提交防重复，输入和频率有界；本轮不增加独立平台管理员、分派、聊天式工单或站外通知。
- 反馈正文与业务来源权限独立，不因附带错误编号开放其他成员的消息、附件或系统日志。服务端校验公司／成员范围；前端隐藏入口不能代替授权。
- 断网或服务不可用时，反馈表单也必须保留当前输入，并提供“复制反馈信息”用于手动发送；没有保存成功不能提示已提交。本轮只做文字与诊断摘要，不含截图附件。

### R4 — 手机实际操作

- 以 iPhone Safari、Android Chrome 为首批适配与验证目标；微信、钉钉等内置浏览器尽量兼容，但不自动视为已验证。录音指工作助手已有的短语音消息，不新增 Web 会议录制。
- 各浏览器使用同一套 Web 页面与后端，以能力检测处理录音格式等差异；范围指优先适配与实测组合，不是浏览器访问白名单，不据浏览器名称直接阻止访问。
- 覆盖登录、首次入口、消息与文件发送、录音试听、工作确认、报告编辑提交，以及管理员看板／反馈处理；保留当前视觉、角色权限和业务状态。
- 重点处理软键盘弹出后的输入框与发送按钮、浏览器地址栏收缩、安全区、横竖屏、长消息滚动、菜单／弹窗定位。主要触摸目标至少 44×44 CSS px 或有等效可点击区域，不要求依赖悬浮操作。
- 输入框保持有上限且可内部滚动，中文候选确认不误发；沿用已确认的 Enter 发送、Shift+Enter 换行，并保留明显的发送按钮，不在本轮暗改键盘规则。
- 录音区分非安全上下文、权限拒绝、无设备和设备不可用，给出文字／文件替代路径；停止、切后台和权限请求后离开页面均释放麦克风。已交付给页面且可用的片段可试听后发送，不承诺锁屏／后台持续录音或浏览器强制回收后的恢复。
- 保留现有图片、文档、语音格式及大小限制，仅在受限时解释；不以本轮手机适配自动增加 HEIC、视频、长录音或 OCR。
- 实体手机验证记录系统／浏览器、访问地址类型及实际结果；没有可访问真机或 HTTPS 环境时，将对应项目列为未验证，不能以桌面窄屏／浏览器模拟结果代替。

## 非目标

不包含跨刷新／关闭浏览器的草稿持久化、离线发送队列、PWA、推送通知、移动原生 App、Electron 或说话人识别；不新增业务 Agent 能力、不改已确认的汇报规则。本轮不开通云资源、不执行生产部署、不引入第三方故障跟踪服务或重型 CI。

## 边界、技术与兼容性

沿用现有 Web／API／数据库、共享主题与控件。请求和会话处理不降低 CSRF、身份与公司权限；读取重试和重新登录不自动执行写操作。反馈新增独立数据表并增量迁移，保留既有用户资料；反馈不进入工作报告或模型上下文。服务不可用、身份撤销、迟到响应和多人并发均需有明确结束／恢复行为。

## 验收标准

- [x] 网络、超时、401／403／429／5xx、非 JSON 响应均有可理解的提示；主动取消不误报，错误编号可复制且不带敏感正文。
- [x] 断线及回包丢失后，原样重试不重复创建业务消息；重连／重新登录不自动发送内容或重复调用模型。
- [x] 同页过期登录后的聊天暂存仅能由原身份恢复，换号／撤权清除，私有工作区在登录恢复前不可见。
- [x] 两类角色的空会话入口可用，示例不覆盖已有输入、不自动发消息或造数据，首次真实发送与最近会话恢复无回归。
- [x] 站内反馈可提交／查看／处理，离线可复制；公司／本人授权和提交去重通过，诊断不包含敏感正文。
- [ ] 电脑与手机视口的关键操作可达，键盘／弹窗不遮挡操作；确认范围内的真机项目逐项记录，缺少验证明确列出。
- [x] 必要检查与改动相关，现有记录保留，未把完整桌面／大模型／生产部署检查加入日常 CI。

## 实测条件

- 产品决策已具备实施条件。当前未提供可控制的实体手机及 HTTPS 测试地址；先完成实现与可执行验证，真机软键盘、权限、录音和文件选择保留待实测，不冒称通过。
