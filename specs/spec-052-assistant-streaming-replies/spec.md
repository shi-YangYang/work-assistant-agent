# Spec 052：工作助手正文流式输出

## 状态

已实施。流式交付与核对截断修复的验证结果见 [验收报告](acceptance.md)。

## 背景

工作助手已有 SSE 任务反馈，但正文通常要等模型完整响应和结果核对后才出现。用户希望像日常聊天产品一样，在 AI 生成回答时逐步看到文字。

## 目标

- Web 工作助手真正边生成边显示回答，不用完整答案模拟打字。
- 正文、任务步骤、工具结果、确认卡各自保持清晰职责。
- 中断、失败、自动重试、刷新和最终结果交接不串消息、不重复文字、不闪空。

## 非目标

- 不改 Electron、报告生成或语音合成的输出方式。
- 不展示模型隐藏推理、内部审查文字、原始工具参数或系统提示词。
- 不更换 Agent 框架，不增加一次专门复述答案的模型请求。
- 不新增自动重试策略、前端定时轮询、WebSocket、Redis 或消息队列。
- 不取消业务授权、回执、引用和权限检查。

## 当前行为

- `integrations/models/chat.py` 能接收供应商 SSE，并保留 `on_text` 回调，但 Agent 当前没有把增量正文送给前端。
- `BoundedChatModel._astream()` 等完整结果再返回一个块；仅修改 `streaming` 参数不能解决展示问题。实际 HTTP 是否流式仍由已绑定的模型配置决定。
- 最终答复主要放在 `finish_task.answer` 工具参数内，普通 `delta.content` 经常只是过程内容，不能直接当作最终回答。
- 任务反馈通过 `Job.feedback` JSONB 保存最新快照，API 每 0.5 秒检查变化并经现有 SSE 连接发送。前端按任务共享连接，不需要为文字另开连接。
- 当前正文预览为空；旧展示路径使用纯文本，并会在终态或失败时隐藏。阶段更新还会重建反馈字典，不能直接加字段而忽略保留逻辑。
- 团队资料的反馈正文当前被明确屏蔽，最终结果另做引用与权限核对。

## 目标行为

### 正文与界面

1. 模型尚未输出可展示正文时，沿用现有任务状态；首段有效正文到达后，在同一个 Noria 回答区域追加显示。
2. 只显示对用户的答复。工具调用期间继续显示任务步骤，不输出工具 JSON，也不把每次模型调用都变成一条回答。
3. 生成中使用一个轻量状态提示，正文采用现有 Markdown 样式；真实到达的增量按渲染帧平滑展开，积压时加快，显示滞后保持短暂。完成、中断、撤回或权限失效时立即同步，不重播历史正文；减少动态效果时直接显示。
4. 标题、列表、代码块、表格和链接逐步成形，未闭合格式安全展示；不执行 HTML，不将半截内部引用变成可点击来源。
5. 已在底部时跟随新增内容；用户向上阅读时不强制滚回底部。输入框、发送／中断按钮、上下文按钮不随正文重挂载。
6. 等待最终核对时保留当前正文；完成后原位换成正式结果和有效引用，不先清空、不插入第二条相同答复。
7. 流式预览不能证明工作已保存、报告已提交或文件已生成。这些状态继续以服务端真实回执为准。

### 失败、中断与重试

- 普通网络或模型故障、用户主动中断：保留允许展示的正文片段，标注“回复未完成”或“已中断”，不能显示成成功回答。
- 手动重试沿用原消息原位替换：清除上一轮片段，从新一轮输出开始，不另建用户消息，不重复业务操作。
- 同一节点自动重试或答复修正：清除被替代的候选正文并增加输出版本；任务步骤展示重试状态。旧版本到达不能覆盖新版本。
- 内容审核拦截、权限／资料失效、无法安全解析的输出：撤下候选正文，沿用明确错误提示；保留片段不是绕过这些失败的手段。
- 断开浏览器连接不等于取消后台任务。沿用现有断线提示和一次恢复同步，不增加循环重连、自动重发消息或定时 GET。
- 刷新或切换会话后按服务端快照恢复；未完成片段只供当前消息展示，不进入正式聊天历史上下文、跨会话记忆或下一轮压缩材料。

### 可流式范围

- 模型配置启用了流式、且可以识别最终正文时，普通问答、写作、公开资料搜索、个人材料分析等支持实时输出。
- 涉及团队／其他成员资料的答复，本期保留现有完整权限和引用核对后再显示的边界；不把完整答案拆成动画冒充实时流式。
- 业务操作卡片仍在参数完整、授权和实际执行结果成立后显示；预览出现不触发执行。
- 显式关闭流式的模型、历史缓存恢复、无法识别增量收尾格式的兼容响应，继续一次性交付；不擅自修改管理员模型配置。
- 普通正文转为 `finish_task` 的协议补齐仍可流式展示 `answer`；只允许收尾，不重做业务操作。内部专项核对、引用纠错和遗漏操作修复仍不直接外显，通过后用正式结果替换候选正文。需要进一步放开团队资料流式时，另行确认该输出边界。

## 功能需求

### 1. 可复用的流式分层

- 模型适配层负责协议、增量事件、完整响应装配及错误分类，不引用业务工具名或数据库。
- Agent 输出层负责识别 `finish_task.answer`、限制可展示范围及候选版本，不执行未完成工具。
- 任务反馈层负责租约、权限、节流、快照和终态，不重新实现模型协议。
- Web 层消费快照并渲染，不通过模型原文猜测成功、授权或业务状态。

### 2. 正文选择与完整性

- 在识别出唯一候选 `finish_task` 后，增量解析它的顶层 `answer` 字符串；只发送已正确解码的完整文本片段。
- 正确处理任意切块、转义引号、反斜线、换行和 Unicode；字段乱序不能影响提取。重复键、多个收尾调用、与其他工具混用或损坏参数要撤销候选并走既有错误流程。
- 其他工具参数、同次调用的伴随 `content`、核对模型输出不进入答案区。
- `[DONE]`、结束原因、完整 JSON、收尾契约和工具参数验证仍然必须完成；任何片段都不能提前执行工具或写入业务记录。
- 不复用遇到任意 `[`、`<`、`{` 就截断的旧预览规则；合法 Markdown 和代码必须保留。内部引用在完整解析且验证前不激活。

### 3. 快照与交接

- 使用任务已有 JSONB 和 SSE 快照；不每个 token 新增数据库行，不建立文件副本。
- 正文有独立输出版本，结合现有 `jobId / attempt / fence / seq` 识别新旧。节点进展和上下文统计更新不能清空当前正文。
- 快照包含当前完整前缀，可跳过中间快照；客户端替换前缀而非重复拼接，不依赖收到每个网络分片。
- 每次正文更新仍验证任务租约；取消、输入版本变化、删除和权限变化后，迟到输出不能继续写入或展示。注销后旧登录会话不能继续订阅、读取或显示预览；后台任务沿用现有处理规则，不因本功能新增注销取消行为。
- 正式消息落库后再发布终态。前端保留预览直到同一轮正式结果到达；最终 GET 暂时失败也不能闪空或重新显示旧轮结果。

### 4. 性能

- 首段和末段即时刷新，其余写入按约 200 ms 合并，每个活跃任务最多约 5 次正文快照写入／秒；不按 token 写库。
- 沿用一个任务一条共享 SSE、当前约 500 ms 的服务端检查节奏，不增加浏览器请求数量或长事务。
- 受控本地流式响应中，首个可展示片段被服务端识别后 1 秒内出现；至少两个可区分前缀在供应商结束之前可见。
- 供应商可能延迟或一次性吐出内容，不承诺首 token 的外部服务耗时；不靠额外动画掩盖这一点。
- 有界保存最新文本，不保存累计的所有前缀；沿用正文长度和请求预算限制。

## 边界条件

- 空回答、仅工具调用、只有确认卡、临时提问、非流式服务：维持现有交付能力。
- 断流前产生完整外观的工具参数，也必须等合法结束后才能执行。
- 自动重试、人工重试、worker 重启／租约转移、缓存命中分别测试；业务副作用不得重复。
- 任一流未完成时退出账号，旧登录会话在下一次授权检查后停止接收并清除预览；删除会话或撤销资料访问后停止输出并清除不可再展示的候选。已在浏览器显示过的内容无法通过后续撤销使其“从未被看见”，因此团队资料不提前展示。
- 两个账号、多会话同时运行，不共享候选正文。取消会使 fence 更新，旧正文只能以服务端重新封存的“已中断”快照保留，不能接受旧 worker 的后续增量。
- 历史消息没有新字段时按现有方式展示；管理员和员工不新增不同的发送入口。

## 技术约束与兼容性

- 只改 Web 工作助手及其调用链，共用模型客户端新增能力默认关闭，报告和模型测试保持原行为。
- 只增加可选 DTO 字段；旧数据不迁移，当前方案不新增表或 migration。
- 前端继续使用共享订阅、统一请求身份处理、现有 Markdown 和 CSS Modules。
- 预览属于未确认结果，不能绕过引用校验，不能从预览产生业务动作或自动记忆。
- Caddy 已有 `flush_interval -1`，API 已设置 SSE 非缓存响应头；以代理链路验证决定是否需要定向修正，不能假定必须改部署配置。

## 验收标准

- [x] 长回答在供应商响应结束之前显示多个递增前缀，非完整答案打字动画。
- [x] 普通聊天、公开检索后回答、带个人材料的回答均覆盖；工具执行阶段不泄露参数、内部核对或推理文本。
- [x] Markdown、中文／emoji、转义字符和拆开的 JSON 字符串不乱码、不截断正常代码、不产生可执行 HTML。
- [x] 消息任务、节点、自动重试及最终消息状态一致；无正文闪空、重复回复或旧版本复活。
- [x] 手动中断、网络中断、供应商拦截、修正回答、刷新恢复按本规格的规则展示。
- [x] 业务修改只发生一次，未完成工具不执行；团队资料及权限失效场景不提前暴露正文。
- [x] 不增加重复 SSE、轮询 GET、自动 POST；页内多订阅复用同一连接。
- [x] 桌面／手机可读，自动滚动只在原本靠近底部时发生，输入区和操作按钮不闪烁。
- [x] 代理链路下确实逐步到达，兼容非流式配置和旧消息。
- [x] 验证按分层定向测试执行，记录真实模型验证与受控协议测试的区别。
