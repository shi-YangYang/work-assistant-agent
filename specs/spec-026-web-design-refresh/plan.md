# Web 设计改造实施计划

需求与范围见 [功能规格](spec.md)，视觉依据见 [设计基准及原型](../../docs/design/README.md)。原型只用于比较外观与交互，不替换正式数据流。

## 涉及模块与顺序

| 阶段 | 主要位置（相对 `apps/web/src/`） | 实施内容 |
| --- | --- | --- |
| 1. 页面基线 | `app/AppRoutes.tsx`、`app/navigation-items.ts`、现有浏览器页面 | 核对两类角色的路由、子视图、弹层和关键操作，记录代表性改造前截图；用当前源码补足原型未覆盖的功能 |
| 2. 主题与公共组件 | `styles/theme.css`、`base.css`、`select.css`、公共 Module；`components/` | 映射中性灰语义变量，统一控件、折叠、列表、详情、错误与弹层；补齐危险状态和键盘焦点，保护登录页作用域 |
| 3. 应用框架 | `app/{Shell,Sidebar,Topbar,Breadcrumbs,AppRoutes}` 及各自 Module | 内嵌主画布、紧凑导航与设置入口、通知及命令面板；调整滚动所有者、菜单层级与移动导航 |
| 4. 工作助手 | `features/assistant/`、`features/jobs/components/JobNotice.tsx`、`features/sources/` | 拆分用户与助手的视觉结构，整理处理过程、引用、业务确认、输入器与媒体布局；展示组件按职责提取，保留原 Hook 生命周期 |
| 5. 工作、报告与团队 | `features/{work,reports,team,members,records}/`、`pages/`、公共 Record 组件 | 列表工具栏、空状态、详情与管理表单统一；保留所有筛选、分页、编辑及授权操作 |
| 6. 设置 | `features/{model-services,settings,feedback,voiceprints}/`、认证模块的 `LoginMethods`／配置组件 | 模型服务、用途、参数和测试反馈优先，再覆盖全部设置与管理页面；不改登录书本和认证回跳 |
| 7. 收尾 | 实际修改的 Web 组件及测试 | 清理被本次替代且无使用者的样式，完成各页面状态与适配核对，不建立新旧两套运行时主题 |

主题、公共控件和各业务的层叠关系高度相关，由一个实施 Agent 按以上顺序推进，再交新的独立验收 Agent；不让多个实施者同时修改公共样式。实施过程中优先展示工作助手、列表与模型服务的真实页面，及时对照基准，不等全部完成后才看界面。

## 实现边界

- 保留 `app → pages → features → 基础层` 依赖，组件引用自己或明确共享的 Module。主题变量和基础控件是 Web 内部复用点，不创建跨端样式包。
- 现有 `--accent` 等变量可映射新语义值，按实际需要补充层级变量；同时检查硬编码蓝紫色、状态色及局部覆盖，不用末尾巨型覆盖表或大量 `!important` 补救。
- 消息的用户内容、助手正文、反馈、来源和业务操作仍消费同一条真实消息及当前状态；可提取呈现组件，不能复制请求、订阅或权威状态。
- `data-scroll-container`、`data-chat-content`、ref、Portal／dialog 层级和焦点返回具有行为用途，布局调整需同步其实际所有者。不可用修改 React key／重挂载来强制刷新样式。
- 复用现有主题偏好。若提取主题切换逻辑，由单一所有者处理系统变化与持久化，避免顶部操作、外观页和初始化各持一份不同状态。
- 菜单、选择器和动效先用现有浏览器能力及项目组件；增强能力做特性检测与退化，不因追求动画引入一整套库。
- 整理模型配置布局时保留 `useServiceDraftSession`、`useServiceCheck` 的状态与失效判断。输入、测试、保存各自反馈清楚，不把布局调整扩展成协议变更。

## 数据流、接口与迁移

仍使用现有业务 API、唯一请求客户端、身份与草稿管理、消息实时反馈和报告／工作操作。URL、请求响应、公司权限、数据库与存储键不变，不需要数据迁移。原型中的按钮必须映射到已有可执行能力，缺少能力的演示入口不进入正式产品。

本次预期只修改 `apps/web/src/` 及直接相关的 `tests/web/`。设计基准仅在实际需要补足缺失语义时更新，不复制一份 Decision；归档原型保留为参照，不随实施改成“与成品一致”来规避视觉差异。

## 验证计划

Spec 文档按 **S0**，仅检查 diff、引用与范围一致性。实施按 **S3 的 Web 范围**：主题、基础控件、应用框架和全站布局共同受影响，需要完整 Web 检查，不等于全仓库验收。

- 修改时用项目 Prettier 整理本次文件；存在行为改动时优先运行对应测试，纯样式不新增复述实现的测试。
- 最终代码运行一次 `npm run test:web`、`npm run typecheck:web`、`npm run build:web`；ESLint 限 `apps/web/src` 与相关 Web 测试，格式检查限本次改动文件。已经在最终代码通过的检查不重复执行。
- 保留已有架构、权限入口、表单、会话隔离、草稿与查询测试的有效断言。定位方式改动时优先使用角色、标签和稳定语义属性，不绑定 CSS Module 哈希或删除断言求通过。
- 在用户现有本地环境查看真实页面；需要数据写入时使用可识别且可清理的本地测试记录，不改用户业务、模型配置或密钥。固定响应可用于稳定构造失败／流式／确认状态，但应标注，不能声称真实模型联调已通过。
- 不默认调用付费模型、跑全量后端／桌面测试、下载模型、打包 Electron 或触发 CI。本次未改后端、桌面或协议时无这些检查依据。

## 页面与交互核对

截图放 `artifacts/spec026/`，按实际路由和状态命名；在验收记录内列出覆盖与未测项，不另建重复测试报告。每个页面组覆盖下列内容：

| 范围 | 核对重点 |
| --- | --- |
| 框架与导航 | 主导航、系统设置、面包屑、命令搜索、通知、账号；直接链接、前进后退、菜单定位及键盘操作 |
| 助手与来源 | 空会话、有消息、实时正文、工具／引用展开、确认与冲突、失败重试、附件／转写／PDF；发送不闪烁、草稿恢复、历史阅读不跳动 |
| 工作、报告与详情 | 空数据与筛选无结果、有数据、分页、长标题、字段错误、编辑／提交／删除确认、详情返回位置 |
| 团队与成员 | 工作／汇报页签、统计与明细范围、角色入口、成员创建／密码／删除；选中与禁用可辨认 |
| 模型服务与用量 | 无服务／已有服务、服务编辑／切换、模型选择与参数、测试结果、用途分配、未保存保护、错误／冲突、用量表格 |
| 其余设置 | 账户、外观、汇报规则、登录方式、声纹、反馈的查看／编辑／错误；折叠展开、下拉和弹窗 |
| 认证回归 | 翻书关闭／打开／直接登录、表单校验、正常登录、会话过期；钉钉回跳和桌面授权组件不受主题／全局样式污染 |

所有有效页面和主要子视图至少查看桌面 1440px 与手机 390px，不只查看原型中的五个页面；浅／深主题按页面组覆盖，核心助手、公共控件及弹层两种主题均看。补 900px 导航过渡、320px 窄边界和短高度的关键组件检查，不要求所有状态、尺寸、主题做笛卡尔积。

重点检查横向溢出、重复滚动条、截断菜单、输入区域闪烁、焦点丢失、灰字对比度及仅悬浮可达的操作。手机视口模拟与软键盘相关代码检查不标为实体手机验收；无法完成的真机或外部授权步骤如实列明。

生产构建后抽查应用框架、助手、列表、模型服务弹层和登录页，确认 CSS 产物、静态资源与直接路由加载有效。截图核对和实际交互共同判断，不能以构建通过代替视觉验收。

## 风险与回退

主要风险是公共变量改变影响登录、层叠覆盖残留、消息 DOM 调整破坏滚动与订阅、弹层继承失效，以及模型表单因组件重挂载丢失草稿。按模块完成后及时核对对应行为；修复实际归属与生命周期，不累加全局补丁。

回退仅涉及本次 Web 源码及关联测试，无数据回滚或服务端部署步骤；保留已有用户修改。验收只评价本次范围，不把历史未验证的桌面事项算成本次阻塞或已通过。
