# Web 界面与交互统一改造

## 背景与当前行为

Web 已完成业务模块拆分与 CSS Modules 隔离，但正式页面仍使用偏蓝灰的主题、蓝色强调和较重的卡片边界。工作助手把用户内容、处理过程和助手回复装在同一消息区域，列表、报告和设置的层级与间距也不统一。

新的中性黑白灰原型已归档到 [UI 设计基准](../../docs/design/README.md)。本次把该设计落实到真实 Web，色值、圆角与动效细节引用基准，不在本 Spec 复制另一套定义。

## 目标

- Web 的应用框架、业务页面、设置及弹层采用已选定的设计，覆盖浅色、深色和手机浏览器。
- 让用户消息、助手回答、处理状态、引用来源和业务操作形成清楚的阅读顺序。
- 统一列表、详情、表单和空状态，保留现有业务能力与使用习惯。

## 非目标

不改造 Electron 或原生手机 App，不重做翻书登录页，不新增业务、模型能力或后端接口；不更换前端架构、认证、状态管理和 UI 技术栈。不把原型的内存导航、假数据、模拟成功或演示角色切换带入产品。

## 目标行为与功能需求

### 应用框架与公共控件

- 桌面采用原型的紧凑侧栏、轻量顶部导航和内嵌主画布；主内容随可用宽度伸展，聊天正文可限制阅读行宽，列表和设置不能被统一窄宽度限制。
- 侧栏保持现有角色入口；设置通过紧凑二级入口组织，避免展开后挤占全部主导航。保留通知、账号入口、退出、命令搜索及多级面包屑。路由、默认落点与深链接不变。
- 每页只有一个主标题，主操作与标题就近排列；筛选、列表、分页形成整体。主要滚动发生在内容区域，避免页面与内层双滚动；聊天输入区、列表工具栏保持可用。
- 统一按钮、搜索／输入／选择／日期时间控件、页签、状态标签、折叠区、菜单、Tooltip、弹窗、错误及加载反馈。鼠标焦点不出现带间隙的紫色外圈，键盘焦点仍清晰可见。
- 采用中性灰阶和反色主操作，语义色限于真实状态；错误、危险操作和字段校验补齐浅深主题样式，不仅用颜色表达含义。Logo、钉钉等品牌资源保留，不为了黑白配色替换品牌。
- 普通内容不反复套白色卡片。折叠用于较长详情和次要信息，主操作、错误、待确认事项和用户正在编辑的内容不能默认藏起。

### 工作助手

- 用户正文采用反色气泡，助手回答在主画布上排版；时间与身份弱化，附件、转写、来源和操作保持清楚归属。视觉拆分不拆散原消息的数据关系。
- 工具执行和引用采用可展开的紧凑摘要；只展示已有接口返回的受控信息，不虚构推理过程、进度百分比或完成结果。等待、运行、待确认、成功与失败可辨认。
- 业务确认卡呈现操作对象、关键内容和确认／取消入口；保留修改、忽略、冲突恢复及执行回执等既有能力，不能把 UI 动画当作业务完成。
- 输入器沿用稳定工具栏与有上限的输入高度。语音、图片、文档分类展示，播放器有足够操作宽度；保留粘贴／拖拽、预览、上传进度、删除附件和错误恢复。
- 保留空会话直接发送后创建会话、历史会话管理与返回恢复、草稿、Enter 发送及中文输入法处理。空状态快捷入口只使用已有操作或填入可编辑文字，不自动发出演示消息。
- 保留实时正文、处理反馈、停止／重试、补充、转写修正、来源定位、业务授权失效提示。新消息可短暂入场，生成过程不反复播放整段动画；发送、刷新、切换主题不闪烁输入器或重置焦点。
- 保留阅读历史时的滚动位置与新回复提醒，不以自动滚到底打断阅读。诊断摘要继续只在助手错误中按需展开，其他页面正常展示错误。

### 业务页面与设置覆盖

原型展示了主要页面，但不是完整功能清单。以下现有入口全部适配，未展示的子页面沿用同一设计语言：

| 页面组 | 覆盖与保留能力 |
| --- | --- |
| 工作助手与消息来源 | `/assistant`、`/assistant/:conversationId`、`/messages/:id`；会话选择、消息、业务确认、附件与来源预览 |
| 我的工作 | `/work`、`/work/:id`；创建、完整搜索、状态筛选、分页、编辑、进展、来源、删除及详情返回 |
| 我的报告 | `/reports`、`/reports/:id`；汇报待办／全部报告、日／周类型、期间与状态、生成、编辑、提交及按权限删除 |
| 团队看板 | `/team` 的工作／汇报视图、统计与筛选、成员及业务详情；既有旧链接重定向继续有效 |
| 成员管理 | `/members`；创建、字段校验、启停用、重置密码、删除及现有授权限制 |
| 模型服务与用量 | `/settings/models`、`/settings/usage`；服务管理、获取／手动添加模型、推理预设与参数、协议选择、测试、用途分配、用量筛选与分页 |
| 其他设置 | `/settings/account`、`appearance`、`rules`、`login`、`voiceprints`、`support`；账户改密、主题、汇报安排、钉钉配置、声纹登记管理、问题反馈 |

- 列表具备紧凑可读的行与操作位置，空数据和筛选无结果分别解释，不展示无效分页；有数据时不能因长标题、姓名或状态挤压主要信息。
- 详情的标题、状态与操作就近排列，正文获得主要空间；保留来源、历史和返回时的筛选／分页／滚动位置。
- 模型服务保留“服务及模型配置”和“用途分配”的清晰边界，步骤与当前编辑对象明确；高级选项可折叠，保存、测试结果和字段错误就近呈现。服务切换、未保存密钥保护、配置冲突和草稿恢复不退化。
- 手机把必要的多栏改成单栏或抽屉，不直接缩小桌面；筛选可收纳但应显示当前条件，重要操作不能仅悬浮可见。

## 边界条件与兼容性

- 保留浅／深／系统跟随、已有主题存储键和默认值。系统主题变化、刷新与直接打开页面应一致；登录书本的独立配色、动画、焦点和无外层滚动表现不受基础样式修改影响。
- 不改变管理员／员工可访问范围。品牌名继续使用“公司工作助手”，不复制原型的角色切换、示例人数或未接入的入口。
- 不改变请求客户端、账号隔离、会话过期处理、跨页草稿、数据校验、提交确认、版本冲突、记录删除与来源失效等行为。
- 菜单和弹层不被父容器裁切，视口边缘可翻转；短窗口、长文本、软键盘、安全区和浏览器缩放下关键操作可到达。
- 保留现有浏览器兼容范围：不依赖仅部分浏览器支持的选择器／动画 API 才能操作。遵循减少动态效果偏好；输入、焦点、选中和错误信息可由键盘及辅助技术识别。
- 登录、钉钉回跳及桌面授权的业务流程不变，本次只做受公共样式影响的回归核对，不重新设计这些独立认证页面。

## 技术约束

沿用 React、TypeScript、Vite、Lucide 与现有组件；不新增 BeUI、Tailwind 或动效框架依赖。参考其效果，通过当前技术栈实现。代码继续遵循 [Web 模块与样式边界](../../docs/architecture.md#web-前端组织)，公共组件只处理表现和交互，业务流程留在原有 feature／Hook 中。

Web 自己维护主题与 CSS Modules，不导入 Electron 私有样式；不把原型的大型演示 TSX 或全局 CSS 直接复制为生产结构。允许为真实复用需求提取展示组件，不顺带重构 API、数据库或 Harness。

## 验收标准

- [x] 原型已覆盖的页面在相同主题与尺寸下，配色、空间层级、消息结构、控件与动效方向一致，不能仅替换主题色。
- [x] 表中所有页面及主要子视图完成适配，管理员与员工入口完整，空／有数据、加载／错误可辨认。
- [x] 工作助手发送、实时反馈、附件、确认、重试与历史阅读正常，输入器无瞬时重挂载／闪烁，真实业务结果不由假数据替代。
- [x] 工作、报告、团队、成员与模型服务的现有操作及表单校验可用，草稿、筛选和返回状态不丢失。
- [x] 桌面与窄屏逐页截图核对；浅深主题、关键弹层、长内容、短高度和手机输入区无溢出、遮挡或无法操作。
- [x] 登录页视觉与真实认证流程保持；Web 与 Desktop CSS 边界不被破坏。
- [x] Web 测试、类型、限定范围 Lint、改动文件格式和普通生产构建通过，浏览器交互及生产产物抽查有记录；未执行项如实说明。

## 待确认问题

无阻塞项。视觉以已选定的归档方案为准；本 Spec 覆盖 Web，后续其他端单独实施。
