# Spec 009 — 公司级模型服务管理

## 状态

ACCEPTANCE · 2026-09-12。实施与独立工程复验已通过，首次发现的检测撤销缺陷已关闭；真实供应商联调仍待用户配置与授权，详见 [验收报告](acceptance.md)。实施方案见 [Plan](plan.md)，技术取舍见 [决策 0012](../../.ai/decisions/0012-company-model-services.md)。

## 背景与当前行为

[Spec 008](../spec-008-meeting-followup/spec.md) 已实现员工上报、业务 Agent、进展确认、日报／周报和老板看板。服务端目前从环境配置读取模型地址、密钥、模型 ID 与有限参数；工作助手和报告共用一个模型，语音识别仅有百炼 Qwen-ASR 兼容调用。更改配置需要运维操作，Web 没有模型服务管理入口，真实外部服务联调仍待完成。

Electron 已有多服务、模型目录、自定义推理预设和连通性测试。本轮延续其使用体验，服务端独立管理公司配置与凭证。

## 目标与目标行为

管理员在 Web 保存服务 → 获取或填写模型 → 配置推理预设并测试 → 为工作助手、报告、语音选择模型 → 员工继续使用原有上报流程。

管理员日常调整服务不再编辑服务器环境文件或重启进程；员工无需提供自己的 Key。真实模型联调补齐 Spec 008 的相应证据，不重新实现已经完成的汇报流程。

## 功能需求

### R1 — 公司共享配置与管理权限

- “模型服务管理”仅向老板／管理员开放，由服务端校验角色与公司归属。公司内管理员共同维护同一组配置，员工不能枚举配置、获取模型目录、测试服务或改变用途分配。
- 可新增、编辑、删除多家服务；每家保存名称、Base URL、密钥和模型配置。服务名称只是标签，不决定厂商、模型能力或推理参数。
- 密钥为只写字段。已保存后只显示“已设置”，不返回明文或可复制的密钥；可替换。编辑时留空仅在同一服务及地址不变时保留旧密钥，更换地址必须重新输入，不能把旧密钥发送给新接收方。
- 保存和测试分开。保存失败保留当前有效配置与编辑草稿；并发修改提示版本冲突，不能覆盖另一位管理员的新设置。删除前列明受影响用途；被选用的服务须先解除或更换分配，历史工作和报告不随服务删除。

### R2 — 模型目录与配置

- 管理员可按当前地址和密钥主动获取模型目录；支持搜索并选择 ID，也允许手动填写目录未提供的模型。刷新为空、请求失败或模型从目录消失，不自动清空原选择或改用其它模型。
- 目录来源、当前手动值和检查状态清楚区分。目录可见不代表具备生成权限、图片理解、工具调用或语音转写能力；不根据名称、品牌或列表成功推断能力。
- 地址、密钥、服务、模型或参数变更后，过期目录和测试结果不能冒充当前配置的结果。异步返回必须绑定发起时的草稿版本，切页保留非敏感编辑，取消／退出后清除未提交密钥。
- 首版接入已确定的兼容协议，具体范围见 Plan；不承诺任意厂商的私有接口都只需更改 URL 即可使用。目录不可用时保留手动配置入口。

### R3 — 推理预设与请求方式

- 沿用 [决策 0008](../../.ai/decisions/0008-meeting-minutes-provider.md)：每个服务／模型可保存多个自定义推理预设。简单模式填写推理强度字符串，高级模式填写有边界的 JSON；不维护逐厂商、逐型号的强度枚举。
- “服务默认”表示不附加推理参数，不能自动加入 `enable_thinking=false` 或猜测默认档位。切换模型恢复该模型自己的预设，不沿用上一个模型的参数。
- 新增聊天模型配置默认启用“使用流式接口”，可关闭；已有环境配置导入时保留原来的非流式行为。语音接口按其协议配置，不继承聊天模型的推理预设。
- 流式指服务端接收方式；本轮工作助手仍在结果完整、校验完成后展示回复和待确认进展，不新增逐字输出或展示模型思维链。流式工具调用须完整组装后才能执行，断流不得将片段当作成功结果。
- 自定义参数不能覆盖输入、模型、凭证、工具、传输或资源限制；不支持的参数明确报错，不悄悄删除参数、切换协议或降档后再次付费调用。

### R4 — 按业务用途分配模型

| 用途 | 选择方式与所需能力 |
| --- | --- |
| 工作助手 | 选择服务、模型、预设和请求方式；处理文字、图片及转写后的内容，需要文本、图片输入与工具调用 |
| 报告生成 | 默认明确显示“同工作助手”，也可单独指定；仍经现有业务 harness 保存草稿，需要文本与工具调用 |
| 语音转写 | 独立选择服务、模型与语音接口；输出可纠正文字后交给工作助手 |

- 同一家服务可用于多种用途，三个用途不要求三组不同密钥。选择服务不等于自动切换所有用途，用途设置单独保存并显示有效配置。
- 允许只配置部分用途；相应未配置功能明确说明原因，员工已经发送的原始材料保留。不得改用另一家服务、Electron 密钥或隐藏默认模型。
- 新任务开始处理时固定一次配置。修改用途只作用于之后开始的新任务；执行中不能悄悄更换模型、参数或接收地址。配置变化后的恢复规则见 Plan，管理员测试不生成员工消息、工作或报告。

### R5 — 测试与反馈

- 提供“获取模型”和“测试配置”两个独立操作。测试使用当前待保存配置；开始前清楚显示接收服务及所测用途，说明会发送小样本并可能计费，用户主动点击后执行，不在输入、保存或打开页面时自动调用。
- 按用途测试真实需要的能力：工作助手核对文本、固定图片和受控工具往返；报告核对文本与受控工具往返；语音核对固定中文短音频的实际转写。每项显示通过、失败或未测试；测试工具没有业务写入权限。
- 结果显示服务、模型、配置版本、时间、耗时及可操作错误。区分地址／网络、鉴权、额度、协议／参数不支持、无效响应、超时与断流；不得将完整服务响应或凭证直接呈现给员工。
- 单次测试不自动重跑、自动换模型或批量扫描全部模型。测试与业务调用有相同的超时、并发和用量边界；有返回用量则如实记录，未知费用不能显示为零费用。
- 允许保存未测试配置，同时保留“未测试”提示。测试通过只代表该配置完成了相应样本，不能宣称所有任务质量、所有模态或厂商全部模型均已验证。

### R6 — 页面与操作连续性

- 以当前 Electron 及刚对齐的 Web 为视觉基准，遵循 [决策 0009](../../.ai/decisions/0009-interface-design-direction.md)：侧栏底部设置、紧凑面包屑、单个主标题、canvas 背景与 surface 内容面、统一控件和选中反馈。
- “模型服务管理”分为“服务配置”“用途分配”两个页签；服务配置内先选服务，再编辑连接、模型与预设，高级参数可折叠。避免把所有服务、所有模型和三类用途堆成长表单。
- 电脑保留稳定服务列表与编辑区；手机按服务列表→服务详情进入单列编辑，返回保留当前草稿。模型搜索和预设菜单依附触发器，长 ID／预设名可读，不出现左上角弹层或横向溢出。
- 跨页面保留普通草稿；未提交密钥只在当前管理页面内存使用，不进入通用草稿存储、localStorage 或浏览器地址。离开含未保存密钥的页面提示保存或丢弃；退出登录、会话失效或角色失去管理权立即清除。

## 边界条件与兼容性

- 服务端承担加密凭证存储和对外访问；首期面向可信部署方管理的 HTTPS 模型端点，不开放匿名代理。具体密钥文件、出站边界与备份要求见 Plan。
- 保留 Spec 008 的人工确认、材料来源、任务幂等、超时与失败重试规则；替换模型不能改变员工权限，不能自动确认进展或发布报告。
- 现有环境配置提供一次显式导入入口，导入前展示不含密钥的概要；不自动覆盖公司配置。导入成功后以数据库分配为准，清空用途不重新落回环境变量。未导入时现有环境模式保持可用并明确显示来源。
- Electron 服务、密钥、本地会议、转写模型和启动方式保持独立，不自动同步或上传。本轮不迁移项目目录、不重做 harness，也不增加默认重型 CI。

## 非目标

自动模型路由／失败切换、员工个人 Key、计费结算系统、任意代码或 HTTP 请求模板、所有厂商原生协议、实时语音对话、逐字回复、RAG、画像、会议同步，以及云资源开通和公司正式部署。

## 验收标准

- [x] 管理员完成多服务保存、密钥替换、模型发现／手填、预设切换和三类用途分配；员工与跨公司请求被服务端拒绝。
- [x] API、日志、草稿、数据库明文字段和 checkpoint 不出现原始密钥；换地址不沿用旧密钥，密钥保护不可用时明确失败。
- [x] 三类测试使用所选版本与对应接口，实际检查输入与结果；不产生业务记录，不把目录成功当作业务测试通过。
- [x] 新配置无需重启即可用于新任务；处理中编辑、重试、重启恢复和服务删除遵循固定配置与来源规则，无静默改投或重复业务写入。
- [x] 流式和非流式文本／工具调用、断流、用量限制及自定义预设边界有定向证据；“服务默认”不注入厂商特定参数。
- [x] 环境配置显式导入、空配置、部分用途配置、版本冲突与设置备份恢复可验证，已有员工材料及 Electron 数据保留。
- [x] 浅深主题、手机与电脑布局、长模型 ID、预设菜单、草稿和会话失效行为满足 R6。
- [ ] 在授权服务上跑通中文文字、图片、短语音、连续补充／纠正、报告人工提交和老板查看，并核对事实与来源；固定响应与真实服务结果分别记录。

## 待确认与联调准备

用户已确认多服务、自定义预设、两类角色、跨端风格、首版协议范围和任务恢复方式，并授权实施；不重复询问已确认决策。

首次真实联调所用服务、模型、可用额度和账号由用户在管理页面配置，密钥不发送到聊天；由用户发起测试，或另行授权 Agent 使用固定样本联调。不具备条件时如实保留该项未验证，不用模拟响应替代。准备真实服务不阻止无外部依赖的业务实施。
