# Spec 051：工作助手跨会话记忆

## 状态

已实施，独立验收通过。验证范围及模型语义限制见 [验收报告](acceptance.md)。

## 背景

Noria 应逐步理解用户的背景、习惯、目标和做事方式，让用户换一个对话也不用重新介绍自己。本期先完成类似 ChatGPT 的个人记忆体验，不接入 RAG、embedding 模型或向量数据库。

参考 [ChatGPT 记忆说明](https://learn.chatgpt.com/docs/customization/memories)中的跨对话使用和用户管理体验；不假设其内部实现。

## 目标

- 记住有长期价值的用户信息，在同一账号的不同会话中自然使用。
- 支持自动记忆、明确要求记住、纠正和忘记；用户通过一份可编辑的 Markdown 记忆文档直接管理。
- 使用现有 PostgreSQL 与工作助手聊天模型，控制上下文体积和额外调用。

## 非目标

- 全量历史对话检索、知识库、RAG、embedding、向量数据库。
- 完整数字分身、心理画像、管理员查看员工私人画像。
- 主动定时行动、记忆驱动的自动汇报、修改三级执行权限。
- Electron 本地会议记忆、企业公共记忆、临时聊天模式。

## 当前行为

- `ConversationContext.payload` 保存单个会话的上下文；任务 checkpoint 用于单次任务恢复。
- 人设控制表达，执行权限已按账号共享，但没有独立的个人长期记忆。
- 新会话不会自动获得其他会话中的个人偏好和背景。

## 目标行为

| 用户行为 | 结果 |
| --- | --- |
| 在对话 A 说“以后给我方案先写结论，尽量少用表格” | 保存偏好；对话 B 请求方案时自然应用 |
| 说“我负责产品设计，最近在推进 Noria 的上线” | 可记住职责和持续目标，不保存成具体工作记录 |
| 说“这一次详细解释，并用表格比较” | 当前要求优先，不因此覆盖长期偏好 |
| 说“我现在负责运营，不做产品设计了” | 更新已有信息，不并列保留互相矛盾的职责 |
| 说“忘掉我负责运营这件事” | 删除对应记忆，成功后才告知已忘记 |
| 在“我的记忆”文档中增删或修改内容并保存 | 同一账号其他会话的后续请求使用保存后的内容 |
| 关闭记忆 | 停止向模型提供记忆和对话中的记忆写入，保留已存文档 |
| 删除对话 A | 已保存记忆保留；通过记忆管理单独删除 |

## 功能需求

### 1. 记什么

- 默认开启。自动保存明确、有持续价值的个人背景、交流偏好、工作习惯、持续目标，以及用户明确表达的判断原则和取舍。
- 不要求固定说“记住”；普通交流也可以形成记忆。模型判断语义，不维护案例关键词白名单。
- 不自动保存问候、一次性问题、临时情绪、单次任务指令、引用示例、虚构角色或未经用户认可的推断。
- “最近”“这个项目”等范围必须保留；明确有效期的信息到期停止使用。不把临时背景变成永久性格。
- 不保存密码、验证码、密钥等凭证。不从员工材料或聊天内容推断敏感身份、健康、心理等画像；涉及敏感个人信息不得自动记忆。
- 网页、附件、工具结果和助手自己生成的内容不能自行变成用户记忆。用户明确采纳某个约定时，可以结合当前会话理解其指代。

### 2. 怎么记与更新

- 复用当前聊天模型，通过专用记忆工具保存／更新／删除；前后端管理和 Agent 工具共用领域服务。
- 不为每条消息增加独立的提取模型调用，不增加后台扫描全部聊天的任务。
- 工具写入必须关联本轮用户输入，服务端校验消息归属及来源；历史上下文只能帮助理解，不能作为重新学习已删除记忆的唯一来源。
- 相同含义合并；明确纠正更新对应内容。一次性例外不覆盖长期偏好；确有冲突且无法判断时才询问。
- 用户和 AI 维护同一份文档，没有互相独立的“用户记忆”和“AI 记忆”。用户可以自由增删段落、改标题、调整顺序，不要求固定模板。
- 用户手动编辑的内容优先于自动推断；AI 只做必要的局部追加或修改，不整篇重写、自动改排版或恢复用户删除的内容。后续明确要求修改仍可更新相应片段。
- 成功保存／删除后，复用现有工具反馈表达结果，不新增 toast、确认卡或强制追问。失败不能回答“已经记住／忘记”。
- 记忆工具遵守现有节点重试机制，具备幂等与版本检查；不建立另一套自动重试或轮询。

### 3. 跨会话使用

- 按 `company_id + owner_id` 读取当前账号的记忆，与人设分开；切换人设、新建会话、刷新和服务重启后仍有效。
- 记忆作为可纠正的用户背景注入实际模型请求，不作为系统指令、业务事实凭证或操作授权。
- 优先级：权限和安全规则 → 用户当前要求 → 相关且有效的记忆 → 人设默认表达。
- 记忆可以帮助选择表达和做法，不能让无关问答偏题。通常直接应用，不每次声明“根据你的记忆”。
- 工作状态、材料权限、报告数据等仍读取业务系统；“我一般喜欢自动完成”不能替代本次指令或三级权限。
- 注入有预算上限，计入上下文使用量；会话压缩不删除长期记忆，也不把注入的记忆固化进会话摘要。

### 4. 管理入口

- 在系统设置增加“记忆”，管理员和员工均管理自己的记忆。
- 页面顶部提供名为“启用跨会话记忆”的开关，默认开启，作用于当前账号的所有会话。状态保存到服务端，刷新、重新登录或更换设备后保持一致。
- 开关独立于文档的“保存”操作，切换即提交；提交中防止重复操作，失败时恢复原状态并通过统一错误组件提示，不显示假成功。支持键盘操作并明确表示开启／关闭状态。
- 页面其余内容只包含简短说明和“我的记忆”Markdown 文档，显示最近更新时间；阅读态提供“编辑”，编辑态提供“保存／取消”和预览切换。
- 用户可直接新增内容、修改或删除文字；支持标题、段落和列表，不要求逐条打开表单。可提供“关于我、交流偏好、工作习惯、当前目标”的示例结构，但不强制保留。
- 空文档有简短引导，不把示例当作真实用户信息。提供二次确认的“清空记忆”；不增加导入导出、文件管理或历史版本页面。
- 编辑时保留本地草稿，AI 或其他页面的更新不能覆盖正在输入的文字；保存遇到版本冲突时保留草稿，允许查看最新文档后合并，不能静默覆盖任一方修改。
- Markdown 预览采用安全渲染，不执行 HTML、脚本或加载外部图片；记忆文档用于文字背景，不存附件。
- 不增加画像图表、分类配置台或输入框工具栏按钮。沿用现有页面间距、CSS Modules、表单校验、确认弹窗与统一错误展示。
- 关闭后仍可在管理页查看、编辑、删除已有内容；对话中的新增和更新停止。明确要求忘记可以执行删除，但不能借此把其余记忆注入回答。
- 关闭时要求“记住”应说明当前未开启，不偷偷开启或声称保存成功。清空仅删除内容，不修改开关。
- 开关旁说明：“让 Noria 在不同对话中记住你的偏好和背景。关闭后停止使用和自动更新，已保存内容保留。”关闭不影响当前会话的前文承接与上下文压缩。
- 文档区说明：删除聊天不会同步删除已保存记忆，可在这里编辑或清空。

### 5. 数据与隔离

- 使用独立的账号记忆记录，JSONB 保存 Markdown 正文和必要元数据；正文是唯一内容来源，不再维护一份需要双向同步的条目正文。
- 文档版本和片段元数据用于追踪来源、人工编辑及可选有效期，不展示为用户必须维护的 ID 或标记。来源关联可在聊天删除后失效，不能级联删除记忆。
- Markdown 是用户编辑和模型读取的内容形式，不在服务器磁盘上为每个账号维护另一份 `.md` 文件。
- 管理接口与工具均从登录身份／任务身份确定归属，不接受模型指定的账号或公司 ID。管理员身份不带来读取员工记忆的能力。
- 删除账号时清理该账号记忆；同名账号重建后不继承。账号切换清理前端相应缓存。
- 删除、清空、关闭和人工修改后，旧任务回放、延迟写入不能恢复旧值；并发会话更新不能覆盖其他会话已保存的内容。
- 应用日志、进度标签和诊断摘要不输出完整记忆；普通日志只记录操作结果、长度和版本等必要元数据。

## 边界条件

- 删除记忆只删除已保存的记忆，不篡改聊天正文；仍打开的旧会话可能包含用户当时的原话。不得承诺同时清除所有聊天、备份或已经发给模型的内容。
- 关闭／删除对后续模型请求生效，已发出的请求无法撤回；正在运行的旧工具在提交前重新校验，不能写回过时记忆。
- 开关关闭或读取失败时，不使用旧缓存记忆。普通问答可继续；显式记忆操作失败必须如实告知。
- 文档总长度和注入体积均有限制；不限制用户必须写成多少条或每段多长，超限不截断正文或假称保存成功。
- 未保存草稿不进入模型请求；取消编辑不改变已保存记忆。关闭记忆时可手动编辑，重新开启后才用于对话。
- 目标不明确的“忘掉那个”只做必要澄清，不能直接清空全部；明确“忘掉所有记忆”可以执行。
- 首次发布只从新输入形成记忆，不自动回扫历史聊天；重新开启不会重新提取关闭期间的消息。

## 技术约束

- 保留现有 FastAPI 模块边界、统一 Web 请求入口、任务租约和服务端权限校验。
- 记忆领域服务不依赖 Agent harness；工具和管理 API 均依赖领域服务。
- 不引入新模型、新外部服务、Redis 或通用文件系统记忆插件。

## 兼容性要求

- 现有账号默认开启、初始记忆为空；已有会话、模型配置和权限设置无需迁移语义。
- 新表通过数据库迁移创建；旧业务数据不变。回滚代码应能忽略新表，删除新表前需另行处理已保存记忆。
- 保持聊天、附件、工作引用、工具执行、人工确认、重试和中断流程正常。

## 验收标准

- [x] 自然表达及明确“记住”均能保存有用信息，在另一个会话中正确使用；刷新、重启不丢失。
- [x] 一次性指令、敏感凭证、材料注入、助手自述不形成记忆；长期取舍的适用范围不丢失。
- [x] 相同信息不重复，纠正能更新；当前要求优先，人工编辑不被旧推断覆盖。
- [x] Markdown 可自由增删、排序和修改标题，保存后跨会话生效；AI 局部修改保留无关正文和排版。
- [x] 编辑时发生 AI／其他页面更新，草稿不丢失，冲突不静默覆盖；取消、空文档和安全预览行为正确。
- [x] 开关、查看、编辑、删除、清空均可用；关闭不注入／新增／更新，仍可按明确请求删除。
- [x] “启用跨会话记忆”位于设置页顶部，按账号持久化、切换独立保存；刷新与重新登录后状态正确，关闭不影响当前会话上下文，提交失败不假成功。
- [x] 删聊天保留记忆；删记忆不被旧消息、重试或并发工具恢复；删账号后重建不继承。
- [x] 同公司两账号、不同公司以及管理员与员工之间均不能读取或修改对方记忆。
- [x] 注入计入上下文预算，压缩和重试不会重复注入或固化已删除记忆。
- [x] 断网、读取／写入失败、版本冲突、容量上限不产生假成功，不引入轮询。
- [x] 记忆不能绕过三级权限或替代工作数据；问答、工作更新、文件任务多流程回归通过。
- [x] 固定输入测试和真实模型跨会话样本分别记录结果；未运行的真实验证不能表述为通过。

## 待确认问题

无阻塞问题。范围为 Web 工作助手个人跨会话记忆；RAG 和更完整的数字分身后续另行设计。
