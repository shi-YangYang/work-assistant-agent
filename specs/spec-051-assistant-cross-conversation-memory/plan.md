# Plan：工作助手跨会话记忆

## 涉及模块

- `modules/memories`：持久化、归属校验、容量约束、版本冲突、管理 API。
- `agent/memory`、`agent/tools`：当前输入中的记忆候选、模型注入与真实操作回执。
- Web 设置：顶部“启用跨会话记忆”开关、Markdown 文档编辑和预览；不改造工作助手输入框。开关使用服务端账号状态，独立提交，不依赖文档保存或浏览器本地设置。
- 会话上下文、节点恢复和账号删除：预算、过期值隔离、生命周期联动。

## 数据设计

新增 `AssistantMemory`，每个 `company_id + owner_id` 唯一，包含 `enabled`、`revision`、`generation`、`document JSONB` 和更新时间。没有记录时视为开启且为空，首次写入再创建。

`document.markdown` 是唯一正文；`document.schemaVersion` 标识格式版本，`document.annotations` 仅记录片段定位、来源类型、来源消息及可选有效期，不复制正文。片段定位绑定当前文档版本，修改时原子更新，不能沿用失效偏移。来源只作追溯，不保存整段聊天，不依赖原会话存活；不另建磁盘 `.md` 副本。

- 初始文档上限 6,000 字符，集中在领域常量中；删除原方案的条数与单条长度限制，不增加用户配置项。
- 注入最多使用 6,000 个估算 token，且不超过本次可用输入预算的 10%。通常注入完整文档；不足时按人工／明确记忆优先、较新优先选择完整语义片段，保留所属标题、范围和期限，不截断句子或拆散列表／代码块。过期信息不注入，正文不因此被重写。
- 更新在事务内锁定账号记忆行，使用预期版本；首次并发创建受唯一约束保护。手动保存提交完整 Markdown，Agent 提交追加／精确替换／删除片段的局部补丁；两者只在版本匹配时原子提交。
- 手动保存按与原版本的差异标记新增／修改片段为人工内容；未修改片段保留原来源，移动片段不丢失人工标记。自动推断不得替换或删除人工片段；明确的修改／忘记请求可修改对应内容，未涉及部分保持原样。不得通过追加矛盾信息规避人工优先规则。
- 冲突返回 `409`，不覆盖正文。前端保留编辑草稿与基准版本，显示最新内容供用户合并；后台不推送替换编辑器值，不新增轮询。
- `generation` 在开关变化、人工编辑和删除／清空时递增，撤销旧任务的记忆写入资格。恢复任务不能通过重新读版本，把旧输入变成新的写入授权。
- 工具幂等键绑定任务、输入版本和工具调用，结合现有节点回执处理重复执行。成功写入后崩溃、回放旧回执时必须核对当前版本；已被删除的旧结果不能再次宣称仍已保存。

## 数据流

1. 验证当前任务和用户身份，读取有界记忆快照及版本。
2. 每次模型请求构建独立背景区块，明确其低于当前指令且不能授权操作；进入现有上下文估算和压缩流程。
3. 当前模型按规则选择 `save_memory` 或 `forget_memory`，无需独立提取模型。结合上下文理解指代，写入依据必须包含本轮用户输入，只提交必要的文档片段修改。
4. 工具调用领域服务，检查归属、开关、来源、版本、人工片段和容量；精确替换须唯一匹配旧片段，失败不猜测位置。事务提交后返回结构化结果，沿用节点反馈。
5. 管理页调用同一领域服务；变更后使账号快照失效，下一次模型请求读取最新状态。

记忆区块仅用于组装本次请求，不写入 `ConversationContext.payload`、历史消息或压缩摘要。模型请求／工具回执中可能已有旧内容，恢复时需过滤专用记忆区块、旧记忆工具回执，不能把它们再次当作有效记忆或写入来源；用户原始聊天不因此删除。

关闭时不向模型提供记忆内容，保存工具返回已关闭；删除工具可在服务端对该账号文档做受限匹配，只返回删除结果或必要的澄清选项，不返回其余记忆。无需为管理页的用户主动读取关闭中的记忆设置障碍。

## 接口变化

所有接口要求登录，写操作沿用 CSRF；归属只取当前身份，不提供管理员代查参数。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/assistant/memory` | 开关、版本、Markdown 正文、更新时间和容量信息 |
| `PATCH /api/v1/assistant/memory/settings` | 修改开关，带 `expectedRevision` |
| `PUT /api/v1/assistant/memory/document` | 保存用户编辑的完整 Markdown，带 `expectedRevision` |
| `DELETE /api/v1/assistant/memory/document` | 清空文档，查询参数传预期版本，不修改开关 |

工具只提供当前账号的保存／更新与忘记能力。`save_memory` 接收新增 Markdown 或精确的旧／新片段、来源片段与适用期限；`forget_memory` 接收目标片段或删除描述及本轮依据。版本由服务端快照绑定，不让工具通过自行填写最新版本绕过旧输入限制。服务端检查真实来源和版本，不能由模型设置 `origin=manual`、账号或权限。

模型决定信息是否长期有用；服务端负责身份、来源、结构、凭证防护和提交规则。不声称简单字符串检查能完全判定语义，不新增一套独立业务授权审批。

## 实施顺序

1. 建立迁移、领域模型／服务和 API；完成隔离、版本及删除生命周期测试。
2. 接入记忆工具和注入中间件，调整人设中“尚无跨会话记忆”的能力描述；不改变人设风格。
3. 接入节点白名单、结果标签、幂等恢复和上下文预算，验证工具组合与会话压缩。
4. 增加设置页、Markdown 编辑／安全预览、导航、请求和共享类型；复用现有请求缓存与失效机制，不新增周期请求或大型编辑器依赖。
5. 用固定测试验证工程边界，再用真实聊天模型走跨会话流程；独立验收后记录结果。

## 测试计划

实施按 **S3** 验证：新增持久化、公共 API 和个人数据隔离。限于 Web／服务端相关子系统，不因此运行 Electron、ASR 或打包检查。

| 场景 | 必须观察的结果 |
| --- | --- |
| 普通表达、明确记住 → 新会话 | 已保存文档与回答行为一致，不靠旧会话正文蒙混通过 |
| 背景、习惯、长期目标、判断原则 | 不仅记格式偏好，适用范围与期限保留 |
| 当前例外、纠正、手动编辑 | 当前要求生效；旧值不复活，不产生矛盾内容 |
| 重复输入、并发会话、双标签编辑 | 不重复，不丢失另一会话更新；冲突可恢复 |
| 自定义标题、段落排序、长段落、列表 | 用户可自由编辑；AI 补丁不改无关文字和排版，片段来源不串位 |
| 输入中 AI 更新、保存冲突、取消、账号切换 | 草稿不被刷新替换；冲突可查看最新正文；取消不保存，草稿不跨账号 |
| Markdown 预览与空文档 | 不执行 HTML／脚本或加载外部图片；示例不被当作真实记忆 |
| 删除、清空、关闭与运行任务竞争 | 已发送请求边界如实；后续注入及迟到写入受控 |
| 写后崩溃、自动／手动重试、旧回执 | 幂等、无恢复已删内容、无假成功 |
| 删聊天、账号切换、删账号重建 | 保留或清理符合各自规则，前端不串号 |
| 同公司两用户、跨公司、管理员 | 文档读取、修改、工具调用均无越权；管理员也有自己的记忆 |
| 网页／附件注入、虚构示例、凭证 | 不生成或执行恶意记忆，不输出敏感值 |
| 小上下文、压缩、超额、读取／保存失败 | 有界注入、计量正确、不静默丢失、不阻塞普通问答 |
| 关闭时请求记住／忘掉、重新开启 | 不偷开；删除可用；不回扫关闭期间消息 |
| 开关切换、刷新、重新登录、提交失败 | 账号状态持久化；不依赖文档保存；失败恢复原状态；当前会话前文仍可承接 |
| 个性化问答 → 引用工作并修改 → 生成文件 | 偏好自然使用，业务权限与真实结果保持不变 |

- 自动检查：新增记忆测试、相关账号删除／上下文／执行权限测试、API 请求覆盖及后端架构规则；Web 记忆页与导航测试、Web 类型检查。只格式化改动源码。
- 真实模型：使用授权测试模型和隔离测试账号，至少 12 组、多轮且跨会话，覆盖上表中的语义与端到端流程；包含管理员、员工及对照账号。保留输入、记忆前后变化、回复、工具结果和耗时，不仅断言回复中出现“记住”。
- 确定性断言验证隔离与状态；真实语义评测区分模型误判和系统缺陷，不能用重复跑到通过代替修复。未提供真实模型条件时记录未验证项，不伪造通过。
- 浏览器检查管理员／员工、桌面／窄屏的空文档、有内容、编辑／预览、关闭、冲突和错误状态。使用测试数据，不删除用户实际记忆。

## 风险与迁移

- 自动记错：限制来源、范围和敏感内容，提供可见可改的文档，保护人工修改；不宣称模型能无误学习用户。
- 延迟／成本：复用当前模型和节点，只在必要时调用记忆工具；不增加每轮必经的独立记忆模型调用或后台全量整理。
- 迁移只加表和约束，旧账号惰性创建空记录，无历史聊天回填。关闭功能可停止使用但保留数据；不把删除新表作为常规回滚。
- 上下文和工具恢复是主要回归风险，先验证预算、失效与幂等，再接 UI。记忆不参与业务权限计算或操作结果核对。
