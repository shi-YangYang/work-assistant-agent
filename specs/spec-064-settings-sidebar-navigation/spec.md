# Spec 064：系统设置侧栏导航

## 状态

已完成，独立验收 PASS，详见 [验收结果](acceptance.md)。系统设置入口和返回按钮只切换左侧菜单，点击具体菜单项才切换右侧页面。

## 背景

系统设置中的账户、记忆、外观等入口实际承担二级导航职责，目前却放在侧栏旁的浮层中。用户希望在同一左侧栏内切换主菜单和设置菜单，并通过返回按钮回到主菜单。

## 目标

- 用同一侧栏承载两套菜单，取消系统设置菜单浮层。
- 保持当前页面、设置入口及权限规则，减少打开浮层和反复寻找入口的操作。
- 桌面、平板和手机采用一致的两层导航关系。

## 非目标

- 不调整设置页面内部的表单、子 Tab、业务功能或权限。
- 不新增设置首页、第三层菜单、导航配置服务或持久化用户偏好。
- 不改动 Agent、模型请求、数据库、API、部署及 Electron。
- 不移除宠物外观、汇报通知、命令面板等正常使用的弹窗。

## 当前行为

- `Sidebar` 显示主菜单，底部“系统设置”通过 `usePopover` 打开菜单浮层；点击其中一项进入 `/settings/*`，关闭浮层及移动端导航抽屉。
- `Shell` 根据身份过滤主菜单和设置菜单；命令面板使用同一批入口。
- 桌面侧栏宽 228px；761～1023px 为 72px 图标栏并可展开抽屉；760px 及以下默认隐藏，通过导航按钮打开抽屉。
- 移动端抽屉已有遮罩、Escape、焦点约束和关闭后的焦点恢复。路由跳转还受现有录音与草稿处理规则约束。

## 目标行为

系统设置入口及返回按钮只切换菜单，不触发页面跳转。

| 操作或场景 | 左侧菜单 | 右侧内容与地址 |
| --- | --- | --- |
| 在业务页面点击“系统设置” | 原位换成设置菜单，底部原入口替换为“返回主菜单” | 保持当前页面和 URL |
| 点击“账户”等具体设置项 | 保持设置菜单，对当前设置项高亮 | 按原路由打开所选页面 |
| 点击“返回主菜单” | 恢复主菜单 | 保持当前页面和 URL |
| 返回后点击“我的工作”等主菜单项 | 保持主菜单，高亮相应入口 | 按原路由打开所选页面 |
| 刷新或直接进入有效 `/settings/*` 地址 | 初始为设置菜单 | 展示地址对应的设置页 |
| 从命令面板或页面链接进入设置页 | 自动切换为设置菜单 | 正常导航 |
| 从设置页进入业务页，或浏览器前进／后退 | 按实际到达的路由切换菜单 | 遵循现有路由历史 |

手动切换菜单不产生浏览器历史记录；浏览器返回负责页面历史，“返回主菜单”负责菜单层级。右侧仍是设置页而左侧已返回主菜单时，底部“系统设置”继续体现当前位置；不会伪造某个业务页的选中态。

## 功能需求

### 1. 菜单内容与布局

- 两套菜单复用当前主菜单所在区域、侧栏宽度、图标和条目样式；同一时刻只显示其中一套。
- 品牌、全局搜索、底部账号和退出入口保留位置与功能；原有汇报通知继续按既有条件显示。
- 设置菜单上方清楚标识“系统设置”；底部原“系统设置”位置替换为带左箭头的“返回主菜单”按钮。两者共用位置和样式，设置模式下不显示“云搭子 beta”。
- 主菜单恢复现有入口、顺序及禁用的“云搭子 beta”，不增加右侧内容区的标题栏或额外占位。
- 设置项沿用现有顺序：记忆、用户声纹、账户、外观、汇报规则、登录方式、模型服务管理、模型用量、问题反馈；问题反馈仍位于末尾。保留适量分组间距，不另加一套分类体系。
- 切换不改变侧栏宽度，不推动右侧内容；不新增明显的滑动、缩放或等待动画。

### 2. 权限与路由

- 普通用户显示记忆、账户、外观、汇报规则、问题反馈；管理员另有用户声纹、登录方式、模型服务管理、模型用量。
- 复用 `pages`、`settingsPages` 和已有过滤结果，不复制菜单定义或增加第二套权限判断；命令面板可用入口不变。
- 当前页高亮由路由决定，菜单层级由“当前路由的初始层级 + 用户当前手动选择”决定。页面实际跳转后重新按目标路由同步；单纯重渲染、数据刷新、开关抽屉不得覆盖手动选择。
- 无权限或不存在的设置地址继续走原有路由回退，菜单与回退后的地址同步。
- 菜单状态只保留在本次应用会话内；刷新按 URL 恢复，不写入服务器或浏览器长期存储。身份切换后不沿用前一用户的菜单状态。

### 3. 手机与平板

- 在已有导航抽屉内部切换两套列表。点击系统设置或返回主菜单时抽屉保持打开；点击具体页面后沿用原有收起行为。
- 平板图标栏点击系统设置时打开既有完整抽屉并展示设置菜单，方便读取名称；不再创建旁边的浮层。
- 重新打开抽屉保留当前菜单层级；仅关闭抽屉不导航。手机不显示抽屉顶部的收起按钮，通过遮罩或 Escape 收起；平板保留收起按钮。
- 所有菜单项及返回入口在窄屏上可点击，触控高度至少 44px。低高度时可滚动访问完整列表、通知与退出入口，不能被裁切。

### 4. 焦点与内容稳定性

- 使用真实按钮和导航链接；主菜单、设置菜单具有独立且明确的无障碍名称，图标栏也有可读标签。
- 用户进入设置列表后焦点落到返回按钮；返回主菜单后焦点回到系统设置入口，避免停留在已卸载元素上。
- 继续使用现有抽屉焦点约束；命令面板、通知等弹层打开时，遵循原有焦点与 Escape 优先级。
- 单纯切换菜单不重挂载右侧页面，不清空输入、录音状态或草稿，不中断流式回复，也不重启宠物状态订阅，不发起新的业务请求。
- 点击具体页面继续遵循现有离页行为；录音取消离页时不得只切菜单却仍停在被拦截的页面。此项不扩展现有页面草稿保留能力。

## 边界条件

- 在设置页手动返回主菜单后，页面内切换 Tab 若造成真实路由变化，则按目标设置路由恢复设置菜单；纯本地表单更新不恢复。
- 同一地址重复点击菜单项仍按现有导航行为处理，不新增历史跳转或手工页面缓存。
- 从设置菜单点击品牌首页、汇报通知或命令面板中的业务入口，菜单跟随实际目标路由。
- 缩放或跨越桌面／平板／手机断点时，抽屉按原规则关闭，菜单层级不因此丢失。
- 设置菜单较长、用户名称较长、深色主题和减少动态效果模式均不遮挡返回入口或菜单文字。

## 技术约束

- 仅在 `apps/web/src/app/layout/` 内管理侧栏展示和路由同步，沿用 React Router；设置页面不感知导航层级。
- 移除 `Sidebar` 专用的设置浮层及样式，不改动共享 `usePopover` 的其他使用者。
- 不增加 UI 库、动画库、API 请求或常驻页面实例，不通过重挂载 `Shell`／`AppRoutes` 实现切换。

## 兼容性要求

- 现有设置 URL、收藏链接、权限回退、主菜单、全局搜索快捷键及设置子 Tab 可继续使用。
- PC 侧栏和移动端抽屉沿用同一菜单数据；手机钉钉 WebView 不依赖原生 Popover 支持完成导航。
- 后端无迁移；设置内容及未提交表单的原有保存机制不变。

## 验收标准

- [x] 点击系统设置在左栏原位出现设置列表和返回按钮，不再出现设置浮层。
- [x] 入口和返回仅切换菜单，URL、右侧页面实例和未发送内容保持；无额外业务请求或布局跳动。
- [x] 设置项完整，员工／管理员可见性、顺序及选中态符合现有权限。
- [x] 深链接、刷新、命令面板、品牌首页、通知及浏览器历史均正确同步菜单。
- [x] 手动返回在相同路由的重渲染、数据更新和抽屉开关后保持；实际路由变化后按目标恢复。
- [x] 手机／平板可进入、返回、关闭和重新打开菜单，选择页面后抽屉正确收起，所有条目可达。
- [x] 键盘焦点、Escape、触控尺寸、窄屏滚动和主题显示正常，无焦点落空或遮挡。
- [x] 录音离页拦截、聊天流式状态、跨页草稿、宠物状态和设置表单未被菜单切换干扰。
