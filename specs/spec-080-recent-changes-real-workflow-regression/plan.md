# 最近变更的真实流程回归：实施方案

## 执行边界

按本规格执行用户明确要求的跨模块完整回归：覆盖最近变更的公司 Web／API／worker／迁移和镜像边界，不运行无关桌面全套测试。文档维护本身仍按 S0。

主 Agent 完成范围决策；一个 `high` 实施 Agent 串行补充测试与执行，随后由新的 `high` 独立验收 Agent 审核。验收 Agent 不修改业务代码，不无理由重复已通过的检查。产品缺陷仅记录，不在测试任务中自动返工；测试脚本缺陷可修复，但保留先前结果。

## 实施顺序

1. **冻结清单**：用 Spec 的 Git 范围对照实际差异，建立变更文件→功能→F01～F20→已有证据／缺口的映射。输出实际测试 SHA、场景散列、入口、角色、模型配置、执行上界、预期状态和读回条件。实际代码变化导致旧结果失效才补跑对应范围。
2. **准备隔离资源**：复用 `environment.py`，检查资源归属和空闲端口；建立测试公司及账号、媒体目录、相同配置的 API／worker、数据库与 Redis。读取配置时不打印密钥。迁移准备单独可销毁库；有沙盒流程时核对真实控制服务与执行镜像。
3. **最小确定性回归**：复用现有相关 Web／server 测试，补齐有具体缺口的边界；先排除脚本、契约和持久化故障，再花真实模型请求。用现有 `test_question_schema.py`、交互测试、报告来源／重建／退出及任务身份测试覆盖不能依赖模型自然触发的分支。
4. **真实功能旅程**：使用正式 Web，完成登录、上传、对话、问题框、工作、周报、团队页及文件下载。浏览器真实提交作为起点，API／SQL 只作前置数据和独立读回，不能替代待验的按钮或业务结果。
5. **真实模型首试**：按固定 low/high 场景分别运行，记录每个实际模型节点。报告页、助手、待办和调度单独覆盖；能够复用的已生成对象用于后续 UI 测试，减少重复生成。
6. **异常、恢复和兼容**：仅在隔离资源触发断网、冲突、来源变化、授权期间／绑定后的竞争、重放和旧日报恢复。先证明注入已发生，再判断实际拒绝、保留、恢复与数据副作用，不能用 mock 失败提示当作系统拒绝。
7. **镜像与解析／执行检查**：本地构建受影响目标，核对实际安装依赖、缓存命中与运行日志；在 worker 镜像执行现有 Office preflight，实际上传解析；有真实执行回执和可打开文件后才判定沙盒流程完成。无可用服务记 BLOCKED，不能改用 export_table 顶替。
8. **汇总和独立验收**：提交证据索引及简短实施说明给新验收 Agent；其核对必需入口、实际请求与读回、首试失败、缺陷归因和模型限制。只对具体新疑点执行最小复现。通过项不重复采样，失败项不因后来成功被覆盖。

## 数据流与接口

正式 Web → 现有 API → 任务／worker → 原有模型与业务工具 → 来源、授权及事务保护 → 持久化回执 → SSE／查询 → 正式页面 → 独立读回。

没有计划内生产 API、工具 Schema 或数据模型变更。测试驱动使用现有协议；发现契约问题按缺陷报告。临时控制时序仅用于隔离故障注入，并明确其与自然真实模型流程的区别。

## 检查与命令策略

已有入口：

- `scripts/company/web-acceptance/environment.py prepare --suite spec080 --purpose web --output <私有环境元数据路径>`；Web／API 端口先核对后通过现有参数显式指定。`exec --metadata ... -- <command>` 将后端检查绑定隔离环境。
- `agent-browser.mjs`／`agent-browser-common.mjs`：复用实际登录、网络证据和会话驱动；现有脚本的旧选择器须对当前页面核对，不能假设仍有效。
- `agent-http.py`、`readback.py`、`request_coverage.py`：补充接口、任务及数据证据；HTTP 流程与浏览器流程分别标识。
- `npm run test:web -- <相关文件>`、隔离环境中的 `.venv-server/bin/python -m pytest <相关模块>`：按清单执行。历史检查复用须说明被测提交与本轮是否受影响。
- 最终被测范围的格式、定向 ESLint、`npm run typecheck:web` 和 `npm run build:web` 至多各一轮；后端相关测试和隔离迁移按风险覆盖。已有完全适用证据不因进入新 Spec 再跑一次。
- Docker 构建只作用于本地测试镜像；具体 target、配置与启动命令根据当前 Dockerfile／Compose 确认，不部署、不下载无关模型权重。

执行结果必须对应实际命令及证据；计划中的脚本或步骤尚未完成时，不提供虚假的“已可运行／已通过”结果。

## 证据组织

```text
artifacts/recent-changes-regression/
├── manifest.json                    # SHA、环境归属、场景散列、配置与预算
├── coverage.json                    # 变更与用例映射、证据类型、PASS/FAIL/BLOCKED/NOT_RUN
├── private/                         # 凭据与环境元数据；不作为公开附件或 Git 内容
├── cases/<case>/<effort>/attempt-1/  # 原始输入输出、trace、网络、读回、截图、下载文件
├── faults/                          # 注入方法、已触发证据、原始失败和恢复结果
├── migration/                       # 迁移前后关系与保留／清理核对
└── images/                          # 构建、依赖、解析和执行日志
```

一次长流程可为多个断言提供同份证据，但四个生成入口不能只引用一次助手生成。超时不是成功；只读终态不要求无意义写入。下载必须记录实际字节、散列与格式打开结果，不能只拍按钮或检查扩展名。

最终只维护 `acceptance.md` 一份汇总记录，不叠加重复 Markdown 实施日志；过程信息放结构化证据。现有历史验收记录不改写。

## 风险、迁移与停止规则

- 模型和外部网络有波动：记录实际配置、请求和时长，不通过换模型、抬预算或扩大等待掩盖失败。若需要重测，先说明具体原因并另存结果。
- 真实写入具有副作用：所有创建／提交／删除／调度／迁移都只针对隔离测试资源；若发现指向日常或生产环境，立即停止依赖操作并保留诊断。
- 移动端或共享样式变更可影响多个入口：实际检查代表页面，不以单个公共组件快照替代集成结果。
- 全量范围有环境阻断或纯模型失败时，如实交付不通过及未覆盖清单，不无限等待或重跑。
- 用例覆盖和必要证据齐全后停止；清理本轮拥有的进程、schema、媒体及临时镜像资源，保留测试证据。无需新增业务迁移；仅验证既有迁移。
