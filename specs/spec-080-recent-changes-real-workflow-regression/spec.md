# 最近变更的真实流程回归：需求

[实施方案](plan.md) · [验收结果](acceptance.md)

状态：本轮实测与独立验收已完成，整体 **FAIL**。测试证据返工已完成，产品失败、归因缺口及活跃问题框320／390px未覆盖仍保留；未修改业务代码。隔离服务及测试数据已清理，详见 [验收报告](acceptance.md)。

## 背景

最近修改覆盖 Agent 决策与搜索、提问框、附件及成果卡片、工作详情与修改记录、周报来源与生成、日报移除、错误反馈和公司镜像依赖。既有验收包含模块测试、部分真实模型流程和组件浏览器演示，但没有把所有受影响用户入口串起来验证。

卡片临时原型已移除。其样例数据、演示 API、回调计数和截图只能证明当时的组件表现，不能证明真实解析、生成、保存或任务恢复。

## 目标

- 对最近改动建立逐项覆盖清单，验证从用户操作到后台处理、持久化、刷新和再次访问的一致性。
- 涉及 AI 的正常流程使用实际配置的模型；程序异常和并发边界单独验证，不伪装成模型自然触发。
- 产出可复核的真实回复、请求与工具顺序、任务状态、数据库读回、文件和桌面／手机截图。
- 区分产品缺陷、模型表现、环境故障和测试脚本问题；保留首次结果和未执行范围。

## 非目标

- 不修改生产数据，不连接生产执行生成、提交、删除或迁移，不部署、push 或合并。
- 不恢复已删除的演示页面，不增加另一套模拟业务服务充当验收环境。
- 不扩大到未受本轮变更影响的 Electron 录音、桌面转写、双平台安装卸载或全产品压力测试。
- 本规格为测试与证据补全，不自动修复发现的产品缺陷。测试脚本自身的错误可以修正；产品问题记录后交用户决定。
- 不为已确认的纯模型问题增加提示补丁、审核模型、关键词判官或重试预算。

## 目标行为与真实流程要求

主要流程必须走：真实浏览器登录 → 实际页面操作／上传／发送 → 正常 API → worker／任务队列 → 配置要求的真实模型或解析／执行服务 → 程序校验与事务保存 → 页面更新 → 刷新／重新登录 → 独立 API 或数据库读回。

API 202、任务已入队、工具传输成功、卡片显示成功均不能单独判定完成。需要核对目标记录、回执、任务结果和最终展示。普通只读回答按产品的实际终态契约判断，不机械要求所有任务都为 `succeeded`。

使用合成业务内容及独立测试账号。可通过受控脚本建立旧历史、边界日期和迁移前数据，但这些仅为前置条件；需要验证的创建、编辑、提交、删除及生成必须由相应真实入口执行，不能预先写好预期结果。

## 模型与异常覆盖

- 冻结输入后，工作创建／修改、关键歧义提问、文档读取、公开搜索、助手周报生成／改写、文件交付分别至少包含一次真实助手 low 与 high。可用连续用户旅程覆盖多个场景，不为每个按钮独立发一轮模型请求。
- 每个固定场景、每档默认一次首试；运行前清单中列出请求上界及超时，沿用既有预算。程序自带的有限重试计入同一首试，测试人员另发请求必须另存 attempt 和原因。
- 报告专用、授权、提取等模型记录实际 provider／model／reasoning 配置；助手 high 不代表其他节点 high。有效配置不支持某档时明确记为未覆盖，不静默换模型。
- 自然出现的错误原样保留。无法保证真实模型自然产生的无效参数、连续纠错、超限问题、来源失效、并发和租约故障，以受控输入或故障注入验证程序边界，单独标记；不得改 provider 回复后声称是真实模型结果。
- 问题框最大边界、删除旧日报迁移和并发错误不需要为了“真实模型全量”额外调用模型。全量指所有受影响功能和边界有证据，不是所有场景必须由模型制造。

## 边界条件与技术约束

- 复用现有本地隔离验收工具，为本 Spec 建立唯一数据库 schema／账号／媒体目录及队列归属；API 与 worker 必须指向同一隔离环境。启动前校验服务归属和端口，不接管日常 5174／8000 或旧隔离进程。
- 员工本人、另一员工、管理员、另一公司作为权限角色；用户内容全部为合成数据，密钥不进 Git、截图、trace 或公开报告。
- 调度测试使用真实调度用例和任务消费，以隔离配置设置已到期周期；不修改宿主时间或生产安排。不能通过直接调用生成函数替代调度入口验收。
- 故障注入只在本测试拥有的资源执行；不能停止日常 Redis、worker 或清理用户文件。日报迁移测试使用独立可销毁数据库并验证可恢复备份，不迁移日常库。
- 不削弱幂等、租约、权限、意图授权、来源身份及版本检查；不增加生产测试开关、固定案例特判或额外模型节点。
- 输入上游缺失、契约歧义、节点遗漏及程序增加往返必须先排查。只有实际输入和轨迹支持时才归因模型；归因不明记录为未决。

## 兼容性要求

保持已有 API／工具契约和历史链接行为。公共卡片保留各业务自己的请求与权限逻辑；待确认、错误、删除影响及恢复操作不能被固定高度裁掉。日报旧对象保持失效，不悄悄转成周报。

## 证据与判定

每个用例记录：被测 SHA、用例摘要／散列、环境与入口、角色、真实配置、开始结束时间、请求／任务／操作／对象 ID、输入与原始回复、工具与模型调用顺序、HTTP／最终状态、前后读回、截图或文件及其散列、结果和缺陷归因。敏感信息脱敏，原始首试证据不可覆盖。

用例结果区分 PASS、FAIL、BLOCKED、NOT_RUN；证据类型区分真实浏览器流程、真实 HTTP 流程、确定性故障注入、组件测试及历史证据。只有对应浏览器入口完成整条链路，才能称为真实页面流程通过。

最终独立验收给出 PASS／FAIL。存在必需流程失败、未测、环境阻断或未归因问题时，不得给出“全量通过”。系统检查和模型内容表现分列；纯模型失败保留在总体结果中，但不要求以代码补丁或反复测试把它消掉。

历史 v6／v7／v8 耗时和失败不覆盖、不合并不同采样条件，不用新单样本替换旧矩阵。性能只给本轮实际配置下的观测值和必要限制。
