## 状态与依赖边界

- **会话任务状态**：新增 `company_conversation_task_state`，按会话唯一关联公司和用户，保存有版本的 JSONB；包含当前任务、持续范围及未完成事项的最小信息。
- **来源证据**：使用原始用户消息 ID、版本、必要原文片段及可信来源类型；每次使用核对真实性、有效性和权限。模型只能提出解析，不能创建可信来源或自行批准高风险操作。
- **运行快照**：Job 保存本次 taskId、状态版本、输入版本与必要快照。RunContext 在本次运行内复用；旧 Job 不能读取后来的授权为自己补票。
- **操作回执**：BusinessAction 仍是写入事实来源。新增可空的逻辑任务／事项关联和唯一约束；新机制跨消息复用回执，旧数据保持原 message／step 幂等规则。
- **会话摘要**：ConversationContext 继续只存可重建资料；压缩不会删除独立任务状态，恢复状态不从助手摘要推断授权。
- **执行检查点**：继续按 Job 隔离。澄清产生新 Job，读取逻辑任务状态和回执，不直接复制旧 Job 的待执行工具调用。
- **客户端**：只读取安全结果投影，不提交可信授权标记、不自行推断操作成功。

任务类型允许自由组合既有能力。确定性约束管理权限、来源、版本和幂等；语义理解通过主模型及现有审核完成，不建设关键词路由或业务句式白名单。

## 实施顺序

1. 固化本次多轮回归和能力矩阵，记录现有失败发生在解释、审核、执行、恢复还是展示层。样本期望在修复前冻结。
2. 建立类型、任务存储及增量迁移。按项目现有锁顺序和 lease fence 写入，使用任务状态版本比较防止旧 worker 覆盖新指令。
3. 接入统一任务解释与证据校验，替换“只认当前消息授权子串”等冲突约束。普通请求不强制增加一次独立规划调用；任务范围变化才更新状态，已有审核复用同一输入。
4. 统一正式操作、建议和报告交接结果。补齐稳定事项关联，先核对已完成回执再执行未完成项；原业务事务和版本检查保留。
5. 重写完成修复的准入条件：只修复已授权、信息足够且未执行的事项；缺信息、拒绝、取消和相同阻碍不会触发盲目补执行。
6. 任务结果接入 API／SSE 和现有 UI，保留一个状态入口及原有确认卡。增加字段时同步类型与前后端使用点。
7. 运行相关回归、迁移验证和隔离真实评测；新独立验收 Agent 检查需求、diff 和证据。文档如实记录未完成项。

## 数据流与恢复

```text
用户消息／澄清答复
  → 读取当前会话任务与真实来源
  → 解析继续／新建／切换／覆盖／取消，形成同一任务快照
  → 主助手选工具
  → 范围核对 + 确定性权限／版本检查
  → 事务执行或返回具体阻碍
  → 记录事项结果及真实回执
  → 按任务要求核对交付
  → 已完成／部分完成／等待补充或确认／无法继续
```

- “允许继续”的证据必须来自用户输入或实际环境变化；审核拒绝原因本身不是重新授权。
- 重复失败按任务事项、动作及阻碍原因归并；参数／对象版本／用户补充变化后才允许重新评估。同一无变化阻碍不靠换 tool call ID 或 step 绕过。
- 新消息先解析是否回答待补问题。唯一明确的承接直接续接；更换目标、修改计划或取消时先更新任务范围，再执行相应动作。
- 连续补充每条新消息是新一次获授权的内容更新；重试同条消息或回答其澄清则沿用原事项。一个任务内的显式多个相同副本保留独立身份。
- 追加字段由既有授权核对标明本次完整增量，增量必须是拟议字段中的连续原文片段；服务端保留原文后拼接。无法从重述中分离增量时让助手修正参数，不把参数问题变成用户重复授权，也不靠模糊去重删除内容。
- 写入与成功回执保持原子性，任务结果可从回执补齐。取消不回滚已提交事务；迟到结果不能覆盖取消后的未执行事项或新任务。
- 模型与审核读取同一任务版本。写入前重新核对来源、权限、约束和对象版本；失效时停止，不用旧快照继续写。

## 接口与兼容

- 不新增执行模式接口或专用问答端点。沿用发消息、replyTo、重试、中断和确认接口。
- Job 与反馈增加可选 `taskOutcome`：状态、已完成／未完成事项的简短描述、阻碍类别和允许的下一步。内部授权片段、私有来源内容、模型思考过程不进入 DTO。
- 结果状态由统一模块派生，不修改通用 Job 状态以迁就展示；旧消息缺字段时走保守兼容展示，不把所有 `awaiting_input` 当成成功。
- 表结构扩展和新增列需先迁移后部署。旧数据按需初始化，不批量回放；旧客户端忽略可选字段。
- 代码回滚可保留新增表／可空列，回到旧逻辑；删除迁移数据仅用于隔离测试库的回滚验证，不自动对生产执行 downgrade。

## 验证计划

检查限于公司后端任务、权限与持久化及相关 Web 交互。

### 确定性验证

- 在专用 `paa_company_test` 数据库验证迁移升级、旧记录读取及回滚；不指向日常库。
- 定向运行新增状态测试及任务完整性、写入范围、操作恢复、节点重试测试。再覆盖相关的来源访问、上下文压缩与取消测试；以实际受影响模块选用，不默认跑整个仓库。
- 测试必须断言未授权字段不变、原内容保留、回执及记录数量、来源失效、并发版本保护、角色与会话隔离，不能只断言助手文字或工具被调用。
- UI 运行任务进度与 JobNotice 测试；覆盖等待信息时可发送回答、刷新保持状态、继续后展开不关闭。
- 契约修改后运行 Web 类型检查；对修改过的 TS／TSX 使用项目 Prettier 并定向 ESLint。必要时补 Web 构建，不运行桌面打包或真实 ASR。

已有入口：`npm run test:server -- <测试文件>`、`npm run test:web -- <测试文件>`、`npm run typecheck:web`。测试文件按上面的目录树及实施 diff 选取；不要重复执行已通过且未受新修改影响的检查。

### 真实模型评测

复用 `scripts/benchmarks/agent-evaluation.py` 的配置读取、测试租户与检查点隔离，新增 `--suite task-consistency`；不新建另一套评测框架。

| 能力族 | 必测组合 |
| --- | --- |
| 持续授权 | 建立指令、连续补充、保留原内容、限制字段 |
| 范围变化 | 一次覆盖、永久撤销、话题切换、返回目标 |
| 指代与澄清 | 同名对象、成果条目、只回答缺少的字段 |
| 多目标交付 | 批量修改、操作后解释、独立与依赖事项 |
| 自主拟写 | 自由创建、示例文稿、仅讨论不保存 |
| 报告与角色 | 员工生成与确认、管理员本人工作和现有报告限制 |
| 中断恢复 | 部分成功、响应丢失、重复重试、过时任务 |
| 来源边界 | 引用命令、材料注入、跨账号／会话、无授权或授权失效 |

- 首轮固定 24 个场景，每族 3 个不同的任务结构，覆盖两种角色和两种人设，不展开无意义的全排列；8 个为保留样本，每族 1 个，不参与 prompt 调试。
- 使用实际配置的助手及核对链；报告场景使用实际报告模型。不得将授权审核替换成恒定允许的 mock 后声称真实通过。
- 修复前建立基线，修复后运行同一套场景，保存首次结果。代码未变化不靠反复运行筛出成功；确需重测时保留原失败及原因。
- 真实评测检查最终业务数据、未改字段、回执、可见答复、澄清次数与重复阻碍；记录总耗时和各类模型调用数，不用增加多层审核掩盖一致性问题。
- 本次核心回归、安全隔离、幂等与取消场景必须全过；24 个端到端场景完成率至少 95%，已知相关机制缺陷修复前不得判 PASS。保留样本失效后若据此调参，补等价的新保留样本。
- 服务商超时／拒绝单列原因，但仍计入端到端未完成，不删除样本美化通过率。外部问题阻塞关键链时写明未验证，不用受控模型结果替代。
- 真实评测手动执行，不加入默认 CI；只读日常配置，业务写入与故障注入全部在测试租户，日志脱敏，清理临时业务数据，保留精简证据在 `artifacts/agent-task-consistency/`。

### 交互验收

在桌面和手机宽度查看实际聊天：完成、待补充、待确认、部分完成、失败重试、中断。截图核对紧凑状态文案、折叠状态与输入区稳定性，不重做全站视觉验收。

## 风险与约束

- 把一般聊天误当持续授权：状态必须保留用户来源及作用范围；无法确定业务写入时集中澄清，不能用助手承诺代替。
- 去重过度：区分同一事项的重试与用户新的明确操作，复用回执前核对身份和已保存效果。
- 待补问题被误配到新任务：保存明确事项关联，拒绝从无关消息填入缺失参数。
- 旧 worker、旧重试覆盖新指令：使用 lease、输入版本和状态版本保护；不把未来授权应用到旧运行。
- 成本与耗时增加：不默认追加一轮固定规划或多重裁判，优先复用主模型、既有审核和确定性结果；前后对比必要模型调用数。
- 不扩大权限或功能范围：角色规则、提交／删除确认、资料隔离和已支持业务工具均保留。
