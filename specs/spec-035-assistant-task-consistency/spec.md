# 工作助手多轮任务与执行一致性

## 状态

已完成，独立验收通过。权限模式和临时回答框不在本期范围。

## 背景与目标

同一任务换种说法、分几轮表达后，不应反复修改特例 prompt 才能执行。主助手、授权审核、工具和完成核对必须使用一致的任务范围、对象、约束及操作结果。

- 连续指令、指代、补充和纠正能够自然承接；任务切换、取消与权限边界明确。
- 用户已授权且信息足够的操作直接完成；真正缺信息时只问必要问题。
- 根据失败原因恢复，仅处理未完成事项，不重复写入、不循环索要同样授权。
- 以用户目标和实际结果验收，不能用内部节点数量或助手口头承诺代替完成。

## 当前行为

- 已有会话 JSONB、成果版本与关联、业务工具、操作回执、节点重试和确认卡，不重建这些能力。
- `intent.py` 要求授权引用必须是当前消息子串；历史内容主要用于当前消息明确承接的引用。持续授权不能稳定表达。
- `policies.py`、`history.py`、`reply_review.py` 分别解释任务，可能出现主助手接受、审核拒绝、核对又要求补执行的冲突。
- 正式操作会保存 `operationFeedback`，进展建议的拒绝没有统一进入同一结果机制；补执行可能重复已被拦截的动作。
- `awaiting_input` 混合了普通答复结束、缺信息和部分未完成；前端可能显示“已完成若干步骤”。
- 现有评测包含大量任务，但不足以证明持续授权、澄清、切换和失败恢复的组合能力。

## 目标行为

| 场景 | 预期 |
| --- | --- |
| “接下来发的进展都补充到上线 web” → 发送仓库地址和今日提交情况 | 解析并保存限定范围的持续指令；定位唯一工作，补充对应内容，保留已有说明和未要求改变的字段 |
| “接下来的话关联到上线 web” | 若上下文无法确定是聊天背景还是业务写入，只澄清这一区别；不能先承诺已设定，再每轮重新询问 |
| “只是聊天背景，不要保存” → 后续讨论 | 保留讨论上下文，不写工作、建议或报告 |
| 讨论方案 → “把前两项加入工作” → “第二项的日期改到周五” | 按已有成果条目和真实关联完成创建、修改，不重新要求描述目标 |
| “只把刚才那条补进去，后面先别保存” | 执行这一次明确补充，结束持续写入授权 |
| “换到客户回访这项工作”／“这条只讨论，不保存” | 切换目标／覆盖当前条目的保存要求，不污染上一项工作；不能凭同名猜目标 |
| 同名对象 → 用户补充“甲客户那项” | 接续原意图，只补齐对象，执行一次，不让用户重述整条命令 |
| 两项修改中一项成功、一项缺日期 | 保留成功结果并只询问缺失日期；回答后执行剩余项 |
| “随机拟一项工作并保存，再给我建议” | 在委托范围拟定并真实创建，随后给建议；不只保存占位标题或只完成前半项 |
| 保存已成功，但答复超时 → 重试 | 复用实际回执，恢复答复或剩余事项，不重复保存 |

表中是能力示例，不作为触发词、固定句式或新的任务白名单。

## 功能需求

### 1. 同一份任务上下文

- 区分一次后台运行与跨消息的用户任务；任务记录目标、真实对象引用、内容范围、限制、未完成事项和当前阻碍。
- 区分聊天背景、一次性操作、持续指令。持续指令只在用户明确要求后建立，默认仅对当前账号、当前会话有效，刷新或 worker 重启后仍可使用。
- 一次性操作完成即消费，不因后续“继续”而重新执行；持续指令只约束后续匹配范围的输入，不把闲聊、引用或无关问题一律写入业务。
- 持续指令允许限定对象、操作、字段和期限；无期限时保留到用户取消、替换或来源失效。切换话题不等于授权新对象，返回旧任务须有可识别的承接。
- 当前明确指令优先于旧指令。一次性的“这条不保存”只覆盖当前消息；“以后不保存”撤销后续写入；含糊且影响执行时再问。
- 执行、审核、恢复和核对使用同一版本的任务快照，不分别从截断历史中重建相互冲突的授权。
- 快照保持简短，保存对象与来源引用、约束和结果标识，不复制整个聊天、附件正文或业务数据库。

### 2. 授权来源与业务权限分开

- 授权可以来自当前请求及仍有效的历史持续指令、澄清答复；每项指令绑定真实用户消息、来源版本和范围。不能只验证当前消息中是否出现授权动词。
- 模型负责语义理解，但模型生成的摘要、助手承诺、工具结果和检索材料不能自行建立授权。服务端校验引用的消息身份、会话、版本及取消／替换关系。
- 当前直接录制语音指令沿用现有来源规则；上传的语音、附件、网页和其中的命令仍是材料。获授权使用材料，不等于允许材料改变任务或权限。
- 用户说“补充”默认保留原内容；明确替换、纠正或清空才改变原内容。只修改约定范围，不推断完成状态、日期、共享附件或额外负责人。
- 普通查询、分析、私人创作不需要业务写入审核。明确的常规写入不增加通用二次确认；提交报告、删除等继续使用既有确认卡。
- 公司、账号、角色、对象所有权、来源访问权和版本检查仍由后端执行；持续授权不提高权限，不把管理员身份变成员工私人数据访问权。
- 授权来源被删除、语音指令被纠正、目标被删除或权限变化时，使相关范围失效。摘要压缩不能丢失仍有效的指令，也不能恢复已撤销指令。

### 3. 工具与结果统一

- 复用现有查询、成果、工作、报告工具，明确各工具的用途、输入、业务效果、确认要求和结构化结果。
- 明确修改已有工作使用正式操作；只有要求待确认建议时才生成建议。工具名称与描述应帮助模型区分实际修改和建议，不能用建议偷偷替代执行。
- 统一表达：成功、已入队／处理中、等待确认、缺少信息、权限拒绝、版本冲突、可修正参数、暂时故障，以及本次未请求的多余动作。
- 正式操作与建议工具走同一结果记录入口，记录它们对应的用户事项、实际效果和阻碍。拒绝信息不能只留在一段工具返回文本里。
- 成功依赖持久回执或实际成果；缺信息依赖具体未满足项。审核模型不能凭一句“需要再确认”掩盖系统错误或把未完成事项标为完成。
- 对没有请求的多余动作停止执行，继续完成原任务，不诱导用户批准新增范围。
- 原有业务能力边界保持不变，不用一套新的任务类型枚举限制用户组合现有工具。

### 4. 澄清、恢复与防止循环

- 澄清保存关联任务、未完成事项、问题及缺失字段；本期使用正常聊天提问和现有输入框回答，不新增弹窗或模式选择。
- 用户回答后可以产生新的消息和 Job，但继续同一用户任务；保留成功回执，仅执行本次补齐且仍获授权的事项。多个候选无法唯一关联时才澄清。
- 网络或模型暂时故障复用现有节点重试；参数和可恢复版本冲突允许依据新证据修正；缺信息、权限拒绝或取消不进入自动重试。
- 同一任务、同一动作和相同阻碍在没有新输入、新版本或新证据时，不再被完成修复循环调用，也不能换节点编号继续撞同一道检查。
- 恢复必须区分“成功”“确认尚未点击”“生成尚未结束”“执行结果未知”。结果未知先查回执，不能当失败重新创建。
- 稳定操作标识跨 worker 重启、人工重试及澄清续接保持；用户明确的新一次补充、新副本或新修改建立新标识，不误去重。
- 中断结束当前执行，已提交结果不回滚、不隐瞒；未完成动作不能在后续无关消息中自动恢复。取消持续指令与中断运行分别处理。
- 重试旧消息不得借用未来消息的授权或覆盖新任务状态；已被取消／替换的事项不得通过旧重试入口复活。

### 5. 完成判断与极简反馈

- 按用户请求的事项核对成果、业务回执和必要正文；“创建并解释”不能只创建，“写文稿”不能以没有数据库写入判失败。
- 任务呈现区分处理中、等待补充、等待确认、部分完成、完成、无法继续和已中断；这些是业务结果，不要求另建一套队列状态机。
- 报告生成入队仅表示交接成功，报告生成状态仍显示处理中；不能宣称报告已经生成或提交。
- 已完成事项与剩余事项同时存在时，优先显示具体阻碍和真实结果；节点完成数只作辅助，不作任务完成结论。
- 复用当前节点列表、确认卡、结果卡和单一重试入口，保留展开状态、文字光带及桌面／手机布局，不增加常驻任务面板。
- 人设仅改变表达，不能改变能力、授权、确认条件和完成判断。

## 非目标

不新增 Full Access／Auto-review 模式开关、临时回答框、审批后台、跨会话长期授权、任意 shell 或新的外部操作。不调整 Electron、登录页、任务派单、已有报告权限及默认 CI 范围。

## 技术与兼容要求

- 沿用 Deep Agents／LangGraph、任务租约、检查点、业务事务和节点重试，不增加新的 Agent runtime 或多层固定规划／审核调用。
- 会话任务状态使用独立持久 JSONB 与版本控制，不能塞入会被重建覆盖的会话摘要缓存；业务事实仍以原表和修订为准。
- 新增数据采用增量迁移，旧会话按需建立状态；不批量执行历史指令，也不根据旧助手的承诺制造授权。续聊时可核对原始用户消息建立当前有效范围。
- API 增加可选的任务结果字段，查询、SSE、刷新恢复一致；旧消息及无新字段的响应仍可展示。
- 会话／账号删除、输入修订、任务取消和来源撤权覆盖新状态；公司和用户隔离适用于恢复与展示，不只适用于写入。
- 本期代码风险为 S3，重点验证公司后端任务、授权与持久化，以及相关 Web 交互；不因此运行 Electron 模型、录音和打包检查。

## 验收标准

- [x] 本次“持续关联工作 → 仓库地址与提交进展”的回归通过：范围明确则保存，确有歧义则集中澄清一次；无重复授权循环。
- [x] 连续补充保留原说明，明确纠正／替换按要求处理；未涉及字段不变。
- [x] 明确否定、一次覆盖、持续撤销、切换对象、同名澄清和来源修订均正确，旧任务不能恢复被取消的写入。
- [x] 跨消息、刷新、压缩及 worker 重启后的执行与审核使用相同任务范围；授权不跨会话／用户／公司泄漏。
- [x] 多事项、私人方案入库、自由拟写、报告交接和管理员本人工作能够按真实角色能力完成；完成判断覆盖必要正文与持久结果。
- [x] 暂时故障、参数错误、缺信息、拒绝、版本冲突分别处理；无新证据的相同阻碍不会反复调用。
- [x] 部分成功、回执丢失、重复提交、澄清续接和旧消息重试不重复写入、不误消费新操作。
- [x] 等待补充／确认／生成不显示为整个任务完成；状态在普通查询、SSE 与刷新后保持一致，节点展开不回退。
- [x] 相关确定性回归通过；真实模型完成跨措辞、多轮组合及保留样本评测，检查实际数据和用户可见结果，不靠模拟授权证明语义可靠性。

## 待确认问题

无。本方案采用会话内持续指令、保留提交／删除确认、沿用聊天澄清。
