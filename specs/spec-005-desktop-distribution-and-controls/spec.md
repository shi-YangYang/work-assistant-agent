# Spec 005 — 桌面打包与会议操作体验

## 状态

ACCEPTANCE · 2026-09-11。关键产品决策均已确认，实施结果已交独立验收；尚未声明完整交付。技术方案见 [Plan](plan.md)，分发原则沿用 [决策 0005](../../.ai/decisions/0005-self-contained-desktop-distribution.md)，暂停时间轴依据见 [决策 0006](../../.ai/decisions/0006-recording-and-storage-baseline.md#spec-005-暂停时间轴)。

## 背景

现有应用已具备会议录音、转写和纪要，仍依赖开发环境启动。设置内容逐渐增多，录音缺少暂停操作，原生播放器也不便于回顾长会议。本轮补齐安装分发与日常操作体验。

## 目标

- 安装包包含 Python 核心及运行依赖，用户无需另装 Python 或 Node.js。
- 移除设置中的“应用状态”卡片，为内容较多的设置区域提供统一折叠交互。
- 将“纪要模型服务”改名为“模型服务管理”。
- 同一场会议支持暂停、继续录音和结束保存。
- 用自定义播放器界面替换原生音频控件，增加会议回顾功能。

## 非目标

自动更新、应用商店上架、正式代码签名／公证、Intel Mac／Windows ARM64 安装包、波形与 A–B 区间循环、周报／Memory、说话人识别、录音剪辑、跨应用重启继续采集同一录音、替换 ASR／LLM 协议。

## 当前行为

- `npm run dev` 使用项目虚拟环境或系统 Python；构建仅输出 `out/`，没有安装包与内置 Python 核心。
- 设置包含“应用状态”“纪要模型服务”“本地转写模型”“录音与转写”。
- 录音只有开始和结束；ASR 的暂停／继续处理文字不等于暂停采集声音。
- 历史录音使用 `<audio controls>`，文字和纪要引用可定位到对应音频。

## 目标行为与功能需求

### R1 — 应用自带运行环境

- 交付 macOS Apple Silicon（ARM64）与 Windows x64 的可安装测试包；本轮不做正式代码签名／公证，保留运行所需的 ad-hoc 签名。安装后自动启动随包提供的核心及转写工作进程。
- 包含 Python 3.12 与已锁定运行依赖所需的原生库、数据和证书资源；不能依赖开发机源码、`.venv`、系统解释器或用户手动安装组件。
- 打包模式只从应用自己的资源定位核心。核心缺失或损坏按应用故障处理，不让用户配置解释器，也不静默退回系统 Python。
- 开发仍在本项目运行 `npm run dev`。Whisper small 模型继续由应用内下载，复用已有模型，安装包不夹带开发者的模型、录音、数据库或密钥。
- 安装、重装和升级保留现有用户数据位置、模型服务配置、录音、转写及纪要；沿用系统加密，不因换成安装包增加明文密钥回退。
- 打包进程的启动、重连、退出、休眠和崩溃处理保持受控；不能残留录音或 ASR 工作进程。安装路径包含中文／空格时同样可运行。

### R2 — 设置折叠与去除应用状态卡片

- 移除“应用状态”卡片。连接、录音、模型或存储故障仍通过相关操作位置的简洁提示提供恢复入口；错误提示不再指向已移除卡片。
- “模型服务管理”“本地转写模型”“录音与转写”使用同一折叠组件，可分别展开，不互相排斥。
- 初次进入默认折叠，随后记住上次展开状态。标题行保留必要摘要，例如当前模型服务、模型准备状态或下载进度。
- 折叠不清空未保存的表单，不停止模型下载、连接检测、录音或转写；后台错误在标题摘要中可见，用户可以展开处理。
- 标题可点击并支持键盘操作，展开状态对辅助技术可读；内容隐藏后不残留不可见的可聚焦控件。

### R3 — 模型服务管理命名

用户可见标题、无障碍名称与操作说明统一为“模型服务管理”。现有多服务、动态模型列表、推理预设、连接检测和纪要服务选择继续保留；不因改名重建配置或变更服务用途。

### R4 — 暂停与继续录音

- 录音中可“暂停录音”，暂停后可“继续录音”或“结束会议”；继续仍属于原会议，不产生新历史记录。
- 只有麦克风采集实际停止、暂停前已接收的音频处理完成，才显示“已暂停”；暂停期间不采集声音，输入音量归零。
- 录音时长只累计实际采集的音频，暂停期间不增加时长、不填充静音；继续后追加到同一条音频。转写和纪要引用按该音频时间轴定位。
- 暂停、继续和结束串行处理，重复点击不会创建多个输入流或重复写音频；过渡期间显示真实状态，操作失败给出下一步。
- 继续时重新打开可用麦克风，保持同一音频格式；设备不可用或不支持原采样率时保留暂停与已有内容，允许重试或结束，不错误显示正在录音。
- ASR 可继续处理暂停前的音频，暂停采集不能被当作会议结束或触发提前生成纪要；最终结束并完成转写后仍沿用现有自动纪要规则。
- 暂停仍属于未结束的活动会议，不能开始第二场会议；本轮沿用活动会议期间禁止历史回放的规则。切页不改变采集状态，退出／休眠／崩溃沿用保存或中断恢复语义，不自动恢复采集。

### R5 — 自定义会议播放器

- 使用统一风格的自定义控件，提供播放／暂停、拖动进度、前后跳转 10 秒、倍速、音量／静音、当前时间与总时长。
- 倍速建议提供 0.5、0.75、1、1.25、1.5、2 倍；保持语音音调。超过一小时的录音使用小时显示，跳转限制在有效范围。
- 保留点击文字和纪要引用定位并播放，播放器进度与实际媒体时间一致；更换会议不会延用另一条录音的播放位置或异步加载结果。
- 提供明确的加载、播放结束、不可播放和文件错误状态；支持键盘操作，快捷键不抢占输入框。开始录音、离开会议或重连时按现有规则停止回放。
- 不要求整场音频先读入 renderer 内存才能播放，继续使用受限会议音频协议及范围读取。

## 边界条件

首次无模型、离线启动、权限被拒绝、暂停时设备拔出／切换、快速重复操作、暂停后结束／退出、零音频、长录音、文件损坏、异步结果晚到和存储失败均须有明确状态。异常不得损坏已有音频、文字、纪要或设置。

## 技术约束与兼容性

- 保持 Electron／React／Python 架构和既有目录；打包扩展不迁移业务源码或用户数据。
- 原生核心按目标操作系统与架构构建；最低系统版本以 Electron 与所带依赖的交集和实际验证为依据，不能仅凭打包成功声明兼容。
- 新增录音状态必须贯穿协议、UI、持久化、恢复与退出判断；如改变存储语义，使用有版本和备份的增量迁移，不重建用户数据库。
- 本机交互验收使用用户日常环境；打包的无外部运行时验证及 CI 临时数据边界遵循 [AGENTS.md](../../AGENTS.md#21-测试与验证规则)。

## 验收标准

- [ ] 约定平台／架构产出可安装包；无源码、虚拟环境和可用系统 Python／Node 的情况下，随包核心及 ASR 工作进程正常启动。
- [ ] 安装包可完成录音、保存、本地转写和回放；缺失运行资源给出应用故障提示，不要求用户安装 Python。
- [ ] 安装／重启后原有模型、录音、文字、纪要及服务配置可继续使用，密钥不进入日志或产物。
- [ ] 设置不再出现“应用状态”卡片；故障恢复入口仍可用，三个设置区域的折叠、摘要、草稿保留和键盘操作符合 R2。
- [ ] “模型服务管理”命名统一，旧服务配置与功能保留。
- [ ] 同一会议可多次暂停／继续；确认暂停后不再采集，音频帧数与录音时长保持不变；继续后音频连续追加、定位正确，不补静音或重复写入。
- [ ] 暂停后结束、继续失败、设备变化、退出／休眠／崩溃的保存与恢复符合 R4；没有提前生成纪要。
- [ ] 播放器的定位、跳转、倍速、音量、时间、快捷键及文本引用定位正确；长录音无需整文件加载后才可播放。
- [ ] 独立验收报告区分本机日常环境、安装包、CI 与未执行项目，对应提交的必需检查通过。
