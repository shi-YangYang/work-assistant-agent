# 工作助手中断与执行动效

## 状态

已实施，独立验收 PASS。验证范围与限制见 [验收记录](acceptance.md)。

## 背景与目标

发送消息后，当前会话一次只处理一条用户请求。发送按钮在处理期间变为“中断”，任务步骤文字通过从左到右的光带提示正在执行。

## 当前行为

- 消息提交成功后，发送按钮立即恢复，助手尚未处理完也能继续发送。
- `pending` 表示提交结果尚未确认，不代表助手正在执行；断网后依赖它原样确认请求结果。
- 后端已有取消状态和租约保护，但没有用户主动中断接口；心跳失去租约也不会主动打断正在等待的模型请求。
- 任务步骤已有运行、重试和终态展示，目前主要用图标旋转提示执行。

## 范围与非目标

仅调整 Web 工作助手的发送、中断和步骤展示。不修改 Electron、公司任务调度、模型重试次数，不增加消息排队、自动发送草稿或独立任务管理页面。

## 目标行为与功能需求

### 1. 发送与中断

| 当前状态 | 右侧按钮 | 能否提交下一条消息 |
| --- | --- | --- |
| 空闲、处理完成、等待用户补充／确认、处理失败 | 发送 | 可以，沿用内容校验 |
| 上传或提交消息，尚未获得任务身份 | 原位置显示发送中，禁用 | 不可以 |
| 提交结果因断网等原因未知 | 原样重试确认结果 | 不可以创建另一条请求 |
| 服务端已受理，任务排队或执行中 | 中断 | 不可以 |
| 正在提交中断请求 | 中断中，禁用 | 不可以 |
| 已确认中断 | 发送 | 可以 |

- 限制以当前会话为单位。其他会话保持现有使用方式，不改变后台按账号调度的规则。
- 处理包括材料解析、语音转写、模型／工具调用、自动重试等待、上下文压缩和结果核对，均提供同一个中断入口。
- 处理中可以编辑下一条草稿；Enter 不发送，Shift+Enter 继续换行。发送函数自身校验状态，不能只禁用鼠标按钮。
- 附件与录音沿用原有校验，可以准备下一条消息；中断、完成或消息列表刷新不得清空未发送草稿。整页重新加载沿用已有草稿能力，不新增本地持久化。切换人设不改变已受理任务的配置。
- 发送与中断使用相同位置、尺寸的图标按钮；中断使用方形停止图标，悬浮／键盘聚焦提示“中断”。上下文按钮保持原位，状态切换不闪烁、不撑开工具栏。
- 点击中断直接执行，无二次确认。服务端确认后才能恢复发送；网络失败显示简短错误并允许再次中断，不假装停止，不丢失草稿。
- 刷新、切换页面返回、多标签页及账号切换后按服务端状态恢复，不能因消息未加载或旧事件迟到而误开放发送。

### 2. 中断的实际含义

- 中断当前会话本轮助手任务。排队任务不再启动；运行任务停止后续模型、工具、重试、压缩及最终答复写入，并释放本地执行资源。
- 保留用户原始消息、附件和已完成的业务操作／回执。中断不是撤销；已独立创建的报告生成任务按原有生命周期执行，回执继续显示真实状态，不一并标记为已停止。
- 消息显示“已中断”；已完成步骤保持完成，未完成步骤变为“已中断”，不残留等待、倒计时或运行光带。不增加“继续执行”按钮。
- 未核对的流式内容不能成为正式答复或后续上下文事实；已提交的工作、报告或成果不得因中断被删除或重复执行。
- 取消请求幂等。若任务已完成，返回真实终态；旧执行版本的取消请求不能中断后来重试的任务。
- 服务端阻止绕过前端在同一会话并发发送或重试旧消息。已受理请求的幂等重放仍返回原结果，不能误报为重复发送。
- 只能中断本人且当前有权访问的会话任务，不能中断其他员工、其他公司或非助手任务。
- 本地取消会断开正在等待的调用，但不承诺第三方模型服务一定停止计算；不为此增加常驻说明或确认弹窗。

### 3. 任务步骤光带

- 使用既有黑白灰主题，低对比度窄光带从左向右循环移动，周期约 2 秒；不使用彩色霓虹、大面积闪白或布局位移。
- 列表展开时，仅当前执行步骤的名称文字有光带；折叠时，仅任务摘要文字显示光带。
- 自动重试等待继续展示倒计时，排队展示等待文案，两者不伪装成正在执行；恢复实际执行后再启动光带。
- 完成、失败、中断和等待用户输入／确认后停止动效。迟到事件不得重新点亮已结束的执行版本。
- 光带裁剪在文字字形内，不能覆盖整行或容器背景。图标、状态文字与背景保持静止，不改变行高、对齐或点击行为。
- 遵循 `prefers-reduced-motion`，减少动态效果时恢复正常静态文字；状态不能只依赖动画表达。

## 技术约束与兼容性

- 分别管理“提交中／结果未知”和“助手执行中”，不复用 `pending` 表达两种含义。
- 复用任务状态、节点投影、版本序列、租约和 SSE；发送／中断状态集中在专用 hook，避免各组件重复维护。
- 中断逻辑独立于路由与 UI，执行写入继续校验任务状态和执行版本。服务端确认取消后，旧执行不能覆盖新请求或会话上下文。
- 不新增任务状态枚举或数据库表，继续使用 `cancelled`；“中断中”为前端请求状态。样式限定在对应 CSS Module。
- 旧会话若已有多条排队请求，保留这些消息，按实际当前任务提供中断；仍有待处理任务时不得假装空闲或静默删除队列。

## 验收标准

- [x] 受理后按钮变为中断，任务结束后恢复；受理与列表刷新之间无短暂可重复发送窗口。
- [x] 鼠标、Enter、多标签页、旧消息重试均不能在同一会话插入并行请求；原请求的幂等确认仍正常。
- [x] 排队、模型调用、工具执行、重试等待、压缩和核对阶段均可中断；完成与取消竞争返回正确结果。
- [x] 中断后没有新的业务写入或答复／上下文回写；已完成操作和原始内容保留，独立报告的回执状态不被误改。
- [x] 中断请求失败、重复点击、刷新、离线恢复、会话／账号切换和旧版本事件均正确处理，草稿不丢失。
- [x] 光带只表达真实执行，停止后不残留；桌面／手机、浅／深色正常，减少动态效果的 CSS 已核对，未模拟该系统偏好。

## 待确认问题

无阻塞问题。默认允许边等待边编辑草稿；中断直接执行，保留已完成的操作。
