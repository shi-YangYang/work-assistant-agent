## 数据与接口

- `GET /api/v1/conversations/{id}/active-job`：校验本人会话与业务权限，返回 `{ job: Job | null }`。查询关联消息的 `queued / running` 助手任务，旧队列按执行顺序取当前项，不受聊天分页影响。
- `POST /api/v1/jobs/{id}/cancel`：接收 `expectedAttempt`、`expectedFence`，返回当前 `Job`。仅本人助手消息任务可取消；终态重复请求返回真实终态，活动执行版本不符返回冲突并刷新状态。
- 取消事务按现有锁顺序执行：检查身份／来源／版本，设置 `cancelled`、释放租约、更新反馈及用量的未完成状态。提升执行 fence，阻止旧执行写回；已完成节点、业务回执与有效上下文保留。
- 新消息和助手重试共用会话互斥检查，使用一致的事务锁顺序；幂等重放先返回已受理结果。已有活动任务时返回明确的 `409 conversation_busy`，不得创建另一条消息或清空草稿。
- 发送接口已有 `messageId / jobId / conversationId`，前端补齐实际返回类型，不等待历史刷新才进入处理中。首次自动创建会话也保持同一任务状态。
- 通过现有 SSE／断线恢复通道同步，以账号、会话、任务及 `attempt / fence / seq` 过滤旧反馈；活动任务查询用于进入、重连和冲突恢复，不额外建立高频前端轮询。

## 实施步骤

1. 实现活动任务查询、受权取消与会话互斥，统一消息提交和助手重试的锁顺序。查询不加载完整历史或上下文 JSONB。
2. 执行端增加轻量取消监视，在运行期间约每 2 秒检查持久化取消／版本状态；信号到达后取消正在等待的执行协程，并等待清理完成。心跳异常也须传播给执行体，不能只让心跳自行退出。
3. 排队任务取消后不再领取；模型流、工具 HTTP、解析子进程及重试休眠均通过取消链退出。确认 `CancelledError` 不被普通失败／自动重试捕获，不被 worker 异常恢复重新排队。复用原有子进程清理和租约保护，不另造重试框架。
4. 用 `useAssistantTask` 管理活动任务与中断请求；消息卡与输入区复用按任务标识共享的反馈订阅。保持上下文用量更新，避免重复 SSE。
5. 接入发送守卫和固定位置中断按钮；区分提交中、结果未知、执行中和中断中。编辑草稿、键盘换行不受影响；终态只解除发送限制，不自动发送。
6. 展开列表的当前步骤名称、折叠列表的摘要文字使用字形裁剪渐变光带，图标、状态与容器背景保持静止；依据真实节点状态开启，终态立即移除，减少动态效果时恢复正常文字。
7. 定向验证后交新的独立验收 Agent，记录结果和必要限制；不运行 Electron、打包或整仓测试。

## 验证

文档阶段为 S0，仅检查 diff、需求一致性和引用。实施涉及取消、并发写入和接口权限，按 S3 验证受影响的助手子系统。

- 服务端：排队／模型流／工具／重试等待／压缩／核对中的取消；确认后拒绝旧写入，正常本地条件下 3 秒内开始取消并及时清理资源。慢请求用可控阻塞响应验证，不用大量真实模型调用代替竞态测试。
- 互斥与权限：并发发送、发送与重试竞争、幂等重放、旧执行取消、重复取消、取消与完成竞争；跨账号／公司拒绝，不取消独立报告。
- 持久化：不删除原始消息、附件或回执；旧任务不覆盖新任务／上下文，worker 重启不恢复已取消任务；已完成业务操作不重复执行。
- 前端：受理瞬间锁定、首次会话创建、Enter 拦截、草稿保留、结果未知原样确认、中断网络失败、刷新恢复、多标签页与身份切换。上下文按钮不消失、工具栏不跳动。
- 浏览器：当前本地环境验证发送 → 中断 → 再发送；截图检查电脑／手机、浅／深色、展开／折叠后的运行与终态。检查动画实际运动方向及减少动态效果模式，不只依靠截图。
- 修改源码使用已有格式化器；执行相关服务端、前端测试与 Web 类型检查，通过后停止。使用已有授权配置做一轮真实中断验证，清理本轮测试数据，如实区分真实调用和固定响应测试。

## 风险与兼容

- 供应商可能在连接断开后继续计算；本地需停止消费、后续执行并拒绝迟到写入，不承诺远端撤销已受理调用。
- 不同会话沿用当前后台调度；此处只禁止同一会话同时处理多条用户请求。
- 旧排队任务不删除、不补执行；完成或中断当前任务后重新获取下一项。前后端共同上线，避免旧客户端不能正确处理新增冲突提示。
- 预计不需 migration，不扩大工具权限或改变已完成业务操作的撤销规则。
