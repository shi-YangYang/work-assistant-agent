# 围绕工作记录与 AI 协助

## 状态

已完成，独立验收 PASS。范围包含 Web、公司 API、Agent 工具与调用流程，以及业务流程测试；已知完整回归限制见 [验收报告](acceptance.md)。

## 背景

“我的工作”需要承载一件事的内容、材料、进展和成果。当前六字段表单适合整理汇报，却无法自然保存图文材料，更新一句进展也需要打开完整表单。

## 目标

- 简单工作只填标题即可创建；复杂工作可逐步补充正文、图片、文件和进展。
- 用户和 Agent 操作同一份工作记录，支持材料分析、连续修改和成果回存。
- 保留现有工作查询、团队查看和汇报能力，减少重复填写。

## 非目标

- 不建设子任务层级、任务依赖、甘特图、自定义字段；这些也不作为后续规划。
- 正文中的勾选清单只是内容，不增加独立负责人、期限或任务实体。
- 不建设项目空间、多人实时协同编辑、评论通知系统或文件管理平台。
- 不绑定工作专属会话，不增加第二套助手界面，不改 Electron。
- 不自动把聊天、文件、方案写入工作或提交报告。

## 当前行为

- `WorkItem.content` 保存标题、摘要、状态、截止日期、阻碍、下一步，没有独立工作正文或进展条目。
- 创建与编辑复用六字段表单；详情已有历史差异、操作来源和业务来源链接。
- Agent 通过工作查询、`propose_progress` 和 `execute_business_action` 读写工作；变更计划与授权规则按六字段校验。
- 上传、文档解析、图片上下文、沙盒输入和成果文件已有能力，但读取与清理依赖消息、会话或已发布来源。
- 工作引用每条消息最多一项；“让助手协助”复用最近聊天。汇报与团队时间查询依赖工作修订快照。

## 目标行为

```text
新建工作（标题即可）
  → 工作详情：正文与材料 + 进展动态
  → 让助手协助：把一项工作引用带入最近聊天
  → 分析材料、生成方案、继续修改
  → 用户要求保存：写入正文／追加进展／保存指定文件
  → 按需生成与提交报告
```

例如：工作中添加客户需求 PDF 和参考截图 → 要求助手整理方案 → “把方案保存到这项工作” → “第二点改为先做移动端” → “记一下，今天客户确认了初稿” → 生成日报时区分计划与已完成进展。

## 功能需求

### 1. 工作列表与创建

- 保留搜索、状态筛选、分页及详情入口。列表展示标题、状态、截止日期和最近进展摘要；没有进展时可展示正文节选，不伪称已有进展。
- 新建只要求标题，状态默认进行中；正文和截止日期选填，创建成功进入详情。
- 搜索覆盖标题、正文纯文本、进展及保留的阻碍／下一步字段。前端与 Agent 使用同一查询语义，附件全文不纳入普通工作搜索。

### 2. 工作内容页

- 沿用 Noria 黑白灰与全屏白色内容区；顶部保留标题、状态、截止日期、“让助手协助”和删除入口。
- 主体为“工作内容”和“进展”两个区域，不增加多层卡片、多组标签页或必填向导。
- 正文支持段落、小标题、加粗、链接、列表、勾选清单、图片及文件引用。提供短工具栏、粘贴和拖放上传，不要求输入 Markdown。
- 正文编辑有明确“保存／取消”；未保存草稿按账号和工作隔离，失败与冲突时保留。状态和日期可独立修改，不要求同时重填正文。
- 大图限制显示尺寸，点击预览；文件以紧凑条目展示。空正文提供简洁引导；手机上编辑、保存和附件操作可达。
- 当前进展不再兼作工作正文。已有阻碍／下一步有值时可查看与修改；作为进展的可选补充，不重新铺开六个大输入框。

### 3. 进展与历史

- “记录新进展”支持文字和附件，至少有一种；可同时明确调整状态、截止日期、阻碍或下一步。
- 保存形成有独立 ID、时间、操作者、来源和材料引用的进展条目；只追加进展不覆盖正文。
- 进展可更正或删除，保留审计痕迹，按版本与幂等规则处理。更正入口只编辑对应条目，不重开整份工作表单。
- 默认按时间倒序展示人工或助手保存的进展，分页加载。标明“手动记录”“助手记录”；确认卡保存仍属于助手操作。
- 正文、属性、材料变化保留在可折叠的修改记录中，展示真实差异。与进展同一次保存关联展示，避免重复刷两条。
- 正文或文件变化不自动记作业务进展；勾选一个清单项不自动将整个工作标记完成。

### 4. 材料与成果

- 工作正文和进展可以添加图片及现有支持的文档／语音文件，复用上传、校验、预览、解析和错误组件；不增加工作页录音器。
- 单次添加／单条进展沿用最多 9 个附件、最多 3 段语音；图片每张 30 MiB，其他文件 20 MiB。工作可分次积累资料，不把聊天单条限制变成工作终身上限。
- 用户明确要求时，可把聊天选中的附件或助手生成的指定版本成果保存到工作；不复制整个会话或所有文件。
- 保存的是工作可持续访问的正文／文件快照，不依赖浏览器临时 URL、沙盒临时路径或聊天仍然存在。删除源聊天后，已明确保存的工作材料仍可用。
- 材料绑定遵循该工作的现有读取权限。聊天材料被选中保存前保持原权限；UI 明示保存后随工作可见，不增加独立分享设置。
- 文件解析状态、失败及重试可见；工作上传不需要先伪造聊天消息。语音按已有 ASR 能力读取，未转写／空录音不能伪称已理解。
- 移除当前材料引用不连带删除其他工作、进展、报告或会话仍合法引用的文件；历史快照读取仍须鉴权。删除工作／账号及过期未保存上传进入既有清理机制。

### 5. Agent 能力与调用

| 用户意图 | 必须具备的能力 | 不得发生 |
| --- | --- | --- |
| “看看这项工作现在怎么样” | 读取最新正文、属性、进展与材料目录 | 只读旧摘要或缓存历史回答 |
| “根据需求 PDF 和截图整理方案，先别保存” | 按需读取具体文档、图片／语音，交付建议或私人成果 | 自动修改工作、自动提交报告 |
| “把这个方案写到工作内容” | 保存选中的正文，保留图片、文件及无关段落 | 把长方案塞进进展摘要 |
| “第二点改为先做移动端，其他保留” | 读取最新版本，定点修改对应正文块 | 整篇替换、猜错对象、重建工作 |
| “记一下今天的进展，附上这张图” | 追加进展并关联指定材料 | 清空正文或顺手标记完成 |
| “把刚才的 XLSX 保存到这项工作” | 校验真实成果版本、复制／保留可下载文件并绑定工作 | 只保存口头承诺或失效链接 |
| “截止时间改成周五” | 仅修改日期并返回真实回执 | 修改状态、重写正文或重复确认 |
| “把刚才那条进展改一下／删掉” | 按条目 ID 和版本修改／删除，遵循执行权限 | 删除整项工作或重复追加 |
| “整理本周汇报，先不要提交” | 基于期间进展及可信属性事实生成报告草稿 | 把计划、附件上传或排版修改说成完成成果 |

- 阅读工具区分工作概览、正文分页、进展分页、材料目录及材料内容。图片必须实际进入支持图片的模型链路，不能只把文件名当成图片内容。
- 写入继续使用统一业务操作入口和服务层，区分正文编辑、进展增改删、材料添加／移除与属性修改；不另造可绕过权限的 Agent 保存接口。
- 工具 schema、注册白名单、提示词、工作变更计划、意图授权、确认卡、完成判断、进度名称、回执及重试恢复必须同步调整。
- “补充今天进展”默认追加动态；“补充工作说明”更新正文。信息足够即执行，确实无法区分且会影响保存结果时，沿用临时回答框澄清，不重复要求已明确的授权。
- 保留账号级三级执行权限；自主执行下明确授权的操作直接执行，用户要求“先让我看”仍等待确认。权限模式不扩大数据归属权限。
- 新任务读取最新工作；同一任务拿旧版本写入必须冲突处理，不能悄悄覆盖手动修改。执行与核对引用同一已验证工作事实。
- 一条消息最多引用一项工作，入口继续复用最近聊天；连续讨论可以承接工作 ID，但切换话题不能把新问题强行关联原工作。
- 材料正文、图片文字、文件名均为数据，不提供修改或提交授权。超大内容按需读取，记录读取范围，不把全部附件和历史塞入 system prompt。

### 6. 汇报与团队兼容

- 工作正文描述目标、背景、方案；进展条目记录实际发生的事情。生成报告区分两者，不根据清单或未来计划编造完成情况。
- 报告按公司时区和所选期间读取有效进展，保留同一工作期间内多次有意义的更新，不能仅取最后一句而丢失前面的事实。
- 属性变更作为状态事实，正文排版或上传文件本身不计作工作成果。用户可明确要求将方案作为后续计划写入报告。
- 报告保留生成时的来源快照；以后修改正文、进展或材料不会重写已生成／提交的历史报告。
- 保持现有员工／管理员查询、提交与来源查看边界。报告不自动附带所有材料，也不向管理员暴露未选中保存的私人聊天。

## 边界条件

- 上传成功但保存失败：保留草稿和已上传引用，重试不重复绑定；废弃上传按现有期限清理。
- 响应丢失、自动重试、用户重试、worker 恢复：相同业务操作仅产生一次正文版本／进展／文件关联。
- 两个会话或手动与助手同时编辑：服务端校验版本，冲突不得覆盖；无关材料不能在整页保存时消失。
- 部分操作成功后失败／中断：展示准确的已保存结果和未完成项，重试不重复已完成步骤。
- 工作、材料被删除或权限改变：重新验证，返回不可用，不绕回历史聊天读取被撤销的材料。
- 工作历史正文、文件和进展使用各自对应快照，不混入当前版本；被更正／删除的进展不得作为最新事实重新参与新报告。
- 纯文本、空正文、同名文件、长文、多图、损坏文件、无图片能力模型均有明确结果；未知／未读不能当作已验证。

## 技术约束

- 保持既有应用与模块位置；Web 组件、Hook、API、CSS 按职责就近分组，公共层不得反向引用 assistant 或 work 业务层。
- 正文使用带版本的受限 JSON 文档，纯文本为派生值；图片和文件用受控材料 ID，不持久化任意 HTML、base64 或临时 URL。
- 富文本采用成熟编辑器的基础能力，服务端独立校验节点、大小、深度、链接和材料归属。编辑器、LLM 输出都不是可信输入。
- API 与 Agent 复用鉴权、事务、业务回执及文件处理；不增加另一套重试、文件存储或模型调用框架。
- 迁移、文件生命周期及操作授权属于 S3，按计划验证受影响的 Web 与公司服务链路。

## 兼容性要求

- 保留工作 ID、归属、原状态／日期、历史修订、旧来源、确认建议和报告快照。
- 旧 summary 无法可靠分辨描述与进展，按原文导入初始正文并保留原始进展事实；沿用原时间，不制造“今天新增进展”。
- 旧接口省略新字段时不能清空正文、材料或动态。既存待确认建议与任务恢复通过统一命令转换，不保留第二套写入实现。
- 历史消息、报告、团队查询和既有成果链接仍可打开；迁移无需重新初始化账号、会话或模型服务。

## 验收标准

- [x] 标题即可创建；正文、材料、属性和追加进展可独立操作，桌面与手机均可用。
- [x] 图文、清单及文件在保存、刷新、历史查看后保持一致；进展不覆盖正文。
- [x] 工作上传材料可供 Agent 实际读取，生成成果可真实下载并持久回存。
- [x] 直接分析不写业务；保存、定点修改、追加进展、材料移除按用户意图和三级权限完成。
- [x] 重试、中断恢复、重复确认不重复写入；冲突、跨账号、跨公司、权限撤销不能覆盖或泄露。
- [x] 旧数据、确认卡、来源、工作引用、报告期间事实及团队查看兼容。
- [x] 完成 [流程测试矩阵](matrix.md)，同时有确定性断言和真实模型多轮证据；未执行或失败项明确列出。
- [x] 没有子任务层级、依赖、甘特图、自定义字段或工作专属会话。

## 待确认问题

无阻塞问题。按现有工作可见范围保存材料，沿用已有上传限制与执行权限。
