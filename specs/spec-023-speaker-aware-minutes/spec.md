# 发言人视图与会议分析

状态：已实施，验证范围与限制见 [验收记录](acceptance.md)。

## 目标与当前行为

让会议文字既便于连续阅读，也能看清谁说了什么，并让纪要使用可靠的发言人信息整理讨论、责任事项及后续工作。

目前文字记录已有说话人标签和人工纠正，但没有纯文本／按发言人切换；导出文字会附加已有姓名。纪要输入只读取片段 ID、时间和文字，不含说话人；自动生成由转写完成触发，不等待会后说话人处理。现有纪要包含摘要、讨论要点、明确决策、行动项、风险及未解决问题，仅决策和行动项具备结构化原文引用。

## 目标行为

### 同一份记录，两种视图

- 在“文字记录”内增加“按发言人／纯文本”切换，不复制两份文字或重新转写；切换不改变片段 ID、原始文字、时间、搜索和回放定位。
- 默认按发言人展示；已知姓名、临时说话人和多人／待确认明确区分，保留已有改名与片段归属纠正。纯文本隐藏说话人标注，不改写原话，也不作为匿名化功能。
- 复制／导出文字可选择是否带发言人，沿用 Markdown／TXT。已有会议无姓名时仍能正常查看、生成纪要和导出，不虚构人员名单。

### 纪要使用说话人信息

- 默认选择“含发言人信息”，生成处可改为“仅文字”；阅读视图切换不悄悄改变生成依据，不同时生成两份纪要。
- 含发言人输入带稳定的会内说话人标识、已有姓名、身份来源及原文片段；人工更正优先，无法识别的保留临时标签。仅文字模式不附加说话人字段，但原话中提到的姓名仍保留。
- 姓名和对应文字会发送给用户已配置的纪要服务；录音、声纹向量和完整公司人员名单不随纪要请求发送。
- 发言者不自动等于负责人。只从明确分工或承诺提取责任；有歧义、混合发言或身份不确定时标为待确认，不按公司成员名单猜测。自动声纹匹配不能被表述为本人确认。
- 已启动说话人处理的会议，自动纪要等待会后处理完成；未启用或处理失败时可使用已有资料生成，并说明说话人信息是否完整，不无限等待。后续识别成功不静默追加付费生成。
- 每次任务锁定文字、说话人信息和输入模式的快照。使用了说话人的纪要在姓名／归属更正后标为待更新；纯文本纪要不因仅改姓名失效。生成期间输入更新不能把旧快照结果标成最新，重新生成失败保留上一份成功纪要。

### 更完整、可核对的分析

首版固定为下列内容，不新增开放式会议聊天或模板编辑器：

| 内容 | 目标 |
| --- | --- |
| 会议概览与议题 | 简明结论、讨论背景、各议题进展及结果 |
| 发言人摘要 | 按实际发言整理主要观点与明确承诺；不把沉默人员列为已参会 |
| 共识、决策与分歧 | 分开呈现已经确定、仍有争议和没有结论的事项 |
| 行动项 | 任务、明确的负责人、原话中的期限、依赖或阻碍；缺失项待确认 |
| 风险与待确认 | 对应原文问题、缺少的信息和需要补充确认的责任或安排 |
| 后续建议 | 明确标为 AI 建议，与会议已经作出的决定分开；不自动创建任务或提醒 |

- 事实性条目可定位到真实文字片段并回放；AI 建议也应指向相关讨论依据，不伪造引用。引用存在不等于结论正确，需要覆盖语义准确性的验收样例。
- 无相关内容的区域按需收起，不为凑版面填充长文；纯文本模式不生成依赖说话人标签的逐人摘要。
- 页面、会议搜索、复制、导出和原文定位支持新增内容；沿用紧凑排版、独立内容滚动和桌面既有视觉。

## 兼容与边界

- 保留已有纪要的阅读、搜索与导出；新结果使用版本化结构，不要求用户重新生成全部历史会议。
- 保持游客模式、本地录音、公司声纹缓存及当前模型服务接入方式。转写、声音匹配与网络生成失败不得损坏原始记录。
- 本次不更换声纹／转写模型，不训练模型，不承诺识别准确率提升；重点是信息呈现、可靠归属及分析衔接。长会议仍遵循现有请求限制，不隐式增加多轮模型调用。
- 不接入公司任务写入、跨会议记忆、员工绩效／性格分析或声纹身份认证。

## 验收标准

- [x] 两种视图展示同一份文字，姓名纠正、时间定位、复制／导出及历史会议兼容。
- [x] 默认含说话人生成，可选仅文字；实际模型请求与选择一致，未发送声纹向量或无关成员资料。
- [x] 等待、失败降级、人工改名、片段重指派、生成中变更及重转写均正确维护输入版本和待更新状态，不重复自动请求。
- [x] 能区分“我来处理”“请他处理”、提议与决定、已确认姓名与未确定身份；负责人不由发言者字段机械填充。
- [x] 新分析模块具备有效来源，建议和事实分开，界面／搜索／复制／导出一致，旧版纪要仍可读。
- [x] 实施时针对受影响模块检查，并在日常桌面环境使用授权配置做真实模型样例验证；固定响应、实际模型和平台未测范围分别报告。
